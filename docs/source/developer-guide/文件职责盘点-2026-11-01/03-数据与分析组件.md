- 盘点日期：2026-11-01
- 范围：当前工作树中的 backtrader/feeds、filters、commissions、sizers、signals、observers、analyzers。
- 方法：逐个阅读当前 Python 源文件并核对 Git 状态；意见只针对可见源码与当前仓库职责指南，不运行测试、不读取私密输入、不做账户或服务操作。
- 结果：现存 Python 源文件 76 个；另有 Git 标记删除的历史源文件 6 个；目录内另有 330 个 __pycache__ 下的 .pyc 生成文件，不属于源文件清单。下面对 76 个现存文件和 6 个删除项逐项给出归属。
- 工作树标记：[改] 为已有修改，[新] 为未跟踪文件，[净] 表示该路径当前无 Git 差异。状态只描述盘点时工作树，不代表改动已验收。

## 总体判断

1. 目录主线仍清晰：Feeds 把外部/本地数据转成 Backtrader 数据行；Filters 对行流作变换；Commission、Sizer 分别提供费用/持仓量计算策略；Observer 画图或记录运行过程；Analyzer 产出回测统计。市场历法、合约选择、实时服务投影和资格证明等近期工作扩大了 feeds 的领域职责，宜先稳定 API、厘清 SDK 与框架边界，再渐进拆分。
2. 多个包初始化文件通过星号导入形成兼容性导出；部分模块没有明确 __all__。包的可见 API 会随实现导入而变化，且可选依赖、弃用模块可能在用户未直接使用时加载。应先盘点现有调用和导入兼容性，再逐包明确导出清单，不能直接删除旧名称。
3. 当前 7 个已修改路径和 6 个新建路径都属于源码状态变化，集中在 Feed、市场快照/投影和期权佣金。这些路径按当前指南属于迁移或候选实现；本文仅作静态源码归属审查，不将其描述为结构迁移完成、行为验收、交易能力或账户证据。
4. 超大模块主要是 feeds/btapifeed.py、feeds/futures_main_contract.py、feeds/barrier.py、feeds/csvgeneric.py 和 observers/trade_logger.py。建议按稳定的数据结构/协议边界提取小组件，保留旧入口和数据格式；避免一次性重写热路径或输出格式。
5. 本轮发现两个明确的维护点：InfluxDB.start() 的查询异常分支之后仍使用可能未赋值的 dbars；SharpeRatio._convert_rate_returns() 在 return rate, returns 后留有不可达的重复比率计算代码。另有若干需由调用合同明确的容量、日历、单位、时间语义问题，文中标为待确认，不冒充已证实的运行故障。
6. 仓库职责指南要求在改动前阅读 docs/source/developer-guide/repository-responsibilities_zh.md。该指南指出正在进行的 Iteration 53 归属迁移及若干能力尚未验收。当前源码中 BtApiFeed 使用 backtrader.utils.bar_projection.normalize_bar；指南里仍有旧 Store 私有归一化入口的描述，建议后续做文档事实核对，不能据此认定当前代码存在该耦合。

## 建议的渐进实施顺序

1. 先做导出与兼容表：记录包级公开名、星号导入结果、延迟导入边界和外部调用者；依此小步定义 __all__ 和懒加载，不先删除旧模块。
2. 处理窄而确定的维护风险：修正/明示 InfluxDB 错误路径、连接关闭与单位映射；移除 Sharpe 不可达重复代码；把 DataTrades 10-feed 容量及 Session/Calendar filler 的时间边界写成可检查合同。
3. 收敛纯投影边界：把 SDK 数据/历法/执行快照只映射成 Backtrader DTO；provider 原始请求、解析、产品分类、来源时钟和账户权威留在 SDK/provider。当前新 Feed 与 commission 文件逐项标注 WIP，不能在未满足接口合同前升级为“通用可用”。
4. 以兼容门面拆分大文件：优先抽无状态解析/投影/报告格式化，状态机/轮询/Filter stack 的生命周期所有权一次只留一个；保留现有类名和输出结构作为过渡入口。
5. 对 Observer/Analyzer 先固定输出 schema、时钟、缺失/无效值和部分成交口径，再统一重复指标实现或限制长期缓存；TradeLogger 的 sink/隐私/异常关闭独立设计。
6. 最后处理删除项和弃用在线 Feed：通过包导出、调用方、打包和兼容路径盘点后逐批收敛。任何后续行为/性能/账户验收应作为独立阶段记录；这份静态清单不替代验收。

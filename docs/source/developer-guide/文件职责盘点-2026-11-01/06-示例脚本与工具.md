## 可规模化的逐文件生成方案

1. **权威清单只取 Git index。** 用 `git ls-files -z -- examples scripts tools` 构造路径集；分别记录 tracked/worktree 状态，显式标注删除、重命名和“tracked 但缺失”。不扫描 `.env`、真实 `config.yaml`、私有捕获、忽略的 `evidence/` 或证据内容；公开、无秘密模板可按公开静态/限量规则读取；真实配置与私密捕获仍禁止读取。
2. **按类型读取元数据。** Python 只 tokenize/AST parse，不 import、不执行；提取模块 docstring、顶层定义、import edges、CLI 解析点、`__main__`、可识别网络/进程/订单/数据库/文件写/本机调用标记及行号。Shell/bat 只静态扫描命令/入口；Markdown 只取标题、链接、明确状态词；模板/数据只记路径、类型、大小/来源字段（若已公开登记），不读私密值。
3. **一文件一行，模板只能帮归组。** 输出字段建议：`path, owner_group, declared_role, AST_symbols, callers/importers, entrypoint, config_inputs(names_only), external_effect_markers, outputs, retirement_state, evidence_level, source_anchors, confidence, follow_up`。99 个 case 文件可以共用模板指纹列，但仍逐个生成行；只有结构指纹相同也不能推定策略合同/风险完全相同。
4. **把推断与已证实事实分列。** 每项职责需要源文件/README 行号；模式/账户/生产写入/行为通过必须从真实调用链和可核查验收来源另行确认。没有调用者、声明或足够源码证据时标 `待核查`，不依据文件名推断“安全”“可用”“已退休”。对于退役 stub，引用返回码/原因；对于遗留 helper，检查是否被当前 `run.py` 实际调用。
5. **按风险分批人工复核。** 第一批 live/managed/provider、`root_activation`、网络请求、订单撤销/平仓；第二批数据库、release、批量文件移动/删除与来源修改；第三批普通回测和文档/性能工具。每批先生成静态行，再对 outlier/跨目录调用链人工核对，不运行目标命令。
6. **完备性检查。** 验证每个 Git 路径恰好一行、总数与 index 分组数一致、重复路径为零；从 current CI workflow 到脚本入口以及 `run.py` 到 helper/Strategy 的静态边逐项核对。自动摘要不能记作行为或账户 acceptance。
7. **输出与编码。** 生成物仅写 `.codex-tmp/`；中文 Markdown 用 UTF-8 BOM，严格 UTF-8 解码、无 `U+FFFD`、抽查中文文本，并用 Windows PowerShell 默认 `Get-Content` 确认可读。审核通过后再另行决定是否制作正式目录/文档，不在盘点阶段批量搬迁或改写。

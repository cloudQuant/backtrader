# Backtrader 支持目录与包内资源逐文件盘点（2026-11-01）

## 范围、方法与结论口径

本轮先读取了仓库职责指南，再核对现有 dev 工作树中以下目录：bokeh、btrun、channels、configs、live_trading、notifications、plot、reports、utils，并检查了 backtrader 包中的非 Python 资源。

“源码已确认”只表示文件职责能由当前源码、模块说明、导出或可检索调用点支持；不代表代码已通过行为、导入、安装包、账户或真实服务验收。本轮没有运行产品导入、测试、构建、网络或账户操作。静态核对使用文件清单、AST 符号与导入、调用点搜索及 setup.py 包数据声明。

配置方面只处理了 backtrader/configs/account_config_example.yaml 这一示例资源，未输出其中的值，也未读取真实账户配置或密钥。仓库元数据将其标为无凭据模板；本轮未验证任何值是否能通过真实服务认证。

## 高价值风险与建议顺序

1. **先处理 dirty Store 的未跟踪依赖。** 当前修改中的 BtApiStore 直接导入 bar_projection.py 与 runtime_redaction.py，但二者未被 Git 跟踪。干净 dev checkout 无法重现当前导入面。若保留该 Store 改动，应将所需模块、调用方和最小回归作为同一明确源码轮交付并核对发行包；若暂不验收，则不能把该状态描述为可移植实现。
2. **收紧 Bokeh 敏感内容的默认展示和服务器边界。** 默认 tab 会显示策略 params、日志、Broker cash/value 和 Python 源码；Webapp 可绑定非本地地址且没有认证/TLS 接口。提供默认关闭敏感 tabs、脱敏与显式远程服务配置；在有访问控制前保持本机限定。
3. **修正 plotting 的可选依赖边界。** plot 包入口虽然延迟 Matplotlib Plot，但提前导入 PlotlyPlot；旧 plot.py 又组合了 Plotly、Dash、pyecharts 和 Matplotlib。按 backend 延迟加载，并分别验证 Matplotlib、Plotly、Bokeh 的最小依赖集合。
4. **让通知系统导入更安静、生命周期更显式。** notifications/config.py 会注册 fork/exit hooks，配置后才创建单例与 worker。可将 hooks 延迟到显式配置，或用惰性注册器，维持未配置导入不操作网络/文件的承诺。
5. **明确 live_trading 与 Broker/Store/SDK 的关系。** 当前只有独立 DTO、ABC 与注册表，没有框架调用方或具体 adapter。先决策保留兼容接口、转成薄 adapter 还是标为未支持；订单/账户/时间/session 合同明确之前不把它作为实盘入口。
6. **拆清 channels 的数据职责和证据等级。** 文件解析、事件优先级队列、数据校验和有限 Line 桥接混在同一子包。文档应分别说明 replay/file 与 live event path、队列丢弃统计、时钟来源及兼容边界；validator 不能替代 provider/session/source-clock 证据。
7. **缩小 utils 聚合。** load_data 是 tests/examples 支持、fractal 是指标、flushfile 有 import 副作用、ordereddefaultdict 未见外部调用，均与常用核心日期/结构工具混放。分批迁移时先冻结兼容导入，保持已有用户代码路径。
8. **把报告视为敏感输出。** ReportGenerator 将 params、kwargs、user/memo 投影到 HTML/JSON；建议在模板和 JSON 两路使用同一脱敏策略，并避免把配置对象或凭据串入策略参数。
9. **把示例资源的无密钥保证做成机器可查合同。** 当前唯一包内非代码资源是 account_config_example.yaml。继续只打包示例模板，模板值使用肉眼可识别的虚构内容，并由 wheel 资源检查阻止意外加入 account_config.yaml 或其他配置。

本清单是静态归属快照，不是重构授权或行为验收。调整前按仓库规则检查调用者、打包、兼容与现存改动，并将每轮接受结果、精确文件范围和提交记录分开保存。

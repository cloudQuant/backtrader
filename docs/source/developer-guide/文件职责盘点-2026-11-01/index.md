## 优先重构与注意事项

1. **明确迁移中的接口及发行边界。** 当前 Store、Broker、Feed 与 SDK 之间有未提交的新旧路径并存；先核对调用者、公开兼容、安装包及状态 owner，再按领域小步迁移。
2. **核实因子持仓快照的无 I/O 合同。** 候选代码通过 Broker 公共持仓读取路径取值，该路径在某些条件下可能同步 Store；应以明确的缓存接口和隔离验证保证合同。FactorPositionBook 与 SDK journal 的事务/schema 边界需要明确，不能无证据称为两套账本。
3. **先查清引擎时钟补丁和 cohort 的所有权。** `metabase.py`、`lineroot.py` 和 `lineseries.py` 都存在与 `Strategy._clk_update` 相关的运行时 patch 尝试；导入/调用顺序和最终绑定需实际验证。cohort 的调度、身份及退出状态跨引擎、Feed 和 research，收敛前不能放宽现有身份校验或改变事件顺序。
4. **逐项验证组件风险。** InfluxDB 查询异常分支、零价格填充、固定数量观察线和不可达分析代码等均有源码线索；优先建立最小复现并修复对应合同，不把静态观察直接当作已复现故障。
5. **隔离展示后端和历史入口。** 绘图后端应避免无关可选依赖阻断所选后端；示例、运维脚本和历史归档应标清是否仍支持及其副作用，保留现有公开 API 与证据字节。

每项变更应先明确对象及调用者，再按现有 `dev` 小轮工作流实现、验收和提交；涉及实盘、外部账户或已消费的历史调用时，遵守既有授权和保护约束。本次清单没有运行这些操作。

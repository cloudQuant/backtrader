### 1.1 SDK 失配的精确边界

本机发现的分发元数据为 `bt_api_py==0.15.3`，但模块为 namespace package，且没有导出当前
测试/Store 所需的 `BtApi`、`CancelOrderRequest`、`CrossVenueLeg`、`FeeSchedule`、`Freshness`、
`CtpExecutionApprovalCapability`。仓库虽有
[`requirements-ci-sdk.txt`](../../../../../requirements-ci-sdk.txt) 固定 SDK 组合，普通
`make test-fast` 不会安装或预检它；`optional_sdk()` 又刻意只在**分发不存在**时 skip，已安装但
不兼容时会正确暴露问题，结果是 165 个级联失败而非单一、可操作的环境诊断。

这不证明 Backtrader 核心逻辑有 165 个独立缺陷，也不允许把当前环境解释成完整通过。必须先
用可审计制品确认 SDK API 与测试合同，然后再对剩余失败逐项归属。

### 1.2 当前脏工作树的单独边界

在本轮早期的主工作树诊断中，`make test-fast` 曾出现 2 failures + 2 errors，涉及 CTP/SDK
相关测试。该工作树含大量其他迭代的未提交修改，不能与上述 clean-baseline 结果混合，也不能
作为任何人分支的回归归责。迭代 33 只在相关 owner 提供干净、可定位的提交后处理它们。

## 2. 架构结论与治理原则

1. **核心与可选 SDK 的部署边界不够显式。** `BtApiStore`、`BtApiBroker`、`BtApiFeed` 和
   012 系列示例共同消费 SDK 顶层合同，但本地“核心”测试命令会受环境中偶然存在的 namespace
   分发影响。
2. **高复杂度集中在正确性敏感路径。** `BtApiStore` 约 15,584 行、`BtApiBroker` 约 8,227
   行；line system、策略时钟、回测循环、订单簿和 CTP 证据逻辑同样包含 F 级函数。拆分必须先
   建立字符化/回归护栏，不能以“降复杂度”名义改变时钟、订单或 fail-closed 语义。
3. **顶层重导出扩大了循环导入面。** `backtrader.__init__` 与多个子包的星号重导出维持兼容性，
   但也让核心、live SDK 与可视化路径在导入时互相牵连。`BACKTRADER_LIGHT_IMPORT` 是现有切点，
   应变成可测试、文档化的依赖边界，而非隐式逃生门。
4. **异常处理要从数量治理走向语义治理。** 广捕获和 `pass` 有些是为 line/热路径容错保留的，
   不能批量删除；但每个必须有明确的恢复语义、可观测性或经审查的 `# nosec` 理由。
5. **质量工具必须只有一个可复现合同。** CI 使用 Ruff/Black/isort/mypy/Bandit/pip-audit，
   Makefile 却使用 Pylint/Safety；`AGENTS.md` 又把 `make lint` 描述为 Ruff。这会制造假绿或假红。

## 5. 执行顺序与发布门槛

```text
WP33-A SDK 制品/profile ─┬─> WP33-B 单一质量门禁 ─┬─> WP33-C 架构拆分批次
                         │                          └─> WP33-D 文档 warning 递减
                         └─> WP33-E 已定位的在途回归
```

1. 先完成 A1/A2：没有可信 SDK 制品和预检，不运行“全绿”宣称。
2. 再完成 B：锁定工具和本地/CI 命令，得到一份可比较的基线。
3. C/D 可并行，但每个代码批次只处理一个高风险簇；任何影响 line system、时钟、Broker/Store 的
   修改都先跑最小合同，最后跑完整策略回归。
4. E 只在 owner 提供基线后开始，绝不混入已验收的通知提交。

### 5.1 `NO-GO` 条件

- AC33-01～05 未全部通过时，不得声称完整仓库测试或 SDK 集成可复现。
- AC33-06～10 未全部通过时，不得把本地 `make quality-check` 称为 CI 等价门禁。
- AC33-11～14 缺 characterization evidence 时，不得对 Store/Broker/line system 做大规模“清理”重构。
- AC33-15～17 未达到时，不得把 Sphinx exit 0 描述为文档无警告或在线文档完全健康。
- 任一真实 CTP/SimNow 或第三方平台送达结论仍须自己的凭据、会话、制品和运行时证据；本计划不解除
  既有 fail-closed 准入门槛。

## 6. 本轮未执行项

| 项 | 状态 | 原因 |
| --- | --- | --- |
| 完整 `make test-all` / 慢策略以外的全量组合 | `NOT_RUN` | `make test-fast` 已被 SDK 契约失配阻断；先关闭 WP33-A，避免重复制造同一批级联失败 |
| SDK 锁定制品的重新安装与全套 SDK 合同 | `NOT_RUN` | 需要不污染当前 Anaconda 环境的受控制品/隔离安装流程 |
| 真实 CTP/SimNow、第三方通知送达 | `NOT_RUN` | 本轮质量审计不含凭据、账号、会话或外部写入授权 |
| 当前脏工作树 CTP/SA 失败修复 | `BLOCKED` | 等待 owner 提供干净、可归责基线 |

本文件是审计驱动的实施计划，不是当前仓库已经通过上述门槛的声明。每个 `PASS` 必须绑定最终
源码 hash、命令输出、必要制品 hash 与受影响回归；所有未执行项保持原状态。

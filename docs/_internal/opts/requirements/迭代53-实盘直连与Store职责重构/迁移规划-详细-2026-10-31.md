# `backtrader/stores` 逐模块/逐函数迁移规划（2026-10-31）

状态：**规划稿，未执行。** 本文在迭代53计划 §5 的基础上，把每个模块、每组函数/类
落到具体 owner 与目标模块，并给出前置条件、测试归属、实施波次和验收门。任何
“迁移”都必须同时满足：唯一 owner、无反向依赖、公开 API/版本、测试随代码走、
无静默回退。

## 0. 总原则

1. **Backtrader 只留框架真值**：BT Order/状态机/通知、Feed/Broker/Store 生命周期、
   BT 数据投影、Cerebro/Strategy 连接、BT 类型映射。
2. **provider 真值归 provider 包**：CTP 字段、方向/开平/投机套保、RequestID/
   OrderRef、交易日、查询与回报解释归 `bt_api_ctp`。
3. **可靠执行真值归 `bt_api_execution`**：durable intent/dispatch/fill、journal、
   outbox、容量、归档、恢复、UNKNOWN 对账；一个库只有一个 journal 写者。
4. **中立合同归 `bt_api_base`**：无 Backtrader/SDK import 的 DTO、协议、错误码。
5. **组合与部署归 `bt_api_runtime`**：服务装配、factory、CLI、生命周期；不拥有
   账户真值，不授予写权限。
6. **共享会话/行情归 `bt_api_gateway`**；只读观察/告警归 `bt_api_monitor`；
   业务风险政策归 `bt_api_risk`。
7. **不搬“混合体”**：一个文件同时含策略事实、CTP schema、执行 journal、BT 投影时，
   先拆职责，再按最小代码块迁移；未证明事务单写前不删旧实现。
8. **测试随代码走**：新 owner 用新写的公开合同测试；BT 保留集成/特征化测试；
   禁止从 archive 复制测试充当新 owner 验收。

### 0.3 依赖顺序修正（2026-10-31 实测）

原计划把 W3（journal）排在 W6（factor 事实）之前。实际尝试证明顺序应反过来：

- journal 的 fee-pair 方法直接读取 `FactorExecutionFacts` 的具体属性
  （account/quotes/target_routes 等），不是只调用一个 validator；
- journal 通过 `record_factor_position_grid` / `validate_factor_position_close_owner`
  / `record_factor_position_flat_checkpoint` 在**同一事务**写 position book；
- `bind_known_ctp_order_sysid_from_query` 要求 `type(store) is RegisteredSimStore`
  的 exact-class 身份。

因此仅注入 validator 不足以解耦。正确的顺序是：

1. **W6a**：把 fee-pair/risk 策略事实从 journal 拆到 `backtrader/research`；
   把 CTP schema/查询事实拆到 `bt_api_ctp`；
2. **W3a**：把 position book 的调用改为显式 post-commit/事务端口，或与 position
   book 一起作为 W6 的 owner 迁移；
3. **W3**：journal 只保留订单/执行事实，再整体迁入 `bt_api_execution`；
4. W4–W7 依赖上述结果。

在 W6a 完成前，journal 保持现状是符合计划 Gate 的选择，不是遗漏。

## 5. 每波 Gate

- **W1**：BT 内部 helper 抽出后，`import backtrader` 与全量单测不变；无跨仓依赖。
- **W2**：CTP 字段只在 `bt_api_ctp` 有真值；BT fake 覆盖 insert/cancel/回报/错误码；
  不要求真实账户。
- **W3**：journal 单写者、schema 迁移/回滚、UNKNOWN 不重发；BT 只通过公开 API 使用；
  隔离 wheel 可安装；无 BT↔SDK 反向依赖。
- **W4**：`ctp_i9_*`、registered-sim 原生逻辑有唯一 owner；BT 保留薄适配器；
  示例副本与 core 双实现问题收敛。
- **W5**：service 组合失败 fail-closed；direct 不依赖任何 service 包；monitor 无写权。
- **W6**：账户真值只由 provider/Broker 投影；策略归属账本单写；fee-pair 事实回 research。
- **W7**：wheel/RECORD/import graph 无旧模块；旧入口与 facade 删除；证据归档。

## 2. 目标边界与当前源码

### 职责和不变量

- **Backtrader**：Cerebro 和策略调度、Store 实例及生命周期、Feed 数据线与 bar、Broker 的 BT Order/Position/Trade、框架绑定、投影和通知。Store 非强制单例，实例与 route 必须明确关联，不为各交易所建立专属 BT adapter。
- **bt_api_py**：统一 facade、provider 发现与 route 选择、跨包会话及中立账户/行情/命令工作流；不复制 BT 引擎或 provider 事实。普通 direct 应只需 Backtrader、SDK、Base 和所选 provider，不要求安装或启动可选服务。
- **bt_api_base**：跨包中立 DTO、协议、字段、端口和通用投影，不创造账户身份、行情来源或授权事实。**provider** 持有对应原生认证、会话、规则、请求、结果及中立转换。
- **Execution、Risk、Gateway、Monitor、Runtime、ZMQ transport** 仅明确选择后承担各自持久执行/恢复、业务风控、账户域路由、观测、装配和传输职责；选中后缺包、故障或关闭不确定须明确失败，不静默回退。Monitor 观察不授予权限；聚合、拆单和算法调度仍是目标，不假称已实现。
- SDK/provider 维护真实会话、身份、请求与回报关联；BT Order 经中立请求和精确 route 绑定，provider 单次派发，无法确定结果时保持 UNKNOWN、以原身份查询，不自动换 ID 重发。来源、时间、账户完整性、权限和能力缺少依据时保持 unavailable。
- 唯一状态 owner、journal 单写者，锁/事务/关闭责任明确。策略本地归属账本与 provider 持仓分开；不把多币种、多账户无权威估值的结果简单加总。

## 4. 已发现缺陷：审阅后修复和验证

以下为静态观察，并非实际运行结论；审阅前不把相关路径标为可用：

1. **Risk v6 恢复**：非 exposure 零成交观察不含恢复校验要求的完整 exposure 字段，零值格式也不同。核对生产写入、持久记录与恢复合同，修复后覆盖写入至恢复链及缺失字段/格式分支。
2. **组合订单**：终态分支未执行非终态分支使用的版本和累计成交单调性检查。修复后覆盖终态、重复和乱序事件、累计数量回退及来源摘要重验。
3. **Broker**：`BtApiBroker._apply_order_reconciliation_completion` 中 10 处引用未定义 `command`；原 submit/cancel/query 片段位于该方法末尾，`_apply_command_completion` 当前未接续。`_parse_approval_expiry(value)` 被实例调用但签名无 `self`、亦非静态方法。`execution_recovery` 依赖 Store 尚未实现的 snapshot/armed/abort/complete 接口；确认实际合同后修复并验证。
4. **其他已登记项**：`recovery_binding_owner` 调用需要两个参数的 `_local_strategy_position_key_ref` 时只传一个；CTP `store_account_session.py` 有三处 `_require_utc` 缺失；Execution `journal.py` 有未定义 `self`，`durable_capacity.py` 有不可达的 `payload` 引用；OKX `market_stream_provider.py` 有未定义 `snapshot`。按上下文确认修复，不猜测实现。
5. **服务恢复启用判定**：Broker 的 `_uses_service_execution_recovery` 检查 session 的 `recovery_journal`，当前 `ServiceExecutionSession` 源码持有的是 `recovery_flow` / `recovery_facade`，未见 `recovery_journal` 属性。静态上可能导致该 Session 的恢复路径未被 Broker 识别；须审阅后核对实际装配和行为，再决定修复，不能据此断言恢复已可用。
6. SDK `security_compliance.monitoring.security_monitoring` 的 `.audit_logger` 引用与现有 `security_compliance.core.audit_logger` 位置不符；监控示例存在专用日志方法及旧配置/管理器缺口。按活跃入口和 owner 确认、修复或退役，不假称示例可运行。
7. **期货选择**：已有 EOD/expected-calendar 测试仍引用旧的类型和接口；快照采集器对 `product_universe` 是否具备与其他 family 等价的时间范围约束需结合 SDK 与 028 示例复核。安装夹具未固定新期货选择 SDK，research、replay 和 synthetic-live 暂时明确拒绝，需审阅后重新装配并验证。均为未运行的静态观察，不以来源覆盖或查询完成时间推断行情新鲜度。

# 迭代 53 设计文档

状态：目标设计与部分 SOURCE_WIP；目录存在或源码迁移不代表行为已验收。需求与执行顺序见[需求规划](需求规划.md)和[迭代计划](迭代计划.md)。

## 依赖与状态所有权

```text
Strategy / Cerebro → Feed / Broker / Store → bt_api_py → bt_api_base + 所选 provider
                                                ↘ 显式选择的 runtime / gateway / risk / execution / monitor
```

BT 负责自身对象、引擎运行、Feed bar、通知及本地关联；SDK 负责中立协议、facade、provider 路由和可复用工作流；provider 持有真实认证会话、字段/规则和回报事实。可选服务显式组合；direct 不依赖这些服务。Store 实例和路由必须有明确一对多绑定，不使用跨实例 Store 单例。

## 核心链路与不变量

1. **订单**：BT Order → 中立请求及本地引用 → SDK 选择精确 route → provider 依据真实 session 生成/验证订单身份并单次派发 → SDK 校验关联回报 → BT 映射 Order/通知。不存在可证明 ACK 时保持 UNKNOWN，查询原身份，禁止自动换 ID 重发。
2. **队列**：SDK `queued_command_runtime` 工作区/源码提交持有 worker、队列、generation 和完成 inbox；BT 注入回执、丢弃和健康投影。保留 FIFO/优先级、容量预留、锁顺序、停止、晚到丢弃和守恒；组件拆分不得复制状态。当前跨包接线未行为验收。
3. **行情/账户**：SDK/provider 持有订阅、原始数据、来源时钟和账户事实；BT 持有数据线、bar 水位、数据/订单关联及实例通知。source-clock/当前性未证明时明确 unavailable。
4. **持久与因子归属**：选用 execution 时由其持有 journal、schema、事务、幂等、恢复和容量；BT 仅提供其策略/订单事实和 Broker 比较。同一事务内的归属账本不能双写；provider 持仓与本地归属分开。
5. **服务**：runtime 装配与关闭属于 SDK/runtime；BT 只桥接 Cerebro/Strategy/Broker 生命周期。Gateway/Risk/Monitor/Execution 的能力和故障均需显式选择，不以现有源码或观测结果推断授权。

# 迭代 53 设计文档

> Binance/OKX 绑定式只读 runtime 的路由注册、精确 owner 和配置校验归各自 provider；Base 中立路由携带 SDK 注入的 API 类型，SDK 负责组合及有限错误转换。旧 SDK 专用注册模块和 `compose_binance_read_only_runtime` / `compose_okx_read_only_runtime` 已移除；按配置创建新 owner 可用中立 `compose_read_only_runtime`，它与复用已有 owner 的语义不同。跨包入口、线程、清理和行为待审阅后验收。CTP runtime 的路由、环境和合约字段校验归 `bt_api_ctp.managed_runtime_route_validation`；SDK 保留授权期限、会话与生命周期。该 CTP 专用 SDK 模块导入需要 provider，来源和行为未验收。

> 执行账本的凭据绑定身份格式由 `bt_api_base.execution_ledger_identity_policy` 定义，并由 provider 级入口声明；SDK 不再以 OKX/Binance 名称硬编码。内置 13 家保持原格式选择（两家凭据绑定，其余沿用历史格式），这不证明账户身份。声明缺失或插件不可发现时执行身份路径失败，历史迁移和自定义 provider 属破坏性变化；成功选择在进程内缓存。账本兼容、安装发现与行为待审阅后验收。中立风险读取是否仍需原生账户绑定由独立 provider 合同 `account_risk_source_policy` 声明；CTP 仍不可用，其他 12 家沿用旧分支，声明本身不证明来源。未注册 provider 的风险读取会失败，发现和行为待审阅后验收。

> Gateway SDK 组合器仅接受中立 `GatewayMarketBinding` 和受信 provider 工厂；删除 `GatewayOkxMarketBinding` 与 `okx_market` 参数，OKX 调用方显式提供 `bt_api_okx.market_provider.OkxTickerQueueMarketProvider`。原绑定要求每个主体覆盖全部 key，通用绑定允许非空子集；OKX key 在订阅时校验，队列/连接参数在 provider 构造时校验，校验时机发生变化。旧调用及行为待审阅后验收。

> CTP 受管风险订单 payload 的构造、schema 和撤单目标匹配归 `bt_api_ctp.risk_dispatch_binding`；Base 声明可选的 provider 合同，SDK 保留证据选择、claim、日志和 writer fence。带 schema 的目标订单现在要求对应 provider 显式声明并校验，其他尚未接入的 schema 会失败，是破坏性变更。日志兼容、provider 缺失、跨包和行为待审阅后验收。CTP 原生报单字段一致性、派发绑定、零成交观察载荷及零成交字段对照归该 provider；SDK 保留会话、类型与来源核对、日志写入和失败状态。provider 是字段对照的信任依赖。

> 中立盘口最优报价检查和中间价计算归 SDK `market_stream_contracts.orderbook_midpoint`；Feed 保留事件丢弃、分发及 bar 数据线写入。盘口来源、时间与行为待审阅后验收。

> 订单状态与成交费用字段候选由选定 provider 策略声明；Binance、OKX、CTP 和历史策略暂保留原字段及顺序。未声明的策略明确报错；其他第三方策略、动态字段覆盖及行为待审阅后验收。下单持仓模式并发栅栏也按 provider 路由声明：OKX/Binance 沿用启用，其余内置路由沿用旧不启用行为；缺少声明的路由拒绝下单，属于破坏性变更。声明不证明其他场所的持仓模式能力。

> 中立持仓行与已配置路由、合约身份的匹配归 SDK `bt_api_py.broker_event_envelope.resolve_neutral_position_route`；Broker 继续收集框架 Feed/订单绑定和维护本地持仓。匹配不证明账户来源，跨包及行为待审阅后验收。

> 未验证执行事件的中立标识字段投影归 SDK `bt_api_py.execution_event_projection`；Backtrader 保留本地订单绑定、UNKNOWN 更新和丢弃记录接线，旧投影入口委托 SDK。Store 的已完成 bar 队列及其框架投递状态继续归 Backtrader。跨包导入及行为待审阅后验收。

> CTP 受管订单与撤单身份值类型归 `bt_api_ctp.managed_request_identity`；SDK 通用请求在使用这些字段时惰性引用原类型，旧 SDK 导出保留类型别名。类型模块名、序列化、注解解析、来源绑定及可选依赖发行兼容性待审阅后验收；身份值不授予执行权限。

状态：目标设计与部分 SOURCE_WIP；目录存在或源码迁移不代表行为已验收。需求与执行顺序见[需求规划](需求规划.md)和[迭代计划](迭代计划.md)。

## 依赖与状态所有权

```text
Strategy / Cerebro → Feed / Broker / Store → bt_api_py → bt_api_base + 所选 provider
                                                ↘ 显式选择的 runtime / gateway / risk / execution / monitor
```

BT 负责自身对象、引擎运行、Feed bar、通知及本地关联；SDK 负责中立协议、facade、provider 路由和可复用工作流；provider 持有真实认证会话、字段/规则和回报事实。可选服务显式组合；direct 不依赖这些服务。Store 实例和路由必须有明确一对多绑定，不使用跨实例 Store 单例。

### 0.0 四个目录及相关功能：职责收敛范围

`backtrader/service/`、`backtrader/stores/`、`backtrader/execution/`、`backtrader/factor_execution/` 及被它们调用的 Broker、Feed、旧 runtime、SDK/provider 代码均纳入本次函数级重构范围。对现有跟踪和未跟踪源码逐项建立“文件/类/函数 → 当前调用者和状态 owner → 目标模块 → 调用切换/退役方式 → 依赖和证据”清单；不是只移动整个脚本，也不以目录数量或行数作为完成标准。目录可以在拆分后缩减、合并或删除；只有实际依赖 Backtrader 对象、时钟、Broker/Feed/Strategy 或 Cerebro 生命周期的薄桥留在 Backtrader。可破坏性改名或退役旧路径，但须同步处理活跃调用、公共导出、发行声明和用户文档。

## 核心链路与不变量

1. **订单**：BT Order → 中立请求及本地引用 → SDK 选择精确 route → provider 依据真实 session 生成/验证订单身份并单次派发 → SDK 校验关联回报 → BT 映射 Order/通知。不存在可证明 ACK 时保持 UNKNOWN，查询原身份，禁止自动换 ID 重发。
2. **队列**：SDK `queued_command_runtime` 工作区/源码提交持有 worker、队列、generation 和完成 inbox；BT 注入回执、丢弃和健康投影。保留 FIFO/优先级、容量预留、锁顺序、停止、晚到丢弃和守恒；组件拆分不得复制状态。当前跨包接线未行为验收。
3. **行情/账户**：SDK/provider 持有订阅、原始数据、来源时钟和账户事实；BT 持有数据线、bar 水位、数据/订单关联及实例通知。source-clock/当前性未证明时明确 unavailable。
4. **持久与因子归属**：选用 execution 时由其持有 journal、schema、事务、幂等、恢复、容量和本地数量比较；BT 提供策略/订单事实与待比较的 Broker 数量。同一事务内的归属账本不能双写；provider 持仓与本地归属分开。
5. **服务**：runtime 装配与关闭属于 SDK/runtime；BT 只桥接 Cerebro/Strategy/Broker 生命周期。Gateway/Risk/Monitor/Execution 的能力和故障均需显式选择，不以现有源码或观测结果推断授权。

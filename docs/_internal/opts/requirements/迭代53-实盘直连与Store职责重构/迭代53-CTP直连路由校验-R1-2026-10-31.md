## 变更

- 移除“provider 为 CTP 就无条件通过”的写路由早退。
- 普通注入的 `api` 与懒创建 `api_cls` 必须暴露静态、可读取且非空的 `exchange_kwargs`。API 构造后、Store 执行 connect/start 前检查一次；submit/cancel 交接前再次检查。
- 若 Store 有路由快照且 API 有 live map，检查规范化 route root 和完整规范化 key 集。仅有配置快照、API 没有 live map 时，普通注入失败关闭。
- 保留精确 stock CTP wrapper 的兼容路径：直接注入只认由框架工厂登记的精确 wrapper 类型和构造时绑定的同一个实例；显式 `api_cls` 只在它是登记的精确 stock 类、且 Store 懒创建的实例类型完全相同后绑定；默认懒创建路径也绑定 Store 创建的确切实例。替换对象不能继承此例外。
- 保留 `RegisteredSimStore(api=existing RegisteredSimWrapper)` 路径，但仅当 Store 类型精确为 `RegisteredSimStore`、MRO index 1 是真实 `RegisteredSimWrapper`、index 2 是框架登记的 stock CTP wrapper，并且 API 对象是构造时绑定的实例。
- submit/cancel 的最终检查传入实际准备调用的 API 实例，发现 `self._api` 已被替换时，在 fake API 收到写调用前拒绝。

## 证据范围与限制

此轮检查的是 exchange route root/key 一致性，不是写权限或 API capability 证明。它不证明 endpoint、账户、provider session、登录身份或 SDK typed/native gate。

精确 stock CTP wrapper 不公开 live `exchange_kwargs`。它只证明固定的 CTP route root。若 Store 存在带后缀的 snapshot key 而 wrapper 没有 live map，代码只能把 snapshot 的 route root 与 Store 预期 root 比对；不能据此声称 snapshot 的完整 key 集与 wrapper 的实际 dispatch key 一致。普通注入 API 有 live map 时，route root/key 也只在检查时读取；在检查结束后，API、映射或相关对象仍可能被并发改动。本轮没有实现锁或原子 dispatch，也不宣称覆盖任意自定义 API 的 capability 绕过。

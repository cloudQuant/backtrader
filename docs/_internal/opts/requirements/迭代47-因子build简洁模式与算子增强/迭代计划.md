# 迭代47 — 公式式 build 与025/026/027双模式对齐

版本：**v0.5**；更新：**2026-10-22**。状态：**规划修订；E0–E4及AC47-01–07全部NOT_RUN。**

本轮交付是在 FactorIndicator 子类中直接写 Alpha101 风格的 build 表达式，并让025、026、027三个现有示例在回测前选择 native 或 build，产出一致的研究结果。三个示例实际涉及 **CloseMA、ROC、KDJ.J、Alpha003四种因子**。迭代47只要求其中的Alpha003进入生产Alpha build目录；原“固定20式”范围取消。迭代48复用Alpha003，再补其余100式。

本文按45/46重构后的当前接口规划。历史45、46验收记录保留，但不能代替重构后的基线验收；实施前须绑定[45–46优化验收结果](../迭代45-46优化/验收结果.md)的实际状态及准确提交，不能把PARTIAL/IN_PROGRESS改写成PASS。共同要求见[四迭代路线与对齐合同](../迭代45-Indicator因子研究与多因子合成/四迭代路线与对齐合同.md)。

## 1. 用户写法与交付边界

下面是**待实现的目标API**，不是当前已经可用的接口：

```python
class Alpha003Build(FactorIndicator):
    lines = ("factor",)
    panel_mode = "expression"
    formula_fields = ("open", "volume")
    required_fields = formula_fields
    lookback_h = 9

    @classmethod
    def build(cls, ctx, **params):
        return -ctx.correlation(ctx.rank(ctx.open), ctx.rank(ctx.volume), 10)
```

作者在build里写字段、运算符、函数嵌套和局部表达式变量，不需要写资产循环、逐bar赋值、节点注册或手工调用next。CloseMA的公式主体应能写成：

```python
@classmethod
def build(cls, ctx, period=20):
    return ctx.close / ctx.sma(ctx.close, period)
```

类的参数声明、formula_fields/required_fields、lookback_h及校验沿用现有FactorIndicator约定；上面的CloseMA片段只展示公式主体。不同period仍显式计算并校验H。分母为零、非有限值和预热规则必须保持现有CloseMA行为，不能只完成正常输入上的表达式翻译。

- 保留现有native实现，供用户选择、对照和回归。build实现作为同文件内的伴随FactorIndicator子类；不再执行其native类的用户初始化，避免同一公式建两套依赖图。
- build返回代表各目标资产结果的表达式；本轮围绕现有单输出factor line实现。多输出字典、字符串公式解析、任意运行时Python回调不列为本轮前置。
- native与build在装配前选定，均经同一个FactorSpec、FactorStrategy、Cerebro、FactorPanel/sink路径；结果入口是get_panel()。不恢复已删除的get_dataset、execution、inputs/storage、外部availability/PIT表或重复身份对象。
- Alpha算子复用当前alpha101-v2 float64语义，包括稳定相关/协方差和精确浮点并列规则。生产计算不恢复历史Fraction/Decimal实现；独立测试参考可以保留高精度计算。
- 不引入第二套数值解释器、调度器、时间循环或缓存框架。自动H推导、CSE、跨实例节点共享及公式重写都不作为47退出条件。

## 2. 最小实现方案

### 2.1 build接入现有构造生命周期

当前FactorIndicator、FactorSpec均拒绝build/expression；需一起调整验证，而不是只增加一个同名方法。

1. 在绑定后的实例已具备datas、outputs、参数和研究上下文时，于该实例的OwnerContext中调用build一次。每个绑定实例/研究组各调用一次，不能逐bar重新建图。
2. ctx字段表示按目标资产关联的原生line集合；运算符及ctx函数构造现有Indicator/Line依赖。禁止用资产位置猜测绑定，必须保持目标资产映射和研究组身份。
3. 保存结果line引用，由FactorIndicator公共输出搬运逻辑处理prenext/nextstart/next；Cerebro负责所有子指标推进。保持现有调用计数、strict错误上下文和缺失窗口遮罩。
4. native类的next要求继续成立；expression类必须提供build且不混入自定义计算next。缺少实现、混合声明、错误返回、跨实例表达式或缺字段应明确失败。
5. 正常绑定通过bound_class(*datas)进入patched-init路径；不能假设新增dopostinit就会被现有调用自动执行。实现必须用实际构造路径验证owner注册和build调用次数。

最多增加一个职责明确的包内表达式适配模块；其余修改落在已有factor_indicator.py、specs.py、算子/导出文件中。优先直接复用已有类型，不为每种操作新增脚本或模块。保持现有节点诊断引用；如需适配trace，在已有测试工具中完成最小映射。

### 2.2 四种因子的语义映射

| 因子与示例 | build表达式需求 | 必须保留的现有行为 |
|---|---|---|
| CloseMA，025/026 | close / sma(close, period) | 原生SMA；H=period-1；均线为0或输入非有限时NaN；两示例参数独立 |
| ROC，026 | roc(close, period) | 原生ROC的计算顺序与比例单位；H=period；历史分母为0/非有限时NaN |
| KDJ.J，026 | highest/lowest → RSV → sma(K) → sma(D) → 3K-2D | RSV=100*(close-low)/(high-low)；high>low才有效；K、D均为现有简单移动平均；H=period+period_dfast+period_dslow-3 |
| Alpha003，027 | -correlation(rank(open), rank(volume), 10) | 当前原生截面rank、公式池、缺bar成员及RollingCorrelation；H=9；所有中间节点可验证 |

ctx在47只补以上所需的字段、四则运算、比较、where、sma、roc、highest、lowest、rank、correlation及标量广播。时间序列条件通过ctx.where表达；表达式进入Python if、and、or或bool时应明确报错，防止构图时错误选分支。

不能因为函数名称类似就替换数值实现：025/026继续用其原生指标和既有运算顺序，Alpha003继续用研究算子。共享适配需要保留有限值、除零、NaN和内部reason行为。where的未选分支也不得因急切计算触发原先没有的除零异常。

## 3. 三个现有示例的模式选择

统一新增以下**目标接口**，默认保持native：

```text
--factor-mode native
--factor-mode build
```

三个quick入口的公开config.yaml增加顶层factor_mode: native；优先级为CLI > config > native。026一次选择同时作用于CloseMA、ROC、KDJ.J，列顺序保持现有close_ma、kdj_j、roc。非法模式和未实现的build必须报错，不能静默回退。

| 入口 | 需要修改的既有位置 | 引擎选择 |
|---|---|---|
| 025_factor_single/run.py | 配置/CLI、CloseMA类选择、实际模式摘要 | 保留默认runonce及既有--runnext |
| 026_factor_multi/run.py | 配置/CLI、三个类选择、实际模式摘要 | 保留默认runonce及既有--runnext |
| 027_alpha003_panel_acceptance/run.py | 配置/CLI、Alpha003类选择、实际模式摘要 | 保留当前默认runnext；框架测试覆盖两种引擎 |
| 027_alpha003_panel_acceptance/run_daily.py | CLI、参数指纹、worker配置、类选择、结果和resume校验 | 保留当前runnext及分段方式 |

factor-mode描述因子编写方式，与runonce/runnext相互独立。不得拿runonce代表native、runnext代表build。

Alpha选择在现有get_alpha上增加可选关键字mode，目标为get_alpha(3, mode="build")；get_alpha(3)、list_alphas()及现有native导出保持兼容。47仅3支持build；其余ID请求build明确报未实现，不创建第二套注册框架。不同实现的源码指纹允许不同。

025/026的--panel是读取已有面板后评价，不运行因子；显式同时传--panel与--factor-mode应报参数冲突。配置中的默认factor_mode不得触发重算，离线摘要需清楚记录因子计算NOT_RUN。

027 daily独立于quick YAML。模式必须进入现有参数指纹并传至实际子进程，resume遇到不同模式拒绝复用。47验收限定为可复现的小型多分段、真实worker子进程和续跑用例，复用现有独立oracle；不把它描述成5,471只全市场验收。

## 4. “两种模式结果一致”的验收合同

完整合同为ALN-01–08。本轮至少固定以下层次：

1. **同一输入**：数据文件及有序资产清单、grid、字段映射、参数、H、预热/研究/尾段、公式池、方向、标签和合成配置全部相同。运行前冻结输入身份，不分别生成两份近似数据。
2. **因子配对**：同引擎下native/build完整索引、顺序、NaN/finite mask、首个有效时点、内部缺失/退化reason及有限值逐格精确相等。离散分支、排名和并列精确一致。不能用dropna交集、整行排序、相关系数或IC相近替代。
3. **独立正确性**：四种公式分别对独立参考验证。沿用已有参考的预先固定标准；Alpha连续值默认1e-12 + 1e-10*abs(ref)，离散结果精确。此oracle误差标准不作为native/build配对放宽依据。
4. **最终产出**：025/026比较factor_values.csv读回结果、保存面板、标签、单因子及合成信号、权重、消融、样本池、IC/rankIC、分组与稳定性等现有评价表，以及报告底层数据。027比较其现有因子CSV、摘要和报告数据，不额外给027增设评价系统。
5. **允许差异**：实际实现模式、源码身份、耗时、运行时间、输出路径等元信息可以不同；PNG或HTML不要求字节一致，但内容与底层数值不能删减。数值摘要仍须相同。
6. **回测含义**：这三个入口是无交易因子研究；保持原有submit/cancel为0。验收现有研究结果，不新增买卖策略或用收益率代替因子验收。

验证矩阵：

- 小型完整矩阵：四种公式 × native/build × runonce/runnext；覆盖参数变体、预热、缺bar、零分母、平坦窗口、NaN、资产重排、未来扰动、研究组及跨实例隔离。必须有有限输出见证。
- 三个真实quick入口：冻结各自当前默认500只资产清单和数据，在各自默认引擎上跑native/build配对；保留原入口完整评价/报告内容。025/026缺fincore时的PANEL_ONLY或exit 0不算完整通过，记BLOCKED或PARTIAL。
- 027 daily：小型多段子进程配对、独立oracle、同模式续跑、跨模式续跑拒绝。
- 现有全101 native回归用于防止共享底座退化，不能计为101 build覆盖。修改核心clock/minperiod时按仓库要求执行完整策略回归；只改表达式适配则执行覆盖受影响行为的研究/指标回归。
- 仓外已安装wheel运行四种公式配对及示例入口，记录准确提交、wheel哈希、实际导入来源与依赖。复用Anaconda base依赖必须如实记录，不称为全新隔离消费者环境。

## 6. 控制改动规模

- 产品代码集中在现有research模块、alpha101/alpha003.py及三个示例原文件；不增加alpha101_build包、表达式执行引擎或新的run_build.py。
- 测试优先扩展test_factor_research_examples.py及现有research/Alpha测试；alpha101_native_harness已有alpha_classes注入入口，可复用全套独立参考和逐节点验证。
- 安装验证复用verify_factor_research_installed.py；配对、性能或归因需要时扩展现有benchmark_factor_*、verify_factor_research_pair_semantics.py和diagnose_factor_research_pipeline.py，禁止为同一入口新增一套脚本。
- fincore继续负责评价和报告，不复制其算法到Backtrader。当前重构已有独立性能目标；本轮报告build相对native的实际成本，不擅自增加或降低性能验收门槛。

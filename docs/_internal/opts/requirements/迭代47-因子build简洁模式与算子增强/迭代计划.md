# 迭代47 — 因子 build 声明编译与原生算子组合计划

版本：**v0.2**；更新：**2026-10-21**。实施前置：迭代45、46必须先按各自范围独立完成并验收；当前两份计划仍将其功能AC标为 NOT_RUN，不能视为已通过。前置通过后，native Indicator/Lines/clock/minperiod 生命周期与全101 native 结果才作为本迭代的已验收基线。状态：**迭代47 的 AC47-01–07 全部 NOT_RUN**。本文是实施计划，不表示 build 前端、表达式编译或任何迭代47验收已经完成。

## 1. 定位与依赖

迭代47为因子作者提供 `panel_mode="expression"` 下的 `build(ctx, **params)` 声明入口，把声明编译成 Backtrader 原生 Indicator/Line 依赖图，并交给同一个 `FactorStrategy`、Cerebro 调度和 `get_dataset()` 结果路径执行。优先复用 Backtrader 已验收的 Indicator、Lines、owner 注册、clock、minperiod、runonce/runnext 生命周期及 `once_via_next` 适配能力。不得强制引入共享 `PanelEngine` 数值解释器或另一套私有 owner 重复调度，也不得开启第二个时间循环。

研究入口统一由 `FactorIndicator` 承载，显式选择 `panel_mode="next"` 或 `panel_mode="expression"`。表达式声明可作为定义/规格对象而不实例化成普通 Indicator；该限制只约束声明类。编译器产生的真实 Indicator/Line 节点仍须按 Backtrader 原生生命周期构造、注册并调度。单资产时序公式可在 panel 因子内部组合原生 `bt.Indicator` 子指标（如 SMA、ROC）；这些依赖不是第三种研究入口。普通独立 `bt.Indicator` 路径仍由非研究回归覆盖。

## 2. 目标与边界

### 2.1 必须交付

1. `build(ctx, **params)` 声明前端：校验字段、PIT、profile、H 和参数，将受限表达式编译为已注册的原生 Indicator/Line 依赖图；拒绝任意 Python 回调及不支持的节点，并给出可审计的编译 trace。
2. 原生调度接入：编译节点归属、clock、minperiod、预热和 runonce/runnext 行为符合既有 Backtrader 生命周期；同一 `FactorStrategy` 中用 `get_dataset()` 收集结果，不增加时间循环或第二次调度。
3. 先完成代表式 #3 的 vertical slice：native #3、build 编译后的 #3、独立参考三方对照。未通过此门槛前，不扩展到20式和混合装配。
4. 在安全范围内复用纯表达式节点；不得把“同类”当作可共享依据，也不得合并用户手写的有状态因子实例。
5. 完成固定20个代表式的 build 编译、逐式独立参考、native 对照及混合装配；#3 作为首个完整端到端验收案例。
6. 从仓库外使用已安装产物验证 build 入口、原生调度、输出与指南；明确表达式可编译范围及限制，为迭代48交接稳定的前端合同。

### 2.2 算子增强范围

迭代45已经按全101需求盘点共享算法，迭代46已实现并验收全101 native 因子。因此迭代47**不再承诺另做一轮“补齐缺失数学算子”**。本轮只增加表达式到现有 Indicator/Line 能力的适配、组合、安全缓存，以及被验收证据定位的真实缺陷修复。

不要求所有新方法都加入原有 `Indicator` 基类。算子放在职责对应的 Indicator 类或专用适配器中；若现有算子语义不符合特定 `operator_profile`，提供显式 opt-in 的专用实现，不改变旧调用默认语义。不得为 build 复制整套数学实现，也不得为了共用代码而把 API 塞进无关基类。

### 2.3 声明、节点与缓存

- `build` 声明只描述节点与组合；它不因“定义一个因子”而被实例化为普通 Indicator。编译器生成的真实 Indicator/Line 节点必须正常实例化、挂到原生 owner 并注册调度。
- 编译 trace 应显示从公式声明到输入绑定、算子节点、依赖边和最终输出的实际路径。把整条公式委托给既有 native 因子，然后把该结果包装成 build 输出，不算 build 覆盖。
- 缓存/CSE 只适用于无副作用、无内部状态的纯表达式节点，并严格限制在同一 `operator_profile`、同一输入 bindings、同一研究组及同一 time-pool 身份范围内。身份或配置不同即不得共享。
- 用户手写的有状态因子实例按实例保留；即便类相同、参数相同，也不得仅凭类名或表达式外观合并。
- 缓存命中不得改变节点的 clock、minperiod、warmup、缺失值或退化原因，也不得跨 `FactorStrategy`/数据池泄漏。

## 3. 对齐与三方 oracle 合同

ALN-01–08 是四迭代共同规范。迭代47所有 oracle 对照必须完整覆盖相同、有序的时间索引和资产索引；有效/缺失 mask 与每格缺失或退化 reason 精确一致。不得只在结果非空交集上比较，也不得先裁剪、重排或静默丢掉不匹配格。

在验收结果揭盲前冻结数值阈值：对有效数值格，允许误差为 **`abs(actual - ref) <= 1e-12 + 1e-10 * abs(ref)`**。截面 rank、布尔值、分类值、离散分支与离散输出必须精确一致；NaN/有效 mask、索引和 reason 也必须精确一致。公式池、PIT 成员、字段/行业绑定和时间池使用相同身份与版本。完整定义服从 ALN-01–08；不得事后放宽阈值结案。

#3 是首个三方 oracle：

1. 独立参考实现不调用生产 Indicator、生产算子或 build 编译器；
2. 迭代46/45已验收的 native #3 单独与参考比较；
3. `build` 编译得到的 #3 原生节点图也单独与同一参考比较；
4. 再比较 native 与 build 的结果，并验证编译 trace 确认声明真正产生了对应依赖图，而不是整式委托给 native #3。

后续20式同样要求 native 和 build 各自对独立参考，不以两条生产路径彼此一致替代 oracle。

## 6. 迭代47退出与迭代48交接

迭代47仅在 **AC47-01–07 全部通过**时关闭；实施前置仍要求迭代45、46先按各自范围独立收口，但不占用或回填AC45/46编号。迭代47不要求未实现的101 build或原论文收益。20式、混合策略与已安装产物必须分别达到对应AC，任何BLOCKED/未执行子项保持原状态。

向迭代48交付：

- 受限 `build` 声明语法、编译 trace、字段/PIT/profile/H 错误合同；
- 真实原生 Indicator/Line 节点注册、clock/minperiod 与 Cerebro 调度约定；
- 纯节点缓存边界、实例隔离及其测试；
- 固定20式逐式独立参考、native/build 三方证据和安装结果；
- ALN-01–08 实施记录及未解决缺口。

迭代48复用此编译前端和20式证据，只增加其余81式并完成101/101 build 独立参考、native/build 完整对齐与安装回归；不以整式委托native因子充当build实现。

## 7. 安全、范围与证据边界

- 不实现新执行器、私有调度循环或自由 Python 表达式沙箱；不改写已验收 native 默认语义。
- 不将全101 native 算子盘点重新包装成“47 算子补缺”工作；确有缺陷才基于复现和 oracle 修复，并使用 opt-in 专用实现避免破坏旧 profile。
- 不承诺论文收益或真实供应商 PIT，不触碰账户、私有配置、实盘进程或 CTP/live 边界。
- 性能只记录输入规模和实测资源；不能以缓存数值或一次 smoke 推断大池性能。
- 保留已有无关工作区改动；只修改本计划明确范围，不建 worktree，不推送/发布/合并 master。

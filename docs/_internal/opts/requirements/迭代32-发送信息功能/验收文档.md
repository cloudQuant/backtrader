| AC32-15 去重 | 同 `dedup_key` 在 `dedup_cooldown` 内调用 5 次、窗口后 1 次；不同 key 交错 | 窗口内只实际投递 1 次，其余 4 次返回 `deduped` 且不计数为失败；窗口后再次投递；不同 key 互不影响 |
| AC32-16 多进程静默与 fork | `maxcpus>1` 的 optimize 运行（或等价的 spawn 子进程用例），分别在 `workers="silent"` 与 `workers="send"` 下执行 | `silent`：子进程零网络、返回 `worker_silent`、主进程统计不受污染；`send`：子进程可投递（用户显式开启）；fork 后不存在"假 worker"（子进程内 send 立刻返回可判定结果，不静默挂起） |
| AC32-17 微信 ClawBot 会话锚定 | 假传输模拟：未绑定直接发送；`getupdates` 返回一条带 `context_token` 的入站消息后发送；连续主动发送超过刷新阈值 | 未绑定 → `not_bound`、`attempts=1`、不重试；绑定后投递请求含 `client_id`（每次唯一）、`message_type=2`、`message_state=2`、`from_user_id=""`、正确的 `context_token`、`base_info`；达到 `sends_since_refresh` 阈值 → `stale`/`not_bound` 并给出"需新入站消息"提示；绑定凭据文件权限 `0600` |

### 6.2 与设计的偏离（均为实现级细化，已回写文档）

### 6.3 过程中发现、并**不属于本迭代范围**的既有缺陷

**`examples/013_1|013_2/ctp_example_support.py` 在模块导入期调用 `load_dotenv(REPO_ROOT/'.env')`，把开发者本机 `.env`（含 `HTTP_PROXY`/`HTTPS_PROXY`/`SOCKS_PROXY`/`PROXY_HOST`，指向本地未运行的代理）注入该进程的 `os.environ` 且不还原。**

- 复现（确定性、单进程）：`pytest tests/unit/test_ctp_pair_examples.py tests/unit/notifications/test_transport_live.py -q` —— 前者的导入使后者的 urllib 请求经本机代理，报 `ConnectionRefusedError [Errno 61]`。
- 影响面：同一 xdist worker 内**任何**之后使用 `urllib`/`requests`/`ccxt` 的测试都会受影响（`test_ctp_sa_midfreq_example.py` 用 autouse fixture 屏蔽了 `_load_env_file`，但那是模块函数级屏蔽，对"导入期已注入"无效）。
- 本迭代处理：**只加固自己的测试** —— `test_transport_live.py` 的 `isolated_opener` fixture 显式 `ProxyHandler({})`（声明"无代理"），不受该泄漏影响；生产传输层仍尊重代理（真实部署需要）。
- 建议（另立需求）：在测试侧隔离 `/` 清理代理环境变量（例如 session 级 autouse fixture 保存并还原 `os.environ` 的 `*_PROXY` 项），或把两处导入期的 `load_dotenv_if_available()` 改为显式函数调用。

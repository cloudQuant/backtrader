## N72-03：安装失败后的事务与连接

直接调用各版本真实 _open_gateway_execution_db。store、持锁状态和路由为空是合成输入；限定状态目录为该测试的 pytest tmp_path。为绕过旧版在 Windows 上把 POSIX 权限位当作可信前置的环境障碍，仅在目标模块替换 os 叶子代理：针对该临时目录和 DB 的 lstat/fstat 提供合成 owner、目录模式和链接数，保留真实 fd/path 的设备与 inode；其他 os 调用仍走系统。Windows 安全检查模块用合成可信结果，_gateway_execution_parent_routes 返回空；这些替身不验证真实权限、ACL、安全策略或并发路径。

sqlite3.connect、BEGIN IMMEDIATE、DDL、INSERT 和锁行为使用真实 SQLite；替换的 installer 断言事务已开始，在本地 DB 建表插行后抛出固定 RuntimeError。分别记录并断言安装已调用、缓存连接、连接事务状态、第二连接立即获取写锁和失败后重复调用是否返回同一连接。旧版输出 installer_calls=1、cached=True、transaction=True、second_writer=False、reused=True，实际失败在 assert not cached；修复版输出 1、False、closed、True、False 并通过。旧版失败测试在 finally 中显式 rollback/close 该测试自身创建的连接，未操作任何保留 host。

这一红绿证明隔离条件下安装异常后旧版保留活动事务和缓存，修复版关闭连接、清缓存并释放 SQLite 写锁；不证明生产 Windows ACL、实际 Gateway 服务或账户行为。

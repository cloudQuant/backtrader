为避免向仓库写入临时 `mypy-report.txt`，本地扫描输出在 PowerShell 内存中捕获；本地错误行数按含 `error:` 的输出行计数。这是按相同正则得到的本地计数，不表示本轮实际执行了 CI 的 `grep`。

以下是 workflow 的命令片段，不是本地执行的 CI shell：

```bash

ruff check backtrader/
MYPY_THRESHOLD=0

count="$(grep -cE 'error:' mypy-report.txt || true)"
```

本轮实测：`ruff check backtrader/` 输出 `All checks passed!`、退出码 0。Mypy 输出 `Found 576 errors in 79 files (checked 695 source files)`、本地捕获的 `error:` 行数 576、退出码 1。GitHub Actions 的 `shell: bash` 默认启用 `-e -o pipefail`，本脚本还显式执行 `set -o pipefail`；Mypy 返回非零会使管道非零，并由 `-e` 在该管道后提前退出，后面的 `count=` 与阈值比较不会执行。因此本轮没有 CI `grep` 的实跑结果，也没有 Ubuntu 实跑。基于本地 Mypy 非零结果，type-check 管道会失败；零阈值保持不变。

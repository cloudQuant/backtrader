## 公共入口与 fake 边界

测试以修复提交已有 fixture `attach` 构建 broker、实际临时 pending host 和 mock 的 RPC；调用新旧均存在的 `broker.next()` 两次，不调用修复版新增私有方法。原有 `event_for` 构造无日期的成交事件，序号 4100，响应页的 offered sequence 设置为 4100。两个版本的 host checkpoint 都实际读到 `stored_sequence=4100`；每次处理都保持 `TIME_UNAVAILABLE` 且成交执行量为零。

在相同测试中包装 host 的 `read_execution_events`：`limit=1` 的事件消费读取委托实际临时 host；`limit=256` 的历史分页由相同内存数组模拟，序号 1–4099 的合成记录使用不同于目标成交的 key，序号 4100 为目标事件。分页按 `after_sequence` 顺序返回，计数每个 256 行历史分页的实际返回行数，不修改 broker 生产代码。除该模拟叶子外的持久化 host 并未持有这 4099 行，故不能把它当作真实全历史持久化或服务压力验证。

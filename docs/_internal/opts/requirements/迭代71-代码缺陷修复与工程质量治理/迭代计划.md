## 4. 目标与非目标

### 4.1 目标

- 按 `待办清单-TODO.md` 逐条解决，每条遵循「最小复现 → 最小修复 → 回归测试 → 勾选记证据」。
- 先修复 P0/P1 中**能证明会造成错误结果、错误交易状态、资源泄漏或安全放松**的条目，并补最小回归测试。
- P1 性能条目给出可复现的 before/after 基准；没有可测收益的条目不进入实现。
- 清理全部 Ruff 45 处违规与 OCR Dead Code，使 `ruff check backtrader` 保持 **0 errors**。
- 保持公共 API 兼容；不改变现有默认交易语义；不引入新 metaclass。
- 所有修改严格符合 **Fail-Closed**：不放宽安全边界，不伪造数据、不静默吞异常、不自动重发 UNKNOWN、不改变订单/成交/风控语义。
- 所有修复按小步提交，保留无关 dirty 修改；状态为 `REVIEW_PENDING`，用户 `ACCEPTED` 后才算通过。

### 4.2 非目标

- 不重写 `strategy.py` / `linebuffer.py` / `_btapi_direct_mode.py` / `btapistore.py` 等大文件；大单体仅确立边界与逐步剥离路径，不做推倒重来式破坏性重构。
- 不改变底层 `bt_api_*` 家族的 API 协议与对外合同；跨仓变更按 SDK 子仓 → 父仓 gitlink → BT 顺序另立流程（`R72-BUG-09` 标注 `[跨仓]`）。
- 不假造或放宽任何交易日历、实盘下单或风控数据前置；不批量修复全部 contrib 指标中的 P2/P3，首批只处理已复现的 P1/P2 正确性问题。
- 不把静态审阅、源码回读或 fake 运行当成真实账户、SimNow、真实 Gateway/Risk 或发行验收（均为 NOT_RUN）。
- 不做无实测收益的大规模伪优化；不因性能优化改变订单/成交/UNKNOWN/风控语义，性能改动必须先证明全序列等价。
- B026/B004 等扩展规则不计入「45 处清零」验收目标，避免目标漂移。

## 7. 风险与回退预案

| 潜在风险 | 影响分析 | 预防与应对措施 |
|---|---|---|
| OCR 误报 | 迭代 71 已发现至少 1 条（`strategy.stats.items`），本轮另排除 6 条疑点 | 71.01 逐条复现；无法复现的条目不进入实现；误报清单不重新打开 |

| Windows 安全原语等价性不足 | 补 TOCTOU 复检/ACL 收紧可能与 SDK 现有实现重复或冲突 | 先补真机测试再改代码；与 `R72-BUG-10` 统一锁门面一起设计；复用或删除 `_db_handle_from_fd` 前先决策 |

| 性能优化引入行为差异 | 缓存/索引/集合替换可能改变边界 | 优化前后全序列 parity；无等价证明不合并 |
| 闭包传参变更导致签名不一致 | 若内部函数被外部非常规反射引用，可能破坏调用 | 保持局部私有函数（以 `_` 开头）作用域受限，不暴露到公共 `__all__` |

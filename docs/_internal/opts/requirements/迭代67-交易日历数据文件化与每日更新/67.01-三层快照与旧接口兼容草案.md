# 67.01 三层快照与旧接口兼容草案

状态：**实施候选，尚未冻结或验收**。此稿将用户已决定的交易日、品种交易时段和例外三层设计转换为可以检验的合同；场所规则、六所品种清单和字段细节仍需真实来源及集成证据。它不以示例数据冒充交易所公告，也不授予账户权限。

## 快照边界

一次只绑定一个不可变组合版本，至少含交易日、品种时段、例外和来源；所有层和引用一起校验。同一版本可在多个 route 绑定，但绑定与可信日切由 SDK/调用方管理。生产加载只接受 SDK 校验后注入的完整只读快照；CTP 不依赖 SDK 文件实现。对于不同交易所或品种，可以分别有已核实覆盖和缺口；组合完整指结构与引用完整，不意味着覆盖全世界或全部年份。

每个层的内容和来源字段均为待冻结候选，标识、适用范围、起止日期（含端点约定）、来源及证据状态不可省略：

| 层 | 必要语义 | 缺失时 |
| --- | --- | --- |
| 交易日 | `venue`、已核实自然日期覆盖、逐日期开闭状态、来源；开市日期不自动证实任一合约已经上市。 | 覆盖外、无法证明或冲突的日期为 UNKNOWN；不能通过缺失记录断言休市。 |
| 品种时段 | `venue`、合约类型、品种和必要的精确合约范围、有效期、时段模板及来源。模板应区分连续交易、申报/撮合等需要支持的竞价阶段及休息，明确本地时区、起止及自然日偏移。 | 合约标识、上市有效期或模板不明确为相关范围 UNKNOWN；期权不能默认继承期货。 |
| 夜盘归属 | 每个适用交易日和作用范围明确夜盘是否存在、对应本地起始日期及跨午夜结束日期；特殊公告或休市导致无夜盘需证据。 | 无归属证明时不能以周末、前一工作日或其他市场日历推断。 |
| 例外 | 交易所、期货/期权、品种或合约、自然日期及交易日、受影响时段、变更方式、有效期和来源。 | 例外范围不明确或无法解决的重叠冲突为 UNKNOWN，不能以宽泛优先级自行覆盖。 |
| 来源 | 规则和公告身份、适用范围、获得时间、核验状态与可复核定位；实际保存内容和权限按来源条件处理。 | 不可仅因 URL 存在、人工补录或两个同源副本一致就证明事实。 |

窗口表示为 UTC 半开区间 `[start, end)`，保留交易所本地解释与对应交易日；跨午夜使用自然日偏移解释，不把结束日期猜成起始日期。相同阶段之间的重叠、竞价和交易阶段关系由适用场所规则校验；不预设所有交易所相同。复杂冲突先标记为缺口，不引入未经验证的覆盖规则。

## 两个接口的投影

1. **新时段查询合同**：根据明确的 venue、合约类型和合约身份返回状态/时段及请求范围、各段交易日与 phase、实际覆盖、缺口、来源摘要和 `calendar_ref`。分别表达有效空窗口、未上市、范围之外和 UNKNOWN；原 `windows()` 的空 tuple 不足以证明休市。具体接口和中立类型待 Base/SDK 实施并验证。
2. **旧研究期货日历**：保留 `FuturesExpectedCalendarPort` 的日盘连续时段投影和完整性、签发及来源时效检查，不因文件化把夜盘加入原有研究网格；期权不隐式进入期货专用 DTO。必须能忠实表达多个来源及其时间，不能任一缺证就伪造单来源完整快照。
3. **旧时段接口**：兼容策略须在 67.03/67.04 明确并验证；未知范围不能因旧 tuple 接口被误当作完整休市。两条旧接口源自同一个组合数据，但各自保留用途和自身合同。
4. 国债期货最后交易日或其他单合约例外按实际作用范围表达；不能将一个合约的例外自动扩展到同品种所有合约。规则、合约和查询投影分别核对。

## 样例验收需求

合成 fixture 必须标注 synthetic、不得复制到正式种子。至少覆盖：两家示例场所、不同夜盘结束时间、跨午夜、交易间断、明确归属的周五夜盘、节前无夜盘、交易所级休市、品种/单合约临时例外、期权与标的不同模板、未知/过期产品、半覆盖、相互冲突来源，以及两个国债合约不同最后交易日。每项测试需验证交易日与自然日、UTC 边界、phase、scope、版本和来源；包括旧研究只取日盘、完整空窗口与 UNKNOWN 不混淆、并发发布后两端不混版本。

**真实数据门槛**：六所各自的交易日、期货和期权品种、时段及例外依[来源核查](六家交易所交易日与期货期权时段来源核查-2026-11-11.md)逐项验证。2027 未发布或未能核实的官方资料保留缺口；合成 fixture 只能证明算法，不能证明真实年度覆盖。67.03 尚无完整六所验收证据。

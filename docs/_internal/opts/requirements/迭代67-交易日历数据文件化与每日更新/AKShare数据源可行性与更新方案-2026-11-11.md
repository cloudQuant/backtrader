## 2. 官方文档和本机公开接口验证

### 2.1 `futures_rule`

[AKShare 官方文档](https://github.com/akfamily/akshare/blob/main/docs/data/futures/futures.md#期货规则-交易日历表)将它描述为国泰君安期货的指定近期交易日规则表。官方 [futures_rule 源码](https://github.com/akfamily/akshare/blob/main/akshare/futures/futures_rule.py)通过 HTTP 获取期货公司网页并解析 HTML 表；多个数字字段使用 `errors="coerce"`，缺失不能当成零。响应受第三方页面结构和可用性影响。

2026-11-11 使用 Anaconda base 中 AKShare `1.18.64` 对公开接口做有界只读抽样：

| 调用 | 本次结果 | 限制 |
| --- | --- | --- |
| `ak.futures_rule(date="20260106")` | 155 行、10 列 | 包含交易所、品种、代码、保证金比例、涨跌停、乘数、最小变动、单笔限量、特殊调整、备注；不包含交易时段、休市日历或返回数据日期列；含期权行 |
| `ak.futures_rule(date="20261110")` | 162 行、同样 10 列 | 仅该次响应，不能据此保证全部品种/日期完整或日期参数真实生效 |
| `ak.futures_rule(date="20261114")` | `ValueError: No tables found` | 单次异常；不能把错误或空结果等同于休市 |

`date` 是请求参数而非响应中的可验证交易日字段；因此需记录请求日期及抓取时间，但不得把前者冒充来源确认的事实日。保证金等可能是期货公司口径，不自动用于账户风控、结算或下单。数据中的期货、期权需显式分类。

本机已安装的 `1.18.64` 实现使用 `requests.get(..., verify=False)` 且没有显式超时参数；本文的进程调用设置了外部超时，不能视为库本身的保证。当前 GitHub main 已使用不同的 `http.get` 实现，不能将本机版本的细节外推到最新源码。若将结果用于自动发布，须验证所选实际版本的 TLS 证书校验、超时和依赖锁定；缺失时使用可验证的受控采集实现或保持未通过，不以这次成功调用代替验证。

### 2.2 其他 AKShare 接口

- [`futures_contract_detail`](https://github.com/akfamily/akshare/blob/main/docs/data/futures/futures.md) 从新浪取单合约详情，包含自由文本“交易时间”。本次 `RB2701` 返回日盘 09:00–10:15、10:30–11:30、13:30–15:00 和夜盘 21:00–23:00，可作为时段候选；不自带逐日节假日、覆盖证明、夜盘例外或来源有效期。
- 同次 `futures_contract_detail_em(symbol="rb2701")` 返回的上午时段为 09:00–11:30，未显式表示 10:15–10:30 的间断；上期所[交易时间页面](https://www.shfe.com.cn/services/calenderandholidays/tradinghours/)将螺纹钢上午分为 09:00–10:15 与 10:30–11:30。说明不能简单接受单一文本或以两个第三方一致推断完整时段；详情页与官方规则的字段和生效期仍需核对。
- [`tool_trade_date_hist_sina`](https://github.com/akfamily/akshare/blob/main/docs/data/tool/tool.md#交易日历) 官方描述为**股票**交易日历，可作为参考或差异提示，不能直接当成各期货交易所的交易日、夜盘及假期事实。

这些是一次公开调用和文档抽查，不证明全年、全交易所、后续更新、准确性或商业使用许可；尚未进行长期稳定性、限频、安装包及跨平台测试。

## 3. 本期数据路径与后续边界

操作系统定时器默认每天北京时间 20:30 触发正常更新；更新器读取可用 AKShare 结果及明确选择的 mock／YAML 补充输入，生成带来源和范围的三层数据，执行结构校验、差异比较以及 D67-23 的自动或人工审核发布。测试使用隔离日历目录，运行中的 SDK、BT 和 Gateway 读取相应文件化版本。人工 YAML 保持 D67-36：下次正常运行读取，不设必需的独立导入命令。

- **AKShare 可用数据**：分别记录函数、版本、请求范围、获取状态和实际返回字段；空表、超时、未知身份、缺字段和不支持的日期分别报告，不能转成休市或本次成功。接口不能证明有效期、身份或覆盖的部分保留 UNKNOWN。
- **mock 数据**：开发和测试明确标注 MOCK 或 SYNTHETIC，与 AKShare 数据分别记录；接口失败后若使用 mock，报告真实获取失败及 mock 使用范围，不静默冒充真实数据或成功检查。mock 可驱动隔离环境的自动／人工审核、发布、版本切换和查询，以验证完整功能。
- **真实运行边界**：mock 不代表交易所实际开闭市、真实品种或合约时段，默认不作为真实账户运行时的可信交易日历；真实覆盖和生产使用单列 GAP/NOT_RUN。来源、覆盖、差异和数据类型须在状态与审核结果中可见。
- **后续 Opendata**：预留可替换的来源输入接口、数据来源和覆盖字段；本期不实现或依赖 Opendata、不要求对方提供 API 或服务，也不假称接口已冻结。后续取得真实数据后按适用合同接入、验证和替换 mock。
- **采集范围**：本迭代不编写交易所官网、公告或 PDF 的直接解析器。此前已做的来源调查或解析实验保留为历史记录，不转成新增实施前提。

其他既定运行合同仍按[迭代计划 §3.6](迭代计划.md#36-每日更新工具)执行：AKShare 记录版本、请求、状态、范围和摘要；可重试的临时失败最多再试两次，默认间隔 10 分钟并设置超时；空表、解析错误和冲突不冒称成功。D67-07 的 CTP 缓存优先，只有显式启用且获授权才可执行只读查询。按 D67-18 分别记录每所失败及最近成功时间，不以 mock 刷新真实来源成功时间；真实候选范围不完整或冲突不得冒称真实有效。模拟环境仍须验证变更差异、无变化、部分失败和两种发布模式；锁冲突、提交不明按原 ID 核验。D67-09 的历史查询、D67-05 的交易日切换和 D67-21/28/29 的独立邮件通知规则也未取消，详细验收见迭代计划 67.05、67.05a、67.05b。

## 4. mock 功能样例与验收

以下为**虚构示例，不是实际交易日历，也不是正式 schema 或合约代码**。六所均构造期货与期权样例，每所至少一个各自标识的 mock 品种；当年与下一年各覆盖一段固定测试日期。时间固定为 Asia/Shanghai，具体日期和合约字段由测试 fixture 声明。

| 范围 | 虚构场景 |
| --- | --- |
| 六所期货和期权 | 每所分别设置期货和期权；至少一个期权与对应期货时段不同，验证不自动继承 |
| 普通交易日 | 模拟日盘 09:00–10:00、10:15–11:30 和 13:30–15:00，以覆盖间断及边界 |
| 夜盘／跨午夜 | 模拟 21:00–次日 01:00，并显式指定夜盘自然日起始日期及所属交易日 |
| 交易所休市 | 在 mock 日期标记该交易所闭市；检查该所所有样例与其他交易所的隔离 |
| 停夜盘与临时例外 | 指定一日无夜盘，另一日仅对一个 mock 品种或合约取消一段时窗 |
| 覆盖与错误 | 两个年度、覆盖外 UNKNOWN、空 API、缺字段、冲突、无变化和变更后版本切换 |

实际 fixture 可增加不同收盘时间、集合竞价、跨周末和合约级例外；所有日期、身份和数值均标为合成。功能验收至少包括：

1. 六所分别覆盖期货和期权，检查交易日／时段／例外三层及本地、UTC 和跨日映射；不要求模拟出真实全品种全集。
2. 固定 AKShare 样本或替身覆盖正常、空表、缺字段、异常、超时及数据变化；记录失败和 mock 使用，不能将模拟替代写成来源成功。
3. 在隔离目录完成无变化、变更、版本差异、自动发布、人工审核、确认后发布、回滚／结果不明及下个可信日切加载；验证 mock 数据不能默认进入真实账户日历。
4. 检查来源切换边界：相同日历合同可接收 AKShare、mock 和未来来源声明；未来 Opendata 以独立后续集成和真实数据证据验收，不凭本期 mock 宣称已接入。
5. 三平台、安装包、Gateway 联调、通知和获授权的 SimNow 等其余计划项仍分别记录 PASS/GAP/NOT_RUN；无真实来源时不把模拟通过写成真实数据或生产验收。

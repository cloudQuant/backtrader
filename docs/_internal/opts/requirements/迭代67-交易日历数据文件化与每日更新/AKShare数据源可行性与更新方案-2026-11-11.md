# 迭代 67：AKShare 数据源可行性与每日更新方案

状态：**调研与设计建议，REVIEW_PENDING**。2026-11-11 用户提出前期通过 AKShare 获取日历数据，并给出 `ak.futures_rule(date="20260106")`；随后澄清不限定该函数，可使用其他接口或适当来源，以补全期货、期权交易日期和时间为目标（D67-35）。发布策略由 D67-23 更新为可配置自动或审核；本迭代先完成，未来采集迁往 Opendata（D67-14）。D67-03 已决定分层表达交易所交易日、品种交易时间和例外安排；D67-04 已决定通用版本仓归 SDK；D67-18 已决定部分交易所失败时可按条件发布已核验变化。具体实现及后续行为问题仍待确认。本报告的接口调研未修改交易产品代码、触碰账户或安装依赖。

## 1. 结论

目标是补全六家交易所的期货、期权交易日期、分段时间和例外，不限定单个函数；前期可结合 AKShare 其他接口和交易所公开来源。已验证的 `futures_rule` 返回品种交易规则，不能单独提供逐日休市、节前无夜盘、分段时段和临时停市；它是候选线索而非必选接口。不能把第三方网页响应当作交易所实时事实，也不能因为自动采集就推断所有日期均已验证。有变化时按 D67-23 配置自动发布或人工确认后发布；具体来源和覆盖仍需验证。

## 2. 官方文档和本机公开接口验证

### 2.1 `futures_rule`

[AKShare 官方文档](https://github.com/akfamily/akshare/blob/main/docs/data/futures/futures.md#期货规则-交易日历表)将它描述为国泰君安期货的指定近期交易日规则表。官方 [futures_rule 源码](https://github.com/akfamily/akshare/blob/main/akshare/futures/futures_rule.py)通过 HTTP 获取期货公司网页并解析 HTML 表；多个数字字段使用 `errors="coerce"`，缺失不能当成零。响应受第三方页面结构和可用性影响。

2026-11-11 使用 Anaconda base 中 AKShare `1.18.64` 对公开接口做有界只读抽样：

| 调用 | 本次结果 | 限制 |
| --- | --- | --- |
| `ak.futures_rule(date="20260106")` | 155 行、10 列 | 包含交易所、品种、代码、保证金比例、涨跌停、乘数、最小变动、单笔限量、特殊调整、备注；不包含交易时段、休市日历或返回数据日期列；含期权行 |
| `ak.futures_rule(date="20261110")` | 162 行、同样 10 列 | 仅该次响应，不能据此保证全部品种/日期完整或日期参数真实生效 |
| `ak.futures_rule(date="20261114")` | `ValueError: No tables found` | 单次异常；不能把错误或空结果等同于休市 |

`date` 是请求参数而非响应中的可验证交易日字段；因此需记录请求日期及抓取时间，但不得把前者冒充来源确认的事实日。保证金等可能是期货公司口径，不自动用于账户风控、结算或下单。数据中的期货、期权需显式分类。

本机已安装的 `1.18.64` 实现使用 `requests.get(..., verify=False)` 且没有显式超时参数；本文的进程调用设置了外部超时，不能视为库本身的保证。当前 GitHub main 已使用不同的 `http.get` 实现，不能将本机版本的细节外推到最新源码。若将结果用于自动发布，须验证所选实际版本的 TLS 证书校验、超时和依赖锁定；缺失时使用可验证的受控采集实现或保持未通过，不以这次成功调用代替验证。

## 3. 建议：自动获取 + 来源分层 + 有边界发布

```text
操作系统定时器（每天运行，不先依赖当前日历判断今天是否交易日）
    ↓
独立更新进程：适用的 AKShare 函数 / 交易所等可用来源
    ↓
受支持的交易所官网日历、时段、休市及临时公告来源（逐所评估接入）
    ↓
标准化 → 来源与覆盖核对 → 比较旧版 → 输出变化及问题
    ↓
满足已确认发布规则的部分生成候选版本；缺失、冲突和不能证明的区间明确 UNKNOWN
    ↓
版本化提交到 <calendars.root>/ctp/；运行中的 SDK / BT / Gateway 只读
```

采集与运行时分离：计划任务可联网，BT、策略和 Gateway 查询只读本地版本；AKShare 作为更新工具的可选依赖，不强制安装到不运行更新器的交易进程。按 D67-04 C，场所规则和解析归 CTP provider，中立版本仓及更新入口装配归 SDK；Base 保留中立合同。SDK 装配 CTP 采集与版本发布，避免 CTP 为此反向导入 SDK；具体接口和打包仍待冻结。Gateway 侧配置和状态转发归 63。是否支持自动读取交易所网页、具体的解析和字段覆盖应逐来源核验，不假定全部交易所有可用的机器接口。

| 数据项 | 初期建议来源 | 可自动处理与缺口 |
| --- | --- | --- |
| 已知品种、乘数及规则变化 | `futures_rule`；已有 CTP 合约目录可辅助交叉核对 | 可做品种发现、映射和差异；不能把未出现的品种断言为退市，不能把空数据变成休市，参数不自动进入 Risk |
| 普通分段/夜盘 | AKShare 合约详情形成候选；交易所公开交易时间核对 | 自由文本必须规范化并校验完整区间、午休、竞价、品种及生效期；发现冲突时只处理可证明的范围，未证实部分 UNKNOWN |
| 逐交易日及节假日 | 交易所休市与交易日安排；AKShare 股票日历只作提示 | 不以单日规则表、空响应、股票日历或国务院调休上班直接推出期货交易日；D67-12 A 目标直接发布已核实的 2027 文件化数据，来源缺失时不扩张覆盖 |
| 节前/临时无夜盘 | 交易所明确公告 | 能可靠取得与解析的来源可成为自动候选；格式变更、来源冲突或范围不明须提示，不能推断 |
| 实际合约状态 | 授权且来源可信的 CTP 状态观察，经 63/67 合同投影 | 文件日历与观测分离，不把公开页面当实际状态或授权；D67-08 B 已决定有效实时状态冲突优先，须与 63 旧合同协调 |

三类计划数据按 D67-03 独立核对来源、适用范围和覆盖，作为同一个组合版本发布；某层无法证明时不补造对应范围。AKShare 的品种发现、交易时间候选和交易所例外公告不能互相替代，具体来源的可采集性仍须验证。

**D67-36 B**：维护人员可将已核实的公告资料补入 YAML，更新器在下次计划或人工触发的正常更新时读取；无需专门导入命令，保存不直接发布。记录来源和适用范围并与自动采集候选一同校验；文件错误、来源不足及冲突须报告并按 D67-18 处理。通过校验的候选继续按 D67-23 的当前目录模式发布，人工补录不代表人工审核；文件位置与 schema 在 67.01 冻结。

**D67-34 A**：按年度维护当年和下一年，覆盖目标随年度向前推进；官方公告未公布或来源不足时须单独报告已核实范围及缺口，不能将年度目标当作已经获得完整数据。实际覆盖终点继续按 D67-31 提前预警，既有发布历史继续保留。

国务院调休日与交易所实际交易日不可简单按日一致：例如[国务院 2026 年安排](https://www.gov.cn/gongbao/2025/issue_12406/material/gwygb202532.pdf)列出 5 月 9 日上班，而[上期所休市安排](https://www.shfe.com.cn/services/calenderandholidays/holiday/)列为周末休市。比较规则应识别调休上班与交易所休市差异，不能把正常差异当成冲突。

## 4. 每日处理流程（候选）

1. **触发和重试（D67-19/20）**：默认每天北京时间 20:30 自动运行一次，包括周末与节假日；时间可由部署配置。计划任务使用上海时区，不依赖旧交易日历判断是否触发；20:30 不证明来源当天已更新或交易日已切换。公开采集的临时网络/服务故障在首次失败后最多再试 2 次，默认间隔 10 分钟，次数和间隔可配置；单次及总耗时设上限，遵守来源限流。解析或来源冲突仍需核查，逐来源记录失败；人工模式候选变化须重新确认，发布 UNKNOWN 不盲目重试。请求日期、夜盘交易日归属待 67.01 冻结。
2. **抓取**：使用固定并记录的 AKShare 版本、接口、请求参数、抓取时刻、状态及响应摘要；分开请求失败、空数据、解析错误和有数据。保存允许留存的原始响应或可复验快照；法律/来源条款和保留方式需核实。不得声称 `futures_rule` 的返回自行证明所请求的交易日。
3. **标准化**：映射交易所、品种和期权；解析已支持的时段文字，明确时区、跨午夜、竞价、时间边界及生效范围。缺字段、未知标识、不支持的写法和 NaN 保留 UNKNOWN。
4. **来源核验**：与经核对的交易所时段/休市来源及已批准版本比较；记录来源和差异。同源衍生页面的一致不构成独立交叉验证。对数据的适用日期与覆盖做显式标记，不因为当天规则返回成功就补出整个未来年度。
5. **发布策略**：成功检查的范围无变化时记录该范围成功，当前指针不变、不生成新版本；失败范围不得记为成功或已确认无变化。仅抓取时间、检查时间或运行号变化不构成内容变化。任何内容变化均生成差异，验证合格后按 D67-23 配置自动发布或经人工确认后发布；已发布版本全部保留并提供时点查询（D67-09 A）。人工确认绑定完整候选内容和差异的摘要，候选变化须重新确认。**D67-18 A**：部分交易所失败时，已核验变化可与其他场所仍在有效覆盖内、未发现明确冲突的上次已发布数据组成完整新版本，按 D67-23 配置处理后整体发布；逐所报告本次检查及最近成功时间，不以部分成功冒充全量成功。有明确冲突、覆盖不足或跨场所一致性/完整性无法证明时，不因确认而伪造事实，按适用合同报告，无法证明安全的候选不发布。
   **D67-21 A / D67-22 / D67-29 B**：本期独立邮件提醒程序在显式启用并配置后，向审核人发送变化摘要、候选标识和审核方式；人工模式下候选仍有效且待审核时按北京时间每天提醒一次，同候选同日去重，审核完成、候选失效或切自动后停止该提醒。发送失败不影响候选待审核状态，邮件不构成审核，实际投递另行取证。67 先交付命令行查看和确认指定候选，网页审核后续由 69 交付，两者共用审核与发布合同。
   **D67-28 A**：自动模式有实质变化且发布成功可证明时，启用并配置后的独立通知程序发送版本及变化摘要；无变化或发布结果不明不发送成功邮件，发送失败不回滚已发布版本。
6. **恢复**：网络错误、HTML 变化、限流、目录无权限、版本损坏及重复运行分类报告。D67-05 已决定：新版本经确认发布后，在下次可信交易日切换时对持续运行的进程生效，同日重启可加载最新已发布版本。D67-06 已决定：指针损坏时，仅可证明版本已发布、完整且应恢复时才自动恢复并告警，否则 UNKNOWN；具体提交证明实现待冻结。

## 5. 代码归属与交付分期（候选）

- **调研与小样**：按 D67-32/33 将 SHFE、INE、CZCE、DCE、CFFEX、GFEX 的期货和期权均纳入本期范围；对实际采用的接口固定依赖版本，逐所、逐类型核验品种识别、交易日、时段及例外的来源，抽查期权/期货的差异与可证明的模板共用、节前和休市日、最近及未来日期、页面变化及请求超时；形成公开 fixture 和覆盖矩阵。不能由 `futures_rule` 含期权行推断期权交易时段已覆盖；无法获得的品种、日期或来源标 GAP/NOT_RUN，不以抽样当成全量覆盖。
- **本地读写核心**：继续 67.01–67.04 的日历 schema、版本仓、种子和 SDK 接口，不改变 62 已有行为。
- **自动采集**：67.05 在本迭代实现 CTP 的 AKShare 采集器、数据清洗，SDK 更新入口装配差异报告及按配置自动或人工审核后的版本发布；逐所补充受支持官方来源。未来采集迁往 Opendata，当前不依赖它，跨项目接口尚未实现。D67-07 已决定优先使用可用的 CTP 目录缓存；缺失或不可用时，仅显式启用并获授权才查询 CTP，否则报告清单未更新并继续 AKShare 采集。
- **联合接线**：67.06–67.10 完成实际状态及 BT 接线，并与 63 Gateway 文件化扩展在版本固定、授权范围和 UNKNOWN 上联合测试。Win11/Ubuntu/macOS、安装包和 SimNow 证据按计划分别记录，SimNow 另需授权。

自动运行、发现变化、自动发布是三个独立能力；先分别验证。AKShare 数据源不是长期在线依赖，运行时不应因 AKShare 故障改变已加载快照；旧版本超出覆盖不应冒充新版本。

## 6. 测试与可观测性

- 每次运行记录来源、请求日期、获取时刻、AKShare 版本、命中行数、期货/期权分类、覆盖、变化、缺失/冲突、发布 ID 与结果；不可输出凭据。
- 用真实公开快照的固定 fixture 覆盖 NaN、空表、字段缺失、HTML 改版、无返回日期、重复品种、交易所映射、期权行、非交易日、时区与中文文本解析。
- 时段测试至少包括上期所螺纹钢 10:15–10:30 间断、夜盘跨日、竞价边界、法定假期、节前停夜盘、临时休市、未来覆盖缺失及第三方/官方差异；以已核对来源为每个 fixture 的适用时间，不把样例外推至未核验年份。
- 独立进程故障、断网、超时、限流、并发锁与提交点前后失败；D67-18 A：逐交易所区分成功和失败、失败场所成功时间不刷新，符合配置策略的局部变化以完整版本发布；D67-10 A：按受影响交易所连续 2 个交易日未成功检查时告警；D67-31 A：覆盖终点提前 30 个自然日预警，阈值可配置且与检查失败告警独立。陈旧本身不阻止覆盖内有效日历使用，覆盖外仍 UNKNOWN；时间或交易日计数无法证明时报告不确定。进程崩溃测试与断电耐久测试分开。
- 联调验证 SDK、BT、Gateway 的版本/覆盖一致性与冲突处理；63/64 同期工作使用独立测试目录、状态、端口、安装环境及运行时。

## 7. 已决定的采集与发布策略

每日更新以 AKShare 为前期采集入口、用已验证来源补齐；原候选如下：

1. **自动获取、变化自动发布**：只有满足事先确认的来源、覆盖和校验门槛才发布；冲突、来源缺失或未知范围不自动变成有效交易时段。
2. **自动获取、变化人工确认后发布（D67-14 原 B；D67-23 后适用于人工模式）**：工具提供差异，日常无变化自动完成；有任何变化须人工确认。
3. **先做自动采集和差异报告，暂不接入自动发布**：取得覆盖和稳定性证据后再定发布政策。
4. **分级发布（建议）**：每日自动采集和校验，无变化自动记录；对具备已验证来源、明确范围及完整校验的低风险变更，在约定规则内自动发布；节假日、临时休市、夜盘时间等影响待发单行为的变化先人工核对。来源缺失或冲突按覆盖语义标 UNKNOWN，人工核对也不创造缺失的场所事实。具体自动发布的内容和门槛须另行明确，不能把未核实来源视为可靠。

用户后续决定按 D67-23 配置自动或人工审核发布，并按 D67-24 在模式项未指定时默认自动；D67-25 决定同一日历根目录的 CTP 交易所统一配置。配置无法读取或值非法须报告错误。前期在本迭代完成、未来将数据采集迁往 Opendata。具体补充来源、覆盖及实现合同仍待核实和冻结；方案 4 为历史建议，不能代替用户选择。

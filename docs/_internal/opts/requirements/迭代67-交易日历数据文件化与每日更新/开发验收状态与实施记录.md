## CTP 两条既有日历链的兼容性盘点（STATIC）

- SDK 应只加载一次组合版本并向 CTP 注入同一只读快照；CTP 按交易所、合约类型、品种/合约与日期组合交易日、时段和例外。每个交易日的夜盘自然日期及归属须有明确数据，不能沿用旧实现按周末间隔猜测的规则。范围或来源缺失保持 UNKNOWN。
- 既有 `CtpTradingSessionSchedule` 提供日盘、夜盘和竞价；`CtpFuturesExpectedCalendarProvider` 及 BT `build_expected_daytime_calendars` 是研究链的日盘连续时段合同。把完整夜盘直接注入旧研究网格会改变研究结果；新全时段接口与旧投影需分别验证，不能因共享来源而改变旧查询范围。
- 现有 `TradingSessionSchedulePort.windows()` 返回 tuple，无法从空结果区分无交易窗口和范围/品种未知。新接口需要携带范围、覆盖、缺口与版本；旧接口的未知行为及兼容迁移须明确，不能把空结果当成已证明休市。
- 既有研究快照按 venue/product 组合且要求完整覆盖、来源时效及实例签发；期权种类、按合约例外及多个来源不能直接塞入旧 DTO 后宣称完整。完整年度接口不可把部分年份截取后冒充全年。
- Base 已有 `FuturesContractKind` 等中立类型可评估复用，但目录类型本身不证明期权交易时段或全量品种；旧 `rules_manifest_sha256` 含请求相关的到期叠加，不能等同组合版本内容摘要。BT 研究 `SessionWindow` 具有精度和窗口长度限制，需验证后投影，不可静默截断。
- 现有国债到期日叠加按产品合并多合约到期日期并可能将单合约例外作用于整个产品；实际影响需结合调用者和规则复核，不能直接照搬至新模型。回归需包含多合约不同最后交易日。

以上为源码盘点和实现约束，不是行为或官方规则验收。测试需覆盖同快照两端一致、跨版本隔离、夜盘归属、期权识别、品种/合约例外、部分覆盖及研究日盘兼容。

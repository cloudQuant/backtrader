### QW67-01（P1）67 不在 11-08 复核/交接范围，13 项候选决定无确认队列，且 D67-12 时限逼近

- **定位**：[复核清单](../迭代63-Gateway统一转发与多策略共享会话/archived/复核与待确认清单-2026-11-08.md) §8（:147-153，提问顺序无 67）、§11.3（:284-286，交接材料为"五份现行计划/设计"）；[迭代计划](迭代计划.md) §5（:272-288，D67-01～13）、D67-12 行（:287）、§4 表 67.01 行（:258）。
- **问题**：11-07 五份专项报告与 11-08 复核清单都只覆盖 63/64/65/66/68；67 的 13 项候选决定不在 §8 的用户确认顺序里，67.01 的验收判据"用户确认 D67"没有排期。同时 D67-12 自设触发线"67.05 不能在 12 月中旬前验收时选 b（先在常量中补 2027 年）"：截至本轮基线，67 连首轮审阅都刚发生，按 §1.1，2027-01-01 起所有 CTP 品种时段查询将全部 UNKNOWN（休市待发单不可用、R-3 日历核对 unknown）。这是同步缺口，不是对已确认决定的重提。
- **建议**：把 67 纳入复核清单 §8 的确认队列与 §11.3 的交接材料；在队列中只提行为项（D67-01、06、07b 授权、08、12、13），其余标注"由架构/开发在 67.01 定稿"；为 D67-12 设一个更早的决策检查点（建议 2026-12-01：届时 67.01～67.03 未验收即启动 67.00 过渡步骤）。
- **理由**：RVX-03 已确认"分批提问、先定阻塞第一个里程碑的少数几项"的组织方式，67 应套用同一机制而不是游离在外；2027 断档是计划自己认定的最大风险（§6.1 第一行）。

### QW67-02（P1）仓库已有一条完整的日历文档线未被盘点，新 schema 与它的规范出处关系未声明

- **定位**：[迭代计划](迭代计划.md) §1.2（:21-48，22 项清单）、§3.4（:150-185，`bt_api.trading-calendar/1`）、§4 表 67.03/67.07 行；源码 `backtrader/futures/calendar.py:418,483`（schema `backtrader.exchange_session_calendar.v1`）、`backtrader/futures/expected_projection.py:1-40`、`backtrader/futures/bundle.py:225-226`、`backtrader/feeds/market_factor_source.py:114-196`、`bt_api_py/futures_selection/models.py:170-200`、`backtrader/tradingcal.py:257`。
- **问题**：BT 研究/主力合约线已有"日历文档 schema + 严格加载器 + 证据哈希 + bundle 持久化"的完整实现，其数据源头正是 67.03 要改的 `futures_expected_calendar_provider`。计划 §1.2 的 22 项清单完全没有这条线；§3.4 新设第四种日历表示（ctp 常量、BT `exchange_session_calendar.v1`、SDK `futures_selection` 证据模型之外的新 JSON schema），既没说复用也没说边界。后果：(a) 违反 RVX-02"每个共享合同只保留一个规范出处"的方向——日历文档合同将出现两个 schema 各自演化；(b) 67.03 把 `expected_trading_days` 改为读数据文件后，`futures_selection → expected_projection → bundle → market_factor_source` 链的回归不在 67.03 的测试范围（只列了 `session_state`/`windows`/`expected_trading_days` 三项等价），67.07 的回归清单（`tests/unit/brokers`、`live_state`、`stores`、`feeds`）虽名义上覆盖 `tests/unit/feeds/test_futures_*`，但计划未点名这条链，重核时容易漏。

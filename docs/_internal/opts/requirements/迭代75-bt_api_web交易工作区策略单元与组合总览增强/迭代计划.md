## 1. 背景、核心目标与跨仓职责边界

### 1.1 问题背景与用户目标

迭代 74 已在 `bt_api_web` 中上线了基础组合总览（`/portfolio`）与运行策略表（`/strategies`），但对照机构量化交易管理终端与 `ai-for-investor` 已有交互体验，当前存在两大核心短板：

1. **运行策略页过于扁平，缺少工作区与策略单元工作台**：当前 `/strategies` 仅是一张按 Runtime 单元平铺的只读列表，无法将运行中的多个策略（如当前 SimNow 栈的 11 个运行策略）组织为“交易工作区”打开管理；无法点开单个策略单元查看脱敏参数配置、运行日志、策略归因持仓、策略级委托成交流水、持仓对比与交易日统计，也缺少受控的多单元启停/锁控操作台。
2. **组合总览信息维度不全，缺少盈亏绩效、可视化图表与来源可信度细节**：当前 `/portfolio` 仅展示 8 张静态标量 KPI 卡、3 个快捷链接与 1 张账户余额表，缺少当日/浮动/已实现盈亏、手续费与成交统计、净值/累计盈亏/回撤曲线、多空与品种敞口配置图、策略贡献与未归属残差拆分、内联核心持仓与委托流水速览，以及组合切点一致性与风控门禁健康面板。

本迭代目标是：**在不破坏 5 组件 fail-closed 架构与安全隔离边界的前提下，将 `ai-for-investor` 中成熟、高频的“交易工作区 + 策略单元工作台 + 组合总览全景视图”能力工程化迁移并升级至 `bt_api_web` 及其上游 SDK 只读/受控接口**。

## 2. 现状盘点与上游契约缺口分析

经核实当前运行中的 SimNow 7x24 全栈环境（`review7`，5 组件 `available`、11 策略 `RUNNING`）与各仓源码，现状与缺口如下：

1. **已具备、可直接复用的能力**：
   - `bt_api_runtime`：`units.json` 已登记每个策略的 `name`、`access`（`gateway/direct`）、`strategy_dir`、`heartbeat_interval_s`、`stop` 超时配置；`runs/<unit>.json` 持有 `run_id`、`started_at_utc`、`pid`、`stdout_path`、`stderr_path`；`control_service.py` 已实现 `list_units`、`unit_status`、`unit_logs(stdout/stderr)`、`start/stop`、`command_status`、`audit`。
   - `bt_api_gateway`：`/api/v1/scopes/{scope_id}/snapshot` 已提供柜台权威余额、持仓、活动委托及 `balances_complete / positions_complete / open_orders_complete / consistency / fresh_for_seconds`；`/executions` 已提供携带 `strategy`、`trading_day`、`trade_time`、`price`、`quantity`、`offset`、`status`、`error_code` 的执行流水；`/causes` 已提供账户/策略/合约三级控制原因；内部已实现 `strategy_position_ledger.py` 与 `strategy_financial_ledger.py`。
   - `bt_api_risk`：`/api/v1/risk/status?portfolio_summary=true` 已提供 exact-Decimal `equity/balance/available/margin/margin_ratio/gross_notional/priced_gross_notional/net_notional/long_notional/short_notional/gross_leverage/net_leverage/valuation_status/missing_reasons` 与逐持仓估价；另有 `/latches`、`/unknown`、`/counts/{day}`、`/policy`、`/audit`、`/cancel`。
   - `bt_api_web`：已具备 `accounts.sqlite3` RBAC、CSRF/Host/Origin/CSP 安全头、7 语种前端 i18n + `backendText.ts` 短语翻译、8 套主题配色 CSS 变量体系。

2. **核实存在的关键契约缺口（本迭代须优先闭合）**：
   - **缺口 G1（策略单元业务元数据与安全日志）**：`runtime.units.list` 目前仅返回运维状态（`state/phase/heartbeat/run_id`），不包含该策略交易的 `symbols`、`timeframe`、`bar_seconds`、脱敏 `strategy_params` 及可用 TradeLogger 日志频道；且 `runtime.unit.logs` 仅支持 `stdout/stderr` 并直接返回物理路径。同时实测策略目录下 `state/keys/*.secret` 存放 Ed25519 私钥，**绝不允许 Web 直接扫策略目录**。
   - **缺口 G2（多单元受控启停）**：`bt_api_web/runtime_control.py` 当前硬编码绑定**单个固定 `unit`**，无法在工作区对选中的多个策略单元执行受控优雅启停。
   - **缺口 G3（策略归因账本与按策略过滤流水）**：Gateway Operator HTTP 尚未开放只读策略归因持仓投影接口，且 `/executions` 尚未支持 `strategy` / `trading_day` 服务端过滤参数（仅靠最新 50 条全账户流水在前端过滤会导致高频策略淹没低频策略明细）。
   - **缺口 G4（组合盈亏、手续费与净值历史序列）**：Risk `portfolio_summary` 当前未投影 `unrealized_pnl`、`realized_pnl`、`today_pnl`、`commission_total` 与单持仓浮盈/保证金；全栈当前也缺少持久化账户净值/盈亏历史时序查询接口以绘制净值与回撤曲线。
   - **缺口 G5（本地可视化图表依赖）**：`bt_api_web/frontend/package.json` 尚未安装图表库，须引入支持 Tree-Shaking 且 100% 本地打包的 `echarts`（严禁外部 CDN）。

## 3. 三大核心模块详细架构设计

### 3.1 模块 A：交易工作区（Workspaces）与 `/strategies` 升级

#### 3.1.1 路由与导航设计
- 新增主路由：
  - `/workspaces`：交易工作区列表页（卡片/表格视图、聚合 KPI、5 组件就绪条、创建/编辑/删除自定义工作区）。
  - `/workspaces/:workspaceId`：单个交易工作区详情页（打开工作区后进入策略单元工作台与报表）。
- `/strategies` 路由兼容与升级（受 `D75-01` 确认）：
  - 推荐方案：访问 `/strategies` 自动展示/重定向至系统默认托管工作区 `/workspaces/runtime-default`（顶部提供“返回全部工作区”面包屑与工作区切换下拉框），既满足用户“把 `/strategies` 运行中的策略弄成工作区模式、可以打开展示策略运行信息”的直接体验，又保持既有 URL 书签与 E2E 路径完全平滑过渡。

#### 3.1.2 双源工作区模型（零配置可用 + 灵活逻辑编排）
1. **系统自动投影默认工作区（`id = "runtime-default"`，`readonly_membership = true`）**：
   - 实时从 `bt_api_runtime` 的 `runtime.units.list` 自动同步所有已注册托管策略（如当前 11 个 `007_ctp` 策略），无需任何手工初始化。
   - 按策略名称/脱敏元数据自动推导默认逻辑分组（如 `TickBroker` / `MixBroker` / `BarBroker` / `DualMA`，并允许在工作区元数据中覆盖自定义分组名与排序）。
   - 不可删除，确保任何部署打开即可看见完整托管运行策略。
2. **用户自定义逻辑工作区（持久化于 `bt_api_web` 本地 `workspaces.sqlite3`）**：
   - 表结构精简严格：`workspaces(id, name, description, tags_json, layout_json, created_by, created_at_utc, updated_at_utc)`、`workspace_unit_bindings(workspace_id, unit_name, group_name, display_name, sort_order, notes, pinned)`。
   - **严格安全边界**：自定义工作区只允许绑定 `bt_api_runtime` 已注册的合法 `unit_name`；**绝不存储交易所 API Key / 密码 / 策略源码 / 物理目录路径**；删除自定义工作区仅删除编排元数据，**绝不停止或注销底层 Runtime 进程**。
   - 权限边界：`viewer` 可查看全部工作区与单元详情；仅 `admin` 可创建/编辑/删除自定义工作区与调整分组绑定（`runtime-default` 的只读展示对所有人开放）。

#### 3.1.3 工作区列表页与详情页布局
- **列表页（`WorkspacesListView.vue`）**：

## 4. 跨仓接口契约清单（概要）

### 4.1 `bt_api_runtime` 增量契约
- **`runtime.unit.metadata`（只读，`viewer` 可用）**：
  - 入参：`unit_name`（或批量省略返回授权单元摘要）。
  - 返回字段（严格白名单）：`unit`、`access`、`kind`、`started_at_utc`、`symbols`（`list[str]`，`<= 32`）、`exchanges`、`timeframe`、`compression`、`bar_seconds`、`contracts_summary`（仅 `exchange/multiplier/price_tick/quantity_unit`）、`strategy_params`（递归剔除任何敏感键、密钥值、绝对路径，限制深度 `<= 3` 与总大小 `<= 8 KiB`）、`available_log_channels`（逻辑名称列表如 `["stdout", "stderr", "system", "signal", "order", "trade", "position", "value", "bar"]`）。
- **`runtime.unit.logs` 扩展（只读，`viewer` 可用）**：
  - 新增可选参数 `channel: str = "stdout"`（枚举白名单：`stdout | stderr | system | signal | order | trade | position | value | bar`），保留 `lines`（硬限 `1..1000`）并新增响应字节上限 `max_bytes`（默认 `131072`，硬限 `262144`）。
  - 内部解析最新 `TradeLogger` 目录并验证 `realpath` 严格位于 unit 的 `logs/` 子树下、拒绝符号链接、拒绝 `..`、拒绝非白名单文件名；**向 `bt_api_web` 返回投影中移除原始物理路径 `path` 与 `tradelogger_dirs`**。

### 4.2 `bt_api_gateway` 增量契约
- **`GET /api/v1/scopes/{scope_id}/strategy-attribution`（只读，需 Gateway session + provenance proof）**：
  - 返回 `status: OBSERVED | UNAVAILABLE`、`source: {journal_id, owner_generation}`、`trading_day`、`baseline_ready: bool`、`strategies: [{strategy, positions: [...], financial_summary?: {...}}]`、`external_baseline: [...]`、`unallocated_residual: [...]`、`authority_note`。
  - 若 `strategy_position_ledger` 未建立或基线校验未通过，fail-closed 返回 `status: "UNAVAILABLE", reason: "STRATEGY_LEDGER_UNAVAILABLE"`。
- **`GET /api/v1/scopes/{scope_id}/executions` 扩展**：
  - 增加可选查询参数 `strategy`（合法策略标识正则校验）与 `trading_day`（`YYYYMMDD` 校验），在 SQLite 查询层完成过滤，保持 `limit <= 100` 与 `before_sequence` 游标不变。
- **`GET /api/v1/scopes/{scope_id}/equity-series`（依 `D75-03` 拍板决定落 Gateway/Risk 或 `bt_api_web` 采样缓存）**：
  - 返回有界时序点 `[{observed_at_utc, trading_day, equity, balance, available, margin, unrealized_pnl, realized_pnl, valuation_status}]` 与显式 `series_source`、`completeness` 元数据。

### 4.3 `bt_api_risk` 增量契约
- **`GET /api/v1/risk/status?portfolio_summary=true` 向后兼容扩展**：
  - 在 `portfolio_summary` 中新增可选 exact-Decimal 字符串字段（缺失一律为 `None`）：`unrealized_pnl`、`realized_pnl`、`today_pnl`、`commission_total`；单条持仓新增 `unrealized_pnl`、`margin_value`。

### 4.4 `bt_api_web` 新增 API 路由总览（全部 `extra="forbid"` + 回环 Host/Origin/Session/CSRF 校验）

## 6. 不可退让的安全红线、性能预算与兼容约束

1. **零私钥、零凭据、零宿主物理路径泄露**：
   - `bt_api_web` 永远不直接读取策略目录文件系统，必须经 `bt_api_runtime` 白名单接口投影；
   - `bt_api_runtime` 侧硬拒绝 `state/keys/*`、`*.secret`、`*.sqlite*`、`*.lock`、`tokens.json`、`operator.json` 及任何路径穿越/符号链接；
   - 脱敏配置递归剥离 `token / secret / password / api_key / auth_code / passphrase / private_key` 及本地盘符路径；
   - 彻底移除 `ai-for-investor` 的 `openUnitRuntimeDir` 能力。
2. **Fail-Closed 与账本隔离铁律**：
   - 任何缺失的盈亏、手续费、保证金、最新价、名义市值、杠杆、回撤字段**一律返回 `null` 并在前端渲染 `—`**，同时展示 `missing_reasons`，**绝不补零、绝不前端拍脑袋估算**；
   - **Gateway 柜台权威持仓**与**策略归因持仓**严格分表/分栏展示并标注权威声明，绝不混算相加；
   - 受控写操作（启停/撤单/风控控制）超时或响应异常时**一律返回 `UNKNOWN`**，强制锁定原 `command_id` 仅允许查询账本，严禁自动重试或新造 `command_id`。
3. **严格同源 CSP 与离线机构级可用性**：
   - ECharts 必须经 npm 安装并由 Vite 本地构建打包进 `static/`，**严禁引入任何外部 CDN 脚本/字体/图标**；
   - 所有新增 UI、表头、空态、错误原因与 ECharts Tooltip 必须完整覆盖 7 种语言（`zh-CN/en/fr/ja/de/ko/ru`）与 8 套配色主题（含深色/浅色高对比度可读性）。
4. **性能与资源硬预算**：
   - 单次 `/api/v1/portfolio` 与工作区聚合读预算维持 `<= 1.8s`（线程池并发读取上游，局部超时局部降级不拖垮整页）；
   - 日志拉取单次硬上限 `1000` 行 / `256 KiB`；执行流水单页硬上限 `100` 条；前端图表大数据量启用 ECharts LTTB 抽稀避免主线程卡顿。
5. **向后兼容约束**：
   - 既有 `/api/v1/dashboard`、`/api/v1/portfolio` 原有 JSON 字段、`/overview`、`/runtime`、`/gateway`、`/risk`、`/execution`、`/monitor`、`/calendar`、`/positions`、`/trades` 路由及既有 `accounts.sqlite3` 账户数据保持 100% 兼容，无破坏性字段删除。

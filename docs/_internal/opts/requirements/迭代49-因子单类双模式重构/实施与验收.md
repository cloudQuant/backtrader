## 接口决定

```python
alpha = get_alpha(3)  # 两种模式使用同一个类
native = FactorSpec("native", alpha, "factor", field_bindings=bindings, mode="native")
built = FactorSpec("built", alpha, "factor", field_bindings=bindings, mode="build")
# 在已有策略中直接绑定也可选模式：
factor = alpha.bind(data0, data1, mode="build")
```

- `mode=None`根据类实际能力解析：有原生next时默认native，否则使用build；双实现默认native。显式请求不存在的模式或非法值明确报错。
- 模式属于FactorSpec/绑定实例，不改写原类属性。`factor_mode`反映实例实际模式。模式独立于runonce/runnext，并进入metadata、运行身份和daily续跑指纹。
- 同一类可在同一FactorStrategy同时绑定两种模式、不同参数和不同研究组；状态与子图互相隔离。
- build选择必须跳过用户原生初始化和原生各计算阶段；native选择不调用build。保留原有参数解析、OwnerContext、字段绑定、真实子指标、原生调度和显式H。
- 使用现有私有bound类实现分流，不新增公共模式包装类、共享可变选择器或第二套调度器。
- 全101个Alpha、025/026示例的build方法并回对应原类，删除公共Build伴随类及重复声明。保留原类名与默认get_alpha/list_alphas身份；旧`get_alpha(..., mode=...)`明确失败，迁移到`FactorSpec.mode`。不让旧调用静默跑成默认模式。
- classmethod build签名和公式运算顺序不变；此次不修改数值算子、fincore评价数学或恢复Dataset/PIT。

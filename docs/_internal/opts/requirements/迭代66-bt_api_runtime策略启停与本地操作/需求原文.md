## 3. 解读说明（起草人注，非用户原话）

- 原话 2 中的“写一个写的迭代计划”，按上下文理解为“写一个新的迭代计划”；原文照录不改。
- 原话 3 中的“继承到ai-for-investor”，与迭代 65 需求原文的同一用语一样，按上下文理解为“集成到 ai-for-investor”；原文照录不改。集成本身不在迭代 66 范围内，本迭代只要求接口适合以后集成。
- 原话 3 中的“按钮放到runtime里面，会有本地的操作命令”，计划按以下理解设计：按钮背后的执行者和本地入口（命令行）在 runtime；图形界面以后由 ai-for-investor 作为 runtime 的客户端提供，本迭代不做图形界面。如果用户的本意是 runtime 自带一个本地网页按钮，见计划 D66-19。
- 原话 3 中的“微服务”，计划理解为：runtime 是常驻的服务进程，有自己的配置、状态存储和受鉴权的接口。迭代 65 中 execution 的“微服务形态”采用 ServiceHost + CURVE；runtime 的接口传输方式另作决定（计划 D66-03），因为 runtime 在没有 Gateway 的部署里也要可用。
- 63 控制面分析对 S-15 的选项 a 还包括“Gateway 部署下 monitor 控制台作为可选前端转发”。原话 3 没有提到 monitor 控制台，计划不把它列入本迭代（计划 D66-19）。原话 8（S-20）之后，monitor 不发出控制命令，这一选项不再可选。
- 原话 4（S-01）与 63 控制面分析的建议（选项 a：risk 作为库运行在 Gateway 进程内）不同，用户选了独立的风控服务、放在 Gateway 之前。它对迭代 63、64 计划的影响由主会话登记，本迭代不改其他迭代的正文。对 runtime 的影响只有一点：Gateway 部署中，risk 成为又一个需要有人启动的服务进程（计划 D66-02），以及策略启动前检查是否要查看 risk 服务的就绪状态（计划 §3.4）。
- 原话 5（S-13）表明，不选 risk 时自成交保护缺失是已知的功能缺失。runtime 不承担自成交检查，也不把“是否启用 risk”作为启动策略的前提。
- （2026-11-06 晚改）S-16～S-25 已由用户回答（U66-8～U66-17）。原先本条写的“尚未回答、S-19 待定”及计划中相应的“待定”表述已删去，计划改动见计划修改记录。
- U66-10（S-18）的次序与 63 控制面分析 §2.4 第 4 条的建议不同：分析先发 SIGTERM，超时后再请 Gateway STOP_NEW、DRAIN；用户的次序是对**已判定不响应**的进程先 DRAIN、再 SIGTERM、再 SIGKILL，且不含 STOP_NEW。计划把“正常停止”（进程有响应时的 SIGTERM，即 U66-15 的优雅停止）与“不响应时的升级”分开写，升级按用户次序；“怎样判定不响应”是计划的设计，待审阅（计划 §3.5）。
- U66-9 与 U66-10 中“direct 拒绝暂停”“direct 从 SIGTERM 开始”是同一事实的两面：direct 部署没有 Gateway，也就没有急停状态（S-23 a），runtime 无处下达 STOP_NEW、FREEZE 或 DRAIN。
- U66-11 与 63 计划的关系：控制端口、runtime principal 的权限和急停状态机都在 63.12 实现（原话 7：Gateway 相关开发都在迭代 63）；runtime 只是控制端口的客户端，不改 `bt_api_gateway`。RESUME 按 U63-9 “只能由运营执行”；runtime 的“恢复”按钮怎样满足这一点，见计划 D66-08。
- U66-15 的核对：用户转达时说“尚未合入”。主会话 2026-11-06 22:50 核对时，backtrader 本地 `dev` 已有提交 `56bacb32b`（2026-11-06 22:43，“SIGTERM requests a graceful Cerebro stop in the 007_ctp examples (S-23)”，新增 `backtrader/live_trading/graceful_stop.py` 并改 22 个 `run.py`），未推送到远端，也未经用户验收（STATIC）。计划只引用它，不重复实现。
- U66-16：runtime 只使用 `bt_api_base` 的统一急停词汇（63.02）；计划中“暂停/恢复”是界面上的按钮名称，发往 Gateway 的动作一律是 STOP_NEW、FREEZE、DRAIN、RESUME。
- U66-17：租约过期自动 DRAIN 由 Gateway 自己判定和执行（63.12），runtime 不配置、不触发，只显示该原因；它在升级时看到策略已被排空，如实显示。

## 4. 主会话归纳的目标（非用户原话，供审阅核对）

- `bt_api_runtime` 负责策略进程的登记、启动、停止、重启和状态查看；一个策略目录就是一个实例。
- runtime 提供本地操作命令（命令行），并作为常驻服务提供受鉴权的接口，以后供 ai-for-investor 集成。
- runtime 不在下单路径上，不发送或撤销订单；停止策略时走 BT 自己的优雅停止（迭代 62 的 direct 停止：只撤本策略的活动单，不平仓；SIGTERM 入口见 U66-15）。
- runtime 在 direct 与 Gateway 两种部署中都可用（U66-8）。
- “暂停/恢复”按钮是下单控制，不是进程启停；它映射为策略范围的 STOP_NEW 或 FREEZE 与 RESUME，经 Gateway 控制端口交给 Gateway 执行（U66-9、U66-11）；direct 部署拒绝。
- 进程不响应时，Gateway 部署按 DRAIN → SIGTERM → SIGKILL 升级，direct 部署按 SIGTERM → SIGKILL（U66-10）。

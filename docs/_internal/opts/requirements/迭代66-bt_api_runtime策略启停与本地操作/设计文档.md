## 2. 组件与所有权

```text
CLI / 独立前端 / 未来 AFI 客户端 --认证、授权--> runtime 本机服务
                                     |-- 命令台账 / 审计 / 本机登记
                                     |-- 进程适配器 --> 策略目录 run.py --> BT / SDK
                                     |-- 状态与摘要 <-- BT 进程合同
                                     +-- 可选 Gateway 控制客户端 --> 63 控制端口
                                                             +--> 策略范围急停
                                     +-- 可选、单向事件 --> Monitor（只观察）
```

runtime 负责策略进程生命周期、受限本机控制和操作审计；BT 保留 Cerebro 调度、Broker 停止、订单/持仓和本地状态；SDK 持有写入准入及中立会话协调，provider 拥有场所事实。Gateway 拥有自身会话、账户/行情转发、急停原因和实际执行；Risk/Execution 仅在显式选择后承担各自职责。runtime 不调用下单/撤单，不加载策略或 provider 代码，不持有账户凭据或订单事实；策略进程不导入 runtime。direct 监督不因使用 runtime 而安装、导入、启动或连接 Gateway、ZMQ、MessagePack codec、Risk、Execution、Monitor（INV-01）；选定组件失败不得回退绕过。

D66-02 的首期策略监督包括注册、start、stop、status、adopt 等；Gateway、Risk、Execution、Monitor 由各自入口或系统服务管理器运行。runtime 可读取/检查已选服务状态，并按既定授权通过 Gateway 请求策略范围暂停或排空，这不构成服务启停。停止策略不联动停止共享服务；所选前置服务不可用时按既定 fail-closed/所选组件故障合同处理，不代启动、不回退。Risk 仍可选，不建立固定 Gateway → Risk → Execution 启动硬依赖。

**D63-03（Q35 已决定）**：Gateway 断连时策略进程继续运行等待恢复，相关写入不可用，不回退 direct。runtime 的进程存活、Gateway 连接与写入资格分别展示；不能只因 Gateway 失联判断策略退出，或自动 stop/重启。显式用户 stop/restart 和真正异常退出时 D66-09 的策略仍独立有效。在场委托或在途请求在失联期仍可能成交；无法核实时显示 UNKNOWN/PARTIAL，不宣称已停止、已撤单或终态。连接恢复后以 Gateway 的对账、回报补齐及准入结果展示，runtime 不自判可交易、不自动 RESUME、不盲目重发。

监管目录与策略 `state/` 隔离：runtime 只读策略身份及 BT 为监督准备的状态；不写 `state/`、`logs/current_position.yaml`，也不通过尝试持有 `state/run.lock` 探测进程。若采用停止文件兜底，请求只写 runtime 专用受限控制目录，BT 只读消费。runtime 不能因心跳或预检成功认定交易授权、账户完整、订单终态或对账通过。

## 3. 配置与启动合同（候选）

单元登记为 `{unit_id, kind, strategy_dir, entry, interpreter, args, access, heartbeat_interval_s, start_timeout_s, stop, credential_reference}`；`kind` 是待冻结的候选字段，首期仅支持策略类型，未知或首期不支持的类型在注册、配置校验和操作时明确以有限码拒绝。服务类型仅预留未来版本化接口及配置扩展位置，不实现服务单元 start/stop、注册或自动发现启动。`access` 为 `direct | gateway`；后者另持 Gateway 端点和已登记主体的安全引用。策略 UUID 由 BT 只读接口加载，未初始化为 `NOT_INITIALIZED`。每次启动生成新的不可预测 `run_id`，与持久策略 UUID 不同；同目录不同 run 不能共用观察或停止请求。登记解析基于配置文件所在目录，拒绝未知键、目录别名冲突、路径逃逸、无效超时、Gateway 缺连接信息；不按当前工作目录解析。解释器与入口为明确路径，拒绝 shell 插值，日志不打印密钥或参数中的秘密。

候选凭据方式 D66-11(a)：只把 env 文件**路径**交给策略 `run.py`，runtime 不读取该文件；子进程环境使用按平台冻结的最小白名单。Gateway 策略按 63 不持有场所凭据。是否允许其他交付方式仍待决定。启动前只读预检仅显示诊断，不能代替 SDK/BT/Gateway 的准入。不得自动 `--first-init`、rebind、resolve、平仓或 RESUME。`init` 若最终选用，须是显式、授权和审计的独立入口，并设计首次身份未生成时的并发预留。没有可信账户 scope 时，跳过检查并提示不构成互斥通过；D66-12/13 的入口、可信 scope、互斥和失败方案仍须冻结，未证明前相关门禁为 GAP，不假定已约束手工或跨主机写者。

启动事务：验证登记、授权和进程身份；原子占用单元并按 D66-13 最终决定对 runtime 管辖范围内同账户预留；先持久化命令及启动意图，再在策略目录中独立拉起 `run.py`，传入 run_id 和由受限目录限定的状态/摘要路径；记录 PID、进程创建时间、boot 身份、可验证命令行摘要、平台进程组或 Job 身份和日志路径。持久化与 OS 拉起之间没有原子事务：如果崩溃后无法证明是否拉起，不重发启动，标 `UNKNOWN` 并核验。仅本 runtime 的并发检查不证明不存在其他监督者、手工进程或跨主机写者。

BT 启动步骤之间应检查已锁存停止，停止新步骤并清理已获得资源；不能将“启动未完成”推断为没有派发或结算写入。在 D62 恢复合同下，已有持仓、活动单、历史委托或在途结算需要按原身份和会话核验；缺少完整且可信的事实时保持 UNKNOWN、阻断相关新交易写入，不由 runtime 猜测或清除。恢复到可观察状态不等于已获写授权。

**Q31 / D66-09 策略异常退出自动重启（已决定，未实现）**：默认 `never`；可逐策略显式启用“异常退出后重启”，并配置有限尝试次数与有界退避间隔，枚举具体名称、字段和计数窗口由 66.01/66.04 冻结。开启却缺参数、值不合法或越界时明确拒绝，不静默回到关闭、不允许无界重启。自动尝试只针对异常退出的目标策略：必须可靠确认原 run 的目标进程已经实际退出、该策略相关未决写入/UNKNOWN 已解决或经权威事实证明不存在，且满足当前启动硬门禁。无法证明、`BLOCKED` 或相关在途/UNKNOWN 时不自动重启；不能由心跳 STALE、PID 复用、超时或异常退出单独推断旧进程已退出或事实完整。不因其他策略无关 UNKNOWN 扩大为全账户自动阻断，独立的账户级硬门禁仍适用；自动资格不改手动启动和恢复合同。

运行记录分别标识异常退出与用户 stop、显式 restart、force 退出；用户正常 stop 不触发自动重启，显式 stop 撤销尚待执行的自动尝试。以持久生命周期代际和原子裁决防止旧退出通知、退避回调或多控制者在 stop 后重拉；尝试前重新核验身份、退出、权限、门禁、代际及剩余预算。持久保存尝试次数、退避和代际，runtime 重启不能无限重置次数；跨 boot 或时钟不可比较时不能假定退避已到期或缩短等待。其他启动硬门禁满足时，适用 DRAIN、FREEZE 或 STOP_NEW 本身不阻止已配置的异常自动重启，启动后须显示原因并继续受限。新策略进程按原身份重新启动并对账，不代表可交易，不自动 RESUME 或解除 Gateway 急停/UNKNOWN；策略进程政策不管理共享服务，区别于 Q29 的 Execution 已重启后的母单恢复政策。

## 4. 运行身份、进程状态及恢复

BT 原子发布版本化状态和最终摘要：至少含策略 UUID、run_id、PID、进程创建身份、boot 身份、序号、UTC 记录时间、同 boot 单调时间、阶段、有限错误码、停止预算和独立的未决事项。文件只允许固定 schema 和大小，采用临时文件、必要的持久化及原子替换；权限、符号链接、路径替换及读写失败均需明确处理。BT 单调递增序号防止旧文件倒退；写失败不能以空值表示成功。主循环进度与心跳分别呈现，心跳只是生产者自报。

候选状态映射：

| runtime 状态 | 触发/约束 |
| --- | --- |
| `NOT_INITIALIZED` | BT 只读身份接口确认策略目录尚未初始化；身份文件损坏、不可读或身份不匹配分别报错或 UNKNOWN，不能当作未初始化。 |
| `INITIALIZED_NO_RUN` | 身份有效，且能确认该单元没有历史 run；只是可进入启动硬门禁的候选状态，不代表账户干净或可交易。已有历史但记录缺失、损坏或旧摘要不能匹配时为 UNKNOWN，不得冒充从未运行。 |
| `STOPPED` | 已知本次 run 的进程结束，且最终摘要通过 schema、策略 UUID、run_id 与进程身份核验；摘要状态明确为 `STOPPED`，活动单、在途写入及其他规定的未决字段均明确表示已解决或无未决。字段缺失、损坏或 UNKNOWN，或存在活动单/在途写入时不得报干净停止，应分别报告相应未决状态或 UNKNOWN。该状态仍不证明整个账户无委托、持仓或风险。 |
| `STARTING` | 拉起已知且等待同 run 身份；启动观察超时不证明进程不存在。 |
| `RUNNING` | 身份匹配且心跳新鲜；`RECONCILING`、`WARMUP`、`LIVE` 为 BT 自报子阶段，不赋予交易权限。 |
| `STALE` | 心跳过期的健康标签；自身不触发停止或 DRAIN。默认三个间隔仅为候选。 |
| `STOPPING` | 已持久化停止意图，保存阶段、起点和结果；断线不视为停止完成。 |
| `STOPPED_WITH_WORKING_ORDERS` / `STOPPED_WITH_WRITE_IN_FLIGHT` | 来源于匹配摘要；同时显示每个未决字段，前者不能因后者覆盖而消失。 |
| `BLOCKED` / `CRASHED` / `KILLED` / `LOST` | `BLOCKED` 须有绑定本 run 的可核验启动拒绝记录；其余分别代表已知异常退出、已确认强杀、无法证明原因的消失。退出码 2 只是观察，不能单独证明 BLOCKED；没有有效摘要按 INV66-04 报告进程结局和撤单未知，不能说已干净停止或撤单成功。 |
| `UNMANAGED_RUNNING` / `UNKNOWN` | 前者只观察，是否允许显式 adopt 由 D66-10 确认；身份、命令副作用或账户事实无法判明时为 UNKNOWN。 |

命令受理/结果、进程状态与停止结论独立呈现。`start` 在观察到 RECONCILING 时标记 APPLIED 只表示启动请求已落实、进程已观察，不能推断对账完成、交易授权或可交易；与 BT/SDK 给出的阻断和恢复状态同时显示。

按 D63-41，公开默认 `getcash/getvalue/getposition` 查询账户，显式策略 getter 查询策略，下单辅助继续使用策略隔离事实；runtime 及监控的账户查询不要求重复配置策略资金，未配置的策略资金视图仍不可用。D65-27/28 的虚拟仓及平仓转换、STOP_NEW 专门例外由 Gateway 等 owner 执行；runtime 只展示 Gateway 权威原因和其公开的转换可用性，缺证据显示 UNKNOWN，不自判放行，也不把普通 OPEN 视作例外。

接管前及每次操作前核对 PID、创建时间、命令行摘要、run_id 与 boot；这些检查本身不能消除检查后目标退出和身份复用的 TOCTOU。发信号必须使用该平台可验证、与目标身份稳定绑定的句柄或等效能力，且证明该操作实际作用的进程或组成员属于本次 run 的授权范围。对进程组先扫描成员再 `killpg` 仍会发生 leader 退出、组复用和成员脱组/加入竞态，不能单独作为范围证明；无法实现稳定身份绑定或无法证明成员范围时，拒绝该操作并记录 UNKNOWN，不以降低验证要求补齐跨平台支持。Job/进程组只覆盖可证明受控的成员，脱组后代不能假称已清理；必要时逐个使用稳定句柄操作并保留未覆盖项。runtime 重启不终止策略；接管的非子进程无法取退出码。最终摘要仅在 schema、UUID、run_id 和进程身份全部匹配时有效；旧文件、损坏文件或退出码 0 均不能证明安全停止。

停止计时用本次启动同一 boot 的单调时钟，持久记录 boot 标识、起点和原始预算；审计另记 UTC。runtime 同 boot 重启后只有时钟及身份可核验才续算。跨 boot、boot 身份缺失、时钟不可比较或起点不可靠时不把 UTC 差值或旧单调值当剩余预算，也不自动强杀：标 UNKNOWN，等待操作员依明确授权处理。不能把启动时的相对超时跨机器/跨 boot 复用。

## 5. 停止、升级与对账

普通停止先验证目标并记录命令，再向主进程请求优雅停止；已选 Execution 时按用户决定取消该策略未完成母单余量并尝试撤其场内子单，63/65/66 冻结受权停止屏障及持久取消合同。用户后续取消了本期重启后提示或操作原母单余量重新下单的功能，原订单及成交继续按权威事实对账；进程启动和原单终态分别判定，见共同合同 §2.33。POSIX 使用 SIGTERM，Windows 采用可验证的 CTRL_BREAK 或待 D66-05 决定的停止文件。BT 锁存请求、阻止新增写入并走自身停止合同：只处理本策略可关联的活动单，等待回报，不平仓。迭代 62 direct 路径的休市待发单保留按其既有合同处理；已选 Execution 的正常停止须按上文取消其母单未派发余量，不能将 direct 待发单政策套用于它。**停止时可能已有结算确认在途**：即使新写入栅栏已关闭，已经提交的写入仍可能到达场所；不能靠进程停止或请求超时推断未发生。BT 发布的预算必须涵盖当前实际串并行关闭阶段、在途等待和收尾余量，不把 10 秒撤单与 35 秒在途等待机械相加或取最大值当作已验证总上界。预算无法证明时不宣称可自动强杀。

对有响应的进程，先按普通停止等待；超过候选的 `max(graceful_timeout, BT预算+余量)` 或起始状态已失联时进入升级。Gateway 升级先向 63.12 控制端口提交该策略 DRAIN，记录所有原因及 `APPLIED/PARTIAL/REJECTED/UNKNOWN`；已有可自动解除原因不能替代覆盖停止意图全程的受权屏障；之后 SIGTERM，再在预算允许时 SIGKILL。DRAIN 不可达、拒绝或超时须明确记录，继续请求停止不等于 DRAIN 已完成。direct 无 Gateway，升级自 SIGTERM 开始，不伪造 DRAIN。停止请求首次发出时记录 `t_stop`；自动强杀不得早于 `max(最后一次升级请求时间 + kill_timeout, t_stop + 已证明的完整停止预算)`。配置值只有经证明覆盖本 run 全部停止阶段才可作为预算，不能以任意时限代替；无法证明则不自动强杀。计划的显式 `--force` 例外须由授权主体给理由并审计，Gateway 按计划先请求 DRAIN，但不把受理当撤单完成；force 不豁免目标身份和作用范围核验。

候选停止文件包含版本、目标 UUID/run_id、命令 ID、有效期和一次性 nonce；受限目录原子创建并绑定身份，BT 在启动、运行、停止期间只读验证，拒绝旧 run、过期、重复和替换攻击；消费确认不能证明订单终态。防重放、目录 ACL、文件名与回收策略须经平台测试后冻结。不可用时报告失败，不能偷偷写策略目录或把 Windows `TerminateProcess` 当成优雅信号。

最终摘要分别记录停止结果、已请求撤单数、未解决活动单数量/原因、在途写入身份与结果、待发单保留、快照和资源释放结果。即使命令成功到达或进程退出，场所回报不完整、迟到、跨日、重启后的查询无法绑定，均保持 UNKNOWN 并交给 BT/SDK 按原身份对账；不能重发原命令、自动解除标记或声称订单安全。重启是完整停止后新 run 的启动：BT 自行按 D62 合同核验，Gateway 的 DRAIN 原因不由 runtime 自动解除；既存原因及不可确认的对账状态必须显示，不能绕过底层门禁。

## 6. 控制接口、鉴权与持久化（候选）

`serve` 在本机提供控制，CLI、首期独立前端和未来 AFI 作为客户端，复用相同服务合同及后端认证、授权、命令台账和审计；前端不以独有旁路直接运行进程或绕过权限。D66-03 推荐回环 HTTP/JSON，最终需冻结实现及安全证明，非回环绑定拒绝启动；也可选经确认的本地套接字。若改用 SDK ServiceHost/ZeroMQ，必须先解决 direct 的 INV-01，不得假装不存在冲突。所有请求设大小和时间上限、严格 schema、有限错误码与 Host/来源检查；逐主体凭据或 OS 主体映射、权限安全存储、轮换和撤销必须真实可验证。共享令牌仅能表示单主体，不得声称可区分操作者。Windows ACL 未验证时保持未就绪。

独立前端首期提供策略列表及状态、启动/停止/重启与其他已授权策略生命周期操作；显示心跳、启动阶段、阻断、停止摘要和 UNKNOWN，不把请求受理当作交易就绪。Gateway 下暂停与有限代理恢复仅按 D66-08 和 63.12 调用；运行状态只展示已有受权事实，不能自行写策略账本或绕过 Execution 和 Gateway；Monitor 不作为控制入口。页面关闭或断连不停止 runtime 或策略，不自动启动 Gateway、Risk、Execution、Monitor，也不自动 RESUME；服务或权限不可用时明确呈现不可用或 UNKNOWN。

主架构选型：Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus、Axios，图表按需 ECharts；Web 适配优先 FastAPI、作为可选 Web 依赖，复用 runtime 应用操作及中立服务客户端，不重写进程或交易 owner。Node 仅为构建/开发依赖，发布可选安装的预构建静态资源。选择依据为 [D63-47 共同合同 §2.13.1](../迭代63-Gateway统一转发与多策略共享会话/跨迭代合同与决策.md)：ai-for-investor `dev` `1fef35a63` 的公开前端与后端源码；选用相近栈不表示复制 AFI 全局 store、路由、认证，也不表示已有通用微前端或插件。未来集成采用显式路由、组件及 API 适配，本期不实施 AFI 集成。FastAPI 是可选 Web 适配，不代替 D66-03 的传输选择，也不强制 CLI 或全部控制面改为 HTTP。

AFI 现有 Axios 默认重试策略不能照搬到停止/恢复等命令；超时后以原命令 ID 和内容按服务端幂等合同查询或重试，不假定未执行。AFI JWT/RBAC 不证明 runtime 或 Gateway 的 grant，须按 63/66 冻结可验证的主体与授权映射，不共享超权密钥。

接口候选：`units.list/status`、`start/stop/restart`、Gateway `pause/resume`、`logs`、`commands.get`、`events.read`，以及登记、注销、初始化、接管、审计和危险操作确认对应操作。每个命令携带 UUID command_id、unit_id、动作、参数、原因；服务从认证结果取得主体，不能信任请求自报用户名。viewer 读已授权范围的状态/有界日志；operator 管理被授权单元；admin 管理登记、初始化和接管；force、全停、接管及初始化需确认令牌绑定主体、动作、目标、参数和期限。具体角色与二次确认属于 D66-14 待确认方案；Gateway 的 RESUME 按已定 D66-08 由受权运营主动发起，仍需 63.12 的可信主体与有限代理授权合同交付。

RESUME 的原因归属由受信的稳定 runtime principal、目标策略、不可复用 cause_id 共同绑定；Gateway 验证运营与代理的当前授权及原因状态版本，审计“运营经 Runtime”，仅解除该 principal 为该策略设置的指定原因。不得仅信 payload 的操作者字符串，不能解除其他来源原因、UNKNOWN 或系统阻断；多原因逐项校验，解除一项不代表策略可交易。重试或响应丢失用原命令 ID 和内容查询/幂等处理，pending 不显示已恢复；无权、旧请求重放、过期授权或原因状态不匹配明确拒绝或 UNKNOWN。重启不自动 RESUME，但重启后受权运营新发起并通过当前认证的请求，可以解除同一稳定 principal 先前留下且仍有效的原因，不能仅因其创建于旧进程 boot 拒绝。具体证明、令牌、授权衰减和撤权由 63/66 冻结；不授予 runtime 完整运营 principal。

D63-04（Q28 已决定）的订单 UNKNOWN 范围由 Gateway 持有：所属策略该合约全部新订单暂停，其他策略仅同合约同持仓方向可平容量无法证明时暂拒平仓；撤单/查询仍按权限可请求，连接不可达如实报告。Runtime 展示受权的命令、范围、原因及版本，不因此停止整个策略进程，也不能通过重启或有限代理 RESUME 清除它；多个 UNKNOWN 逐项解决由 Gateway 处理，其他急停原因仍保留。验证页面/状态不会把局部阻断显示为全账户停机，不把单项解决显示为全面恢复；不改变 direct 的迭代 62 合同。

SQLite 候选台账采用事务及耐久设置：先提交命令、主体、目标、参数摘要、原因及 UTC 时间，再做副作用；每单元生命周期命令串行，未拉起的启动可被停止抢占。同 ID 同内容返回现存状态/结果，同 ID 不同内容拒绝；状态为 `PENDING → CLAIMED → APPLIED/REJECTED/UNKNOWN`，记录每一步与有限码。崩溃夹在外部调用和提交之间时，记录 UNKNOWN；按 Gateway 最终冻结的幂等/查询合同确认，禁止以本地 CLAIMED 推断未执行或盲重发。确认令牌一次性消费，审计追加、脱敏且不记密钥、账户原文或令牌。台账、登记、状态数据各有版本和迁移/回滚方案，损坏或不可持久时 fail-closed，不能无审计执行。

## 7. 日志、平台与落地模块

runtime 子进程输出不能依赖监督器存活的管道；候选为子进程直接写持久文件并使用经真实进程验证的有界轮转机制。仅重命名已打开文件不能完成轮转。按运行分目录，stdout/stderr、总量上限、磁盘写满、编码和权限均有有限结果；只暴露有界尾部，并避免凭据、原始账户行与令牌泄露。中文使用 UTF-8；磁盘上限无法证明时保留 GAP。

POSIX 独立 session/进程组本身不能使策略脱离 systemd cgroup 或 launchd 服务管理范围；Windows `CREATE_NEW_PROCESS_GROUP` 也不保证脱离继承的 Job，尤其 `KILL_ON_JOB_CLOSE` 在最后句柄关闭时可能终止策略。66.01 须按具体服务管理器、配置与权限设计并证明策略进程及其必要后代的独立存活边界，包括受支持的 breakaway/独立作业或独立服务单元，以及关闭句柄、服务停止和管理器清理时的作用范围；不得假定 `start_new_session`、进程组或 Job Object 即可保证解耦。Windows 控制台与 `CTRL_BREAK_EVENT`、无控制台接管及强杀能力须在 Windows 11 实测。每个支持的部署组合均须在真实管理器和目标 OS 上验证 runtime 正常退出、被强杀、服务管理器重启后策略仍存活且能安全接管；无法证明则该组合记 GAP，不声称满足 runtime 退出不终止策略。文件锁、ACL、路径大小写、长路径、原子替换和进程创建时间接口按 Ubuntu、macOS、Windows 各自验证。迭代 67 的日历更新由操作系统计划任务负责，runtime 不承担定时任务；如展示日历状态，仅消费受支持的只读接口。

建议模块划分：`bt_api_runtime/runtime` 增加监督核心、平台进程端口、持久化/命令台账、认证授权、本机服务、Gateway 控制客户端和 CLI；首期独立前端的所属构建与部署边界在 66.01 冻结；`contracts` 定义版本化配置、命令、事件、有限码与状态 DTO，核查 SDK `bt_api_py.run_contracts` 和旧 parser/registry 兼容；BT `live_trading/` 提供进程合同与可选非信号入口，`live_state/` 继续拥有本地状态；22 个示例通过公共辅助接入，避免复制实现。名称仅为候选。新监督配置与现有 schema-v1/v2 及 `validate/doctor` 的识别、版本和迁移须在 D66-17/18 确认；不悄然改变旧入口语义。后续 AFI 改用 runtime 客户端的集成另立工作，防止两个监督者各自发信号。

## 8. 分步交付与验收

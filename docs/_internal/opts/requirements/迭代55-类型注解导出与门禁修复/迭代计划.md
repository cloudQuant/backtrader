> 状态：**待审阅**。本轮只产出计划与实测基线，未修改任何源码。

## 1. 核心目标（唯一）

让**已经写下的类型注解对下游真正可用**，并且**类型门禁真的会拦**。三个交付物：

1. `py.typed` 导出链路打通（PEP 561），安装后的 wheel 在消费端能被 mypy/pyright 解析出类型；
2. CI 类型门禁恢复有效（现在它在数学上"存在"，在运行时无效）；
3. 注解方言（`typing.List/Dict/Optional/Union` vs PEP 585/604）与 `Any` 通胀收敛到有成文规则、有机械守卫的状态。

配套的唯一收益门禁：**用一个真实下游消费 venv 证明类型外溢生效**，且 CI 的 mypy 步骤被实际执行并按 ratchet 单调下降。任一条拿不到就整体回退（§7）。

### 明确非目标

- **不**给 5949 个函数批量铺注解。`indicators/` `analyzers/` `observers/` `sizers/` `filters/` `plot/` `bokeh/` `reports/` 约 1726 个函数近似零注解，本迭代不动（`Any`-padding 会让门禁更绿、信号更差）。
- **不**为迁就 mypy 严格模式重构 line 系统热路径，**不**重新引入 metaclass，**不**改公共 API 语义与 `params`/`lines` 声明语法（AGENTS.md 硬约束）。
- **不**顺带做与注解无关的格式化/风格清理；不与迭代53/54 的运行时改动混在同一提交。
- **不**把 pydantic 引入 `backtrader` 包 —— 这是决策点 **D5**，需审阅者拍板，本文件不预写"已锁定"。

### 2.3 三个已经在运行时/交付面上的真问题

1. **缺 `py.typed`（最高投入产出比）**。全仓无该文件；[setup.py:35](file:///Users/yunjinqi/Documents/new_projects/backtrader/setup.py#L35) 的 `package_data` 只有 yaml；无 `MANIFEST.in`、无 `include_package_data`；`git grep py.typed|PEP *561` **0 命中** → 是疏漏而非决策。后果：下游 `pip install` 后，1403 个返回注解全部按 `Any` 处理。
2. **注解引用了未导入的名字**（真实缺陷，不只是风格）。[backtrader/research/factor_strategy.py:31](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/research/factor_strategy.py#L31) 用 `Sequence[Any]` 但只 import 了 `Mapping` —— ruff `F821` 与 mypy `name-defined` 同时命中。当前**仅因**该文件有 `from __future__ import annotations` 才没抛异常；任何 `get_type_hints()`/去掉 future import/运行时内省都会变成 `NameError`。同一处清理的两半还留在 [research/sink.py:15](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/research/sink.py#L15)（反而 import 了未使用的 `Sequence`）、[sink.py:18](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/research/sink.py#L18)（未使用的 `typing.Dict`）、[brokers/btapibroker.py:25](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/brokers/btapibroker.py#L25)（未使用的 `..order.OrderExecutionBit`）。
3. **打包校验不会断言新产物**。[scripts/ci/verify_release_wheel.py:39](file:///Users/yunjinqi/Documents/new_projects/backtrader/scripts/ci/verify_release_wheel.py#L39) 按 `name.endswith(".py")` 收集期望成员 → 加了 `py.typed` 也不会被现有 wheel 消费者校验覆盖，会变成"打包了但无人验证"。

### 2.4 方言并存目前**守住了** 3.8（正面结论，审阅者需要知道）

- [setup.py:113](file:///Users/yunjinqi/Documents/new_projects/backtrader/setup.py#L113) `python_requires=">=3.8"`，classifiers 3.8–3.13；black / ruff / mypy 三者 target 均为 `py38` / `"3.8"`。
- AST 扫描 643 文件（`backtrader` + `backtrader_runtime`）：在**没有** `from __future__ import annotations` 的文件里，PEP 585（`list[]`/`dict[]`）与 PEP 604（`X | None`）出现在**求值位置**的次数 = **0**；151 处命中全部是合法老式 `Optional[...]`。
- 全仓 `__annotations__` / `get_type_hints` 运行时内省 = **0 处** → 统一加 future import 属零行为风险。
- 但方言只靠作者习惯维持，无成文规则：core 仅 **36/606（5.9%）** 文件有 future import，`backtrader_runtime` **33/37（89.2%）**，`research` **9/116（7.8%）**；`| None` 全文本仅 49 处、分布在 9 个文件。[docs/source/developer-guide/style.md](file:///Users/yunjinqi/Documents/new_projects/backtrader/docs/source/developer-guide/style.md) 自己都不一致——同一篇里既示范 `list[float]` 又示范 `from typing import Optional, List, Dict, Union`，还写着"最大行长 124"（实际 black 100）与"性能关键代码不加注解（注解有开销）"（future import 后该论断不成立）。→ 决策点 **D1/D6**。

### 2.5 `Any` 通胀与表达工具缺位

- 已注解签名中 **28.3%** 的参数是 `Any`（713 / 2516），返回 `Any` 128 处；`cast()` 全 core 仅 16 次。
- 最差的恰是"看起来已类型化"的新模块：`research/_expression.py` 返回注解 100% 但参数 **76% Any**（`def _line_for(self, target: Any) -> Any`，[:76](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/research/_expression.py#L76)）、`research/panel.py` 56%、`stores/ctp_i9_parent_request_builder.py` 50%、`stores/service_execution_session.py` 47%。
- 表达工具基本没用：`TypedDict` **0**、`Literal` **1**、`TypeAlias` **0**、`Protocol` **5**；`@dataclass` 73（新代码主要靠它 + `Mapping`/`Sequence`）。
- 方言规模（全文本 grep，含 import 与文档串，仅作规模参考）：`Optional` 560 / `Dict` 350 / `Tuple` 214 / `List` 140 / `Union` 6；AST 注解位置的现代形式：PEP 585 共 104、PEP 604 共 26。
- 结果错配：mypy 的 76 个错（CI 钉版）集中在**真打了注解**的 `research/_expression.py`(41) 与 `stores/service_execution_*`(15)，占包大头的老核心一个不报。本机 mypy 2.3.1 下同一文件只报 21 —— 这个差值本身就是 D4 要解决的问题。

## 6. 验收矩阵

### 6.1 正确性（硬门，任一失败即回退本轮）

- `ruff check backtrader/` = 0 错；`black --check` / `isort --check-only` 通过（CI 现成步骤）。
- CI 的 mypy 步骤**被执行**且错误数 ≤ 当前 ratchet 阈值；R3 的注错实验证明门禁会拦。
- `make test-fast` 全绿；R6 额外跑 `make test-strategies`（本迭代不该触碰 multi-data clock/minperiod 路径，若触碰则按 AGENTS.md 要求跑全套）。
- Python 3.8 语法可解析性：对全部被改文件跑 `ast.parse(src, feature_version=(3, 8))`；**这验证语法，不验证运行时**。若无法取得 3.8/3.9 实机解释器，记录 `NOT_RUN`，不得把语法检查写成"3.8 验收通过"。
- 运行时行为零改动证明：diff 中除 R1 的 import 补全外，不得出现任何非注解/非配置的执行语句变更（逐 hunk 核对）。

### 6.2 类型可交付性（本迭代真正交付物）

- 安装后的 wheel 内含 `backtrader/py.typed`；`RECORD` 覆盖之。
- 下游消费 venv 里，对一个真实策略脚本运行 mypy：改前 = 类型不可见（`Any`），改后 = 能报出签名类型与错误位置。原始日志入 evidence。
- ratchet 曲线单调不增，且每轮下降有对应源码改动可指认。

### 6.3 诚实边界（必须写进交付记录）

- 源码/mypy/ruff 结论 **不等于** 真实账户或 provider 通过；本迭代不产生任何账户结论。

- ratchet 数字下降不代表类型正确性提升；`Any` → `Any` 的替换不算收益，以 §6.2 消费端可解析性为准。
- `indicators/*` 等近似零注解区域在本迭代结束后的状态要如实写明，避免"py.typed 已发布 = 全包有类型"的误读。

## 2. 目标与边界

目标：形成可配置、按授权范围观察 Gateway 及已接入来源的事件、健康、指标与告警服务；明确丢失、延迟和未采集；提供有限容量、可诊断的故障隔离；完成与 63 心跳确认合同的对接和证据分级。

**独立服务与未来集成（D63-47）**：用户原话“monitor应该是一个服务，gateway, execution, risk这几个最好都有一个前端页面，可以独立开启这个页面，另外后面我也会把这几个集成到ai-for-investor里面”。其后用户明确选择“查看＋各服务授权管理，Monitor只观察”。因此 Monitor 作为独立可选服务，提供可独立使用的服务启动入口或系统服务装配及生命周期，受认证、版本化的观察查询接口供未来集成；CLI 或服务入口不能依赖页面或 ai-for-investor（AFI）。本期提供可独立启用的 Monitor 只读页面，展示经授权的监控和告警，不代理控制或形成自动控制闭环；页面启用不替代 Gateway 前置与服务鉴权。Gateway、Risk、Execution、Runtime 页面和各自授权管理分别归 63/64/65/66，通过各自服务 API 为未来 AFI 集成预留接口；本迭代不实现 AFI 集成，技术栈按共同合同 §2.13.1 采用。66 首期不监督这些服务，Monitor 的实际启停由其独立入口或系统服务承担。

不在本迭代实现 Gateway、Risk、Execution、Runtime 的业务或控制状态机；Gateway 侧中继、心跳、响应确认来源校验、`monitor_required` 判定和 STOP_NEW 都属于 63.12（D63-15），缺口提回 63。Monitor 不下达交易、风控、暂停、恢复、急停或撤单命令，不取 provider 凭据，不充当账户、订单、成交或持仓真值；ACK 是对特定请求的处理确认而不是控制命令。撤单及 STOP_NEW 的效果、宽限和原因解除遵守 63 的合同，不能由 Monitor 自行决定。既有交易、恢复和 UNKNOWN 处理不因未选择 Monitor 而消失。通知渠道按 D68-08；生产账户、历史数据清理与不可逆旧库迁移不默认纳入。

**部署约束**：显式启用 Monitor 必须先启用 Gateway；配置相矛盾时以有限错误拒绝启动。未安装、已安装但未选择和 direct 不配置时，交易链不隐式导入、启动或连接 Monitor。63 INV63-12 将 Gateway 和策略进程与可选服务包隔离；SDK 可以提供合同/客户端，但实际服务进程组合须按 63 接口验证。是否需要对独立离线库的旧调用施加相同启用限制见 D68-01，不以此放宽新部署约束。

## 3. 设计合同（68.01 冻结）

### 3.1 事件、时钟和授权

事件合同须规定 schema 版本、来源服务/逻辑 producer、可信 principal、授权 scope、来源 epoch、稳定 event_id、事件种类、来源发生时间、Monitor 接收时间和有限字段白名单；时间需标明 UTC/偏移与来源，单调时间只用于本进程年龄计算，重启不得跨进程比较。可信身份与 scope 由认证和服务端授予，不从载荷信任；事件 ID 按 producer 与 scope 命名空间去重，重试须同 ID 同内容，冲突拒绝。未知版本、种类、键、非有限数和越权数据以有限码拒绝，输出不包含原始载荷。

最小来源包含 63.12 确认的命令结果和拒绝码、UNKNOWN、会话/回报、日切、急停状态、对账摘要、配额和中继健康；字段须来自授权投影。Monitor 分别消费 Risk、Execution 和 Runtime 经 64、65.09、66.08 交付的受权只读投影，不推导其业务结果；不可用时显示 `not_collected` 或 `unknown`。按 D68-10，行情中断告警须消费可信的本地文件交易时段合同，真实联调依赖 67 和 63 的对应能力；其余独立观察基础能力不以 67 整体验收为前置。细粒度数据默认不收集；账户/策略标识采用获授权的中立引用，禁止凭据、令牌、原始私有载荷与不必要个人信息。输出、告警、错误、指标标签和测试夹具同样执行白名单及脱敏。事件来源声明不是真实性证明。

68.01 会同来源 owner 以 §3.7 的已选基础目录为底稿，建立唯一版本化逐类目录，列事件类型、授权投影与字段、生产者、持久来源、传输、保留/重放、去重、丢弃和 gap 行为。66 当前拟议向 `telemetry.append` 转发的普通遥测是可丢失的，Runtime 的本地事件表不等于 Monitor 持久接收；需要持久事件时先与 66 冻结接口。65 的母单冻结、子单 UNKNOWN 告警和调度/预算等观测按所选来源逐项登记验证，缺失标 NOT_RUN，不推断来源完整。

发布与查询分开授予最小权限，按 principal + scope + operation 检查；不能由客户端提供或扩大目标 scope。跨账户、跨策略、不同生产者冒用和模糊 scope 均拒绝；分页游标绑定认证主体、查询 scope、过滤条件和 epoch，篡改、过期或不匹配拒绝。访问日志仅保留安全诊断码及中立引用，不记录载荷。单进程状态和不同租户实例不能互相泄漏；重启后重新认证。

服务观察查询提供版本化、受认证授权的健康、事件、指标与告警接口，冻结 scope、分页、错误码、兼容和缺失语义；供独立客户端与未来 AFI 接入，不依赖任何页面或 AFI。该接口只读，不能间接执行 Gateway、Risk、Execution 或 Runtime 控制。独立部署、启动、就绪、停止、重启及资源释放需有可操作入口和故障证据；系统服务配置为可选部署方式，不把 runtime 或 UI 作为启动前置。

Monitor 只读页面独立启停，通过版本化观察 API 展示所授权范围的健康、事件、指标和告警；对未知、陈旧、缺口及服务不可用应明确显示，不显示伪造的正常状态。页面使用身份认证和服务端范围授权，不能凭前端隐藏按钮替代权限控制。页面不可用或关闭不影响服务、API、CLI 与告警；不得提供或间接触发交易、急停、风控、通知配置写入或其他组件管理。页面与推送通知是不同交付，Webhook 按 D68-08 显式选择。

### 3.2 传输、容量和游标

普通遥测是有界、可丢失的 best-effort：分别限制事件数、编码字节、单事件大小、速率及保留时间；入队不网络调用，不在交易回调中同步 flush；超限或发送失败按冻结的策略丢弃并累计按原因计数，暴露积压、最老年龄和最后错误码。不得无界重试或由监控慢拖住交易。持久事件的本地提交、去重、容量检查与返回语义以 68.01 验证的现有实现为基础：同 ID 同内容可重试，冲突拒绝；D68-03 已决定逻辑容量满或磁盘无法持久写入时拒收新持久事件并明确报错，不覆盖历史或返回成功 ACK；持久确认只说明 Monitor 接收持久化成功，不等于来源业务完成。避免将数据库逻辑字节上限误称磁盘/WAL 硬上限；磁盘与 WAL 容量单独监测。

来源接收与告警计算分阶段时，Monitor 对已持久接收事件维护可恢复的计算消费游标/待处理记录；告警状态、告警事件、所选 sink outbox 与该事件处理水位须同库同事务推进，或由 68.01 证明等价的幂等恢复协议。接收 ACK 后至计算前、计算中、提交后崩溃均需恢复，不得静默漏算或重复产生不同身份的告警；告警计算落后或缺口须可见。消费者持久 checkpoint 仅在 sink 接受后前进，崩溃于接收与 checkpoint 之间会重复；消费者必须按作用域及 event_id 幂等，不能声称跨库原子或 exactly-once。对可识别的重复事件按身份去重，对约定窗口内的正常乱序按合同重排；超过窗口且无法补齐、缺页或游标超出保留范围时明确报告 gap，不把每次重放或乱序都认作缺口；不得静默跳到最新或自动把未知标成功。D68-03 已决定可配置自动清理安全到期数据及满时拒收；具体保留时长、容量、低水位、消费者安全下界与可验证清理合同仍由 68.01 冻结，未经证明不得删除记录。分页受限于条数和编码字节，单项超限返回有限错误，不截断伪造完整页。

### 3.3 指标、健康与告警

定义指标名、单位、类型、允许标签和基数上限，至少覆盖入口成功/拒绝、按原因丢弃、队列/持久库占用、游标滞后、最老未处理年龄、服务存活、认证失败、导出失败及告警投递结果。避免账户、订单、自由文本等无界标签。收包新鲜度与来源活性分开：近期收到的心跳最多证明近期收包；递增序号的旧积压也可能晚到。只有经可信通道验证且绑定当前身份、代际与请求的因果请求/响应才能支持本期约定的来源活性判断；普通遥测的时间戳即使递增也只表明接收或来源自报时间，不能升级为活性。其他来源如需采用时钟证据须先由来源 owner 定义可信时钟、偏差/延迟上界和重启语义，未冻结则为 `unknown`；无数据为 `not_collected`，陈旧为 `stale`，均不表示账户就绪或允许交易。Monitor 自身状态不能作为账户真值。

指标须限制直方图样本内存，不保留无上限原始 observations；可使用有界样本或累计桶并明确精度。计数器按实例 epoch 标明重启 reset，缺失采集区间为未知而非零；若需要跨重启精确累计，须另决定持久化、容量和恢复合同，不能把可选外部时序采集当成本地耐久保证。

阈值规则显式配置、无隐含交易阈值；冻结窗口、时区、去重、迟到事件、恢复/抑制、维度上限和告警幂等；失效、重启、规则过期或来源缺失不得默认为健康。告警是可观察记录，可经显式选择的 sink 输出；失败、积压、抑制及丢失可见。Prometheus/ELK 与日志导出可选，默认本机绑定；改变监听范围需显式配置、身份认证和授权。阈值只告警，不能触发控制。

### 3.4 Gateway 心跳和旧版过渡

本轮用户授权两种确认方式均可，由主代理选定：仅 Gateway 中继主动请求，Monitor 在同一受认证请求的响应中 ACK；复用 SDK 既有请求响应抽象，不增主动上报 endpoint。普通持久事件在 Monitor 本地事务提交后响应；心跳走独立容量或优先路径，完成验证和处理后响应，ACK 绑定认证身份、精确 scope、当前中继 epoch、心跳 ID/序号和处理结果，不代表业务积压全部追平，也不授予控制权。身份来自可信通道而非消息自报；旧代际、未知心跳、跨 scope 或失败响应不证明存活，不伪造 ACK。编码、认证、权限、代际轮换和超时等 wire 细节由 63.01/68.01 联合冻结。参考 [ZeroMQ socket 消息语义](https://libzmq.readthedocs.io/en/latest/zmq_socket.html)和 [NATS JetStream 的确认与重放](https://docs.nats.io/concepts/jetstream)；只借鉴语义，不新增 NATS 依赖。

63 的 D63-36 判断依据是“最近一条已 ACK 心跳的**发出时间**在配置时长内”，并有启动宽限；新 ACK 到达时刻不能让旧心跳重新变新。Gateway 重启按新代际和宽限计算；业务事件积压不能饿死心跳，真实资源故障可导致 ACK 不可用。默认未启用 `monitor_required` 时 Monitor 停止、慢或满不影响交易；启用时 Gateway 在失活超时后自行施加账户范围 STOP_NEW，撤单遵守 63。Monitor 不发送控制命令；选型不代表 wire 合同、实现或验收完成。

**D63-33 的 Monitor 部分（Q34 用户已决定）**：仅显式 `monitor_required` 的失联产生 Gateway 自有的账户范围 STOP_NEW。Monitor 恢复并通过既定认证、当前代际与新鲜心跳 ACK 确认后，Gateway 默认自动解除对应 Monitor 失联 cause；也可配置为等待具备 Gateway 既有权限的运营主体执行 RESUME。Monitor 不发送控制请求，页面无恢复按钮或控制代理；不新增未经授权的等待轮数。旧积压/重复 ACK、仅进程或页面上线、Webhook 送达均不能证明恢复；Gateway 重启按既定启动宽限和当前代际重验，不用旧健康快照直接恢复。

规则 schema 至少需要版本、范围、显式阈值与持续时间 `for`（允许显式 0）、pending/firing 状态、级别、触发/恢复、恢复通知开关、迟到/乱序、抑制/去重及容量上界；告警目录逐项记录来源/条件/持续时间/级别/恢复条件/处置手册和测试或缺口；静默窗口如交付只表示运营维护抑制，不等同交易时段、不能清除事实或停止记录。恢复通知是否启用及目录为运营配置/用户决策，不能让默认值暗中改变交易策略。持仓观察长期陈旧或中断告警属于已选基础目录，阈值和来源合同须配置并冻结；来源未接入显示未采集，不能声称已启用；Monitor 自身完全停止或满盘时无法自证故障或保证发出告警，外部独立监督如后续采用另行冻结。

**时钟与迁移。** `fresh` 既有消费者须分离“接收新鲜度”和“来源活性”的版本化字段，列举 SDK 查询角色和旧版消费者；混合版本不能把旧 `fresh` 翻译成来源健康。新字段名及兼容/拒绝策略由 68.01 冻结，过期回放、重启、未知时间和版本回退均覆盖。直方图移除或有界化无上限 `_observations`，清楚标记 `reset` 与实例 epoch；长压断言内存不随观测次数增长、桶/count/sum 正确，手动 reset 与进程重启各按合同反映 epoch，epoch 变化旧值不残留。Webhook 借鉴现有公开 notification 的签名或配置须逐项盘点，不复制其 best-effort 语义为已持久投递；以 D68-08 的独立 outbox、稳定 delivery_id 和有限重试为目标合同。

## 4. 配置与启动方案

以下仅是待冻结的语义示例，不是现有配置或已确定键名：

```yaml
gateway:
  enabled: true
  monitor_required: false
  heartbeat_timeout_seconds: 30  # 候选，Gateway 判活账户配置；具体键由 63 冻结
monitor:
  enabled: false
  event_limit: 10000
  event_bytes_limit: 67108864
  telemetry_queue_limit: 256
  telemetry_bytes_limit: 1048576
  bind_host: 127.0.0.1
```

判活时长由 Gateway 账户配置及 63.01 冻结并独立执行，Monitor 不另设第二个 Gateway 判活阈值；Monitor 页面只读取经授权状态。数值只是解释单位的示例，不是生产默认；必填字段、边界、`monitor_required` 与 enabled 不一致的拒绝码、路径规则、认证材料来源、sink 和生命周期在 68.01 与 63.01 对齐。配置解析拒绝未知键、无效数值、不安全绑定和相互矛盾项；不得把秘密写入日志或示例。显式选择的 Monitor 服务初始化失败必须以有限错误报告，不能静默声称已启用或切换成未选择；Gateway 启动时如何处理配置或连接初始化错误由 63 的合同决定。Gateway 正常运行后，未启用 required 时 Monitor 停止、变慢或不可用不阻塞交易；启用 required 时由 Gateway 遵守自己的存活合同。配置文件归属、账户级与实例级作用域以 63 冻结为准。

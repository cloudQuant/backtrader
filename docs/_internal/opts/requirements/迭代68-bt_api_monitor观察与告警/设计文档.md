## 2. 数据流和权限

```text
Gateway 持久日志 → 63 的有界中继 → Monitor 持久入口 → 查询/投影/告警
Gateway 心跳请求 → 独立或优先容量 → 受认证响应 ACK → Gateway 自判存活
Risk / Execution / Runtime 只读投影 → 各自中继 → Monitor
普通遥测生产者 → 本地有界队列 → 非交易线程发送 → 易失观察
```

来源控制自己的事实与日志，中继负责读取、投影和 checkpoint；Monitor 负责授权接收、保存、读视图与健康和告警。跨库不存在原子提交，Monitor 接收成功不表示来源业务成功、provider 接受或账户完整。事件不可用或未授予范围显示 `not_collected` / `unknown`，不以零值补齐；来源时间、接收时间、处理进度分别展示。Risk、Execution、Runtime 各自输出受权只读投影；非时段相关基础能力不依赖 67，但 D68-10 的真实时段告警依赖 67 和 63 的对应交付。

68.01 与各来源共同建立逐事件目录，明确类型、owner、授权字段、是否持久、保留与重放、丢弃、gap 和对应告警。66 当前拟议使用 `telemetry.append` 转发普通遥测，可能丢失；Runtime 本地事件表不能证明 Monitor 持久接收。要可靠重放须先由 66 和 68 冻结来源到接收的接口。65 的母单冻结、子单 UNKNOWN 告警及其余观测逐项核对和验收，未选或未交付标 NOT_RUN。D68-07 已由用户决定：行情恢复超时、恢复和最终失败告警首期仅覆盖 Gateway 来源；direct 暂时沿用迭代 62 日志，不安装、连接或新增外部 Monitor 观察例外，也不改变 direct 的恢复和准入规则。

建议分离发布 `events.append`、普通遥测 `telemetry.append`、查询分页、告警查看以及确认通道所需最小权限；可信身份、服务角色和 scope 来自认证后的服务端注册与授权映射，载荷不得选择或扩大账户、策略、producer 或授权范围。拒绝错误主体、跨账户/策略、未授权操作、身份冒用和模糊范围；身份轮换、撤权及重启重新绑定。认证材料来源、传输保护与 ACK principal 以 63.01 冻结为准，不假设现有 HMAC 能直接用于本协议。

独立观察服务对健康、事件、指标和告警提供版本化只读查询接口，冻结客户端身份、操作与 scope 授权、分页游标、结果及错误码、缺失/陈旧和版本兼容；CLI 或独立服务客户端可消费，未来 AFI 可经此接口集成，均无需依赖页面。此为拟议服务合同，不声称已实现。接口不向其他组件转发控制，也不把观察结果解释为交易授权。

Monitor 页面通过只读 API 读取健康、事件、指标与告警，支持独立启停；服务端验证主体和 scope，页面只显示其获授权范围，明确标识未知、陈旧、gap 和服务不可用。页面不能下达或间接代理交易、风控、通知配置写入和其他组件管理；服务、API、CLI 和告警的启动与运行不依赖页面。页面状态、外部通知和账户/订单真值分别处理，不以页面显示成功证明告警已经送达或交易就绪。UI 技术栈按共同合同 §2.13.1 采用。

## 3. 事件合同与隐私

以下为供 68.01 审核的逻辑信封，非已实现的 wire 格式。现有 durable 入口请求仅接受 `schema_version`、`event_id`、`event_type`、`occurred_at`、`data`，可信 producer 与 scope 由服务端注入；扩展须明确版本升级及混合版本行为，不能把内部元数据误写成现有协议字段。

| 字段 | 拟议验证与含义 |
| --- | --- |
| `schema_version`, `event_type` | 精确版本和封闭种类；未知版本、种类、键拒绝，不默认为兼容。 |
| `producer`, `principal`, `scope` | 服务端根据认证及映射获得，逻辑 producer 与精确授权范围绑定；载荷自报不可信。 |
| `source_epoch`, `source_sequence` | 来源实例/日志代际和该代际序号；缺失即无法证明连续，不假定跨 epoch 可比较。 |
| `event_id` | producer + scope 命名空间下跨重启稳定；同 ID 同规范内容幂等，同 ID 异内容冲突拒绝；重试不得生成新 ID。 |
| `occurred_at`, `received_at` | 前者为来源声明的带偏移 UTC 时间及来源类型，后者由接收端生成；不能把任意时间视为可信时钟，单调时间只在同进程计算年龄。 |
| `data` | 每种事件独立有限字段白名单、长度/类型/数值上限；拒绝非有限数及未知嵌套，不截断后冒充完整事实。 |

63.12 最小事件类别为命令结果及有限拒绝码、UNKNOWN 产生/解决、回报中断/补齐、会话与结算、日切、急停状态与 DRAIN 进度、对账摘要、配额及中继健康。实际字段由来源 owner 与 68.01 对齐冻结；其他来源结果不由 Monitor 推断。引用使用获授权的中立标识，不采集原始账号、凭据、令牌、私有报文或不必要个人信息；错误、诊断、日志、告警、导出标签及测试夹具遵循同一白名单。拒绝响应只返回有限码和安全关联引用，不回显载荷。保留期与访问权限按范围约束；标识仍可能可关联，不能称匿名。

**D63-03（Q35 已决定）的 Gateway 断连观察**：策略进程继续运行等待恢复；Monitor 区分策略进程存活、Gateway 连接及交易就绪，不发送停止/恢复命令。不以策略仍活或重新连上 Gateway 推断行情、回报和对账已完整；断线中状态按来源缺失/过期展示，场内单可能成交，旧状态不当作当前终态。中继回环覆盖断连、策略继续运行、重连但对账或 UNKNOWN 尚未解决。

**D63-04（Q28 已决定）的 UNKNOWN 观察**：消费 Gateway 按命令身份发布的产生/解决事件、影响的策略/合约/持仓方向、容量依赖和来源版本；所属策略该合约全部新单暂停，其他策略只在同合约同方向可平容量不可证明时暂拒对应平仓。页面按授权展示局部范围，不把一笔 UNKNOWN 渲染为全账户停机；一个解决事件不覆盖其他未决，旧版本不得显示全面恢复。Monitor 不决定容量或解除阻断，不将数量不匹配告警等同于 UNKNOWN；撤单查询保留与实际可达性分别显示。68.03/04 的替身及真实中继回环验证局部范围、多个 UNKNOWN 与乱序解决，不增加控制接口。

## 4. 交付、读取与恢复

**普通遥测**：生产者入队只做本地有界校验和计数，不进行网络或磁盘 I/O；分别限制单事件编码大小、数量、总编码字节、速率、存活时间。满时按 68.01 冻结的丢弃次序丢弃并按原因计数；传输失败不做无界重试，显示队列深度、字节、最老年龄、丢弃数和最后有限错误。发送由独立于交易回调的适当 owner 调度并测量同步 RPC 超时；当前 SDK 没有自动 worker，不能声称隔离已实现。进程重启可丢样本；重复心跳不应延长新鲜度。每实例及受权范围限额，慢 sink 不拖住交易。

**持久事件**：来源先保存并持有稳定 ID；中继读取后调用受权入口，接收侧在一次 SQLite 事务中检查去重及逻辑事件数/字节容量并插入，再返回接收序号。满时拒绝新事件，已有完全相同重试仍可取得原序号；冲突明确拒绝。超时是结果不明，来源仅用同 ID 同内容按限速/退避显式重试，不能假定未接收。成功只表示接收方按约定事务边界持久化，不保证另一个库的业务提交。

中继仅在 sink 接受后持久化自己的 checkpoint；接收成功而 checkpoint 失败或进程崩溃会重放，sink 按身份、scope、event_id 幂等。至少一次是有条件的目标：来源先持久保存并保留至确认，中继持续重试，目标最终恢复且认证授权仍有效，才能期待最终投递；不承诺 exactly-once。来源丢失、容量耗尽、停止重试、授权失效或无法证明交付时，按可观察证据报告 gap 或 UNKNOWN，不能宣称已投递。消费者进度独立；重放、重复与可重排乱序不得误报 gap。为每个来源冻结 epoch、连续序列、允许重排窗口及缺页补取；超过窗口仍缺或游标早于保留下界时显示明确 gap、范围与可用起点，不静默跳到最新。epoch 切换重新绑定并提示不连续，无法证明连续时保持 unknown。

查询游标为不透明、经服务端完整性验证的版本化令牌，绑定 principal、精确 scope、过滤条件、查询 epoch 和保留边界，限制有效期及页条数/编码字节；越权、篡改、过期、条件不符拒绝，单条超限返回有限码而非截断。查询期间采用冻结快照边界或显式说明结果可能变化，不能丢项却称完整。D68-03 已决定配置保留与安全自动清理、满盘拒收及源端原 ID 重试；具体期限、消费者水位、墓碑、清理并发和源端容量/恢复合同在 68.01 冻结，证据不足不得清理。来源自身溢出或不具持久重放能力须显式 gap/UNKNOWN 并记 GAP，不能承诺零丢失。当前逻辑字节预算不是 SQLite 文件、索引或 WAL 的硬上限；须监控磁盘余量、WAL 及写失败，并注入满盘测试。禁止凭观察记录自动修复来源状态。

## 5. 心跳确认：选型与待冻结合同

本轮用户授权两种方式均可，由主代理选定**中继主导请求/响应**：仅 Gateway 中继主动发送请求，Monitor 在同一受认证请求中返回 ACK；复用 SDK 既有请求响应抽象，不新增 Monitor 主动上报 endpoint。普通持久事件仅在本地事务提交后确认；心跳使用独立容量或优先路径，在身份、范围、代际及心跳检查通过并处理后响应，不要求它先等待全部业务事件追平。ACK 是对应请求的处理结果，不代表来源业务完成、不构成交易控制命令。实现不得将传输发送成功误当 Monitor 处理成功。

[ZeroMQ socket 文档](https://libzmq.readthedocs.io/en/latest/zmq_socket.html)说明消息排队与 socket 类型行为，[NATS JetStream 文档](https://docs.nats.io/concepts/jetstream)说明持久流、确认与重放；这里仅借鉴协议语义，不引入 NATS 依赖，也不将参考文档视为当前实现证明。

确认绑定认证的 Monitor principal、精确 scope、Gateway/中继当前 epoch、心跳稳定 ID、序号及处理结果；身份来自可信通道而非消息自报。Gateway 记录自身发出时间和确认时间，按**最近已确认心跳的发出时间**是否处于配置时长内判断；重复或迟到的确认至多推进对应序号，旧心跳不会因刚到达而变新。错主体、跨范围、未知序号、重放、撤权及旧 epoch 均不能刷新存活。Gateway 重启或中继代际轮换后重新注册并进入 63 启动宽限，不能用旧代际证明新存活；不可跨进程比较单调时钟。心跳通道独立容量或严格优先，避免业务积压和普通遥测饿死；实际满盘、确认所需资源故障仍可能使确认不可用，不能伪造 ACK，required 模式由 Gateway 按超时和宽限合同施加 STOP_NEW。身份认证、消息编码、错误码、epoch 生成与轮换、心跳处理的具体提交边界由 63.01/68.01 冻结并测试；不把心跳 ACK 误称为普通事件持久提交。

63.12 负责发出、可信确认、宽限、超时、STOP_NEW 和解除；68.05 负责经冻结协议的 Monitor 侧接口。D68-02 已决定：`monitor_required` 开启时，Gateway 启动阶段若确认 Monitor 版本缺少当前协议的身份与心跳绑定确认能力，应拒绝启动，提示升级或更换；不得先发布交易就绪或派发新命令，也不能以旧 ACK、关闭 required 或宽限静默降级。能力证明与认证、检查时点、有限码、资源清理及重启恢复由 63.01/68.01 冻结。暂不可达、认证失败或未能获取能力证据与已确认旧版不兼容不同，按 63 既有初始化与宽限/失活合同报告；无法证明也不是兼容或健康证明。Gateway 已运行后失联仍遵循 D63-36/Q34，不据该启动决定擅自停止运行服务。未冻结 wire 或未完成真实联调仍为 GAP/NOT_RUN；fake 不替代协议与真实服务证据。

**Monitor 失联原因解除（D63-33，Q34 已决定）**：仅显式启用 `monitor_required` 时，Gateway 在存活失效超时后产生自己的账户 STOP_NEW cause。恢复并通过既定身份认证、当前代际和新鲜心跳 ACK 确认后，Gateway 默认自动解除对应 Monitor 失联 cause；账户配置也可要求运营通过既有 Gateway 授权执行 RESUME。Monitor 继续被动接收中继并在同一请求中响应 ACK，不发控制命令，页面不提供恢复按钮或代理控制；不增加未经授权的等待轮数。旧积压或重复 ACK、仅进程/页面上线以及 Webhook 送达均不能证明恢复。Gateway 重启按已有启动宽限和当前代际重验，不以旧健康快照直接恢复。

Monitor 按 Gateway 权威 `cause_id` 与版本投影解除状态，旧恢复事件不能覆盖再次失联的较新原因；显示某原因已解除不代表账户可交易。其他急停原因、Q28 的 UNKNOWN 和独立系统阻断仍按各自合同保留。普通业务事件 ACK 只代表本地接收，优先心跳 ACK 证明该请求已处理，告警恢复表示告警状态变化：三者不能相互替代；Webhook 与存活和解除无关。

## 6. 健康、规则与导出

服务健康与来源观察分开：无样本 `not_collected`，超过期限 `stale`；近期收到心跳只支持收包新鲜，递增序号的旧积压不证明来源当前存活。本期只有绑定可信身份、当前代际与请求的受验证因果请求/响应支持约定的来源活性判断；普通遥测及递增来源自报时间只表收包或自报，不证明活性。其他时钟证据路径须先由来源 owner 冻结可验证的时钟偏差、延迟上界及重启语义，否则 `unknown`；不能从客户端自报时间推断。收包新鲜也不证明交易连接、账户就绪或订单终态。重启、规则过期、来源缺失与无法验证时不默认健康。指标须登记名称、类型、单位、有限枚举标签和基数上限：入口成功/拒绝、丢弃原因、内存与持久积压、最老年龄、游标滞后/gap、服务和来源状态、认证失败、导出与告警结果。禁止账户、订单 ID、任意错误文本作为无界标签。

当前 `metrics.py` 的原始 `_observations` 追加是须处理的源码差距；冻结有界样本/桶、`reset` 与实例 epoch 的关系。直方图不能无限保存 observations；按实现选择有界样本或累计桶并声明精度。内存指标按实例 epoch 标识 reset，重启期间或采集失败的区间是缺口而非零；需要跨重启精确值时冻结持久化、恢复和容量，不借外部可选 exporter 假称本地耐久。测试递增序号延迟重放、接收端重启、长期高频观测的内存上界及 counter reset。

阈值显式配置，无未经批准的隐含交易阈值；每条规则冻结版本、窗口与时区、最少样本、可为显式 0 的持续时间 for、pending/firing、级别、迟到/乱序、触发/恢复、恢复通知开关、抑制、去重键和上限；维护静默不等于交易日历、不删除告警事实。告警事件采用稳定 ID 以支持幂等投递，不递归产生无界告警；D68-08 已决定本地持久记录及可选通用 Webhook，基础告警目录、自动安全清理和满盘拒收原则已由用户决定；具体事件字段、保留期、队列容量、墓碑和预算仍按 D68-03/04 冻结。sink 缓慢或失败时在可用通道报告积压和可观察性受损；满盘或自身故障可能连本地失败记录都无法写入，必要时使用独立外部观察，不能承诺告警必达。Prometheus、ELK 等按显式配置可选，网络监听默认 loopback；对外暴露必须明确绑定并按冻结机制认证授权。exporter 失败不改变订单状态，阈值不调用控制 API。

**D63-48 持仓恒等式观察与告警。** Gateway 提供受权、版本化的对账投影，至少包含账户和合约范围、可比切点/水位、各策略理论 signed net 之和、外部策略 signed net、账户 signed net、差额、比较状态/完整性以及来源版本和新鲜度。signed net 为多减空；保留 gross、今昨等明细及其来源/完整性，不把净额一致扩展成所有维度一致。候选差额定义为 `账户净量 − (Σ策略理论净量 + 外部策略净量)`，具体字段和数值精度与 63 联合冻结；Monitor 消费 Gateway 比较证据，不自行构造账户事实。外部账本来自 BASELINE 加外部实际成交增量，不通过账户减策略理论量倒推外部量来强行相等；外部策略不参加虚拟转换。 普通策略汇总包含已停止、离线但理论持仓尚未清零的策略，不按当前运行进程列表过滤。

仅当三个量同账户/合约、完整、新鲜且水位可比，并由 Gateway 对账投影报告非零差额时产生不匹配告警；缺失、过期、水位不齐或来源不可证明时展示未能核对 / `unknown`，不记为零或健康，不能用 Monitor 新近收包时间弥补陈旧来源。恢复必须是新的、完整、新鲜、可比且差额为零的观察，旧事件及不完整观察不能关闭既有告警。页面按授权范围显示三项净量、差额、来源版本和比较状态；本地记录和所选 Webhook 遵守 D68-08，不修改账本、发送控制或自动暂停，外部订单依 Q25 照常。例 A 理论 +5、external −5、account 0 为匹配，不产生数量不匹配告警；纯策略 +5/−5 实际净量 0 也不能因逐腿差异误报。D63-49（Q27 已决定）要求无真实可平量时拒单且 A 理论仓不变，不自动改为开仓。Monitor 只展示来源确认的拒单与账本观察；该例拒单后仍净额匹配，不能仅因拒单产生数量不匹配告警，也不替其他服务作交易准入或恢复。

持久接收 ACK 后的规则计算须维护持久消费水位或等价可恢复机制；仅在告警状态/事件、所选 sink outbox 与该处理水位同事务提交后推进，或以经故障测试证明的幂等协议达到等价效果。ACK 后计算前、事务中及提交后崩溃均可重放，不漏算、不重复产生不同身份，积压或 gap 可见。告警状态按规则版本、授权 scope 和生命周期分组，触发与恢复具有单调状态版本；来源事件接收提交即可响应 ACK，不等待后续告警计算；告警计算产生的状态/事件及所选 sink outbox 在 Monitor 本地另一事务中原子写入，事务失败不能声称该写入成功。稳定 delivery ID 包含告警生命周期、状态版本和 sink 配置版本，重试与重启不换 ID；同 sink 同告警按状态顺序投递，失败的触发不能被恢复静默覆盖，迟到旧触发不能反向覆盖已恢复状态。后台有界 worker 发送，不在交易或 ACK 线程同步发送；Gateway 普通持久事件 ACK 在 Monitor 本地接收提交后返回、心跳不等通知队列，二者都不等 Webhook 送达。目标不可用不改变已成功的本地接收或 Gateway 存活合同，不主动施加控制。远端接受只证明端点接受，回复丢失可重复，不证明人已阅读或控制完成，不承诺 exactly-once 或必达。显式配置有限超时、退避、总时长和容量，失败、积压、到期和耗尽可见；保留与满盘原则已按 D68-03/04 决定，具体数值、墓碑及来源留存合同仍待冻结。

Webhook 默认关闭，显式选择后无效配置明确失败，不退为仅本地。目的 URL 和 secret 只由受信部署配置提供，不接受事件 payload 指定目标；只向受权接收端主动通知，不向 Gateway 或其他服务控制端点发命令，也不把响应作为控制。禁止无限重定向、日志与响应不得泄露秘密，认证/签名的 wire 合同在 68.01 冻结。最小载荷按版本包含稳定 delivery_id、sink 配置版本、事件 ID、生命周期/状态版本、受权来源 scope、安全摘要、发生时间和记录时间、规则版本；禁止秘密、原始私有载荷和不必要个人信息。配置类别包括启用开关、受权目标及认证引用、sink 配置版本、超时、退避、重试总时长和容量，不在文档写真实值。63 的被动 ACK 是 Gateway 通道约束，不禁止此主动通知。

### 6.1 已选告警目录与时间语义

来源和告警类别底稿以计划 §3.7 为共同概览，68.01 将来源目录和告警规则目录分别成表、逐条关联并确认 owner；用户已选基础告警类别与可配置保留/容量，具体字段、数值和来源合同待冻结。逐行标明 producer、principal/scope、版本和持久/可丢、字段、游标、触发/恢复、缺口及验收 owner。63 对账观察长期陈旧或中断属于独立基础告警；与可信非零差额分开，来源未知不算健康。自身失活或磁盘满可能连本地告警都无法写入，独立外部观察需另行交付，不能承诺监控自证存活或必达。

行情恢复中断按用户决定仅累计可证明连续交易时段，跨午休/夜盘休市累计，集合竞价不计；按交易所和品种分别计时，同一品种多个合约合并展示。时段由 67 规划的本地文件数据及 63/SDK 的受权中立查询供给，数据缺失/不可比较、映射不明或中断边界无法证明时标 unknown，不以固定窗口或自然时间补齐。来源恢复才关闭告警，休市不视为恢复。具体阈值、事件边界、来源映射、持久计时与版本恢复由 63/67/68 冻结；真实时段告警依赖其对应交付而非 67 整期。

旧查询消费者的 `fresh` 需要版本化迁移为接收新鲜度和可证来源活性，逐一确认 SDK 查询角色及混合版本/回退；旧字段不得自动解释为来源健康。现有 `service_ingress.py` 已将可信 producer、scope、outbox scope 与 source event ID 转为命名空间化存储 ID，底层 `durable.py` 使用全库唯一键；68.01 须核对逻辑 producer 在重启/身份变化后的稳定性、旧/新调用者与授权 scope 的完整兼容，按需要制定不破坏旧数据的迁移或明确拒绝策略，不能把底层全局唯一键单独当成缺陷。Gateway 判活超时只由 Gateway 账户配置持有并执行，Monitor 仅读受权状态；wire 和具体键由 63.01/68.01 冻结。

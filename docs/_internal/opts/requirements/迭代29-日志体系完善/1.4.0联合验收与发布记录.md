## 4. 合并与发行约束

本次仅允许 `dev`→`development` 提升，符合三分支治理：`dev` 是日常开发入口，`development` 是改进/优化版本，`master` 是原始 Backtrader 的历史只读基线。`master` 必须 **NOT_TOUCHED**：不向其合并、不从其构造合并提交、不推送、不跑本次发布 CI、不打本次 tag，也不创建本次 Release。此前对 62 个 master 独有提交的逐项审计仅用于识别已补齐的兼容能力；旧策略布局、已移除组件与历史文档留在 Git 历史。

`.github/workflows/publish.yml`、`release.yml`、`sync.yml`、`tests.yml` 及其他已删除的旧部署工作流不能自动复活；`backtrader/configs/account_config.yaml` 保持删除，包中只允许无凭证模板。Backtrader 发行不调用旧 release.sh、不推全部标签、不强推、不发布 PyPI。外部 SDK 分发属于另一组仓库和授权，不能借此恢复 Backtrader 的旧 PyPI workflow。

`setup.py` 当前已保留 `author="cloudQuant"`。归档[合并审计](evidence/release-1.4.0/merge-audit.md)已补记该处置；初始审计中“现代 author=cloud，建议恢复”的观察保留为历史，不再当作未解决项。

Pages 的现有环境只授权 `development` 发布；本次候选的远程门禁也只针对 `development`。`master` 不因文档构建、CI、tag 或 GitHub Release 而发生任何改动。本次 GitHub Release 不等于 Pages 网站切换到 1.4.0，且未修改远程环境访问控制。

本记录验证框架与离线 SDK 集成，不是实盘、SimNow、真实成交或策略盈利验收。来源为 archive 的 SDK 安装若没有完整 VCS attestation，示例准入仍按现有规则 fail-closed。

# 迭代 29：日志体系完善需求

版本：1.3；修订日期：2026-09-15；状态：`PLANNING`。本轮只写计划文档，不修改代码。原始诉求见[初始需求](./初始需求.md)。1.1 修订：目录布局增加"按运行脚本分组"层级，采纳用户补充形式 `logs/<脚本名>/<YYYY_MM_DD>/<级别>.log`，脚本名自动取自 `sys.argv[0]`。1.2 修订：写日志默认优先使用 `spdlog`（PyPI `spdlog`，bodgergely/spdlog-python，C++ spdlog 的 pybind11 包装），包不可用时自动回退 Python 标准库 `logging`；spdlog 为可选依赖，核心功能保持零第三方依赖。1.3 修订：经本机实测更正 1.2 的悲观判断——macOS sdist 构建安装成功且冒烟通过（详见事实基线与 D29-13），spdlog 是现实可用的默认后端。

## 1. 目标与决策

目标是让每次回测/交易运行都能产出**按运行脚本分组、按级别分类、按天分割**的可查询日志：错误不再被静默吞掉，关键生命周期节点有 INFO 痕迹，`log_message.py` 提供开箱即用的分级+按天文件能力。

**核心决策：**

- **D29-A 按脚本分目录、按级别分文件、按天分目录。** 采纳三级布局
  `logs/<脚本名>/<YYYY_MM_DD>/{error,warning,info}.log`（`debug.log` 可选）。
  脚本名自动取自 `sys.argv[0]` 并规范化（`xxx/run.py` → `xxx_run`：去
  `.py` 后缀、路径分隔符换 `_`），可用 `script_name` 参数显式覆盖；无法
  探测（交互式/`-c`/`<stdin>`）时回退固定名 `backtrader`。相对于单一
  `run.log` 或日期平铺式（`error_YYYY_MM_DD.log`），"脚本 → 日期 → 级别"
  三级对"查某个脚本某天的所有级别"和"按脚本隔离、按天清理保留期"两类
  查询都最直接；不同脚本的日志天然互不混写。
- **D29-B 保持默认静默合同。** 框架作为库默认不产生任何输出（现有
  `NullHandler` + `test_default_is_silent` 保护的行为不变）。分级分天文件通过
  `configure_logging` 新增 `log_dir` 参数一键开启；开启后即创建当日级别文件，
  保证"每次运行都能查到日志"。
- **D29-D 写入后端：spdlog 优先、标准库回退。** `log_dir` 模式下默认优先使用
  `spdlog`（性能好），探测失败自动回退标准库 `logging`（1.1 设计的
  `_DailyLevelFileHandler` 路径）。spdlog 是**可选依赖**：不安装时全部功能
  由标准库路径等价提供，`requirements.txt` 不新增强制依赖。macOS 已实测
  sdist 构建安装可用（见事实基线），spdlog 是现实可用的默认后端；回退仅作
  未安装/构建失败场景的兜底。与历史的关系：本仓库早期曾硬依赖 spdlog、后
  移除（`log_message.py:4` docstring 与 `SpdLogManager` 兼容类为证）；本决策
  不恢复硬依赖，默认行为与现状一致。
- **D29-C 治理优先级 = 可观测性缺口大小排序。** 最大的缺口不是工具函数，而是
  两个事实：(1) `btapistore.py`（199 个 except）与 `btapibroker.py`（145 个
  except）已创建模块级 `logger` 但**零调用**，全部异常静默；(2) 全库 227 处
  logger 调用中 185 处是 debug，仅 8 处 error——错误路径被系统性降级到 debug。
  本迭代以这两项为 P0。

## 4. 功能需求

| ID | 需求及可判定边界 |
| --- | --- |
| FR29-01 | `configure_logging` 新增 `log_dir`（日志根目录，如 `"logs"`）、`script_name`（可选，默认自动探测 `sys.argv[0]`）与 `backend`（`"auto"`/`"spdlog"`/`"stdlib"`，默认 `auto`）参数：开启后在 `log_dir/<脚本名>/<YYYY_MM_DD>/` 下创建 `error.log`、`warning.log`、`info.log`（`level=DEBUG` 时加 `debug.log`），配置即建文件（当日无事件也存在空文件）。`auto`：探测 spdlog 可用则用之，否则回退标准库并提示一次；显式 `spdlog` 不可用时抛 `ImportError` 不静默降级；`stdlib` 强制标准库。脚本名规范化：去 `.py` 后缀、`\` 统一为 `/`、`/` 换 `_`、非 `[A-Za-z0-9_.-]` 字符换 `_`，探测失败回退 `backtrader`。现有参数（`level`/`log_file`/`console` 等）签名与语义不变；`log_dir` 与 `log_file` 互斥，同时给出报 `ValueError`。幂等：重复调用不产生重复行（沿用 `_BT_HANDLER_FLAG` 替换语义）。 |
| FR29-02 | 级别精确分流：`error.log` 收 ERROR+CRITICAL；`warning.log` 仅 WARNING；`info.log` 仅 INFO；`debug.log` 仅 DEBUG。用 handler 级别 + 过滤器实现，不改变 logger 对象语义。跨午夜运行自动滚动到该脚本名下的新日期目录（`log_dir/<脚本名>/<新YYYY_MM_DD>/`）。 |
| FR29-03 | 保留期清理：默认保留 30 天日期目录（可配 `retention_days`），清理范围限于**本脚本目录**（`log_dir/<脚本名>/`）下的 `YYYY_MM_DD` 日期目录，不动其他脚本目录与非日期条目；超期目录在配置/滚动时清理；清理失败仅 stderr 告警一次，不抛出。 |
| FR29-04 | except 静默治理：M0 产出全量清单（文件:行:处置:建议级别）作为 evidence 落库后分批处理。~36 `pass` 与 ~32 `continue`：预期分支（如可选列缺失、属性探测）→ debug 并注明可忽略原因；可恢复异常 → warning + 上下文；数据/资金相关 → error。~57 裸 `raise`：上抛前补 `logger.error`/`exception`（含堆栈），保证 error.log 可见。兜底 `except Exception` 必须带 `exc_info=True`。 |
| FR29-05 | 异常风暴抑制：热循环内同类重复异常不得逐条落盘——采用首次全量 + 后续计数 + 周期性/退出时摘要（同一 logger+异常类型键）。抑制策略可关闭（诊断模式）。 |
| FR29-06 | 关键节点 INFO：Cerebro `run` 开始（运行模式、策略数、数据源数、初始资金）与正常结束（终值、总收益率、耗时）；数据加载完成（每 feed 的 bar 数、时间范围）；策略 `nextstart`（minperiod 首次满足）与 `stop`；订单生命周期（提交：ref/买卖/量/价，成交，拒绝/取消至少 warning）；引擎异常终止（error + 堆栈）。所有 INFO 带结构化上下文（策略名、数据名、订单 ref）。热循环内（每 bar）不产生 INFO/WARNING。 |
| FR29-07 | 级别语义修正：对现有 185 处 debug 逐处判定，属于错误路径的升级为 error/warning（判定依据与逐处结论入 evidence）；升级后 `docs/LOGGING_GUIDELINES.md` 补充错误分级规范：error=数据损坏/下单失败/连接断开/资金状态不一致；warning=可恢复降级/重试/兼容回退；info=生命周期节点；debug=细节。 |
| FR29-08 | print 治理：核心引擎路径（`cerebro`/`_cerebro`/`strategy`/`broker`/`brokers`/`feed`/`feeds`/`stores`/`channels`）的 `print(` 改为 logger 调用；bokeh/plot 可视化交互路径豁免（豁免清单入 evidence，逐处注明理由）。 |
| FR29-09 | 兼容与测试：`get_logger`/`configure_logging` 现有行为全部保持，`tests/unit/utils/test_logging_config.py` 既有 10 项不修改断言继续通过；`SpdLogManager` 保留。新增单元测试覆盖：分级分流正确性、脚本名探测/规范化/显式覆盖、跨午夜滚动、保留期清理、幂等、log_dir/log_file 冲突、默认静默（含"不配置则不创建任何文件/目录"）、**双后端**（stdlib 全量必测；spdlog 已安装时 parametrize 同套断言，未安装时显式 skip 并记录探测结论）。布局/分流/滚动/清理语义在两条后端路径上等价。 |

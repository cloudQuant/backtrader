## 2. D29-02：滚动方案选择

支撑 FR29-01、FR29-02。

| 方案 | 收益与代价 | 决策 |
| --- | --- | --- |
| 自定义 `_DailyLevelFileHandler`：文件路径含脚本名与日期，emit 时惰性检查日期切换 | 路径即 `log_dir/<脚本名>/<YYYY_MM_DD>/<级别>.log`，滚动=开新文件，跨进程语义清晰；需自写 ~70 行 handler | **采用** |
| `TimedRotatingFileHandler` + 自定义 `namer` 重命名进日期目录 | 标准库滚动成熟，但滚动模型是"旧文件重命名"，与"每日新路径"不匹配；namer hack 在多 handler 并存时易错 | 不采用 |
| 日期平铺 `log_dir/<脚本名>/error_YYYY_MM_DD.log` | 层级少一层，但按天清理需解析文件名、跨级别查询需 glob，弱于日期目录式（需求 1.1 用户已明确选目录式） | 不采用 |

惰性切换语义：午夜后首条日志触发切换；无日志的午夜跨越不产生空目录（当日文件已由配置时创建保证，见 D29-03）。日期源抽取为 handler 的 `_today()` 方法，测试用 monkeypatch 覆盖，不引入 freezegun 依赖。日期目录名用下划线格式 `YYYY_MM_DD`（如 `2026_09_15`），与需求 1.1 用户示例一致。

## 3. D29-03：API、分流与清理设计

支撑 FR29-01、FR29-02、FR29-03、FR29-09、NFR29-02。

```python
configure_logging(
    level="INFO",
    log_file=None,        # 既有，与 log_dir 互斥
    log_dir=None,         # 新增：日志根目录，如 "logs"
    script_name=None,     # 新增：脚本目录名，None 时自动探测 sys.argv[0]
    backend="auto",       # 新增："auto" | "spdlog" | "stdlib"（D29-13）
    retention_days=30,    # 新增：保留期
    fmt=None, datefmt=None, console=True,
    max_bytes=..., backup_count=..., propagate=False,   # 既有不动
)
```

脚本名探测（模块内私有函数 `_detect_script_name`）：

```python
def _detect_script_name(default="backtrader"):
    argv0 = sys.argv[0] if sys.argv and sys.argv[0] else ""
    if not argv0 or argv0 in ("<stdin>", "-c") or argv0.startswith("<"):
        return default                       # 交互式 / -c / 嵌入式
    name = os.path.splitext(argv0.replace("\\", "/"))[0]   # 去后缀、统一分隔符
    name = name.strip("./")
    name = re.sub(r"[^A-Za-z0-9_.\-]", "_", name)          # 非安全字符换 _
    return name.replace("/", "_") or default
```

- `xxx/run.py` → `xxx_run`（保留相对路径结构，与用户示例一致）；`run.py` → `run`。
- `python -m` / pytest 等工具场景 argv[0] 为入口模块路径，规范化后名字可能较长——无害但建议此类场景显式传 `script_name`（指南注明）。
- 探测在 `configure_logging` 调用时执行一次并绑定到 handler；同进程内重复配置以新探测/新参数为准。

handler 矩阵（`log_dir` 开启时，全部打 `_BT_HANDLER_FLAG`；`<脚本名>` 为探测或显式给出的名字）：

| 文件 | handler 级别 | 过滤器 | 收录 |
| --- | --- | --- | --- |
| `log_dir/<脚本名>/<YYYY_MM_DD>/error.log` | ERROR | 无 | ERROR + CRITICAL |
| `log_dir/<脚本名>/<YYYY_MM_DD>/warning.log` | WARNING | `_ExactLevelFilter(WARNING)` | 仅 WARNING |
| `log_dir/<脚本名>/<YYYY_MM_DD>/info.log` | INFO | `_ExactLevelFilter(INFO)` | 仅 INFO |
| `log_dir/<脚本名>/<YYYY_MM_DD>/debug.log`（仅 `level=DEBUG` 时创建） | DEBUG | `_ExactLevelFilter(DEBUG)` | 仅 DEBUG |

`_ExactLevelFilter` 为模块内私有 `logging.Filter`，`record.levelno == self.level` 判定。控制台 handler 保持层级语义（无 exact 过滤，级别 = 配置 `level`），与现状一致。

行为合同：

1. **配置即建文件**：`log_dir` 给定即创建 `log_dir/<脚本名>/<今日>/` 目录与全部适用级别文件（空文件），满足"每次运行都能查到日志"；不同脚本运行互不覆盖。
2. **幂等**：重复调用沿用 `_remove_managed_handlers` 替换语义，不产生重复行。
3. **互斥**：`log_dir` 与 `log_file` 同时给出抛 `ValueError`（新增、显式）；只传其一或都不传保持现状。
4. **保留期清理**：配置时与每次日期切换时，扫描**本脚本目录**（`log_dir/<脚本名>/`）下一级 `YYYY_MM_DD` 格式目录名，删除早于 `retention_days` 者；其他脚本目录、脚本目录内非日期格式条目一律不动；清理异常捕获后经 stderr 告警一次并继续，绝不抛出到调用方。
5. `level=INFO`（默认）时 DEBUG/WARNING 及以下级别日志对 info.log 不可达——分流只路由，不提升级别。

## 5. D29-05：except 静默治理与风暴抑制

支撑 FR29-04、FR29-05。

分批（处置 = 逐处判定为 升级 ERROR / WARNING / 保留 DEBUG（注明理由）三类之一，判定结论入 evidence）：

| 批 | 文件（except 数） | 依据 |
| --- | --- | --- |
| P0 | `stores/btapistore.py`(199)、`brokers/btapibroker.py`(145) | 外部交易路径，已建 logger 零调用，错误代价最高 |
| P1 | `lineiterator.py`(115)、`lineseries.py`(92)、`linebuffer.py`(78)、`lineroot.py`(24)、`metabase.py`(24)、`parameters.py`(22) | 框架核心构建/行系统，回归风险区 |
| P2 | 其余：`observers/trade_logger.py`(72)、`strategy.py`(60)、`functions.py`(29)、`feeds/csvgeneric.py`(23)、`feed.py`(20) 等 | 剩余 |

三类处置规则：

- `except: pass`（~36 处）：预期分支（可选列缺失、属性探测）→ 保留并补 debug 说明；其余 → warning/error。
- `except: continue`（~32 处）：循环内跳过必须有 warning + 计数上下文；预期跳过 → debug。
- 裸 `raise`（~57 处）：上抛前补 `logger.error`（有堆栈用 `exc_info=True`），保证 error.log 可见；不改变异常类型与传播。
- 兜底 `except Exception` 一律 `exc_info=True`。

风暴抑制（模块内新增，`log_message.py` 承载）：

```python
_throttle_state: dict  # (logger_name, key) -> {"count": int, "last_log": float, "since": float}
_throttle_enabled = True

def throttled_error(logger, key, msg, *args, every=100, window=60.0, exc_info=True): ...
def throttled_warning(logger, key, msg, *args, **kw): ...   # 同构
def set_throttle(enabled: bool): ...                        # 诊断模式开关
def flush_throttle_summary(): ...                           # atexit 注册；输出各 key 累计
```

首次全量输出；后续仅计数，每 `every` 次或距上次输出超 `window` 秒输出一条摘要（含累计次数）。键建议用 `(模块, 异常类型)` 字符串。开销：命中抑制路径仅一次 dict 取址 + 整数递增，满足热路径约束。P1 热循环内的重复异常必须走 throttled 路径。

## 8. D29-08：多进程与写故障隔离

支撑 NFR29-03、NFR29-04。

- **多进程**：`log_dir` 模式下，若 `multiprocessing.parent_process() is not None`（非主进程），文件名加 `.p{pid}` 后缀（如 `error.p12345.log`，路径仍在 `log_dir/<脚本名>/<YYYY_MM_DD>/` 下——spawn 子进程继承 argv，探测结果与主进程一致），子进程各自独立文件，主进程无后缀。不引入跨进程锁与文件轮转竞争。验收以 `maxcpus>1` spawn 场景文件无交错行为为准。
- **写故障**：`_DailyLevelFileHandler.emit` 捕获写异常后走标准库 `handleError` 路径，首次失败额外 stderr 告警一次（模块级标志去重），不抛出、不断回测。标准库 `Handler` 的 emit 异常本就不外抛，此处显式化并加测试锁定。

## 13. D29-13：spdlog 后端与标准库回退

支撑 FR29-01（backend 参数）、FR29-09（双后端测试）、NFR29-01（性能采样）。

**包事实（2026-09-15 PyPI 核验 + macOS 实测）**：PyPI 包名 `spdlog`，作者 bodgergely（即 bodgergely/spdlog-python），最新版 2.0.6（2023-04-19），pybind11 包装 C++ spdlog；PyPI 仅 cp310 Windows wheel + sdist。**本机实测（Apple Silicon / Python 3.11.8 / pybind11 3.1.0）**：`pip install spdlog` 从 sdist 源码构建成功（产出 `cp311-cp311-macosx_11_0_arm64` wheel），`FileLogger` 写入、按 logger 级别过滤（`set_level(ERR)` 拦下 info）、`flush`、`set_pattern` 冒烟全部通过——**macOS 上 spdlog 现实可用，是默认后端而非边缘选项**。Ubuntu 未实测：sdist 为平台无关 pybind11 + C++ 源码、无平台限制代码，预期 gcc 构建可行；实现轮在有 Ubuntu 环境时补验（AC29-15 记录探测结论）。标准库回退保留为未安装/构建失败场景的兜底，两路径功能等价合同不变。

**架构约束：布局逻辑与写后端解耦。** 脚本名探测、目录布局（`log_dir/<脚本名>/<YYYY_MM_DD>/`）、级别分流矩阵、配置即建文件、日期切换触发、保留期清理全部由框架层（`log_message.py`）统一决策；后端只承担"向指定文件路径写入格式化日志行"。禁止 spdlog 自身的 daily rotation 命名规则（如 `filename.YYYY-MM-DD` 后缀）泄漏到布局中——日期切换由框架层检测后重开 sink/handler。

```text
configure_logging(backend=...)
  ├─ "auto"   → _detect_spdlog() 成功 → SpdlogBackend（提示一次"backend=spdlog"）
  │                失败        → StdlibBackend（提示一次"spdlog 不可用，回退 stdlib：<原因>"）
  ├─ "spdlog" → 探测失败 → 抛 ImportError（显式要求不静默降级）
  └─ "stdlib" → StdlibBackend（不探测）
```

**探测契约（`_detect_spdlog()`，配置时执行一次）**：

1. `import spdlog` 成功；
2. 具备本设计所需能力符号（logger 工厂、级别设置、flush 控制——M1 实施时以实际安装版 API 冻结最小符号集，登记版本）；
3. 对临时文件一次冒烟写入+flush 成功。

任一步失败即视为不可用，异常捕获后返回 `None`，不让探测异常外溢。

**两后端行为等价合同（AC29-15 逐项断言）**：目录/文件布局一致、分流矩阵一致、跨午夜滚动一致、保留期清理一致、幂等/互斥/静默合同一致、多进程 pid 后缀规则一致。允许差异仅限：行内时间戳/格式微差（指南声明）、flush 时机（见下方适配要点），回测结束时统一 flush。

**spdlog 2.0.6 实测 API 适配要点（2026-09-15 macOS 实测，适配层 `SpdlogHandler` 据此实现）**：

1. **单字符串参数**：绑定的 `info/warn/error/critical/debug` 只接受一个已格式化字符串（未暴露 C++ fmt 变参）。适配层流程与标准库 Handler 天然一致——`record.getMessage()` 展开惰性 `%s` 参数后拼完整行再传 spdlog，惰性格式化语义保留。
2. **方法/枚举映射**：`Logger.warning → spdlog warn`、`LogLevel.ERROR → spdlog.LogLevel.ERR`、`WARNING → WARN`；`critical/debug/info` 同名。适配层维护常量映射表。
3. **弃用 `DailyLogger`**：实测其文件命名为 `daily_2026-09-15.log`（基础名_日期），与三级目录布局不符——按 D29-13 架构约束，日期切换由框架层检测后 `drop` 旧 logger 并以 `FileLogger` 重开新路径，不依赖 spdlog 自带滚动。
4. **flush**：模块级 `flush_every` 在此绑定中不存在；用 `logger.flush_on(spdlog.LogLevel.WARN)`（WARN 及以上即时 flush）+ 回测结束统一 `flush()` + `spdlog.drop(name)` 释放句柄（drop 后文件方可被保留期清理删除）。
5. **探测契约最小符号集**（1.2 版预留"以实际安装版 API 冻结"，现冻结为）：`spdlog.FileLogger`、`spdlog.LogLevel`、logger 具备 `set_level/set_pattern/flush/flush_on/info/warn/error/critical`，外加临时文件冒烟写入。
6. `logger.should_log(level)` 可用于适配层快速门控；`spdlog.drop_all()` 用于 `reset_logging()`。

**依赖与安装**：不加入 `requirements.txt`；`LOGGING_GUIDELINES.md` 提供安装说明（`pip install spdlog`——macOS 实测 Apple Silicon/Python 3.11 直接成功；Ubuntu 预期 gcc 构建可行、实现轮补验；失败则自动回退）。`setup.py` 可选 extras（如 `backtrader[spdlog]`）是否提供在 M1 实施时以实际构建验证决定，不预先承诺。

**get_logger 返回对象**：无论后端，`get_logger()` 仍返回标准库 `logging.Logger`——spdlog 后端以自定义 `logging.Handler`（emit 内转调 spdlog sink）挂载到 backtrader logger 层级，框架内全部 `logger.xxx()` 调用点（含 D29-05/06 的 throttled/关键节点日志）不感知后端差异。此设计保证：热路径惰性格式化/`isEnabledFor` 门控语义不变；任何 spdlog 侧异常在 handler.emit 内吞掉并走 handleError，不外抛（与 D29-08 一致）。

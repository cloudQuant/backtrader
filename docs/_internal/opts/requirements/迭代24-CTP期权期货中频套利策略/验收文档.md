## 2. 测试约束与证据格式

1. 实现期所有 Python 命令使用 `/Users/yunjinqi/opt/anaconda3/bin/conda run -n base python ...`。本文件不给尚不存在的 runner 命令制造“已可运行”印象，测试命令在实现后补充准确模块路径。
2. oracle 由验收方独立计算，禁止从被测函数重新生成 expected；不仅比较最终净值，还逐事件验证数据可用性、订单权限和现金占用。
3. replay 真实 SDK/CTP 连接与交易写为零。仿真 broker 的假设成交计数另记，不能据此声称外部成交。
4. 每次运行采用新的不可覆盖证据目录：`run_manifest.json`、`acceptance_results.json`、`gate_results.json`、输入 hash、导入包/native/源码身份、quotes/bars/feature/decision/token/order/fill/risk 时间链和错误码。account 只记录非秘密指纹。
5. 每条 result 至少包含 case ID、status、fixture hash、config/code/package/native hash（不适用时明确 null+reason）、开始结束时间、关键断言、证据相对路径及失败原因。修改被测源码或配置后，旧结果不作为当前候选 PASS。
6. 自然第一套证据、工程 smoke、第二套 API 诊断、historical/hypothetical/actual 账和 R1/R2 必须分别保存，不拼接不同候选或不同 generation 的证据。

## 2. "跑通"验收定义（技术贯通，非盈利准入）

运行分三种模式：dry（配置自检）、`--replay`（离线回放，模拟证据）、`--live`（真实账户运行）。
"跑通"以 `--live` 为准；各模式判据如下：

1. **干跑自检**：`python run.py` 退出 0；只验证公开配置结构与凭据 env 变量名
   （名称，不读 `.env` 值）、不要求真实凭据已存在、不构造 provider、不导入交易会话、不联网。
2. **离线回放**：`python run.py --replay` 退出 0；在本地冻结/合成 fixture 上运行
   同一份策略逻辑（公式、事件顺序、指标），产出确定性报告；零网络、零 provider、
   零订单/成交，报告标注 `LOCAL_REPLAY_ONLY`。它是模拟证据，不是账户/交易证据；
   同一策略文件在三种模式下共用。
3. **真实贯通**（`python run.py --live`，写入另加 `--allow-write`）：
   - 连接成功：SimNow 为穿透式登录（AppID/AuthCode）+ 有效交易日 + 连接代次；
     OKX/Binance 为服务器时间偏移补偿 + 签名读取成功；
   - 行情接入：订阅/快照到达且通过新鲜度检查（价格与时间戳）；
   - 策略循环：信号计算与风险检查在真实数据上执行；
   - **订单生命周期**：请求身份明确、受理/拒绝可确认、终态可查询；
   - **成交往返（完整贯通的必要条件）**：本示例对应的全部交易腿存在可确认的
     正成交量，每腿成交暴露均有对应平仓；最终持仓、活动挂单与成交对账通过。
     纯拒单或纯撤单仅证明订单生命周期，不构成"跑通"PASS；
   - 失败路径安全语义：所有订单 `track_order` 登记、失败补偿撤单、
     UNKNOWN 冻结该会话写入（沿用迭代 41 语义；多腿与清理预算细则见 §5.3）；
   - 退出码：0 PASS / 1 FAIL / 2 BLOCKED / 3 UNKNOWN；
   - JSON 证据写入目录内 git-ignored `evidence/`；证据不含账号/密钥字符串
     （仅伪名指纹）；记录触发来源（natural/drill）与完整最小证据字段（§7.1）。
4. **受控演练单（drill）**：仅当自然观察窗口结束、无自然订单尝试、无未决订单或
   UNKNOWN 且预检通过时，才允许一条"链路演练往返"——走同一风险与执行链、
   显式 `drill: true` 标记、有界（最小可成交数量、单次往返、强制平仓）。
   Drill 只替代信号来源，必须覆盖示例自身的完整腿组合（双所/双腿/C-P-F 三腿）；
   不得在自然交易已拒单、部分成交、超时或状态不确定后用它覆盖原结果；
   不产生任何策略有效性或盈利结论。
5. **证据化 BLOCKED 原则**（沿用迭代 41）：BLOCKED 保留给已证明的外部能力、
   授权输入或运行环境限制；自身接口误用、装载错误或不忠实 fixture 属实现/测试缺陷，
   应继续修复，不归因于场所。阻塞必须附"为何不可达"的完整事实，并如实写明翻转
   所需变更与复验范围（可能涉及配置或合约映射调整，不承诺"零改动"）；
   不把"不可复现"伪造成 FAIL，也不把"不可观测"当成 PASS。
   优先选择可运行的、操作员授权范围内的场所 API 路径，不轻易接受 BLOCKED。
6. **区分证据层级**：源码 QA / 离线模拟测试 / 真实账户验收严格分开记录；
   真实账户验收不得用模拟测试替代。
7. **预热与运行期限**：每例在 config/README 明确最小预热数据量与真实数据来源
   （或预热等待方式）、自然信号截止条件、最大运行期限、订单确认期限与清理期限；
   除启动预热外不得用虚构行情填充真实验收；超时一律使用单调时钟；
   行情停更时也必须能安全结束。

## 3. 标准四件套规范（参考迭代 41）

形态语义对齐迭代 41 的 000 三件套（`config.yaml + <ID>_strategy.py + run.py`，
干跑默认 / `--live` 执行 / 退出码 0–3 / 证据 JSON），本迭代另加 `--replay`
离线回放为并列一等模式；差异仅在：
策略示例的"策略文件"是可复用的交易策略类（而非认证案例的检查逻辑），
且不引入统一场景引擎（遵循既有"三件套、无引擎"约定）。

### 3.1 文件职责

- **README.md**：本示例是什么（策略逻辑、场所、标的）、怎么运行
  （dry / `--replay` / `--live` / `--allow-write`）、解释器要求、验收状态、证据位置。
- **config.yaml**：
  - `schema_version`、`strategy_id`、`venue`/`environment`（demo/simnow）、
    合约/标的、`strategy_params`；
  - `credentials`：**只写 env 变量名**（如 `CTP_BROKER_ID`、OKX/Binance Demo 的既有名称），
    密钥只存在于 checkout 根 `.env`（git-ignored）；
  - `policy`：有界写上限（`max_actions` / `max_quantity` / `max_notional`），
    默认取"最小可成交规模"；
  - CTP 前端：1–8 组完整 MD/TD pair（env 名），选择规则见第 5.1 节；
  - `timeouts`、风险参数。
- **`<name>_strategy.py`**：策略类（`bt.Strategy` 子类或显式状态机）+ 模块级 `RISK` 标记
  （READ/WRITE/DANGEROUS）；导入无网络、无凭据、无副作用。
- **run.py**：唯一入口，三种模式共用同一策略文件。`python run.py` = 干跑自检
  （配置结构与凭据 env 名格式，不读 `.env` 值、不联网）；`--replay` = 离线回放
  （本地 fixture，零网络零写入）；`--live` = 真实运行，写操作另加 `--allow-write` /
  `--allow-dangerous` 分级授权；每次 replay/live 运行写一份 JSON 证据；
  退出码与验收语义符合第 2 节。

### 3.2 共享代码与自包含边界

- 遵守仓库既有自包含契约（`tests/unit/test_examples_self_contained.py`）：
  每目录仅可导入标准库、已安装发行版（`backtrader`、`bt_api_py`、`bt_api_ctp` 等）
  与本目录模块；**不跨示例目录 import**。
- 场所会话/签名/重试等共同能力优先复用已安装 SDK（dev `D:/bt_api_py`）自身接口；
  确需共享的小模块按仓库惯例做**目录内字节一致副本 + 漂移守卫**（如 013_1/013_2 的
  `ctp_example_support.py` 模式），并在守卫表中登记。
- 000 certlib 仅作形态参考，**不直接引用、不修改**；认证套件与示例目录相互独立。
- `test_examples_self_contained` 只是导入边界检查，不等于复制后立即可运行
  （不覆盖数据独立性、并对核心 SDK 模块名放行）：另做一次目录外 dry/`--replay`
  运行检查（公开测试输入与显式依赖清单）即可，不新增复杂验证体系。

### 3.3 目录最终形态

清理收敛后，对外使用面 = **四件套**（README.md、config.yaml、`<name>_strategy.py`、
run.py），`run.py` 为唯一运行入口；运行必需的内部模块、fixture 与审批资产可以保留，
但逐目录登记职责与替代关系，且不构成第二套独立运行面。清理只删除已被替代的旧入口、
失效候选与模板——不为目录外观删除仍有职责的内部能力模块（如锁、风控、报告、
签名审批资产），也不把全部逻辑压进 run.py。`backtrader_runtime` 登记与相关测试
在收尾轮统一处置。

## 5. 关键机制与复用资产

### 5.1 SimNow（期货/期权示例）

- **会话**：CPython 3.11（`C:/anaconda3/python.exe`）+ dev `bt_api_ctp`
  （`BT_API_PY_ROOT`，默认 `D:/bt_api_py`）；穿透式 AppID/AuthCode 登录、
  结算确认、查询、报撤单。
- **写准入与集成路径（R0 决定，2026-10-10，源码验证）**：SimNow 三条候选路径现状：
  ① 直连窄口径准入 `arm_execution_for_registered_sim`（client 级，精确 SimNow 前置白名单、
  一次性武装、capability 随报撤单传递）——迭代 41 已证端到端（000 认证 98/99）；
  ② Store/managed 路线（`BtApiStore` 需 typed CTP managed adapter）——当前为 fail-closed
  占位，direct CTP Store 写入被硬关闭（`btapistore.py:7796/8137`、内层 wrapper
  1906-1917）；③ facade 通用路线 `arm_execution_from_preflight`——对 SimNow 明确拒绝
  （`_reject_simnow_native_execution` → `ctp_simnow_execution_not_admitted`）。
  **决定：SimNow 执行采用路径 ①（直连 registered-sim）**，由各示例 run.py 持有有界
  直连执行层（TD 会话/查询/报撤单/对账 + capability 传递 + §5.3 规则）；bt.Strategy 型
  示例经 Cerebro + SDK 行情 + 直连执行桥运行；Store/managed/facade 的 SimNow 写路线
  保持关闭，本迭代不重开（重开需独立治理评审，不在本迭代范围）。
  如需 SDK 增补（如稳定的订单事件公共钩子），先在 `D:/bt_api_py` dev 窄范围实现、
  测试、提交，再在主仓使用；源码验收不计真实账户通过。
- **前端选择（自动择优）**：1–8 组完整 MD/TD pair；每端 ≥1/3 有界探测成功即可选，
  按 max(MD 成功中位延迟, TD 成功中位延迟) 排序、配置序破平；
  标准前置在交易时段可达时优先，否则落 7x24 常时前置。TCP 探测仅用于候选筛选，
  运行前另行验证登录、交易日、所需合约可交易、行情到达与新鲜度；证据记录所选
  front 组、环境类型（标准/7x24）、交易日、连接代次与能力检查结果；标准与
  7x24 的证据按各自覆盖范围记录，资金/保证金/结算结论分别标注；自动选择或回退
  仅限首次写入之前，存在订单、持仓或 UNKNOWN 后不自动换环境重跑。
- **期权合约预检（014/015 前置）**：核对 C/P/F 的标的对应、到期日、行权价、
  交易状态、乘数、最小数量与盘口；按合约规格确定可行的最小腿组合，
  不能只用各腿各自最小下单量的简单相加。
- **凭据**：仅按名从 checkout 根 `.env` 读取（`CTP_*`，已有轮换后凭据）；
  证据仅输出伪名指纹。

  不改动迭代 21 的经济研究结论；manifest 状态刷新在 R2 中完成。

### 5.3 写重试、多腿失败与 UNKNOWN 恢复

- **统一写重试策略**（消除"写不重试"与"OKX 同 clOrdId 重试"的表述冲突）：
  - 确定拒绝：记录拒绝与原因；仅符合明确重试条件时才允许再次尝试；
  - 明确可重试错误（白名单，如 OKX `50013 Systems busy`）：使用固定逻辑订单身份、
    有限次数与总期限，每次请求消耗预算；
  - 超时、断连或受理结果不确定：先查询与对账，未确认前禁止盲目重发。
  `clOrdId` 仅要求订单活动期内唯一，**不构成永久幂等保证**；一次查询未找到
  不等于未受理；明确受理后以场所订单身份跟踪；本地逻辑订单 ID 在整个运行与
  恢复周期内保持唯一。
- **多腿失败与清理预算**：预算区分逐腿数量、整轮名义金额、最大未对冲敞口及其
  持续时间；报单尝试、撤单与补偿均计数；为撤单与已确认持仓的减仓预留清理额度
  （预留本身有上限），不因开仓耗尽预算而无法清理。
- **UNKNOWN 恢复规则**：停止新增风险；以稳定订单身份查询与对账；只有确认活动
  订单后才撤单，只有确认剩余持仓后才减仓，不盲目重发或发送猜测数量的反向单；
  冻结与未决记录持久化，并以账户+环境范围的锁阻止其他示例或重启进程绕过。
- **失败路径测试与试点前置**：首腿成交+次腿拒绝/超时/UNKNOWN、部分成交/撤单与
  迟到成交竞态、补偿单部分成交/拒绝/不确定、超时/异常退出/重启后未决订单、
  重复回报与重复启动——用实际策略与执行代码 + 受控外部叶子测试验证；
  真实模拟账户只做有界正向成交往返，不为制造异常扩大交易规模。
  试点要求相关账户初始空仓、无活动单；清理仅覆盖本轮授权订单与持仓，
  不清空账户其他业务。
- 每轮有界 policy（`max_actions`、`max_quantity`、`max_notional` 显式声明）、
  退出码 0/1/2/3 与 JSON 证据继续沿用（§2/§7）。

## 7. 验收矩阵与证据归档

每轮验收记录写入本目录 `evidence/<round>-<slug>/`：

- 范围与提交范围（文件白名单）；
- 验收命令与实际输出（dry / `--replay` / live / 关键日志摘要）；
- 最小证据字段（见 §7.1）；现场原始证据留在各目录 git-ignored `evidence/`，
  脱敏摘要与证据哈希归档到本目录（避免换机后只剩不可访问路径）；
- 仓库/分支/提交哈希（backtrader dev；SDK 若改则含 bt_api_py dev 提交与 gitlink）；
- 失败轮保留原始记录，修复后新起记录，不覆盖历史。

### 7.1 最小证据格式

| 层级 | 必要字段 |
| --- | --- |
| 运行 | schema 版本、run_id、示例 ID、开始/结束、状态与失败阶段、触发来源（natural/drill/none） |
| 运行来源 | 策略与配置哈希、Backtrader/SDK 提交与实际加载版本、验收命令 |
| 环境 | 场所、demo/simnow 类型、所选 front 组、交易日与连接代次 |
| 每腿 | 合约及规格、方向/offset/position side、逻辑与场所订单身份、请求量、累计成交、剩余量、终态及补偿关联 |
| 对账与清理 | 本轮最终持仓、活动单、快照时间与代次、预算消耗、UNKNOWN 是否存在、资源关闭结果 |
| 归档 | 脱敏证据路径与 SHA-256、验收代码来源、本轮提交引用 |

最终 tracker 逐示例字段：`dry`、`replay`、`live`、`tier`（成交往返 / 仅生命周期 / 仅自检）、
`trigger`（natural/drill/none）、`env_scope`（front 组与环境类型）、`orders`（报/撤/成交数）、
`cleanup`（平仓与对账）、`evidence_sha256`、`commit`、`status`（PASS/BLOCKED+证据）。

## 8. 风险与对策

1. **SimNow 前端时段性与能力差异** → TCP 探测仅作候选筛选；运行前验证登录、
   交易日、合约可交易、行情到达与新鲜度；自动选择/回退仅限首次写入前；
   标准与 7x24 证据按覆盖范围分别记录（资金/保证金/结算结论分开标注）。
2. **SimNow 写准入与 Store 链路集成未定** → R0 定接口方案（Store 可消费接口或
   窄范围 SDK 补充），R1 前完成源码验收；不得私有属性绕过 Store，
   不同时维护两套执行链。
3. **SimNow 期权合约可用性**（014/015）→ R0 只读预检 + 交付前复验；
   不可用则证据化 BLOCKED + 如实写明翻转所需配置/映射变更与复验范围。
4. **策略自然信号稀疏**（套利类阈值型策略）→ 自然信号优先；drill 仅限
   "无自然尝试、无未决/UNKNOWN"门控下使用；不覆盖失败或不确定结果。
5. **旧测试与字节绑定**（manifest、`qualification-v3.json`、字节 pin 测试、
   `VENDORED_COPIES` 漂移守卫）→ 清理前逐目录登记依赖与替代位置；只删被替代
   入口与失效候选；统一刷新清单与逐文件核对；历史证据工件保持字节不动。
6. **012 经济禁令** → 已按"技术验收"例外登记（1.3）；不改经济研究结论。
7. **环境差异**（CTP 需 CPython 3.11 + dev SDK）→ README 写明解释器与 SDK 路径要求；
   `run.py` 在错误解释器上给出明确拒绝信息。
8. **自包含契约** → 四件套为公开使用契约 + 已安装 SDK；
   `test_examples_self_contained` 只查导入边界，另做目录外 dry/`--replay` 运行检查；
   跨目录复用走字节一致副本 + 守卫登记。
9. **写入意外扩大** → 每轮 policy 有界 + `--allow-write` 显式授权 +
   订单登记/补偿撤单/UNKNOWN 冻结 + 多腿失败与清理预算规则（§5.3）；
   验收结束强制平仓与账户对账。

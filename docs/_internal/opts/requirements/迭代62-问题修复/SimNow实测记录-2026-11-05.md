## 4. 实测发现并已修复的缺陷

1. `CtpDirectWriteProvider.settlement_status` 把“完整查询但无当日确认”误判为 UNKNOWN（实际状态码为 failed/unknown 等）；改为按查询结果完整性判定 UNCONFIRMED。
2. 撤单使用去掉空格的 OrderSysID，CTP 按原始右对齐字符串匹配；改为优先用原会话 FrontID/SessionID/OrderRef，否则用原始 `order_sys_id_raw`。
3. Store 启动在 direct 模式仍执行 SDK 执行日志恢复（无日志，报 unproven）和托管余额读取；direct 模式改由 Broker 的账户事实与 live_state 负责。
4. SimNow 路由在 SDK 中的环境标签为 `demo`，示例 `MarketInstrumentKey` 用 `simnow` 时订阅报 `MARKET_STREAM_ROUTE_UNAVAILABLE`。
5. BT 行情订阅的身份检查只接受旧版 tick 身份类型，SDK provider 会话 owner 返回中立 `MarketStreamIdentityReceipt`；合同改为两者都按同一键与状态校验。
6. Feed 缺少合约最小变动价位时把每笔行情标为 `PRICE_TICK_UNKNOWN`（数据缺陷），保持 DELAYED、不生成 bar；示例配置增加 `contracts`（交易所、price_tick、乘数）写入 Store 合约元数据。
7. direct 订单缺少 `comminfo`，成交通知时 BT Trade 记账崩溃；提交时补齐。
8. 场所时间核对容差过窄：SimNow 登录返回的交易所时间比 NTP 校正后的本机时间约晚 2.1 s（整秒截断加传输延迟），原容差（粒度+误差界+0.5 s）判为不一致导致全部行情不可交易；容差改为粒度+误差界+已配置的延迟上限（默认 2 s），逐笔延迟仍按 D62-37 直接比较。
9. CTP 行情投影没有原生规则标识（`rules_hash` 为空），而合同要求可交易行情必须带质量合同引用；改为由 SDK 时钟资格策略在 provider 未提供时写入自己的策略引用（I62-09），连续性缺陷的行情仍不可交易。
10. CTP 行情客户端以原生 Join 观察线程启动，停止永远无法证明完成，Gateway 关闭报告 `UNSUBSCRIPTION_UNCERTAIN`/`CLOSE_FAILED`；改为无 Join 观察线程（I62-11）。交易客户端同类问题暂未修改（GAP，见 I62-11）。

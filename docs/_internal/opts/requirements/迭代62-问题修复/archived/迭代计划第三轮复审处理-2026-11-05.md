## 补充说明

- `BtApiBroker` 当前预检对账户模式作直接比较；账户事实和 BT 投影的合同要分别验证，不能因为 CTP 有多空双侧记录就误拒 `net` 模式。
- 原生 6.7.7 Trader API 未找到现成 `ReqQryInstrumentStatus` 方法；不能因为存在相应结构体或其他 CTP 版本接口，就写成当前项目已有查询。当前公共流 QUICK 的登录后范围与状态通知是否属于该流，仍须分别验证。
- 调度顺序为同一策略内的实际发送顺序，不意味着先前委托已成交。策略在平仓原单被拒后重提的新单顺序可能晚于已经排队的反向开仓单。
- 交易所日历、时间证据、账户权限、交易与回报都必须按源码、隔离模拟、安装和已授权账户分别记录证据，不能以本次文档处理替代。

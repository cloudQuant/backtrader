## 3. 接口合同（冻结）

### 3.1 写入准入（D62-01、02，INV62-01/02）

- 配置：`write_enabled`（布尔，默认 `False`）。只能由显式配置开启；不按模拟或实盘、前置地址或模式名区分。
- 操作：`place`、`cancel`、`settlement_confirm`。
- SDK 每次写入前签发一次性 `WriteGrant`（绑定 route、操作、会话代际、随机编号），provider 在原生调用前通过 SDK 提供的校验器核销；同一授权只能核销一次，会话代际变化即失效。
- 未开启或校验失败时不发生原生调用，返回 `write_admission_denied`。
- CTP 现有的 `simnow_direct_writes` 开关和 SDK `_reject_simnow_profile_write` 的提前放行在 62.02 删除，由统一准入取代；托管运行时的原生能力机制保留。

### 3.2 direct 下单与派发前提交（D62-03、04a1、14，§5.3b R-4）

`BtApi.make_order(exchange, request, *, pre_dispatch_commit, host_scope)` 在没有执行会话时的顺序：

1. 写入准入检查（未开启即拒绝）。
2. provider 预留原生身份：CTP 在当前会话 `MaxOrderRef` 之上分配 12 位 OrderRef，并带 FrontID、SessionID、交易日、会话代际。
3. 调用宿主注入的 `pre_dispatch_commit.commit(record)`。返回耐久确认才继续；缺少端口、异常、超时或未确认一律不派发，并释放预留。
4. 再次核验会话代际和准入，签发一次性授权。
5. provider 派发原生请求，返回受理前的提交结果。

撤单同理：按原始身份（FrontID/SessionID/OrderRef，或 ExchangeID/OrderSysID）撤单，先耐久提交撤单标记再派发。

### 3.3 direct 回报（§5.3a 第 2 条，I62-01）

- provider 把 OnRtnOrder、OnRtnTrade、报单/撤单错误回报转换为中立事件，携带原生身份、会话代际和交易日。
- SDK 用"本进程预留表 + 宿主恢复的未决标记"关联事件；关联成功的标为 `direct_identity_match` 证据交给宿主，无法关联的保持未验证。
- 去重键：订单状态按 (FrontID, SessionID, OrderRef) 或 (ExchangeID, OrderSysID) 加状态序；成交按 (ExchangeID, TradeID, Direction, OrderSysID)。
- 私有流改为 RESTART（I62-01），每次登录重放当日回报，用于重启恢复。

### 3.4 行情时钟资格（D62-21、27、28、37）

- SDK `ClockVerifier` 用 SNTP 测本机偏差与误差界限（多服务器取最小界限），有效期 15 分钟，过期即视为未验证。实测（2026-11-05 21:50）：本机慢约 0.28 秒，界限约 75～160 毫秒。
- 场所时间交叉核对：CTP 登录回报中的交易所时间与校正后的本机时间之差不超过 1 秒加误差界限。
- 来源时钟与接收时钟同时满足上述条件时，SDK 把 tick 标为 VERIFIED，并记录误差毫秒数；来源时间到校正后接收时间的实测延迟不超过 2 秒（D62-28、37）为 FRESH，否则为 STALE。
- 不满足条件的 tick 保持 UNKNOWN 或 STALE，仍交给 BT 进入数据线（D62-27），但不能用于下单；缺少或无法解析来源时间的 tick 不进入数据线。

### 3.5 BT direct 状态目录（D62-04c、05、13、14，I62-06/07）

```text
<策略目录>/
  state/identity.json        策略 UUID、主机名、目录路径、账户与 route 绑定
  state/sequence.json        局部序号与 ref 高水位（文件锁保护，原子写入）
  state/pending.json         派发前未决标记（派发前提交端口的 BT 实现）
  state/waiting_orders.json  休市待发单（D62-30）
  state/audit.log            人工核验与身份迁移的审计记录
  state/run.lock             运行期排他锁（实现采用 `run.lock`；见计划修改记录）
  logs/current_position.yaml 版本化持仓快照（D62-05 的固定入口）
  logs/<配置名>/<时间戳>/    TradeLogger 可读日志（按运行分目录）
```

所有状态文件采用"临时文件、落盘、原子替换"写入；快照记录运行模式、账户与 route 绑定，模式或账户不符的快照不能用于实盘恢复（§5.3b R-2）。

### 3.6 订单类型与有效期（D62-33，I62-02、05）

CTP direct：限价单按原值发送（GFD）；`valid=None` 与 `Order.DAY` 为 GFD；市价单只在场所支持时按 CTP 协议表达，否则报告 `order_type_unrepresentable`；`Order.Close`、止损类在当前路径报告无法表示；显式 GTC 报告 `order_validity_unrepresentable`。

### 3.7 交易时段（D62-30、34、36，I62-04）

provider 提供含夜盘的品种时段表与交易日（2026 年数据来自已审核的预期日历规则），SDK 提供中立查询：给定合约与时刻，返回所处阶段（休市、集合竞价、连续交易、未知）、当前交易日与下一连续交易时段。2027 年节假日未公布前返回未知。

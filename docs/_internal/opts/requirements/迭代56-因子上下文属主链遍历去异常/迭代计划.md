> 状态：**待审阅**。本轮只产出计划与实测基线，未修改任何源码。
> 分支：`dev`（直接在现有工作区推进，不另建 worktree）。
> 证据级别：全部数字为**本机合成基准实测**，不含任何真实账户结论。
> 关系：本迭代优先级**高于**迭代54（参数访问器改单，实测仅值 1–3%），二者同病因、不同风险面，见 §7。

## 1. 核心目标（唯一）

消除普通（非研究）回测里**每 bar 数十次的 `AttributeError` 构造**：`_factor_strict_context` 这个只在
研究严格模式下才会被实例持有的属性，在非研究路径上从不被赋值，但每 bar 被 `getattr(obj, "_factor_strict_context", None)`
反复查询；由于 `LineSeries.__getattr__` / `Lines.__getattr__` 对下划线名不缓存，每次查询都要走
"Python 函数调用 → 格式化 f-string → 抛异常 → getattr 吞掉" 全链路。

手段：在 [lineroot.py:59 `LineRoot`](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineroot.py#L59) 与
[lineseries.py:710 `Lines`](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineseries.py#L710)
两个类体各加一个类级默认 `_factor_strict_context = None`，使该查询变成一次普通类型属性命中。

### 明确非目标

- **不改任何研究侧语义**：严格上下文的安装、传播、失败聚合、错误传播一律不动。
- 不在本迭代处理 `_lineaction_datas` / `_datetime_line` / `_owner_ref`——它们有直接读取或 `try/except AttributeError`
  分支，加类默认会**改变控制流**（§4 逐条给证据），必须另轮逐点改。
- 不改 `__getattr__` 的实现本体（不往里塞特判），避免把优化写进已经是热点的兜底函数。
- 不动公共 API，不引入 metaclass。

设计意图本身写在源码注释里（[lineiterator.py:399-401](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineiterator.py#L399)）：

> "Normally descendants receive the context during construction. Walking the owner chain here is a
> **defensive fallback** for custom construction paths that attach an owner after `donew`."

即：遍历是防御性兜底，但今天**无论有没有上下文都无条件执行**，这就是本迭代要拿掉的固定成本。

## 4. 为什么不能顺手把别的名也一起加（逐条源码证据）

审阅者最可能问"既然这招好使，为何不批量套"。答案是**这些名字的读取方不是 `getattr(..., 默认)`**：

1. **`_lineaction_datas`**：[lineiterator.py:1953-1960](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineiterator.py#L1953)
   是 `try: datas = self._lineaction_datas / except AttributeError: datas = self.datas; filter_lineactions = True`。
   加类默认（无论 `None` 还是 `()`）都会**跳过这个 except 分支**，直接改变逐 bar 的数据过滤控制流。
   实测证据：运行时把该名的未命中改成返回 `None` → `TypeError: 'NoneType' object is not iterable`（该异常栈就在
   [lineiterator.py:1962](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineiterator.py#L1962)）。
   → 若要处理，必须先把 `try/except` 改写为显式哨兵判断，再谈默认值；属独立小轮。
2. **`_owner_ref`**：既有 `getattr(owner, "_owner_ref", None)`（[:81](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineseries.py#L81)），
   也有**直接读取** [:125](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineseries.py#L125) `owner._owner_ref`。
   直接读取处今天可能靠 `AttributeError` 走别的分支，加类默认会把"抛异常"变成"拿到 None 继续跑"，属静默语义变化。
   → 需逐点审计后才能进清单。
3. **`_datetime_line`**：[feed.py:744](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/feed.py#L744)、[:909](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/feed.py#L909) 为直接读取，同上必须逐点审计。
4. 反观 `_factor_strict_context`：`backtrader/` 内全部读取点均为 `getattr(..., None)`
   （[lineiterator.py:407/561](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/lineiterator.py#L407)、
   [linebuffer.py:73/1766](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/linebuffer.py#L73)、
   [research/factor_strategy.py:373](file:///Users/yunjinqi/Documents/new_projects/backtrader/backtrader/research/factor_strategy.py#L373)），
   且 `backtrader/` 与 `tests/` 内**无任何 `hasattr(...)` 或 `del` 依赖该名**（已 grep 验证，无命中）。
   → 类默认与今天的"未命中→getattr 默认 None"完全等价，这就是本迭代敢只加两行类属性的理由。

## 6. 验收矩阵

### 6.1 正确性（硬门，任一失败即回退）

- `make test-fast` + `make test-strategies`（1,286 个按 master 指标烘焙的回归）。
- 研究侧门禁：**21 项**（[tests/unit/test_factor_strict_error_propagation.py](file:///Users/yunjinqi/Documents/new_projects/backtrader/tests/unit/test_factor_strict_error_propagation.py) +
  [tests/unit/test_factor_research_isolation.py](file:///Users/yunjinqi/Documents/new_projects/backtrader/tests/unit/test_factor_research_isolation.py)）全绿——
  这两份是"上下文丢了会不会静默算错"的直接防线。
- 迭代48/49 的全 101 公式 native/build × runnext/runonce 四道矩阵（本改动位于每次回调包装处，研究侧首当其冲）。
- 多数据/多周期专项：次级时钟 `_resolved_secondary_clock` 相关用例（AGENTS.md 明确该区一改就要跑 `make test-strategies`）。
- `BACKTRADER_USE_INSTALLED=1` 与本地源码两条解析路径都跑，防止假绿。
- 逐字快照对比：改动前后同一数据集上策略计数 + 各指标末值 + 表达式末值必须完全相等（R0 落为测试）。

### 6.2 性能

- 门禁：runnext ≥25%，runonce ≥3%（R1）；R3 再叠加 ≥4%。
- 测量要求：同机交替 ≥3 轮取最小值、固定解释器、脚本必须**断言 `bt.__file__` 落在仓库根内**。
  本目录脚本首版就踩过这个坑：从 `docs/**/evidence/` 直接运行会静默测到 site-packages 安装副本，数字全部失真。
- 反作弊：不得靠调低 bar 数、减少指标数或换 `stdstats` 来凑比例；基准配置在 R0 冻结。

### 6.3 诚实边界

- 32.8%/4.5% 是**该合成指标栈**的数字，不是全仓库平均值；纯表达式指标 + runonce 的日常日线回测收益会靠近 runonce 那一列。
- 合成基准只证明分发开销，不等于任何策略盈利，更不接触真实账户（本迭代不涉及任何 provider/账户路径）。
- 若 `test-strategies` 或研究 21 项出现任何漂移，一律按语义回归处理，禁止调阈值或标记 xfail。

# 迭代 71（opts 线）：全库缺陷修复与性能优化（静态审阅驱动）

状态：**规划草案（REVIEW_PENDING）**，2026-11-17。本轮只做静态审阅与计划，**不修改任何产品代码**；本计划不表示缺陷已修复、性能已提升或任何能力已验收。所有发现见[审阅发现清单](审阅发现清单-2026-11-17.md)，证据级别以该清单为准。

## 1. 背景与目标

2026-11-17 使用 OpenCodeReview（`ocr`）v1.13.11 对当前 `dev` 工作树的 `backtrader/` 包做全文件扫描，并由 10 个只读子代理按域复核。目标是：

1. 找出会导致**错误交易状态、错误指标/报告结果、静默数据丢失、资源泄漏或异常路径失控**的真实缺陷。
2. 找出在回测/实盘热路径上**可显著测量**的性能问题（O(n²)、每 bar 重复分配、每 tick 重复 DB/锁操作等）。
3. 把发现整理成可分批实施、可回归验证、可回退的迭代步骤；本轮不实施。

本计划不把 OCR 候选当作事实：每条进入清单的发现都经过源码回读；标注 `PLAUSIBLE` 的条目必须在实施前用最小复现确认。未运行仓库测试，未取得真实账户、SimNow、真实 Gateway/Risk 证据，均为 **NOT_RUN**。

## 2. 审阅方法与范围

- 工具：OpenCodeReview v1.13.11，`ocr scan` 全文件模式；模型为当前会话模型 `deepseek-v4.1-flash`（OCR 网关不接受 `[1M]` 上下文别名）。
- 并行：10 个子代理，按核心引擎、线系统、broker/execution、feeds/stores/service、核心指标、contrib 指标、分析器/报告、Alpha101、外围/绘图/工具、性能专项分域。
- 范围：`backtrader/` 下 693 个 Python 文件；16 个 OCR 会话（含 1 个 17 文件管线自测），约 1,049 次文件审阅（含域间重叠），约 14.6M tokens。
- 证据：`STATIC/CONFIRMED`（源码可证明）、`STATIC+FAKE runtime`（子代理用 `/tmp` 合成数据复现）、`PLAUSIBLE`（待复现）。真实数据、真实账户、真实 Gateway/Risk 均为 `NOT_RUN`。
- 详细扫描统计、会话 id 与逐条发现见[审阅发现清单](审阅发现清单-2026-11-17.md)。

## 4. 目标与非目标

### 4.1 目标

- 先修复 P0/P1 中**能证明会造成错误结果、错误交易状态或资源泄漏**的条目，并补最小回归测试。
- 对 P1 性能条目给出 before/after 基准；没有可测收益的条目不进入实现。
- 保持公共 API 兼容；不引入新 metaclass；不改变现有默认交易语义。
- 所有修复按小步提交，保留无关 dirty 修改；状态为 `REVIEW_PENDING`，用户 `ACCEPTED` 后才算通过。

### 4.2 非目标

- 不重写 `strategy.py`/`linebuffer.py` 等大文件；不进行无发现支撑的架构重构。
- 不修改 `bt_api_*` SDK 合同；BT 侧只修适配层，跨仓变更按 SDK 子仓 → 父仓 gitlink → BT 顺序另行处理。
- 不因性能优化改变订单/成交/UNKNOWN/风控语义；性能改动必须先证明等价。
- 不把静态审阅或 fake 运行当成真实账户、SimNow、真实 Gateway/Risk 或发行验收。
- 不批量修复 207 个 contrib 指标中的全部 P2/P3；首批只处理已复现的 P1/P2 正确性问题。

## 目标与两轮分工

同一 `FactorSpec`、因子类和 native/build 图可用于研究、回测和实时增量计算。迭代50负责共用的严格绑定、闭合bar交付、指标前截面同步、预热/恢复、有界缓存和普通Strategy到BtApi执行链的基础；不把因子变成另一套调度器或交易客户端。

| 范围 | 交付责任 | 完成条件 |
|---|---|---|
| 49及可能追加的优化轮 | 批量研究性能与既有公式优化 | 采用已经提交的可复现基线，不等待未定优化轮结束 |
| 50-A 基础切片 | Alpha003所需的完整通用链，含必要核心回归、安装与恢复 | [验收方案](验收方案.md)定义的50-A交接集合通过，只表明该profile基础可用 |
| 50-B 全101扩展 | 全101字段/数值/qbuffer/缺格、递归因子边界和多因子长稳 | 剩余AC50-01～27全部通过，不用Alpha003代表全部因子 |
| 51 示例落地 | 自动主力、共同交易分钟、受控换月、统一028示例及SimNow实际闭环 | [迭代51](../迭代51-因子流批一体与Alpha003-SimNow实盘示例/README.md)全部必需验收通过 |
| 50-C 真实路由验证 | 引用51相同版本/profile的真实行情、订单和恢复证据 | AC50-28～30逐项核对，不另建示例或重复账户调用 |

依赖只有 **50-A → 51运行集成**；51的主力研究/公开数据准备可提前进行，50-B与51可并行，50-C不作为51的前置条件。50最终完成仍要求50-A、50-B、50-C全部通过，51完成不等于50全101完成。

共用模块及测试由50维护，主力和示例由51维护。即使同一开发者连续实施，也按模块归属登记；51发现共用缺陷时回到同一库修复、补受影响验收，不复制live绑定、cohort、订单journal或第二个runner。跨轮结果仅在来源/依赖、输入合同、实际profile与判据均覆盖时复用。

## v0.2 关键调整

1. 统一028示例；先交付完整Alpha003基础切片，不让全101泛化成为51的串行阻塞。

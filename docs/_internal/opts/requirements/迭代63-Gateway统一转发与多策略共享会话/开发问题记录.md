## I63-S002：SDK 结算状态与提交日/会话未绑定（R06 本地修复）

状态：**R06 本地修复，完整服务与账户验收仍待完成**。以下为修复前问题。SDK 基线 9a762e67，DirectWriteCoordinator.ensure_settlement 先读 status，再分别读取 session_generation/trading_day 构造 marker。状态读取后重连或跨日时，旧日 UNCONFIRMED 可能被用于新会话的标记；原生 grant 拒绝旧代不能替代 read-first 证据绑定。后续须使用 provider 绑定的结算观察与提交/发送前复核，并以稳定账户/交易日/attempt 恢复持久 marker。R05 只修 provider 的回读分类，不据此关闭本项或宣称 Gateway 每日自动确认已交付。

R06 修复前源码核对进一步确认：当时 WriteGrant 只含 route/operation/generation，不含账户、交易日或观察绑定；grant.issue 在 marker 提交后执行。CTP 普通 confirm 路径未传递 _request_settlement_confirmation 已有的 expected_generation，最终 native 入口的 settlement authorization 会话核对位于 callback-ingress 分支。后续须复用 provider 查询来源/issuer，把一份不可变观察贯穿 marker 与原生调用前复核；持久化进程无关的账户/日/attempt，不能把 issuer 对象当作重启身份，也不能以加锁声称网络发送原子化。进入 native 或提交结果不明仍按 UNKNOWN 恢复。

R06 处理：Base 观察和写绑定将同次 query 的账户、日、原生代际、observation_id 贯穿 SDK marker/grant 与 CTP 最终 native 栅栏；复制票据、声明变更、过期、重连和错误来源均拒绝。普通与 ingress 的账户 fingerprint 格式统一，SDK profile 不允许省略观察回调。Gateway 同库保存每日尝试并在重开后只读回查，不重复确认；周期维护复用现有 owner 线程。主代理的最终 SDK/Base/OKX/Binance 相关回归为 296 passed，CTP 扩大回归为 434 passed。完整联合、安装包证据与边界见[第六轮审阅](archived/实施第六轮结算与日志升级审阅-2026-11-08.md)。真实日期语义仍由 I63-S003 单独跟踪。

## I63-C002：交易 owner 在 TD 暂时不可用后不自动恢复（GAP）

R07 工厂维护先刷新账户 query scope 再更新结算观察；refresh 超时或抛错会触发既有 GatewayDirectOwner 的 maintenance_failed，停止接纳并执行清理。当前不会等待前置恢复或自动重建 owner；关闭未确认时仍须持有 guard 并可重试。该 fail-stop 行为不能算作 D63-03 / 63.09 自动恢复完成。

后续恢复必须先关闭交易准入、保持唯一会话/owner 与清理责任，再验证原生代际、订单/回报及账户状态，最后按各独立原因恢复准入；不能仅重新取得结算 CONFIRMED 就释放订单 UNKNOWN、急停或恢复门禁。用户的策略继续运行/等待 Gateway、不得回退 direct 决定保持不变。

# 63.12 控制端口与心跳 wire 冻结（2026-11-16）

状态：**常量与文档冻结**，对应 63.12（D63-24、D63-43、D63-25、D66-08）。证据等级 UNIT/FAKE；不证明真实 Gateway、Monitor、provider 或账户路径，也不改变 63 的验收状态。

## 冻结位置

- Gateway 包：`bt_api_gateway/control_wire.py`（控制端口）、`bt_api_gateway/monitor_heartbeat_wire.py`（心跳 ACK）。
- 人类可读合同：Gateway 仓 `docs/gateway-control-wire-v1.md`。
- 服务端使用：`bt_api_py/gateway_direct_service.py`（`direct.control.*` 处理与授权）、`bt_api_py/gateway_required_monitor.py`（心跳请求/ACK 校验）。
- 资源包：`bt_api_py/ctp_gateway_local_profile.py` 接受 `kind: "runtime"` 及显式 `runtime_proof`。
- 客户端配置：`bt_api_py/service_config.py` 新增 `runtime` 客户端别名，只允许 `application.direct_write`。

## 关键决定

- 控制端口沿用已冻结的名称 `direct.control.apply` / `direct.control.status` / `direct.control.resume`（计划正文的 `control.kill_switch` / `control.status` 是设计期拟名，`gateway-web-api-v1.md` 与本仓实现已使用现名）。
- 控制面由 Gateway `trading_owner` 角色在 `service.direct_write` 上提供，只有显式 `control_enabled` 时才可用；未配置时返回有限码 `CONTROL_UNAVAILABLE`，不公布这些操作。
- 路由器命令种类补 `STOP_NEW`（持久值 `stop_new`），与既有 FREEZE/DRAIN/RESUME 一样只记录并交给注入执行者，语义仍由交易 owner 的急停状态机执行。
- `runtime` principal 是 D66-08 的受限代理：仅策略范围、仅 `apply/status/resume`，只解除自己 `runtime:<哈希>` 来源的原因，且必须携带显式证明（稳定 `delegation_id`、已登记的运营 `operator_ref`、绝对 `expires_at`、显式 `revoked`）。缺失、过期、撤权、换主体一律拒绝；重放按 journal 的 cause id / operation id 返回原结果。

## 未包含

运行时客户端（66.07）、Monitor 客户端（68.05）、传输认证与真实账户/柜台证据不在本次冻结内；它们按本 wire 合同另行实现与验收。

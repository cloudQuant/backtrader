# 迭代 63 第十五轮：撤单准备、同库尝试与单 owner 排队

日期：2026-11-09（开发始于 2026-11-08）。整期 **IN_PROGRESS / 未验收**。本轮交付真正远端撤单所需的持久准备与本地派发链；服务 RPC、客户端、CTP 取消回报归属和 BT 接线仍待后续完成。未执行真实账户调用，未更改 BT 产品。

## 实现与审阅

主代理按[冻结合同 §18](../分轮合同冻结稿-2026-11-08.md#18-r15原生撤单尝试先准备再持久派发)划分五条实现线：Base/SDK 协调、CTP 准备及最终原生栅栏、Gateway 同库尝试、SDK 装配、同 owner 取消队列。两条独立只读审阅核对持久次序、身份、schema 和锁；主代理检查差异并独立运行跨包测试。

Base `PreparedCancelRequest` 保存原目标身份、独立派发日/代际、完整字段及严格排序唯一的尝试键，提供版本 1 的有界映射和摘要；它不授予权限。`PreDispatchRecord` 仅在显式 prepared cancel 时增加对应字段，严格匹配 route/target/symbol/day/generation。SDK `cancel_prepared` 按准备、持久提交、代际/授权复核、单次提交执行，不回退旧 cancel；未知或矛盾的提交结果保持 UNKNOWN。

CTP 在原有 Trader 状态锁下分配 RequestID/OrderActionRef 并保管精确来源票据，准备和释放均不发送或隐式连接。只有原实例签发的准备对象可单次消费；最终 native pre_dispatch 中重新验证 API/SPI/登录/字段并消费 grant，native_call_started 区分入口前拒绝与入口后不确定。调用 native 时不持 Trader 状态锁；provider 和 SDK coordinator 的串行化锁仍保留。真实 SPI 回调在 fake native 内由另一线程执行的用例仅证明内建 listener 路径，不证明任意第三方回调死锁安全。

CTP 本轮对原日与派发日不相同的目标在分配请求号前拒绝，即使有 OrderSysID 也不猜测跨日延续。原因是原生撤单没有交易日字段、场所号可能跨日复用；完整跨日恢复证明尚未交付。中立 DTO 可以保留不同日期，fake provider 的该向量不代表 CTP 账户支持。

Gateway 原数据库升至 v6，新增 cancel attempt 与其强键表，保留原命令、回报、净量和消费游标。v5 必须显式升级，v2/v3/v4 的显式入口升级至 v6；重开继续校验旧数据及新增记录。每次取消按策略和 operation_id 幂等绑定原命令/摘要/native identity；当前自有原命令路径要求原 principal，不把该限制掩饰为已实现代理授权。取消的 REQUESTED/DISPATCHING/SENT/NOT_SENT/UNKNOWN 只描述本次请求，不改变原订单或持仓。重复进入 DISPATCHING 的尝试不重发；结果落库失败保留该标记。

取消 Dispatcher 复用原 Dispatcher/guard/journal，SDK 用真实 coordinator 装配；原 owner 新增独立有界取消队列，默认 16 个等待位，与 PLACE 使用不同去重空间并共享唯一线程，优先处理取消且保留定期维护。关闭、过期、最终撤销和维护失败覆盖两个队列，活跃 native 不能被队列伪取消；status.accepting 仍仅描述 PLACE，取消必须看 enqueue_cancel 结果。当前 profile 和服务能力未自动开放该入口。

## 发现与处理

- I63-E015：初版取消键与原订单键只有单向冲突检查，可能写入后无法重开。改为按操作类型分开的两个命名空间；双向同文本键、后学别名和重开测试通过，取消空间自身仍拒绝重复。取消回报以后必须查明确的 attempt 空间。
- I63-E016：旧 helper 会隐式连接、旧授权消费时机早于最终原生锁；新增准备路径分别拒绝缺现存来源及在 final hook 重新消费授权。跨日目标也改为无证明即拒绝，不以接收日改写原日。
- I63-N001：补充网络 ACK 测试时发现 1 字节预算小于 sealed frame 开销，返回 UNKNOWN 而非明确超限；游标未推进。512 字节的明确 REPLY_TOO_LARGE 与不推进行为通过。该预算下限问题已登记，未在本轮修改产品。

## 实现及审阅结论

Base 提供 PreparedPlaceRequest，完整复制并封印身份、原生字段、日/代际、来源和独立请求键。PreDispatchRecord 仅在 PLACE 接受 prepared_place，没有该字段时维持旧编码。新错误事实 v3 把 place request key 纳入摘要；旧 v1/v2 形状及摘要保留。公共事件/page v3 只公开 prepared_digest，严格接受旧版本输入。审阅发现初稿可把带来源报单错误描述成 REJECTED，已修正为 status 必须 None（I63-E026）。

CTP 在现存 Trader 和已密封登录下预先分配 OrderRef、RequestID，固定实际 native double 的规范 float.hex 文本。准备不查询、不连接；完整准备与 marker 持久化成功后，原 native 最终锁内复验精确对象、来源及字段，消费 grant 后再验。原 insert history/evidence 的 record_dispatch 保留，原生调用不持状态锁或 provider 外锁。缺来源、字段变化或撤权不发送；进入 native 后异常保留 UNKNOWN。

新路径明确要求原生裸合约名、规范 exchange_id、contracts/lots/native 的正整数手数以及投机套保设置。默认 base 数量单位、非投机 hedge 和缺场所均在分配 ID 前拒绝；这是主代理冻结的显式收窄，不自动改变旧 direct 的映射。旧 CTP 单位校验 no-op 与套保字段遗漏已登记 I63-E025，旧路径仍 OPEN。

Gateway 原命令库显式升级到 v8，准备 JSON、摘要、独立键与原 native marker 同事务写入。旧 v2–v7 显式迁移不补造准备来源。insert 错误经专门入口在同事务核对原单、策略、身份、日/代际、来源与摘要，再写事实、侧表和事件；普通 ingest 拒绝 v3 绕过。运行中读取和重开也核对关联。错误仅为该次请求的观察，不改变命令派发状态、释放持仓/占用或消除 UNKNOWN，迟到 ORDER/TRADE 仍按原身份处理。

SDK CTP Gateway profile 显式选择 place_prepared，缺少能力不回退。原回报维护先投影完整 offered 前缀，再按类型入账；来源复验和原 ticket ACK 边界保留。缺 RequestID、旧 marker 无来源、字段不完整或错账户的拒单继续保留 ticket 并关闭新派发。来源标签只证明 Python 接收时上下文，不证明交易所内部入队时刻。

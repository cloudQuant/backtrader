## 3. 发现与建议

### QW63-01（P1）Gateway 宕机时的应急撤单通道仍无任何交付步骤

- **定位**：计划 §6.1"单点故障"行、§3.12"Gateway 宕机且有活动委托"与"日志损坏或丢失"行、§5 步骤表、§6.3 矩阵、63.09 场景 7；上一轮 RV63-01/Q63-01。
- **问题**：上一轮给出 a/b/c 三方案并列为问题 Q63-01，无回答记录；复核清单 §7/§11.1 也未把它列入待决。§6.1 缓解仍只写"运营撤单工具"，没有任何步骤交付该工具、没有验收项。CTP 无断线撤单（§6.2 第 3 项），Gateway 是账户唯一 TD owner：它宕机、起不来或日志损坏时，全账户活动委托无人可撤，行情波动直接成为资金暴露；63.09 场景 7"停 Gateway"也没有后续撤单动作。
- **建议**：按上一轮方案 b 为主：在 63.12（或新增子项）交付 Gateway"仅撤单模式"——同一份日志、身份映射与账户锁，登录后完整查询、按范围（账户/策略）撤单、写审计、退出或停留；方案 c（期货公司紧急撤单/手工终端规程）作为日志损坏时的兜底写入 63.10 的 Gateway 与 007 README；"期货公司是否提供断线/紧急撤单服务"并入 §6.2 第 9 项清单（联动 QW63-09）。63.09 增加场景：停 Gateway 后经仅撤单模式撤单。
- **理由**：FIA 把 Kill Switch / Cancel-on-Disconnect 列为最佳实践（上一轮 [S13]）；单一 owner 架构的可用性缺口必须有独立于 owner 本身的兜底，否则 D63-03"策略继续运行等待恢复"在长时间宕机下没有任何对冲手段。
- **验收**：回环 + 替身下仅撤单模式撤销全部/按策略活动单且拒新单、写审计；日志损坏时该模式明确拒绝启动并提示经纪商兜底；63.09 有一条 SimNow 撤单记录（在既有授权内）。

### QW63-02（P1）D63-38 的静默期/重复确认被复核清单定为"须另问用户"，但既未问也未登记

- **定位**：计划 §3.6"查不到"分支表与补充规则"不自行加额外等待轮次"；复核清单 G3 末句；上一轮 RV63-02/Q63-02。
- **问题**：G3 明确"是否增加额外静默期和多轮查询会改变既定判定时点，若要采用须另问用户"，但 Q34–Q40 不含此问，§11.1 待决表也未列。G3 补的"判定后迟到回报"规则只能事后更正账本，不能撤销策略在收到 Rejected 后已重新发出的订单：Gateway 崩溃后数秒内重启、启动完整查询立即判 `not_found_at_venue`，原单可能仍在柜台处理，重复敞口已经形成。迭代 62 direct 的运行中补账有 2 s 静默期（`direct_return_gap_quiet_period`），Nautilus 用阈值窗口 + 重试 + 定向查询（上一轮 [S1][S3]），Gateway 侧无任何对应参数。

### QW63-04（P2）账本数量/金额精度与比较容差未冻结，迭代 62 缺陷 26 的教训未进入 63

- **定位**：计划 §3.11（归属账本）、§3.11c D63-48 恒等式、设计 §5.2（四桶"四者之和等于原总量"）、共享合同 §2.17（"差额非零报告不匹配"）；证据：backtrader `37a1e2bf9`、`backtrader/brokers/_btapi_direct_mode.py:302–320`（`_QTY_REL_TOL = 1e-9`、Decimal 求和）。
- **问题**：迭代 62 缺陷 26（分数成交后 float 残差 −1.1e-16 导致订单不能完成、1e-16 幻影持仓）迫使 direct 模式改为 decimal 求和 + 残差容差；这是同仓库一周内的真实缺陷。63 的 Gateway 归属账本、external 账本、D63-48 恒等式、母单四桶守恒、D63-44 资金公式全部是数量/金额求和与相等比较，但计划/设计/合同只给整数手算样例，未冻结数值类型、规范化和比较容差——恒等式的"相等/差额非零"判定与守恒断言在浮点残差下会误报不匹配或漏判守恒破坏。本轮修改记录最后一条为 11-08 00:44，缺陷 26/27（`37a1e2bf9`、`442b020eb`，01:35 之后）也未登记进 §1.5。
- **建议**：63.01 冻结：账本与恒等式统一 Decimal（或定标整数）存储与运算；比较一律在规范化后精确相等，不用 float `==`；费用、盈亏、预算调节项的舍入与残差规则单列；§1.5 第 12 项补记缺陷 26/27 作为账本设计输入。
- **理由**：D63-48 的 Monitor 告警、D63-49 的拒单、设计 §5.2 的守恒都以等式判定为触发条件；CTP 手数虽为整数，但求和路径若沿用 float（如经 SDK DTO 转换）仍会复现缺陷 26 的形态。
- **验收**：63.03 账本测试含残差/分数聚合向量：恒等式不误报、四桶守恒不被 1e-16 级残差绕过；冻结稿写明数值类型与容差来源。

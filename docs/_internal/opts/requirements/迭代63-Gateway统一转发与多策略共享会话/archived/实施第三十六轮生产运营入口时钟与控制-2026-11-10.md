# 实施第三十六轮：生产运营入口的时钟与控制（2026-11-10 凌晨）

> 状态：IN_PROGRESS。不标 ACCEPTED。7x24 运行只验证启动、服务、控制状态与停止，不构成交易验收。

## 1. 发现：已安装的 SimNow 交易 profile 无法派发

此前 SimNow 运行使用 QA harness 自建的 profile。核查已安装的 `ctp-simnow-trading` 运营入口（`bt-gateway-operator`）后发现：

- 资源包加载器从未向交易 profile 传入 Gateway 时钟校验器、允许服务器与刷新策略。决策 B 下每次派发都要以新鲜报价和 Gateway 自身已校验的时钟限定，因此配置行情时所有派发均被拒（`MARKET_GATE_UNAVAILABLE`）；不配置行情时 claim 覆盖无法封印，同样无法派发。
- 资源包不能安装控制授权，因此运营入口没有急停能力。journal 已为 schema v10 时，`control_enabled` 缺授权即被拒，入口无法启动。

## 2. 修复（SDK，本地 dev，未推送）

- `d3027d6d`：交易资源包可带 `clock` 段（SNTP 服务器、最大误差界、样本有效期、刷新间隔）。配置行情而缺 `clock` 时启动即拒绝；不含行情的旧资源包仍有效。附测试与变异检查。
- `515d25c6`：交易资源包可带 `controls` 段：APPLICATION_CLIENT 运营身份、其 CURVE 公钥、仅限 `direct.control.*` 的 `service.direct_write` 授权（`GatewayControlGrant` 二次限制）、账户或策略范围，以及显式的 `upgrade_controls_from_v9`。运营者不获任何交易授权。
- `34205217`：运营示例文档补充上述两段。

## 3. 生产入口复核（7x24，非交易证据）

以本轮重建的 wheel 安装到隔离 venv，由 QA 构建器生成受保护资源包：凭据只从 `.env` 程序化写入 0600 文件，复用 harness 的 journal、守护目录与身份。

- `bt-gateway-operator` 离线校验通过。
- 启动报告 `ready: true` 后转入 running；控制客户端可读取既有 FREEZE 原因的状态。
- BT 策略 B 连接后持续收到实时 tick。其 21 时遗留预约在启动时经 Gateway 判为 EXPIRED 并通知 Canceled。
- SIGTERM 后 stop 成功，状态 closed。

过程中的配置问题：QA journal 已由控制演练升级到 v10，运营配置须同时设 `control_enabled: true` 并提供控制授权，否则 owner 目标 schema 为 v9，启动失败。journal 不降级，属设计。

## 改进与审阅结论

Base 新增不可变 GatewayReturnFact，严格映射、规范十进制字符串、完整事实摘要与成交经济摘要分开。它不认证账户、来源或交易权限。Gateway 在原命令 SQLite 库扩展 v4，以一个事务保存原回报、强键归属、成交去重、策略净增量和事件；原派发身份/强键/版本保持不变，后来学习的场所别名单独存储，回报早于 submit 返回不会破坏 finish。

v2/v3 必须在既有账户 guard 和锚点下显式升级；迁移核对旧 schema、命令/强键/release/结算及共享容量。v4 重开验证完整 DDL 白名单、事实摘要和引用、事件序列，并从已应用逐笔成交精确重算净增量与每单累计量。额外触发器、损坏量、孤儿事实、非法序号、未归属记录错误挂靠等均拒绝；不自动修库，不证明任意外部备份或整体篡改的真实性。

独立审阅复现并修复 I63-E002：成交带会话 A 与未绑定的 venue X 时不能先归属 A，再由 B 的订单回报学习 X。现只有 ORDER 可学习唯一的新 venue，其他未绑定强键先保留 UNATTRIBUTED；所有键一致后才归属。多命令命中及同成交键经济内容矛盾持久保留，原内容重放不能清除冲突或重复入仓。订单累计 filled 不当逐笔成交；NOT_SENT 后实际成交保留矛盾。未归属不自动归 external。

公平恢复扫描采用仅提交成功后推进的 owner 内存游标，避免前 256 条长期未归属记录饿死后续记录。fact_count 与每单累计量同事务维护，避免每笔全量扫描；pending 和策略事件有专用复合索引，实际 EXPLAIN 验证范围检索且无临时排序。无投影返回 None，真实抵消保留字符串 0；这仅是本库成交净增量，不是账户基线或真实可平量。

同库事务采用 SQLite 的显式事务机制；不同数据库各自提交不能替代此原子边界。数值以 Decimal 和规范文本处理，避免用二进制浮点构造精确成交量。[SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)、[浮点说明](https://www.sqlite.org/floatingpoint.html)

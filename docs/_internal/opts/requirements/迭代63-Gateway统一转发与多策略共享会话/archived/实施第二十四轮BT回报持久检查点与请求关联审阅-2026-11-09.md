## 审阅处理

主代理使用 bmad-code-review 的审阅与分流流程，沿用当前受信合同审阅，另外并行安排边界审阅与验证缺口审阅；依用户规则不强制发现数量、不重复申请已授权修复。主代理阅读最终差异、独立运行源码回归及包/提交核对。逐项记录见[审阅发现](../evidence/round24-20261109/review-findings.json)。

- **E046，读取起点错配**：实际 after=1 仅返回序号 3 的结果，不能写入 stored=0 的宿主；原 after=0 结果随后仍可保存 1 和 3。独立 Gateway 进程通过真实 SDK、ZMQ/CURVE 验证该行为，数据为合成事实。
- **E047，原生合约符号**：初版误用 instrument_id 匹配请求 symbol，已对齐服务端 native_symbol 合同，覆盖两种符号不同的合法回报和原生符号错误拒绝。
- **原命令关联**：校验原 binding key 摘要子集，同成交键不能归另一个请求/预留；允许合法原生身份富化和场所别名。prepared digest 没有本地原文时不伪造验证。
- **JSON 幂等**：同投影水位使用规范 JSON 字节比较，覆盖 1/True、0/False、1/1.0。该问题已在工作候选内修复；不表述为已发布账户故障。
- **升级证据缺口**：加强原用例，在 v3 已有取消 plan/record、原生身份、active marker 和 terminal history 时升级并重开，逐字段核对保留。只加强测试，未为此修改迁移产品逻辑。
- **保留 NOT_RUN**：旧 v1/v2 wire 页经新增 SDK 请求上下文、BT 持久端口和重开的组合尚无本轮证据。Base 解码单测和当前 v3 网络用例不能代替此组合。

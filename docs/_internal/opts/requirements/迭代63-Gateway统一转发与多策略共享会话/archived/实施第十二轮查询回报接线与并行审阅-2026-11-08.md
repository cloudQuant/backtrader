# 迭代 63 第十二轮：查询回报接线与并行审阅

日期：2026-11-08。整期状态：**IN_PROGRESS / 未验收**。本轮为本地源码、合成原生接口和隔离安装切片；没有执行真实账户调用。

## 范围与并行分工

按用户要求增加并行：四个执行切片分别负责 CTP 来源栅栏与原生查询、CTP 精确回报投影、Gateway 预留事务准入、SDK 查询入账组合；独立审阅代理检查边界。BT 接线、旧执行流/ACK 与剩余项的只读盘点同时完成。主代理冻结合同、检查 diff、独立运行最终源码回归并接受本轮局部结果。文件所有权分开，没有重复开发同一实现。

本轮沿用 [冻结合同 §15](../分轮合同冻结稿-2026-11-08.md)：

- CTP 成交回调在 Python 入口捕获接收代际，锁内复验精确 API/SPI/会话并拍字段，getter 重入后再核验；监听器锁外执行。原先 API/SPI 替换及同 SPI 重登录竞态已用 barrier 复现。
- 同一个已登录 TD 的 orders/trades 查询经过封印、请求过滤、成功终包、摘要、来源及 TTL 检查；复用原生查询 accumulator 的 8192 行上限，超过上限拒绝。批次不可变，最新 ticket 受 owner/PID 限制，逐笔复核不重扫整批。
- provider 原生整数数量不经 float 转换；CTP double 价格按收到的值规范化。绑定身份、场所身份分开，交易日/会话不从当前登录补写；SDK 统一生成强键。弱 OrderRef 不升级为强身份。
- SDK 将整批先投影，再逐笔写入原 R11 同库账本。失败可留下已提交前缀，重读幂等；查询处理成功不表示完成归属、启动恢复或解除 UNKNOWN。
- 新预留 fence 持有至 SQLite 提交/回滚结束；原幂等记录仍可查询且不续 TTL。只在工厂/进入前的精确拒绝能回复 ADMISSION_DENIED，提交后/退出错误保持不确定。

## 审阅发现与修复

| 项目 | 触发与影响 | 处理与证据边界 |
| --- | --- | --- |
| I63-E003 | 检查与拍字段之间换 API/SPI 或重新登录，旧回调贴上新接收代际 | 同锁捕获与复验；原代码两种 barrier 场景失败，修后通过。不证明进入 Python 之前的 native 延迟来源。 |
| I63-E004 | 成交键没有交易日，跨日同号被持久去重误判为冲突 | 键改为交易日/交易所/合约/成交号；同 guard、同 ledger 的两日合成成交各入账一次，重读不重复。 |
| I63-E005 | 两个有效但不同账户的 reader 和 ledger 可被错误组合 | 单一 AccountKey 关联 reader 账户/经纪商/环境、账本 canonical scope 及合约 realm；交叉组合连空查询也拒绝。 |
| I63-E006 | 查询复制/摘要后返回前可能已经过期 | 返回前复验精确 ticket 与双时钟期限，失败撤销；分别注入 UTC/monotonic 越期，不用 sleep。 |
| 新投影拒绝优先级 | 原生未知状态 a 配合 InsertRejected 4 被提前拒绝 | 保留显式报单拒绝；撤单/改单拒绝不推成原单拒绝。 |
| 新 reader 重复扫描 | 每笔入账前重算完整 batch 摘要形成平方级工作量 | read 完整核验并冻结一次，assert_current 只做固定规模的来源/时效核对。 |

独立审阅复核上述三项组合问题修复后未发现本切片新的实质缺陷。该结论不代替部署、provider 或账户验收。

## 1. 遗留预约收尾（BT `8bc98d0a9`）

问题：派发被拒或结果未知的订单，其本地记录保持 RESERVED 并带有派发 marker；重启后该订单永久停在 Submitted。Gateway 重启后该记录属于旧 owner 代际，其后同一行情上的每次提交都报 `ORDER_RECONCILE_REQUIRED`（R33 夜间策略 A 即如此）。

处理：

- 绑定记录本进程实际请求派发的请求键。其余仍为 RESERVED 的预约视为前一进程遗留，回读后若仍为 RESERVED 则释放并以 Canceled 收尾；释放与迟到派发谁先成功由 Gateway 版本原子裁决。
- Gateway 已到期（TTL 或代际）的预约同样收尾：释放结果不明后回读状态、恢复路径和事件循环三处均覆盖。pending 宿主的 `cancel:` 本地通知现接受 EXPIRED 作为未发送终态。
- 已在本地收尾（`cancel:`/`reject:`）的订单不再阻塞后续提交；本进程仍在派发中的预约保持不动。

上述三个分支均做变异检查。真实复核：7x24 上重启策略 A 后，其 21 时遗留订单被 Gateway 判为 EXPIRED，BT 在启动时通知 Canceled，策略正常退出。

发现两处流程问题：

1. BT 发行名 `back-trader-python==1.4.0` 与 PyPI 已发布版本同号，按索引安装会取到不含 `live_state`/`service`/`execution` 的 PyPI 版本。正式运行须按文件路径强制安装本地 wheel，或改用本地版本号。

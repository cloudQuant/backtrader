## 结果与范围

R22 复现的行情初始化阻塞现改为原 native owner 上的非阻塞取得与来源探测，Gateway 使用有界 bootstrap 任务，SDK 客户端按原操作身份分步推进。策略客户端的原 owner 线程在步骤间维护租约并服务其他请求；没有新增原生会话、策略调度器或传输实现。默认传输仍为 bt_api_transport_zmq。本轮修改 Gateway 与 SDK，BT 产品、Base、CTP 和 ZMQ 产品没有修改。

合同见[冻结稿 §25](../分轮合同冻结稿-2026-11-08.md#25-r23异步行情引导与同线程续办本轮局部验证通过整期未验收)。操作按认证注册和稳定 ID 绑定，丢回复保留原任务，取消墓碑阻止晚到 begin；pending 和终态记录、结果字节及维护步数有界。共享 key 不重复取得上游；恢复借用原 active ref，单成员关闭或失效不自动释放原 batch 的其他成员。授权水位、来源描述、原始 epoch、回复预算和未确认清理继续保留。

默认市场设置请求异步三项；显式旧同步操作集合原样保留，部分异步集合拒绝，Registry 不自动授予新权限。异步服务拒绝旧同步 RPC，不允许发送后降级重试。

## 发现与修正

第一版完整 SDK 源码和安装均为 **702 passed / 8 failed**。其中七项旧同步三端口场景被新增的设置校验误拒绝；修正为默认异步、显式同步保持原权限，并补默认/部分集合验证。另一个本地新测试没有传入最终合同要求的 result_fits，按无 wire 的受信调用显式提供检查器，保留原断言；产品回复预算检查没有放宽。失败日志分别保留在 [source-v1](../evidence/round23-20261109/source-v1/sdk-source.log.gz) 和 [installed-v1](../evidence/round23-20261109/installed-v1/sdk-frozen-final.log.gz)。修复使用独立 v2 冻结与安装目录，不覆盖失败版本。

第一版安装验证的首次包核对通过；工作树进入修订后再次校验报告源码副本漂移，该日志也保留。它不能替代最终 v2 校验，也没有被当作新的安装产品缺陷。开发中发现并修正的其他边界包括：来源 future 被其他维护消费后丢失、pending-only reset/ACK 停滞、任务超时被 readiness 暂停延长、首次回复预算缺失、旧 batch 回滚误删共享 ref、恢复前新 SUB 创建失败影响旧资源、未发送换代被误判远端未知、授权拒绝未锁存、重复关闭及关闭后重授权重试死路。相关定向失败和复跑日志存入 development，不将共享中间态测试当作最终版本证据。

主代理复核上述最终差异并独立运行最终源码集合，未重复执行安装全集；安装由执行代理完成，主代理独立执行包与提交 verifier。Ruff E9/F 检查按执行者所列变更范围通过；装配产品文件既有 F401 单列在原日志，不宣称仓库完整 lint 无问题。

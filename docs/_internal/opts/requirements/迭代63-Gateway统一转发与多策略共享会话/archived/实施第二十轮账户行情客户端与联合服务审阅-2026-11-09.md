## 实现与独立审阅

按[冻结合同 §23](../分轮合同冻结稿-2026-11-08.md#23-r20同线程账户与行情客户端及保留调用结果)，扩展既有 ThreadedServiceClientRuntime：原线程构造、启动、调用并清理可选 owner 扩展，客户端持有单次调用句柄。等待超时保留同一次调用；取消仅作用于尚未开始的排队项。参数和结果以有限 JSON 值复制，限制深度、节点和字节预算。关闭尝试账户、行情与原 runtime 的清理，失败保留原资源重试；远端退订不确定计数不会被后续本地关闭抹去。工厂未返回资源便抛错时仍报告清理无法证明。

账户 owner 复用 ServiceAccountClient、原中立账户视图和单调时钟截止。超时后取回旧结果须在当前 owner 重新验证绑定和当前快照，不能重复 refresh 或延长新鲜期限。验证排队遇到 QUEUE_FULL/NOT_READY 时保留原结果和待验证阶段。status 的旧结果同样重新获取。当前只开放显式账户读取，不提供缺少来源的策略资金或 metadata；调用 timeout 是每个等待阶段的预算，不是组合调用总时限。

行情 owner 复用 ServiceMarketClient 和默认 bt_api_transport_zmq。配置静态订阅名且拒绝重复完整 key；不自动订阅、重同步或回退。每订阅绑定一个合作进程内消费代理，缺失或不同 token 拒绝；poll 出队后的转换失败在 owner 锁存 LOCAL_RESULT_GAP，不允许第二代理继续消费。原句柄跨等待超时保留并只取回一次结果。PID 在本地锁前检查，代理锁非阻塞。poll(timeout_ms=0) 不等待 SUB，但维护和补读 RPC 仍有其有界等待。该 token 约束不构成抵御恶意 Python 私有内存修改的安全边界；没有引入每 tick 的 reserve/ACK 往返。

GatewayStrategyClientSession 将必需交易绑定和可选账户、行情绑定装入同一个已有 owner runtime；各端口独立显式请求操作和 Registry grant，同一服务、实例、账户及策略运行身份。公开 market 配置沿用原合同省略 account_ref，由可信 scope resolver 注入注册范围。构造仅验证和复制公开配置、设置与可信密钥，不启动网络或原生资源。

ServiceHost 的 trading_owner 资源明确包含原 binding、可选 read_service 和 hub。审阅修正了三处边界：行情 publisher 只接受与真实 binding 账户、本实例和范围精确匹配的 market.subscribe 静态授权公钥，并要求 hub ACL 一致；正常行情 pending release 只拒绝相应行情操作，账户读取和独立授权撤单仍走原检查；history 的已知 key 授权错误映射为 SCOPE_DENIED。未知组件维护异常仍保留原 fail-closed，旧 market_hub 角色没有据此获得全面安全审计结论。

独立只读审阅发现并复核了 I63-E027–E033，主代理检查最终差异、冻结摘要、回归结果及安装内容后接受本轮局部交付。各审阅者的静态结论与执行者测试结果分开记录，不把静态复核写成独立运行测试。

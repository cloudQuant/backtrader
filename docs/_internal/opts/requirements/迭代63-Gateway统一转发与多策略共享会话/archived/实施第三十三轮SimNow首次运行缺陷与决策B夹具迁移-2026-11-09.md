## 2. 运行过程摘要

1. MD 登录回报的 request id 为 0，被丢弃，行情不可用（E086）。
2. 修复后策略可资格化并预约成功，但派发 RPC 先后返回 UNKNOWN（客户端把 `MARKET_GATE_UNAVAILABLE` 当作非法回复，E090）、`MARKET_QUOTE_EXPIRED`（候选窗口 250 ms 与 SimNow 报价节奏不匹配，E089）、`PRE_DISPATCH_FAILED`。
3. 逐层追踪到 CTP provider 的 `prepare_order` 因 `ctp_prepared_cancel_session_unavailable` 拒绝：SimNow 本次登录分配了负的 SessionID，而全部身份检查只接受正数（E091）。
4. 运行期间还观察到：每个维护周期的结算查询挤占 owner 线程（E087）；任一写者操作失败（MD 停止失败、SNTP 样本失败、Registry/journal 回滚）把 claim 域永久毒化，直至重启（E088）；BT 在预约被拒或派发被拒后把订单永久留在 Submitted，并在后续 `next()` 中先于读取事件返回 RECOVERY_PENDING，阻塞同策略全部事件处理（E092）。
5. 23:00 后改用 7x24：预约与派发链路正常推进，但策略资格判定为 `VENUE_CLOCK_UNAVAILABLE`。原因是 7x24 回放的 tick 带原始交易所时间戳，按设计不能用于实时交易资格（E096）。因此交易场景必须在实盘时段（日盘 09:00 起或夜盘 21:00 起）重跑。

## 4. 仍开放

- E094：BT 行情适配器把 `OWNER_OPERATION_PENDING` 当作终态；行情订阅客户端只有单个待完成槽位，由 poll 与时钟资格判定共享，一次超时调用后可能永久卡住。本轮由 harness 诊断线程的并发调用复现，诊断改为只读缓存后消失，产品侧尚未修复。
- E095：Gateway 关闭偶发失败（owner 线程仍存活），守护锁保持占用；当前只能在核对 journal 无已派发命令后人工复位，缺少运营对账工具。
- E096：7x24 回放无法满足实时时钟资格，属设计结果；63.09 交易场景须在实盘时段运行。
- E097：7x24 首次启动时回报维护持续 QUERY_INCOMPLETE，重启后恢复，原因未诊断。
- legacy `bt_api_execution` 存储仍要求正 SessionID（含 SQLite CHECK 约束），需要独立迁移，不在 Gateway 路径上。
- 回归现状：SDK `tests/integration -k iter63` 由 43 失败/18 错误降至 10 失败/6 错误（剩余为生成 profile/ServiceHost 进程组合与时序用例，以及引用退役模块的收集错误，均在上一 HEAD 已失败）；SDK `tests/unit` 全量 196 失败/17 错误在修改前后的失败集合相同（主要为非 iter63 存量）。这些须在 63.10 集中处理，不能以局部通过替代。

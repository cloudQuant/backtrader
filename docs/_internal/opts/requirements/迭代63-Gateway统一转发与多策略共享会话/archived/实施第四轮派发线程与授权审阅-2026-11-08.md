# 实施第四轮派发线程与授权审阅

日期：2026-11-08。范围：Gateway 耐久派发桥、SDK Registry 延后准入、独立 owner 队列、显式 dispatch RPC。结论：本地切片已完成针对性检查；整期仍为 **IN_PROGRESS / 未验收**。未修改 Backtrader 产品架构，未调用真实账户。

## 审阅发现与处理

| 发现 | 本轮处理 | 证据与限制 |
| --- | --- | --- |
| ServiceHost 同步 handler 执行 native 时会拖住网络收包与续租 | 独立账户 owner 线程；handler 有界非阻塞入队，按原键查询状态 | 真实 CURVE 回环、两个客户端和阻塞的 synthetic native；不能推定 native GIL 或存储阻塞也隔离 |
| owner admission 漏写 return 会放行 | 只接受字面 True | 缺失返回、False、异常和其他值拒绝；既有本地组合 fixture 同步 |
| 首次 RPC 授权不能证明排队后仍可派发 | Registry 签发绑定完整参数和认证上下文的进程内能力，初检和提交前复核 | 租约、撤权、注销、run claim、STOP_NEW、epoch、关闭及参数篡改测试 |
| 等待 journal 写锁时租约可能过期 | 取得写锁后再调用同 scope 的 recheck，重新检查预留 TTL | 实际 SQLite 第二连接持锁、受控时钟过期，保持 RESERVED、零 marker、零发送 |
| migration marker 的 sidecar 锁/fsync 也可能跨过到期或 close | marker 前校验，marker 完成后再次校验当前权限、时钟及能力状态 | 最终 Registry 测试含阻塞 marker 期间到期/关闭；主代理检查最终代码并复跑 |
| factory 已取得资源后异常，或 BaseException 杀死 owner，会丢失清理责任 | 明确 startup cleanup 句柄；未知清理状态保留 owner，清理失败可重试；四个责任边界保留 custody | synthetic guard、SystemExit/KeyboardInterrupt、关闭超时及清理重试；不能替代真实 session 停止证明 |
| 可把其他线程或其他 journal 的 dispatcher 误装进队列 | 发布 binding 前检查精确对象及 owner PID、线程、generation | 错线程预建资源和 journal 不匹配拒绝 |
| 无 owner 仍发布派发能力，或身份 JSON 隐藏敏感字段 | dispatch_enabled 显式发布并校验 owner；身份 JSON 完整解析、有界/重复键/敏感字段检查 | 默认三项 storage 能力；开启缺 owner 失败；CURVE 回环拒绝 synthetic secret-shaped 身份 |

## 主代理检查

所有 Python 使用 Anaconda base。Gateway 最终针对性与相关既有回归为 **167 passed / 2.40s**；SDK 最终联合回归为 **381 passed、1 failed / 5.62s**。唯一失败是已在 R02 用修改前源码独立复现的 I63-D003（Monitor roleless/control-only 配置），本轮未修改该规则或断言。首次 SDK 联合运行的 379 passed 后又增加了 Registry 关闭竞态和严格身份检查，故重新运行最终联合集；不把旧结果当作最终版本。

主代理检查最终 diff、锁序、身份投影和配置发布路径；各 worker 完成相关 Ruff，Gateway 两模块另做 mypy；主代理的 SDK/Gateway diff --check 通过。原始日志和逐项结果见[分轮记录](../实施基线与分轮记录-2026-11-08.md)。独立审阅为静态审阅，不计作额外运行次数。

最终 SDK/Gateway wheel 从干净快照构建，主代理独立核对安装/快照/源码文件集合和字节，安装后合成 smoke 及 137 项专用测试通过。Base/transport 仍来自既有 editable 环境，非干净依赖解析或真实 native 验收；产物和来源见分轮记录。对应本地 dev 提交为 Gateway `4e05fe1`、SDK `9a762e67`，未推送。

## 保留的边界

- QUEUED/ALREADY_QUEUED 仅是当前进程内排队观察，不能替代 DISPATCHING 的耐久记录或场所回执。超时、拒绝本次排队和丢回复不证明原命令 NOT_SENT。
- Registry → journal 锁序只保护同一协作 owner。固定 WAL snapshot 不拦截绕过 Registry 直接改数据库的外部写者；最后复核后到实际提交/发送之间不是外部硬 fence。
- permit.close 是非阻塞 finalizer。它拒绝后续复核，不撤回已通过最后复核的本地提交；真正政策撤销通过 Registry 门禁序列化。
- 查询仍同步访问 SQLite，可等待写锁；队列是全局 FIFO，尚无策略公平配额。排队期限约束开始派发，过期项在出队或 close 时清理。
- owner 队列不拥有交易事实；D63-04 最小 UNKNOWN 阻断、完整 TD/MD 生命周期、每日结算、回报账本、远端客户端和 BT 接线仍需继续。独立服务进程部署、真实 native、Windows 与 SimNow 未验收。

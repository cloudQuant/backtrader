# 第三十轮：成交日期补充与一致性审阅

日期：2026-11-09。结论：本轮限定实现和本地源码/隔离安装验证通过；整期仍 IN_PROGRESS / 未验收。五仓产品已提交本地 dev，未推送。

## 交付与行为

CTP 回调和查询保留原生 TradeDate，经 TRADE 专用 GatewayReturnFact v4、独立版本 GatewayExecutionObservation v2 传到执行流。缺失日期保持未知，非空非法日期拒绝；不使用 TradingDay、本机日期、Feed时钟或推断时区补值。旧事实v1/v2/v3和观察v1保持原字段与规范字节。

Gateway新日志为v9，旧v8在原账户guard、journal身份和revision约束下显式升级。新增同库日期记录始终关联原来计入数量的成交。后续同归属同经济事实补日期时，同事务追加TRADE_DATE_ENRICHED，applied=False并标记trade_metadata_only；原数量、持仓、累计量和原计量事实指针不变。重复日期不追加事件，不同已知日期保留冲突。重开和运行中读取均核对日期、原成交及事件关系。

SDK执行流传递该标记并保持原请求关联、权限、回复预算及显式ACK。BT只扩展已批准pending文件的一致性检查：补充必须有原成交，经济内容/归属/已知日期不能冲突，旧收据和未确认通知保持。它尚未把新事件应用到生产Order/Position/Trade，也不自动ACK。默认传输仍为bt_api_transport_zmq。

完整合同见[冻结稿§32](../分轮合同冻结稿-2026-11-08.md#32-r30成交自然日期与不重复计量的日期补充)。

## 审阅处理

- E071：metadata-only候选可缺少成交关联字段。现要求成交键、数量、价格、方向和场所键；普通不完整观察保持原行为，实际原成交/归属仍由journal和pending验证。
- E072：篡改reason并删除冲突记录可让候选重开时丢失日期冲突。现验证retained冲突背后的原冲突证据及标志。
- E073：运行中读取只依reason，可能把补充事件返回为普通成交。现分别验证原计量指针及补充旁表/原事件关系后再确定标记。

独立审阅者完成限定前后验证，但只保留于对话工具记录，没有单独原始日志文件。归档review-summary明确为整理摘要；最终产品回归日志和JUnit由主代理与安装验证另行保存。本地完整性检查不声称能认证任意重写的数据库或证明交易所事实。

## 实现与审阅

按[冻结合同 §20](../分轮合同冻结稿-2026-11-08.md#20-r17撤单错误尝试归属与-bt-取消宿主)分为 Base、CTP、Gateway、SDK、BT 五条实现线，另行审阅来源和事务关联、BT 宿主并发。主代理冻结合同、检查差异、独立执行源码回归和安装产物核验。

Base PreparedCancelRequest 新增可选不可变 source_binding，非空显式使用 v2，旧 v1 形状及摘要保留。I63-E019 修复为仅 CANCEL_ERROR 使用事实 v2，将 cancel_request_key 纳入摘要，区分同原单同错误码的不同取消尝试；只改变旧摘要排除的 source_ref 无效。公开事件增加有限 operation_id/attempt_id/prepared_digest，page 显式 v2，原始来源和取消强键不公开。

CTP 在准备和最终 native 入口核对同一密封登录来源，捕获登录请求号；正错误回报严格核对原生账户、目标、RequestID、OrderActionRef 和来源。OnRsp/OnErr 按各自 callback 参数校验。来源标签只说明 Python 接收边界，不证明 vendor 排队时间或真实字段回显。旧 v1 准备不补造来源，跨日目标无延续证明仍拒绝。

Gateway 原命令库显式升级 v7，取消错误关联、事实和策略事件在同一事务提交，并在提交前复核来源；重复幂等、冲突拒绝。原订单、取消发送状态及净数量不因错误观察改变。I63-E021 在运行中读取时交叉核对 attempt 的原订单和策略，不能只依赖下次重开审计；事实交易日/代际也须匹配准备记录。

SDK 复用当前 offered ticket、原取消 journal、原订单强身份投影，接通错误和认证策略流。真实 CURVE/Registry/SQLite 回环覆盖同原单两次错误、双 callback 去重、非零净量不变、策略隔离、ACK 重启、预算和损坏关联不推进进度；provider 错误和来源验证仍是合成输入。成功 action 响应、insert 错误和完整恢复未在本轮关闭。

BT 既有 pending.json 显式 v2→v3 升级，四个取消宿主方法使用原文件锁和原子替换保存首写计划、单调观察及耐久 winner。重开验证原意图、路由和身份；未决取消阻止顺序 new_instance。v1 direct 导入隔离保留，测试子进程改用当前解释器。GatewayPendingHost 尚无生产 Broker/Store 调用，不能称 BT Gateway 模式已可用。

I63-E020 保持 OPEN：new_instance 检查/目录归档与独立 pending/waiting writer 存在并发窗口，state 内锁不能跨 rename 解决。稳定协调锁涉及更广 BT 入口，见[待确认申请](../Backtrader-状态归档并发调整申请-2026-11-09.md)，未擅自扩大此前批准范围。同目录 CAS 和顺序拒绝不关闭该缺口。

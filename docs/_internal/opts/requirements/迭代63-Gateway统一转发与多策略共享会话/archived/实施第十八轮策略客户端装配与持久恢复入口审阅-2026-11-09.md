## 实现与审阅

按照[冻结合同 §21](../分轮合同冻结稿-2026-11-08.md#21-r18策略客户端装配与持久取消枚举)，分别委派客户端装配、BT 枚举、跨进程集成及安装验证；另行只读盘点和审阅。主代理决定合同，独立查看差异、执行扩大源码回归并核验产物。

GatewayStrategyClientSession 接收严格解析的 ClientConfig、可信 binding/route/peer、外部 CURVE keys、原 durable host 和显式 requested_operations，组合原 ThreadedServiceClientRuntime、GatewayDirectClient 和 GatewayExecutionStreamClient。只允许精确一个 required direct-write binding 和对应 ZMQ profile；配置与主体/账户/策略/run/服务不一致在启动前拒绝。构造无线程和网络，原 runtime/transport 在独立 owner 线程创建；不创建 provider 或本地 Gateway 服务。

原命令和事件权限不自动扩大，取消状态可独立读取，新取消须显式配状态操作及实际取消宿主。配置及外部安全容器复制后冻结；只预检 CURVE bytes/40 字节形状，Z85 内容与密钥对仍由原 transport 启动时校验，形状合法不等于密钥有效。启动或关闭超时、清理失败保留同一 handle，关闭重试沿原 runtime，不替换实例或自动重发。

I63-E024 审阅修复：session.route/binding 返回脱离的 DTO，owner identity 与客户端预期 identity 分离；异常底层 identity 变化触发原 route_ready 拒绝。公开原 runtime 是受信低层 API，不将 frozen Python 对象当作抵御任意私有内存修改的安全边界。用户正常输入容器和公开标签的脱离已验证。

GatewayPendingHost.list_cancel_plans 在原锁内读取并完整校验：v2 返回空，v3 按 operation_id 排序返回独立不可变值，损坏/超容量/错身份拒绝；不升级、写入、过滤或派发。复用既有 schema 和锁，E020 跨目录归档并发协议仍待批准，没有以枚举测试关闭该缺口。

真实联调使用公开临时 YAML、spawn 的独立 Gateway 进程、真实 CURVE/Registry/SQLite 和 BT GatewayPendingHost v3，provider 为合成实现。覆盖 reserve/dispatch/status、两次取消、同 ID 幂等、一次回复丢失后原 ID 恢复、跨策略读取拒绝、关闭重开宿主及新 run 只读恢复；最终仅两次模拟取消。2 秒服务租约下，调用者 3.2 秒不轮询，观察到独立续期且 registration 不变。每个客户端线程及 Gateway 子进程的关闭均明确检查。事件投影仅测试内存列表，再由测试显式 ACK；不证明 BT Order/Position、持久投影或 cursor 原子性，也不将该短租约向量冒充计划中的全部长阻塞验收。

## 3. 本轮发现与处理

1. **E097 根因已查明**。回报查询超时默认 0.5 s。当日账户有委托后，SimNow 的 ReqQryOrder 超过 0.5 s，结果为 `timed_out`，读取器判为 `QUERY_UNTRUSTED`。回报因此一直不健康，所有预约 `ADMISSION_DENIED`。
   - 定位方式：
     - SDK `dedaed87`、`b6bc99fd`：在日志中写出查询失败的原因链；
     - 在 QA venv 的已安装副本中临时插桩，已还原。
   - 修复：SDK `4f35d66e`，资源包 `returns` 可选 `query_timeout_seconds`（0.05–5 s，产品默认仍为 0.5 s）；QA 设为 3 s。
   - 另：SDK `a6dc915a` 也记录回调批次失败。
2. **新缺陷（已修复）**。被拒预约的订单出现在后续投影的 originals 中，但该订单没有 Gateway 记录，策略从此无法重启（`GATEWAY_NOTIFICATION_RESTORE_INVALID`）。BT `f78beddcc` 修复，并附复现测试。
3. **E103（新，OPEN，待确认）**：派发 QUEUED 后，owner 未发送，预约在到期后 EXPIRED（BT 收尾为 Canceled），Gateway 侧无日志。推测：回报查询（最长 3 s）占用 owner 线程，排队派发的 claim 超出 50 ms 候选窗口或报价已非最新。查询间隔 5 s 时复现，30 s 时少见。
4. **E104（新，OPEN）**：执行事件（Accepted、Canceled）到达策略的延迟约等于查询周期（19–60 s），疑似要待查询确认才发布，而不是由 CTP 回调即时发布。
5. **E105（新，OPEN，待确认）**：撤单完成后，后续预约持续 `ADMISSION_DENIED`，直到 Gateway 重启（09:01 与 09:43 两次）。推测回调摄取失败使回报维护一直不健康；已加日志，待复现。查询或维护进行期间也可能短暂拒绝预约。
6. **环境限制**：
   - SimNow 标准环境的 tick 交易所时间落后本机 1–3.5 s（中位约 2 s，10:00 前后实测）。
   - 策略侧新鲜度阈值可配置；QA 设为 5 s，产品默认 2 s。
   - Gateway 市场门（决策 B）的 `max_latency_seconds` 硬上限为 2 s，因此大部分派发被拒（`MARKET_GATE_UNAVAILABLE`），成交往返与多策略并发本时段无法完成。09:00–09:15 延迟较小时派发成功。
   - 是否为 SimNow 放宽此上限属产品安全决策，须用户决定。
7. QA 工具调整：

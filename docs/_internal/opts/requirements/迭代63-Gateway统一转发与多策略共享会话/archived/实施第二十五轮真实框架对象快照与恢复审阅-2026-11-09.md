## 交付及职责

新增 Broker 私有 `_btapi_gateway_projection.py`，按[冻结合同 §27](../分轮合同冻结稿-2026-11-08.md#27-r25真实框架对象快照与恢复)捕获真实 Order、Position、Trade、执行片段和历史记录；复用现有框架构造与算法。快照保留原单与通知副本、OCO/parent、嵌套 info、历史订单指针及共享对象关系，恢复时由受信 Feed、owner、broker 和佣金模型重新绑定。运行时引用由正常计数器分配并提供旧→新映射，不重置全局计数器；跨独立进程不要求引用数值永不相同。

支持 15 个现有标量型内置佣金类，严格核对实际 broker lookup、规范化参数、有效缓存和跨 Feed 共享关系，不重新构造佣金对象或二次缩放百分比。原 broker=None、fee_correction_ids、时区/fold 和未消费执行窗口均保留。快照不加载 provider、不访问账户、不自动安装到 Strategy 或发送 ACK。

生产调用链仍需完成。既有 pending/Broker/Store 授权继续有效；新 [Strategy 私有通知钩子](../Backtrader-Gateway通知持久化钩子调整申请-2026-11-09.md)和原 [E020 状态归档锁调整](../Backtrader-状态归档并发调整申请-2026-11-09.md)均待用户确认，未实施。需要确认源于用户要求 BT 架构调整事先批准；SDK/Gateway/ZMQ 已授权范围不受这两项等待阻止。

## 审阅和修正

沿用 bmad-code-review 审阅流程，由独立缺陷、边界和验证缺口审阅提供反馈，主代理负责合同裁决、最终代码核对与接受。依用户持续开发授权修复候选问题，不设发现数量，也不把局部审阅通过改成整期完成。初版差异与合同叙述、逐项裁决见[审阅记录](../evidence/round25-20261109/review-findings.json)及同目录 review-initial。

- E050：初版只记录“存在佣金对象”，会允许恢复后的模型改变后续经济计算；已补受信对象、参数、有效缓存和共享组核对。
- E051：初版误拒绝 Broker 的顶层浅拷贝 info、内部别名、OCO/tuple 和费用通知字段，并把原 broker=None 改为绑定状态；现按实际引用图保存和恢复。
- 同 ref Trade 不能出现互相矛盾的已知 long 方向；初始副本的 None 可保留。独立 deque 和历史列表按输入真实别名关系保存，不能仅因同 ref 强制合并。
- 共享 info 节点缓存可能绕过较深根的逻辑深度限制；现对每次引用计入子树高度，保留合法浅层共享。
- T008：首轮两个容量测试使用未知字段，即使没有边界检查也会拒绝。主审发现后仅加强测试：其余 schema 合法的超限输入在真实 guard 下拒绝，只移除该 guard 时可恢复。旧结果保留，最终结果使用加强版。

这些是本轮候选问题，不表述为已发生的账户事故。静态盘点的 E048 通知钩子及 E049 当前联合服务 metadata/成交日期/实际费用缺口仍 OPEN。

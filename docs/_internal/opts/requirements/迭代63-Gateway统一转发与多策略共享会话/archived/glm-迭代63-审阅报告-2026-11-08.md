### GL63-01(对抗)[既有 RV63-01,仍开放,两轮同步未处理] Gateway 宕机或无法启动时没有应急撤单通道

- **定位**:§6.1:778("单点故障……缓解:fail-closed(D63-03);运营撤单工具;监控告警;不回退直连");§3.12"Gateway 宕机且有活动委托"行;§6.2 第 3 项。全文检索"仅撤单/撤单模式/应急/cancel-only"零命中;§5 无交付步骤;§6.3 无验收行;§0/§4.1 无对应候选。
- **问题**:Gateway 是账户唯一 TD owner。它宕机、起不来(日志损坏按 §3.12 拒绝启动)或登录失败时,所有策略都无法撤单。CTP 没有交易所层的断线撤单(FIA/CME 列为交易所层最佳实践,11-07 报告 RV63-01 依据)。11-07 报告已给出方案对比(a 独立运营 CLI / b Gateway"仅撤单模式"启动 / c 纯运维规程),推荐 b+c;用户至今未被问及此项(复核清单 §7 的处置表不含它,§8 的确认队列也没有它)。
- **建议**:把"Gateway 无法启动/宕机时的撤单途径"登记为候选决定并排入下一批确认(见 QGL63-01);63.01 冻结稿把 RV63-01 的所选方案落成交付条目(新增 63.12 项或 63.14 页面外的 CLI),§6.3 增验收行("停 Gateway 后经仅撤单模式撤单")。至少应在 §6.2 未决问题表登记"活动委托在会话断开后是否仍保留在场所(现有第 3 项)"之外补"无法撤单的处置"。
- **影响**:真实账户一旦 Gateway 故障,活动委托在场所持续暴露,只能靠期货公司紧急处置(需事先确认是否有该服务)。

## 范围与实现

本轮沿用默认 bt_api_transport_zmq，在独立 Gateway 进程中把原 CtpGatewaySession 的交易、账户读取和惰性共享行情接到同一服务。原 native owner 保持唯一 TD 和共享 MD 的生命周期；Host 线程的 Hub 通过有界 service queue 借用 provider。策略仍通过 SDK 连接，不在策略内创建第二账户会话。

改动范围为 SDK owner/行情桥/CTP profile/operator、Gateway Hub 的确认清理入口，以及 CTP 的轻量 key 合同与缓存交付检查；Backtrader 本轮仅改文档。BT 完整接线、经济账本、控制/代理、Web、恢复及实际账户验收仍按主计划推进。

## 不可扩大解释的边界

行情来源许可是在 native owner 核对时产生的观察。T0 核对后 T1 断线、T2 才到达消费者的窗口无法由该检查原子撤回；旧观察保留自己的时间、source 和 epoch，不得改标新源或称为接收瞬间 live 真值。已确认 reset 后必须清旧缓存，消费者原有来源与 freshness 校验仍在。

验证脚本限制常见 socket/DNS/ZMQ 到回环/本地 IPC，并替换两个 CTP native factory；它不是进程沙箱，也不保证拦截任意 ctypes/native 调用。源码和安装均按各自唯一 run-id 关联日志：Gateway 14 个已记录进程中 8 个缺退出审计；CTP 1/0；SDK 83/3。已记录组的 guard 存在且无 VIOLATION，缺失退出证据仍为 GAP。SDK Monitor 的 `-I` 子进程不注入 guard；新增 CTP 纯合同 `-I` 子进程只有测试自身的指定 native/feed 导入拒绝，不是完整 guard，另列说明。

Monitor 22 文件和 ZMQ 7 文件仍为单独核验的 editable 依赖；安装使用 --no-deps，不是完整 resolver 验收。未做真实账户、跨平台、Windows PowerShell 5.1、性能或发布验收。中文文档仅核对 UTF-8 BOM、严格解码、替换字符与本地链接。

日期：2026-11-08。结论：本轮源码切片完成本地复核，整期 **IN_PROGRESS / 未验收**。SDK/Gateway/CTP 按既有授权修改；本轮无 BT 产品或 ZMQ 产品改动，默认传输仍是 bt_api_transport_zmq。

## 范围与职责

Gateway 提取原 account worker 的观测、覆盖、时钟和快照校验，单 owner 写入 GatewayAccountReadModel，网络线程仅读不可变缓存和原 journal。原 worker 复用模型并保持自身 provider/guard 生命周期。重开日志只作诊断；新代要求新 observation ID；同代重复成功观察不续鲜。

SDK trading_owner 支持显式 direct_write/account_read 双端口。读取仅开放 snapshot、snapshot.typed、head、read_after、ack、progress，不开放 execution stream 或未装配原生能力；静态 Registry 和 Gateway ACL 都保留。公开账户和内部 journal 必须与 direct 账户一致。CTP profile 用原 owner/单 TD 读账户，不新建会话；先失效再查询、普通失败保留命令状态 RPC、硬会话身份变化停止 owner，关闭先失效模型再确认 native 停止、最后释放 guard。

CTP provider 统一三类原生查询的完整字段合同，精确比较 intent/readback/额外过滤/行上限，逐行检查账户归属。当前 typed 结构默认值的构造证据见 [native-defaults](../evidence/round09-20261108/worker-native-defaults.log)，没有创建原生会话。默认 NUL 业务类型、空币种不证明所有场所业务和币种覆盖。

# 迭代 63 第七轮：单一 CTP 会话与交易服务装配审阅

日期：2026-11-08。范围：CTP provider/session 和 SDK trading_owner/profile；Gateway 与默认 bt_api_transport_zmq 的产品代码本轮未修改。基线为 CTP ce8a6cc5、SDK da63b6ff。整期保持 IN_PROGRESS / 未验收；本轮具体源码与安装结果见下述证据，不将本地检查提升为账户验收。

## 交付与边界

CtpGatewaySession 复用账户 reader 持有唯一 TD，direct 借用同一精确 feed/Trader，关闭隐式连接和后台结算线程；一个惰性 MD provider 服务多个 symbol。工厂在独立 owner 线程按 guard、锚定既有 journal、session、dispatcher/controller 顺序创建；网络 Host 另在线程运行。规范账户 scope 使用 AccountKey.account_key_id，默认写准入关闭；派发同时验证当前结算票据和调用者字面 True 准入。session 全部确认停止后才释放 guard，未确认关闭保持可重试资源。

SDK trading_owner 已接命令服务；共享账户读取与行情网络端口、完整策略账本/最小 UNKNOWN 和自动恢复仍未实现。受信 factory 与业务 callback 是组合依赖，不能用恒 True 的测试 callback 代表生产准入。profile 支持范围是当前明确的 SimNow，真实账户与跨平台另需验收。

## 审阅发现与处理

| 发现 | 处理及证据边界 |
| --- | --- |
| operator 角色错配时可能遗漏已启动的候选部署 | 先保存候选责任；仅尚未绑定资源的新 Host 可直接拒绝，已启动候选进入原线程清理并保留失败重试 |
| Host 健康读取异常可能留下 ready=True | trading_owner 读取实际 healthy，异常或非 bool 结果降为不就绪；RPC 就绪不等于可交易 |
| ComponentResources 再包装会引入第二套 once 状态 | 直接透传原资源；工厂将 owner.close 非 True 转有限异常。通用裸 False 回调边界记 I63-L001 |
| 市场 handle 公开 stream/queue/owner token 可绕过 owner 方法 | 公共 handle 改为不可变 key/generation 与不透明对象身份；资源和源状态只在 provider 内部，复制/伪造对象拒绝 |
| 退订后保留 handle 导致旧 stream 继续被弱映射 value 强持有 | 替换为不持资源的失活标记，保留退订幂等；GC 回归及独立内存探针确认旧流可回收 |
| config_front_pair 被误判为 managed，SDK direct 已 armed 却被要求 disarmed | I63-C001 定位到 Feed 分流；保留账户/front/profile 检查，使用一致的现有 SDK admission 与最终 native gate；未引入旧 runtime 作为 direct 前置 |
| 新分流可能混入 managed 订单/动作身份 | Feed 和 Trader 最终入口均显式拒绝 SDK direct 的非 None managed 身份（包括空字符串）；下单/撤单、部分/完整元组与直接 Trader 入口负例覆盖。direct 不冒充 managed 的逐字段业务审批 |
| MD 包装线程尚未退出时，第二次 close 仍可 False | 原始扩大回归失败保留；加入可控阻塞 wrapper，用 typed stop、对象保管及有界退出后重试验证正确合同。原失败缺少内部状态，不能断言唯一原因 |
| TD 维护失败会停止 owner 而不自动恢复 | I63-C002 保持 GAP；不得仅凭新结算票据释放订单 UNKNOWN 或恢复门禁 |

缓存 direct provider 的代际边界另作复核：实际工厂的 dispatch 与提交前再次 gate 均验证当前 provider 结算票据、账户/日/原生代际，再核调用方准入；未发现仅缓存 direct 引用即可在该工厂绕过这些门的证据。reader.refresh_session 继续只负责账户查询 scope，旧结果不重标代际。任意 Python 私有反射不属于隔离承诺。

# 实施第五轮客户端与结算回读审阅

日期：2026-11-08。范围：Base 共享命令观察、Gateway 规范载荷和原生身份校验、SDK 策略客户端及独立进程联调、CTP 结算只读回读。结论：本轮限定切片完成源码复核和离线回归；整期仍为 **IN_PROGRESS / 未验收**。未修改 Backtrader 产品架构，未运行真实账户调用。

## 发现与处理

| 发现 | 最终处理 | 证据边界 |
| --- | --- | --- |
| 客户端无法精确核对回复的持久归属；首次回复可被误作 journal 信任来源 | Base 提供严格 schema_version=1 和绑定 DTO；服务字段取自持久行；客户端与可信配置中的 journal/account/strategy/principal 全等核对 | DTO 不证明账户或服务来源；仍依赖已认证 Registry 和正确配置 |
| 原生身份可在发送后才因过长或不可编码而无法回读 | Gateway 派发提交前和服务回执使用同一个 Base 身份校验 | 不可回读身份零 marker、零合成发送；强键摘要不是可查单原生键 |
| 两端自行编码载荷可能造成原键摘要漂移 | Base 共用规范编码；保持旧 ASCII JSON、边界及摘要；Gateway 继续做秘密字段检查 | 规范编码本身不脱敏；旧新编码合成差分仅是抽样 |
| reserve、dispatch、release 前没有可复用的策略侧持久端口 | 新 SDK GatewayDirectClient 注入宿主；依次持久意图、派发标记、稳定 release 计划，并检查回读 | 测试 SQLite host 不等于 BT 生产接线或 fsync 证明 |
| 丢回复后的重复 dispatch 可能读到更高版本，旧检查会错误拒绝 | 接受合法单调状态推进；相同版本仅允许动态观察字段及 EXPIRED 首次 release pair | 重试仍用原键，服务不再次派发；没有自动重试 |
| release 回执原先未与本次持久 operation/version 精确匹配 | 成功回复必须为 RELEASED/EXPIRED 且操作对匹配 | 不把当前 RPC 拒绝解释为原订单 Rejected 或 NOT_SENT |
| fork 后继承的客户端锁可能死锁；客户端导入连带加载服务器装配 | 所有公开方法在取锁前校 PID；订单 decoder 迁至中立 SDK 模块，不保留旧名称别名 | 既有 SDK 包初始化仍加载部分凭据类型定义；未读取凭据、未创建原生会话 |
| CTP 错误账户的完整查询被误分类为 UNCONFIRMED | 验证真实 Trader、来源封印、账户过滤、完整终包、记录摘要及查询前后会话；不可信结果 UNKNOWN | 真实 TraderClient 配合合成 native；只读向量不发送确认 |
| 结算旧代失败可能清理新代证明 | 清理前核对原 generation/account/day/API/SPI；确认后的回读接入严格路径 | 不关闭 SDK 读取后再取 day/generation 的竞态 I63-S002 |

## 主代理独立验证

Python 均使用 Anaconda base；完整命令和逐项结果见 [R05 证据](../evidence/round05-20261108/commands.json)及[分轮记录](../实施基线与分轮记录-2026-11-08.md)。

- Base/Gateway：**228 passed / 2.65s**。
- SDK：**433 passed、1 failed / 19.43s**。唯一失败仍为 I63-D003，旧 Monitor roleless/control-only 配置返回 PORT_ROLE_MISMATCH；R02 已用修改前源码复现，本轮未改其规则或断言。
- CTP：**339 passed / 26.06s**，覆盖结算回读、查询来源和终包、查询槽、direct provider、重连与 flow/MD 生命周期。
- 主代理检查共享编码与 DTO、客户端持久化次序和版本/路由绑定、服务生产者及 CTP 回读差异；四仓 diff --check 通过。独立审阅为静态复核，不算额外运行次数。
- worker 的受控 SDK/Base/Gateway 文件 Ruff 通过；CTP 仅针对 E9/F 检查通过，未清理既有类型风格告警。

真实 multiprocessing spawn 用例运行一个 Gateway 子进程和两个策略客户端子进程，采用独立 CURVE 主体、同账户同合约同请求键。验证策略隔离、回复丢失后原键重试、策略进程重启读取原 SQLite host、STOP_NEW 的作用域，合成 provider 每个策略只发送一次。它不是两个真实 BT 策略或三个策略的部署验收。

## 结算语义与后续门槛

本地 CTP 6.7.7 头文件的 SettlementInfoConfirmField 只有 ConfirmDate（“确认日期”），没有 TradingDay；同时带这两个字段的冲突测试是合成输入。ConfirmDate 与交易日，尤其夜盘的关系，以及查询空结果的完整覆盖语义，尚无真实场所证据。当前保留原实现的本地政策：可信完整空结果或全部严格合法旧日期为 UNCONFIRMED；错误账户/来源、混杂/冲突日期、未来日期和会话变化为 UNKNOWN。保留政策不是本轮新证实的场所事实，登记 I63-S003。

provider 每次 settlement_status 现在执行新鲜只读查询，不再单凭缓存 trading_ready 返回；查询槽占用和延迟应纳入完整 owner 调度。SDK 的状态读取与随后采样日/会话仍未原子绑定（I63-S002）；Gateway 每日自动确认的耐久 attempt、重启、日切和未知恢复仍待实现，不因本轮 provider 修复而称已完成。

BT pending 的逻辑预留接线、生产宿主持久性、完整单 TD/MD、账本/回报事务、最小 UNKNOWN 门禁、租约 DRAIN、代理、示例、页面、全量回归与账户验收继续按计划交付。Gateway 默认 bt_api_transport_zmq 和独立进程不变；本轮未修改 ZMQ 产品代码。

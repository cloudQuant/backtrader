# 迭代 63 第十三轮：回报维护与消费游标审阅

日期：2026-11-08。整期状态：**IN_PROGRESS / 未验收**。本轮推进单 owner 的回报持久链路和同库消费进度，没有执行真实账户调用。

## 范围与结果

四条实现线分别负责有界回报缓冲、CTP 启动前来源接线、SDK owner 查询与回调入账、Gateway 消费游标；两条独立只读审阅分别检查来源/接线及存储/迁移。实现按文件划分所有权，主代理负责[合同 §16](../分轮合同冻结稿-2026-11-08.md#16-r13回报接收owner-入账与策略消费进度)、集成决策、diff 审阅与独立验证。中途会话中断后先核对旧代理句柄已消失及三个产品工作树无改动，再重新分配，没有重复执行或覆盖并行实现。

CTP 在原 Trader 启动前安装 provider 所有的缓冲，保留原生订单/成交及错误回调。拍字段前后检查 API/SPI 和登录范围，支持位置、关键字及混合回调参数；来源缺口和容量溢出不覆盖已有行。缓冲是内存队列，按逻辑载荷字节和条数限制，单次 offer 最多 256 项；未 ACK 重取同一前缀，记录身份查询不反复扫描整批。ACK 只移除成功处理的前缀，不清 gap，也不提供崩溃耐久保证。

SDK 在既有交易 owner、guard 和命令库内组合查询 reader、执行账本和回调消费。配置显式 CTP 合约目录与查询预算，write_enabled 的 profile 必须提供 return_settings。整批先投影，逐条提交，全部成功才 ACK；已提交前缀的失败重放由同库去重处理。先成交、后委托学习场所键，再关联入账的路径纳入合成原生测试。查询失败撤销完整对查询状态，按间隔补查，不重发订单。

账户读取与回报查询在同一维护循环公平轮换，每 tick 最多执行这两类读取中的一个阶段；既有结算控制器仍可另行查询。预留 fence 初始关闭，维护异常及清理开始时先关闭；派发重新校验当前完整来源和缓冲状态，并保留结算与调用方准入要求。缓存准入及顺序查询不构成原子场所截面，也不自动建立 external 基线、资金/可平能力或解除 UNKNOWN。

当前来源携带的合法历史 TradingDay 按原生日入账，接收日不覆盖它；未来日拒绝。相同原生号跨日各入账一次。reader 绑定完整 FrontID/SessionID、交易日及原生来源；仅同 Trader/API/SPI 的受检登录更新可在 provider 同锁内重绑，新 reader 经校验后，账户读模型先失效、创建新读 epoch 并重新查询。原服务 guard generation 保留。

Gateway 命令库显式升级至 v5，策略消费者进度与事件同库保存；v4 不自动升级，v2/v3/v4 显式升级验证旧结构与数据后原子迁移。消费者按账户/主体/消费者/策略隔离，最多 8192 条，重开扫描同样有界。策略序号允许全账户序列中的间隔；只能恢复或 ACK 已 offer 的本策略序号。完整响应预算检查改为必传，超限缩页或拒绝且不推进；空页不建立消费者，无需 ACK。消费进度不增加命令/事实 revision，也不删除历史。

## 发现与处理

| 发现 | 处理与证据边界 |
| --- | --- |
| I63-E007：可遗漏回复预算 | 必须显式传 result_fits；覆盖完整页面加外层包装超限、缩页、首条拒绝及已有进度不变。是新本地接口的合同修正，尚无该网络 RPC。 |
| I63-E008：错误被静默忽略、关键字参数误报 gap | OnErr 的 None/零码保留来源缺口；六类回调按签名规范化，非法调用不吞原 TypeError。 |
| I63-E009：相同 generation 下登录身份变化未拒绝 | 保存并复核完整登录范围；同代 FrontID/SessionID 改变及 getter 重入被拒绝。 |
| I63-E010：旧检查与新 reader 构造之间可换原生对象 | provider 原子重绑工厂在同锁内前后检查精确旧 API/SPI 和新 scope；确定性中途替换测试拒绝。 |
| 维护失败的缓存准入 | 外层异常和 cleanup 首先关闭 fence；保留资源/关闭失败不留下开放的预留准入。 |
| 测试收集顺序 | 主代理扩大集首次 726 passed / 26 errors，新来源测试通过 pytest_plugins 引用已收集模块而未取得 fixture。改为显式 fixture 导入，断言不变，原日志保留。 |

独立审阅在最终限定差异内复核上述来源和迁移问题，未发现仍需修改的实质问题。结论是静态复核，测试接受由主代理独立运行提供；不代替真实交易所或账户验证。

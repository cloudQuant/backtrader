# 迭代 63 第十轮：活动委托与持久观察身份审阅

状态：**本地源码与隔离安装切片验证通过；整期 IN_PROGRESS，未验收**。本轮无 BT 产品变更。默认传输仍是独立 bt_api_transport_zmq；不创建第二个 TD 或策略调度器。

## 范围与结论

CTP 账户读取复用现有订单投影器和 SDK 持久 issuer，将支持的非空活动委托投影为 opaque 观察身份。同一原生规范身份与同一 issuer 重开后 ID 一致；front/local 到 system 的身份输入变化不在合并保证内。观察 ID 不提供策略归属、原生撤单键或 UNKNOWN 解阻证明。

账户 snapshot 配置与实际 execution 队列分开：前者不创建事件队列，保留同 Trader 的来源刷新；后者继续拒绝会话刷新，避免旧队列事实跨代。完整查询来源、账户归属和交易日检查保留；终态过滤前验证数量一致性，无法表达的条件单、未知合约和非法行拒绝整个快照。

SDK profile 要求预先创建身份库并保存非秘密 issuer_id，仅严格 open_existing；缺库、空库、坏 schema 或错 ID 在 native 创建前拒绝。三个数据库拒绝路径/符号链接/硬链接别名，不宣称跨库原子性。清理顺序为读模型、确认会话关闭、issuer、guard；任意 close 失败禁止业务且保留精确连接，初始化失败以 typed close 端口交接责任，并在事务锁内拒绝与失败关闭并发的写入。

账户持仓的成本基准仍未证明，average_price/currency 保持未知。Gateway 策略仓位由自己的归属账本建立，不能借账户全览代替。实现合同见[§13](../分轮合同冻结稿-2026-11-08.md#13-r10-账户活动委托投影与持久观察身份)。

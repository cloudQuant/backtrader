## 实现与审阅结论

新增 GatewayPendingHost，显式将 pending v1 无损升级为 v2；意图、远端观察、提交标记、release 计划和原生身份在同一文件锁内原子替换。普通初始化仍创建 v1。固定 binding、容量和首份意图不得覆盖，Gateway 去重记录不受旧 history 500 项裁剪。无 marker 的未决意图也会阻止 new_instance；不可变 load_context 提供本地序号、BT ref 和 marker 的恢复关联。

SDK 共享意图/释放编解码和观察进展校验，限制 payload 大小、摘要类型及静态身份类型。强身份纯投影复用既有 coordinator 的相关性算法，不创建 provider；BT 用旧标记的两种合法 scope 候选摘要与远端实际摘要比较，不猜测场所规则。

| 发现 | 处理及检查 |
| --- | --- |
| stale RESERVED 在另一宿主已推进远端记录后仍可取得 marker | 锁内校验同 RESERVED/同版本；既有 marker 必须 active PREPARED；终态、UNKNOWN、已派发标记不能重新准入；并发/重试用例检查零写入与零派发 |
| 完整 native 映射不同但 SDK 强身份相同，或旧身份仅后补于 facts | 共用 SDK 强键投影、类型严格合并 facts；正向补写、反向旧 commit/attach 与重新加载统一验证；不同日 scoped、非日域和额外字段分别覆盖 |
| 原生身份补写与既有 facts 冲突，或 bool/int 相等掩盖字段变更 | v2 每次读/写均检查；SDK 稳定观察按规范 JSON 比较类型；冲突不落盘 |
| 强键补强曾拒绝合法 v1 的无关浮点字段 | 空 Gateway 或不同 route 不进行不必要投影；仅约束参与身份键的字段，保留其他合法旧数据，验证 502 项历史原样升级 |
| Registry 已释放旧 run 后，新 runtime 自动采用旧 durable run，客户端却拒绝恢复 | 仅 status/release 允许精确原意图的已授权 binding；当前 runtime 身份/run 仍匹配，第三 run 与多重匹配拒绝；reserve/dispatch 不借此放行 |
| markerless 意图缺少公开本地关联读取 | 增加冻结的 GatewayPendingContext 与 load_context，重开可读，不补造框架订单 |

两名独立审阅者分别核对持久层和 SDK 合同；主代理检查最终 diff、修复边界并运行以下源码回归。独立审阅的静态结论与执行测试分开记录，不以测试数量替代合同覆盖。

## 实现与审阅

按[冻结合同 §19](../分轮合同冻结稿-2026-11-08.md#19-r16远端取消的独立授权持久请求和客户端恢复)拆分 Registry、Base/客户端、journal/服务、配置/profile、CTP 只读来源检查和真实网络集成六条有界实现线。两条独立只读审阅关注授权与持久次序、宿主并发；主代理决定合同、检查差异和独立运行源码回归。

新增 direct.cancel 与 direct.cancel_status，默认不扩大旧客户端注册。服务从原命令库取目标身份和 symbol，只接受认证主体自己的策略原单；wire 不提供原生字段或代替主体。取消 token 固定确切 operation、完整参数与原 Registry 上下文，不借用 PLACE 许可。STOP_NEW 允许已获权取消，租约、run claim、当前资源权限及 MIG03 写门禁继续生效。

creation_scope 仅发行线程一次，不占用 owner 线程绑定；获得 SQLite 写锁后在提交前重新检查授权，创建尝试持久后才交现有取消队列。后续 scope 绑定原 owner 线程。取消同 ID 重试只复用原尝试，非 REQUESTED 仅观察；响应预算不足保留已持久但未入队的 REQUESTED，不能误称零写入或原订单已取消。原始 native 错误不会出现在公开取消记录中。

许可 close 的语义与原 ServiceDispatchAdmission 一致：最后 recheck 为本次本地提交的准入点，之后发生 close 不撤回已获准提交；owner 后续 scope 必须拒绝该关闭许可。真实 SQLite 测试分别验证等锁期间 lease 过期零记录，以及最后 recheck 后 close 可留下 REQUESTED 但不再进入派发。这不是跨数据库或物理 fsync 的原子撤回保证。

GatewayDirectClient 显式接受 cancel_host，先保存并回读稳定 operation_id 计划，再调用取消 RPC；新 run 只按显式权限读取旧尝试，不自动重发。E017 修正要求宿主原子首写计划、原子单调合并观察并返回耐久 winner，SDK 校验返回值和回读。单实例 RLock 不替代跨客户端/进程的持久 CAS；公开纯进度校验函数供未来 BT 宿主在事务内复用。SDK 不能证明任意不遵守接口合同的宿主实现安全。

cancel_enabled 默认 false，要求 dispatch_enabled 和精确绑定的取消 dispatcher；配置 parser、operator 白名单、组件能力和 runtime 显式操作集合同时接通。CTP profile 在原 provider/coordinator/journal/guard/owner 上装配取消，保留 write_enabled 必须配置回报设施的启动约束。取消 gate 与 PLACE 的结算/回报完整性/业务准入分开，但仍要求当前来源、固定账户绑定、CANCEL 写准入及关闭检查。

E018 修正新增 provider.assert_cancel_ready(expected_account_binding=...)。它在原 provider→Trader 锁序中只核对现有登录，不通过可能隐式连接的 GatewaySession getter；不会发起连接、查询或准入。启动期固定账户绑定只用于一致性核对，最终 prepared/native 和 SDK CANCEL grant 仍承担各自验证。

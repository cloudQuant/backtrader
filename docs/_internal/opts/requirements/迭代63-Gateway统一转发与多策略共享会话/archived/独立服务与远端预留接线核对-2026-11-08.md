# 迭代63：独立服务与远端预留接线核对

日期：2026-11-08。源码依据：BT e1ebe5854、SDK 496011f5、CTP5e22b2e、Gatewaye36c663；后续本轮仅默认传输依赖及文档变更。以下为独立只读源码盘点，不是完整会话或远端交易验收。

## 1. 默认传输

用户确认D63-50：默认使用已有bt_api_transport_zmq，未来其他中间件另建独立包；允许Gateway和该传输包必要破坏式重构。SDK ServiceHost和ZmqTransportFactory已经引用该包，现有通信profile明确backend=zmq。SDK gateway extra已加入该包，不在Gateway复制另一套ZMQ实现。主代理13项源码CURVE回环通过，安装包元数据/隔离导入另见分轮记录；不能据此声称完整独立交易服务可用。

## 2. 单账户会话的组合约束

- 现有GatewaySessionOwner本身只通过受信factory取得provider，不必然另开TD；但CTP只读account provider要求尚未连接且无现成Trader的feed。已连接的BtApi feed不能直接被其接管；ctp_account_process自身会构造feed，不能自动复用其他实例。
- CtpTradeStream指定同一request_feed才复用其Trader；不指定会自建。CtpQuoteV2MarketProvider可让多个key共用一个CtpMarketStream；另走BtApi逐订阅建流的路径可能多开MD。离线分别已有fixture，但尚未完成统一组合验证。
- GatewayAccountSessionWorker和GatewayDirectDispatcher分别调用guard.bind_consumer绑定自身；同一个guard不能同时绑定这两个对象，另建guard又会竞争同账户锁。下一步须一个统一账户owner拥有guard、唯一会话与关闭责任，并组合受控读/写端口，不能直接并排拼装既有worker。
- GatewayOperatorDeployment目前一次装配account_session_worker或market_hub，尚不装配trading_owner；storage RPC尚无dispatch/cancel。单独存在这些类不是可启动完整服务的证据。
- 每日自动结算需Gateway按账户/日耐久调度SDK ensure_settlement_confirmed；原生auto_settlement_confirm继续false。UNKNOWN先回读；关闭时先停止新写与消费者，确认MD/TD退出后才释放guard，未知关闭不冒称成功。

## 3. 远端预留与BT恢复

- Base DirectOrderReservation强制原生identity，SDK native place立即使用其交易日/代际。应新增独立逻辑预留合同，不伪造NativeOrderIdentity，不跨进程传native grant。
- PendingCommandStore当前拒绝无原生身份place；仅放宽检查会令同route空身份共用去重键。现有attach只写facts，不更新重启恢复读取的native_identity/client_order_id/session_generation，需要明确的原子身份补写合同。
- 当前BT恢复对PREPARED空原生身份可能走完整场所查询查不到分支。Gateway标记必须先按原request_key/reservation_id读Gateway，取得强原生身份后才用D63-38；不能把逻辑预留当成场所查无此单。
- BT当前OrderRequest的account_id为direct且idempotency_key为空，需由可信Gateway路由绑定规范账户及策略UUID/序号请求键。客户端订单号不是CTP已分配OrderRef。
- sequence文件只存高水位，不存每笔完整请求。reserve发出前需耐久保存稳定请求意图，或交付可信按策略恢复扫描；不能从高水位猜回丢失的摘要。远端reserve/dispatch超时也不能流入现有“任意异常=确定拒绝”分支。

上述是后续63.02/03/05/06必须完成的接线项，未擅自更改BT产品代码或放宽恢复。实现需覆盖真实BT标记持久化、身份补写崩溃、丢回复、重复、迟到成交与单TD/MD的独立进程向量。

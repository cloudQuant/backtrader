## 1. 根本原因分析

五服务在 macOS 能启动、Win11 不能，原因是启动前置校验直接使用 POSIX 安全原语，而 Win11 无同语义实现，代码选择 fail-closed。四类原语：

| 原语 | macOS/POSIX | Win11 现状 | 能否等价 |
| --- | --- | --- | --- |
| 受保护文件读取 | `O_NOFOLLOW`+`dir_fd` 逐级遍历+`getuid`+权限位 | 无同名 API，符号链接是 reparse point、权限是 ACL | **能**（`FILE_FLAG_OPEN_REPARSE_POINT`+`GetFinalPathNameByHandle`+SID/DACL+nlink） |
| 睡眠包含单调时钟 | `CLOCK_BOOTTIME`/`CLOCK_MONOTONIC`(Darwin) | `time.monotonic_ns()` 不含睡眠 | **能**（`GetTickCount64`，实测含睡眠） |
| 非阻塞文件锁 | `fcntl.flock` | `msvcrt.locking`（项目已有先例） | **能** |
| 存储隔离信任 | sticky bit+uid+权限位 | 无 sticky bit | **部分**（ACL owner/写权限等价；特权主体语义需文档化） |

**设计原则**：跨平台适配 = 在 Windows 上实现**等价安全强度**，不是删除校验/伪造 uid/放宽时钟。无法等价的点保持 fail-closed。AGENTS「不以替换导入放宽校验」在此前提下满足。

## 2. 技术验证结果（实测）

- `GetTickCount64()` 含睡眠：sleep 0.25s → 前进精确 250.0ms；64 位不回绕；ms 分辨率需向上取整到 ns 上界（租约只会提前≤1ms 失效，不会延后授权）。
- `stat.FILE_ATTRIBUTE_REPARSE_POINT` 可用；`CreateFileW(FILE_FLAG_OPEN_REPARSE_POINT)` 打开链接本身不跟随。
- `GetFileInformationByHandle` 提供 volume-serial+file-index+nlink+时间戳，等价 POSIX `fstat` stamp。
- `GetFinalPathNameByHandleW` 返回句柄真实路径（`\\?\` 前缀），实测与请求路径一致——用于证明"文件未被重定向"。
- Python 在 Windows 暴露 `st_nlink`/`st_dev`/`st_ino`（实测 nlink=2 for hardlink）——消除"无法等价 nlink"的担忧。
- **pywin32 修复**：原安装 DLL 加载失败；`pip install --force-reinstall pywin32==311` + 运行 `pywin32_postinstall.py -install` 后 `win32security`/`win32api`/`win32con` 可用，提供内存安全的 owner/DACL/ACL 遍历。裸 ctypes 做 SID 遍历实测触发段错误（已弃用该路径）。

## 5. 边界与已知非等价（文档化，不静默接受）

- 具备份/恢复/接管特权的用户、同一 SID 下的第二进程：与 POSIX 的 root / 同 uid 进程同类，属威胁模型外，不视为本适配的失败。
- `FILE_WRITE_EA(0x10)` 的 DACL 位：Windows 默认 DACL 广泛授予，POSIX mode 位不涵盖 xattr 写，故从"other-writable"判定中排除（不因此放宽文件内容/所有权写防护）。
- 祖先目录：`read_bounded_windows(protected=True)` 对每级祖先做 owner 校验（current user 或特权 SID；卷根 `C:\` 视为 POSIX root 等价跳过；SYSTEM 拥有的 `C:\Users` 等豁免），与 POSIX「祖先 owner∈{0,euid}」等价。因 Windows 无 sticky-bit 等价且目录 DACL 普遍继承 family/group ACE，祖先不施加 others-writable 检查；**最终文件仍做完整 owner + no-others-write + nlink==1 检查**。这是语义最近等价，避免把用户自己的 Temp 目录链误判为不可信。
- 受保护文件（密钥/token）需运维在 Windows 上显式设置 owner-only DACL（等价 POSIX chmod 0600）；默认 DACL 会被正确拒绝。代码不代设用户提供的密钥文件权限（避免引入暴露窗口），仅对服务自己新建的文件/目录在创建时即设严格 DACL。
- `account_journal_host.__init__` 的 fd 级根检查已通过 `_win32_fdops` 完成等价（CreateFileW 相对路径 → 绝对路径 + by-handle stamp + 真实路径复核）；目录 `fsync` 在 Windows 无 API（NTFS 关闭句柄时落盘），属崩溃一致性而非访问控制，未放宽任何校验。
- `FreshSubmissionIntake` 与 store 的 POSIX-only 根作用域仍 fail-closed（本次授权范围外的他人文件）；它们不在五服务启动路径上。
- 真实账户、SimNow 交易写入、认证来源、R05 覆盖、交易时段：仍 NOT_RUN，与平台适配无关，需另行授权与真实服务链。

## 6. 完成判定

五服务 CLI 在 Win11 合成配置下全部启动到 ready，且所有原语测试通过、POSIX 零回归，方可视作平台适配完成；这不等同于任何迭代的用户验收，也不证明真实账户能力。

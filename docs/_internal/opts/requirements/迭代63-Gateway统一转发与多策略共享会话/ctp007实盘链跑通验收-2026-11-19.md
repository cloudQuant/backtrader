## 6. 7×24 SimNow 下的真实下单尝试（2026-11-19 17:20）

用户提供 7×24 SimNow（当日非交易时段仍可连接下单），据此做了完整下单验证：

### 可达性与行情
- profile `set2_7x24`（180.168.146.187:10130/10131）TCP 超时；`set2_7x24_4000x`（182.254.243.31:40001/40011）TD/MD **均可达**。
- 临时切 direct config：`env_profile: set2_7x24_4000x`、`timeframe: seconds` + `compression: 5`（5秒bar）、`fast 2/slow 3`（快速触发交叉信号）、`market_clock_verification: false`。测试后 config 已完整恢复原值（git status 干净）。

### 实测结果：信号触发，但下单被 fail-closed 拒绝
- 5秒bar 让双均线持续交叉：`SIGNAL golden cross buy 1 @ 960` / `death cross sell 1 @ 955` 多次触发，15 根 bar。
- **每一笔都被拒**：`target_data_not_tradable:SOURCE_CLOCK_UNVERIFIED`，附 `RECEIVE_CLOCK_UNVERIFIED, FRESHNESS_UNAVAILABLE, UPSTREAM_EXECUTION_INELIGIBLE, EVENT_TIME_STALE`。账户权益始终 10,022,465.23 不变，0 成交。

### 根因（SDK 深层安全架构，非配置可绕过）
- 7×24 行情的 event time 是虚拟交易日（2026-11-17），与真实 SNTP（2026-11-19）时钟域不一致，无法 qualification。
- 当前 CTP feed 走 legacy ticker 路径：`ctp_ticker.py:59` 默认 `source_clock_quality="unknown"`；生产代码无一将 legacy tick 设为 verified。
- 只有 quote_v2 路径能在 `quote_v2_projection.py:150-181` 产出 `execution_eligible=True`，且要求 native managed callbacks + parent attestation + rules_hash + clock_domain 完整证明链；`_quote_v2_metadata:2900-2903` 明确"managed native callbacks 会替换 caller 提供的 clock/quality 声明"——**无法用配置伪造 verified**。
- 全仓搜索无任何 `allow_ineligible` / `allow_unverified` opt-in：这是刻意设计，防止用不合格行情下真实单。
- `allow_stale_event_time`（`bt_api.py:978`）只放宽 event-age，且要求 evidence 有效 + venue_check.consistent；7×24 时钟域不一致时 venue_check 无法 consistent，仍不 eligible。

### 结论
- 7×24 环境**行情可连、bar 可生成、策略信号可触发**，但 SDK 的 `execution_eligible` fail-closed 门使真实下单不可能，除非接入完整 quote_v2 证明链（native managed stream + parent attestation，属服务/运营级能力，非本地配置可达成）。
- 这是安全架构的正确行为，不是 bug；本轮未放宽该门。
- 附带：为 gateway `--first-init` 补了 Windows state setup 等价适配（`gateway_initialization.py` 的 `_prepare_gateway_state_windows`，owner-only DACL + reparse 拒绝 + reservation 防重试，POSIX 路径不变），`--first-init` 已能生成 UUID4 identity；live_state 测试 480 passed/19 skipped，1 failed 为既有 Windows symlink 特权问题（WinError 1314，与改动无关）。

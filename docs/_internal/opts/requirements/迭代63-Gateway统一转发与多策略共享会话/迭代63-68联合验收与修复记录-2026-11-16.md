### 不能通过本地配置消除的来源缺口

当前 provider 对多项账户查询明确标记 non_atomic_consistency，scope_complete/history_complete 为 false。CTP 6.7.7 本地头文件及绑定虽有 SequenceNo、NotifySequence、BrokerOrderSeq，但没有发现可将其视作查询与全账户回报共同水位的合同；Gateway return buffer 的序号只是本地回调计数。当前私有流默认为 QUICK。切换重传、等待缓冲为空或重复空查询均不能单独证明共同切点。官方 [SFIT Mini API 手册](https://www.simnow.com.cn/DocumentDown/api_3/5_2_4/SFIT%2BCTP%2BMini%2BAPI-V1.7.0.pdf) 的订阅语义仅作参考，不替代当前 6.7.7 柜台的供应商保证。

Risk 的 attributed account.events 不包含未归属手工或其他程序回报；独立 account.facts 目前也只证明本地观察。现有 Risk cursor 每账户唯一，不能供第二个独立 epoch/sequence 流复用；需要独立持久游标、跨流身份映射、原子落账后 ACK。相同 fact_digest 的归属和冲突状态可能变化，不能单靠该摘要去重。本轮未通过修改私有数据库或伪造来源绕过这些合同。

Execution AtomicIntakeService 的 local_intake_available 当前明确为 false，原因是缺独立的账户级旧写者停止/撤销证明。已有正向测试用替身提供该前提，不能转成部署证据；新建空根目录、账户 journal 本地 lease 或当前只读宿主不能证明其他根、旧进程和延迟调用均被栅栏。完整收单和派发仍不开放。

再次核对新旧 Execution 路线：新的 ParentSubmitService、ParentJournal、ParentScheduler 尚无非测试 SDK 服务宿主实例化；ParentSubmitService 的 strategy/delegation 形状检查及注入端口不替代 Registry 授权和账户写者权威。旧 ExecutionGatewaySession 绑定另一套 ParentAuthority，不能直接注入新服务。Risk service 对 risk.parent.reserve/release 明确返回母单不可用，现有逐单 Risk 客户端也不是母子单适配器。因此不能把 Atomic Intake 的硬门当成已被新服务淘汰，也不能把裸 ACCEPTED 测试端口装入部署。

007 的 Gateway Broker 恢复循环当前仅区分 Risk 委托和 Gateway 自有订单。完整 Execution 接入必须持久化独立母单路由，并在提交、撤单、停机、重启、事件消费中一致使用；否则母单可能被错误送到 Gateway own-command 查询并被 NOT_FOUND 误判。现有 direct 母单投影和 Monitor 观察 relay 不等同于带账户/策略绑定、游标及完整成交事实的 Gateway 母单回报链。

007 Gateway 日历读取也没有现成公共能力可直接接入：Base 的实验性 TradingCalendarQueryPort 尚未接注册、编码或路由，现有 Gateway facade 没有日历查询；BT Store 的 Gateway 分支明确拒绝。需要范围授权、固定发布身份和代际一致性的只读传输合同，再连接 Feed，不能只追加 calendar scope 配置假称已使用。当前 package seed 仍为 SYNTHETIC_MOCK。

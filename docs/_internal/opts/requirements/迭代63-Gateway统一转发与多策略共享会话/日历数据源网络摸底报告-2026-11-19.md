## 3. 与既有报告对照
- 联合报告记录"SHFE 官方页已取但时段仍 SYNTHETIC，INE ACCESS_CHALLENGE"——**本次复核一致**。
- 新增发现：CFFEX 可达；DCE 超时、CZCE 412、GFEX 证书问题。
- 关键结论：**页面可达 ≠ 可用日历数据**。200 只说明能拿到 HTML；要从页面提取真实交易时段/节假日，
  仍需：(a) 页面结构解析（且随时可能改版）；(b) 与来源证明（source_authentication）绑定；
  (c) 覆盖六所全部品种/期权；(d) 每日更新链。这些都不是"能访问"就能闭合的工程。

## 4. 为何仍不能宣称真实日历覆盖
1. 仓库按设计不携带真实日历数据（`SIMULATION_ONLY/NOT_PROVEN` 是硬编码证据标签）。
2. SHFE 200 页面内容是.html 骨架，时段数据多由 JS 异步加载，静态抓取拿不到完整时段。
3. INE 明确 Challenge；DCE/CZCE/GFEX 各有反爬/网络/证书障碍。
4. 即使全部抓到，也缺"受信来源证明"——这正是 D1–D6 认证来源合同（第1项）要解决的。
5. 用户已选择第10项"先试网络摸底"，本项目的是摸清可行性，不是伪造真实日历。

## 4.1 第二轮深挖：进程内服务链与安全边界精分

用户再次强调本目标后，追加两名专项代理复核"能否在本机启动服务验收 Gateway"，修正了上一轮把 POSIX 限制一概归为"不可放宽安全边界"的粗判，改为三类精确分层：

- **A 类·纯可移植性**（加 Windows 等价分支不改变安全语义）：`fcntl` 硬导入（已有 `gateway/session_guard.py:24-27,303-324`、`risk/risk_order_journal.py:125-130` 的 win32→msvcrt 先例）；`signal.SIGKILL` 别名；`read_bounded(protected=False)` 对普通配置的无差别拒绝（`:45` 使非密钥配置也被挡，属过度；密钥安全全由 `protected=True` 分支承担，为该分支加 Windows 有界读取不会降低密钥安全）；Gateway operator profile 安装形态。
- **B 类·安全语义**（Windows 无等价原语或语义未确立，放宽即降安全）：`read_bounded(protected=True)` 的 `O_NOFOLLOW`+`getuid()`+权限位链遍历（`monitor_service_config.py:52-68`）、`monitor_service_host.py:65-67` 存储链、`gateway_storage_trust.py:82-83` 存储隔离信任、`ctp_gateway_local_profile.py:91` 资源加载、`account_journal_host.py:37-55` 睡眠包含单调时钟（注释明示「其他平台语义未确立前不可用」，混用 uptime 时钟会使 lease 提前失效）、`execution_read_service_host.py:163` / `execution_parent_service_host.py:269-270` 的 owner 检查、Runtime token `_protected` 读取。此类 **AGENTS 明确要求不放宽**。
- **C 类·外部依赖**：真实 CTP 前置/账户/交易时段；Risk 依赖活 Gateway observer（`GATEWAY_OBSERVER_UNAVAILABLE`）。

**结论（CLI 启动）**：五服务 CLI 在本机 Windows 用合成配置全部启动到 ready **不可行**——每个服务至少有一处 B 类硬边界，纯 A 类适配只能让早期配置门通过，没有一个能到 ready；WSL 被本机安全策略拦截，不可用。最少所需是换到 POSIX 宿主（与 11-17 验收同环境）且 Risk 需预运行活 Gateway。Windows 上若坚持，须先建立并验证等价安全原语（reparse-point 拒绝 + ACL/SID owner 校验、单调时钟语义对齐），属新安全工程而非可移植性修复。

**结论（进程内链 / 本机可达最高证据）**：以真实 `ServiceHost` + SQLite + CURVE + 合成 CTP 的 INTEGRATION_SIM，实测跑通四种**两服务真实链**——Gateway+Risk（`test_dim03_gateway_position_risk_host` 2 passed）、Gateway+Monitor（`test_gateway_required_monitor_long_restart` 3 passed）、Gateway+Execution（`test_iter63_gateway_execution_stream_processes` 6 passed）、Runtime+Gateway（`test_runtime_service_composition` 1 passed）。007 Gateway 功能逐项在进程内验证：行情 DELAYED→LIVE 投影（111+6 passed）、只读拒单（13 passed）、停止映射（43 passed/3 skipped）、心跳 epoch（22+3 passed）、策略账本读（52 passed）。**五服务同时起链 NOT_RUN**：最强四组件同壳测试 `test_service_host_integration.py:70` 因迭代65 角色退役被 skip（非 Windows 原因），其余测试各只覆盖 1–2 服务。

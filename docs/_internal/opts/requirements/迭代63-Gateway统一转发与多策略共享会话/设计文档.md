## 2. 组件、路径与启用

D63-10（Q33）已决定：Gateway 首期只交付 CTP 共享会话与交易转发；OKX/Binance 的 Gateway 接入放在后续。统一 SDK 与 Base 的中立类型、端口和路由保持 provider 扩展，CTP 原生字段、身份及会话语义归 CTP provider，不能将其作为其他 provider 的中立真值。已有 direct 路径不因本决定取消，其行为与验收按各自证据记录，不以路径存在或 CTP 测试推断通过。本决定不放宽现有 SimNow 以外 Gateway 写入限制，也不新增实际账户调用授权。

## 3. 配置与身份

下列为语义清单，具体键名及默认值未冻结，不是可运行配置。运营侧显式配置 Gateway 启用、账户 route 与环境、凭据来源、受信锁根、状态库、会话和行情键集合、主体及 scope/操作/合约 grant、传输监听与密钥、写入准入、查询/事件/配额上限；monitor required、租约自动 DRAIN 和其超时分别显式配置。策略侧只配置 Gateway 连接、自己的 UUID/本地状态、允许的账户路由、行情与可选服务选择，不包含 provider 凭据。默认 direct 不隐式启动可选服务；配置缺失、冲突、未知键、无效范围、未安装已选组件或不可证明环境给有限错误，不能自动降级。每个时长必须指定单位、上界和作用域；63.01 冻结租约、预留过期与限频值，不将建议数值当生产默认。

传输认证的可信 principal 由服务端映射密钥得到，载荷中的身份只作被校验声明。授权检查 principal + 账户 + 策略 UUID + operation + 合约；代理须获委托权限且 `on_behalf_of` 精确匹配被代表策略。运营、runtime、risk、execution、账户观察者和策略 principal 使用独立凭据；各自操作与策略/合约白名单由受信 grant 控制，状态、游标与预留句柄均不可跨主体复用。D63-13 已确认静态主体登记；撤权、证书轮换、授权代际与审计保留在 63.01 冻结。普通诊断日志不输出完整订单载荷、凭据、原始账户或认证材料；受保护交易 journal 必须保存规范身份、数量/价格和恢复所需事实，权限及保留按实施合同补充 §6。凭据不得进入任何日志，审阅只用脱敏材料。

拟议 `service.direct_write`：`session_status`、`reserve`、`dispatch`、`release`、`cancel`、`command_status`、`account_facts`、`strategy_book`、`instrument_positions`、`trading_permissions`；回报按授权流 `read_after`/`ack`；运营控制另设 `kill_switch`/`status`。`reserve` 需版本、账户、会话代际、请求键、订单摘要、来源、被代表策略、可选母单/子单身份；响应为预留号、期限与状态。`dispatch` 只接受原 principal 或服务端登记代理、同一预留号及摘要；状态查询同样授权。`account_facts` 请求含分区、新鲜度、期限、快照/分页游标；结果含交易日、会话代际、快照版本、完整性和有限错误。母单信封仅在 D65-01 选用相应方案后生效；格式、字段字符集和大小上限、序列化及最终名称均由 63.01 冻结。不同语义复用同一 request_key 拒绝；相同语义重试返回已记录状态，绝不重复派发。

## 4. 事务、订单身份与崩溃恢复

BT 局部序号 → Gateway 按账户/策略及请求键登记 RESERVED → BT 持久化含账户作用域和预留号的 PREPARED → Gateway 派发锁内校验授权、代际、期限、急停和摘要 → 分配原生身份并持久 DISPATCHING → Gateway 本进程签发并消费一次性 grant → 调用 provider → 持久 SENT/NOT_SENT/UNKNOWN → BT 附加原生身份 → 归属成交、账本和事件流同事务提交 → BT 幂等投影并持久快照后 ACK。策略库与 Gateway 库不共享事务；不得声称跨进程 exactly-once。

| 崩溃点 | 可证明的状态与动作 |
| --- | --- |
| 请求前、预留未提交 | 无可证明原生发送；按请求键查询或重新预留，不能推断网络已到达 |
| RESERVED 已提交，BT 未提交 PREPARED | 到期与派发同锁同事务竞争；重启前一进程代际的 RESERVED 在 owner 就绪前作 EXPIRED。仅在 EXPIRED 已持久且命令作用域/授权、完整日志覆盖、旧 owner 与迟到请求 fence 均满足 §4.1 时可报告 NOT_SENT，否则 UNKNOWN；测试到期与迟到 dispatch 竞态及 fence 缺失 |
| PREPARED 后、派发请求或回复丢失 | Gateway 自身协议可使用同一预留号/摘要查状态或幂等重试；已选 Risk 且 dispatch 超时则按 64 查询原身份，由 Risk 协调恢复，不自动重发 dispatch，也不绕过 Risk 直达 Gateway；测试超时、迟到请求与恢复；不能以超时报未发送 |
| DISPATCHING 提交后、原生调用前后无法区分 | UNKNOWN，按强身份与交易日查询；不重新发单 |
| 结果提交后回复丢失 | 查原状态；不得以新身份重复派发 |
| 成交提交后、BT 快照/ACK 之间 | 从旧游标重放，按来源事件及成交身份幂等；ACK 不得先于持久效果 |
| 数据库提交/磁盘失败 | 不发原生请求，停止新增派发并报告日志不可用；已发请求按 UNKNOWN 处理，不能凭异常认定未发 |

到期使用单调时钟，审计墙钟不能跨重启推断期限；两个事务都须条件更新且检查提交结果。CTP 新入口应在派发锁内分配递增 OrderRef，原 direct 行为保留；provider 自身的 native 授权仍有效。身份归属只认 `(交易日, FrontID, SessionID, OrderRef)` 或 `(交易日, ExchangeID, OrderSysID)` 的强键；成交先于委托时有界缓冲，超时进入未归属与待核，不以弱 OrderRef 猜归属。回报掉队、队列溢出、断线须产生缺口并补齐；未证明完整时不宣布就绪。

D63-38：完整、同交易日、会话一致且强身份的委托查询查不到时，记录 `not_found_at_venue`、通知所属策略并解除对应阻断，不自动重发；该结果不证明从未发送。缺页、代际变化、旧交易日或弱身份仍 UNKNOWN。休市待发单同样以 Rejected 通知；“取消待发”是停止本地待发而非场所撤单或 BT Canceled，不自动重新排队。迟到事实的真实 BT 原型、历史通知及更正验收见实施合同补充 §5，不假定终态绝对不能修订。Gateway 停机时不得隐式直连，撤单无法送达时报告部分完成并保留身份；本系统 UNKNOWN 范围按已定 D63-04（§4.2），其他独立对账异常待 D63-07。恢复、回调、状态查询应与同一订单的派发/撤单、日切及租约变更串行或以版本条件更新，保持可追溯的状态版本；D63-38 的迟到真实事实通过明确更正事件处理，不用“单调终态”丢弃成交。

### 4.0a Gateway 断连与恢复（D63-03，Q35）

Gateway 断连时策略进程继续运行并等待恢复，展示 `gateway_unavailable`；暂停无法可靠通过 Gateway 提交的交易请求，不因断连自动停止策略，也不回退策略本地 direct。场内活动委托仍可能保留或成交；断连、超时及撤单无法送达不能当成已撤或失败，保留原身份及结果不明状态。用户主动停止仍按既有停止和部分完成合同报告。

连通恢复仅是重连起点：须先重连并校验代际、补齐回报缺口和按身份去重、完成本策略/账户所需对账，再复核写入准入、时钟及其他适用条件，满足后才能恢复相应交易。未决命令按原身份查询，不换新身份盲目重发；D63-38 对完整同交易日强身份查询的已定解决规则和 D63-04 最小影响范围继续适用。断连本身不另建需要运营 RESUME 的持久暂停原因；其他独立急停或系统阻断按各自合同保留，通信恢复不能清掉它们。Q35 不改变 Runtime 正常 stop 或 Q31 自动重启政策。

63.05/06 使用替身和真实 Gateway 回环覆盖策略保持运行、断连提示、不回退、不可可靠提交的暂停、场内挂单断连期间成交/撤单不可达、UNKNOWN 原身份查询不盲发、重连后的缺口回补/对账/准入以及其他原因保留；缺证据保持 NOT_RUN。

### 4.1 命令 NOT_SENT 证明接口提案（63.01/03/13 与 64.01 对齐）

面向经授权的原 principal 或受权代理，候选扩展 `command_status` 返回受认证的账户 scope、请求键及摘要、Gateway owner/session epoch、日志保留区间与连续覆盖水位、命令的权威状态/终态及可验证的 fence 结果；不得仅凭调用者自报身份。63.01 冻结字段、认证、保留和过期语义；63.03 实现同一 owner 日志和状态转换；63.13 提供最小范围的代理查询权限。实现需证明水位涵盖所有可能到达的同一 reserve/dispatch，终态与封禁在持久边界内一致；旧 owner、旧代际和网络迟到请求此后均不能成功执行。跨主机或不同锁根缺少可信 fence 时不得声称有单写保证。保留期外、日志缺页、代际不明、查不到、超时或权限不足均不得单独证明 NOT_SENT，结果为 UNKNOWN；Risk 已有 claim 按最坏情况保留占用，不重发、不释放。

权威终态需要与迟到 fence 共同证明不存在后续生效请求，才能作为 64 风控侧 `settle(NOT_SENT)` 依据；`NOT_FOUND` 或没有 DISPATCHING 行不够。此合同不改变 D63-38：完整同交易日强身份场所查询查不到仍按该决定通知策略、解除相应阻断且不自动重发；它不单独证明命令从未发送，也不代替 Risk 释放占用所需的命令日志和 fence。测试包括旧 writer 接管、迟到 reserve/dispatch、有效 fence 后重放、缺页/过期/滞后水位、越权、事务提交与回复丢失；证明缺失标 GAP/UNKNOWN。

### 4.2 UNKNOWN 范围状态与准入（D63-04，Q28 已决定）

按计划 §3.6a 和共同合同 §2.19 实现：所属策略该合约所有新订单均暂停，其他策略仅在同合约同持仓方向真实可平容量因该 UNKNOWN 无法证明时暂拒平仓；不将该范围扩大为全部策略/整个账户。其他独立阻断仍可适用，撤单和查询保留，不自动撤已有委托或停止策略进程。派发结果未知与外部来源/数量差额分开。

Gateway 用原命令身份关联账户/策略/规范合约、持仓方向与适用桶、容量依赖、来源状态版本及解决依据；不能只用一个账户 blocked 布尔值。预留、派发及内部转移提交复核当前集合，与状态变更串行或条件更新，不能换母单/请求键绕过。真实可平证明须覆盖 UNKNOWN 最坏影响与占用，缺事实不补零；此系统未知栅栏在无 Risk 路径也适用，一般 R-03b 仍归所选 Risk。Risk 的未知最坏占用与 Gateway 范围分开，不能因范围小而释放。

收到权威解决事实后只解除该 UNKNOWN 的原因并重算其他策略的容量依赖；多个未决及急停/会话等原因继续保留，旧解决消息不能清除新状态。D63-38 查询判定、通知、迟到修订、不自动重发及 NOT_SENT 证明区别均保持。事件/UI 按授权展示原身份、影响范围、原因和版本；Runtime/Monitor 不主动清除。63.03/06/07 验证 A 未知平多、B 平多容量可证/不可证、B 平空/其他合约、无 Risk/所选 Risk、两笔 UNKNOWN 独立解除、重启/旧版本/并发、撤单查询与真实不可达，未测不标通过。

## 5. 账户事实、归属及内部转移

### 5.0a 账户首次接入与外部基线（D63-06）

Gateway 在同一 SQLite 事务原子提交基线、外部仓账本投影、审计及初始化状态；提交前失败不得留下部分基线，提交后丢回复查同一命令 ID 与摘要，同 ID 不同内容拒绝。快照中已含的历史成交不得通过补账再次作为新增成交；若不能按冻结的切点与覆盖证明历史和新事件之间的区分，则不能宣布就绪。新发生的订单及成交先强身份关联、缓冲与核对；可确认本账户外部来源的按 D63-09 作为 external 账本后续事件，不修改或吸收入原基线；来源不明按 D63-07/04 和既有合同处理。已有账本或日志损坏、账户身份冲突或状态未知，必须恢复/人工核验，禁止以重新初始化抹账。

外部基线记为 external 账本的 BASELINE 期初来源，不创建运行策略持仓、预算、手续费或场所成交；运行策略不能平或轧差 external 份额。账户初始价值已含外部仓的盈亏不重复入账；此后外部仓盈亏/费用须有独立来源，未知不填 0；D63-46 预算调节仅是策略预算差额，不作为基线。方案需以 synthetic 持仓及成交历史、真实 ServiceHost/SQLite 回环和替身 provider 验证，不追加任何真实账户操作；缺证明记 GAP/NOT_RUN。

63.01 冻结权限、版本、来源、切点及恢复；63.03 在 Gateway 提供受权命令、原子提交和替身测试；63.06 在 BT 区分账户首启、策略首启和重启、只消费状态；63.07 对接账户对账及外部仓隔离。63.03 不等待 63.06/07，63.07 在二者就绪后联测；如 63.14 页面提供此操作，只能复用同一受权 API，不增旁路或新 UI 步骤。

### 5.0b 运行中外部订单与 external 策略账本（D63-09）

用户已决定运行中可确认属于本账户外部来源的订单及成交归专用 external 策略账本，Gateway 和已有策略按正常流程继续；不能因外部订单或成交这一事实自动暂停全账户或合约，也不自动撤其订单。external 是账户账本范围，不是运行策略进程，不自动获得普通策略的写入或撤单权限。独立的账户/系统门槛和已决定的安全合同仍适用，本系统 UNKNOWN 范围按已定 D63-04，D63-07 其余独立异常另待明确。

记录外部订单和成交属于事后事实归集，不以普通策略授权、事前 Risk 批准或显式策略预算为前提，也不因 external 账本缺策略预算而自动停止全账户。事实归集与归属、资金 getter 可用性、所选 Risk 实际账户政策分别处理。

先按强身份匹配 Gateway 本系统订单，成交先于订单时缓冲、查询与核对；不能把未决本系统订单或只因暂时未匹配的事件自动归外部。可确认的本账户外部订单和成交保留来源、交易日、原始强身份、状态、数量、价格及真实费用；费用缺失保持未知，迟到费用更正、回报重放、乱序和重启按原身份幂等，账本与事件/审计按 Gateway 本地原子边界更新并参与账户对账。来源未能确认的保留未归属及证据；不得以账户差额倒算或伪造成交来消除不一致。BASELINE 是 D63-06 首次接入的外部期初分录，独立标记来源且不伪造成交；运行中外部事件是后续事实，不重写或吸进入原基线。首启仍要求无活动委托，运行中已有外部活动单不适用该首启限制。

**D63-48（Q26 已确认）**：同账户、规范合约和可比较切点，`Σ普通策略理论净持仓 + external 净持仓 = 账户净持仓`；多减空，买成交增加、卖成交减少。理论账仅按该策略已确认成交、内部转移及转换增量变化，未完成订单的请求数量单独作为 pending，不预计入已形成持仓。external 由已核准 BASELINE 加可证明来源的真实外部成交增量产生，禁止用账户减策略倒算抹掉差异；它不参与策略内部匹配、转移或虚拟转换。净额一致不代表账户真实多空/今昨及可平、gross 风险和其他映射全部正确；这些维度仍单独保存、按相应合同核对。预算、费用和盈亏公式不从数量恒等式自动推导。 普通策略汇总包含已停止、离线但理论持仓尚未清零的策略，不按当前运行进程列表过滤。

Gateway 在可比较切点发布版本化只读对账观察（来源/水位、账户、合约、理论汇总、external、账户数量、差额、完整性）；相等不报不匹配，差额非零由 Monitor 告警，事实不足或无法比较时显示未能核对，不填零或冒充健康。Monitor 只观察/告警，不修账、不发控制命令；63 用替身独立验证事件合同，不等待 68 综合验收，真实联调按各自步骤记录。外部订单/成交本身不触发自动停机，D63-04 本系统 UNKNOWN 范围按 §4.2 已定，D63-07 其余独立异常不因此代选。

63.03 为 external 分录、命令身份、事件与授权作替身验证；63.06 分别投影已确认 external 与未归属，禁止运行策略接管或撤 external 委托；63.07 用 synthetic 与真实 Gateway/SQLite 回环核对可确认外部订单/成交后系统继续、原生身份/费用去重、迟到与恢复、授权隔离及期初 BASELINE。验证 D63-48 的净额相等、非零差额与不可比较观察及 Monitor 替身，D63-49 的拒单/UNKNOWN 边界与账本不变须验证，未运行保持 NOT_RUN；不新增账户操作。

### 5.0 策略资金与回测统一合同（D63-44/45）

### 5.0c direct → Gateway 空仓迁移（D63-12，Q40）

首期只支持本策略空仓迁入，带仓迁移后续；本决定不改变 Gateway → direct 的独立准入与虚拟仓问题。先停止旧 direct 策略，核实原账户与策略身份，用完整可信且可比较的策略归属及原身份证据证明无持仓、无属于本策略的活动/在途/UNKNOWN 命令和未决账本动作；来源不明、日志缺口或不完整不当作空。不能自动平仓、清除账本、改名或重归 external 将策略仓绕过，也不得把旧原生日内订单复用为母单。

迁移工作流需持久记录请求 ID/摘要、账户与策略身份、原 writer 代际、核验事实与版本、接管状态及审计；同 ID 同摘要查询原结果，异摘要拒绝。先证明旧 writer 已退出并 fence 迟到请求，再让 Gateway owner 按受权条件接管并建立该策略空账本；两者互斥无法证明则不允许新路径写入。本机协作锁本身不能证明跨主机/不协作旧 writer 已停止。接管和空账本、审计在 Gateway 本地事务一致提交，跨进程失败或丢回复按原身份查询、恢复，不允许双跑或抹除旧证据。

不要求清空账户其他无关外部持仓：账户首次接入须符合 D63-06/Q24 经运营授权登记外部基线、全账户无活动委托及对账等条件；已初始化 Gateway 使用其已有 external 账本。外部基线始终归 external，不能分配为迁移策略仓。63.07 使用 synthetic、真实 Gateway 回环与 SQLite 验证空仓成功、带仓/活动/在途/UNKNOWN/未决拒绝、来源不明、错账户/策略、旧 writer 或迟到请求、阶段崩溃和同 ID 重试、外部仓与首次基线条件；该设计不授予本轮真实账户操作。

### 5.1 内部转移：63 权威合同的变更提案

D65-26 已允许内部转移；D65-27 进一步决定首期同时支持虚拟多空及后续平仓转换，不能仅实现已有真实持仓的归属转移。真实账户事实、策略虚拟账本与转换映射分别持有可追溯状态，不用净额守恒代替多空/今昨/风险核验；D65-28 允许虚拟 CLOSE 导致实际 OPEN 时按单独配置转换准入通过 STOP_NEW，按共同合同 §2/2.1 实现 Gateway 权威校验。此处提出对 63 账本合同的变更，**尚未冻结或实现**。Execution 65 产生可配置方案与双边提案，Gateway 是唯一权威归属账本及内部转移提交 owner；Risk 64 在启用时位于提交之前，独立判断并预留/claim 双边转移的暴露和占用，也消费获授权事实作结算；Gateway 不调用 risk、不检查批准。未选 risk 的路径独立，不以 risk 为前置。内部转移不产生场所 TradeID、场所成交、场所手续费或 provider 持仓，原生账户事实只能由 provider 更新。D65-31 明确同向不合并下场，轧差后各母单余量也分别下场；实际 child 唯一绑定发起母单/策略，真实成交不跨母单分摊且只记一次。虚拟转换的经济映射仍单独记录，不能以映射影响多个策略为由复制原始成交。多方内部转移由单一 Gateway 账本按各方授权原子提交，不形成共同场所订单。

### 5.2 跨日母单与信封（D65-04，Q38；63.13 扩展）

用户决定首期原母单可跨交易日继续；交易日结束不自动让母单或信封到期，也不重建身份或无限延长，原显式期限/有效期和独立阻断仍适用。母单调度和算法归 65，Risk 计数日及政策归 64；Gateway 提供权威持久状态，不导入 Execution。入口方案和接口名称仍按 D65-01 及 63/65 合同冻结；本节为需交付的 Gateway 侧语义，不声称已经实现。

**持久字段与身份约束**：为每个账户持久化稳定 `parent_id`/信封 ID、原策略及账户、请求摘要、原方案/授权版本、显式期限、母单总量和状态版本；子项保存 `child_id`、父 ID、唯一发起策略、请求/派发摘要、原生强身份及所属交易日、会话代际、状态及占用。母单标识不以当前交易日为唯一键；每笔实际子单场所身份按其自身交易日绑定。账本事实与可平桶映射保存来源事件、交易日、映射/账本版本和查询覆盖、完整性及可比切点；仅当事实完整可信时提供权威可用数量，不完整保持 UNKNOWN/不可用。字段名称和编码为候选，由 63/65.01 冻结。

**状态与事务**：母单的受理、冻结、继续、终止和显式到期必须带预期状态版本；日切只推进交易日状态和经证明的今昨桶映射，不隐式改变母单期限或归属。旧日活动、撤单中、派发中或 UNKNOWN 子单继续按原身份查询、接收回报和保留占用；取消请求本身、旧日空查询、切换交易日均不证明终态或允许释放。D63-38 仅按其完整同交易日、会话一致且强身份的规则解决，不用次日/旧日不完整空查询推断。日切与子单派发/撤销/成交/到期/恢复按同一 owner 串行或条件版本更新，子单占用变更、事件日志、母单计数和账本投影在同一持久事务内提交；回复丢失查询原身份，同 ID 异摘要拒绝。

以母单固定总量为上界，在同一版本划分互斥的已完成量（真实成交或经确认的内部转移，按原母单各记一次）、在途占用量（含待派发预留、活动、撤单中及 UNKNOWN 的最坏占用）、可用未下量和已确定取消/到期量，四者之和等于原总量；同一数量不得同时计入多个桶。部分成交只把增量从占用移至完成，确认撤销后才按原计划和适用政策决定是否释放至可用或记入终止；不能仅凭发出撤单释放。内部转移/虚拟转换按已冻结的独立来源和映射记账，不伪造场所成交、不让 external 参与转换。任何不完整事实或版本竞争都不允许创建超出权威剩余量的次日子单。

**平今母单的跨日目标映射（D65-37，Q39）**：母单持久保存原始平今意图、账户/策略及合约方向、目标仓位来源/归属与目标数量；日切时基于 provider 声明的规则和版本建立原目标持仓由今转昨的可追溯映射，不能拿次日新开的今仓替换原目标，也不改写母单意图。原期限仍有效、映射及原目标归属完整可信、真实可平量和其他准入均满足时，未成且未被旧子单占用的余量可派生平昨子单。记录母单意图、派生子单 offset、原目标及映射版本、授权/账本/可平事实版本和理由的审计链；中立平昨对应何种原生 offset 由 provider 按场所规则声明，不将 CTP 原生值写死在中立合同。64/65 消费此权威映射与版本，各自负责风险和调度。

Gateway 在同一权威事务及版本条件下核验和占用原母单剩余与目标真实可平容量，并持久化新子单、映射和审计；旧日活动、撤单中、派发中或 UNKNOWN 不因日切释放、重发或与新单重复占用，迟到成交按原身份幂等计入完成并扣减对应权威剩余。原目标无真实可平量按 D63-49 拒绝而不自动改为 OPEN；事实或映射不足保持不可证明，不凭空补足。DAY 或原期限已到期不得延长。external 不参与虚拟转换，也不能充当原目标策略仓或转换对手。

例：原平今母单 5 手，已成 2 手，余 3 手无旧子单占用；次日原期限仍有效、原目标的剩余 3 手已依权威映射转昨且真实可平时，派生平昨子单 3 手。若旧子单仍在途或 UNKNOWN，则相应数量继续占用；若迟到成交，先按原身份扣减，不能再按原 3 手派发。63.13 以 synthetic 和真实 Gateway 回环覆盖该例、旧日活动/UNKNOWN、迟到成交、目标归属与新今仓隔离、映射及授权撤销/版本竞争、无真实可平、缺事实和 DAY/期限到期，并核对 offset 审计和数量守恒；不新增账户操作。

次日子单先核验当前会话交易日与结算、当前授权及租约、有效期、行情与交易时段、写入准入，以及权威剩余量、真实可平桶与完整性版本；条件不足保持不可派发并报告，不以连接或日切完成单独当作交易就绪。Risk 日计数随其规则归属，不能把它当作母单总量复位。测试以替身 Execution、真实 Gateway 回环和 SQLite 覆盖原身份跨日、显式到期、活动/撤单中/UNKNOWN、迟到成交和费用、日切/派发/撤单/恢复竞争、逐事务崩溃及丢回复、旧日空查询、撤权/过期行情/结算未就绪、桶和完整性缺失、重复事件以及数量守恒；扩展单列验收，缺证据记 GAP/NOT_RUN，不增加真实账户操作或使 63 基础步骤等待 65 综合验收。

D63-36 的时间判定不变；D63-43 已按用户授权选定 Gateway 中继主动请求、Monitor 在同一受认证请求中响应 ACK，不增主动上报 endpoint。普通持久事件提交后确认；心跳验证处理后响应，只证明该心跳已处理，不证明全部业务流追平。认证 principal/scope/epoch/心跳 ID、重复和过期处理遵守共同合同 §2.2；Gateway 以自身发出时间判断，不以回复到达时间刷新旧心跳。心跳处理独立/优先且有界，不与交易线程共享阻塞发送；缺回复不能伪造确认。required 未选时监控不阻塞；选中时 Gateway 按宽限/超时施加 STOP_NEW。方式已定，wire schema、错误码、版本及真实联调仍待交付。

**D63-33 的 Monitor 部分（Q34 已决定）**：仅显式启用 `monitor_required` 时，Gateway 在 Monitor 存活丢失后施加账户 STOP_NEW；有效恢复后默认由 Gateway 自动解除该 Monitor 失联原因，可配置为人工运营 RESUME。有效恢复必须是当前中继代际、受认证、绑定已发心跳请求的响应，且该心跳发出时间满足 D63-36 新鲜度；Monitor 仅响应 Gateway 主动中继请求，不发送控制命令。进程启动、网页打开、积压旧 ACK、刚收到的旧心跳响应都不能证明恢复，本决定不增加等待轮数。

Gateway 用 `cause_id` 与状态版本条件提交解除，并与失联、重启、其他原因更新串行或作等价版本竞争；恢复判定后再次失联产生新原因或版本变化时，旧恢复不能解除新原因。只解除该失联原因，不解除 Risk、人工、Runtime、其他 Monitor 新失联原因、UNKNOWN 或其他系统阻断；原因消除不等于交易就绪。Gateway 重启按 D63-36 的新代际启动宽限并重验，不以旧持久健康或旧代际 ACK 自动解除。人工模式只允许既有受权运营 RESUME；Runtime 的 D66-08 有限代理不能解除 Gateway 来源的 Monitor 原因。租约过期 DRAIN 的解除默认未在 Q34 中决定。

D68-08 的主动告警 Webhook 与 Gateway–Monitor 被动确认通道分开；Gateway 事件接收 ACK/心跳不等外部通知。通知端点不授予控制权限，Webhook 慢/失败不自动改变 Gateway 的交易准入或撤销已确认接收；Monitor 服务本身存活仍按 required 合同处理。

行情断线时 Gateway 宣告恢复中，Feed DELAYED；源重启轮换 epoch 后按 D63-39 自动 resync，健康且满足时钟资格的首笔 tick 再 LIVE。逐消费者游标、队列、丢弃、gap、订阅健康必须有界可见；重试、重启、旧事件和退订不得串流。日切持久 `switch_pending → settled → catalog_ready → observed → ledgers_converted → reconciled → day_ready`；账本今转昨与转换标记同事务，失败保持阻断。D63-14 已确认结算由 Gateway 每交易日自动确认；未知结果按既有回读规则处理，以上日切状态仍须实现和验收。

### 6.1 Gateway 独立前端（D63-47）

按共同合同 §2.13 与计划 §3.21，交付独立可启用的页面及 Web 适配入口。读模型显示会话/行情、账户/策略资金持仓、实际订单、内部转移、急停原因及命令进度；快照版本、来源时间、完整性/UNKNOWN 随结果保留。账户与策略名称、真实与内部成交来源均不得在 UI 合并。

页面可受权提交现有 STOP_NEW/FREEZE/DRAIN/逐原因 RESUME；Gateway 继续持有状态和鉴权/执行/审计，不新增人工交易、任意改账或清 UNKNOWN 能力。浏览器会话的可信操作者须映射到当前 grant，HTTP 适配复用同一应用操作及命令日志，不让浏览器持有 provider/CURVE 私钥或通用运营密钥。授权的目标范围、操作、原因、预期版本及请求 ID 都在服务端校验；如页面提供 D63-06 外部基线登记，仅能调用同一受权运营 API，不能手填数量绕过 provider 事实或对账；隐藏按钮不能替代拒绝测试。

63.01 冻结端点/schema/错误/版本与身份映射；63.14 实施 Web 读接口、控制适配、页面和独立启动/构建说明。页面模块、运行外壳和 API 地址/认证/路由宿主配置分离，技术栈采用共同合同 §2.13.1 的 Vue 3/TypeScript/Vite、Vue Router/Pinia、Element Plus/Axios 及可选 FastAPI 适配；不依赖 AFI 或 Monitor 才能运行。当前本机部署边界保持，未来 AFI 是同一服务 API 的客户端，不重复实现领域逻辑。

写命令耐久受理后，UI 按原 ID 查询/订阅结果；双击、跨标签页和断线不能重复执行或把未知报成功。若两标签构造不同 ID，仍须依目标版本与原业务状态消除相冲突的写入，不宣称幂等键能合并所有独立操作。页面退出不取消业务操作，不自动 RESUME；原因解除与可交易分别显示。UI 接口资源有界，关闭/崩溃仅页面不关闭 Gateway，不影响策略租约或 monitor_required；监控服务本身失活仍按原合同处理。

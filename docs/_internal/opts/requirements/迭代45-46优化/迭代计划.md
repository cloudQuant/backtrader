## 1. 目标与归属

### 1.1 新的目标结构

```text
已知可用的行情/额外字段 → 调用者 align_to_grid 对齐到统一 grid，保留真实bar标记
  → Cerebro 推进 → FactorStrategy统一回调采集因子值、open/close
  → FactorSink（Memory / CSV）→ FactorPanel
       ├─ evaluate_frames → fincore 评价
       ├─ write_factor_report → 单因子 HTML
       └─ to_csv / from_csv → 可选 CSV 往返
```

不再有PIT as-of预对齐、逐格availability表/input_times、ResearchDataset校验/封存、dataset存储manifest和内容哈希。算子内部的轻量reason数值线与真实bar布尔标记仍用于正确传播缺失和数学域错误，不导出成第二套审计数据集。

目标：

1. 删除 `_collect_current_grid_point` 中每个格点 × 资产 × 因子的availability/input_times记账；只保留grid校验、真实bar判定和必要的数值输出处理。
2. 用 `FactorPanel` 承载 fincore 实际需要的五类数据及少量区间/方向参数，不引入第二套校验/封存模型；具体最小接口见§3.1。
3. 用 `FactorSink` 作为采集出口：默认 `MemorySink`；`CsvSink` 在正常结束时统一写CSV。observer只作为可选旁路日志（见OPT-09），不作为主采集路径；两者的finalize、close和缓冲释放顺序见§3.2。
4. 保留 fincore 评价和 HTML 报告的薄适配器；能力预检、错误翻译和索引规范化继续保留。
5. 保持因子公式、Cerebro生命周期及共同输入上的fincore统计口径；float64迁移允许事先定义的舍入差异，删除PIT/快照等能力单独列出，不冒充全API等价优化。不得删数据、填0、缩短窗口或跳过evaluation换取速度。
6. 以 025/026/027 的 50 只诊断和 500 只用户主场景为基线，分别测量旧实现与新实现的阶段耗时、端到端耗时和峰值/驻留 RSS。

## 3. 必须保持的合同

1. **因子结果与对齐。** 在共同输入范围内保持完整`(time, asset)`索引、因子列顺序、研究/预热窗口和首个有效时点。`prenext/nextstart/next`共用一次采集入口，每个grid只采集一次；真实缺bar写NaN，不沿用旧值。不再生成availability表和input_times；保留算子内部`OperatorReason`/reason线及严格异常传播，它们不是被删除的逐格审计表。
2. **数值语义。** 运行时统一 float64，移除相关/协方差的 Fraction/Decimal 路径。Pearson 相关与总体协方差 `ddof=0` 保持完整窗口，但退化规则必须分型：相关系数在常量输入或窗口小于 2 时为 NaN+DOMAIN_ERROR；完整有限常量窗口的协方差、标准差为 0，单值总体协方差也为 0，不能套用相关系数的拒绝规则。采用稳定的浮点算法，例如适当缩放、中心化、`math.fsum` 和 `math.sqrt`；避免两个巨大且接近的原始矩相减，并验证缩放恢复及中间乘除的溢出/下溢。允许与旧高精度结果存在正常舍入差异，不要求逐位一致；rank 按实际 float64 精确相等分组，不引入 epsilon。
3. **生命周期。** Cerebro 仍是唯一推进者，保留 owner 注册、原生子指标、clock、minperiod 和 runonce/runnext 行为；不引入第二套面板调度或手动重复调用 `next()`。缓存按实例/研究运行隔离；跨因子只复用冻结输入和对齐事实，不共享带 owner/clock/strict 状态的可变 Indicator。runonce 先计算后采集时，仍要保留研究窗口内的逐点结果，不能只保留最后状态。
4. **输出与交换。** `FactorPanel`是普通帧容器，不是不可变快照；最小数据、CSV格式和显式复评参数见§3.1。不恢复dataset ID、manifest、内容哈希、防篡改或历史snapshot读取功能。内部缓冲转为面板后只保留必要所有权，不为每次取数整表深拷贝。
5. **fincore 统计。** 保持 NaN、零权重、退化分组、标签期、组中性、等权/因子权重、重叠持有期、索引/列顺序、公开返回模型及 `result_fingerprint` 合同。不合并参数、样本池或数据身份不同的计算，不跨运行保留可变全局缓存。多因子共享限于身份相同的未按因子清洗标签；每因子的 finite mask、联合 dropna、分位、IC 和权重仍独立。不能用各周期独立 mask 的算法替换当前 HTML 多周期联合清洗语义。
6. **可见结果。** 默认股票数、日期、因子、评价期和报告内容保持现有配置。正式前后配对使用相同输出范围；纯 HTML 试验与完整评价/图表试验分别标识。报告未显示的模型字段仍可能参与语义指纹，展示无变化不等于公开结果合同无变化。
7. **明确移除的能力。** PIT表/as-of选择、专用classification接入、`table:`绑定、ResearchSpec输入表、`ResearchDataset`及save/load、dataset ID、dataset manifest/内容哈希、旧dataset CLI均移除。历史snapshot不保证可被新版本读取。公式需要的行业编码/cap/VWAP等作为普通feed输入；本轮不承诺替调用者完成发布时间、行业历史或复权/单位治理。
8. **迁移范围。** 公共导出、specs、factor_indicator/strategy、`research/_helpers.py`及公式输入声明、薄适配器、025/026/027 quick、仍可执行的`027/run_daily.py`和相关测试/当前指南一起形成可运行迁移闭包。历史证据保留原文并在入口注明旧API；无残留导入的检查只针对活动代码和当前用法，不要求删除历史资料中的文字。

### 3.1 最小面板与CSV合同

| 对象 | 最小约定 |
|---|---|
| `factors` | float64宽表，唯一UTC `(time, asset)` MultiIndex，列为有序因子名；覆盖研究区间的完整时间×目标资产积，保留NaN，不dropna或填0 |
| `grid` | 有序、唯一UTC close_time索引，保留fincore所需open_time等现有日历列；研究start/end均在grid上 |
| `prices` | open/close float64宽表，列为有序目标资产；可以覆盖预热和研究结束后的标签尾段，不能只从因子采集窗口截取 |
| `universe / groups` | universe为研究网格×资产的布尔宽表；未提供才默认全True，提供后不静默补True。groups为资产到研究分组的映射，不等于行业中性化标签 |
| 区间/方向 | 显式start/end、目标/因子顺序及每因子±1方向；方向取自FactorSpec，不猜测或统一改成+1 |
| 评价配置 | `evaluate_frames(panel, spec)`由spec提供评价期、标签、价格口径/日历/频率、调用者数据版本声明等fincore实际必需项；不再从旧dataset私有属性取默认值 |

CSV保持轻量交换：`factors.csv`为long格式`time/asset/factor/value`，另写`grid.csv`、`prices_open.csv`、`prices_close.csv`、`universe.csv`、`groups.csv`。时间显式UTC、资产名按字符串读取以保留前导零、数值采用可往返float64的格式、NaN不丢行。格式/列名在R1冻结；不新增manifest、dataset身份或摘要文件。

`from_csv`必须显式获得研究start/end、覆盖所有因子的方向、`target_order`和`factor_order`（由调用者或示例config传入），按它们重建完整索引；不从首末非空值推断区间，不猜long CSV的因子列序。NaN单元也有实际行，读回时缺行或重复键都报错，不能将截断文件静默reindex成NaN。仅做一次结构/类型/区间检查；缺文件或无穷值明确报错。全NaN但结构完整的面板允许保存/往返，评价不得因此判为可计算；空grid、无目标或无因子明确拒绝。旧snapshot/评价ID的重建不属于CSV合同。

公式输入只包含到研究end为止的已知信息；标签所需后续open/close由调用者的普通价格帧提供给面板，不让因子通过新增接口读取未来值。以独立fixture验证next-open的1/5/20期尾段，不能因为只在`next()`采价格而丢掉尾段；真实样本确实没有未来价格时保留相应缺失。

所有权默认明确为借用：panel和适配器不得修改调用者传入帧，调用者也不得在评价/报告期间并发修改。读取单因子/open价格不复制整个面板；若fincore公开入口需要隔离，最多在消费边界作一次必要副本，计入wall/RSS，不恢复递归封存模型。

R0b冻结新研究入口的最小spec及能力声明：方向覆盖每个因子，direction_overrides仅作为显式覆盖；价格口径、日历、频率和source/version说明由调用者提供，不生成数据身份。本轮支持由open/close生成标签；若不提供`precomputed_returns`输入则显式拒绝precomputed标签，不能沿用旧能力声明声称全部支持。HTML适配保持“原始open价格+`next_open=True`”，移位只由fincore执行一次，不改用close或在两端重复shift。每份报告内部必要的复制也分别计数，不把“边界一次”误称为所有因子总共只复制一次。

### 3.2 采集、真实bar和结束顺序

- 在`reindex`之前由原始源索引产生每资产的`present`布尔向量；reindex补出的空行仍有grid时间，因此`feed_time == grid_time`本身不证明真实bar。`current_bar`需同时检查时钟和该标记；真实存在但数值NaN的bar与不存在的bar分别测试。
- 最小presence可作为只读布尔数组或普通feed线传入，布局在R1冻结；它只表达源bar存在，不记录available_at或PIT历史。截面算子的默认成员应排除缺bar资产，即使某条分支/常量线仍输出有限值，也不能让补齐资产进入rank/scale。
- 缺bar用`present=False`和NaN表达，不为它伪造OperatorReason中的某个值。删除旧collector的`NO_CURRENT_BAR`等availability字符串，不等于删除算子的NOT_READY/INCOMPLETE_WINDOW/DOMAIN_ERROR等数值传播合同。
- 预热回调只推进指标和校验grid；研究区间内每个`(time, asset)`调用一次`on_point(time, asset, values, open, close, present)`，values包含该资产全部配置因子。保留runonce已计算结果的对应历史槽位，不能用最后状态代替历史，也不能在nextstart和next重复写入。
- 正常结束顺序为：最后一次on_point → `FactorStrategy.stop()`内finalize面板 → 若选CsvSink则写出 → close释放资源；`get_panel()`在结束后重复调用返回同一结果，不重复pivot/编码/写文件。覆写stop的子类遵循super调用合同，不改通用Strategy调度来迁就sink。
- 关闭应幂等。包住`cerebro.run()`的外层try/finally负责异常清理，不能假设异常时Strategy.stop一定完成；异常向上传播，产物标FAILED/PARTIAL，不生成假“完成”摘要。CSV先写新临时目录，成功finalize且写齐后才发布到新的目标目录，读取缺文件即报错；不实现重启恢复或事务日志系统。
- 默认MemorySink与CsvSink均可能需要完整面板内存，后者不是低内存流式承诺。优先float64/布尔缓冲，面板形成后释放不再使用的行对象；后续若需要有界分块sink，作为独立实测任务，不在本轮暗中增设第二套存储层。

### 3.3 公式输入、数值迁移与能力删除的边界

- 全101公式并非只需OHLCV。例如Alpha048需要subindustry、Alpha058需要sector、Alpha056需要cap；VWAP/ADV等也有专门输入要求。移除分类/PIT管理API后，必要标签以已对齐普通feed数值编码读取，声明和绑定并入普通字段路径，不恢复分类表、as-of查询或逐格来源记录。研究groups不能替代行业编码；缺必需输入时明确拒绝，不填默认行业或跳过该公式假装101/101通过。
- 当前18个公式需要行业编码：industry为059/063/069/070/080/087/089/091/093/097；sector为058/067/076/079/082；subindustry为048/067/090/100（067跨两个层级）。这些字段并入普通`formula_fields`和`feed:<name>:<line>`路径，未知编码为NaN；时间变化的编码也由调用者逐grid预先提供，不在研究层恢复分类历史管理。
- 删除`formula_universe`管理后，公式池定义为明确传入的目标集合、研究分组及真实bar/有限输入；评价universe只影响下游样本，不追溯改变已计算的公式。旧动态公式池/PIT成员接口不再兼容，相关旧测试按移除能力登记，不与共同输入parity混计。
- 字段存在性、唯一绑定、数值类型等在装配时一次检查；单位、复权、数据发布时间由调用者负责提供正确输入。删除field_validation并不意味着缺字段可静默填值或忽略因子声明。
- 数值策略一次切换至`alpha101-v2`：生产只用float64，无高精度后端或精度开关。旧v1仅为历史证据。算子和每个受影响公式分别对独立float64参考验收；事先冻结误差预算，记录近并列导致的rank/分支变化，不用epsilon还原旧高精度并列，不直接把生产输出写成expected。
- `dataset_id`删除不要求fincore丢弃自身的评价/报告指纹；同一输入下报告复用优化仍比较完整模型与指纹。新旧适配产生的身份字段差异单独说明，不要求跨已删除的身份合同保持相同ID。若fincore研究入口强依赖dataset属性，应在fincore改为接受普通帧及显式spec，不能造一个hash/UUID或恢复旧dataset来绕过。

### 4.1 删除与替换边界

- 删除的是旧能力及其入口：ResearchSpec输入表、classifications/formula_universe管理、FactorSpec的table/classification绑定及PITValueLine/table_lines均移除；专用PIT测试随能力删除，通用时钟/缺bar/公式数学测试迁移到新路径。
- 保留 `FactorIndicator.formula_fields`（因子声明的字段别名，如 `close/open/high/low/volume`）和 `feed:<name>:<line>` 绑定校验；删除的是 `ResearchSpec` 层的输入表/PIT 语义，不是因子字段声明本身。
- `universe` 保留为可选的布尔宽表；未提供时按网格 × targets 全 True。它不再从 `formula_universe` 或分类表推导。
- `groups` 保留为资产到研究组的映射；没有分组时使用单一默认组。
- `align_to_grid`对源索引和grid做一次UTC、重复/乱序/区间检查；每资产一次reindex并生成真实bar布尔标记。市场值不前填，不执行available_at或PIT as-of选择。相同对齐事实可借用，不能跨不同grid/资产复用。
- sink的on_point、finalize及close统一按§3.2实现，不在stop之前先关闭仍需写入的出口。CsvSink统一写出，不在每bar反复open/write/close。
- 面板与消费边界的所有权按§3.1明确，不默认递归deepcopy所有帧；需要调用方隔离时由其显式复制并计入成本。
- CSV 是交换格式，不是身份格式；没有 manifest、dataset ID、字节级规范编码和篡改检测。需要内容校验的调用者自行计算文件哈希。
- 删除的manifest/hash仅指旧研究快照身份系统，不包括输入行情清单、fincore自身结果/报告指纹、基准证据摘要或run_daily独立分段恢复标识；不能全仓搜索这些普通词后批量删掉其他功能。

补充矩阵采用单轴增长和少量代表场景，不做资产×历史×因子×窗口×模式的笛卡尔积。R0a冻结规模、有效输出下限和测量预算；Alpha048的H=251，需给足有效观测及普通feed行业编码，不能用243日全NaN或缺必需字段的输出验收它。合成长历史用于复杂度/正确性，不冒充真实500只数据吞吐。

500只样本固定资产清单、行情manifest/日历和输入摘要。前后不得重新抽样、删掉慢资产、更换评价期或减少输出；登记真实/缺bar及各因子finite/NaN计数、阶段错误，不恢复逐格availability原因表。结构重构的parity范围为普通已知可用feed输入、相同目标池和预热/标签尾段；不比较已移除的PIT查询/动态成员功能。float64迁移另列数值差异；fincore等值优化固定新profile和相同输入表，避免把有效样本变化算作性能收益。

### 6.2 记录方法

- 同一台机器、相同解释器与依赖、串行测量；记录系统、CPU、内存及后台负载。前后使用相同 I/O 与文件缓存口径。
- 基线和候选分别用新进程；先预热，再交替顺序进行至少 3 组配对普通计时，保存原始轮次、median 和范围。波动明显时先定位噪声再扩展，不能只选最快一次。
- 分开记录导入/能力预检、CSV 读取、`align_to_grid`、输入/节点装配、Cerebro、采集回调、panel 构建、CSV 写出、`from_csv`、每因子 HTML、研究评价、图表导出及完整进程 wall/CPU。
- 测量进程树峰值 RSS，以及采集后、panel 构建后、报告后的驻留 RSS；记录采集行数、因子单元数、panel 各表形状、CSV 体积；父子阶段不能重复相加，CPU 百分比注明核数口径。
- 另做有界计数剖析：采集回调次数、`on_point` 调用次数、pivot/复制次数、标签/weights/positions 构造、完整编码次数（CSV）；关键算子区分窗口读取、数值核、来源解析与调度。计数工具的开销不混入正式普通计时。
- cProfile 用于归因，普通计时用于性能判断；性能测试串行运行，不与 xdist、coverage 或另一仓库重型基准混跑。
- 每次记录代码/配置/输入哈希、两仓提交、依赖版本、模块 `__file__`、是否 dirty、命令、输出目录和失败原因。正式对比绑定干净提交或明确冻结的源文件集合。
- 每阶段分别记录请求与适用性、能力、执行状态、耗时和产物。未执行耗时为 null，不是 0；阶段区分 PASS/FAIL/BLOCKED/NOT_RUN/SKIPPED，027 不存在的评价标 NOT_APPLICABLE。退出码 0、PANEL_ONLY、COMPLETED 或已有 HTML 均不能覆盖其他阶段失败。

## 9. 开发记录与风险处理

后续实现时在本目录维护 `开发与验收记录.md` 和 `验收结果.md`，每轮记录范围、两仓提交、命令、输入/源摘要、正确性与性能结果、失败定位及下一步；本次仅更新本计划，不提前创建空验收材料。若采用不同算法或调整候选门槛，须在相应优化开始前说明依据，不能在失败后降低标准。

每个提交交付能独立导入、运行和验收的变更闭包；重构所需适配/入口/测试可一起提交，float64与报告数学复用另批归因。提交前完成对应反例和小型对照；全101回归用于数值/公式输入变更，500只完整集成用于收口和关键里程碑，不要求每次文档或局部试验都重跑全套。

主要风险及处理：

- **删除校验后静默错误：** 最小结构检查、真实bar标记和普通字段绑定按§3执行；发布时间/单位/复权等由调用者负责，不恢复逐格PIT管理。缺输入不得默认填值，补齐行不得进入截面公式池。
- **新旧 parity 无法复现：** 删除前必须由 R0a 冻结旧源码快照或 wheel、输入摘要和 fixture；删除后不能只凭记忆或历史日志声称等价。旧快照只用于对照，不重新进入生产路径。
- **迁移断裂：** R2以可运行闭包覆盖公共导出、辅助函数、普通公式输入、薄适配、quick和run_daily，静态导入/当前入口检查收口。历史45/46资料保留原文并在当前入口注明，不能为全仓grep零命中而改写历史证据。
- **fincore 依赖缺失或签名变化：** 保留 capability 检查和错误翻译；R0b 恢复明确配套的研究 API；评价缺失时保持 BLOCKED，不把 HTML 成功或退出码 0 当作评价通过。
- **内存换时间或成本转移：** 同时测量 CSV 读取、`align_to_grid`、采集、panel、CSV 写出、报告和评价；不把工作从 panel 挪到调用者脚本后不计入端到端。峰值/驻留 RSS 与耗时分开判定。
- **旧重层变相回流：** CSV缺的少量复评参数由调用者显式提供，不新增身份manifest/递归封存；普通feed行业编码不承担PIT历史管理。若未来真要as-of/数据治理能力，另立任务，不塞回FactorStrategy或align_to_grid。
- **数值迁移与删除混批：** 先完成 panel/sink 等价性和删除验收，再提交 float64；不允许用“已经重写”作为放宽数值门槛的理由。
- **历史与当前合同混淆：** 仅历史目录中的旧脚本可排除；仓库当前可执行examples/tests必须迁移，不能因为文件创建较早就称其为历史。当前指南指向本版panel/CSV接口，旧快照兼容明确不提供。
- **部分成功或基线噪声：** 逐阶段检查请求、能力、输出和有效性计数；固定样本、配对串行采样。未执行耗时 null，陈旧文件不算本次产物，差异未解释时保持 GAP。

fincore 可复用 `benchmarks/bench_factor_analysis.py` 等现有设施并增加报告/持仓场景；保留其已有基准治理。初稿曾观察到 `7679c71a…` 及后来的 `68162a814dec665aefd2b5ebb51d4ea4093e6df5`，后续复核也遇到变动中的 HEAD；这些都是历史观察，正式实施必须重新冻结两仓分支、源码和环境，不将旧诊断直接套作新基线。

本计划仍未设全市场吞吐目标，也不包含实盘、账户、原论文收益或 build 前端验收。后续若优化 5471 只全市场 `run_daily.py` 的既有分段/子进程链或引入新执行后端，须增加独立范围和基线，不能复用 500 只 quick 结论。

# I52-A A0：OKX 33 案公开源码逐案归属候选

## 范围与证据边界

本表按当前跟踪源码给出迁移归属候选，**不是账户认证结果**。使用 `git ls-files` 只列路径元数据后，逐个读取了 `cases/<ID>/<ID>_strategy.py` 与对应 `cases/<ID>/run.py` 共 66 个文件，以及 `certlib/runner.py`。未读取 `config.yaml`、`.env`、证据、captures 或其他私有输入；未运行测试、案例、交易、replay 或 shadow。

所有 33 行的 RISK、动作和 PASS 条件均是源码声明或源码 oracle。账户、环境值、真实权限、正式通过状态及正式证据均未核实，不能从源码推断。`RISK` 是案例声明，runner 另以 `--live`、`--allow-write`、`--allow-dangerous` 做入口门控；它们不构成账户授权或正式通过凭证。

本次只对照允许读取的 OKX Python 源码；已有“33 类候选”来源文本不在本次读取范围，因此逐项与旧表的文本差异为 **UNRESOLVED**。下面记录源码中能直接确认、可能影响旧归类的行为差异，例如 B01 的说明与实现不一致、EM 案例用篡改凭据模拟限制，以及 L03/M 案例以内联 `Monitor.record` 生成事件。

## 归属口径

- **adapter**：OKX 端点、字段、错误和账户/市场数据形状映射到 Feed、Store、Broker 的边界。
- **execution**：订单意图、委托状态、成交、撤单、持仓和订单历史生命周期。
- **risk**：本地订单校验、名义额/品种限制、暂停或拒绝策略；拒绝必须发生在 Broker dispatch 之前。
- **monitor**：运行事件、阈值、告警和可审计快照；由实际执行/查询事件驱动。
- **runtime**：凭据来源、认证上下文、时间同步、客户端/会话创建与关闭。
- **harness**：保留 OKX + case ID、输入场景、风险声明、oracle、结果映射和证据归档。

检查到的策略都以 `ctx.client` 调用 certlib 客户端 API，没有直接使用 Backtrader `Cerebro`、`Feed`、`Broker` 或 `Store`。每个 `run.py` 的作用是把案例目录和 venue 根加入 `sys.path`，再调用 `certlib.runner.main_case()`；案例本身因此仍需通过产品接口契约迁移，不能把这些脚本当成产品集成已完成。下表中的包/组件位置是提议；若没有现存位置可由允许的源码确认，标为 **UNRESOLVED**。

`certlib/runner.py` 读取命令行、装载策略和配置、解析 RISK、创建客户端、调用 `connect()` 与 `strategy.run(ctx)`，随后处理跟踪订单清理、关闭客户端、写证据及映射退出码。当前 runner 对非 direct transport 和 execution/risk/monitor 拓扑选项返回 `BLOCKED`，不会装载策略或尝试凭据；这说明这些拓扑在当前 OKX 案例 runner 中尚不是已接通实现。

## I52 逐案目标 owner 与迁移决定候选（2026-10-31）

本节是对上表的候选决定补充，来源为当前公开 OKX case 策略、case wrapper 与 certlib 源码；不是账户认证、授权、能力验收或正式 case 状态。owner 指 I52 的逻辑责任工作流，不是已指定的个人或已确认的代码包路径。A1 前仍须用允许的产品/SDK源码核实具体模块路径、现存 Feed/Broker/Store 和 paper/live 装配。本文未读取旧表提到的“33 类候选”来源文本，因此与该旧文本的逐项差异仍为 UNRESOLVED。

决定用语：迁移表示将源码场景的行为合同迁入 I52 统一 Strategy 与产品边界的设计/后续实现，不表示本轮已迁移或支持；保留表示不删除或合并原 OKX/case ID、风险标记和 oracle，旧 certlib 身份继续可追溯；延期表示当前不执行 provider/account 调用，不推导任何授权或正式状态。所有 33 个 ID 均保留，当前没有退役建议。真实环境、账户权限、mode、source QA、paper/live 接受仍未核实。表格中的“主要 owner”描述 case 当前源码主要承担的行为/产品责任；本节“目标逻辑 owner”是迁入 I52 后的主要实现责任候选，因此二者可以不同。例：C01 的第一表归 runtime，指认证会话与连接上下文；目标 owner 是 adapter（runtime 协作），指规范账户/合约/行情 DTO 映射。E01-E03 第一表归 execution，指当前源码确有订单调用；目标 owner 候选是 certification harness（adapter 协作），表示保留并隔离 venue-negative 认证行为，不接入普通 product dispatch。两表都只给逻辑责任候选，不确定个人或模块路径；具体目标路径仍 UNRESOLVED。

### 共享源码核对与更正

- 33 个 case/run.py wrapper 在当前 checkout 的内容相同（SHA-256 2fe4a6ad0cba17d355d83d41592c82fb635cc18439eaa4729dddb17e7a8d5e84）：把 case 与 venue 目录加入 sys.path 后调用 certlib.runner.main_case。策略源码通过 ctx.client 调用 raw client；这些入口没有装配 Cerebro、Feed、Broker 或 Backtrader Store。该结论只针对此 suite，不代表扫描了仓库中所有 OKX 集成。

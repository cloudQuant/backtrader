# I52-D：验收与发行切换

状态：规划；对应总纲 R9–R10。本文是迭代 52 的独立子计划，依赖 [I52-A](./I52-A-清点与统一合同.md)、[I52-B](./I52-B-运行时与首条交易链路.md)、[I52-C](./I52-C-策略与示例迁移.md) 的已提交实现和证据。

## 目标与硬边界

为 paper/live 范围建立完整、逐项可追溯的安装、组合、正式 paper-account 与 live 安全边界证据；只有在这些门槛满足、所有当前 paper/live 活跃引用切换且延期源码/证据已安全拆分后，才在独立小轮移除旧可安装 runtime 和旧门面。

唯一模式集合仍为 `replay`、`shadow`、`paper`、`live`；I52 只运行/验收 paper/live。跨模式复用适用 Strategy 是长期目标，不把 deferred mode 的行为作为本轮验收。production-account write/真实资金操作没有授权。假测试、旧运行时证据或默认零计数不能补足真实事实；任何必需项 `BLOCKED`/`NOT_RUN` 时不得宣称 `FRAMEWORK_COMPLETE`。

## D1 / R9：范围验收与证据闭合

1. **规格先冻结。** 从 A 的验收规格/证据索引锁定各 paper/live 支持场景、规模、资源与性能阈值；沿用适用的 I50/I51 原门槛。测试前冻结未定义的阈值，不按结果放宽。历史 PASS 不自动继承，成功调用不为交付重复。
2. **逐层验证。** 每个目标按 source、真实组件 + fake 外部叶子、隔离 installed、适用 paper-account、live 配置/拒绝边界分别记 `PASS`/`FAIL`/`BLOCKED`/`NOT_RUN`。验证 wheel/依赖/RECORD/仓外 import、配置与身份、Feed/Broker/Store、线程/资源、恢复/对账/停机、Monitor 权威边界及策略三文件行数；不能用 smoke 或 fake 替代安装/账户。
3. **逐项满足矩阵。** 把 52-F01–F19 按范围映射到测试/evidence ID、repo/commit、配置/路由、责任组件、fake 边界和未观察项。实际 paper F20 只按原 formal entry、venue 和 scope 完成外部模拟账户所需订单/回报/撤单或减险/对账/收尾；live 仅验证隔离和未授权安全拒绝。venue 间不代替，case ID/授权/状态不改写。
4. **守住操作控制。** 真实调用前单独复核原授权、fresh source pins、guard、账户 scope、private input 限制、已消费 generation 与 retained-host 状态。无授权或外部条件不可用时如实保留 `BLOCKED`/`NOT_RUN`；不得 unchanged retry、读取晚到私密捕获、人工 release/exit/kill 受保留 host，或运行 production write。

**D1 接受条件：** 每个适用 F-ID、正式 case 和示例都有责任/提交/证据级别/状态；证据满足相应层级而无推断跨级；旧历史记录和权限规则无改变。任何实际必需项未完成，则记录部分完成，不进入“整体完成”声明；是否继续已授权的小轮由具体剩余门槛决定。

## D2 / R10：旧 runtime 退役与发行切换

删除前须形成逐项可审核的切换门：

- A0/R0 的全量 inventory 已闭合；每个当前 paper/live 生产 import、命令、资源、配置字段和序列化 consumer 均有新路径、责任 owner 与安装/组合证据。用静态引用扫描与隔离 installed consumer 检查无活跃旧包 import、隐式 fallback、旧 shim 或双 write owner；搜到的残留逐项分类并处置。
- B/C 的替代能力和当前生产调用方均已验收；适用的 I52 paper/live 必需项和原正式入口结果清楚。`BLOCKED`/`NOT_RUN`、未获授权场景不能被标成 PASS 或由 deferred modes 抵销。缺少任何替代或活跃引用时，停止删除并保持旧包。
- replay/shadow/旧本地撮合专属源、测试输入、fixture 与冻结证据已拆到明确的非运行时保留位置，并用包构建内容证明它们不会随新 wheel/CLI/运行时装入；保留 hashes、原路径/归属映射和未交付声明，不改写历史证据。延期内容并不因拆包而被实现或验收。
- 核对各 repo wheel/version、Python 与依赖矩阵、license/版权、发布说明、升级/回滚版本对。基础 runtime 不意外加载 Backtrader/provider/SDK；无旧 shim、循环依赖、第二 scheduler 或默认权限升级。发布采用既定授权流程；此计划不授权向生产账户写入。

满足上述门槛后，R10 再以一个独立 scoped commit 删除 Backtrader 中已无活跃引用的旧 `backtrader_runtime` 实现/`backtrader.runtime` 门面及其安装资产；删前先验安装包/当前生产消费者，删后再验新安装包、仓外导入和旧 import 的明确失败行为。延期包外资产、历史测试记录和已冻结证据按保留策略继续存在。此删除只表明旧 runtime 退出 I52 paper/live 可安装路径，不表示 replay/shadow/local simulation 已迁移或交付。

若切换回滚，回到已提交且版本匹配的发行物与合同，按权限恢复入口；不重放 UNKNOWN、不复用已消费账户操作，也不撤销或改写已冻结证据。未达到移除前置时，只交付已接受的小轮并把 R10 标 `BLOCKED`。

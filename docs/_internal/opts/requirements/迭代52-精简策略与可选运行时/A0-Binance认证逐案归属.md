## 范围与判读

范围限于 git ls-files 列出的 33 个 tracked 策略文件、33 个对应 run.py，以及 venue 的 certlib/runner.py。没有读取配置、环境变量文件、private 输入、证据或 captures；没有运行测试、认证用例、交易、replay 或 shadow。下表的行为和 PASS oracle 是源码声明/实现的条件，不代表账户、环境、权限、实际运行或正式通过已经核实。

RISK 保留各策略模块的声明值，不是本轮重新评定的实际风险。源码里有两个声明/操作差异：M02、M03 标为 READ，但会启动、删除和续期 listenKey；另有多个 READ 案只证明本地检查路径，不是交易所完整安全证明。后续迁移应保留原始 case ID 与 oracle，另行审核风险标签和权限合同。

归属边界：adapter 管 Binance endpoint、过滤器/错误形状及数据映射；execution 管 Backtrader Broker/Order 生命周期和回报；risk 管本地下单前规则和写权限闸门；monitor 管事件、阈值、告警及快照；runtime 管连接、认证、时钟和 user-data session 生命周期；harness 管认证 case、CLI 授权、隔离、清理与证据。具体 SDK 文件路径未在本次允许读取范围内，故列出的包级位置都是候选，尚未绑定到已有类或文件。认证用例本身继续留在认证 harness，不建议把它们整体复制成产品策略。

## 共用 runner 边界

33 个 run.py 都把 case 目录与 venue 根目录加入 import path，然后调用 certlib.runner.main_case；它们不实现策略或 Broker。共享 runner 解析 READ/WRITE/DANGEROUS 风险等级、--allow-write/--allow-dangerous、transport/topology、策略类加载、client 创建/连接、CaseContext、订单补偿清理和 evidence 写入。它当前在加载凭据前阻断 execution/risk/monitor topology；Binance 的 service transport 仅放行 C01 和 L02，其余 case 返回 service_case_not_implemented。故本表的迁移归属不表示这些 optional runtime 已经接通。

建议认证身份继续由 runner 维护：venue、case ID、声明 RISK、原 oracle、授权结果和脱敏 evidence 关联保持稳定。产品职责迁出后由 harness 调用公共 adapter/execution/risk/monitor/runtime 接口做同一 oracle 的认证，不把认证授权、case 专属例外或 evidence 输出塞进通用策略代码。以上只是来源 API 的候选映射；账户、密钥、环境、权限、生产权限、历史证据及正式 case PASS 均未检查或确认。

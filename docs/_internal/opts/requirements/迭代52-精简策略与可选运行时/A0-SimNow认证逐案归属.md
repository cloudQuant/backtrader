# I52-A0：SimNow 33 案例逐案归属候选

## 范围与证据边界

本清单按公开源码给出 A0 迁移归属候选。已用 git ls-files 路径元数据枚举并逐个读取 33 个 tracked cases/<ID>/<ID>_strategy.py、33 个对应 run.py，以及 venue 的 certlib/runner.py。没有读取 config.yaml、.env、evidence、captures、账户信息或旧的 33 类候选文档；没有运行测试、交易、replay 或 shadow。

因此，owner 和迁移位置是源码归属建议，不代表现有实现已迁移、已集成或获正式验收。账户、环境、权限、提交状态与历史证据均未核；所有正式通过状态均未核。旧 33 类候选文档不在本次只读范围内，逐项差异标为 UNRESOLVED；只记录本次源码能直接证明的差异和风险。

## 共用执行边界

33 个 run.py 都是薄入口：把当前 case 目录和 SimNow venue 根目录加入 sys.path，然后调用 certlib.runner.main_case。runner 按 case_id 导入 <ID>_strategy.py 并取得 <ID>Strategy；RISK 从实例或模块读取。每例身份由 venue=simnow 与 CASE_ID 组成，策略是 run(ctx) 的普通 Python 类，源码直接调用 certlib，不是 Backtrader bt.Strategy/Cerebro 路径。

runner 先读配置并解析 topology。当前只允许 direct transport；transport 不为 direct，或 topology 要求 execution/risk/monitor 组件时，会在加载策略和凭证前返回 BLOCKED。live 路径另检查所需环境变量名是否存在、CPython 3.11、RISK 写入授权及危险授权；执行后负责 tracked-order 补偿清理、client.close 和证据输出。这是认证 harness 的现状，不证明任一后端已可迁移。本文所称候选落点是架构责任边界，后续须映射到实际目标模块。

归属词义：adapter 指 CTP 字段/查询/回报映射；execution 指订单、成交与持仓状态机；risk 指写入授权或本地/交易所拒绝规则；monitor 指事件、快照和阈值告警；runtime 指会话、登录、断开和恢复；harness 指 case 身份、参数入口和认证证据。

## 源码驱动的归属边界

1. 这些 case 当前用 SimNow certlib 的 context/client API；迁移对象是可复用的查询、会话、订单、风控和监控合同，不是把认证 runner 注入用户策略。现有 case_id、venue、RISK、scenario 参数和 CaseResult oracle 应继续由独立 harness 固定绑定。
2. B/O/T 的订单操作归 execution，行情、订单状态、成交、持仓字段归 adapter；E 与 V 的判定要区分交易所拒绝和本地零 dispatch；EM01/EM02 的核心是执行准入状态，不与订单状态机合并。
3. L03/M01/M04/M05/O01/TH02/TH04/TH06 的 oracle 含 Monitor 事件；TH01/TH03/TH05 只测配置快照。不要把策略手工生成的 monitor_start/monitor_ready 标记当成 venue/session 事件。
4. EM03/M02/M03 直接摸到 native _client 字段；这类实现细节应迁移为公开 SessionStatus/LogoutReceipt 合同。M02 的文件说明写外部操作者 stop，但实际代码自行调用 client.close()，随后手动记录 disconnect_observed，PASS 仅检查 close receipt attempted；这属于必须先澄清的 oracle/归属差异。

# I52-A0 决策：旧 runtime 产品入口迁移与删除

状态：本文件是基于任务白名单源码、两份历史 A0 表和主代理提供的 bt_api_runtime 项目交接信息形成的 owner/迁移决策；不表示新 wheel、代码迁移、安装验证、账户权限或正式验收已完成。本次只修订此文件，不改动代码、Binance 矩阵或 A1 合同。

## 决策摘要

1. **长期产品 owner 是 bt_api_runtime 项目，产品入口由其中 runtime build root / bt-api-runtime wheel 承担。** 项目有两个独立 build root 与发行包：contracts root 的 bt-api-run-contract 0.1.4 负责无 Backtrader/SDK import 的 schema/parser；runtime root 的 bt-api-runtime 0.1.8 负责 runtime assembly。两个发行名、版本与源码已存在（主代理提供）；发行验收尚未完成。
2. **新 CLI/entrypoint 属于 bt-api-runtime runtime wheel。独立审阅仅核验 runtime/pyproject.toml 未声明 [project.scripts]；其他 metadata 与 module 入口源码仍待核，不能据此断言不存在入口；新 CLI 命名待核。** 不把纯 parser contract wheel写成 CLI/runtime owner；也不保证继续使用旧 bt-runtime、python -m backtrader_runtime 或 python -m backtrader.runtime。
3. **旧 backtrader_runtime 产品整体取消，不作为长期 owner，也不承诺兼容。** 旧包、现有 bt-runtime console script、python -m backtrader_runtime、旧 schema-v4 parser/registry/runner/CLI，以及 backtrader.runtime 七个兼容 facade 和 python -m backtrader.runtime，最终均删除。迁移期保留历史源码/记录供责任拆分，不等于保留旧可运行入口、旧命令别名或旧配置行为。
4. **按责任拆分 managed execution。** Backtrader Store/Broker 集成层拥有 framework Order 规范化和执行事实向 Broker 的 typed projection；独立 SDK/execution/risk/monitor 接口拥有 provider session、账户范围、durable intent/receipt/outbox 和执行状态真值；bt-api-runtime 负责新 runtime composition 并把已验证依赖注入 framework adapter，不自行授予 provider 写权限。
5. **旧 preset 不做语义猜测式转换。** schema-v4 simulation/paper 是 local_simulation，允许 hypothetical fills、禁止外部写，不能映射为 I52 外部模拟账户 paper。I52 不要求保留该旧行为；需要迁移的策略与配置按新 A1 合同重新定义。

## I52-B/C/D 迁移与旧入口删除

### B：落实两个独立 build root

- 以已批准的 A1 为规范，在现有 contracts build root 完成 bt-api-run-contract 的 schema/parser contract；它不得 import Backtrader 或 SDK。发行名/版本为 0.1.4，但发行验收未完成。
- 在现有 runtime build root 迁移 runtime assembly 到 bt-api-runtime 0.1.8；它调用合同 wheel 而不复制 parser，并拥有未来 CLI/entrypoint。独立审阅仅核验 runtime/pyproject.toml 未声明 [project.scripts]；其他 metadata 与 module 入口源码仍待核，不能据此断言不存在入口；新 CLI 命名待核。该发行版本的安装可用性未验收。
- 把旧 schema-v4/policy/registry/CLI 的职责逐项转写到两个新 owner。迁移期旧文件只能作为历史代码来源，不作为任何新 wheel 的 runtime dependency；新 build root 不得 import 旧 backtrader_runtime。
- 旧 simulation/paper 不映射为外部 paper；旧 replay、shadow、local_backtest、sandbox 不进入 I52 的可运行路径。不要求保留这些旧行为。
- 记录两个 wheel 与 Backtrader wheel 的模块、依赖、resource、console/module entrypoint 分工；只读 source 表不能代替安装 consumer 与外仓调用者调查。

### C：按责任迁移实现与调用方

- 新产品调用统一切换到 bt-api-runtime runtime product，并按其合同消费 bt-api-run-contract。用户长期目标要求同一份适用策略通过配置和 Feed/Broker/Store 装配切换 paper/live；每个迁移调用点需确认实际 mode、账户范围和责任 owner，不能从 examples 路径名或字符串命中推断活跃性。
- 将 framework order normalization、Store receipt 和 Broker projection 实现在 Backtrader Store adapter；将 provider state、risk admission、intent durability 和 outbox truth 实现在 SDK typed interface；bt-api-runtime 只组合二者。旧 managed_execution 可被逐项替换，不需要保留旧 import/API 兼容 wrapper。
- 将 CTP config/setup/front-check/read-only preflight 移入另行批准的 operator/support owner，或随旧 runtime 一并删除。不得把只读查询或 sandbox 登记说成 paper/live 准入。
- 分别迁移生产调用、示例、测试/fixture 和安装 wheel。测试引用及 fake/source-only 证据不能替代真实 paper/live 接受。

### D：删除旧 package、facade 与安装入口

最终产品决策是删除，不是长期兼容。D 的提交与发布必须完成以下切换：

1. Backtrader、bt_api_py 和受影响 SDK/package 中已确认的生产 caller 逐项迁到 bt_api_runtime 项目或其责任 owner；静态调用审查及外部 wheel/plugin/operator consumer 调查完成。当前外部消费者仍未知。
2. 两个 wheel 各自完成独立安装验收：bt-api-run-contract 验收 schema/parser/API；bt-api-runtime 验收 runtime composition/CLI/API。新产品的 paper/live 接受达到两 wheel 之间清楚划分的合同要求。不能用旧 wheel、fake/replay/source-only 结果替代。
3. 在 bt-api-runtime 中实现新 CLI 并明确 command、console script/module entrypoint；完成安装验证。独立审阅仅核验 runtime/pyproject.toml 未声明 [project.scripts]；其他 metadata 与 module 入口源码仍待核，不能据此断言不存在入口；新 CLI 命名待核。旧 bt-runtime 名称不自动沿用。
4. 在 Backtrader setup.py 删除对旧 backtrader_runtime 的 package inclusion、旧 fixture package_data、bt-runtime console script；删除 backtrader/runtime 下全部七个 facade 和 python -m backtrader.runtime 入口。
5. 删除 backtrader_runtime 整个旧产品包及 python -m backtrader_runtime；删除旧 schema-v4 run/bootstrap/operator 命令实现和对应可运行入口。旧源码、历史 A0 文档和已接受 evidence 可以按其自身保留规则只读归档，但不保留可 import、可安装或可执行的旧 runtime。
6. 在外部消费者调查与发行沟通完成前，可以阻止一次未准备好的破坏性发布；这不改变长期 owner 已迁到 bt_api_runtime 项目、旧入口最终删除且不提供兼容承诺的决定。

## 3. 测量方法

1. **时钟口径**：吞吐与延迟一律用 `time.monotonic()`；跨源新鲜度/交易日对齐用场所原生时间戳，不用本机墙钟推断。
2. **延迟分段**（每段单独报告，不合并成一个数字）：
   `source available → 决策就绪` / `决策就绪 → 写授权检查完成` / `提交 → 本地受理回执` /
   `提交 → provider 终态可观测` / `回报到达 → Broker 本地投影完成`。
3. **统计量**：每段报告 p50/p95/p99/max 与样本数；样本数不足 100 的段落必须标 `LOW_SAMPLE`，不得当容量结论。
4. **CPU**：进程 CPU 秒/墙钟秒（单核百分比），并记录观测粒度限制（Windows 细粒度计时不成立时显式标注）。
5. **RSS**：预热稳定后取**首末两个等长窗口**的中位数差；同时报告 line/receipt/diagnostics/pending/订单缓存的容量上界与活对象计数，验证不随格数/事件数线性增长。
6. **队列**：idle pump 队列、SDK 事件队列、outbox 深度的峰值与回落后水位；背压发生次数与是否有界丢弃。
7. **恢复/停机**：unknown→终态确认耗时；停机各步（broker.stop、store.stop、journal close、lease release）逐步耗时与是否全部确认完成。
8. **停止边界**：会话 deadline 触发到引擎实际停止的用时，以及 `PARTIAL/shutdown_incomplete` 是否被正确降级（0.1.16 合同）。

## 4. 阈值口径：硬门 / 记录项

沿用迭代 50 的用户裁定：**纯 p99/max 时延与 CPU/吞吐目标只记录并用于后续优化，单纯超过不判功能长流失败**；正确性、有界内存与完整清理**不放宽**。

### 4.1 硬门（任一失败即该 profile `FAIL`，不得豁免）

1. 无伪造成交、无静默回退、无把 unknown 记成成功；能力不足必须显式拒绝。
2. 有界内存：稳定后首末窗口 RSS 增长 ≤ `max(32 MiB, 稳态 RSS × 10%)`；缓存/活对象数不随规模线性增长。
3. 完整资源关闭：Broker→Store 逆序全部确认，journal 正常 close + checkpoint，重启后回读一致；任一步未确认必须显式降级为 `PARTIAL/shutdown_incomplete`，不得报 `COMPLETED`。
4. 停机与 deadline 有界：到期后在承诺界内停止引擎；不出现无界等待。
5. 未决订单永不自发重发；撤单/减险独立通道在新 OPEN 被拒绝时仍可用。
6. 数据完整性：无缺格、无重复计入、无 oracle/来源缺口；证据文件字段完整且与内存事实一致。
7. 凭据/账户/前置值零泄漏：证据、日志、异常文本都不得含值。

### 4.2 记录项（报告但不作为功能失败）

- 各段延迟 p99/max、CPU 百分比、吞吐（事件/s、决策/s）、停机总用时。
- 历史参考值（来自迭代 50，仅作对照，不是本轮门）：决策持久化 p99 ≤ 100 ms、max ≤ 500 ms；本轮同形状若超出，只登记为优化基线，`status` 由 §4.1 决定。

### 4.3 判定用语

结果只允许 `PASS`、`PASS_FUNCTIONAL_LONGSTREAM_*`（仅因 §4.2 记录项超限而保留原始 `FAIL` 时）、`FAIL`、`BLOCKED`、`NOT_RUN` 五种，且原始 `status`/`gate_failures`/exit code **不回写**；追加裁定另档记录。

## 6. 已知缺口（冻结时就存在的诚实边界）

- 尚无统一的运行期指标出口（当前只有 `DirectSessionReport` 的 shutdown/facts 与示例证据 JSON）；P4/P5 需要新增有界计数导出，属实施项而非阈值。
- 尚无磁盘故障与进程重启的真实 provider 组合案例（P6/P7 目前只能 fake）。
- Windows CPU/RSS 观测粒度限制未消除；报告须带限制说明，不能把粒度噪声当应用回归。
- 长运行的“安静主机”前提不可保证；运行期间存在其它开发活动时必须标注，且不声称稳定提速比例。

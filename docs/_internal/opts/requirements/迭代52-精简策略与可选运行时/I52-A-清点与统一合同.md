# I52-A：清点与统一合同

状态：规划；对应总纲 R0–R1。本文是迭代 52 的独立子计划，母计划为 [迭代计划.md](./迭代计划.md)。不修改或替代母计划中的历史事实、正式 case 或最终门槛。

## 目标

先查清当前代码、运行入口与职责，再冻结可验证的配置和生命周期合同，并用一条最小 paper/live 装配纵切证明合同可落地。目标不是先造一个“通用 runtime”，也不是预设现有 Feed、Broker、Store 或 provider 已支持某种组合。

跨回测、`replay`、`shadow`、`paper`、`live` 共用适用策略代码，仍是长期架构目标。I52 可在合同中列明四种规范模式及未来能力边界，但仅实现和验收 `paper` / `live`；本轮不运行或验收 `replay`、`shadow`、旧本地撮合。`paper` 是 provider 外部模拟账户，不是本地模拟模式。

## 范围与分轮

- 直接从当前 `dev` checkout 复核 Backtrader、`bt_api_py`、相关 SDK 子仓库的 HEAD、gitlink、工作区差异及已存在的提交；历史 hash 和统计仅作历史基线。不得覆盖、清理或误纳入既有 dirty/untracked 内容。
- 逐项盘点旧 `backtrader_runtime` 的模块、公开符号、CLI、资源、配置/序列化字段、测试、固定源码身份和所有 import/callsite；另盘点 `backtrader.runtime` 门面及所有当前 paper/live 生产调用方。
- 完整枚举 `examples/live`、`examples/unified`、相关 certlib、optional16、模板、脚本、工具、文档和测试。至少逐条检查总纲列出的 007、012、013、014/015、028 与 `000_live_certification`，不可只靠目录名、状态标签或是否有真实账户证据筛选。
- 清单每行记录：稳定条目/旧 case ID、路径和调用方、provider/product、策略/数据时钟、Feed/Broker/Store、direct/service、mode 与账户环境、只读/paper-write/live-write 权限、依赖/目标所有者、当前状态、测试与证据级别、迁移/延期/退役决定、保留位置及后续提交依赖。

**A0 接受条件：** 全部条目有唯一归属、实际活跃引用和下一步；每个 paper/live 生产调用方有适配计划；延期内容和冻结证据有明确保全办法；未声称任何未验证能力已存在；原始工作区状态和历史证据保持可追溯。

### A1 / R1：版本化配置、能力与生命周期合同

- 冻结唯一用户配置 schema/parser 的所有者、纯数据校验、只读 `ResolvedPlan`、脱敏诊断和版本迁移/拒绝规则。即使 runtime 未安装或关闭也能校验；Backtrader 不另写一套 YAML parser。拟议 API 和字段先标为设计，不能写成已实现。
- 定义唯一模式枚举 `replay`、`shadow`、`paper`、`live`。能力矩阵逐项写“本轮支持 / 明确延期 / 不支持 / 尚未证明”；I52 的可运行/验收集合只有 paper/live。mode、账户环境、provider endpoint、账户/凭据引用、路由 scope、数据来源及写入权限分别验证，不接受未知键、交叉环境、隐式授权或 `dry`/`demo`/`simnow` 模式别名。
- 从源码和现有公共接口建立 Feed/Broker/Store 能力矩阵：组合、数据/执行边界、账户 scope、订单写权限、线程/资源所有者、Cerebro 生命周期、direct 与已存在的 managed/service 入口、依赖和已观察证据。每个单元只能标已证实、拒绝或待验证；不靠计划补造支持。
- 冻结启动/ready/健康/许可/停止/未决状态，错误分类，部分启动逆序收尾，借用/拥有资源责任，失败传播，以及唯一派发 owner 合同。运行时不成为第二调度器或订单/风险/账户事实权威。managed 失败不得退回 direct/mock/旧路径。
- 建立最小 paper/live 纵切：选用 A0 核实过的现有 Feed/Broker/Store 与可用 provider 组件；仅将最外侧 provider I/O 作为 fake leaf。用同一份普通 Strategy 源码，经配置分别形成 paper 与 live 计划并经过真实 Cerebro/框架适配入口；能力缺口如实阻断，不以 fake 类替换整个生产组合。

**A1 接受条件：** 配置正反例证明模式/账户/endpoint/凭据引用/路由/权限错配 fail closed；同一 Strategy 不因 paper/live 分叉源码；纵切能证明实际选择的组件、边界和失败结果；fake 的位置、来源及限制明示。Source/fake 通过只证明合同和装配，不是 installed、paper-account 或 live-write 通过。

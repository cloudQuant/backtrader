纯合同可安装于 Backtrader/runtime 均未安装的环境以完成文本静态校验；策略 ref/adapter profile 是否存在只能由调用方提供的可信内存 registry snapshot 再检查，未提供或版本不匹配时必须拒绝 plan resolution。runtime 未安装时不得暗中导入旧 parser，也不得宣称 resolved capability/assembly 可用。

## 4. 新合同 schema 与 resolver 边界（A1 未冻结）

### 4.1 版本、字段与 mode

合同包 0.1.4 保留 schema v2 的 product/data_source/clock 字段、显式 plugin 开关、有界嵌套及 None 参数和 capability 请求；静态 resolver 原子匹配 environment 与九 refs，并检查 code-owned 参数契约的顶层 exact 类型、required 项和只读 capability 声明。runtime 0.1.3 已提交 v2 source/fake assembly，组合真实 Cerebro/Store/Feed/Broker/ServiceReadProxy 组件，并显式要求 market.read 与 account.read。写 capability、插件启用仍 deferred；真实身份/权限、真实 provider/account 与完整 A1 未验证。schema v1 继续支持原只读装配路径。

schema v2 使用新的 contract_schema_version: 2，不沿用旧 config_schema_version: 4。公共 mode 枚举候选为 replay、shadow、paper、live。I52 实现和验收集合只有 paper/live；replay/shadow 明确标为 FUTURE。backtest、simulation、dry、demo、simnow 均不是 mode 别名；provider/environment 名可以单独引用，但不改变 mode。

候选 YAML 结构（ref 全部是假标识；不是可运行账户配置）：

```yaml
contract_schema_version: 2
strategy:
  ref: "registered:alpha003-v1"
  parameters: {}
runtime:
  mode: paper
  environment: paper
  adapter_ref: "registered:provider-product-adapter"
  product_ref: "registered:product-family"
  endpoint_ref: "registered:paper-endpoint"
  account_ref: "registered:paper-account"
  credential_ref: "secret-ref:paper-account"
  route_scope_ref: "registered:paper-order-route"
  data_source_ref: "registered:paper-market-data"
  clock_ref: "registered:provider-event-clock"
  requested_capabilities:
    - market.read
    - account.read
    - orders.paper.write
```

静态 schema 校验 mode 与 environment 必须独立且匹配：`paper` 只能配注册的外部 paper environment；`live` 只能配 production environment。`endpoint_ref` 必须是有名 ref，schema 不接受任意 URL；`account_ref`、`credential_ref`、`route_scope_ref` 必须来自同一个 trusted adapter/product/environment 的绑定关系。`credential_ref` 是引用，不含 key/token/password；只有在获得后续许可后，凭据 authority 才能解析该 ref，不能跨 environment fallback。

`requested_capabilities` 是请求集合而非授权集合；registry profile 与许可 authority 必须分别收窄、匹配并签发明确授权。至少检查 `(mode, environment, provider, product, endpoint, account, credential, route, data_source, clock, strategy_ref)` 全组绑定一致。未知字段/ref、字段错位、缺省 endpoint/account/credential/route、交叉 paper/live 凭据、production endpoint 配 paper、provider/product 不匹配、路由超出该账户权限、能力请求超授权集合，均 fail closed。schema 本身的有效性不意味着许可、可交易或 ready。

具体 production-live permit 的签发者、有效期/一次性策略与撤销语义仍为 **NOT_PROVEN**；live write 在本轮无授权且不运行。Paper 的 `orders.paper.write` 若未来接受，只能指向 provider 的外部 paper/simulated account，绝不能映射到 Backtrader 本地 hypothetical-fill Broker。`simnow` 是 CTP 环境标识，不是 mode。

### 4.2 纯 parser / DTO 候选 API

合同包候选 API：

```python
parse_config_text(text: str) -> RunConfig
parse_config_mapping(value: Mapping[str, object]) -> RunConfig
resolve_plan(
    config: RunConfig,
    *,
    registry: TrustedRegistrySnapshot,
    deployment: DeploymentBinding,

```

上面的 parse_config_text/parse_config_mapping 和带 deployment 参数的签名仍是候选，不是现有 API；当前实际入口为 parse_config(source) 和 resolve_plan(config, registry)。runtime 0.1.3 另已实现 source/fake assembly path，使用真实 Backtrader Cerebro、Store、Feed、Broker、ServiceReadProxy 组件并要求 market.read+account.read。相同 Strategy 类及 list/map/None 参数在两组 fake facade 上通过 38 项 source/fake 检查。静态匹配与 fake assembly 不验证真实资源身份、权限或账户。

这些是格式与纯数据约束，不证明原始文件来源可信。v4 的 file descriptor identity、private CTP block、loader weakref seal 不属于新 DTO。若运行入口需要配置来源审计，由 loader 在独立的 `ConfigSourceEvidence` 外层绑定 canonical path、文件摘要、读取策略与 registry 版本；该审计对象也不代表交易许可。

### 4.3 Plan 与启动 API 候选

建议将纯解析/解析计划与具副作用启动分层：

1. parser 校验 schema 并产生 RunConfig；当前静态 resolver 原子匹配 environment 与九 refs，并检查顶层 exact 参数类型/required 项及只读 capability 声明。runtime 0.1.3 已有 v2 source/fake assembly，使用真实 Backtrader 组件并显式要求 market.read+account.read；两组 fake facade 上的同一 Strategy/list/map/None 参数检查为 source/fake 证据，不验证真实身份或权限。
2. 单独的 `authorize(plan, permit)`（属于许可 authority，不属于 parser）验证 mode、account/environment、route、能力、策略和有效期，返回不能从 YAML 构造的 `AuthorizedPlan`。无 permit 时只可检查，不能 prepare。
3. runtime/adapter 层的 v2 source/fake assembly 已在 runtime 0.1.3 提交，组合真实 Cerebro/Store/Feed/Broker/ServiceReadProxy，显式要求 market.read 与 account.read；同一 Strategy 类及 list/map/None 参数在两组 fake facade 上验证。此实现不等同真实 provider/account 运行或资源身份/权限验证。写 capability 与插件启用仍 deferred；授权、生产身份、Strategy startup/cleanup 和完整 lifecycle 仍是 A1 阻断项。
4. 唯一执行入口 `PreparedRun.run(**kwargs)` 只调用一次普通 `Cerebro.run(**kwargs)` 并委托其策略/数据事件调度；它不是第二 scheduler。任何解析、解析计划、授权、factory、启动或 ready 失败都传播为有类型的 fail-closed 结果，不回退到 direct/mock/local-sim 路径。

第 2–4 步的最终包 owner、permit authority、完整 PreparedRun 与现有 run_configured_cerebro() 的组合关系均 NOT_PROVEN。runtime 0.1.3 已有 source/fake v2 assembly，但 38 项组合检查只使用本地 Backtrader/SDK base 源码与 fake facade，非隔离且非账户验收；不能据此证明真实身份、许可或完整生命周期。

### 5.2 状态与启动/停止

候选状态序列为 `UNPARSED → VALIDATED → RESOLVED → AUTHORIZED → PREPARING → READY → RUNNING → STOPPING → STOPPED`；任一阶段失败进入带稳定错误码的 `FAILED` 或 `BLOCKED` 并保留失败阶段。`READY` 仅说明已绑定所需组件且相应的连接/订阅、数据源与 clock preflight 成功；它不是交易许可、账户健康保证或下单承诺。Permit/许可是单独状态事实。

启动原则：schema v2 可静态校验并原子匹配 environment+九 refs；runtime 0.1.3 已提交 source/fake assembly，使用真实 Backtrader 组件并显式要求 market.read+account.read。两组 fake facade 验证不是真实 provider/account 启动，也不验证真实资源身份/权限。写 capability 与插件启用仍 deferred；生产授权、资源身份、ready 和失败收尾证据未完成。schema v1 的有限只读装配证据也不证明完整 Strategy startup 或失败清理。

停止原则：先阻止新策略订单意图，再按明确的策略/许可 policy 处理未决订单；不默默假定所有订单已撤销或已成交。完成 provider reconciliation/尾部事件处理后，仅关闭本 handle owned 的 Feed、Broker、Store、session、thread/transport；borrowed facade 不擅自关闭。关闭失败、回报缺口或未知在途订单使最终状态保持未决/受限，禁止静默 fallback。关停协议和每个 provider 的 close/readiness 证据目前均 NOT_PROVEN。Backtrader df0e0b887 的一次启动失败后尝试 best-effort 清理，但清理完整性未确认；observer 通知与部分 Strategy 状态未确认，不能据此声称启动/清理生命周期已验收。

### 5.3 三类配置不得互相冒充

1. I52 user run config 描述“要运行哪个可信策略、希望哪个 mode、引用哪组可信 provider/product/account/endpoint/credential/route/data/clock profile”——schema 版本由合同 wheel 管。
2. SDK `service_config.py` 描述 service/client process role、binding、transport/service/scope；由 `bt_api_py` 自己解析和版本化。
3. SDK exchange config 描述 provider venue、HTTP/WebSocket/SPI connection、endpoint、authentication 和资产类型；由 `bt_api_base`/exchange adapter 自己解析。

目标合同中的 resolver 应从第一种配置的 opaque refs 找到受信 registry 条目，再调用相应 SDK/parser/factory；当前静态 resolver 只做 environment+九 refs 原子匹配和有限 code-owned 参数契约检查。runtime 0.1.3 已有 v2 source/fake assembly，显式要求 market.read+account.read；写 capability、插件启用仍 deferred。source/fake 不验证真实资源身份、权限或账户。服务 schema v6、service schema v1、exchange Pydantic model 不能拼接成一个 YAML 大 schema。

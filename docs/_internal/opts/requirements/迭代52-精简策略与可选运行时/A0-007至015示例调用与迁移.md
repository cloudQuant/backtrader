## I52 共用迁移责任

1. **Strategy：** 保留与环境无关的信号、仓位目标和风险意图；不得以账户、凭据、provider 端点或交易权限作为策略隐式输入。双腿/三腿策略需显式表达腿关系和不可拆分/部分成交后的状态处理。
2. **Feed：** 对各 provider 负责数据读取、合约身份、单位、时区/交易时钟、序列和新鲜度。跨市场/期权场景须有源级映射及缺口处理合同；未知能力明确拒绝。
3. **Broker：** 负责订单、成交/部分成交、撤改、持仓、保证金/现金、佣金和账户回报语义。外部模拟账户与生产账户必须使用各自实际服务合同，不能以 BackBroker、MixBroker、SimpleExchangeModel 或合成撮合替代。
4. **Store：** 负责 provider 会话、认证边界、查询和资源关闭；只读 service facade 不应获得写权限。模式名不能授予权限。
5. **Runtime / 装配：** 将平行 run.py、legacy_runner.py、simnow_direct.py、run_runtime.py 入口统一到受约束的配置入口；只支持 paper 与 live 两个目标环境，未知模式/配置拒绝。严格区分“入口源码有写分支”与“账户、provider 和权限已验证”。
6. **待查项：** 必须通过公开接口合同或经授权的后续环境验收确认具体 endpoint、品种类型、账户类型、授权范围、订单可用性和实际回报。当前 A0 不对这些内容作推断，也没有正式案例 PASS。

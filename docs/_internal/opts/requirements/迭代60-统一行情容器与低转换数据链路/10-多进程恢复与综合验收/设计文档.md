## 职责与实现设计

- 按账户/授权视图建立订阅缓冲、完整快照及一致切点、重放到明确水位并去重；账户侧非原子事实不得冒充完整。
- 切换前停新命令并处理未决；确认旧 owner/provider 会话失效，或所有实际派发都受可验证 fence 强制约束，并核对在途 UNKNOWN。仅存储 fence 不足以接管。
- 固定相同数据、合同、环境、预热及指标测量 CPU、吞吐、分配、RSS、p50/p95/p99 和丢失；direct 与跨进程分别报告。

## 模式切换顺序

1. 暂停新命令，保留未决/UNKNOWN 并按原订单身份查询；不得为了切换重新派发订单。
2. 保存并核验策略身份、订单绑定、去重、账本、预算预留、游标及审计历史；确认旧 owner 与 provider 会话失效，或实际派发出口对所有 owner 强制执行可验证 fencing。仅存储 fencing 不能阻止旧会话下单，不能据此接管。
3. 新 owner 受控加载同一逻辑账本，取得授权账户快照并衔接事件切点；核对订单、逐笔成交和持仓，出现缺口或不一致则保持不可用。
4. 恢复条件明确满足后才允许继续；跨进程事件接收端应在状态和游标一致持久化后 ACK，不能声称交易所派发 exactly-once。

## 恢复状态机

| 阶段 | 动作 | 准入条件与失败 |
| --- | --- | --- |
| QUIESCE | 禁止新命令，登记在途/UNKNOWN，持久保存绑定、预留、去重、游标及审计 | 无法确定结果保留原身份及 UNKNOWN，不重派。 |
| FENCE | 验证旧 owner/provider 会话失效，或由所有实际派发出口强制检查可验证 fence；存储单调 token 另约束账本写入 | 两个边界都受约束并完成对账才可接管；单靠存储 fence、进程锁、超时或新 owner 自报不够。 |
| RESTORE | 校验版本、身份、同一逻辑账本、预留、游标并加载 | 缺数据、部分提交、身份冲突停止并保留证据。 |
| SYNC | 认证并建立缓冲，取得完整快照及本地日志切点，重放至水位后合并实时事件 | 范围、连续性及完整性可证明；非原子 provider 查询不冒充原子快照。 |
| RECONCILE | 以原身份查询未决订单/成交，核对账户持仓、未归属和策略账本 | 未知身份、缺口、过期或差异保持不可用。 |
| READY | 在有效 fence 和授权下恢复命令 | 持续核验 fence；失效时停止派发并保留在途 UNKNOWN。 |

09 已交付认证 ROUTER/DEALER、快照切点、重放和 ACK 最低闭环；本步验证其崩溃前后持久化边界和多进程接管。消费者将状态、去重及游标一致持久化后 ACK；ACK 丢失允许重投并去重。日志过期、缓冲溢出、epoch 重置和水位缺口重新快照/对账，不可证明则不 READY。行情 PUB/SUB 独立标记缺口，最新值不能补逐笔历史。

## 性能和多策略方案

单账户 10 策略使用一个 SDK 账户协调器与账本，兼容订阅共享上游。Gateway 跨进程传 MessagePack 字节，各进程独立解码、在进程内复用；direct 同进程安全复用对象。对同一合格事件序列、初始分配和估值政策，比较策略订单、成交、持仓、预算、费用、盈亏、未归属、通知及对账。

执行前固定输入样本及 hash、代码/依赖版本、机器/系统、Python、负载与并发、字段精度和资格校验、预热、轮次、统计方法、基线及可接受阈值。分别测构造、编码、排队/传输、解码和投影，记录 CPU、吞吐、分配、RSS、p50/p95/p99、队列深度及丢失。direct 与 Gateway 各自报告，只有合同、精度、校验和负载一致时比较；不满足标 NOT_COMPARABLE。

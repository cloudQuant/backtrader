## 2. 性能对照（`evidence/bench_wire.py`，[原始输出](evidence/perf_wire_2026-11-03.txt)）

环境：macOS arm64、Python 3.11.8、**msgpack 1.0.3（纯 Python fallback，无 C 扩展）**，7 轮取中位数。

| 指标 | 数值 |
| --- | --- |
| 消息大小 | MessagePack v1：1195 B；同字段 JSON：1217 B |
| 编码 | MessagePack v1 50.9 µs；JSON（asdict + dumps）34.9 µs |
| 解码为冻结容器 | MessagePack v1 100.9 µs（其中裸解包 61.3 µs、`MarketTickPayload` 构造校验 13.5 µs）；仅 `json.loads` 7.3 µs |
| 接收端绑定 / BT 投影 | 8.7 µs / 5.2 µs |
| 端到端（解码 + 绑定 + 投影） | 121.2 µs |
| 参照：`msgspec` 0.19.0（C）解码同一字节 | 2.25 µs（比纯 Python msgpack 快约 27 倍） |

**判定：NO-GO（性能）**。在当前环境下，MessagePack v1 没有比 JSON 更快，不能宣称“低转换带来提速”（INV-12）。瓶颈是纯 Python 解包本身。

不能直接换成 msgspec：实测它在无类型解码时**静默接受重复键**（后者覆盖前者），违反 v1 严格解码合同。建议的后续动作（需用户批准环境变更）：换装带 C 扩展的 `msgpack` wheel（它保留 `object_pairs_hook`，严格检查不变），然后重跑本基准。

第一阶段的 direct 路径性能门全部通过：CTP getter −41%、构造 −8%、Store Tick 快照快 6.7 倍（见 60.01 证据）。

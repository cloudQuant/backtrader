| 检查 | 结果 | 证据 |
| --- | --- | --- |

| 本机 CURVE ServiceHost：消费者在 sink 后 commit 前崩溃，重启后同 ID 重达，ACK 后不再投递 | PASS | INTEGRATION_SIM |
| 变异：去掉“前一进程”判定或事实 ID 跳过，对应测试失败 | PASS | — |

OPEN（及原因）：

- 仍为至少一次的窗口（与 direct G3 一致，非恰好一次）：回调已运行但通知日志 ACK 丢失时，以原 `notification_id` 重放一次；订单通知已写日志而 Trade 未写日志即崩溃时只重放订单，重建订单后的 Trade 只含重启后的成交（`executed.exbits` 历史不重建）。Broker 内存 `Position` 不重建（持久持仓以账本为准）。
- Gateway 成交观察不含费用事实（Base 合同如此）：按无费用的 direct 成交处理（`commission_source="unavailable"`）；迟到费用更正在 Gateway 模式无 producer。
- 终态订单在重启后不重建，其迟到成交只计数（`orphaned`）。
- 内置 provider（OKX/Binance/CTP）尚未实现 `read_execution_observations`/`confirm_execution_observations`；只有本地 fake provider。策略归属依赖 client order id 前缀配置；Gateway 命令路由生成 client order id 的接线不在本包。
- BT 崩溃测试使用同进程 `GatewayReadService`（`over_call`）而非 ZMQ；ZMQ 路径由 SDK 本机 CURVE Host 测试单独覆盖。真实部署 NOT_RUN。

## 9. R3：Gateway 成交费用与费用更正、策略 client order id 前缀（2026-11-04）

本节只记录源码与本地测试进展，不是验收结论。证据等级：UNIT/FAKE 与 INTEGRATION_SIM（本地 SQLite、同进程 co-located 读服务）；真实 provider 与 Gateway 部署 NOT_RUN。

- **成交带费用**：provider 提供费用时，Gateway 成交观察携带该笔成交的 `fee`/`fee_currency`（Base 执行事件 v2）。同一笔成交（合约 + trade_id）费用升高时为新事件（费用更正）；同值为重复；降低 `EXECUTION_FEE_REGRESSED`、换币种 `EXECUTION_FEE_CURRENCY_CONFLICT`，在追加事务内拒绝且不写入（provider 保留并重发）。每笔成交的已记录费用持久化在新表 `gateway_execution_trade_fees`（`CREATE TABLE IF NOT EXISTS`，旧库自动建表）。
- **BT 费用更正**：`_btapi_gateway_events.trade_update_row` 把费用写成与 direct 相同的 `fee`/`fee_currency`/`fee_unit` 行；更正事件经 direct 的重复成交费用路径触发 `notify_fee_correction`，账本按币种累计。BT `tests/integration/test_iter60_gateway_fee_corrections.py`（2 项）：direct 与 Gateway 的 `notify_fee_correction`（差额 0.3 CNY）、通知序列、持仓与账本手续费（1.3 CNY）完全一致；更低费用被 Gateway producer 拒绝。上一进程的终态订单不重建，重启后才到达的费用更正只计为 orphaned（与 §8 一致）。
- **策略归属前缀**：`GatewayExecutionScopePolicy.for_strategies({strategy_ref: stream})` 用 Base `strategy_client_order_prefix` 生成路由前缀。Risk `account_owner` 选项 `strategy_client_order_prefix: true` 使该 owner 生成的 provider client order id 为“策略前缀 + 35 位摘要”（长度与原 `risk-` + 40 位相同；默认不变）。SDK 测试：策略 A 的 Risk 生成 client id 的订单观察只进入 A 的执行流，B 的只进 B，默认 `risk-` 前缀的不归属。Execution `account_owner` 的 provider 适配器自行生成 client id，本轮未改。
- **检查**：Gateway 全量 **499 passed**（新增 `tests/test_iter60_execution_fee_events.py` 2 项）；transport 92 passed。
- **OPEN**：内置 provider（OKX/Binance/CTP）仍未实现 `read_execution_observations`，费用字段只有 fake provider 产生；Gateway 下单命令路由（`GatewayCommandRouter`）本身不生成 client id，前缀仅在 Risk owner 侧生成。

## 10. 验收后修复：重启后才到达的 Gateway 费用更正（2026-11-04）

本节只记录源码与本地测试进展，不是验收结论。证据等级：UNIT/FAKE 与 INTEGRATION_SIM（spawn 子进程 `os._exit`、临时 SQLite、同进程 co-located 读服务）；真实 provider 与 Gateway 部署 NOT_RUN。

- **关闭 §8/§9 记录的缺口**：上一进程终态订单的成交在重启后收到费用更正时，不再只计 orphaned：`_apply_gateway_trade` 先交给通知日志的已应用成交索引（`_apply_durable_fill_fee`，见 06 §8），账本费用按币种累计入账一次，Strategy 收到一次 `notify_fee_correction`（只读 `RecoveredOrder`/`RecoveredTrade`，`replayed=False`）和一次修正后的 `notify_order`，日志先写后投递、回调后 ACK、崩溃重放。事实记录 outcome 为 `fee_corrected`/`ignored`/`fee_fenced`，计数分别记入 `applied`/`skipped`/新增的 `fenced`。索引不认识的成交（及此类订单的新成交）仍计 orphaned。
- **修复新发现的缺陷**：重建的未终态订单收到上一进程成交的费用更正时被当成第二笔成交（伪造成交，持仓错误）；重建订单未恢复 `provider_fee_totals`，之后带费成交的累计费用从 0 起算。现在订单记录保存 `provider_fee_totals`、`fee_corrections`、`fee_corrections_journaled` 等费用状态，每个已应用成交（成交事实 → 数量、价格、已记费用、币种）与事实记录在同一事务写入新表 `order_fills`（`CREATE TABLE IF NOT EXISTS`，旧库自动建表；订单记录变为终态时删除其行）。重建时恢复这些成交到 `_seen_trade_ids`/`_applied_fill_fees`，并把已投递的更正序号同步给 Strategy，所以更正走 live 重复成交路径（不重复回调、不伪造成交），后续成交按账本已有累计费用继续。崩溃后重读的已应用未记录事件仍在同一持久状态上重放，生成相同通知 id（R2-C 语义不变）；费用更正条目按 id 去重时保留首次快照。
- **降低或换币种**：Gateway producer 在追加事务内拒绝（`EXECUTION_FEE_REGRESSED`/`EXECUTION_FEE_CURRENCY_CONFLICT`），重启后同样如此，BT 状态不变（已测试）。
- **测试**：`tests/integration/test_iter60_restart_fee_corrections.py` 的 Gateway 参数项（终态、未终态、重复、已写日志未记录事实即崩溃（终态与重建的未终态订单）、producer 拒绝、日志后回调前崩溃、账本后日志前崩溃）与 direct 对等；`test_iter60_gateway_notifications_crash.py` 的崩溃注入点改为包装 `journal.append_many`（`append` 现委托给它），断言不变。
- **OPEN**：内置 provider（OKX/Binance/CTP）仍无执行观察与费用字段，只有 fake provider；重建的未终态订单收到更正时 `trade` 为本进程中该订单更新过的 Trade，否则为 `None`（上一进程的 Trade 不重建）。

# 60.09 Gateway 数据与策略接入——交付说明

状态：**实施完成（行情路径）；本步检查已执行；用户审阅 PENDING**。[总计划](../迭代计划.md) · [公约](../_公共约定.md)

## 1. 范围

按 D60-04，旧 Gateway/transport 只作参考（盘点见 60.01 §4）。本步在既有的 CURVE 认证 PUB/SUB 行情通道上接入 MessagePack v1，打通 **Gateway 发布 → 接收进程解码一次 → 接收端 SDK 绑定 → BT adapter** 这条行情链路，并验证它与 direct 路径对等。账户事件日志、命令路由、远程策略视图沿用既有实现，**本步没有改动**。

## 2. 变更

| 仓库 / 提交 | 变更 |

| `bt_api_transport_zmq` `a02e4c2` | 新增行情 wire version 3：topic 帧 + `wire_codec_v1` 消息体。`try_publish_container()` 编码一次；`receive_container()` 解码一次，得到冻结容器。v3 使用独立的 topic 前缀，与 v2 端互不匹配；消息自带的 `stream_id` 必须与订阅一致，否则丢弃；v3 上拒绝旧的信封 API，v1/v2 上拒绝容器 API。新增 `ContainerSequenceMonitor`：每个消费者独立报告 `FIRST`/`IN_ORDER`/`GAP`/`DUPLICATE`/`NEW_EPOCH`。 |

| 项目 | 本轮实现 | 证据等级与剩余边界 |
| --- | --- | --- |
| 撤权识别 | Gateway 服务接线把 `market.head`／`market.snapshot`／`market.read_after(_bounded)` 上的 `MARKET_KEY_DENIED`（与 subscribe 相同）映射为确定性拒绝，registry 对这些只读操作返回 `SCOPE_DENIED`（原来是不可区分的 `HANDLER_FAILED`）。`ServiceMarketClient` 接受 `authorization_floor` 缺口回复（同 epoch、无事件）。 | SDK `service_components.py`、`service_registry.py`（各一处局部改动）、`service_market.py` |
| 中断 | 拒绝或下限缺口时客户端进入显式中断 `authorization_interrupted`（`MARKET_KEY_DENIED`／`AUTHORIZATION_FLOOR`）：丢弃已缓冲事件、调用接收端 `revoke`（`ZmqMarketSubscriber` 丢弃旧授权帧）、`healthy=False`、`recovery_required=True`、`source_descriptor=None`；`poll`／`drain`／`recover`／`accept_resync` 均抛 `MARKET_AUTHORIZATION_INTERRUPTED`。投影与 BT 行情经 `healthy` 传播为不健康，不会把旧数据当实时（未改 BT `btapifeed.py`）。 | UNIT/FAKE |

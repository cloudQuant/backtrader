## 范围与需求

- 从新合同实现 Gateway 市场、账户与策略视图转发及命令路由；同账户多个策略复用 SDK 单一权威账本。
- 兼容的同合约行情订阅共享上游；每个消费者有独立权限、生命周期和缺口状态。
- 选中 Gateway 失败不得静默切回 direct；不沿用或核查旧 Gateway 实现作为完成依据。

## 完成边界

- 仅交付本步涉及的合同、源码或盘点及引用清单；跨入下一步的能力不得提前声称完成。
- 形成本步交付、兼容/破坏性变化、未决事项和可审阅证据；用户审阅并明确同意后才进入下一步。

## 输入、输出与责任

| 输入 | 输出 | owner |
| --- | --- | --- |
| provider 经服务端 SDK 规范化的行情和账户观察 | 授权范围内行情、账户快照/事件及策略视图 | provider 管原生事实；SDK 管来源、会话、账户协调和唯一策略账本；Gateway 管订阅及账户路由。 |
| 客户端身份、策略绑定、订阅及订单/撤单 | 许可范围数据、命令结果或拒绝/UNKNOWN | 可信宿主注入身份与准入；transport 管认证收发；BT 管 Feed、Broker 和通知。 |
| 08 schema 与 codec | 字节和接收端标准容器 | 可选 codec 共享；每个进程独立解码，不能跨进程共享对象。 |

G09-1：单账户 10 策略订阅同一合约，频道、粒度及权限兼容时共用一次上游订阅；各消费者独立生命周期和缺口状态。G09-2：账户及策略视图隔离，SDK 维护唯一账本，Gateway 不复制记账算法。G09-3：本步交付并验证认证命令及账户快照一致切点、重放、ACK 和缺口处理的最低闭环；行情 PUB/SUB 允许丢失并标明不完整。G09-4：显式选中 Gateway 失败不可回退 direct；direct 不要求 Gateway、ZMQ、codec。连接、topic、回执和 ACK 均不证明授权或交易所结果。

G09-5：Gateway 和 ZMQ transport 分层与重构工作按[架构调研及重构设计](Gateway与ZMQ架构调研及重构设计.md)实施；具体旧接口和数据迁移状态尚未检查。G09-6：按可信授权范围进行发布端隔离，未授权端不能接收或解密；单靠客户端 topic 过滤不满足要求。G09-7：日志/状态快照及切点的一致性、容量、保留和过期策略明确；不可证明切点时恢复视图不可用。

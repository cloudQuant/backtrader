# 迭代60《统一行情容器与低转换数据链路》计划复核报告

- 审阅日期：2026-11-02
- 审阅对象：[总迭代计划](迭代计划.md)、60.01–60.10 子计划，以及与发现直接相关的 06/08/09/10 设计文档。
- 审阅方式：静态计划审阅与跨文档一致性检查；未读取或覆盖同目录已有的 `审阅报告-2026-11-02.md`。
- 当前状态：计划为 `NOT_STARTED`，验证为 `NOT_RUN`；本次没有修改产品代码、执行真实调用或运行测试。

## 一、结论

计划已经清楚表达了许多重要边界：Gateway 可选且故障不静默回退、direct 不强制依赖可选组件、UNKNOWN 不换身份重发、存储 fence 不等于派发 fence、账户快照不自动产生逐笔成交、策略账本不复制真实账户余额，以及各步骤须经用户审阅。这些不变量应保留。

当前主要问题不是缺少安全口号，而是**部分关键合同尚未落到可执行的状态机、负向验收和变更控制中**。尤其是迭代53治理冲突、策略 run 代际、通知/ACK 崩溃窗口、持久格式迁移、滚动升级、跨进程证明强度、孤儿订阅回收和能力解锁时点。建议先补这些内容，再将总计划收敛为导航、命名不变量和追踪索引，详细设计由各子文档单源持有。

## 三、边界路径与恢复场景缺口

| 编号 | 位置 | 未闭合路径 | 应补合同或验收 | 可能后果 |
|---|---|---|---|---|
| E01 | 60.08 十进制字段 | 指数、NaN、Infinity、负零或非规范尾零进入编码/比较。 | 冻结文法、范围及规范化规则，拒绝非有限值后再比较和编码。 | 等价命令判断不一致，非法数值入账。 |
| E02 | 60.08 解码 | 首个合法对象后仍有尾随字节。 | exact decode 要求游标恰好到帧尾，否则拒绝整条消息。 | 拼接对象被忽略，消息边界被破坏。 |
| E03 | 60.08 扩展注册 | 双方版本相同但扩展注册表或关键字段表不同。 | 握手校验 schema、扩展注册表和关键性表摘要，不一致则拒绝连接。 | 同版本消息被赋予不同语义。 |
| E04 | 总计划 §8.3 | sequence 达到编码上限或在同 epoch 回绕。 | 固定位宽与初值；耗尽前原子切换 epoch 并重新同步，禁止同代回绕。 | 回绕被误判重放或缺口。 |
| E05 | 60.09 topic + envelope | 合法 envelope 被发布到不匹配的 topic/分区。 | 接收端重算 topic、授权 scope 与 stream 绑定，不匹配即拒绝并重新同步。 | 其他流数据写入当前消费状态。 |
| E06 | Gateway 行情接管 | 新发布者接管后旧发布者仍可发送。 | 每个 stream 强制发布者 fence；接管更换 epoch，订阅端拒绝旧代际。 | 双发布者复用序号，错误去重或漏报缺口。 |
| E07 | 60.10 ACK | 旧连接/旧 epoch 的 ACK 晚于新 ACK 到达。 | ACK 绑定消费者、run、epoch 和游标；服务端只持久化单调进度并拒绝旧代际。 | 进度回退或跨代误确认。 |
| E08 | 60.09 账户日志 | 消费者长期不 ACK，日志达到容量或保留上限。 | 跟踪逐消费者未确认游标；隔离滞后者并停止其推进，不静默删除未确认事件或阻塞他人。 | 日志无法压缩，或未确认事件提前消失。 |
| E09 | 60.05 成交先于订单 | 有界暂存区被填满。 | 暂存满时持久化隔离并停止相关游标推进，触发对账；禁止丢弃或 ACK。 | 已确认成交丢失，策略持仓永久少记。 |
| E10 | 60.06 命令绑定与预留 | 进程在绑定与仓位/预算预留之间崩溃。 | 同一持久事务写入命令绑定、派发状态和全部预留；恢复拒绝孤立记录。 | 预留泄漏或可平量被重复使用。 |
| E11 | 60.06 去重保留 | 去重记录早于可重放日志或迟到成交期限被清理。 | 去重保留覆盖最大重放/迟到窗口；不足时拒绝旧游标重放并先对账。 | 历史 fill 再次入账。 |
| E12 | 策略重启接管 | 旧 run_id 进程仍存活并发命令。 | 持久化 active-run 代际；命令、订阅和 ACK 均 fence 旧 run。 | 新旧策略实例并发交易。 |
| E13 | 60.10 切换状态机 | 在 FENCE 后或 RESTORE/SYNC/RECONCILE 中途崩溃。 | 持久化切换状态和 owner 代际，逐提交点幂等恢复，并在每阶段前后注入崩溃。 | 接管卡死或新旧 owner 同时恢复派发。 |
| E14 | direct/Gateway 多宿主 | 同一真实账户通过不同 route 或宿主别名同时接入。 | 以 provider 验证的账户及环境身份建立唯一协调/派发 fence；别名不能确定唯一时拒绝。 | 多 owner 独立预留派发，账户被超额使用。 |

## 六、建议补入计划的执行脚手架

### 6.1 60.01 集中决策登记表

每项决策至少包含：

| 字段 | 要求 |
|---|---|
| 决策 ID 与问题 | 使用稳定 ID，后续步骤只引用，不重复改写结论。 |
| owner 与阻塞步骤 | 明确由哪个仓库/角色决定，以及哪些步骤不得提前实施。 |
| 选项与证据 | 区分源码事实、用户选择、目标设计和未验证假设。 |
| 状态与结论 | `OPEN / DECIDED / BLOCKED / REOPENED`，附用户审阅记录。 |
| 失效范围 | 结论变化时列出需要重开的需求、设计、代码、测试和性能证据。 |

### 6.2 按能力设置解锁状态

不要用单一“步骤07完成”推断全部能力可用。至少分别维护：

- direct 行情、direct 单策略订单、策略归属账本、策略预算视图、Gateway 行情、Gateway 命令、多进程接管和真实多策略交易。
- 每项状态明确为 `PLANNED / CONTROLLED_ONLY / READY_FOR_AUTHORIZED_VALIDATION / ACCEPTED_FOR_DECLARED_SCOPE`。
- 解锁证据必须绑定 provider、账户环境、版本、部署形态和授权范围；模拟与 fake 证据不能解锁真实账户能力。

### 6.3 各步骤需要补强的出口门

| 步骤 | 应补出口条件 |
|---|---|
| 60.01 | 迭代53治理冲突有用户结论；Gateway/transport 只读现状盘点；集中决策表和早期性能门建立。 |
| 60.02 | 对象发布前完成初始化、发布后不可变；direct/Gateway 使用相同精度语义；容器局部分配基准完成。 |
| 60.03–04 | Bar revision/迟到政策闭合；多 Feed、minperiod、runonce 与策略回归通过；局部性能无未解释回退。 |
| 60.05 | 成交先于订单的暂存溢出、通知投递语义、命令过载和持久化失败行为明确。 |
| 60.06 | active-run fence、绑定+预留原子性、存储迁移、去重保留和通知/ACK 崩溃窗口闭合。 |
| 60.07 | 策略 API 全消费者范围一致；保持 `CONTROLLED_ONLY`，不因本步完成自动解锁真实多策略交易。 |
| 60.08 | 严格十进制与 exact decode、命令语义指纹、扩展注册摘要、混合版本和 codec 局部基准完成。 |
| 60.09 | 09-A 只验证已审定合同；对象级授权负例、孤儿订阅回收、发布者 fence、ACK 代际和日志保留闭合。 |
| 60.10 | 切换状态自身可恢复；安全故障注入覆盖各提交点；按能力/provider/授权明确解锁，最终端到端性能对照完成。 |

## 七、建议保留的现有设计

审阅不建议重写全部计划。以下内容已经具有明确价值，应在压缩和单源化时保留：

1. direct 与 Gateway 的可选依赖和禁止静默回退。
2. 容器字段、对象引用、来源证明和交易授权相互独立。
3. UNKNOWN 保留原身份查询，不因网络超时换 ID 重发。
4. 账本写入与真实派发两个独立 fence，存储 token 不单独授权接管。
5. 快照、事件、游标、去重和 ACK 的不同语义，以及 PUB/SUB 不保证可靠逐笔历史。
6. 策略账本与真实账户视图分离，未归属、外部成交和差异不得自动分摊。
7. 逐步用户审阅、`NOT_RUN`/阻塞状态及真实账户另行授权。
8. 性能比较要求相同合同、精度和校验强度，不预先宣称“低转换”必然带来收益。

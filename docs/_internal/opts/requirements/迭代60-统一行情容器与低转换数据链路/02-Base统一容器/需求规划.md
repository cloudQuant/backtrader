## 范围与需求

- 为行情、订单、逐笔成交、真实持仓及账户/策略视图确定中立字段、类型、单位和可缺失性；统一或迁移已有 DTO。
- 支持场所子类扩展、稳定对象生命周期与独立来源绑定，不因继承即认定所有 provider 已一致。
- 保留 Python/依赖版本与既有公开接口的兼容决策，direct 不加载跨进程 codec。

## 完成边界

- 仅交付本步涉及的合同、源码或盘点及引用清单；跨入下一步的能力不得提前声称完成。
- 形成本步交付、兼容/破坏性变化、未决事项和可审阅证据；用户审阅并明确同意后才进入下一步。

## 字段与交付合同

步骤 01 决策经用户确认后，Base owner 对现有合同去重或兼容演进；逐字段冻结类型、单位、作用域、缺失/零、精度、来源角色及版本。至少覆盖：

| 类型 | 待冻结的最小语义 |
| --- | --- |
| Tick/Ticker | route、品种、事件/接收时间、最新价、买卖价量、逐笔增量及累计成交量；单位与未知值。 |
| Bar | 品种、周期、起止、OHLC、量、完成状态及来源；历史/实时、精度和空 bar 行为。 |
| 订单观察 | 账户、品种、客户端/场所订单 ID、方向/开平、类型、状态、委托/累计量、价格与观察时间。 |
| 逐笔 fill | 账户、订单与成交 ID、方向/开平、单笔量、价格、费用与币种、成交时间；不可混同累计量。 |
| 真实持仓 | 账户、品种、净方向或多空腿、数量/单位、均价、今昨仓、观察时间及完整性。 |
| 账户/策略视图 | 真实账户作用域、策略身份、预算、估值/币种、持仓归属、未知及完整性分别表达；预算不是账户现金。 |

场所扩展与冲突规则、发布后稳定性、惰性初始化、原始输入和嵌套数据所有权均须明确；缺失事实不填零。容器不持有账本、不签发来源证明或授权，direct 不依赖 Gateway、ZMQ、codec、execution。

旧构造器、getter、属性、导出、子类和 `get_all_data` 须逐项登记调用者、兼容决定、迁移措施和退役前置；破坏变更单独审阅。provider 字段能力未核实、版本/精度和扩展策略未定等均列 owner、影响、关闭条件，未决合同不得当成事实。

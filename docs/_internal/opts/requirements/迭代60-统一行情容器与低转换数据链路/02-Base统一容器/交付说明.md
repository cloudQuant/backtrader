## 1. 范围

本步落实 D60-11、D60-12、D60-13，建立 **Base 容器合同 v1**：

- 第一阶段的统一合同由两部分组成：**provider 容器**（`TickerData`/`BarData`/`OrderData`/`TradeData`/`PositionData` 及其子类）的标准 getter 与语义词表；**已有的不可变发布合同**（Tick 为 `MarketTickPayload`/`MarketTickEvent`），不另建平行类型（D60-14）。
- 不改变 Bar 数据流、账户/策略视图和 MessagePack 编码（分别属于后续步骤或第二、三阶段）。

## 3. 设计决定与理由

- **为什么不在运行时强制冻结**：`__setattr__` 拦截让 CTP Tick 构造慢 451%～534%（见 [性能证据](../01-基线盘点与合同决策/evidence/perf_results_2026-11-02.txt)），NO-GO。冻结以标记 + 测试指纹验证。
- **为什么保留 `AutoInitMixin`**：CTP `quote_v2_provenance.py` 用 `type(item) is CtpTickerData` 判断类型，“初始化后换类”的加速方案会破坏它。
- **为什么语义 getter 有默认值而基类其他 getter 仍抛 `NotImplementedError`**：语义 getter 是 v1 新增的可选事实，所有 provider 都必须能回答；原有抽象 getter 保持不变以免改变基类契约，provider 侧补全见 60.04/60.05。

## 5. 兼容性

- 公开 API 只增不删。`get_all_data()` 返回副本：调用者若曾依赖“修改返回值会写回容器”，行为会改变；在三个 provider 和 SDK 中未发现这种用法。
- `_initialized` 的置位时机从“`init_data()` 之前”改为“成功之后”。provider 在 `init_data()` 内自行置位的写法仍兼容。

## 评审修订补充（2026-11-02）

以下要求来自总计划修订，与上文冲突时以此为准；术语和通用规则见[公约](../_公共约定.md)。

- codec 候选按其实际版本的发行元数据评估 Python 下限（例如本机 `msgspec 0.19.0` 为 `>=3.9`），不引用文档口径；Base 核心不无条件依赖 codec（D60-09）。
- 十进制文法冻结：拒绝 NaN/Infinity；规定负零、指数、前导零、尾零的规范化与等价；逐字段范围和最大有效位，超限在解析前拒绝。
- 严格解码：恰好一个完整对象，拒绝尾随字节、拼接对象、重复键、非字符串键、非法 UTF-8 和未登记 ext 类型。
- 命令语义指纹：覆盖账户、route、策略、命令类型及全部业务参数的规范化值；等价表示不冲突。
- 握手校验 schema 版本、扩展注册表和关键字段表摘要；`sequence` 固定位宽，耗尽前切换 epoch，禁止同代回绕。
- 影响资格判断的字段（D60-11）在任何解码形态下不得丢弃；`managed_paper_fill.v2` 是否进入类别表按 D60-14。
- 混合版本矩阵与 codec 局部性能门。

## 职责与实现设计

- Base 持有传输无关的数据和版本合同，可选共享 codec 提供受控类型注册；兼容 Python 版本由实际可安装矩阵确定。
- v1 使用具名字段 map 和版本、kind、stream/epoch/sequence、来源/时间、业务数据；十进制值按约定字符串编码，不从浮点承诺恢复原始精度。
- 限制大小与深度，不使用 pickle 或动态导入消息中的类路径；unknown major、关键字段及未知/零按合同处理。

## 消息边界

```text
{schema_id, major, minor, kind,
 stream: {stream_id, epoch, sequence}, source, event_time, receive_time,
 data: 标准合同字段与明确命名的场所扩展}
```

以上为结构示意，具体键、时钟精度及扩展兼容规则须在实施中确定。编码在跨进程发布侧发生，接收侧经受控注册解码成标准容器；每个进程分别解码。业务字段、来源绑定与消费进度各有 owner，消息中的自报字段不构成来源证明或授权。

## 版本和逐类别 schema 草案

| 类别 | 必需语义 | 特别约束 |
| --- | --- | --- |
| Tick | 合约、频道、价格、量、事件/接收时间及质量 | 增量、累计和 24 小时量分开，缺失不补零。 |
| Bar | 合约、周期、起止、OHLCV、完成状态 | 历史/实时、已完成/未完成及时间边界明确。 |
| Order | 账户/route、合约、订单身份、方向、状态、委托量及累计成交 | 观察不等于确认终态，缺失身份不可猜。 |
| Fill | 账户、订单/成交 ID、单笔数量、价格、时间、费用及币种 | 单笔量与累计分开，身份作用域决定去重。 |
| Position | 账户、合约、净仓或多空腿、数量/单位、观测时间和完整性 | 未知或不完整不能变成零；今昨仓按可用性声明。 |
| 账户/策略视图 | 范围、完整性、观察时间及定义过的预算、余额和盈亏 | 未知估值不可伪造，真实账户与策略归属分开。 |
| 命令/结果 | 稳定请求 ID、账户/策略绑定、操作、参数、状态 | 请求/回执/交易所事实分别编码，超时 UNKNOWN。 |

公共 envelope 使用 `schema_id`、非负 `major/minor`、已登记 `kind`、`stream {stream_id, epoch, sequence}`、`source`、事件/接收时间及 `data`；非流请求明确流字段不适用。来源字段只为声明，授权和来源绑定由宿主/SDK 验证。时间按 UTC epoch 纳秒及源精度表达；原生浮点不能声称恢复原始十进制精度。实际键、必需字段及限制值在实现前与 02–07 审阅结果冻结。

解码先检查总字节上限，执行有界解析、重复 map 键及 UTF-8 校验，再检查 schema/版本、范围和字段关键性；只用受控注册表构造容器。标准字段不得被 provider 命名空间扩展覆盖。未知 major/kind 或关键字段、超限及畸形输入返回明确错误，无部分可信对象；库若不能在解析期保证限制须增加有界保护或不选用。minor 保留/忽略规则和前后版本样本集中维护。编码/解码失败不触发 direct 回退。

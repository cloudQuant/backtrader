# 60.08 MessagePack 合同与编码——交付说明

状态：**实施完成（Tick、Bar 两类消息）；本步检查已执行；用户审阅 PENDING**。[总计划](../迭代计划.md) · [公约](../_公共约定.md)

## 1. 变更（`bt_api_base` 提交 `e7f4907`，`src/bt_api_base/wire_codec_v1.py`）

| 合同项（计划 §8.2） | 实现 |
| --- | --- |
| 唯一业务合同 | 编码对象就是 Base 已有的冻结容器（`MarketTickPayload`、`MarketBar`），解码端一次重建出同一类型的冻结对象，不另建 Gateway 专用类型。 |
| 信封 | `schema_id`（`bt_api.wire.v1`）、`major`、`minor`、`kind`、`stream{stream_id, epoch, sequence}`、`data`，外加可选的 `ext`（按 provider 命名空间，键名受限，值只能是标量）。 |
| 数值 | 十进制字符串，规范文法：无指数、无 NaN/Inf、无 `-0`、无前导零、小数部分无尾零、最多 40 个字符；消息中任何位置出现二进制浮点一律拒绝；整数限于有符号 64 位。浮点值经 `repr` 转十进制后往返无损（对等测试已验证）。 |
| 缺失与未知 | `None` 原样传输；未知的增量、资格字段等跨进程后仍为未知。 |
| 严格解码 | 只接受恰好一个完整对象（拒绝尾随字节、拼接对象），只允许文本键、拒绝重复键、拒绝扩展类型，限制消息字节数（64 KiB）、嵌套深度（8）、容器长度（256）和字符串长度。 |
| 版本演进 | 未知 `major` 拒绝；`minor` 高于接收端支持版本时拒绝；未知的信封字段或数据字段一律拒绝（不静默忽略）。 |
| 握手 | `schema_digest()`：对 kind 注册表、字段表、十进制字段和枚举取摘要，两端版本号相同但字段表不同时可在建连时发现。 |
| 命令身份 | `command_fingerprint()`：语义指纹。键顺序、可选字段“缺省”与“为 None”、数值字段的等价写法（`"1.50"`、`1.5`、`Decimal("1.5")`）视为相同；标识符类字符串（如 `"007"` 和 `"7"`）逐字比较；账户、策略、数量等任一变化都会改变指纹。 |
| direct 不依赖 | `msgpack` 只在编码/解码函数内部延迟导入；测试在子进程中验证：仅导入合同模块不会加载 `msgpack`（INV-01）。 |

## 3. 范围外与残留

- 订单、成交、持仓、账户和命令的 v1 消息类别**没有实现**：第三阶段只做到行情路径（Tick、Bar）。账户与命令通道仍是既有的 JSON `WireEnvelope` + CURVE ROUTER/DEALER。
- 编解码后端的性能结论见 60.10：本机 `msgpack` 1.0.3 是纯 Python 实现，性能不达标（NO-GO）。

## 3. 逐项判定（60.03-R1～R6）

| 需求 | 结果 |
| --- | --- |
| R1 迁移前基线 | 8 项基线测试固定了 `adapt_market_tick_event` 的现有投影：字段 1:1 复制、`volume` 为增量而非累计、未知增量保持 `None` 且 `bar_eligible=False`、质量标记导致 `INVALID`、STALE 被拒、非事件输入被拒、修改投影结果不影响原事件。另记录 Base 合同本身拒绝“STALE 但可交易”的载荷。 |
| R2 资格字段对应关系 | 三处赋值已画清：容器构造与 `apply_volume_delta()` 均置 `execution_eligible=False`；`market_tick_projection` 要求输入为 `False`；只有 `quote_v2_projection.py:181` 在 `evidence_complete and parent_attested` 时置 `True`。BT adapter 原样传递 `MarketTickEvent.data.execution_eligible`。 |
| R3 增量只算一次 | 满足：转换只在 `live_ctp_feed` 的 `_volume_tracker` 中、发布点之前。 |
| R4 `_tick_value` 默认值 | 已审计（60.01 §2.4）：两处“未知当合格”只影响旧 dict 路径，SDK typed 路径不受影响；本阶段不改，登记为残留风险。 |
| R5 两次复制 | 两处都改为结构共享快照，而不是删除：快照仍与源对象互相独立（测试覆盖双向修改）。`get_latest_tick_snapshot()` 在 BT 内部没有调用方，是对外公开的读取接口；`_latest_ticks` 在 BT 内部只会被 `store_lifecycle` 清空。外部调用者拿到的仍是与 Store 状态互相独立的副本。 |
| R6 策略回归 | 见 §4。 |

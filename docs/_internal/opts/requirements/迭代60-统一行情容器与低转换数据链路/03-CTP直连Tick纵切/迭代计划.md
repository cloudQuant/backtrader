# 迭代 60.03：CTP 直连 Tick 纵切

状态：**NOT_STARTED；验证 NOT_RUN；用户步骤审阅 PENDING**。[总计划](../迭代计划.md) · [需求](需求规划.md) · [设计](设计文档.md) · [验收](验收文档.md)

## 依赖、owner 与输出

前置为步骤 02 合同及兼容决策经用户明确审阅；输入为公开 CTP 样本、现有 direct 源码和来源/时钟合同。CTP provider 负责原生映射；SDK 负责会话、绑定和队列；BT 负责 Store/Feed、数据线及通知。输出跨仓变更、字段及旧接口迁移表、复制记录、离线案例和未闭合来源风险。

## 工作顺序

1. 核对各仓 checkout、dirty、调用者及 01 固定的性能口径，绘制单 Tick 字段和来源绑定链。
2. provider 实施原生映射，区分时间、交易日、累计和增量；缺失保持未知。
3. SDK 接入标准对象并保留会话、来源、时钟、代际和序列校验；BT 适配 Store/Feed，独立维护消费者状态。
4. 验证合法/缺证据/多消费者/异常及无可选依赖；只有隔离和历史快照得到证明后才移除相应复制。
5. 汇总仓库版本、兼容差异、测试和不可用项交用户审阅；必需检查未完成保持 `BLOCKED/NOT_RUN`，明确同意后才进入 04。

本步不执行真实账户调用；合成 Tick 不证明来源时钟、实盘、Bar 或交易能力。

补充：在 SDK 完成相应来源和质量判定后预留只读行情观察接点；未选 Monitor 时无需安装或调用，监控事件不修改容器或改变行情资格。

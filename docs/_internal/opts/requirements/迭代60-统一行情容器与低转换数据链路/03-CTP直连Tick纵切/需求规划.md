## 范围与需求

- 以 CTP 单 Tick 贯通 provider → SDK → BT Feed → 策略通知与数据线，direct 不经 Gateway。
- 保留时间、累计量与实际来源资格；只消除经证实不必要的复制与转换。
- 不可证明的源时钟、新鲜度或实盘资格必须明确不可用。

## 可观察行为与边界

输入为步骤 02 已审阅 Tick 合同和 CTP 公开原生字段；目标为受控 direct 链：CTP provider 解析 → SDK 路由、会话、来源和序列校验 → BT Store → Feed → 策略 Tick 通知与数据线。交付字段映射、各层改动、调用者迁移、隔离案例和对象复用证据；不扩展 Bar、其他场所或交易操作。

分别映射原生时间、交易日/行动日和累计量；无可靠增量时保持未知。保留订阅、时钟资格、来源、连接代际、顺序及消费状态；容器或自报字段不能证明来源，不可证明的时钟/新鲜度保持不可用。BT 数据线和 Feed 本地质量状态由 BT 持有；回调顺序、数值及异常按批准合同执行。

逐项盘点 `MarketTickEvent`、`MarketTickPayload`、`market_tick_adapter`、`poll_tick` 深拷贝及旧调用者；不得为减少复制绕过原有证明、精确类型检查和独立状态。仅在发布对象、嵌套数据、消费者隔离及通知快照稳定后移除具体复制。direct 未安装 Gateway、ZMQ、codec 或 execution 时仍能运行。

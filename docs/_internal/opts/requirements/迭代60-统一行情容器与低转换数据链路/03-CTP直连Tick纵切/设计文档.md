## 职责与实现设计

- provider 按合同解析原生字段，SDK 绑定 route、会话、来源/流与序列，Feed 负责数据线和本地状态。
- 针对 market_tick_adapter、MarketTickEvent、poll_tick 深拷贝登记迁移与消费者；保持鉴权、时钟和消费状态，先证明对象安全才修改。
- 相同进程共享稳定引用；BT 数据线赋值、订阅隔离和必要的状态快照仍保留。

## 数据流与职责

| 环节 | 输入与输出 | owner / 检查 |
| --- | --- | --- |
| CTP provider | 原生 Tick → 标准 Tick 和扩展 | 映射品种、价格、买卖、时间及累计量；未知增量保留未知。 |
| SDK direct | 容器及独立来源/会话绑定 → 已校验消费事件 | 校验 route、订阅、代际、来源与连续性；业务载体本身不证明来源。 |
| BT Store | 已校验事件 → 有界投递 | 管理订阅、实例及队列生命周期，记录丢弃/缺口；不改变资格。 |
| BT Feed | 事件 → 通知与数据线 | 保存本地时间/质量/序列状态，按合同投影数值与回调顺序；保留必要快照。 |
| Strategy | Feed 通知和线值 | 按已批准接口观察，不能修改共享数据影响其他消费者。 |

具体字段/方法依据 01 盘点和 02 冻结合同落实；以上为目标。原有证明、token、精确类型校验和封印逐项映射；缺少等价绑定时保留旧载体或阻塞迁移，不能以宽泛类型检查替代。

## 生命周期、失败和迁移

原生回调缓冲须在复用前隔离，标准对象发布后保持稳定；两个订阅独立保存游标、断线代际和投递状态。慢消费者、满队列、重复/乱序、旧代际与退订后回调按批准合同处理且可观察，不伪造连续性。事件时间缺失或不可证明时不补造成可信时间或实时资格。

adapter、payload/event、`poll_tick` 各建立 `旧入口/调用者/保留校验/新入口/快照需求/退役条件` 表。按 01 预先固定的口径记录构造与复制次数；先验证变异、多消费者、通知历史和线程生命周期，再决定保留、适配或删除。direct 的依赖在隔离环境验证，不启动 Gateway、execution 或外部账户。

## 2. 链路与字段盘点（60.01-R3、R4）

### 2.1 Tick 链路（direct）

```text
CTP 原生回调 → live_ctp_feed: CtpTickerData(...)
  → init_data() → resolve_event_time() → _validate_ctp_quote()
  → _volume_tracker.apply(row) | apply_volume_delta(0, INVALID_QUOTE)
  → [_attach_managed_quote_v2_receipt(row)] → row.freeze()（60.03 新增发布点）→ push_data(row)
  → market_provider: project_ctp_market_tick(item, key, scope, receipt) → MarketTickPayload（Base，frozen dataclass）
  → SDK: bind_market_tick_event(payload, source, cursor) → MarketTickEvent（Base，frozen）
  → BT BtApiStore._poll_sdk_market_stream → market_tick_adapter.adapt_market_tick_event → SimpleNamespace（约 70 个字段）
  → BtApiStore.poll_tick: 保存快照到 _latest_ticks → BtApiFeed（prepare_market_tick_fields 等原地补字段）→ 数据线
```

结论：**Base 已有不可变的中立 Tick 合同 `MarketTickPayload`/`MarketTickEvent`**。provider 容器（`CtpTickerData` 等）是可变的解析缓冲区；BT 消费的是不可变事件，再在 adapter 中展开成每个消费者自有的可变工作对象。因此 INV-11 在 BT 边界上由不可变事件保证；provider 容器的“发布点”由 60.03 的 `freeze()` 标记。

### 2.3 字段语义要点

| 字段 | CTP | OKX | Binance |

### 2.4 BT `_tick_value` 默认值审计（G-08）

`backtrader/feeds/_btapi_cohort._tick_value()` 把值为 `None` 的字段视为缺失、返回调用处的默认值。`btapifeed.py` 中 67 处调用逐一检查，把“未知”当作“合格”的只有两处：第 1127 行 `bar_eligible` 默认 `True`，第 1264 行 `volume_complete` 默认 `True`。经 SDK typed 路径的 Tick 总会由 adapter 显式设置这两个字段（基线测试已覆盖），所以只影响旧的 dict Tick 路径。为不改变旧路径的回归行为，本阶段**不修改**，登记为残留风险。

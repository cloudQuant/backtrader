## 1. 盘点结构

按“输入 → producer → 中立合同 → SDK 绑定 → 消费者 → 输出”建立逐场所链路表。每行记录：仓库/commit/文件:行、构造方法、类型、字段/单位、来源和权限检查、初始化时点、**发布前变异点与冻结点**、所有权、复制、队列、异常及消费者。静态不可证实的分支标 `UNKNOWN`。

CTP 行情至少画出：`live_ctp_feed.py` 的发布流水线（`init_data` → `resolve_event_time` → 校验 → `_volume_tracker.apply` / `apply_volume_delta` → quote v2 回执 → `push_data`）、`quote_v2_projection` 与 `market_tick_projection` 两条投影，以及它们各自到 BT `BtApiStore`/`BtApiFeed` 的消费者。

## 2. 字段矩阵

覆盖身份与作用域、事件/接收时间和时区、价格精度、单位、Tick 增量与累计、质量/资格字段（`volume_complete`、`volume_quality`、`continuity_status`、`execution_eligible`、`quality_flags`、`event_time_source`）、Bar 完成性、订单/fill 身份及费用、持仓模式（映射 BT 现有 `net`/`dual_side` 与 `side`/`position_side`）、缺失与扩展字段。CTP、OKX、Binance 分别登记来源，不将同名字段视为同义。容器载体与来源、会话、时钟证明分行；真实账户、策略分配和 BT 框架对象分开。

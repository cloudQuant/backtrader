## 职责与实现设计

- SDK 根据确认归属、显式分配、费用和版本化估值规则提供策略账户视图；BT Broker/策略侧通过绑定策略身份的视图或代理投影框架对象。
- 预算、盈亏、权益、保证金、币种及行情时间分别说明计算依据；数据不全、汇率/价格过期或共享保证金无法可靠分配时保持未知。
- 并发预留和资金调拨以账户协调器事务更新；UNKNOWN 保留预留，迟到费用及人为调整记录可审计修正。

## 两类视图与 API 边界

| 项目 | 策略视图 | 真实账户视图 |
| --- | --- | --- |
| 资金 | 明确分配的预算、预留及按已声明规则计算的可用预算 | provider 报告的账户余额和可用资金 |
| 持仓 | 根据该策略已确认成交和初始归属形成 | provider 报告的账户持仓，多空腿和今昨仓以场所能力为准 |
| 盈亏、费用 | 根据可归属成交和明确估值政策计算，缺失依据则未知 | provider 报告的账户级事实，未确认部分保持未知 |

对同一 Cerebro 的共享 Broker，先决定如何由框架传递可信策略上下文；`getposition()`、`close()`、目标仓位与策略资金/权益的接口及兼容策略须一致，不能假设每个策略已拥有独立 Broker。示例接口不是现成 API；无策略上下文及资金计算依据时不得静默返回账户总额。账户级查询应有明确名称和权限，Sizer、Analyzer、Observer 与通知同步盘点。

## 状态及故障边界

- 实施前核对工作区和现有调用者；确定唯一状态 owner、生命周期及与相邻步骤的接口。
- 本步涉及的来源、授权、时间、账户事实或结果不确定时保持 UNKNOWN/不可用；显式启用的可选组件失败不得静默回退。
- 设计更改、破坏性迁移和未关闭风险记录在本步交付说明中，提交用户审阅。

## 视图、政策和状态

| 字段/操作 | 输入及规则 | 未知或异常 |
| --- | --- | --- |
| 持仓、可平量 | 06 确认归属、初始归属、预留及账本版本；区分合约、方向与今昨 | 未确认或对账差异时不可用；BT Position 仅可重建投影。 |
| 分配、追加、划回 | 账户、策略、币种、金额、有效时间、操作 ID、权限及政策版本 | 幂等，ID 内容冲突拒绝；账户来源不完整不宣布可用。 |
| 预留及可用预算 | 分配、账户资源、未决单和显式政策；账户协调器原子检查 | UNKNOWN 保留预留；账户或政策不可证明则不可用。 |
| 盈亏、费用、权益 | 归属 fill、费用、方向、乘数、结算、价格/时间、币种/汇率和公式版本 | 必要输入缺失/过期标未知；迟到费用审计调整，共同费用先未分配。 |
| 真实账户视图 | provider 的余额、可用、保证金、持仓、订单观察及完整性/时间 | 按账户权限单独读取，不复制到策略；无有效汇率不加总多币种。 |

具体盈亏、期货逐日结算、共享保证金及汇率按选定政策和能力表实施，记录舍入和有效期；无可靠规则不公布精确权益。调整含稳定 ID、原因、依据、操作者及前后版本，事务重放幂等。

## BT 上下文、兼容与开放门槛

Cerebro 与共享 Broker 装配时，将经认证/授权的稳定策略身份绑定框架上下文；订单将该上下文传 SDK，不能只信任自报字符串。接口最终名称及单策略默认遵循 01 决策；不假设每策略拥有独立 Broker。

| 调用 | 多策略 direct 目标 | 兼容及无法满足时 |
| --- | --- | --- |
| getposition、close、目标仓位 | 同一策略及账本版本的持仓/可平量 | 无上下文或不完整明确拒绝，不用账户总仓。 |
| getcash、getvalue | 显式政策下的策略预算/权益 | 无政策或估值依据不可用；回测和既有单策略默认按 01 决策回归并记录迁移。 |
| Sizer、Analyzer、Observer、通知 | 使用发起策略的同范围视图和事件 | 无作用域拒绝或明确不可用，不泄露其他策略；逐调用者核对兼容。 |
| Broker 账户级查询 | 显式名称、账户范围及权限 | 不静默改变既有账户级 API 语义；列破坏性变更及替代入口。 |

开放实际多策略交易前，必须完成 06 审阅、策略身份绑定及上述全链接口、可信订单/fill、对账和并发预留验收；所选 provider 的身份/会话/回报能力与账户授权须分别有真实证据。任一缺项时保持拒绝或不可用；本步隔离模拟通过不满足真实账户开放条件。

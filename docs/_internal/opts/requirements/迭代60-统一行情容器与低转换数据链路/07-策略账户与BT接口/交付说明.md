## 1. 问题

BT 已有按策略的视图和 Sizer，但只能挂在 service 会话上：direct 模式下 `BtApiBroker.get_strategy_account_book_view()` 直接报“需要活动的 service 会话”。这违反了计划“direct 与 Gateway 使用同一合同、切换模式不需要重写策略”的目标。

## 7. 2026-11-03 更新（验收报告 F3、F4、F6、G1；用户审阅 PENDING）

当前工作树（未提交）的实现；详细说明见 [验收报告回应](../验收报告回应-2026-11-03.md)，目标下单与 Sizer 部分见 [60.11 交付说明](../11-目标下单与策略资金作用域一致性/交付说明.md)。上文“`StrategyBudgetGate`（bt_api_execution）”的预算实现已被 SDK 账本取代。

- **策略资金**：SDK 账本新增 `StrategyCapital(amount, currency)`（分配给策略的现金，不是预算）。现金随本策略现货成交与手续费变化，买单需满足“现金 − 在途买单 ≥ 本单金额”（跨实例原子）；只建模现货多头且计价币种等于资金币种，其他在下单前拒绝。成交缺价格后现金不可知（无恢复接口，残留）。
- **策略视图财务数据**：只有在同一事务内对账 `BALANCED` 时，快照才带现金、持仓成本和财务切点；否则 `financial_available=False` 并给出原因码。
- **BT 接入**：`bind_direct_strategy_ledger` 必须给出对账来源（默认 Store 持仓订阅；Gateway 传流的 `report`；`unreconciled=True` 只有持仓无财务）；手续费由 `BtApiBroker` 按币种记录 provider 累计值并传给账本。
- **兼容变化**：绑定账本后，现金型 Sizer 收到本策略现金（不再是账户现金，也不再一律拒绝）；无预算策略不能开仓；绑定必须有 owner fence。未绑定策略和回测行为不变（BT 全量 4825 通过）。

## 9. 2026-11-04 R2-D 整改（service 同切点估值、通知原子性、3.13 测试卫生；用户审阅 PENDING）

- **service 同切点估值（取代 §8 中“保持不可用”的结论，仅限下述来源）**：
  - Base `account_book_protocol` 的 `StrategyAccountBookSnapshot` 升为**合同版本 2**：新增 `position_cut_id`、`financial_cut_id`、`reconciliation_state`、`contract_version`。声明 `SAME_TRANSACTION` 时，两个切点 id 必须存在且相等、裁决必须为 `BALANCED`、新鲜度为 `RECONCILED_IN_SNAPSHOT`，否则构造即拒绝 `STRATEGY_FINANCIAL_CUT_MISMATCH`；其他版本拒绝 `STRATEGY_BOOK_CONTRACT_VERSION_UNSUPPORTED`，不做升级。typed 编解码的字段表随之变化（注册表摘要改变，`semantics_revision` 1→2），旧对端的 typed part 以合同不一致被拒。
  - SDK `strategy_ledger._snapshot` 在同一事务内为每次读取生成一个切点 id（`generation:cursor:uuid`），持仓、现金、成本、合约条款与该事务的对账裁决共用它。
  - SDK `service_execution_account_books` 读适配器：账本资源若提供 `read_strategy_ledger()`（返回 `StrategyLedgerBookSourceV1`：本账户 `SqliteStrategyLedger` + 订阅维护的 `AccountPositionReport`，不得每次查询 provider），策略 `OWNER_BOOK` 只由 `ledger.reconciled_snapshot()` 一个事务产出，不再混入执行日志的对账；`IN_FLIGHT` 只给持仓、不给财务；`RESIDUAL`/`UNVERIFIED`、持仓证据不可用以有限失败形式返回（`STRATEGY_BOOK_RECONCILIATION_<STATE>`、`ACCOUNT_POSITIONS_UNAVAILABLE`），与 direct reader 一致。通用 map 中不含财务数字（`STRATEGY_FINANCIAL_TYPED_PART_ONLY`）。回复失败形式版本 2→3。未提供该资源的宿主保持原独立切点路径，BT 仍以 `STRATEGY_FINANCIAL_CUT_UNVERIFIED` 拒绝估值。
  - SDK `service_account_book_client`：先读失败形式（不再被覆盖率检查掩盖原因）；旧回复版本或 `contract_version != 2` 显式拒绝 `ACCOUNT_BOOK_TYPED_VERSION_UNSUPPORTED`；切点 id 不一致拒绝 `STRATEGY_FINANCIAL_CUT_MISMATCH`。

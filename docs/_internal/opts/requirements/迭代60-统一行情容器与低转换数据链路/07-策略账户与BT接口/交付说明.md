# 60.07 策略账户与 BT 接口——交付说明

状态：**实施完成（direct 策略视图与 BT 接入）；本步检查已执行；用户审阅 PENDING**。[总计划](../迭代计划.md) · [公约](../_公共约定.md)

## 1. 问题

BT 已有按策略的视图和 Sizer，但只能挂在 service 会话上：direct 模式下 `BtApiBroker.get_strategy_account_book_view()` 直接报“需要活动的 service 会话”。这违反了计划“direct 与 Gateway 使用同一合同、切换模式不需要重写策略”的目标。

## 3. 策略接口作用域（计划 §7.6.4）

| 接口 | 多策略下的行为 |
| --- | --- |
| `strategy.account_book.getposition(data)` | 只返回本策略持仓（A=2、B=3，而账户为 5）。 |
| `strategy.account_book.getcash(currency=...)` | 需要持久化的财务投影；没有时报 `STRATEGY_FINANCIAL_UNAVAILABLE`，**不回退到账户余额**（INV-10）。 |
| `strategy.account_book.getvalue()` | 当前合同没有可信估值输入，始终报 `STRATEGY_VALUE_UNAVAILABLE`。 |
| `StrategyAccountBookPercentSizer` | 卖出数量以本策略持仓为上限（得 2 而不是 5）；买入需要策略现金，不可用时拒绝。 |
| `broker.getposition()` / `getcash()` / `getvalue()` | 保持账户级语义不变（兼容既有单策略和回测）。 |

## 5. 残留

- **策略预算的并发预留**（开仓占用策略现金）没有新增准入门：现金来自 `bt_api_execution` 的持久财务投影，direct reader 支持传入，但本阶段没有把预算预留接入下单准入。开仓目前只受账户级与 Risk 约束。
- `getposition()`、`close()` 在 Strategy 上的默认实现仍是账户级（兼容要求）；多策略应使用 `account_book` 视图或策略作用域 Sizer。是否改变默认行为需要用户决定（会破坏既有单策略用法）。

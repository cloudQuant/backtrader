## 职责与实现设计

- Base 提供身份、归属、视图和存储端口，SDK 实现订单关联、确认 fill 去重、账本变更和对账；本地宿主装配持久存储。
- 按账户/route/策略/合约/方向及今昨仓等维度记账；在事务内一致提交去重、变更和游标，单账户顺序协调并预留可平量。
- 账户持仓 = 已归属策略 + 已确认未归属仅在相同可相加维度和完整切点成立时核对；外部持仓、非原子快照、反向净额及 UNKNOWN 不自动分摊或覆盖。

## 数据流与恢复

1. 策略下单时记录账户、route、稳定策略 ID、运行实例、BT 订单引用及客户端订单身份；派发前持久化绑定，场所身份由 provider 原生规则映射。
2. 经来源检查的逐笔成交到达时，依据可信订单绑定找到策略；在同一事务中检查成交身份、写入归属变更、费用状态和消费水位。身份冲突或无法归属的成交进入待核查，不分给任一策略。
3. 账户协调器对并发平仓先检查并预留该策略对应维度的可平量；未决或 UNKNOWN 状态不提前释放。账户真实可平量仍须按 provider 事实单独核查。
4. 首次启动需确认零仓基线，或建立可审计的初始归属；不明旧仓先记未归属。重启恢复账本、订单绑定、去重信息与预留，再按可用来源核对账户和未决订单。

## 端口、记录和原子性

以下是待设计合同而非现有 API。受控端口只供隔离测试或受控验证注入限定事实及读取结果，不能绕过实际交易准入或作为策略下单入口。

| 记录/操作 | 最小字段 | 不变量 |
| --- | --- | --- |
| 绑定 | account、route、strategy_id、run_id、具体合约、BT 引用、command/client ID、provider 订单 ID、会话代际 | 派发前绑定，身份经认证上下文核验；相同 ID 内容一致。 |
| 事实及去重 | provider、账户、交易日及实际作用域、订单/成交 ID、单笔量和单位、价格、方向/开平、费用币种、来源状态 | 仅合格 fill 记账；缺 ID、冲突或未知费用分别待核查，不以累计值代替。 |
| 持仓与预留 | 策略、合约、方向/腿、今昨桶、数量、均价、可平、未决预留及版本 | 同账户原子检查预留；确认部分成交消费预留，确认终态按规则释放，UNKNOWN 保留。 |
| 对账与调整 | 快照范围、完整性、时点、账本版本/水位、差异；操作 ID、操作者、原因、依据及前后版本 | 同维度且切点可证明才比较；调整授权、审计并幂等，不静默分摊。 |

宿主注入存储端口，SDK 是唯一业务记账工作流，BT Position 为可重建投影。去重、变更、游标在同一持久事务提交；崩溃后回滚或恢复至可验证版本。进程锁不能证明跨主机单写者；存储 fencing 只约束经其检查的账本写入，接管还须按步骤 10 证明旧 provider 会话失效或实际派发出口受强制栅栏约束。

## 对账与恢复

1. 启动恢复绑定、预留、去重和水位；未知订单以原 ID 查询，不换 ID 重发。无确认零基线或经审计初始归属时，依赖仓位的操作不可用。
2. 固定账本和事件切点，读取有范围、时点及完整性的账户观察，缓冲之后回报并按身份去重；外部多次查询不自动原子。无法证明切点记 NOT_COMPARABLE。
3. 仅在同维度可加时比较策略已归属之和加已确认未归属与账户观察；未知、缺页、反向净额和不支持模式不强制求和。差异保留并暂停相关操作。
4. 恢复依可信事实、幂等重放或授权人工修正，记录原因、证据、操作者、前后版本和风险。净仓/双向、今昨、日切、自成交只开放 01 已决且可证明的组合。

零基线 A 多 2、B 多 3、账户多 5：A 最多预留其未预留的 2，不能挪用 B 的 3。此例只适用可比较维度，不适用于不相容净额或双向模式。

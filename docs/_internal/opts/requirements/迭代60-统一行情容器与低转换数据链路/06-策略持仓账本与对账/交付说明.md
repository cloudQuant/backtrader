## 2. 新增能力：按策略的可平量准入（真实缺口）

既有实现把“平仓数量不能超过持仓”交给可注入的 Risk 准入门，但没有一个中立的、按策略计算的实现。缺少它时，策略 A 可以平掉策略 B 的持仓，两个并发平仓也可能超卖。

| 仓库 / 提交 | 变更 |
| --- | --- |
| `bt_api_execution` `5afdf6c` | 新增 `StrategyCloseCapacityGate`（`strategy_close_capacity.py`）：平仓意图（`CLOSE*` 或 `reduce_only`）的数量必须 ≤ `基线 + 本策略已确认成交 − 本策略未终结平仓单的剩余量（含 UNKNOWN）− 本进程已授予但未落库的预留`。每次都从持久事实重算，因此重启后结果一致；开仓不在此限制，可选的 `inner` 门（如共享 Risk）照常调用。`SqliteExecutionStore.list_scope_intents()` 提供它所需的只读投影。 |

## 6. 2026-11-03 更新（验收报告 F3–F5、G2、G6；用户审阅 PENDING）

以下记录当前工作树（未提交）的实现，详细说明与回归证据见 [验收报告回应](../验收报告回应-2026-11-03.md)。上文历史记录保留，与本节冲突处以本节为准。

- **D60-08 已被取代**：按用户对验收报告 P1-5 的决定，策略账本不依赖 `bt_api_execution`。当前唯一账本实现为 SDK `bt_api_py.strategy_ledger.SqliteStrategyLedger`（schema v2，一个账户一个 owner 文件锁，所有准入与状态变更为 SQLite `BEGIN IMMEDIATE` 事务）。
- **预算默认必须配置**（F3）：无预算开仓拒绝 `BUDGET_UNCONFIGURED`；显式 `require_budget=False` 才放开（是否保留该开关待用户决定）。合约条款改为 `InstrumentTerms(multiplier, quote_currency, product_model)`，预算不跨币种相加。
- **手续费身份**（F4）：按 (intent, 币种) 记录 provider 累计手续费；迟到手续费入账、重复投递幂等、累计值变小拒绝；修复了“无手续费回报会清零基线导致重复计费”的缺陷。
- **对账**（F5）：只接受 `AccountPositionReport`（账户、来源、观测时刻、完整性、可选 `valid_until_ns`）；结果 `BALANCED` / `RESIDUAL` / `IN_FLIGHT`（挂单或结算窗口内的新成交）/ `UNVERIFIED`（不完整、过期、未来时刻）。来源为订阅：direct 用 provider 持仓推送 + 周期完整基线，Gateway 用 ZMQ 账户流（`bt_api_py.account_position_stream`）。
- **owner fence**（G2）：共享账户（绑定账本）必须先 `bind_account_owner`；Store 命令 worker 在真正写入 provider 前再查一次 fence。旧 owner 会话确已失效的证明仍需部署方提供，**接管仍为 NO-GO**。
- **无 Execution**（G6）：隔离 venv + 本地 wheel 三环境验收通过（PACKAGE），脚本见 `../10-多进程恢复与综合验收/evidence/iso_execution_envs_check_2026-11-03.py`。

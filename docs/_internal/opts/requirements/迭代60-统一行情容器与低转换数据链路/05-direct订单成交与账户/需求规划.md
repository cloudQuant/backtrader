## 范围与需求

- 将标准 Order、逐笔 Fill、Position 和真实账户观察接入 SDK 和 BT；区分 BT Order/Trade 与交易所逐笔 fill。
- 按账户、route、会话及真实订单/成交身份关联，保留 UNKNOWN，不凭快照差额伪造成交。
- direct 不因需要安全关联而强制安装 Gateway、Execution、Risk 等可选组件。

## 完成边界

- 仅交付本步涉及的合同、源码或盘点及引用清单；跨入下一步的能力不得提前声称完成。
- 形成本步交付、兼容/破坏性变化、未决事项和可审阅证据；用户审阅并明确同意后才进入下一步。

## 可追踪需求

| 编号 | 要求 | 输出 |
| --- | --- | --- |
| 05-R1 | provider 对照 02、现有 DTO，声明订单、逐笔成交、账户字段和作用域 | CTP/OKX/Binance 分别列 ID 约束、时间、单位、状态、币种和未确认字段。 |
| 05-R2 | SDK 关联账户、route、会话代际、命令及可信回报 | 稳定命令、客户端 ID、provider 身份与 BT 引用绑定，身份冲突可观察。 |
| 05-R3 | BT 保留 Order/Trade/Position 和通知生命周期 | 单笔 fill 与累计量、交易所 fill 与 BT Trade 分开；未可信关联不得确认成交。 |
| 05-R4 | 真实余额、持仓和开放订单分别观察 | 标注账户、route、时间、币种/合约、单位、完整性；缺失不解释为零或终态。 |
| 05-R5 | SDK/provider 实施直接路径安全关联 | 不强制 Gateway、Execution、Risk、ZMQ 或 codec；已选组件故障不绕过。 |

ACK、超时、列表缺失和仓位差值均不证明成交或终态。UNKNOWN 保留原命令及订单身份查询/对账，不换 ID 重发；撤单同理。07 完成及验收前共享 Broker 多策略实际交易接口保持拒绝或不可用，不用账户总仓替代策略仓。

# 60.05 direct 订单成交与账户——交付说明（含第一阶段汇总）

状态：**实施完成（容器合同与 SDK 投影范围）；本步检查已执行；用户审阅 PENDING**。[总计划](../迭代计划.md) · [公约](../_公共约定.md) · [60.01 交付说明](../01-基线盘点与合同决策/交付说明.md)

## 1. 范围与边界

订单、逐笔成交、持仓三类 provider 容器纳入合同 v1，并验证 SDK 生成的中立行（BT Broker 的输入）不因此改变。60.01 盘点确认：**BT 不直接调用 provider 容器 getter**，它消费 SDK `bt_api_py._normalization._dict()` 产出的中立行；`_dict()` 会依次调用标准 getter，遇到 `NotImplementedError` 就跳过。因此本步的关键风险是：补全 getter 后，中立行里会不会冒出新的、取值不同的字段。

不在本步范围：通知投递语义（D60-16）、单 Store 多策略身份（G-15/G-19），二者归第二阶段；真实账户读写（NOT_RUN，无授权）。

## 3. 中立行不变性（60.05 关键结论）

| 行 | 补全前 | 补全后 | 是否改变 BT 输入 |
| --- | --- | --- | --- |
| CTP 持仓 | 无 `position_side`；`direction` 来自 `get_position_direction()` | 新增 `position_side`，取值与 `direction` 完全相同 | 否：CTP 归一化策略按 `position_side`→`direction` 的顺序取方向，结果相同 |
| CTP 平仓单 | `position_side` 来自 `get_all_data()` 中的投影（`LONG`/`SHORT`） | getter 返回同一个值 | 否 |
| CTP 开仓单 | 无 `position_side` | getter 返回 `None`，不写入 | 否 |
| CTP 强平/不一致 | `UNRESOLVED` | getter 返回 `None`，不覆盖，仍为 `UNRESOLVED` | 否 |

上表由 SDK 新测试逐行固定（7 项）。

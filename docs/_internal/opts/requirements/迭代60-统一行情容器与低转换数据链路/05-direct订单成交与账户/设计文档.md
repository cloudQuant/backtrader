## 职责与实现设计

- 提交前绑定稳定命令、客户端订单与 BT 本地引用；provider 按场所规则映射订单身份，返回结果需来源校验。
- 成交去重、部分成交、状态乱序、先成交后订单及通知快照由各自 owner 明确处理；不可关联时隔离。
- 真实持仓/余额标注账户、币种、完整性和观察时点；BT 投影本地订单及通知，成交确认不由 ACK 证明。

## 状态及故障边界

- 实施前核对工作区和现有调用者；确定唯一状态 owner、生命周期及与相邻步骤的接口。
- 本步涉及的来源、授权、时间、账户事实或结果不确定时保持 UNKNOWN/不可用；显式启用的可选组件失败不得静默回退。
- 设计更改、破坏性迁移和未关闭风险记录在本步交付说明中，提交用户审阅。

## 接口字段和 owner

| 边界 | 输入 | 输出与责任 |
| --- | --- | --- |
| BT → SDK 命令 | 已绑定账户/route、合约、方向/开平、数量单位、价格、BT 引用、稳定命令及客户端订单 ID | SDK 发送前绑定；provider 声明 ID 字符、长度、作用域及可查询能力，配置字符串不证明授权。 |
| provider → SDK 订单 | 来源/会话、客户端及原生订单 ID、状态、委托量、累计成交、价格、时间 | provider 解析，SDK 核验关联和状态；未知或冲突待核查，ACK 不提升为受理。 |
| provider → SDK fill | 账户/route、会话、订单及成交 ID 和作用域、单笔量、价格、时间、方向/开平、费用/币种 | SDK 验证来源并去重；未知费用保持未知，不能假设 ID 全局唯一。 |
| SDK → BT | 合格观察、绑定结果和真实账户快照 | Broker 投影本地框架对象并产生稳定通知快照；账户快照有完整性，不覆盖策略归属。 |

## 状态与恢复

下单先绑定再派发；派发回执、交易所观察和 fill 是独立事件。部分成交逐笔推进，累计量仅核对而不补造 fill；先到 fill 可有界暂存，超期待核查。同身份同内容幂等，内容冲突隔离并暂停；旧会话回报和乱序不得倒退终态。无法证明身份或顺序时登记不可用。

派发或撤单超时保持 UNKNOWN 与原身份，授权查询并对账，不能换 ID 重发或凭开放订单缺失推断终态。账户读取返回范围、时点及完整性；多次查询不假定原子。快照差额不能伪造成交，迟到 fill 与快照重叠无法证明切点时停止可信推进。

## 可选组件的中立接点

SDK 按账户、route、策略、命令和会话绑定后，依显式配置选择自己的 direct 派发路径或注入的 Execution 派发端口；同一命令只有一个派发 owner。所选 Risk 在每笔实际派发前对当前命令及所需可信事实作出允许、拒绝或不可判定，并按合同管理预留、有效期及更新；未来 Execution 更改或拆分命令时须重新绑定和决策。撤单政策单独明确，失败或过期不静默绕过。Monitor 可订阅带范围和质量的只读命令/订单/成交观察，不拥有或改变事实；默认遥测故障有界隔离并报告，显式设置为必需门槛时按政策停止相应操作。接口以[总计划 §3.1](../迭代计划.md#31-可选-riskexecutionmonitor-的扩展边界)为准，本步不实现各插件业务。

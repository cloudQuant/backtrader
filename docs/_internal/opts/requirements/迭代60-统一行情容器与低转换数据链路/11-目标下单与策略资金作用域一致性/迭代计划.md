# 60.11 目标下单与策略资金作用域一致性——迭代计划

状态：**NOT_STARTED；实施及验证 NOT_RUN；用户审阅 PENDING**。[总计划](../迭代计划.md) · [公约](../_公共约定.md) · [需求](需求规划.md) · [设计](设计文档.md) · [验收](验收文档.md)

本步补充修复 60.07 的策略范围缺口。历史交付和检查记录予以保留，受影响结论须重新核验；不据此假定其他步骤已完成或已获用户验收。

## 1. 问题和目标

绑定策略账本后，`order_target_value()` 非零目标仍读 Broker 账户级价值，`order_target_percent()` 仍读账户级总价值；`PercentSizer` 空仓时仍使用账户级现金。持仓与资金作用域混用，可能导致错误的方向或数量。`AllInSizer`、`PercentSizerInt` 和 `AllInSizerInt` 等继承类也需核对。

修复目标：上述策略入口统一使用具有完整依据的本策略持仓、资金及估值；缺乏依据时在订单提交前明确不可用，不能静默使用账户总额。明确的 Broker 账户级 getter 保持其语义；未绑定账本的单策略及回测行为以修改前基线验证。

## 2. 范围与前置

- 开工时固定 BT 及相关 SDK/Base 的提交、dirty、依赖和账本合同；盘点 direct 与当前支持的 service/Gateway 策略视图、身份、可用字段及调用者。跨仓修改前读取目标仓 AGENTS 和 README。
- BT 保留策略、Sizer 和订单投影；中立财务事实与账本按既有 SDK/Base 职责和实际合同确定。复用已有视图和唯一账本，不创建平行权威账本。
- 确定现金、预算、权益、标的估值的币种、时间、版本及可用性；现货、期货、空仓、多空、乘数、保证金、费用和汇率分别列支持矩阵。无可靠依据的模型明确拒绝。
- 本步不开发迭代 70 的多策略回测账本，不操作真实账户，也不让可选 Gateway、Risk、Execution、Monitor 成为 direct 的必需依赖。
- 本步可根据既有 60.06–07 受控合同开展，受影响结论按公约登记及复核；真实多策略交易仍需独立的账户、provider 和授权证据。

## 3. 工作顺序

| 工作项 | 交付及检查 |
| --- | --- |
| 11-1 基线与盘点 | 固定版本；列出目标下单、内置/自定义 Sizer 和其他资金消费者的实际来源；建立未绑定路径和账户 getter 基线。 |
| 11-2 合同与支持矩阵 | 确定策略身份、现金/预算/权益、标的价值、币种、版本一致性、错误及兼容合同；明确正向支持和不可用范围。 |
| 11-3 目标下单 | 修复目标价值及百分比；单独验证目标为零、目标数量、空仓和短仓等路径，不借账户总值补全。 |
| 11-4 Sizer 与资金消费者 | 修复普通百分比 Sizer 及受影响继承类；核对现有策略账本 Sizer 限制，盘点自定义 Sizer 与其他消费者。 |
| 11-5 验收和交付 | 运行子验收矩阵及关联回归；列修改、跨仓版本、迁移、支持范围、缺口和证据，更新受影响状态并供用户审阅。 |

无法提供可信策略权益时，至少应保证安全拒绝并清楚标记目标百分比不可用；这不等于目标百分比功能已完整实现。对合同已经提供可靠数据的支持场景，还须验证可正常下单。

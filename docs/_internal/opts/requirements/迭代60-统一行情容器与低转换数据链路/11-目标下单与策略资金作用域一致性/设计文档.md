# 60.11 目标下单与策略资金作用域一致性——设计文档

状态：**实施完成（现货模型，工作树未提交）；单元验证已执行，见[交付说明](交付说明.md)；用户审阅 PENDING**。[总计划](../迭代计划.md) · [本步计划](迭代计划.md) · [需求](需求规划.md) · [验收](验收文档.md)

## 1. 现状

`Strategy.getposition()` 在已绑定策略账本时读取策略持仓；`order_target_value()` 仍调用账户级 `broker.getvalue(datas=[data])`，`order_target_percent()` 先调用账户级 `broker.getvalue()`。`Sizer.getsizing()` 把 Broker 现金传给普通 Sizer；`PercentSizer` 空仓计算直接使用该值。当前 `BtApiBroker.getvalue(datas=...)` 忽略 `datas`，不能假定返回该标的账户仓值。

现有策略账本 `getcash(currency=...)` 要求币种与可用财务快照，`getvalue()` 明确返回 `STRATEGY_VALUE_UNAVAILABLE`。简单替换调用不能自动建立可信权益。以上为规划时静态观察，实施时固定版本重新验证。

## 2. 目标数据流

```text
Strategy / Sizer → 已绑定策略身份及策略视图
    → 校验账户、策略、币种、版本、时效、完整性和支持的估值模型
    → 计算建议数量或明确不可用 → Broker 和执行准入
```

这是目标合同，并非现成 API。BT 负责策略入口、佣金模型调用、数量及错误投影；SDK/Base 按开工时确认的合同提供中立事实。不得绕过执行准入或创建第二个资金真值。

| 入口 | 已绑定策略账本 | 未绑定 |
| --- | --- | --- |
| `order_target_value()` | 使用同策略、同标的和同币种的合格估值；不支持或依据缺失时提交前拒绝。 | 保持经基线验证的原行为。 |
| `order_target_percent()` | 使用完整且有效的策略权益和策略标的价值；不能以预算或账户权益代替。 | 保持原账户语义。 |
| `PercentSizer` 及继承类 | 使用审定的策略资金合同与明确币种；资金缺失或模型不支持时不可用。 | 保持原账户现金行为。 |
| Broker 账户 getter | 保留账户范围，不随策略上下文静默变义。 | 保持原合同。 |

## 3. 必须冻结的设计

1. 校验策略、账户和数据身份；快照不完整、过期、版本不一致或身份不符时拒绝。尽可能读取同版本快照，否则验证并拒绝；不承诺跨源天然原子。
2. 分别定义现金余额、预留、可用预算、标的价值和权益。多币种缺汇率不合计；不得以初始预算或账户总额猜测策略权益。
3. 现货、期货、方向、乘数、保证金、费用、结算和舍入逐项列支持矩阵；使用验证过的模型和 `comminfo`，禁止假设所有品种都能简单用价格乘数量。
4. Sizer 仅生成建议；订单前仍需账户级及策略级准入和预留，处理并发及 UNKNOWN。估值不可用时，记录明确错误并阻止提交。
5. 单独审计 `order_target_size()`、零目标平仓、空仓和自定义 Sizer；如零目标不需要估值即可安全处理，冻结其条件并测试。
6. 记录绑定路径可能从静默账户回退改为报错的兼容变化；direct/service 分别验证。缺失策略权益时只能报告安全拒绝已验证，不能报告目标百分比完整支持。

回退需保留绑定路径的明确拒绝或关闭相关能力，不得恢复静默账户回退。模拟、安装包、真实账户分别记录证据。

# 60.11 目标下单与策略资金作用域一致性——交付说明

状态：**实施完成（现货模型；工作树未提交）；单元验证已执行；用户审阅 PENDING**。[总计划](../迭代计划.md) · [需求](需求规划.md) · [设计](设计文档.md) · [验收](验收文档.md) · [验收报告回应](../验收报告回应-2026-11-03.md)

## 1. 实现

- **估值合同** `value_strategy_book()`（`backtrader/service/service_strategy_account_book.py`），政策 `strategy_spot_equity.v1`：权益 = 资金币种现金 + Σ 现货多头 × 行情价 × 乘数。只用**同一份**已对账快照（一次调用只读一次）。
- **输入资格**：快照财务可用且成本完整；单一现金币种（其他币种非零即 `STRATEGY_FX_UNAVAILABLE`）；持仓条款由 SDK `InstrumentTerms.from_version()` 精确解析，BT 佣金模型乘数必须相等（否则 `STRATEGY_INSTRUMENT_TERMS_CONFLICT`）；行情价取对应 feed 当前收盘价，有限且为正，各价 bar 时间差不超过 `Strategy.strategy_mark_max_age`（默认 0）。
- **`order_target_value` / `order_target_percent`**：绑定账本时使用本策略持仓价值与权益；零目标只平本策略持仓、不需估值；任何输入缺失或冲突都在创建订单前抛出带原因码的 `ValueError`。
- **Sizer**：现金型 Sizer（`PercentSizer`、`AllInSizer` 及 Int 版本、自定义）绑定后收到本策略现金；不读现金的 Sizer（`uses_account_cash = False`，如 `FixedSize`）不受影响；Sizer 仅为建议，账本准入原子约束现金。
- **未绑定策略**：保持原账户语义（回测兼容）。

## 4. 2026-11-03 复验缺口整改（F6、G6；用户审阅 PENDING）

### 4.1 可信实盘行情价（F6）

BT 只消费 SDK/Base 已给出的事实。绑定账本的策略在实盘数据上估值（`order_target_value`/`order_target_percent`），必须同时满足：

1. 估值涉及的每个 feed 都提供 `valuation_mark()`（`BtApiFeed`），且 `feed.store` 与策略 Broker 的 `store` 是同一个 Store 实例，即同一账户/provider 路由；否则 `STRATEGY_MARK_ROUTE_UNBOUND`。部分 feed 无此合同：`STRATEGY_MARK_PROVENANCE_UNAVAILABLE`。
2. 线上值来源可信（`BtApiFeed.valuation_mark_sources`）：provider 声明 `bar_final=True` 的 bar（`provider_bar`）；feed 以事件时间水位从已通过质量门的 typed tick 闭合的本地 bar（`local_aggregation`）；Tick 周期下单个合格 typed tick（`market_tick`，即 `quality == "GOOD"` 且无 `LEGACY_SCHEMA`，并已满足既有 `bar_eligible`）。回放 bar、由旧式（未 typed）tick 构成的值一律 `MARK_SOURCE_UNTRUSTED`。
3. 带 provider/交易所事件时间：bar 为收盘时间（开盘时间 + 周期），tick 为其事件时间。
4. 绝对新鲜度：`now - 事件时间 <= Strategy.strategy_mark_max_age_seconds`，`now` 取 feed 注入的 `clock`（实盘为墙钟）。默认 **5 秒**（保守）；更慢的数据须由策略显式调大。它只能收紧 feed 自身的 `valuation_mark_max_age`（默认一个周期 + `receive_time_max_age`），不能放宽。非有限、非正、布尔或非数值：`STRATEGY_MARK_AGE_INVALID`。超时：`STRATEGY_MARK_STALE`；未来时间：`STRATEGY_MARK_FROM_FUTURE`。
5. 多个实盘价各自受绝对时效约束，不再额外比较相对 bar 时间；历史价仍用 `strategy_mark_max_age`（默认 0）比较相对时间。

回测（BackBroker + 非实盘历史 feed）行为不变；其他自定义 Broker 上的非 `BtApiFeed` 数据仍拒绝。零目标仍只平本策略持仓、不需估值。

复验反例：单个极旧（2001 年）合成 final bar 在 `BtApiFeed` 上发布后，`order_target_value`/`order_target_percent` 均以 `STRATEGY_MARK_STALE` 拒绝、不产生订单；新鲜的 final bar（收盘后 1 秒）与新鲜合格 tick 被接受并下单。测试：`tests/unit/test_iter60_live_mark_eligibility.py`（35 项）。证据等级 UNIT（本地 feed、伪 Store 对象与真实 SDK 账本；无真实行情或订单）。

### 4.3 Bar 完成状态（G6）

`BtApiFeed` 只发布 `bar_final is True` 的 bar；`False` 计入 `unfinished`，`None`/非布尔计入 `unknown_finality` 并丢弃。**兼容变化**：未声明完成状态的旧式 dict/tuple bar 不再发布。各生产方（`tests/unit/feeds/test_iter60_bar_finality_producers.py`，真实 provider 容器 + SDK `normalize_event`，仅以直接导入代替未安装的 entry point 发现）：

| 生产方 | 完成声明 | 结果 |
| --- | --- | --- |
| OKX 推送 K 线 | `confirm`：`"0"` → `bar_final=False`，`"1"` → `True` | 未完成丢弃、完成发布；时间戳为开盘时间 |
| Binance 推送 K 线 | `k.x`：`false`/`true` | 同上 |
| CTP | provider bar 容器（`CtpBarData`）无完成声明，不是实盘 bar 来源 | CTP bar 由 `BtApiFeed` 从合格 tick 合成，事件时间水位越过桶末才闭合为 `bar_final=True`；含旧式 tick 时来源标为 `local_aggregation_legacy`（可画线，不作估值价） |
| SDK 历史 | `MarketBar` 合同即已闭合区间（OKX 历史 provider 忽略 `confirm="0"`，采集器拒绝未来收盘） | Store 投影 `bar_final=True` 并发布 |

**新发现（OPEN，SDK 归一化，不在本工作包修改）**：Binance K 线事件经 `bt_api_py._normalization.normalize_event` 后，`timestamp` 取事件时间 `E` 而不是 K 线开盘时间 `k.t`，BT 会把它当作 bar 开盘时间（桶与收盘时间偏一个周期）。估值路径因收盘时间落在未来而拒绝（安全），但 bar 时间本身不正确。已用 strict xfail 用例记录，需 SDK 按 provider 声明选取 bar 开盘时间字段。

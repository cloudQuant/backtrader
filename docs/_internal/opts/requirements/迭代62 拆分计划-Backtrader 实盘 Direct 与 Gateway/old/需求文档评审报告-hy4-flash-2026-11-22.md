## 1. 总体结论

**结论：方案的架构方向和安全边界判断可靠，源码论据经逐条回读全部成立；但在进入 SPLIT-00 之前，必须先关闭 3 项基线阻断，其中"链接全断"和"测试基线丢失 476 个文件"是可立即修复的事实性问题。**

1. **核心反例抽得准**。"Direct SDK + 远端 Execution parent port"确实是代码里的第三条路径——`_configure_execution_routing` 在 L1231–1240 拒绝 Gateway / 读代理 / 非直连 / 非自有 SDK，却在 L1258 接受 `execution_parent_port`，并在 L1404 把该 port 装进 `ExecutionOrderRouter(execution_port=self._execution_parent_port, risk_selected=False)`、在 L1436 注入 `BtApi(..., execution_order_routing=selection)`。这是"不能只改个名字叫 Gateway"的直接证据。

- **事实**：方案写"Execution 建议作为新策略订单意图的唯一上游受理和编排入口，由 Gateway 交易 owner 进行场所派发；Execution 自身不得另开场所写入会话"（L59），消息流写"经约定的授权组件核对 Risk 证据后交给 Gateway 交易 owner 唯一派发"（L64）。但"约定的授权组件"始终没有点名，而 §11 L131 明确"Gateway 本身不检查 Risk 审批……不能把这条职责擅自移给 Gateway"。
- **影响**：Execution 提出意图 → 某授权组件核对 Risk → Gateway 派发，这三步之间必须有可验证的绑定（谁签发的授权、授权是否绑定该订单意图、Gateway 凭什么相信）。当前文本既说 Gateway 不做 Risk 校验，又不指定谁做，落到实现时最省事的做法就是"Gateway 看一眼 Execution 的结果就派发"，这恰好是 §11 要避免的。
- **补充证据**：SDK 侧现在有两套并存的事实——`AtomicIntakeService` 无 `risk_port`，`ParentSubmitService` 带 `risk_port` 但仅限测试；Gateway 另有 `risk_client` 装配（§7 L90，已核实）。三套机制没有统一的"谁核对、用什么证据"合同，§7 说"在 SPLIT-00 冻结"是对的，但 §4 已经提前写成了目标语义，容易被当成已决定。
- **建议**：在 §4 把"约定的授权组件"改为具名，并写明最小合同：Execution 提交时携带（意图身份、账户/策略/route 绑定、Risk 决策的证据引用），Gateway 在派发前只校验**该证据引用与绑定一致且未过期**，不重新执行风控；证据缺失/过期 → 不派发且保持 UNKNOWN，不回 Direct。SPLIT-00 冻结该字段集与错误码。
- **处置**：待处理。**建议修改**，与 REVIEW62S-003 的清退表合并到同一次合同冻结。

## 5. 可选建议

### REVIEW62S-008 · 把"五种状态"与"两种模式"分开表述

§3 L46 的 `Service read proxy / market-data-only` 和 L47 的 `Replay / backtest` 被放在"配置矩阵"里，容易被读成第三、第四种模式；但源码里 `market_data_only` 是可被运行时强制的**写权限状态**（REVIEW62S-004），Replay 是 **Feed 来源**（`btapifeed.py:1005–1013`），都不是模式。建议在 §3 开头加一句定义：模式只有 direct/gateway 两种且启动不可变；market_data-only 是可叠加的只读状态；Replay/backtest 是独立工具入口。这样 §6.3"不跨模式热切换"和 §3 L46"不作为实盘第三模式"就不会互相重复。

### REVIEW62S-009 · 给"模式"一个机器可读的字段名

§3 L50 说"使用显式标签选择；错误码、配置格式、版本校验字段在 SPLIT-00 冻结"，但没有给出模式的字段路径。建议 SPLIT-00 直接定形，例如 `execution.mode: direct|gateway`（与现有 `backend: direct` 和 `gateway_strategy` 键的关系写清楚），并把 §2 里的 `has_execution` / `gateway_strategy` / `execution_parent_port` 三类隐式判据统一投影到该字段。否则 §3 L48"不根据 import 成功、默认参数或服务超时猜测"在实现层仍会退化成多个 `if`。

### REVIEW62S-010 · §11 的行号需要时间戳

§11 的 10 行表格大量使用 `L9、21、153、810` 这类定位，且开头已声明"行号是关键词和关键决策的定位，不是……已经实现的认证"。这个声明是对的，但行号会漂移。建议每行加一列"对应决策号"（如 D63-02、D64-01、D65-31、D66-09、D68-02），决策号比行号稳定，也更便于 SPLIT-00 引用。

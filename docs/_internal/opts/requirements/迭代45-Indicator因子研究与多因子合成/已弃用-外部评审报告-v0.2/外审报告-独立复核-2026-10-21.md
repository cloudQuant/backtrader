## 3. 阻止基线确认的问题

### REVIEW45-101 — ResearchSpec 的时间/资产合同缺类型与构造规则

**定位**：设计 DS45-02 §2.1/§2.2、DS45-03；需求 REQ45-03/04；验收 F-CALENDAR/F-OOS/F-DATASET-INVALID。

**严重程度**：阻止基线确认。

**问题与影响**：

1. `ResearchSpec` 的第一个必需字段是 `grid`，但公开类型、构造入口和校验规则均未定义。DS45-02 示例直接写 `grid=closed_bar_grid`，没有 import、没有构造代码；DS45-03 只说“严格递增、唯一、带 UTC 时区的 close_time 索引；open_time 列”。用户无法从文档写出这个对象。
2. `ResearchSpec` 同时要求 `start`、`end` 和 `grid`。三者关系未定义：
   - `grid` 是否包含研究区间之前的预热和之后的标签尾部？DS45-03 说“prices/grid 含预热及尾部”，但 DS45-03 又称“研究 grid”，验收 F-DATASET-INVALID 又要求 universe 覆盖“某 target×grid”。如果 grid 含尾部，universe 是否要覆盖尾部？
   - `start/end` 是闭区间还是半开区间？是否必须对齐 grid 边界？如果 grid 超出 [start,end]，是裁剪还是拒绝？
   - raw_factors 只含研究区间，prices 含预热/尾部；那么“缺失 grid 行补齐缺失记录”（DS45-04.4）补的是哪个区间？
3. `universe` 只写“可为 `(time, asset)` 布尔表”，没有类型（pandas DataFrame？MultiIndex Series？嵌套 dict？）；`groups` 只写“资产→研究组的静态映射”，缺少目标未覆盖时的默认/报错规则。`FactorSpec` 在表中被当作“映射键是唯一非空因子名”，但名字是 Spec，示例又用普通 dict，类型是 dataclass 还是 mapping 未定。
4. 这些问题直接决定 R1 的公开签名、数据集 schema 和损耗分母。R1 若按现状开工，只能由实现者临时选择，违背“设计文档是数值与时序语义唯一定义位置”的自我约束。

**建议**：

- 定义公开的 `ResearchGrid`（或 `ClosedBarGrid`）类型与构造函数，例如接受“`close_time` 为 UTC `DatetimeIndex`、`open_time` 为同长度序列”的显式对象；规定时区、单调、唯一、`open_time < close_time`、bar 不重叠的校验。
- 明确 `grid` 是**完整时间线**（预热 + 研究区间 + 尾部），`start/end` 是**研究区间**（闭区间、必须对齐 grid），raw_factors/availability/universe 只覆盖 `[start,end] × targets`；预热和尾部仅用于 Indicator 与价格标签。
- 明确 `universe` 的公开类型和覆盖范围（只覆盖研究区间 × targets；缺失即 `UNKNOWN_UNIVERSE`，不得默认 false）；明确 `groups` 缺省行为。
- 明确 `FactorSpec` 是 mapping 还是 dataclass；若是 mapping，给出每个键的类型与校验顺序。
- 同步修改 F-CALENDAR/F-OOS/F-DATASET-INVALID 的输入描述，并在 R1 退出条件中加“grid 合同已冻结”。

### REVIEW45-102 — EvaluationSpec 方向覆盖与 evaluate 签名不一致

**定位**：设计 DS45-02 §2.2（“方向可在离线评价时通过已记录的 EvaluationSpec 显式覆盖”）；EvaluationSpec 表；示例 `strategy.evaluate(preprocess=..., combinations=..., periods=..., ...)`；需求 REQ45-06；验收 AC45-12。

**严重程度**：阻止基线确认。

**问题与影响**：

- 设计说方向可以在离线评价时覆盖，但 EvaluationSpec 的字段表只有 `periods/label/quantiles/min_assets/min_quantile_assets/preprocess/max_loss/combinations`，没有方向字段；也没有规定“原始声明”和“本次覆盖”分别存在结果/清单的哪个成员。
- 示例调用 `strategy.evaluate(preprocess=..., combinations=..., periods=..., quantiles=..., min_assets=..., label=...)` 传的是 kwargs，不是 `EvaluationSpec` 对象；而 `evaluate_dataset(load_dataset(...), periods=(1,10))` 同样。到底公开签名是 `evaluate(spec: EvaluationSpec)` 还是 `evaluate(**spec_fields)`，文档没有唯一答案。
- AC45-12 要求“方向反转须对应反号”，但没有可执行的配置入口；R1 冻结签名时会首先撞上这个歧义。

**建议**：

- 在 EvaluationSpec 增加 `directions`（或 `direction_overrides`）字段，定义为“信号名/因子名 → 数值 ±1”，拒绝 bool、0、非有限值；未列出的信号沿用 FactorSpec 的原始方向。
- 在 manifest/结果中记录 `declared_direction` 与 `effective_direction`，并说明覆盖只改变评价，不改变原始面板或采集配置。
- 明确 `evaluate` 的签名：推荐 `evaluate(spec: EvaluationSpec | None = None, **overrides)`，或明确只接受 `EvaluationSpec`；把示例改成与签名一致。
- 在 AC45-12 增加“方向覆盖 + 非法方向”的负例。

### REVIEW45-104 — “公式异常必须终止”与引擎异常吞噬冲突

**定位**：设计 DS45-08“公式异常 | 明确因子、资产、阶段并终止本次采集；正常 NaN 可记无效，意外异常不自动当缺失”；DS45-04；验收 AC45-14/07。

**严重程度**：阻止基线确认（失败语义合同）。

**问题与影响**：

- `LinesOperation.next()` 在计算 `self.operation(a_val, b_val)` 时（`backtrader/linebuffer.py:2516`），用 `except Exception` 捕获**所有**异常并写入 NaN，只发一条节流警告 `linebuffer.lines_operation.next.nan_recovery`（`:2541`）。
- `LinesOperation.once()` 对 parent/operand 的 `once()` 也用 `except Exception` 捕获并继续（`:2566-2634`），同样可能把异常变成 NaN 或静默跳过。
- 因此，用户 Indicator 的线运算中若出现除零、类型错误、索引错误或真正的代码 bug，模板看到的只是一个 NaN；它无法按 DS45-08 区分“正常缺失”与“意外异常”，也无法“明确因子、资产、阶段并终止”。AC45-14 的 `NONFINITE_INPUT`/`MISSING_LABEL` 可能掩盖代码缺陷；AC45-07 的因果性测试也可能在错误实现上通过。
- 这不是要改核心调度；但设计必须给出可实现的机制，否则 R1 的采集层无法兑现该条失败语义。

**建议**（三选一，需在设计文档中明确）：

1. **研究专用严格模式**：为研究模板提供一种显式的错误捕获/上报机制（例如研究指标基类或上下文标志），让被吞掉的 `LinesOperation` 异常至少能被模板看到并使本次 run 失败；实现时不得改变普通回测的默认行为。
2. **限定指标实现方式**：要求研究因子以 `next()` 实现并自行声明域错误；在 DS45-08 中明确“线运算表达式内部异常无法被模板区分，按 NaN 处理”，并把“意外异常必须终止”限定为模板自身采集代码与 `next()` 实现可上报的异常。
3. **统一为 NaN 语义**：放弃“公式异常必须终止”，改为“所有公式异常都视为该因子该时点缺失并计入损失”，但必须披露这会把代码 bug 伪装成数据缺失，并与 AC45-14 的原因分类保持一致。

无论选哪种，都应增加一个负例 fixture：让某个因子在 `next()` 中主动抛异常，或构造除零线运算，断言 run 的最终状态是**类型化失败**而不是“数据集充满 NaN 但状态 OK”。

## 附录 B — F-ICIR3 的可构造替代面板（供修订参考）

用 3 个资产，因子 `x=(1,2,3)`，三个评价期的收益分别为：

| 期 | y | Pearson IC | Spearman IC |
|---|---|---|---|
| 1 | (2,1,3) | 0.5 | 0.5 |
| 2 | (2,3,1) | -0.5 | -0.5 |
| 3 | (1,0,1) | 0.0 | 0.0 |

均值 = 0；`std(ddof=1)` = 0.5；ICIR = 0；正值占比 = 1/3。将 `min_assets` 设为 3（而不是 2），并保持标签全部有效，即可复现 F-ICIR3 的目标统计量。该面板已用 pandas 2.2.3 复算。

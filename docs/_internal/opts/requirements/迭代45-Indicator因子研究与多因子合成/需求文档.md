## 1. 目标与预期结果

本迭代为 Backtrader 用户提供统一的因子研究入口：用户用普通 `bt.Indicator` 定义或选择研究信号，通过一个公共策略模板配置单因子或多因子研究，不必为每个因子重写 `Strategy.next()`。运行时采集可用的原始观测；运行后可生成收益标签、截面变换、固定权重组合和研究统计，并保存数据以便离线复评。

通用分析能力由 fincore 的本地 `dev` 独立实现、验收并提交，Backtrader 再通过公开接口接入。Backtrader 负责 Indicator 构建、时钟和资产绑定、采集数据集及适配；不在 Backtrader 另写一套统计核。

本迭代完成时必须具备公共模块、针对性验收、用户文档、一个单因子例子和一个多因子例子。当前仅整理文档；全部功能项仍为待实现状态。

## 2. 使用者与用户流程

目标用户是使用 Backtrader 数据源和 Indicator 开展离线因子研究的研究者。预期流程如下：

1. 为加载的数据源指定稳定且唯一的资产名称，并声明 `calendar_id`、`frequency`、Feed 时间戳语义、研究组、价格口径和数据版本。`universe` 只描述研究窗口成员；指标 warmup 使用的更早行情与成员资格分开。
2. 定义或选择一个普通 Indicator 类，配置真实支持的参数、输出线、方向，以及必要时的目标资产和基准输入绑定。
3. 将因子配置交给统一的 `FactorStrategy`。模板按目标资产创建独立 Indicator 实例，并按各资产和各因子的实际可用状态采集观测；用户不另写策略执行循环。
4. 研究运行结束后，对保存的数据集选择收益标签、持有周期、截面变换和固定组合配置，调用 fincore 完成评价。
5. 查看覆盖、样本损失、相关性、基础因子与组合结果，导出 CSV/JSON；需要图表时显式启用 PNG 渲染。
6. 保存数据集后可在没有 Cerebro 或 Indicator 的情况下调整评价配置并重新评价。

## 3. 术语与统计边界

| 术语 | 本需求中的含义 |
|---|---|
| 因子 | 在一个评价时点、一个目标资产上产生一个标量值的研究信号。一个单因子研究可以覆盖多个资产。 |
| Indicator 类 | 用户提供或选择的普通 `bt.Indicator` 类；模板根据配置和目标资产创建实例。 |
| 目标资产 | 该次因子输出和研究评价所对应的资产。 |
| 基准输入 | 因子公式可显式绑定的额外数据输入，例如基准行情；默认不加入被评价资产池。 |
| 研究时点 | 按本轮明确的时间网格和可用性规则采集、分组及评价的时点，不自动等同于任何市场的自然日。 |
| PIT / 点时可用 | 观测只在其真实可获得时间之后进入研究，不使用未来才可见的数据。 |
| 可用性状态 | `READY`、`NOT_READY`、`NO_CURRENT_BAR`、`NONFINITE_INPUT`；分别表达已就绪有限值、预热不足、网格时点无当前 bar、显式合法 NaN。正负无穷按计算失败终止。 |
| 截面 | 同一评价时点、同一明确研究组内的资产集合。单资产数据不构成已通过的截面研究。 |
| 研究收益标签 | 运行后构造的未来价格收益或调用方提供的预计算收益，用于评价信号；不代表实际成交、账户净值或可实现利润。 |

资产标识、因子输入和收益接口保持市场中立；这只表示接口不把资产类型硬编码为股票，不表示全市场、所有日历、数据源或市场语义均已验证。用户必须声明输入数据适用的分组、时钟和价格口径。

## 4. 范围与明确排除项

### 4.1 本轮范围

- 单因子与多因子共用一个模板；单因子是因子集合只有一项的配置。
- 按资产实例化普通 Indicator，指定输出线，并支持目标资产与显式命名的额外基准输入绑定。
- 按因子就绪状态采集原始面板，管理研究时点、预热、标签价格尾部、资产池和数据可用性。
- 保存并加载可复评数据集；在 fincore 中提供本轮缺失的标签、截面处理、组合和统计能力。
- 固定方向与非负权重的命名组合、共同样本比较、因子相关性和逐因子消融。
- 导出研究数据和统计结果；支持显式启用的可选图表依赖。
- 交付可复制、离线运行的单因子和多因子示例及用户指南。

### 4.2 本轮不做

- 单资产时序 IC、任意依赖全市场状态的自定义 Indicator 自动评价，以及一个输出属于资产对的价差因子。输入或输出粒度不符合本需求时必须明确报错，不得伪装成普通单资产因子。
- 机器学习因子、因子训练、自动调参、根据全样本结果自动选方向、动态 IC 权重、自动组合优化器。
- 下单、仓位分配、融资保证金、跨币种账本、真实成交收益、实盘或账户认证能力。
- HAC 或 Benjamini–Hochberg（BH）多重检验校正、通用分析 UI、未列明的 HTML/PDF/XLSX 报告框架，或为扩大范围新增的报告类型。
- 自动补齐未提供的财报可用时间、退市收益、复权版本、期货换月、资金费率、交易日历或历史资产成员。数据语义由输入合同负责。

## 6. 非功能要求与兼容边界

### 6.1 可复现与可追溯

- 相同数据集、版本和配置应得到确定且可复算的结果；记录时区、数据版本、资产分组、因子类及参数、输出线、标签、方向、变换、权重和库版本。
- 原始因子值、方向调整值、变换值、组合评分和收益标签必须能区分；处理不得覆盖原始面板。
- 结果分别说明使用原始收益、超额收益或组内调整收益；分组分析不得被描述成行业或市值回归中性化。
- 重叠持有期收益不得未经定义就逐期连乘并标成真实净值。统计显著性和 IC t 检验的 IID 限制必须披露；本轮不新增 HAC 或 Benjamini–Hochberg（BH）多重检验校正。

### 6.2 Backtrader 兼容性

- 保持普通 Indicator、Feed、Cerebro、Strategy 的现有使用方式；新研究功能是可选路径，不改变普通回测默认行为。
- 保留 `setup.py` 当前必装依赖声明和 Backtrader 现有 Python 支持边界；本轮不把 fincore 或新增 renderer 加入无条件依赖，也不新增仅重复声明 pandas 的 research extra。新增研究域和 fincore 不得由既有核心路径 eager import。研究采集/持久化要求 Python 3.11+ 与 pandas，不要求 fincore；评价要求已验收 fincore；表格评价不主动加载新增 renderer，PNG 仅在显式请求时加载它。集成及复制安装验收须使用两仓已提交源码构建的 Backtrader/fincore wheel，附精确版本、wheel 哈希和依赖锁。
- 仅接受设计规定的目标资产标量输出，以及目标资产加一个基准的多输入合同。市场级、资产对和其他额外输入均不支持。Replay、live、tick、mixed-timeframe、resample 和其他不支持时钟必须明确报错，不猜测或自动转换。

### 6.3 数据质量与容量

- 系统不把接口中立等同于历史数据完备；成员历史、退市收益、复权、合约和市场日历边界由输入合同及结果覆盖报告披露。
- 对示例和验收使用固定、确定性的小型公开或合成数据。记录选定规模下的耗时和内存；未测量的高频、大资产池能力不作保证。
- 对所有用户配置进行明确校验；无效参数、缺少输入、标签尾部不足或可选依赖缺失不得静默成功并产生空白报告。

## 7. 交付要求与完成判定

外审和实施需要围绕以下交付核对：

- **fincore `dev`**：补齐标准面板上的标签、截面变换、固定组合、Pearson/其他缺失绩效、共同样本、相关性、消融及结果输出能力；单独测试、文档化并按轮提交。
- **Backtrader `dev`**：研究模板、采集与时钟/输入适配、数据集保存/加载、fincore 接口适配、指南和两个示例；每轮只提交已经验收的范围。

## 1. 目标与预期结果

本迭代为 Backtrader 用户提供统一的因子研究基础设施：所有因子公式统一由 `FactorIndicator(panel_mode="next")` 进入并遵循真实 Backtrader 生命周期；公式算法自身决定时序、截面或行业计算。45先用 R0 完成 Alpha#3 最小原生闭环，再经 R1–R10 独立交付全套 45 native 范围（20 个代表式、fincore、示例 025/026）；迭代46将 native 覆盖扩至 101/101；迭代47新增 build 编译前端并完成 20 式与 native 等价；迭代48补齐全 101 build。迭代45不实现 build DSL，也不以既有 027 expression 原型作为 native 验收。任一轮都不把代表式结果宣称成完整公式库。目录包含 18 个时序、65 个无行业截面、18 个行业公式。运行时采集可用原始观测；运行后可生成收益标签、截面变换、固定权重组合和研究统计，并保存数据以便离线复评。

通用分析能力由 fincore 的本地 `dev` 独立实现、验收并提交，Backtrader 再通过公开接口接入。Backtrader 负责 Indicator 构建、时钟和资产绑定、采集数据集及适配；不在 Backtrader 另写一套统计核。

迭代45完成时必须具备公共模块、针对性验收、用户文档、一个单因子例子和一个多因子例子。本次先定稿文档，随后按用户授权实施45；截至本次规划定稿，AC45-01 至 AC45-30 均为 NOT_RUN。

## 2. 使用者与用户流程

目标用户是使用 Backtrader 数据源和 Indicator 开展离线因子研究的研究者。预期流程如下：

1. 为加载的数据源指定稳定且唯一的资产名称，并声明 `calendar_id`、`frequency`、Feed 时间戳语义、研究组、价格口径和数据版本。`universe` 只描述研究窗口成员；指标 warmup 使用的更早行情与成员资格分开。
2. 按 Alpha101 公式声明创建 `FactorIndicator(panel_mode="next")`；研究类统一继承 BT Indicator，公式算法决定其时序、截面或行业处理。它按原生 `params`、`__init__`、`self.datas`、`next` 风格运行。
3. 运行前按显式研究 grid 将每项本地行情对齐为 BT-compatible 历史视图，再由普通 Cerebro/Indicator tree 按真实 owner、clock、minperiod 调度计算；next-only 基线通过 `once_via_next` 支持 runonce，手写原生 `once` 优化须证明与 `next` 在同一 grid 索引、输出和有效性语义上等价。缺格写 NaN，不沿用上一格；不提供未来数组。Strategy.next 只采集结果，不替 Indicator 执行公式。面板结果由真实逐资产 scalar line 经 `self.outputs[data]` 映射并采集为 time×asset 数据集，不把字典塞入 line。
4. 研究运行结束后，对保存的数据集选择收益标签、持有周期、截面变换和固定组合配置，调用 fincore 完成评价。
5. 查看覆盖、样本损失、相关性、基础因子与组合结果，导出 CSV/JSON；需要图表时显式启用 PNG 渲染。
6. 保存数据集后可在没有 Cerebro 或 Indicator 的情况下调整评价配置并重新评价。

## 3. 术语与统计边界

| 术语 | 本需求中的含义 |
|---|---|
| 因子 | 在一个评价时点、一个目标资产上产生一个标量值的研究信号。一个单因子研究可以覆盖多个资产。 |
| FactorIndicator 类 | 因子研究统一入口，正常初始化的 `bt.Indicator` 子类；公式算法决定时序、截面或行业计算，每资产输出真实 scalar line。 |
| 目标资产 | 该次因子输出和研究评价所对应的资产。 |
| 基准输入 | 因子公式可显式绑定的额外数据输入，例如基准行情；默认不加入被评价资产池。 |
| 研究时点 | 按本轮明确的时间网格和可用性规则采集、分组及评价的时点，不自动等同于任何市场的自然日。 |
| PIT / 点时可用 | 观测只在其真实可获得时间之后进入研究，不使用未来才可见的数据。 |
| 因子研究可用性 | `FactorIndicator` 输出按 DS45-08 使用 MISSING_FIELD、NOT_YET_AVAILABLE、UNKNOWN_CLASSIFICATION、FORMULA_INELIGIBLE、INCOMPLETE_WINDOW、DOMAIN_ERROR；字段级缺失保留 reason，整类必需字段元数据缺失时拒绝输入。非研究普通 Indicator 保持 Backtrader 原有行为。 |
| formula_universe | Alpha101 公式求值用资产集合，覆盖 warmup 至研究结束；独立于评价用 universe，按静态 research group 求值。退池不抹除此前有效的时序历史。 |
| FactorIndicator | 45 native 范围使用受控 `FactorIndicator(panel_mode="next")`：它是正常初始化的 `bt.Indicator`，使用真实 owner/clock/minperiod/Lines 生命周期；next-only 基线由 `once_via_next` 提供 runonce 支持，手写原生 `once` 优化须证明与 `next` 在同一 grid 索引、输出和有效性语义上等价。面板资产输入均为按 grid 对齐的 BT-compatible 历史视图；每个资产输出为真实 scalar line，并由 `self.outputs[data]` 映射。公式的时序、截面或行业算法由 Alpha 定义决定，不改变统一研究入口。build/expression 是 47 才新增的编译前端；既有 027 expression 原型源码保留历史类名 `PanelFactorIndicator`，本轮不改该原型代码；它不构成本轮 `FactorIndicator` native 验收，也不等同于迭代47的 build 前端。 |
| 截面 | 同一评价时点、同一明确研究组内的资产集合。单资产数据不构成已通过的截面研究。 |
| 研究收益标签 | 运行后构造的未来价格收益或调用方提供的预计算收益，用于评价信号；不代表实际成交、账户净值或可实现利润。 |

资产标识、因子输入和收益接口保持市场中立；这只表示接口不把资产类型硬编码为股票，不表示每类资产都具备每个公式所需的价格、成交量、市值或行业历史，也不表示任意市场、日历、数据源均已验证。缺少必需输入时须明确失败并报告缺项，不能跳过公式或用空值冒充覆盖。用户必须声明输入数据适用的分组、时钟、价格口径及行业/市值映射的点时语义。

## 4. 范围与明确排除项

### 4.1 本轮范围

- 单因子与多因子共用一个模板；单因子是因子集合只有一项的配置。
- 以统一 `FactorIndicator` 入口按显式字段、PIT 和历史依赖绑定全部公式输入；不限制为目标资产加一个基准输入，公式内部可组合符合适用条件的原生多输入子 Indicator。
- 按共享面板合同管理多资产时点、目标资产及公式所需输入，采集原始面板；处理研究时点、预热、标签价格尾部、资产池和数据可用性。
- 建立完整 Alpha101 目录及全 101 项静态依赖结构和输入/PIT/算子/数据能力映射，按 18 个时序、65 个无行业截面、18 个行业公式分组；每项记录原公式语义、必需输入、输出含义和资产/行业边界，不要求本轮编译完整生产图或冻结所有精确 H。
- 为全部目录项建立静态依赖结构及算子/数据能力映射；仅为 20 个代表式手工核算并声明 lookback H（含预热），以原生 `FactorIndicator(panel_mode="next")` 完成数值验收。不在 45 编译 DAG 或实现 build DSL；build 前端在 47 才新增，届时由 build 编译器自动推导 H。
- 保存并加载可复评数据集；在 fincore 中提供本轮缺失的标签、截面处理、组合和统计能力。
- 固定方向与非负权重的命名组合、共同样本比较、因子相关性和逐因子消融。
- 导出研究数据和统计结果；支持显式启用的可选图表依赖。
- 交付可复制、离线运行的单因子和多因子示例及用户指南。

### 4.2 本轮不做

- 单资产时序 IC、Alpha101 清单和面板算子合同之外的任意全市场状态自定义 Indicator 自动依赖追踪，以及一个输出属于资产对的价差因子。Alpha101 声明的截面及行业输入属于基础设施范围；清单外的未声明全市场依赖必须明确报错，不得伪装成普通单资产因子。101 个公式的 native 生产实现属于迭代46，build 实现属于迭代48。
- 机器学习因子、因子训练、自动调参、根据全样本结果自动选方向、动态 IC 权重、自动组合优化器。
- 下单、仓位分配、融资保证金、跨币种账本、真实成交收益、实盘或账户认证能力。
- HAC 或 Benjamini–Hochberg（BH）多重检验校正、通用分析 UI、未列明的 HTML/PDF/XLSX 报告框架，或为扩大范围新增的报告类型。
- 自动补齐未提供的财报可用时间、退市收益、复权版本、期货换月、资金费率、交易日历或历史资产成员。数据语义由输入合同负责。

## 6. 非功能要求与兼容边界

### 6.1 可复现与可追溯

- 相同数据集、版本和配置应得到确定且可复算的结果；记录时区、数据版本、资产分组、因子类及参数、输出线、标签、方向、变换、权重和库版本。
- 原始因子值、方向调整值、变换值、组合评分和收益标签必须能区分；处理不得覆盖原始面板。Alpha101 全部目录项须有静态依赖结构及输入/PIT/算子/数据能力映射；45对20个测试/诊断配方使用原生 Indicator、人工核算 lookback H 和独立数值 fixture，不编译 DAG；不能把它们扩称为 101 项生产实现。#42/#48/#53/#54 的 delay-0 交易时点标记与原始收益复现边界分开记录。
- 结果分别说明使用原始收益、超额收益或组内调整收益；分组分析不得被描述成行业或市值回归中性化。
- 重叠持有期收益不得未经定义就逐期连乘并标成真实净值。统计显著性和 IC t 检验的 IID 限制必须披露；本轮不新增 HAC 或 Benjamini–Hochberg（BH）多重检验校正。

### 6.2 Backtrader 兼容性

- 保持普通 Indicator、Feed、Cerebro、Strategy 的现有使用方式；新研究功能是可选路径，不改变普通回测默认行为。
- 保留 `setup.py` 当前必装依赖声明和 Backtrader 现有 Python 支持边界；本轮不把 fincore 或新增 renderer 加入无条件依赖，也不新增仅重复声明 pandas 的 research extra。新增研究域和 fincore 不得由既有核心路径 eager import。研究采集/持久化要求 Python 3.11+ 与 pandas，不要求 fincore；评价要求已验收 fincore；表格评价不主动加载新增 renderer，PNG 仅在显式请求时加载它。集成及复制安装验收须使用两仓已提交源码构建的 Backtrader/fincore wheel，附精确版本、wheel 哈希和依赖锁。
- 统一 FactorIndicator 研究入口通过显式字段/PIT/历史依赖绑定数据，允许按公式需要组合多个对齐输入和原生多输入子 Indicator；公式结果仍按 (time, asset) 归属。非研究的普通 Indicator、Feed、Cerebro、Strategy 使用方式保持不变。此范围不承诺任意用户 Indicator 的全市场依赖自动追踪；资产对输出、隐式输入和未声明时钟仍不支持。公式要求的市值、行业或行情输入缺失/未通过 PIT 校验时，必须明确失败，不能因接口市场中立而声称所有资产可运行所有公式。Replay、live、tick、mixed-timeframe、resample 明确报错。

### 6.3 数据质量与容量

- 系统不把接口中立等同于历史数据完备；成员历史、退市收益、复权、合约和市场日历边界由输入合同及结果覆盖报告披露。
- 对示例和验收使用固定、确定性的合成多资产面板；冻结全 101 项的静态依赖结构及输入/数据/PIT/算子能力映射。45以20个代表式验证原生计算、手工 lookback H 和数值；47再验证 build 编译与自动 H。记录选定规模的耗时和内存；未测量的高频、大资产池能力不作保证。
- 对所有用户配置进行明确校验；无效参数、缺少字段、PIT 不可用、标签尾部不足或可选依赖缺失不得静默成功并产生空白报告。

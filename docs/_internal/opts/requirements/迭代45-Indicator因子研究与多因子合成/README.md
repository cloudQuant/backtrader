# 迭代 45 外部评审包

版本：**v0.2**；整理日期：**2026-10-21**；状态：**文档待外审，功能未开发，AC45-01–22 全部 NOT_RUN**。

本迭代让用户用普通 `bt.Indicator` 定义因子，通过公共 `FactorStrategy` 完成单因子、多因子和固定组合研究。Backtrader 负责指标生命周期、数据采集与接入；新增通用分析功能在 fincore 的现有本地 `dev` 实现并独立验收提交，再由 Backtrader 的现有本地 `dev` 集成验收提交。两个离线运行示例属于必交付项。

当前这五份文件可以整体交给审阅者；代码片段、测试路径和示例命令都是目标合同，不是可用功能说明。本轮不需要也不允许通过启动实盘或账户认证来审阅。

## 3. 希望外审重点回答的问题

| 主题 | 已给出的候选决定 | 建议核查 |
|---|---|---|
| 使用成本 | 用户只写Indicator/配置，但显式提供研究grid/资产/来源合同 | 是否足够复用；需要的信息是否明确可获得；接口是否有遗漏 |
| 多资产与多输入 | 单次run共享可比grid；目标+一个基准完整对齐；Replay/live/混合周期初版拒绝 | 边界是否符合本轮实际研究，是否有无法实现或误导的承诺 |
| 标签与样本 | next-open需要h+1尾部；缺价不跳bar；先分位后各h过滤；分期标签不跨边界 | 是否会泄漏未来、压缩时间或误删短周期样本 |
| 多因子比较 | 每列先变换再合成；明确比较集合共同池；消融不扩池；IC差值按共同有效期 | 是否存在样本选择、变换顺序或比较分母偏差 |
| 退化与统计 | qcut不拆ties；分位失败保留合法IC；明确max_loss和未年化ICIR | 默认值是否适合业务，异常是否会被错误解释成差绩效/成功 |
| 跨仓接口 | fincore独立分析且先验收提交，BT只采集/适配 | 是否有重复算法、隐式私有API、循环依赖或未提交依赖 |
| 可验收性 | 小型手算fixture、真Cerebro+fincore、离线复评、安装与两例 | 用例是否足以区分正确/错误实现，是否缺关键负例 |
| 范围与节奏 | 先公共能力后单因子和多因子例子，7轮小提交 | 是否存在不必要范围、关键依赖顺序错误或过大的单轮 |

不要求外审者证明因子盈利，不将合成数据IC正值当通过条件；本轮也不验证所有资产市场的收益/账户语义。请将“必须解决的正确性问题”与“后续可选增强”分开，避免把外审变成新项目范围。

## 4. 评审意见记录格式

建议每条意见包含以下字段，可直接在评审回复中填写：

| 字段 | 内容 |
|---|---|
| 问题编号 | REVIEW45-001 起顺序编号 |
| 定位 | 文件、REQ/DS/AC ID及相关段落 |
| 严重程度 | 阻止基线确认 / 实施前需澄清 / 可选建议 |
| 问题与影响 | 具体输入触发什么错误、歧义或遗漏；尽可能给反例 |
| 建议 | 明确的替代口径或需要补的断言；说明是否变更范围 |
| 处置 | 待处理 / 已采纳 / 未采纳及理由；对应文档修订版本 |

请不要只给“总体可行”。对于统计/时间问题，给一个可以区分正确和错误实现的小输入最有价值；对于接口问题，指出用户无法完成的具体调用或缺失字段。

## 5. 评审后的收口流程

1. 汇总并处理阻止基线确认的问题，给每项处置及理由。
2. 同步修改需求、设计、验收和计划中受影响的引用/规则，保持追溯关系。
3. 在 README 记录评审者、日期、结论和剩余边界，将文档标记为已确认基线；未解决的正确性问题不记为通过。
4. 按用户后续安排开始 R1；本次文档请求本身不启动开发。
5. 后续每轮实现、验收、scoped commit，记录两仓修订；功能AC到实际执行后再更新状态。

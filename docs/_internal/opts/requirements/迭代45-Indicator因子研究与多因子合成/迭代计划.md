## 1. 目标与完成定义

让研究者只编写或选择 `bt.Indicator`，通过统一 `FactorStrategy` 和配置完成单因子、多因子及合成因子的研究，不为每个因子重新编写 `Strategy.next()`。

用户负责：

1. 用 `Cerebro.adddata()` 加载研究数据并指定稳定的资产名称。
2. 定义 Indicator，或选用已有指标，提供参数与输出线。
3. 配置资产池、研究时间、未来收益口径、持有周期和分组规则。
4. 多因子研究时配置方向、标准化方式与固定合成权重。

公共模块负责指标实例构建、预热与时间对齐、因子采集、收益标签、截面处理、因子合成、fincore 适配、评价与结果导出。

**本迭代完成必须同时具备：可复用模块、通过的针对性验收、用户文档、一个可运行单因子例子、一个可运行多因子例子。** 两个例子安排在公共能力完成之后交付，是本迭代的必交付项，不能留作迭代外的“后续补充”。

单因子指一个研究信号，可以覆盖多个资产；不等于只加载一个资产。截面 IC 要求同一评价时点有足够资产，单资产输入不能冒充截面研究通过。

## 2. 调研结论与范围

### 2.1 已核查事实

| 事实 | 设计影响 |
|---|---|
| Indicator 支持声明多条输出线、参数、最小周期，以及 `next/once` 计算 | 不新增另一套因子公式基类；普通 Indicator 即可接入 |
| Indicator 可以接收多个数据输入，现有 OLS 指标有 `_mindatas = 2` | 支持目标资产加基准的因子，但额外声明输入绑定和输出归属 |
| 当前 Strategy 的最小周期状态综合多条数据 | 统一处理 `prenext/nextstart/next`，避免晚上市资产阻塞所有已就绪资产 |
| fincore 0.5.1 有独立 `factor_analysis` 域 | 复用其数据准备、Rank IC、分层收益、换手和图表；补充 Backtrader 适配 |
| fincore 的因子 IC 函数固定为 Spearman，没有 Pearson 切换参数 | 分别命名 Pearson IC 与 Rank IC；Pearson 由公共分析模块补齐 |
| fincore 接收 pandas 因子面板，不直接接收 Cerebro 或 Indicator | 先形成统一数据集，再调用分析函数 |
| fincore 0.5.1 要求 Python >= 3.11；Backtrader 当前核心声明 >= 3.8 | 作为可选分析依赖，不能无意提高整个核心包的 Python 下限 |
| fincore 因子 tear sheet 返回图与表，通用 portfolio report 是另一接口 | 本轮明确交付 CSV、JSON、PNG；不宣称已具备因子 HTML/PDF/XLSX 原生导出 |

### 2.2 本轮范围

- 单因子和多因子共用一个 FactorStrategy；单因子是因子集合只有一项的情形。
- 每资产输出一个标量的因子；输入可以是该资产，也可以是目标资产加显式绑定的基准。
- 当期截面排名、Z-score、方向调整、固定权重合成，以及多个命名组合的对比。
- 基础因子、合成因子、因子相关性、共同样本比较与消融分析。
- 规则 bar 的日频研究完整示例，以及规则分钟数据的时间/标签契约验证。
- 资产标识和收益接口不绑定股票；跨市场使用必须显式声明研究分组、时间和价格口径。
- 运行中只采集当时可用因子；运行后计算未来收益和评价；支持保存数据后离线重新评价。

### 2.3 扩展边界

- 任意全市场依赖的自定义 Indicator、输出属于资产对的价差因子、单资产时序 IC：保留输入/输出粒度扩展位置，本轮不假装能够自动识别和评价。遇到未支持粒度须明确报错。
- 多因子机器学习、IC 动态权重、自动调参、组合优化器不纳入本轮；不根据全样本表现自动选择方向或权重。
- 本轮不新增自动订单、资产仓位映射、融资保证金或跨币种账户账本。研究收益不是 Broker 实际成交收益；未来交易回测可复用 Indicator 和组合配置，但需单独验收。
- 财报可用日期、复权版本、退市收益、连续期货换月、资金费率和交易日历由输入合同声明；不因接口允许资产名称就声称所有市场语义已验证。
- 不修改实盘 runtime、SDK、账户准入或历史认证流程。

## 3. 责任分层与代码归属

```text
Data Feed(s) -> Cerebro -> FactorStrategy -> 原始因子数据集
                                  |              |
                         构建各资产 Indicator     +-> 保存/加载
                                                 |
                                 截面处理 -> 固定权重合成
                                                 |
                                   收益标签 + fincore 适配
                                                 |
                                   单因子/组合评价与报告
```

| 部分 | 职责 | 不承担的职责 |
|---|---|---|
| Indicator | 因子公式、输入依赖、最小周期、输出线 | 未来收益、IC、报告、下单 |
| FactorStrategy | 构建实例、识别就绪和新数据、按研究时点采集 | 为每个因子硬编码排名或评价公式 |
| 截面处理/合成器 | 同时点同资产池变换、方向与固定权重 | 从未来收益反推当期方向或权重 |
| 标签与评价模块 | 价格/收益对齐、调用 fincore、补充 Pearson 与比较 | 把研究组合收益标记为成交收益 |
| 数据集/结果对象 | 保存原始观测、配置、有效样本、统计与导出 | 自动重新运行 Cerebro |

拟新增 `backtrader/research/` 包，公开入口为 `backtrader.research.factor_strategy.FactorStrategy`。按职责组织 `models.py`、`factor_strategy.py`、`transforms.py`、`labels.py`、`fincore_adapter.py`、`evaluation.py` 和必要的导出模块；不为凑文件数拆分。R1 固定实际公开接口与导入路径。

仅在显式调用评价/渲染功能时加载相应可选依赖。优先复用当前 Indicator、Feed 和 Cerebro 生命周期；不重写引擎调度或修改核心时钟作为捷径。采集器可以使用内部辅助对象，但对外保持一个模板入口。

## 4. 对外接口合同

以下代码是本迭代目标接口，尚未实现。统一采用 `factors` 映射，不另外维护一套行为不同的单因子策略。

### 4.1 单因子

```python
from backtrader.research.factor_strategy import FactorStrategy
from factors import CloseMAFactor

cerebro.adddata(data_a, name="A")
cerebro.adddata(data_b, name="B")
# 实际研究加载满足 min_assets 的资产集合。
cerebro.addstrategy(
    FactorStrategy,
    factors={
        "close_ma": {
            "indicator": CloseMAFactor,
            "params": {"period": 20},
            "line": "factor",
            "direction": 1,
        },
    },
)
strategy = cerebro.run()[0]
result = strategy.evaluate(
    periods=(1, 5, 20),
    quantiles=5,
    label="next_open_to_open",
    min_assets=10,
)
```

### 4.2 多因子

```python
cerebro.addstrategy(
    FactorStrategy,
    factors={
        "close_ma": {
            "indicator": CloseMAFactor,
            "params": {"period": 20},
            "line": "factor", "direction": 1,
        },
        "roc": {
            "indicator": ROCFactor,
            "params": {"period": 20},
            "line": "factor", "direction": 1,
        },
        "kdj": {
            "indicator": KDJFactor,
            "params": {"period": 9, "period_dfast": 3, "period_dslow": 3},
            "line": "J", "direction": 1,
        },
    },
)
strategy = cerebro.run()[0]
result = strategy.evaluate(
    preprocess="cross_section_rank",
    combinations={
        "equal_weight": {"close_ma": 1 / 3, "roc": 1 / 3, "kdj": 1 / 3},
    },
    periods=(1, 5, 20),
    quantiles=5,
    label="next_open_to_open",
    min_assets=10,
)
```

示例三个方向均为 `+1` 是明确的演示假设，不表示已经证明三个因子均正向有效。未来修改 KDJ 为反转假设时，通过 `direction=-1` 表达并记录为新的研究配置。

### 4.3 规范化和错误处理

- 传入 Indicator 类，由模板按研究目标创建实例；拒绝把已绑定其他运行生命周期的实例直接复用。
- 每个因子名称唯一；输出线存在；参数交给该 Indicator 的真实构造合同校验，不能只看默认值猜测类型。
- 内部规范化为 FactorSpec：名称、类、参数、输出线、方向、输入绑定、输出资产角色。新因子默认单资产输入；额外基准按 feed 名称显式绑定，并排除出默认被评价资产池。
- 输入绑定只使用已加载的数据；未声明的基准、重复资产标识、未知组合成员、非法方向和非有限权重给出明确错误。
- 研究期间保存原始数据；`evaluate()` 只读取完成采集的数据，不再执行 Indicator 或 Cerebro。
- 选用不同持有期、分组数、固定权重时可以重新评价；需要的数据或尾部价格不足时报告缺口，不自动补数据或复算。

## 5. 数据、时钟与收益标签

### 5.1 统一数据集

- 因子面板：唯一 `(evaluation_time, asset)` 索引，每个因子一列；保存未经方向调整或标准化的原始值。
- 价格面板：时间为行、资产为列，至少保存研究口径所需的 open/close；包含因子研究期之后足够的价格尾部。
- 可用性：资产是否在当期资产池、各因子是否预热/有效、输入实际时间、因子可用时间、缺失原因。
- 元数据：数据来源/快照标识、时区、交易日历、bar 频率、资产分组、复权或合约口径、研究范围、因子类与参数/输出线、代码版本和库版本。
- 原始采集、处理后因子、组合分数与收益标签分别保存，避免原地覆盖而无法追溯。

### 5.2 采集规则

1. 公共处理覆盖 `prenext/nextstart/next`，按资产与因子自身的依赖就绪状态采集；未就绪数据记缺失，不填零。
2. 默认只使用研究时点已确认、已闭合的 bar；数据时间未推进时不重复添加记录。Replay 同一 bar 更新应采用明确的最终观测规则，不累计重复样本。
3. 多输入因子要求绑定输入在共同评价时点有效；默认严格对齐，不默默用陈旧基准补齐。未支持的混合周期或不规则时钟组合给出明确限制。
4. UTC/本地时区转换规则显式记录，拒绝混合 naive/aware 时间。不同市场同名“日期”不自动视为同时可用。
5. 资产池采用当期可用成员信息；没有历史成员或退市数据时报告覆盖边界，不能声称消除了幸存者偏差。
6. 财务等非行情特征必须由调用方按真实可用时间进入输入；Indicator 的形式本身不保证 point-in-time 正确。

### 5.3 收益标签

在明确的共同研究 bar 网格上，`h` 表示 h 个研究 bar，不表示 h 个自然日：

| 标签 | 定义 | 用途 |
|---|---|---|
| `close_to_close` | `close[t+h] / close[t] - 1` | 收盘信号与后续收盘收益的统计关系，不宣称可在同收盘成交 |
| `next_open_to_open`（示例默认） | `open[t+1+h] / open[t+1] - 1` | 收盘后得到信号、下一 bar 开盘进入并持有 h 个 bar 的研究标签 |
| 预计算收益 | 调用者提供 `(time, asset)` 对齐的分周期收益及语义 | 特殊市场、合约或外部明确价格口径 |

`next_open_to_open` 最长周期需要至少 `h+1` 个后续 bar 的价格；研究期与价格尾部区间分开配置。缺失目标时点价格时，该资产该周期标签缺失，不前向填充价格，也不跳过停牌 bar 改写持有期。

所有标签只用于运行后的分析，不进入当期 Indicator 或合成方向/权重。对每个持有周期分别统计有效样本，不能因 20 期标签缺失删除已有 1 期标签。分位归属必须先由当期因子/资产池确定，再按该周期收益可用性过滤。

对于自定义标签，不能直接假设 `prepare_factor_data_from_forward_returns()` 自动具备上述分箱顺序；适配层须验证并保持相同规则，必要时先调用公共分箱核，再构造 fincore 已清洗输入。不能通过给缺失收益填零保住分位组。

## 6. 多因子处理与合成

处理顺序固定为：**当期资产池与因子可用性 → 方向调整 → 每因子截面变换 → 按名称对齐固定权重 → 合成评分**。不使用收益标签决定变换样本。

| 配置 | 本轮规则 |
|---|---|
| 方向 | `+1/-1`，先乘原始值；来自明确研究假设，不能全样本自动翻转 |
| `cross_section_rank` | 同时点同研究组内平均秩；n>=2 时转换为 `2*(rank-1)/(n-1)-1`，并列值取平均秩 |
| `cross_section_zscore` | 同截面均值与总体标准差（ddof=0）；零方差列变换为 0 并记录退化，不能据此生成有效 IC |
| `none` | 明确选择才直接使用原始尺度；记录该设置，不把原始值加总描述成已统一尺度 |
| 固定权重 | 按因子名匹配，非负、有限且总和大于 0；归一到总和 1，负方向统一由 direction 表达 |
| 缺失 | 默认所有被选因子均有效才进入该组合的当期变换/输出；不填零，不自动按剩余因子重分权重 |
| 多个组合 | 各自保存成员、权重、变换资产池和覆盖率；不要求再次计算 Indicator |

原始因子独立报告允许使用各自有效资产池；组合使用其完整因子集合对应的共同池。额外的公平比较报告使用完整组合的共同池，并在该池重新执行全部被比较方案的变换。

三因子等权组合定义为 `score=(transformed_close_ma + transformed_roc + transformed_kdj)/3`。权重是信号组合系数，不是资产持仓比例。先加原始值再排名，不等价于分别排名再加权，必须以手算例验证这一差异。

消融比较固定使用完整组合的共同池：分别移除一个因子，对剩余权重归一后评价；不因移除因子扩大样本而制造增量效果。因子相关性按日期、研究组计算，再汇总时间序列，不将所有日期混在一起直接算一个相关系数。

## 7. fincore 适配与研究输出

### 7.1 依赖与适配

- 首个经过验收的版本固定为 fincore 0.5.1，导入其公开叶模块；不使用已退休的 `fincore.alphalens` 或不存在的根级兼容函数。
- 普通价格口径可使用 `prepare_factor_data_by_horizon()`；明确标签可使用预计算收益入口或经验证的已清洗表，遵守第 5 节分箱与样本规则。
- 如果接收 fincore PIT 观测账本，先按评价时点物化，再走分周期准备；`prepare_pit_factor_data()` 本身不能视为已自动完成分周期独立筛选。
- `analyze_factor()` 分别处理每个基础因子和每个合成评分；它不会自动将多列因子训练或合成。
- 准备入口按因子名从原始多列面板提取一条 `(date, asset)` Series；逐个调用，保留输出与因子名的映射。初版显式设置 `include_portfolio_inputs=False`，研究评价不依赖默认的 `1D` 组合输入，也不生成模拟交易明细。
- 关闭全样本未来收益的 `filter_zscore`；保留并导出每周期的损失报告，不能通过随意提高 `max_loss` 掩盖数据缺陷。
- 验证全局返回默认值、demean/group-neutral 等设置，结果写明使用原始收益还是超额/组内调整收益。分组分析不等于已经完成行业和市值回归中性化。
- Python < 3.11 仍可使用既有 Backtrader 核心；本研究评价功能明确提示所需环境。可选依赖缺失时不影响普通回测导入。
- 仅需要表格时不导入图形后端；PNG 图表显式使用可选可视化依赖与无界面后端。

### 7.2 结果要求

| 结果 | 口径与要求 |
|---|---|
| Pearson IC | 每日期/组内因子值与对应未来收益的 Pearson 相关，由公共层计算 |
| Rank IC | 同样本 Spearman；复用 fincore，不能误标成 Pearson |
| IC 汇总 | 每周期均值、样本标准差 ddof=1、未年化 ICIR=均值/标准差、正值占比和有效期数；零标准差的比率给缺失及原因 |
| 原始与处理后评价 | 字段明确标出 raw、oriented、transformed 或 composite；不得把不同输入口径合并成一个无说明的 IC |
| 分层收益 | 各分位组收益、样本数、最高减最低收益差及单调性展示；收益是否 demeaned 明示 |
| 多周期表现 | 各持有周期独立样本/损失统计；以此展示预测期限变化，不冒充因子秩自相关 |
| 稳定性 | 分期/月度 IC、因子排名自相关、覆盖率和分位成员换手 |
| 因子相关性 | 逐期截面 Spearman 矩阵及时间汇总，报告每对有效样本量 |
| 组合对比 | 基础因子、完整组合和三个去一因子组合；同时有自身样本和共同样本口径 |
| 解释性信息 | 因子/标签/组合配置、资产池、时间范围、清洗原因、库版本、数据来源与参数 |

截面不足 `min_assets`、分组样本不足、重复值不能满足指定分位数、常数因子/收益、全缺失时，不伪造 0 IC，不任意拆散相同值。记录原因与有效样本；没有可评价截面时整体结果为不可评价。

fincore 的 IC t 检验具有独立同分布假设，本轮可以保留为有明确标注的描述性结果；重叠持有期不能据此直接宣布显著。样本外按明确时间段评价，并保留组合试验配置；不新增 HAC 推断或自动择优器作为本轮完成条件。

### 7.3 保存、复用和导出

提供带 schema 版本的数据集保存/加载接口；默认交付可读 CSV 与 JSON 元数据，数值精度、时间戳及时区往返需验证，不以 pickle 作为公开交换格式。

保存原始面板、必要价格、可用性和元数据，而不是只保存一张 IC 表。加载后更换周期、分组或固定权重，必须在没有 Cerebro/Indicator 调用的情况下得到结果。元数据记录数据与因子定义的版本/指纹；不匹配时拒绝复用旧结果。

结果至少导出：因子面板、合成评分、逐期 IC、分层收益、覆盖/损失报告、因子相关性、组合比较和 JSON 摘要。开启图表时输出 IC 时序、多周期/分层收益及多因子相关性图。报告只标记“离线因子研究”，不声称是真实交易或实盘证明。

多期重叠收益不能直接逐日连乘充当真实净值；若展示研究累计曲线，须声明持有/重叠组合算法，否则本轮仅展示分层收益与统计表。

## 9. 必交付示例

### 9.1 单因子例子：close/MA

拟目录：`examples/backtest/025_factor_single/`。

- 使用 `CloseMAFactor` 输出 `close / SMA(close, 20)`；分母为零或尚未预热时明确缺失。
- 加载至少 20 个资产、260 个有效研究日，另加充分预热与最长标签所需尾部，满足 5 分位研究。
- 内置小型确定性公开/合成 OHLCV 数据，说明其来源与用途；默认完全离线、不下载、不需要账户。合成数据的 IC 不代表真实市场有效性。
- 使用同一个 FactorStrategy，只注册一个因子；展示 1/5/20 bar 的 Pearson IC、Rank IC、ICIR、分层收益、分位成员换手、覆盖率和报告图。
- 展示保存数据集后调整评价周期的命令；该路径不再次运行 Cerebro。

20 个资产是示例数据规模；接口示意中的 `min_assets=10` 是可配置的单截面最低评价阈值，两者含义不同。指定 5 分位还必须满足有效不同值和分组条件；达到该数量阈值只表示可以计算，不表示统计结论可靠。

### 9.2 多因子例子：close/MA + ROC + KDJ.J

拟目录：`examples/backtest/026_factor_multi/`。

- 三个基础因子为 `close / SMA(close,20)`、20 bar ROC 和 `KDJ.J`。
- KDJ 明确使用 `J=3*K-2*D`，并写清 K/D 的平滑公式、参数和预热方式；核查现有 contrib 实现后复用或用薄包装实现，不将其他 KDJ 变体视为相同结果。
- 三因子分别方向调整、同截面平均秩标准化，然后等权合成；默认三个方向均为正向演示假设。
- 数据口径与单因子例子一致，使差异来自因子组合而不是价格、资产池或交易日历。
- 输出三个单因子、一个完整组合及三个去一因子组合的结果，同时输出共同样本比较、因子相关性和样本外分期统计。
- 用配置更换一个因子或权重即可复跑；不修改公共模板，也不在例子里重新实现研究/合成算法。

### 9.3 示例形态与运行验收

遵循现有 examples 四个核心入口约定：`README.md`、公开纯研究 `config.yaml`、`single_factor_strategy.py` 或 `multi_factor_strategy.py`、`run.py`；允许额外 `factors.py`、`data/` 和忽略的 `output/`。其中 `*_strategy.py` 只导入公共 FactorStrategy、声明本例因子/组合装配，不复制 Strategy 生命周期，也不为满足文件名而增加空的策略子类。

每例包含本地小数据或可离线确定性生成的数据源，不能运行时引用 `tests/`、相邻示例或 `examples/_support/`。复制示例到仓库外后，在已安装相应 Backtrader 与 fincore 的环境仍可运行。相对数据/输出路径按配置文件或例子目录解析，不依赖启动工作目录。

拟验收命令（实现后才成为可用命令）：

```console
python examples/backtest/025_factor_single/run.py --output-dir <single-output>
python examples/backtest/026_factor_multi/run.py --output-dir <multi-output>
python examples/backtest/025_factor_single/run.py --dataset <saved-dataset> --periods 1 10 --output-dir <reevaluation-output>
```

README 给出安装环境、数据说明、指标定义、配置方式、预期输出结构与示例结果解读。默认输出表和图，无图模式显式关闭渲染。缺数据或可选依赖时明确非零退出并提示原因，不以空报告成功退出。遵循既有示例 `0/1/2/3` 退出码含义，离线研究成功不代表策略盈利。

实施前复核 025/026 编号是否仍空闲；如被其他工作使用，仅按 examples 编号规则顺延并更新本计划、文档与验收命令。两个例子均纳入 `examples/README.md` 和用户指南索引。

## 10. 验收清单

所有项目初始为待验收；实现时逐项绑定具体测试/命令与结果，不用源码存在代替执行通过。

| ID | 必须验证的行为 | 判据 |

| AC45-01 | 单/多因子复用模板 | 新增因子只改变 Indicator/配置，例子无自定义 Strategy.next |

| AC45-11 | 共同样本与消融 | 同池重新变换；移除因子不扩大公平比较样本；权重重新归一 |
| AC45-12 | IC 与 ICIR | 非线性已知例区分 Pearson/Spearman；ddof、零方差、正值占比分母明确 |

| AC45-17 | 导出与图表 | CSV/JSON 可读且字段一致，PNG 无界面生成，重叠多期收益不伪装成交净值 |
| AC45-18 | 单因子例子 | 仓库入口与复制目录入口可执行，指标/标签/覆盖及产物均非空且正确 |

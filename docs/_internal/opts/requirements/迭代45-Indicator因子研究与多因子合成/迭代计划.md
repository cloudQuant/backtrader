## 2. 迭代45的产品目标

因子作者继续写Indicator：在`__init__`定义依赖和状态，在`next`计算，使用`self.p`、`self.datas`和数值line。单资产和截面因子统一用真实初始化的`FactorIndicator(panel_mode="next")`，内部优先组合原生Indicator/Lines，一次接收研究组全部资产，每资产有独立输出。用户配置同一个FactorStrategy，不为每个因子重写Strategy.next。

首批展示#3：同日open/volume截面排名→逐资产10格历史→Pearson相关取负。R0必须让用户看到手写算法、三个资产的中间排名、最终数值和运行命令，不先堆完101能力、报告、PIT行业和DSL再展示。

完整迭代45仍交付：统一单资产/多资产采集、profile/PIT及全部101所需算子能力、20个代表式、fincore标签/IC/RankIC/ICIR/分层/覆盖/换手/固定组合/共同池与导出、数据集保存加载与离线复评、025单因子和026多因子正式示例。R0不是缩减后的完整交付。

不做：expression/build实现、101个生产因子、订单/成交回测或成本账本、机器学习/动态权重、HAC扩展、跨频/replay/live、账户认证、原论文收益复现。资产中立不等于所有市场都有股票市值和历史行业数据。

## 3. 原生优先实现原则

- 复用BT真实构造、OwnerContext和指标依赖注册、Lines/LineBuffer、参数、minperiod及prenext/nextstart/next；优先使用既有once/once_via_next。不得`object.__new__`绕过初始化，或仅继承类名后手工拼self.datas。
- 研究入口先将本地同频bar按调用方UTC grid对齐，缺bar是NaN和明确present/available_at状态，不是前值填充；所有同步feed由Cerebro推进。原生Indicator树计算，模板回调只采集，不手动再调用因子next。
- `self.outputs[data].factor[0]`拟作为每资产真实数值线的访问映射；其游标/历史由原生机制推进。R0必须验证固定/可变资产数量的输出构造，不先自造buffer或第二套调度。无资产限定的单条float line不能承载整个截面。
- 私有panel owner/PanelEngine数值解释器不再是硬性前置。只有可复现的原生缺口，才做最小研究适配并记录影响；改核心clock/minperiod必须执行仓库要求的策略回归。
- 算子先做“原生现成可用 / profile需适配 / 真正缺失”复用表。现有指标的NaN、分母0、ddof、排名轴和窗口不匹配时显式适配，不修改原有默认结果。native不需要先实现表达式DAG编译器。
- 未来build只增加声明与编译入口，优先落到同一原生节点和数据合同；具体优化到47验证，45不为尚未测的性能预留另一套执行后端。

细节由[设计DS45-11](设计文档.md#ds45-11-面板声明与共享执行引擎)定义。R0若证明拟议输出映射/依赖时钟不可用，先修订这处设计并补回归，再进行R1；不能带着未验证的原生兼容承诺铺开20式。

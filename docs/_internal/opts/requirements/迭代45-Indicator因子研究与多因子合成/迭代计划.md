# 迭代 45 — Indicator因子研究与Alpha101计算基础设施

版本：**v0.5**；更新：**2026-10-21**。本版按用户决定调整实施顺序：**先交付原生 `panel_mode="next"`（真实 `bt.Indicator` 初始化、`self.datas` 同步资产视图、`__init__/next` 手写算法、逐资产输出线），`panel_mode="expression"`（`build` 声明、共享 DAG）放到最后交付**。设计/验收/README/两份 Alpha101 附件已按同一双模式合同及本实施顺序对齐；027 现有代码仍只是 expression 原型。本轮只更新文档；R1–R11 尚未开始，AC45-01–30 全部 NOT_RUN。用户明确：**迭代45建设充分支持Alpha101全部公式的基础设施，下一迭代才实现101个生产因子。** 本稿不开始开发，也不预先指定下一迭代编号。

## 1. 目标与交付边界

继续保持“因子逻辑写在Indicator类、统一FactorStrategy、Cerebro加载数据、不为每个因子重写Strategy.next”的使用方式。普通bt.Indicator保留逐资产line路径；涉及完整截面的公式先使用`panel_mode="next"`的真实PanelFactorIndicator实例：基类提供按grid发布的同步`self.datas`视图，作者在`__init__/next`中手写算法，并经`self.outputs[data].factor[0]`写逐资产输出线。`panel_mode="expression"`作为最后交付的公式直译/共享DAG前端，复用同一FactorStrategy、PanelEngine和get_dataset。两条路径最终都产生time×asset原始因子面板，再调用fincore评价。

本轮必须交付：

1. 普通Indicator采集、**原生panel生命周期与私有owner调度**、`self.datas`同步视图、逐资产输出线；expression声明/共享DAG作为最后阶段交付；全部所需时序/截面/行业算子与数据绑定能力，支持截面结果继续进入滚动运算。
2. 覆盖101个Alpha的数据和算子依赖映射，不能只保证close/MA、ROC、KDJ可运行；清单里的能力缺口必须闭合。
3. **20个结构不同的代表公式验收配方**，R4先用`panel_mode="next"`手写实现，R11再用`expression`实现并逐值对照；每个有独立已知答案/参考和边界用例，证明框架按原式运算。它们是基础设施测试材料，不是本轮发布的Alpha101生产库。
4. fincore的标签、IC/Rank IC、ICIR、分层、覆盖/换手、多因子固定合成、共同池/消融及报告；新增统计在fincore现有dev验收提交后由Backtrader接入。
5. 原始数据集保存/加载、离线复评、安装产物验证、指南和两个正式示例：单因子025、多因子026。
6. 下一迭代的接口、数据、算子、目录及逐公式验收交接清单，明确101个生产类尚未实现。

本轮不实现完整101生产因子库、不承诺原论文绩效、不新增下单/真实成交回测、成本账本、机器学习、动态权重、HAC或实盘认证。单资产时序IC、pair输出、任意Python全市场Indicator自动依赖追踪、panel与普通BT line互相依赖不在范围。`panel_mode="next"`的`self.datas`是声明的公式组同步视图，不是任意Feed列表；`self.outputs[data]`是面板内部采集接口，不是交易策略可直接消费的信号线。资产类别中立不等于每个市场具有Alpha101需要的股票市值/行业语义。

## 3. 架构决定与v0.5实施顺序

| 决定 | 实施合同 |
|---|---|
| 公式内部截面不等于评价排名 | Alpha#3的rank→滚动相关在PanelEngine里完成；fincore事后rank不能替代 |
| 同一基类两种写法，原生优先 | `PanelFactorIndicator`用显式`panel_mode`区分：`next`为真实初始化的Indicator实例，接收全组同步`self.datas`，作者写`params`/`lines`/`__init__`/`next`并经`self.outputs[data].factor[0]`输出；`expression`在最后阶段实现`build(ctx, **params)`类级声明，不创建普通实例。两种模式共用FactorStrategy、PanelEngine和get_dataset；不得把027原型整体搬入库视为实现。 |
| 两种模式都必须有真实输出 | `next`的`lines=("factor",)`是每资产输出schema，`panel_line`选择采集线；基类为每个data建立独立线容器、游标和历史。`expression`仍按每time/asset一个标量输出。正式结果只经`get_dataset()`；未指定资产的`self.lines.factor[0]`不能冒充整个截面，也不能静默取首资产。 |
| 逐资产输出线不是交易信号 | `self.outputs[data].factor[0]`是面板内部计算/采集接口，不自动等于交易策略可随时消费的原始Feed时钟线；跨调度树实时line依赖不在本轮范围。 |
| 手写模式同样受声明约束 | `panel_mode`显式、`panel_line`在next模式必填、`formula_fields`和有限非负整数`lookback_h`必须声明；字段/PIT/分类/profile校验不因手写而绕过。`self.datas`是按grid发布的同步资产视图，不是未经对齐的原始Feed；子指标归同一私有panel owner，不进普通调度树；自定义`once`、`object.__new__`、手拼`self.datas`和双调度均拒绝。 |
| 同一个共享引擎与同一个grid屏障 | prenext/nextstart/next在源bar同步后由模板推进完整grid；next模式由私有owner驱动真实实例及其依赖，expression模式执行共享DAG；runonce也在事件回放调用同一屏障。每个grid每种模式恰好推进一次；手写实例不合并状态、不自动推导DAG。 |
| build最后实现 | R1冻结两种合同；R2–R4只实现并验收next；R11a/b实现expression核心、共享DAG、20式等价和混合装配。expression不得以半成品提前混入next路径，也不得用next单模式替代双模式验收。 |
| 普通Indicator路径不变 | `execution="indicator"`保持既有lifecycle、line/inputs语义和默认错误规则；025/026现有示例不被panel改造改写。 |
| 三种池明确分开 | 公式formula_universe覆盖预热；研究universe限定评价资格；common池只改变评价变换，不能重算历史Alpha内部排名 |
| 完整数据合同 | OHLCV、日VWAP、美元成交额/ADV、市值和三层历史行业，附可用时点与来源；字段缺失不可伪造为0 |
| 版本化数值规范 | alpha101-v1固定公式rank r/n、窗口floor、TS轴、pow/SignedPower、min/max消歧、缺失和行业去均值；不同于评价[-1,1]rank |
| 全覆盖能力不等于全公式实现 | 全101静态映射+全部算子测试+20式端到端，作为下一迭代开工条件；101生产类和逐式生产验收留后续 |

公式内部算子、两种panel写法的构造/调度/输出、共享状态、输入时钟和原始因子面板归Backtrader计算层。评价阶段标准化、固定组合、标签、IC/ICIR、分位与通用报告归fincore，不能在Backtrader adapter另写统计核。两层出现“rank/相关”同名概念不代表可互换，数值合同和输入轴必须显式区分。next手写算法仍是受字段/PIT/profile/H约束的Indicator，不是绕过合同的任意Python沙箱；expression只是最后加入的声明前端，不改变执行语义。

## 5. 20个代表式的选择

完整案例、原文定位、输入构造与错误区分见[代表验收案例](Alpha101代表验收案例.md)。固定选择：**#1、#2、#3、#4、#7、#9、#13、#29、#48、#56、#58、#62、#63、#67、#81、#84、#92、#96、#100、#101**。

R4先用`panel_mode="next"`实现全部20式；R11b再用`expression`实现同一20式。两套实现必须分别对独立参考核对，再比较完整面板、NaN mask、原因和时间；不得只做相互一致测试，也不得用expression推迟R4的公式能力验收。

| 能力组 | 代表ID | 不能遗漏的特性 |
|---|---|---|
| 简单基线、条件和数值域 | 101、1、2、7、9 | 输出标量、where分支、std/argmax、log/delta、ADV条件、ts_min/max |
| 截面与时序交错 | 3、4、13、29 | rank→correlation、rank→ts_rank、covariance后rank、连续rank/scale/log/product及delay |
| 历史数据与分组 | 48、56、58、63、67 | 250日窗口、市值、sector/industry/subindustry、ADV180嵌套窗口、不同层级同时中性化 |
| 布尔、幂与复杂分支 | 62、81、84、92、96、100 | 布尔转数值rank、滚动乘积/对数、时变幂、逐元素min/max、argmax、多层中性化/缩放 |

必须用能区分错误实现的输入，不能只比较两条同源代码。重点包括：#3错误的“先相关再rank”、#4轴互换、#48仅备250根而忽略嵌套延迟、#67误用同一行业层级、#62把未知布尔当False、#96把max两表达式当窗口、#100错误合并层级/截面。相同分组下重复demean可能数学幂等，不能虚构必然不同的数值来验收图结构。

#3是首个端到端配方：R2原型、R4的next验收、R11b的expression验收都以它为主路径；027现有expression原型不作为R2通过证据。

代表式正向数值与分位可用性分开验收。条件型/二值因子不一定能分成5组，不为凑图打散ties或改公式；仍需有限结果且有正确退化原因。未选的81式仍在算子/数据覆盖检查内，本轮不声称它们的完整公式已经验证。

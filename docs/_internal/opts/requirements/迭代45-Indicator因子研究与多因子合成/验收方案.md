### 1.3 证据和通过原则

每项 AC 需分别记录状态、命令、输入 fixture 版本或哈希、预期与实际、容差、解释器、两仓分支/HEAD、实际导入来源、输出文件清单及 SHA-256。测试路径在实施后确定；本稿后文列出的测试路径均为“拟新增”，不得当成当前可运行测试。

状态含义：

- **NOT_RUN**：尚未执行；本文全部 AC 的初始状态。
- **PASS**：预先约定的断言全部通过，命令退出码为 0，证据可复核且输入来源符合要求。
- **FAIL**：产品代码或结果未满足断言；需在同一轮修复，不能以跳过该断言或换松阈值结案。
- **BLOCKED**：经证据确认的环境或外部依赖阻止执行。记录阻塞点和未执行断言；不得把 BLOCKED 计为 PASS。
- 分析结果状态按设计文档 DS45-08 固定为 **OK / PARTIAL / UNEVALUABLE**；它们不是 AC 验收状态。AC 状态仍用 NOT_RUN / PASS / FAIL / BLOCKED。

源码静态检查、mock fincore、pytest 通过、示例运行、安装产物检查分别只能证明其覆盖的层级。AC45-13 必须实际导入已提交的 fincore dev 产物并调用公开 API；仓内例子通过不能替代复制目录或隔离安装产物验证；任何正 IC、正收益或演示样例均不构成算法正确性或市场有效性判据。

## 3. 测试设置和断言摘要

设计文档 [DS45-05](设计文档.md#ds45-05-收益标签与分周期样本)、[DS45-06](设计文档.md#ds45-06-截面变换组合与样本池)、[DS45-07](设计文档.md#ds45-07-绩效与现有-fincore-差异) 和 [DS45-08](设计文档.md#ds45-08-结果损失与失败语义) 是公式、默认值、样本顺序与错误状态的唯一来源。本节只列独立手算 fixture 的设置和断言摘要；公式或实现若与设计不同，先修订设计和对应 AC，再运行验收。

所有微型分析调用显式设置 min_assets=2；触发分位路径时显式设置 quantiles=2、min_quantile_assets=1。通常设置 max_loss=0.35。全缺失样本的 UNEVALUABLE 用例可显式设置 max_loss=1.0 以到达结果状态，同时必须用同一输入另测默认 0.35 并断言 DataQualityError；不得自动放宽。每份 fixture 证据保存实际 EvaluationSpec，避免小样例误用生产默认阈值或分组数。

每个有效 signal variant（raw、oriented、transformed，以及 composite）都检查 Pearson 与 Spearman 两列。截面 rank 只转换因子 x，不转换标签 y；因此 F-IC3 的 transformed x 与 y 的 Pearson 仍为 4√3/7（约 0.989743），而 Spearman 为 1。不能把 Pearson(transformed_x,y) 错当成 Rank IC 或期待它等于 1。

## 4. 确定性验收 fixtures

## 7. 回归、两个示例和安装产物验收

### 7.1 针对性与回归范围

以下命令是实现后执行的计划命令，并非当前可用命令：

- fincore 新增测试：在 fincore 仓库运行拟新增的 tests/factor_analysis/test_iteration45_*.py 测试；另运行被改动的 factor_analysis 既有测试。记录收集数、通过/失败/跳过、警告及退出码。测试进程不得导入 Backtrader。
- Backtrader 研究单元测试：在 backtrader 仓库运行拟新增的 tests/research/test_factor_*.py；再运行被影响的 Indicator、Cerebro/时钟和示例测试。
- runonce/runnext、预热、多 feed 或研究时间网格的端到端差异需要真 Cerebro；只调用 fincore mock 的测试不能代替。
- 若修改 core clock/minperiod 或迭代计划所定义的核心调度，必须运行 make test-strategies。若只新增隔离研究模块，不触碰核心调度，则运行本轮研究单测、真实 Cerebro 集成、受影响的指标/策略回归和示例检查。记录选择/排除的原因。
- 固定确定性输入规模和容差。性能采样只记明资产数、时间数、因子数、耗时/峰值内存，不设置本轮的正向收益门槛，也不把未测的大规模/高频能力列为已支持。

### 7.2 两例共同的执行门槛

025 与 026 各自至少使用 20 个资产、260 个有效研究日，另加指标 warmup 与最长 horizon 所需的 21-bar 价格尾部。数据必须可离线生成或随例子提供；不得读取 tests、相邻示例、examples/_support 或绝对仓库路径。两例采用相同的资产、研究网格、日历、OHLCV 和标签定义。

每例在首次运行前固定并归档方向、变换、权重和 EvaluationSpec；segments 显式设为前 160 个研究 bar 的 development 与后 100 个的 validation，闭区间互不重叠。任何使用 Cerebro 的入口都在整个运行期间计数 Broker submit/cancel 并断言两者均为 0；离线数据本身不构成无下单证据。

每例通过以下三处检查，三者分别记录，不能互相替代：

1. 仓内从 README 所列命令运行成功，产物结构、非空统计、覆盖计数、schema 和数据范围符合断言。
2. 将整个例子目录复制到仓库外临时目录运行。启动工作目录可以改变；读取数据和写输出都应按配置/例子路径正确解析。
3. 在干净虚拟环境安装两仓已验收的本地 dev 构建产物后，从复制目录运行；记录解释器、实际导入路径、wheel 哈希、依赖版本和产物。不得从当前两个源码树偷读包。

实现后拟使用计划中的入口：

- python examples/backtest/025_factor_single/run.py --output-dir <single-output>
- python examples/backtest/026_factor_multi/run.py --output-dir <multi-output>

### 7.3 示例的业务断言边界

025 验收一个 Close/MA 因子，因子值是 close/SMA(close,20)；预热前或分母无效时记缺失。输出需包含 1/5/20 bar Pearson IC、Rank IC、ICIR、分层收益、换手/覆盖和图表/数据文件。生成数据的 IC 正负皆可；断言数据窗口、手算子集、统计字段、输出完整性和运行可复现。

026 验收 close/MA、20-bar ROC、KDJ.J，明示 J=3*K−2*D 及 K/D 平滑参数和预热。展示三个基础因子、完整固定权重组合、三个去一因子组合、共同样本、相关性和分期结果。development/validation 仅表示预先固定的区间标签，不构成独立样本外或市场有效性证明；默认正向只是示例配置假设，不表示已验证因子方向。例子不得重写分箱/统计/合成算法。

## 8. 错误、覆盖和分析结果状态

### 8.1 输入错误

非法配置不转成可用结果：未知因子名/输出线、重复资产名、缺少显式绑定、非法 direction/q/min_assets、权重非有限或组合成员不存在，都应返回可断言的错误类型与 code/字段。按设计核对异常类型与机器可读 code：非法配置为 ConfigError(code=INVALID_CONFIG)，Replay/live/tick/mixed-timeframe 或其他不支持时钟为 ConfigError(code=UNSUPPORTED_CLOCK)，缺少必需输入为 DatasetError(code=MISSING_INPUT)，schema 不兼容或未完成数据集为 DatasetError(code=INVALID_DATASET)，universe 覆盖未知为 DatasetError(code=UNKNOWN_UNIVERSE)，缺研究依赖为 DependencyError(code=DEPENDENCY_UNAVAILABLE)，超出损失上限为 DataQualityError(code=LOSS_LIMIT_EXCEEDED)。时钟错误只用 ConfigError 和指定 code，不定义独立异常类型；也不能把这些输入/数据质量错误归成“统计结果很差”。

### 8.2 数据覆盖和质量诊断

每个 signal × pool × group × horizon 都按设计文档 DS45-08 验证并报告覆盖：候选分母在因子可用性筛选、标签 mask 与分位处理之前确定，为研究区间内该 group 中已知 universe=true 的候选行数。known false 单列 excluded；unknown universe 先产生诊断并以 DatasetError 拒绝封存完整数据集，不能静默删除后再计算分母。对 own、组合和 common 池均保留形成前 eligible 候选数；组合/common 的成员有效交集另报 pool-formation loss，不能先过滤 factor-valid 候选来缩小 max_loss 分母。

对每个 slice 分别报告因子损失、有限信号上的标签损失，以及 eligible 候选到有限 signal+该 horizon 标签配对的总损失；另列 qcut/标签筛选后的组样本数及每组缺失原因。max_loss 默认 0.35，按 DS45-08 以候选数和有效配对数验收；分位损失另以有限配对数为分母，单独报告，不重复计入 max_loss。任何显式覆盖值须随 EvaluationSpec 留证，禁止自动放宽。超限时断言 DataQualityError(code=LOSS_LIMIT_EXCEEDED)，其诊断含 slice 标识和准确计数，保留诊断但不得返回完整成功结果。另精确记录 min_assets、min_quantile_assets、quantiles、horizon、方向、变换、组合权重与实际池成员。

### 8.3 分析结果状态

结果状态按设计固定为 OK、PARTIAL、UNEVALUABLE。请求的评价项全部符合合同且可用时为 OK；仍有有效结果但部分请求序列/指标退化或不可用时为 PARTIAL；没有任何可计算的请求评价截面时为 UNEVALUABLE，并保留空表 schema 和诊断。名称、参数、索引、时间或 schema 错误，以及未完成运行，不是结果状态，应以类型化 ConfigError/DatasetError 拒绝评价；缺依赖以 DependencyError 表达；损失超限优先抛 DataQualityError(code=LOSS_LIMIT_EXCEEDED)。

逐项 reason 按 DS45-08 精确断言，例如 INSUFFICIENT_ASSETS、CONSTANT_FACTOR、CONSTANT_RETURN、NONFINITE_INPUT、QUANTILE_DEGENERATE、MISSING_LABEL、NO_VALID_PERIODS、ZERO_IC_STD、SEGMENT_BOUNDARY、INVALID_ABLATION。分位退化只使该截面的分层指标不可用并记录 QUANTILE_DEGENERATE，不抹除样本合法的 IC；标签有效总样本少于 min_assets 时不计算该期 IC/分层收益；单个 quantile 组有效标签少于 min_quantile_assets 时只使该组均值缺失，spread 在任一端缺失时也缺失。常数 IC/零标准差 IR 不造 0。命令退出码与库结果状态分开：0=必需输出可用且验收通过，1=计算、数据或验收失败，2=缺依赖/输入等前置条件受阻，3=中断等运行结果未知；UNEVALUABLE/空报告不得以退出码 0 表示通过。

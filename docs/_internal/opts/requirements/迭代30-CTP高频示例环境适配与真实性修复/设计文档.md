## D30-02 环境选择设计（FR30-01、FR30-02、FR30-03、FR30-04、FR30-05）

**已冻结决策（2026-09-16）：默认环境为"族 + 族内冻结备选"** —— config 声明环境族 `simnow_first_group1`（对齐迭代25 G3 的真实市场时段要求），官方前置对为标称端点、备用对为族内冻结备选，实际可达性由冻结的 TCP 探测决定并记录实际 profile。不写死单一 IP，也不做地理/IP 推断（与 `bt_api_ctp` 的既有语义一致）。

冻结依据（2026-09-16 实测，见证据文件第 4 节）：

| 探测 | 结果 |
| --- | --- |
| `180.168.146.187` 的 10201 / 10211 / 10202 / 10130 | **全部不可达**（整台主机在路由层不可达，非端口关闭） |
| `182.254.243.31:30001` / `:30011`（group1 备用对） | 可达 |
| `182.254.243.31:40001` / `:40011`（第二套） | 可达 |
| `select_reachable_ctp_environment(env=set1, profile=set1_group1)` | 自动回退为 `set1_group1_vpn`，`readiness=tcp_pair_reachable` |
| `select_reachable_ctp_environment(env=set1, profile=set1_group2)` | `RuntimeError: no reachable CTP front pair for the selected profile group` |
| `select_reachable_ctp_environment(env=auto, is_trading_day=True)` | 选 `set1_group1_vpn` |

- **`set1_group2` 在本机无任何可达路径**（官方对不可达且无冻结备选）：族内回退耗尽后必须 fail closed，不得改连其它族。
- `auto` + 已验证交易日会选第一套，这与"默认第一套"一致；`auto` 不得因为"网络恰好通"就把未验证的交易日假设升级成第一套。

沿用 `examples/013_3_sa_midfreq_simnow` 已验证的形状（`profiles` 冻结块 + 环境变量选择 profile 名 + 族可达集合），但 015 自包含实现，不 import 该目录。

规则：

1. 环境选择入口为环境变量（拟议 `ITER30_SIMNOW_PROFILE`）+ 配置默认值，取值为上表的**冻结键**；自由形式的端点覆盖一律拒绝（与 013_3 一致）。
2. 族校验：`selected.family` 必须等于会话 `environment_profile` 所属族（`set1_*` / `set2_*`）；跨族或不匹配 → `CTP_SESSION_PROFILE_REQUIRED`（保留错误码，语义从"必须是第二套"改为"必须是所选族"）。
3. 族内回退（FR30-04）：先探测 `sdk_profile` 标称对；不可达则只允许用该 profile 的 `fallback_sdk_profile`（`null` 表示没有备选，直接失败关闭）。探测使用 `bt_api_ctp` 的冻结 profile 表（TCP 连通性），**不得**从 IP、地理、VPN 国家或进程公网 IP 推断路由。报告记录 `attempted_profile`、`actual_environment_profile`、`selection_readiness`、`selection_reason`。任何回退必须可审计，且不得跨族。
4. `market_alignment` 参与时段判定：`actual_market_hours` 时，时段外运行必须给出明确结论（拒绝或等待），禁止按 7×24 静默执行。
5. 派生标识：`clock_domain_id`、`mapping_source`、`profile_family_prefix`、TradeLogger 目录名前缀、工程 observation 的 profile 常量全部由所选环境派生，规则为 `iter30-<profile>-monotonic-v1` / `iter30-<profile>-launcher-anchor` 形式；不再出现 `set2` 字样。
6. 环境族与 SDK profile 名的映射表必须冻结在代码常量中，并附单测，禁止从字符串前缀宽松推断。映射表内容取自 `bt_api_ctp.ctp_env_selector` 的 `_SIMNOW_PROFILE_FRONTS` / `_SIMNOW_PROFILE_FAMILIES`，不得在 015 内自定义或扩写。

## D30-04 fixture 真实性与 tick_size 来源（FR30-06、FR30-07、FR30-10）

**已冻结决策（2026-09-16）：采用方案 α —— 元数据证据绑定。** 方案 β（合成元数据 + 显式降级）不采用：它把"元数据不可信"制度化，却仍允许该元数据进入价格网格与 cohort leg，等于把禁用规则交给运行时自觉；而 α 让 fixture 的合约事实可追溯到真实现场查询，可校验、可复现、可失败关闭。

### D30-04.1 方案 α 定义

1. fixture 增补 `metadata_evidence` 块，记录每腿的 instrument 查询快照及其来源身份与规范哈希。
2. `validate_bundle` 逐字段比对 `bundle` 与 `metadata_evidence`，不一致即 fail closed。
3. 离线 replay 使用记录的冻结证据校验自洽；live 路径额外要求**当场查询**的元数据与记录一致（合约规格应稳定），不一致 fail closed。
4. `price_tick`（Feed 网格）与 cohort leg `price_tick` 只能取自通过校验的元数据，禁止硬编码兜底。

### D30-04.2 `metadata_evidence` schema（拟议）

```yaml

  schema_version: iter30.ctp-instrument-evidence.v1
  source: ctp_instrument_query            # 禁止 synthetic/fixture/replay 标记
  captured_at: "2026-09-16T14:10:00Z"     # 现场查询时刻（UTC）
  provider: {sdk: bt_api_ctp, profile_family: set1}   # 仅环境身份，不含凭据/账号
  query: {exchange_id: CZCE, instrument_ids: [FG701, FG701C970, FG701P970]}
  legs:
    future: {instrument_id: FG701,     exchange_id: CZCE, multiplier: "20", price_tick: "1",   strike_price: null, expire_date: 20270114, product_id: FG,  option_type: null, underlying: FG}
    call:   {instrument_id: FG701C970, exchange_id: CZCE, multiplier: "20", price_tick: "0.5", strike_price: "970", expire_date: 20261211, product_id: FGC, option_type: "1",  underlying: FG701}
```

### D30-04.3 `validate_bundle` 校验规则（全部 fail closed）

| 规则 | 失败表现 |
| --- | --- |
| `schema_version` 已知、`source` 非 synthetic、`captured_at` 可解析 | `FIXTURE_METADATA_EVIDENCE_MISSING` |
| `legs_sha256` 与实际 `legs` 内容一致 | `FIXTURE_METADATA_EVIDENCE_TAMPERED` |
| 每腿 `multiplier`/`price_tick`/`strike_price`/`expire_date`/`exchange_id`/`underlying` 与 `bundle` 完全一致 | `FIXTURE_METADATA_MISMATCH:<leg>:<field>` |
| 合约代码要素自洽：`FG701C970` 内嵌 strike `970` == `strike_price` | `FIXTURE_SYMBOL_STRIKE_CONFLICT` |
| 看涨/看跌 `option_type` 与 `kind` 一致（call=1、put=2） | `FIXTURE_OPTION_TYPE_CONFLICT` |
| live/shadow 模式：当场查询元数据与证据一致 | `LIVE_METADATA_DIVERGED:<leg>:<field>` |

### D30-04.4 证据必须进入 bundle 身份哈希

015 现有 `rules_hash = canonical_sha256(bundle)`（`run.py` 用它做 cohort 规则身份，`_strategy_params` 传 `bundle_hash`）。若 `metadata_evidence` 留在该哈希之外，"证据绑定"可被替换证据绕过。因此：**`metadata_evidence` 必须纳入 `canonical_sha256(bundle)` 的取值范围**，且 `legs_sha256` 自校验通过。这会使 fixture 哈希变化，进而改变现有报告的 `bundle_sha256`/`fixture_sha256`/`config_sha256` 期望值——属于预期内的基线变更（见 D30-04.6）。

### D30-04.5 与合成报价的关系（重要推论）

`multiplier` 与 `strike` 是**合约事实**（必须取真实值），而 `base_quotes` 是**合成场景输入**（可以是任意值）。但二者必须内部自洽，否则 fixture 会以新的方式自相矛盾。现行 fixture 的报价是按 `strike=1000` 构造的：

- 现值（M=10、K=1000、F 999/1001、C 16/17、P 9/10）：`conversion_gross = 10 × (16 − 10 − (1001 − 1000)) = 50`，`reversal_gross = 10 × (9 − 17 + (999 − 1000)) = −90`。
- 只改 `multiplier=20`（K 不变）：50 → **100**、−90 → **−180**。
- 再改 `strike=970`（平价关系被破坏，C−P=7 而 F−K=31）：`conversion = 20 × (16 − 10 − 31) = −500`（不合格），`reversal = 20 × (9 − 17 + 29) = 420`（合格）——**合格方向从 conversion 翻转为 reversal**。

结论：α 落地时合成报价必须**按真实 strike 970 重新构造为平价自洽**（保持 fixture 作为机制/资格测试的用途），并重新基线化全部期望值；不得留下"声明 970、报价按 1000 摆"的新矛盾。真实盘口（F 905/906、C 21/21.5、P 81.5/89）在平价上无边际，不能直接用作 `valid_cohort` 场景输入。

### D30-04.6 α 的实施副作用（必须同批处理）

| 副作用 | 处理 |
| --- | --- |
| fixture 哈希变化 → `bundle_sha256`/`fixture_sha256`/`config_sha256` 变为新值 | 同批更新单测与冻结报告期望值 |
| `gross_cny`/`net_screen_cny` 数值与**合格方向**变化 | 同批更新 `valid_cohort` 场景与断言；不得只改数字而不检查方向语义 |

| 旧报告字段向后可读 | 保留 `discount_factor` 等既有字段（NFR30-07） |

## D30-05 时钟与空闲契约（FR30-08、FR30-09）

### D30-05.0 为什么不动框架

| 约束 | 事实 |

| 改派发签名会破坏公共行为 | 现役无参覆写 4 处：`012_1/strategy.py:2048`、`012_2/strategy.py:1907`、`013_3/strategy.py:1403`、`014_2/ctp_options_midfreq_strategy.py:1189`；改成 `notify_idle(now)` 会直接 `TypeError`，与 AGENTS.md "Preserve public API compatibility" 冲突 |

### D30-05.1 示例层修复步骤

1. **补注入点**：015 目前只接受 `SyntheticTimingProvider`（`ctp_options_highfreq_strategy.py:262-268`），实盘路径下 `_timing_provider is None`，idle 必然走到 latch。按 `014_1` 的形状新增一个返回 `CtpCohortNow` 的 live 时钟注入点（参数 + setter），并把 `run.py:1446` 已经构造好的 `_ObservationTrustedNowProvider`（当前只交给 Feed，见 `run.py:1615`）同时注入策略。离线 replay 继续走合成 provider，行为不变。
2. **`notify_idle` 三态语义**（真正的缺陷修复）：
   - provider 存在 + 观测有效 → 重验缓存 cohort、推进投影（现行为）；
   - provider 存在 + 观测违规（域变化、时钟回退、误差超界、代次不一致）→ **latch**，保持 fail-closed；
   - **完全没有 provider** → 只计数 + 保持现状：不 latch、不改变 `_clock_rejection_latched`、不覆盖 `_last_rejection`、**不清除已确认状态**（禁止顺手 `reset_confirmation=True`）。
3. tick 路径的 latch 检查保持不变（latch 仍阻断 tick），但 latch 只能由**带证据的违规**触发。
4. 报告区分 `idle_without_trusted_now_count`（新字段）与真实 `clock_violation_count`，禁止把"未提供时钟"表述为"时钟违规"。
5. 回归测试沿用 `014_1` 模板（`tests/unit/test_ctp_options_lowfreq_timing.py:551`）：真实 Cerebro + `islive()` 返回 `None` 的 feed，断言 (a) 无 provider 时多次 idle 后 `clock_rejection_latched is False` 且后续 tick 仍被处理；(b) 有 provider 时被调用且投影推进；(c) 违规 provider 时 latch 仍触发。
6. `idle_interval_ms` 二选一：

## D30-06 live 分层取证（FR30-11、FR30-12、FR30-13、FR30-14）

报告新增 `live_evidence_layers`，逐层独立结论，任一层的 PASS 不得提升其它层：

| 层 | 判据 | CTP 环境1 当前预期 |
| --- | --- | --- |
| L0 连接只读 | 会话字段齐全、`read_only_ready`、执行门未武装、写审计为 0 | `PASS`（实测） |
| L1 订阅与 tick 到达 | 每腿 tick 计数与速率、订阅 epoch、connection generation | `PASS`（本轮已观测） |
| L2 quote 资格 | `ctpcohort.py:570-601` 全部条件 + `execution_eligible is True` | `BLOCKED_BY_UPSTREAM_QUALIFICATION`，原因枚举 `UPSTREAM_EXECUTION_NOT_ISSUED`（依据 `live_ctp_feed.py:60-64,1717-1745` 与 `bt_api.py:3203`） |
| L3 cohort 成立 | 完整三腿 cohort 数、确认轮数、clock domain 一致 | `BLOCKED`（同因，随 L2 解除） |
| L4 经济 screen | 基于原生报价的净边际 | `BLOCKED`（同因，随 L2 解除） |

**L0–L4 全部是 015 的目标，不降级、不转交**；`BLOCKED` 与 `NOT_RUN` 的区别是：前者已执行到该层并确认上游缺证据，后者是尚未执行。replay 路径的资格是示例自己写死的（`run.py:477-495`），只能作为公式证据，不能填入 L2 的 live 结论。

补充要求：

1. 不可达原因必须来自枚举，禁止空值与"未观测"混用；L0/L1 通过与 L2 不可达可同时成立。

3. 门限不可达（FR30-14）：保持 `INCOMPLETE` 并输出候选审查结论，禁止就地放宽 `max_quote_age_ms`/`max_cross_leg_skew_ms`。
4. **已冻结决策（2026-09-16，问题4）**：L0–L4 全部保留为 015 的 live 目标，**不降级**。L2 当前不可达属于**阻塞依赖**（待上游提供可签发的原生证据链），状态记 `BLOCKED_BY_UPSTREAM_QUALIFICATION`，而不是把 L3/L4 转交给别的示例。
   - **修正（2026-09-16）**：本文件早前版本写过"需要 L2–L4 的验证改用能签发资格的行情路径（跨所加密行情链路）"，该表述**不成立且已作废**：`012_1`/`012_2` 既无 `CtpQuoteCohortValidator` 也无 `execution_eligible` 概念，与 015 的 L3/L4 不同构；且 015 的 cohort 校验器硬要求 `schema_version == "ctp.quote.v2"`（`backtrader/feeds/ctpcohort.py:566`），换行情源不能直接复用。非 CTP 路径上 `execution_eligible` 不再被 strict V2 约束（`backtrader/feeds/btapifeed.py:1270`），这只是一条**未验证的可能性**，不构成已有能力。
   - 解除条件：上游（`bt_api_ctp`）提供可签发的原生资格证据链（其回执文档已预留 "A future native evidence authority may extend this private contract"）。该工作项属 SDK 仓库，不在本仓。

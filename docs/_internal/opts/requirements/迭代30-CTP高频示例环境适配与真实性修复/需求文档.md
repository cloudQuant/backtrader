## 2. 术语

- **环境族**：SimNow 第一套（`set1_*`，真实市场时段对齐）与第二套（`set2_*`，7×24 工程时段）。族名来自 `bt_api_ctp` 的冻结 profile 集合。
- **可达前置**：本机可达的冻结 TD/MD 对。官方 Set-1 前置 `180.168.146.187:10201/10211` 实测不可达，仅 `182.254.243.31:30001/30011` 可达。
- **L0–L4 取证层**：连接只读 / 订阅与 tick 到达 / quote 资格 / cohort 成立 / 经济 screen。见 FR30-12。
- **资格签发**：上游对某条 quote 明确声明 `execution_eligible`/`execution_qualified` 的证明链。

## 3. 功能需求

### A. 环境适配（让 015 可在环境1运行）

- **FR30-01**：015 必须以配置驱动方式选择 SimNow 环境，至少覆盖第一套与第二套；默认值取**第一套**，与迭代25 G3 的真实市场时段要求一致。配置必须自包含在本目录（`config.yaml` 的 `profiles` 块），不得 import 其它 `examples/`。**默认环境取"族 + 族内冻结备选"（已冻结，见设计文档 D30-02）**：声明环境族（默认 `simnow_first_group1`）、官方对为标称端点、族内备用对为唯一允许的回退目标；不得写死单一 IP，也不得做地理/IP 推断。
- **FR30-02**：`run_engineering_observation` 的环境门槛从"字符串前缀必须是 `set2_7x24`"改为"必须是本次显式选择的环境族且会话 profile 属于该族"；跨族、未知族、族内不匹配仍必须 fail closed 并给出稳定错误码。
- **FR30-03**：所有环境相关标识（clock domain、mapping source、`profile_family_prefix`、`requested_environment_profile`、TradeLogger 目录名等）必须由所选环境派生，不得残留 `set2` 字样。
- **FR30-04**：当前置不可达时，只允许在同一环境族内回退到该 profile 已冻结的备选对（`fallback_sdk_profile`；为 `null` 表示无备选，必须直接失败关闭），并在报告里记录 `attempted_profile`、`actual_environment_profile`、`selection_readiness`、`selection_reason`。禁止从 IP、地理或 VPN 国家推断路由，禁止跨族回退。实测依据：`set1_group1` 可回退到 `set1_group1_vpn`；**`set1_group2` 在本机无任何可达路径**，必须回退耗尽后失败关闭。
- **FR30-05**：明确第一套跨越"真实市场时段"边界的行为：时段外运行必须给出可辨识结论（例如等待/拒绝），不得静默按 7×24 语义运行。

### B. 真实性缺陷修复

- **FR30-06**：fixture 的合约元数据必须改为**绑定真实现场查询证据**（已冻结方案 α，见设计文档 D30-04）：新增 `metadata_evidence`，修正 `multiplier=20`（期货与期权）、期权 `tick_size=0.5`、期权 `strike=970`、期权 `expiry=20261211`、期货 `expiry=20270114`，并记录来源身份与规范哈希。
- **FR30-07**：`validate_bundle` 必须实施 D30-04.3 的全部失败关闭校验：证据完整且非合成、`legs_sha256` 自校验、逐字段与 `bundle` 一致、合约代码内嵌 strike 与 `strike_price` 一致、`option_type` 与 `kind` 一致、live/shadow 下当场查询元数据与证据一致。**`metadata_evidence` 必须纳入 `canonical_sha256(bundle)` 范围**（D30-04.4），禁止证据留在身份哈希之外。禁止未经证据的 `tick_size` 进入 `price_tick`（Feed）与 cohort leg 定义。
- **FR30-07b**：合成 `base_quotes` 必须与真实 `strike`（970）**平价自洽**，不得保留"声明 970、报价按 1000 摆"的矛盾；由此产生的合格方向与 `gross_cny`/`net_screen_cny` 变化必须同批重新基线化（D30-04.5、D30-04.6）。
- **FR30-08**：消除 `notify_idle` 无参调用造成的永久 latch，且**修复只落在示例策略层，不改变 `Cerebro` 的 `notify_idle()` 无参派发与任何框架公共行为**（已冻结，见设计文档 D30-05.0）。必须实现三态语义：provider 存在且观测有效 → 重验缓存并推进投影；provider 存在但观测违规 → latch（fail-closed）；**完全没有 provider → 只计数并保持现状**（不 latch、不覆盖 `_last_rejection`、不清除已确认状态）。latch 只能由带证据的违规触发，且不得阻断后续具备可信时钟的 tick。
- **FR30-09**：`idle_interval_ms` 要么真正生效（pacing 到实际空闲轮询），要么从配置与文档契约中移除；不允许保留无效契约。
- **FR30-10**：fixture 的合成报价与由其推导的经济 screen 数字，必须在报告与文档中标注为非市场证据，且不得作为任何经济或 G3 判据。

### C. live 契约重定义

- **FR30-11**：显式记录并输出"CTP 原生路径能否签发执行资格"的判定结果；当 SDK 侧结构上不签发时，报告必须给出稳定的不可达原因分类（不是空值、不是"未观测"）。
- **FR30-12**：015 的 live 结论必须分层取证并对齐命名：L0 连接只读、L1 订阅与 tick 到达、L2 quote 资格、L3 cohort 成立、L4 经济 screen。**L0–L4 全部保留为 015 的 live 目标，不降级、不转交其它示例（已冻结，见设计文档 D30-06.4）**；L2 当前不可达记为 `BLOCKED_BY_UPSTREAM_QUALIFICATION`（不是 `NOT_RUN`、不是"不需要"），解除条件是上游提供可签发的原生资格证据链。禁止用 L1 通过表述为"策略可运行/有信号"。
- **FR30-13**：与迭代25 G3 对齐：G3 使用第一套真实时段，需满足每腿有效原始 tick 与合格完整 cohort 的数量门槛；若现有 fixture 绑定的三腿（FG701 / FG701C970 / FG701P970）在指定时段达不到门槛，必须给出"合约与时段可选性"的可验证结论，而不是降低门槛。L2 阻塞期间 G3 保持 `INCOMPLETE`，不得因阻塞而改写 G3 门槛。
- **FR30-14**：当 freshness/skew 门限（`max_quote_age_ms=250`、`max_cross_leg_skew_ms=100`）在真实 CTP 快照节奏下不可达时，G3 保持 `INCOMPLETE`，并产出数据/候选审查结论；禁止就地放宽门限换 PASS。**L2 阻塞不得被当作放宽门限的理由。**
- **FR30-15**：示例 README 必须与代码一致：明确 015 的 live 路径当前能证明什么（L0/L1）、被什么阻塞（L2 及以上的上游资格签发）、以及解除条件与责任方（`bt_api_ctp`）；删除"显式请求 shadow/SimNow 会在建立会话前失败关闭"与实际入口并存的歧义表述；**不得把 L2–L4 说成"已转由其它示例承担"**。

### D. 环境与制品治理

- **FR30-16**：运行前置检查必须在建立 CTP 会话**之前**验证 `backtrader` 的加载来源与版本；若不是目标源码/制品（editable 或带哈希的 wheel），必须 fail closed。
- **FR30-17**：live 报告必须记录 `backtrader.__file__`、版本、以及源码/制品哈希，使"这次报告对应哪份代码"可审计。
- **FR30-18**：安装方式文档与仓库状态一致：015 README 当前指示 `pip install -e ../..`，但实际安装是非 editable 的 1.3.0 快照；二者必须统一（改文档或改安装，二选一，并给出验证命令）。

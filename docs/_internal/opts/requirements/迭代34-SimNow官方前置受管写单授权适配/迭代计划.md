## 1. 问题和事实边界

用户目标是使用官方“新 7×24 看穿式前置”对 33 个穿透式认证场景执行真实下单、撤单和自动清理。
2026-09-20 的无写入探测已经证明该前置、凭据和 typed preflight 可用；但它也以
ctp_execution_gate_environment_unverified 在订单创建之前阻止写入。

当前 Backtrader direct CTP 路径只接受 SDK 注册的第三方券商仿真前置；ctp_gateway 兼容路径
又刻意禁止直接 place_order / cancel_order，以避免绕过 capability、arm 和 preflight。
当前 Anaconda 环境生效的 editable bt_api_py==0.15.3 也未暴露 Backtrader 所需的公开受管
Gateway/approval 类型。

这不是“删除门禁即可解决”的问题。不得把官方 SimNow 添加到 direct 路径白名单、绕过 opaque
capability、伪造 receipt，或通过 monkey patch、私有令牌和环境变量把订单写入解锁。

| G34-04 | 证据能区分 SDK 单测、隔离 wheel-consumer、真实 SimNow 会话 | 本地绿灯和历史报告不得充当真实交易通过 |

## 3. 工作包

### WP34-A：bt_api_py 官方 SimNow 受管授权（SDK owner）

1. 定义并发布稳定的公开 API：官方 SimNow profile 校验、只读 preflight、外部批准的
   一次性/有时效 authorization capability、受管 arm、disarm 与恢复查询。
2. 只允许精确匹配官方 SimNow TD/MD 前置对；将账户指纹、交易日、连接代次、授权合约范围、
   preflight hash、运行时/依赖 hash 纳入证明，任何变化均使授权失效。
3. 授权不得由 Backtrader 或策略自签。它必须由 SDK 的公开审批入口提供，并限制有效期、操作数、
   允许合约和风险方向；写入前后均重新验证。
4. 支持订单与撤单的同一受管命令通道；不允许 Gateway 适配器或 direct wrapper 成为旁路。
5. 遇到超时、未知结果、断线或清理失败时，冻结后续开仓，提供可审计的恢复/平仓证明接口。
6. 打包验收：从干净 SDK 源快照构建 wheel，在隔离环境安装后验证 GatewayClient、公开
   approval capability 和所需 CTP 契约可导入；不能依赖 editable 路径或 ambient site-packages。

### WP34-B：Backtrader 受管适配（仅在 WP34-A 交付后）

1. 将 simnow_penetration 的配置改为显式选择受管 SDK 提供者和官方 profile；禁止在失败时回退到
   provider=ctp 或 ctp_gateway 的直接写入。
2. 仅将 SDK 提供的 authorization 交给 BtApiStore.arm_sdk_execution()；Backtrader 不读取私密
   授权字段、不构造 proof，也不记录 capability。
3. 在每个会话前采集脱敏账户指纹、持仓/挂单/成交计数和连接代次。已有非本轮挂单、无法区分的
   持仓、不可接受的风险余额或不完整查询都必须阻止写入。
4. 写入仅可经显式本轮批准：受限合约、1 手上限、总操作数上限、过期时间、串行子进程与
   case trace ID。每个用例 finally 块都执行本轮订单清理和最终对账。
5. 修复并回归所有会把凭据、InvestorID、authorization、账户原始标识写入 stdout、JSON 或日志
   的路径。

### WP34-C：真实 33 场景验收（在 A、B 均通过之后）

1. 先运行只读 preflight，若不满足精确 profile、交易时段/行情条件、账户基线、授权或清理保证，
   整轮 BLOCKED，不得尝试第一笔订单。
2. 每个场景独立子进程且全量串行；每个写入用例保存本轮 result.json、audit.jsonl、
   原始脱敏事件日志、前后快照/对账和清理结果。
3. 对实际写入场景，记录远端接受、撤单/成交/拒单的原始 CTP 事件和外部订单标识；本地校验拒绝
   不能冒充远端写单/撤单。
4. 发生未知订单状态、残留挂单、非预期持仓变化、会话代次变化或恢复不完整时立即停止余下
   写入场景，标记 FAIL 或 BLOCKED 并保留证据。

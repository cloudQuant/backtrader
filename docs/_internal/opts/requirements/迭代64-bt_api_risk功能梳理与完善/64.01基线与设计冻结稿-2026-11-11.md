## 2. 方案选择：新核心 + 旧核心保留为兼容（§7.2 第 5 项，主会话冻结）

比较了三种做法：

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| 旧核心改造 | 在 `core/admission.py`（14 586 行）的 `DurableRiskGate` 上加方向、价格、类型、计数、自成交价格相交、交易日窗口和母单 | 不采用：`RiskIntent` 没有方向/价格/类型，账户级 latch、ACTIVE/SETTLED 生命周期累计额度和大量迭代 60 证明类型都要改，迭代 60 托管路径回归面最大 |
| 全新核心、删除旧核心 | 新服务自建账本，旧 `DurableRiskGate` 与迭代 60 托管路径一起退役 | 不采用：迭代 60 托管路径仍有调用者和测试，删除属于用户未要求的破坏式变更 |
| **新核心 + 旧核心保留为兼容（采用）** | 独立 Risk 服务使用新的预交易账本 `bt_api_risk.pretrade`（与 `RiskOrderJournal` 同一 SQLite 文件、同一账户 writer fence，独立 schema 版本）；`DurableRiskGate` 只留给迭代 60 进程内托管路径，按 §5.7 改名，不接新服务 | 新服务的范围占用、计数、自成交、价格带都在新账本里一次做对；旧路径行为不变，只改名 |

后果（如实说明）：

- S-06（账户级 dispatch latch）在新服务中不存在：新账本按“策略 × 合约 × 方向/开平”记在途占用，UNKNOWN 按最坏情况占用，不阻断其他策略和其他合约（D63-04 的 Gateway 栅栏仍由 Gateway 执行）。旧 `DurableRiskGate` 的账户级 latch 在兼容路径保留（该路径每账户只有一个策略写者），改名为在途占用名称（§9）。§5.1 的“旧代码须失败”测试以同一场景分别跑旧 gate 与新服务：旧 gate 拒其他策略开仓（`FROZEN`），新服务放行。
- §1.2 第 3 项（`_assert_increase_limit` 是账本生命周期累计额度）只影响旧兼容路径，新服务不用它；新服务的额度按交易日与“当前持仓 + 在途”计算（R-03）。
- 新账本复用 `RiskOrderJournal` 的 writer fence 做本机单写者；这不是跨主机 fence（INV64-13），D64-15 每账户一个进程、存储在本机文件系统。

## 3. 服务形态与进程（主会话冻结）

- Risk 服务是一个独立进程，每账户一个（D64-15）。进程入口在 SDK：`bt_api_py.risk_service_host`（命令 `bt-risk-service`），它组合三样东西：`bt_api_risk.pretrade`（判定、账本）、SDK 的 Gateway 代理客户端（`GatewayDelegateServiceClient`、观察流客户端、行情客户端、控制客户端）、`bt_api_transport_zmq` 传输。这样 `bt_api_risk` 不依赖 `bt_api_py`，SDK 负责跨包组合，与现有 `gateway_delegate_risk_host.py` 的分工一致。
- 策略进程只用 SDK 的 Risk 客户端 `bt_api_py.risk_service_client`，它只依赖 `bt_api_base` 与传输，不导入 `bt_api_risk`（INV64-02）。Gateway 进程不导入 `bt_api_risk`。
- Risk 服务对外是一个 ServiceHost，组件 `risk`、角色 `order_service`，端口 `service.risk_order`（策略与 Execution 代理调用）和 `service.risk_admin`（运营调用），认证用 CURVE，主体到授权的映射在服务端静态安装（与 Gateway 的 `TrustedServiceAuthority` 相同做法），不采信请求里自报的身份。
- Risk 服务对 Gateway 是客户端：以 `WireRole.SERVICE` 主体登录，Gateway 资源包已能登记 Risk 代理（63.13 的 `delegates`）、观察者与行情主体；Risk 按策略分别持有 Gateway 授予的代理授权（`GatewayDelegateGrant`，每个被代表策略一条）。

## 4. 服务操作与线上字段（`bt_api_base.risk_service_protocol`，主会话冻结）

中立类型已写入 `bt_api_base/risk_service_protocol.py`（64.02）：`RiskOrderView`、`RiskOrderResult`、`RiskParentView`、`KillSwitchCommand`，有限码集合 `RISK_REFUSAL_CODES`，结果集合 `RISK_OUTCOMES`，许可状态 `RISK_PERMIT_STATES`，急停词汇 `KILL_SWITCH_ACTIONS/SCOPES/RESULTS`（字符串与 Gateway 现用的 `STOP_NEW`/`FREEZE`/`DRAIN`、`account`/`strategy`/`instrument` 完全一致）。

| 操作 | 调用方 | 参数 | 结果 |
| --- | --- | --- | --- |
| `risk.order.reserve` | 策略；Execution 代理（子单） | `request_key`、规范订单载荷（与 `direct.reserve` 相同的 `OrderRequest` 规范 JSON）、`parent_ref`/`child_id`（仅子单） | `RiskOrderResult`：`RESERVED`（含 `permit_id`、Gateway `reservation_id`）/`DENIED`（有限码）/`UNKNOWN` |
| `risk.order.dispatch` | 同上 | `request_key`、`permit_id`、`reservation_id`、`view_digest`，可选 `market_ref` | `DISPATCHED`/`DENIED`/`RELEASED`/`UNKNOWN` |
| `risk.order.release` | 同上 | `request_key`、`permit_id` | `RELEASED`（有 Gateway 证明）/`UNKNOWN` |
| `risk.order.status` | 同上 | `request_key` | 当前许可状态；不存在为 `NOT_FOUND`（不是未发送证明） |
| `risk.parent.reserve/release/status` | 仅 Execution 代理 | `RiskParentView` 规范映射 / `parent_ref` | 母单占用状态（§8） |
| `risk.status` | 策略、Execution | — | 可用性、政策版本、观察流状态、本主体最近拒绝码计数 |
| `risk.admin.*`、`risk.policy.*`、`risk.latch.*`、`risk.unknown.list`、`risk.counts.export`、`risk.audit.read`、`risk.cancel.*` | 运营 | 见 §10 | 只读或受权变更，全部审计 |

规则：

- `RiskOrderView` 由 Risk 服务从它将原样转发的规范订单载荷和已认证调用方推导；调用方不能自报 INCREASE/REDUCE（INV64-04）。规范载荷与视图摘要一起固化在许可里，派发时比对，不一致拒 `risk_permit_mismatch`。
- 幂等键：（账户 scope、策略、`request_key`）。同键同摘要返回持久状态；同键异摘要拒 `risk_request_conflict`。重试不产生第二次 Gateway 派发。
- 策略的 `request_key` 原样作为 Gateway 代理命令的 `request_key`（63 计划 §3.5），Gateway 把订单归属到被代表的策略并写入该策略自己的回报流（63.13 已有证据）。

## 5. 次序、状态机与证明（§4.2、§4.3、§6.1 的具体化，主会话冻结）

许可状态：`RESERVING → RESERVED → CLAIMED → DISPATCHED → TERMINAL`；分支 `DENIED`、`RELEASING → RELEASED`、`UNKNOWN`。

| 步 | Risk 动作 | 持久化 | Gateway 调用（63.13 已有） |
| --- | --- | --- | --- |
| reserve-1 | 认证、授权、推导视图、L1 + L2 检查 | 一个 `BEGIN IMMEDIATE` 事务：许可 `RESERVING` + 最坏占用 + 审计 | — |
| reserve-2 | 代理预留 | 代理意图先落 Risk 库（`GatewayRiskDelegateHost`，已有） | `direct.delegated_reserve` |
| reserve-3 | 记录结果 | 观察到 `RESERVED` → 许可 `RESERVED`（含 `reservation_id`）；Gateway 明确拒绝（`REQUEST_DENIED`，没有预留）或传输确定未发出（`TRANSPORT_NOT_STARTED`）→ `DENIED` 并释放占用；其他 → `UNKNOWN` 保留占用 | — |
| dispatch-1 | L3：重验政策版本（取最新生效版本，D64-12）、参考价、自成交、计数、锁存、授权 | 一个事务里条件更新 `RESERVED → CLAIMED`；不通过则 `RESERVED → RELEASING` | — |
| dispatch-2 | 转发 | 派发标记先落库（已有） | `direct.delegated_dispatch` |
| dispatch-3 | 记录结果 | `QUEUED`/`SENT` → `DISPATCHED`；其他 → `UNKNOWN` | — |
| release | 条件更新 `RESERVED → RELEASING`，再请求 Gateway 释放 | 释放计划先落库（已有） | `direct.delegate_actor_release` |
| 观察 | 从账户观察流按身份幂等结算 | 投影与游标同事务，之后才 ACK | 账户观察流 |

NOT_SENT 证明（只有下列之一才释放占用，主会话冻结）：

1. Gateway 对本次 `direct.delegated_reserve` 的明确拒绝（`REQUEST_DENIED`，由 Gateway owner 事务给出，没有建预留），或 SDK 客户端返回 `TRANSPORT_NOT_STARTED`（请求未离开本进程）。
2. 以原 `request_key` 查询 `direct.delegate_actor_status`，Gateway 日志里该命令处于终态 `RELEASED`、`EXPIRED` 或 `NOT_SENT`，且命令摘要、`reservation_id`、Gateway owner/预留代际与许可记录一致。Gateway 的代理命令按 `request_key` 唯一、终态不可再派发、迟到的同键预留只返回原记录（63.13 已实现，64.09 加故障注入验证），因此这一终态对该键就是有效栅栏。

不构成证明：`NOT_FOUND`、超时、无许可号、本地 TTL 到期。特别是“Risk 已在本地 `RESERVING`、Gateway 查不到”的情况保持 `UNKNOWN` 与占用，列入 `risk.unknown.list`，由运营在核对后处理（Gateway 没有未知请求的墓碑合同，属 63 的候选，本迭代不假定）。

D63-38 的场所查询 `not_found_at_venue` 只解除场所恢复阻断，不单独释放 Risk 占用；Risk 释放只认上面两条。

## 7. 控制目录的具体口径（主会话冻结，用户决定见计划 §8）

| 控制 | 冻结口径 |
| --- | --- |
| R-01 | 策略 × 合约必填；缺失拒 `risk_limit_unconfigured`；OPEN 与 CLOSE 都查（D64-03）；超限 `risk_order_quantity_exceeds_cap` |
| R-01b | 名义 = 数量 × 价格 × 乘数；无限价时用参考价；乘数缺失：OPEN 拒 `risk_instrument_facts_unavailable`，CLOSE 本规则不拒 |
| R-02 | 参考价为 Gateway 行情主体取得的最新成交价，年龄超过 `max_reference_age_ms` 或缺失：受约束的 OPEN 拒 `risk_reference_price_unavailable`；启用时市价单 OPEN/CLOSE 都拒 `risk_price_band_market_order`（D64-04）；reserve 初查、dispatch 重查 |
| R-03 | 最坏持仓 = 已成交持仓 + 本方向在途开仓（含 UNKNOWN）；按策略 × 合约、账户 × 合约，多空分开；事实不完整拒 `risk_position_facts_unavailable`；实际 CLOSE 不受本规则限制 |
| R-03b | 本次平仓 ≤ 账户该方向可平（SHFE/INE 分今昨）− 其他策略在途平仓 − 本策略其他在途平仓；可平为零拒 `risk_closable_exceeded`（D63-49）；事实不完整拒 `risk_closable_unverified` |
| R-04 | 按账户 × 合约 × 交易日计报单（claim 时计，UNKNOWN 计为已发送）与撤单（观察流计）；达 warn 记告警；达 block：本地锁存账户 × 合约，经 Risk 的该合约所有策略普通 OPEN 拒 `risk_order_count_limit`，并向 Gateway 请求账户 × 合约 STOP_NEW（D64-08）；CLOSE、撤单不受本规则拒 |
| R-05 | 新单与同账户（含同策略）已 claim 未结、Gateway DISPATCHING、场所活动、UNKNOWN 的反向单价格相交即拒 `risk_self_trade`：买价 ≥ 反向卖价相交；市价与任何反向单相交；UNKNOWN 视为仍活动；同方向的平仓与反向开仓不算；观察流不连续或活动订单事实不完整：OPEN/CLOSE 都拒 `risk_self_trade_unverifiable`（D64-07） |
| R-06 | 同策略、合约、方向、开平、价格、数量在 `window_ms` 内重复：`warn` 放行记告警，`deny` 拒 `risk_duplicate_order`；同 `request_key` 的重试不算重复 |
| R-07 | 策略：交易日内权益变化（Gateway 策略资金快照，D63-44 口径）与当日高水位；账户：provider 账户事实；事实不完整：启用该检查的范围 OPEN 拒 `risk_pnl_unknown`；越限：OPEN 拒 `risk_loss_limit` 并按 `breach_actions` 请求控制；本地锁存跨交易日保留，运营解除（D64-09） |
| R-08 | 缺省 off（D64-10）；warn 只告警；deny：估计保证金 = 数量 × 价格 × 乘数 × 保证金率，与账户可用资金减本地未覆盖占用比较，不足拒 `risk_margin_insufficient`，事实缺失拒 `risk_margin_facts_unavailable` |
| R-11 | 受信规则文件（单账户）：限仓、日内开仓量、交割月禁开；适用规则所需事实缺失拒 `risk_exchange_rule_unavailable`，越限拒 `risk_exchange_rule_exceeded` |
| 锁存 | 任何本地越限锁存生效时，受影响范围的 OPEN 拒 `risk_breach_latched`；锁存只由运营 `risk.latch.release` 解除，审计 |

## 8. 母单（64.10，主会话冻结）

`risk.parent.reserve` 以 `RiskParentView` 建信封并整笔预留（R-03、R-07、策略额度；R-08 deny 时整笔最坏资金）；子单 `risk.order.reserve` 必须带 `parent_ref`/`child_id`，从信封未用量划拨，累计越过总量或越出范围（合约、方向、开平、价格界、有效交易日）拒 `risk_parent_envelope_exceeded`；`risk.parent.release` 只释放未划拨部分，划拨给 UNKNOWN 子单的部分保留；Execution 崩溃时母单不再接受新子单（`risk_parent_frozen`），已发子单照常按观察流结算。跨交易日：信封身份、总量、期限不变，新日子单重新做全部 L1–L3 检查；旧日 UNKNOWN 按原身份保留占用。平今母单跨日按 D65-37 只接受经 Gateway 映射证明的平昨子单；映射事实由 63/65.03a 提供，未提供时拒绝（GAP）。

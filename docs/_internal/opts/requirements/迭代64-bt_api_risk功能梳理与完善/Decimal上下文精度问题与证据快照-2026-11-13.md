状态：**IN_PROGRESS / NO-GO**。本文记录本机公开源码、合成测试和日志在 2026-11-13 的冻结快照及后续合成测试观察；Risk 工作树仍在变化，数字不构成最终验收。项目范围及先前来源缺口见[后续复核](后续复核-2026-11-12.md)。

## 问题与风险

`Decimal` 表示十进制值并不保证后续运算和 `normalize()` 不受当前线程 Decimal context 的精度、指数范围和 trap 设置影响。用 Anaconda base Python 的局部 context 复现：精度为 2 时，`Decimal("1.23") + Decimal("0.01")` 得到 `1.2`，而精确值为 `1.24`；`1.0001 * 1.0001` 得到 `1.0`，精确值为 `1.00020001`。因此在限额边界附近，名义金额、持仓、保证金、母子单余量或已成交量等若先舍入再比较，可能错误接受或拒绝，亦可能影响账本占用和释放。示例为人工输入，未说明任何真实订单发生过该问题。

旧 v1 使用 `format(value.normalize(), "f")`，并把 `-0` 写成 `0`。精度 28 时，`1.23456789012345678901234567891` 与 `1.23456789012345678901234567892` 都会规范化为 `1.234567890123456789012345679`；若其他字段一致，受影响视图的序列化和摘要可能碰撞。trap 开启、溢出或下溢也可能改变结果或引发异常。线程 context 不同时，同一值的处理也可能不同。

## 源码状态

- Base 本地 `27c170b` 在 `risk_service_protocol._decimal_text` 增加有限值、系数、指数和展开长度限制，格式化后重新解析并比较原值；有损、异常或超限时抛出 `RISK_DECIMAL_ENCODING_INVALID`。这收窄 v1 接受域；对仍被接受的值保留原先字节语义和 `-0` 处理，并非升级协议或为旧摘要追认真实性。其测试包括 golden 摘要、舍入碰撞、不同线程 context 和 trap。由于旧编码仍受调用者 context 影响，同一个输入可在一个 context 被拒绝而在另一个无损编码。
- Base 本地 `b70e920` 增加 Gateway 订单与 Risk 视图的纯值对照及测试；SDK `02d5a1c4`、`eca7d97c` 分别更新 Base gitlink 至上述提交，后者另含 SDK/Base 差异测试。对照接受域比 SDK decoder 窄，值与摘要检查不证明 route、策略、完整品种、provider、账户身份或授权，也不代表接入生产 handler。

- v4 首次尝试账本也是未提交 WIP。当前新库包含 `SOURCE_UNVERIFIED` 来源门，默认首次写入被拒绝；部分专项通过测试局部替换门禁来检验下游事务。它不建立来源、首次发送、账户权威或生产准入，不能据合成结果打开 gate。

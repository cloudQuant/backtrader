## 1. 阻塞 A：认证来源证明 —— 采用 A-1

- **决定**：`_v1_source_quarantined()` 保持无条件为真；v1 决策链继续只读/历史保留；不实现 A-2 的认证来源合同，也不做 A-3 的局部只读解除。
- **改动范围**：无产品代码改动；仅在相关测试中把期望保持为 `UNKNOWN` / `RISK_SOURCE_UNVERIFIED`。
- **仍然 GAP**：v1 永不产生决策；迭代 64 不得声称 R-01～R-11 已具备行为闭环。解除隔离仍需先冻结认证来源合同（签发方、账户 scope、generation/epoch、覆盖水位、有效期、撤权与旧 host 隔离）。

## 2. 阻塞 B：R-04/R-11 v2 政策激活 —— 采用 B-1

- **决定**：允许 `counters is None` 且 `r04_binding is None` 的 v2 政策文档经既有激活路径发布、加载与重启恢复；仍拒绝带 `counters` 或 `r04_binding` 的文档（`RULE_R04_V2_UNAVAILABLE`），因为 v2 规则求值、breach 投影与宿主选择尚未接线。
- **配套**：`publish_policy()` 对上述拒绝返回如实错误码 `policy_r04_v2_unavailable`，不再笼统映射为 `policy_rule_not_allowed`。
- **未改变**：`_require_policy_snapshot` 的多引擎一致性检查与失配 `UNKNOWN` 行为；post-commit 赋值窗口行为；R-04 规则求值/观察路径。
- **仍然 GAP**：R-04/R-11 v2 规则激活（B-2）、breach 语义、来源/FX 权威、期货公司阈值。

## 3. 阻塞 C：CTP 受信子类边界 —— 采用 C-1

- **决定**：SDK 组合改为持有**唯一精确** `bt_api_risk.risk_order_journal.RiskOrderJournal` 实例；`_risk_dispatch_profile`、`_verify_gateway_position_source_receipt` 与 Execution 撤单来源桥改为实例级端口（`risk_order_journal_ports.py`），不再通过继承提供。
- **信任边界不变**：核心的精确类型门（`type(journal) is RiskOrderJournal`）保留，SDK 子类仍被拒绝；端口按实例一次性绑定，缺失、替换、跨实例、类型/身份变化、可调用对象或布尔/字段冒充均使相关路径不可用；每次使用仍走核心自身的 fence、scope 与证据检查。
- **装配失败语义**：确定性的装配拒绝（`FENCE_ENTRY_UNTRUSTED`）不再把账户 scope 永久 quarantine 到进程结束；发送后结果不明（UNKNOWN）仍按原合同隔离。
- **仍然 GAP**：进程内 Python 不是沙箱；真实 CTP/Gateway 来源、账户权威与发行未验收。

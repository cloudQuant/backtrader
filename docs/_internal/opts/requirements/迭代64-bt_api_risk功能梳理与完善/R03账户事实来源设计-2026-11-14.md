## 业务范围

按[迭代计划 R03 决定](迭代计划.md)：逐合约以多头减空头得到净手数，合约间正负不抵扣；各合约用最新成交价 × 合约乘数 × 对应净手数估值，跨币种按受信汇率换算为运营配置的统一币种，分别汇总净多、净空金额并与各自上限比较。账户金额上限豁免实际 CLOSE，可能扩大另一方向净额，是有意识的风险豁免；可平量、UNKNOWN 等独立检查仍适用。虚拟 CLOSE 转实际 OPEN 按实际 OPEN 检查。来源不可证时，适用的 R03 账户金额 OPEN 检查保持不可用，不把缺失填零或回退为未验证来源。

- CTP `bt_api/bt_api_ctp/src/bt_api_ctp/gateway_instrument_query.py` 读取 `VolumeMultiple`，可作为合约乘数的候选原生字段；其投影却固定 `quote_currency=CNY`、`contract_value=VolumeMultiple`、`contract_multiplier=1`。字段名称或 fingerprint 不能建立币种、经济语义、适用合约、来源授权与时效，不能把该投影直接当权威；须依 provider 的原生合同核验，避免重复乘算。
- CTP `bt_api/bt_api_ctp/src/bt_api_ctp/market_tick_projection.py` 投影 `last_price`；最新收到的 tick 可以沿用旧的最新价，tick 时间或本地接收时间并不自动证明该价格对应最新成交发生时间，也未证明时钟域、顺序或覆盖。仅在本次检视范围内，尚未发现可信实时 FX producer；这不是对所有仓库或外部服务不存在该能力的断言。

## 拟议能力合同，尚未实现或冻结

1. **Provider / Gateway 账户 cut：** 为账户、场所、会话及代际定义完整身份与授权范围，证明持仓、活动订单、成交和外部活动的快照与流共享覆盖边界、追平、缺口检测及失效；明确查询终包、清流、跨日、重连和外部写者的语义。若上游无法提供可验证 cut，不用本地时间拼接，保持不可用。Gateway 保留来源绑定和账户读模型职责，Risk 不自建权威事实。
2. **Provider 价格与规格：** 按完整场所/合约键提供经来源、会话与授权绑定的最新成交价、成交时间及规格版本/乘数/计价币种，定义时间域、有效期、价格有效性及重复/缺口处理；不以最新 tick 单独断言最新成交，也不将字段命名或 hash 当授权。规格变更与合约映射须按版本失效。
3. **受信 FX：** 由适当 owner 提供清晰的币种对、方向、报价含义、来源身份、有效期与时钟、会话/版本及受权范围；统一币种由运营配置。方向、取值时刻、取整和缺失语义仍待冻结，不推定任意报价或默认汇率。
4. **Base / SDK / Risk：** Base 拟提供中立、明确类型与完整键的事实和能力合同；SDK 拟装配受权来源、验证会话与有效期并传播失效，不能由调用者自报布尔值替代授权；Risk 在适用的 reserve / claim 中检查来源和覆盖，按受权版本计算并保留 UNKNOWN 最坏占用。各 owner 的签发、撤销及持久恢复合同须单独审查，不能因 DTO 构造成功即放行。
5. **并发与恢复：** 规定 cut、事实、政策、订单状态和授权的版本绑定及最终消费条件；检查后发布、事务提交与发送间存在 TOCTOU，不假定跨组件原子。明确过期、重连、撤权、跨日、回放缺口、claim 后撤权及旧 UNKNOWN 的处理；未证明未发送时不得自动重发或释放占用。需要与 Gateway 的派发栅栏协商可证的失效方式，而非承诺可撤销已在途写入。

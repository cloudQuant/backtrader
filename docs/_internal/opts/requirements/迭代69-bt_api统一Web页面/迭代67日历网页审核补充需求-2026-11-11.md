## 用户需求

- 网页展示待审核的日历候选、交易所检查情况、差异、适用来源与覆盖，并支持有权限的审核人确认指定候选；按 D67-30 确认后立即尝试发布，不等待定时任务，发布前仍须重新核验。具体交互和后端步骤在 69 设计中确定，相关接口尚未实现。
- 根据 D67-23/24/25/26，网页须识别按日历目录统一配置的自动发布与人工审核模式，并显示实际模式、显式/默认来源及发布记录；配置未指定模式时默认自动，自动模式不要求人工确认，人工模式按既有审核合同处理。69 须提供模式修改入口，具有相应权限的人员可切换所选目录的模式，记录修改人、时间和旧/新值；与本地操作共用同一份目录级配置。后端接口、身份授权、配置版本及并发处理须在 69 与 67 联合冻结，不假设相关能力已经存在。
- 网页与 67 命令行操作同一候选、审核记录和发布流程，不在浏览器维护另一套审核或发布真值。人工审核模式保留一人核对、审核人、时间、候选内容与差异摘要，候选变化后旧确认失效并须重新审核；自动模式显示系统发布和版本记录，不伪造审核人。邮件提醒不等于审核。
- 网页经服务端提供的受认证、授权与审计的应用操作读取候选并确认；浏览器不直接读写日历文件或凭据。所需 SDK/服务 API、适配归属、身份和权限合同须在 69 与 67 协调并冻结，当前不假称已存在。
- 重复点击、并发命令行与网页审核、候选变化、网络断开及发布结果不明须按同一候选和发布身份核验，不得绕过当前模式要求、重复发布或虚报结果。区分待审核、已确认、已发布、失败和结果不明。
- 不改变 67 的交易日切换、可配置审核模式、部分交易所更新或已有数据覆盖处理；67 命令行仍可独立使用，未来网页不可成为 67 的交付前提。

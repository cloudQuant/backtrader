## 1. 产品目标与范围

- 建立独立 Python 包和 GitHub 仓库 `cloudQuant/bt_api_web`，在本机单独安装、启动和使用。源码、前端构建、Web 宿主及发布版本都由该仓库维护。安装预构建 wheel 后只需 Python。
- 用一个控制台管理 Runtime、Gateway、Risk、Execution、Monitor。总览显示五个模块的状态、最近观测、来源和待处理事项。点入模块后继续查看明细和执行已授权操作，切换过程保留选定的范围和筛选条件。
- 优先打通 CTP 的授权只读路径，再逐项加入各服务已有的管理操作。首版功能以当前服务的授权、作用范围和结果查询合同为准。接口缺口在对应模块和计划中明确标示，允许只部署部分组件。
- `ai-for-investor`（AFI）后续消费固定版本的 Web 产品。迭代 69 先约定 API 地址、路由、身份和主题的宿主接口，实际集成由 AFI 后续实施。
- 交易日历作为同一控制台的扩展，按第 7 节处理。迭代 67 继续独立交付 CLI 和日历服务。

D63-47 原定五个独立前端。D63-57 将 63.14 限于 Web 接口和宿主，D63-64 再将页面移交迭代 69，合为一个应用。本次明确 Web 维护仓为 `bt_api_web`。原各服务迭代继续负责业务接口和状态，D63-65 的 Gateway 接口缺口仍归迭代 63。交易授权、行情与账户来源、执行账本、风险判断及命令审计留在各服务。见[跨迭代合同与决策](../迭代63-Gateway统一转发与多策略共享会话/跨迭代合同与决策.md)。

## 2. 当前接口基线

2026-11-24 核对的公开源码位于 SDK `dev` 的 `347cc743`。下表记录可复用的入口和待验证限制。各接口的可用版本、认证方式、数据范围和进程行为在 69.01 核对。

| 模块 | 可复用的入口 | 接入时需要验证 |
| --- | --- | --- |
| Runtime | `bt_api_runtime.control_http` 的 `/v1/control`，含 `runtime.units.list`、`runtime.unit.status` 等版本化操作。 | 按当前主体显示授权单元。区分进程存活、心跳过期、启动或停止进度、仍有活动委托，以及写入结果未知。 |
| Gateway | `bt_api_gateway.web.app` 及 SDK 本机宿主，含控制原因、受限账户快照、命令准备与查询、DRAIN 目标。 | 账户数据校验原服务来源、作用范围与代际。控制原因的分页和账户读模型分别展示。读模型缺失或无法证明来源时显示不可用。 |
| Risk | `bt_api_risk.web.app` 及 SDK 本机宿主，含状态、策略版本、锁存、未知许可、审计和受权取消。 | 显示本地计数的覆盖范围及规则版本。撤单的作用范围、Gateway 观察和逐笔终态按服务合同区分。 |
| Execution | SDK `ExecutionManagementReadClient` 提供按母单或请求身份读取本地账本及计划的入口。 | 先确认现有查询覆盖。从有权限的精确查询起步，母子单列表、分页、分配和撤销按各自接口推进。保留本地状态与场所回报的区别。 |
| Monitor | `five_component_health`、`observation_query` 和只读事件模块提供健康快照及受权查询。 | 核对已部署读源、授权和游标。监控观察显示来源、时间和丢失区间，保留只读边界。 |

Gateway 历史前端雏形可用于参考术语和交互。统一控制台的页面源码和发布版本归 `bt_api_web`。核对旧页面是否仍启用，并在迁移时确定命令入口的切换点。

## 3. 页面功能与交付切面

总览按当前部署展示五个模块。状态含可用、退化、未配置、不可用、拒绝、过期与未知。每项展示来源、观测时间、作用范围和必要的覆盖提示。单个模块超时或授权失效时，其他模块仍可查看。读失败时标记旧结果的时间和状态。演示模式须主动开启，并在总览和明细中标明演示来源。

| 模块 | 第一阶段读取 | 第二阶段管理 |
| --- | --- | --- |
| Runtime | 策略运行单元、进程状态、心跳、启停进度和停止摘要。 | 经 Runtime 执行授权范围内的启动、停止与有限代理恢复。展示受理、执行中、失败与最终停止结果。 |
| Gateway | CTP 会话状态、授权账户与策略视图、活动委托、作用范围和控制原因。 | 对已有命令提供受权施加、解除及 DRAIN 目标处理。D63-62 将目标限于可能在途的委托。界面分别呈现原因解除、阻断仍在和整体恢复。 |
| Risk | 规则版本、额度与覆盖、锁存、未知许可、取消意图、审计。 | 按现有授权提交规则版本、释放锁存或请求取消。区分只取消与阻断并取消，逐笔查看实际结果。 |
| Execution | 母单、已取得的计划和子单、分配或转换、对账及未知项。 | 对当前合同明确支持的母单提交取消，并按原请求查询终态。 |
| Monitor | 来源健康、事件、指标、告警以及已知缺口。 | 只读。 |

读取和管理各自验收。全账户一致快照、Execution 聚合历史和告警流的显示范围由接口证据决定。缺少接口时可交付其他模块，验收矩阵保留对应缺口。

## 4. 独立包架构与技术选型

```text
浏览器
  │ 本机同源 HTTP
bt_api_web（SPA、Web 宿主、会话与服务适配）
  ├─ Runtime 控制接口
  ├─ Gateway 已有 Web 或 SDK 接口
  ├─ Risk 已有 Web 或 SDK 接口
  ├─ Execution 受权查询和管理接口
  ├─ Monitor 只读接口
  └─ 日历审核接口（迭代 67 提供）
```

- Web 宿主作为独立进程启动，默认绑定 loopback。同源提供页面和版本化 API。每个模块用显式来源配置和有界请求连接现有服务。按 D63-63，读取超出预算仅影响该次读取。Web 退出和重启只影响 Web 会话与自身客户端资源，服务的账户连接、订单及准入状态由原进程继续管理。
- 采用组件适配层、类型化 API 客户端、页面视图与宿主适配四层。上游响应经字段约束后进入浏览器。记录来源、状态和必要时间。缺失组件与协议不兼容各有明确状态。服务账本、日历目录和策略配置由所属服务读写。
- 参考本机 AFI `91cb89b8` 的公开构建清单。前端选 Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus 和 Axios，确有指标趋势时再引入 ECharts。后端选 FastAPI、Pydantic、Uvicorn。具体版本和兼容范围在 69.01 通过清单与锁文件确定。
- 发布预构建前端资源随 Python wheel 的独立包，记录 API 版本、构建版本及校验摘要。AFI 后续固定消费版本并注入宿主所需的接口地址、认证、路由和主题。AFI 已有 Gateway 操作和进程监督入口，迁移时明确哪一处保留命令入口。

## 5. 身份、授权和命令语义

1. Web 本机会话和服务操作权限分别验证。宿主将会话映射到各服务认可的操作者身份，各服务核对对象、账号、策略、合约和权限。浏览器只使用 Web 会话，场所凭据和服务私钥留在服务端。对接方法、会话过期、撤权及同源写保护在 69.01 确定。
2. 管理动作仅调用所属服务已授权的操作。界面展示作用范围、目标及预期版本。运行、解除、规则发布和撤单等动作使用服务定义的命令标识与内容摘要。双击、并发标签页及重复请求沿用原命令标识。
3. 响应丢失、超时或断开时保留 `UNKNOWN`，按原命令标识查询。状态分开表达受理、执行中、部分完成、拒绝、未知和已确认。服务保存操作者、目标范围、请求及结果的审计链。
4. Monitor 始终仅提供观察。暂停、恢复、冻结、规则变更和撤销等能力缺少受权接口或可查结果时保持不可用。页面保留已有 Gateway、Risk、Execution 的准入和恢复判断。

以下均为计划项。先核对服务接口和部署，再建立最短的浏览器至真实服务只读路径。不同模块可以逐项完成。涉及账户的检查使用各服务规定的授权和测试环境。

## 7. 交易日历扩展

- 迭代 67 拥有候选、审核记录、发布和目录级模式的真值。CLI 和 Web 共用同一套应用操作。
- 页面查看候选、交易所检查结果、差异、来源、覆盖、实际模式及发布历史。按 D67-37 区分 AKShare 与 `MOCK/SYNTHETIC` 的来源和证据。按 D67-23 至 D67-26 显示目录的自动或人工模式，以及显式或默认来源。配置有效且模式未指定时使用自动模式。
- 获得权限的操作者可以确认指定候选，并修改所选目录的模式。模式修改记录操作者、时间及前后值。人工审核记录核对者、时间、候选和差异摘要。候选变化后重新审核。自动模式的发布记录保留系统身份。
- 按 D67-30，确认后尝试发布并重验候选、配置版本和权限。按 D67-27，人工转自动只改模式，旧候选不会因切换而直接发布。刷新、重复点击、CLI 与 Web 并发及发布结果不明时，按同一候选和发布身份处理。
- 验收覆盖授权与越权、CLI 与 Web 一致性、目录模式切换、候选变更、重复确认与发布未知状态。缺少受权写接口时保留可验证的读取部分。详细语义见[补充需求](迭代67日历网页审核补充需求-2026-11-11.md)。

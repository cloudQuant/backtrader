## 1. 目标与行业最佳实践定位

### 1.1 业务目标
在 `bt_api_web` 统一控制台中，让操作人与策略负责人无需查日志或直连 SQLite，即可直接、诚实、低延迟地看到以下核心实盘交易指标：
1. **有哪些策略在运行**：每个策略单元的运行状态（`RUNNING / STOPPED / CRASHED / UNKNOWN`）、执行阶段（`LIVE / WARMUP / RECONCILING`）、心跳新鲜度与延迟、进程存活、`run_id`、退出码及是否受 Gateway/Risk 控制影响；
2. **账户资金与风险指标**：动态权益（Equity）、账户余额（Balance）、可用资金（Available）、冻结/已用保证金（Locked / Margin）、保证金占用率（Margin Ratio）、**总名义市值（Gross Notional）**、**净敞口（Net Notional）**、**多/空头市值（Long / Short Notional）**、**总杠杆（Gross Leverage）**与**净杠杆（Net Leverage）**；
3. **有多少持仓**：以 Gateway 权威账户持仓为主表（交易所、合约、多空方向、总仓/今仓/昨仓、开仓均价、最新价、合约乘数、名义市值、估价状态），并与策略本地归因严格区分展示；
4. **都做了哪些交易**：活动挂单（Open Orders）+ 账户级持久化成交与委托回报流水（Fills / Orders Blotter），对 `UNKNOWN` 状态显式高亮，绝不静默吞并。

### 1.2 行业最佳实践双层架构

#### （1）前端 UI 信息架构：双视角分组导航
参照机构 OMS / PMS / RMS 控制台标准，左侧导航拆分为**两个职责清晰、互不混杂的分组**，完整保留既有运维页面与向后兼容：

- **分组一：`交易与组合`（Trading & Portfolio）**
  - `/portfolio`（**账户与敞口**）：核心 KPI 条（账户权益、可用资金、冻结/保证金与占用率、总名义市值、净敞口、总杠杆、净杠杆、运行策略数）+ 账户资金表 + 覆盖完整度/行情新鲜度诚实提示条；
  - `/strategies`（**运行策略**）：全量策略清单表（关键词筛选、状态过滤、运行阶段、心跳、进程状态、接入模式、`run_id`、控制状态叠加）；
  - `/positions`（**持仓监控**）：主表「账户权威持仓（Gateway + Risk 同口径估值）」+ 明确隔离的副区「策略归因与账户对账边界」；
  - `/trades`（**委托与成交**）：三标签流水页（「活动挂单」「成交明细」「全部委托与回报」），支持搜索筛选并显式高亮 `UNKNOWN`。
- **分组二：`系统运维与风控`（Ops & Guardrails，完整保留）**
  - `/overview`、`/runtime`、`/gateway`、`/risk`、`/execution`、`/monitor`、`/calendar`。

#### （2）后端数据归属与计算边界（严禁 Web 壳私自算账）

| 指标类别 | 权威归属组件 | 架构原因与 Fail-Closed 规则 |
| --- | --- | --- |
| 策略运行状态与心跳 | `bt_api_runtime`（叠加 Gateway/Risk 控制状态） | Runtime 拥有策略进程生命周期与心跳；Web 仅展开既有 `runtime.units.list` 明细 |
| 账户资金、账户持仓、活动挂单 | `bt_api_gateway` | Gateway `/api/v1/scopes/{scope_id}/snapshot` 是唯一绑定 `journal_id + owner_generation` 的券商账户只读真相源 |
| 账户级委托与成交回报流水 | `bt_api_gateway` | Gateway `direct_execution_events` 持久保存经认证的成交/委托/错单回报；新增只读不改游标的倒序分页查询 |
| 名义市值、总/净杠杆、保证金占比 | `bt_api_risk` | Risk 同进程持有 `AccountSnapshot`、合约乘数 `RiskInstrumentBinding` 与带质量标记的实时行情 `PriceFact`；由 Risk 以精确 `Decimal` 计算并输出只读摘要，保证页面杠杆与风控拦单同口径，缺价格/缺乘数/零权益时严格返回 `null` 与 `missing_reasons`，绝不伪造 `0` |
| 统一展示与聚合读壳 | `bt_api_web` | 仅做有界只读投影与严格 Pydantic 校验（`extra="forbid"`），绝不接触券商凭据、绝不修改上游账本、绝不掩盖不完整或旧数据 |

## 3. 不可退让的 Fail-Closed 红线

1. **严禁 Web 壳私自估算市值或杠杆**：若 Risk 未提供有效的合约乘数、实时行情价或正权益，前端与后端必须显示「未知 / 部分可估」与 `missing_reasons`，严禁填充 `0` 或用未校验价格替代。
2. **严禁混淆「账户权威持仓」与「策略归因持仓」**：持仓主表只展示 Gateway 账户级权威持仓；策略归因独立分区并标明「本地归因，非券商权威」。
3. **严禁泄露敏感信息**：所有新增接口均不得输出原始券商账号 ID、登录密码、CURVE 密钥、Bearer/Session token、确认 token 或本地文件系统路径。
4. **严禁破坏既有合同与测试**：`/api/v1/dashboard`、`/api/v1/risk/status`（无新参数）、`/api/v1/scopes/{scope_id}/snapshot` 保持 100% 向后兼容；只读流水查询严禁修改任何消费者游标或 ACK 状态。

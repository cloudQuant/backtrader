## 2. 架构与安全红线核验

1. **后端归属清晰，Web 壳绝不私自算账**：
   - 运行策略清单来自 `bt_api_runtime` `runtime.units.list`（完整展开全量单元并叠加 Gateway 策略级控制状态 `STOP_NEW / FREEZE / DRAIN`）；
   - 账户资金、柜台权威持仓与活动挂单来自 `bt_api_gateway` `/api/v1/scopes/{scope_id}/snapshot`（维持 `journal_id + owner_generation` 证明）；
   - 账户级近期成交与委托流水来自 `bt_api_gateway` `/api/v1/scopes/{scope_id}/executions`（基于 `direct_execution_events` 倒序只读分页，验证 `direct_execution_consumers` 行数为 `0`，绝不修改任何策略消费游标或 ACK）；
   - 名义市值、多/空头敞口、净敞口、总杠杆、净杠杆与保证金占比全部由 `bt_api_risk` 基于 `RiskFactsCache`（`AccountSnapshot` + `InstrumentFacts`/`RiskInstrumentBinding` + `PriceFact`）以精确 `Decimal` 计算，通过 `GET /api/v1/risk/status?portfolio_summary=true` 输出。
2. **Fail-Closed 诚实展示验证**：
   - 任一持仓缺价格、价格 `quality_ok != True` 或缺合约乘数时，Risk 返回 `valuation_status="INCOMPLETE"`、`gross_notional / net_notional / gross_leverage / net_leverage = null` 并列明 `missing_reasons`；`bt_api_web` 前端严格显示 `—` 与缺口原因提示条，绝不补零或估算；
   - 柜台权威持仓（Gateway）与策略归因账本在 `PositionsPanel.vue` 中通过独立隔离边界卡片明确区分，绝不混算；
   - `UNKNOWN` 委托与异常回报在 `TradesBlotterPanel.vue` 中通过顶部告警横幅和行内 `UNKNOWN · 需核对` 标签显式高亮；
   - 未认证访问 `GET /api/v1/portfolio`（`--connected` 模式）返回 `401 UNAUTHORIZED`；携带非法查询参数返回 `400`；上游短暂故障时保留最近一次成功快照并显式标 `is_stale=true`；所有接口均返回 `Cache-Control: no-store` 且无任何凭据/密钥/原始券商账号泄漏。
3. **既有功能 100% 向后兼容**：
   - 原 `/api/v1/dashboard`、`/api/v1/calendar`、`/api/v1/risk/status`（无 `portfolio_summary` 参数时禁止输出 `portfolio_summary`）、既有 7 个运维页面（`/overview`、`/runtime`、`/gateway`、`/risk`、`/execution`、`/monitor`、`/calendar`）与冻结控制面 `CONTROL_OPERATIONS` 均零破坏。

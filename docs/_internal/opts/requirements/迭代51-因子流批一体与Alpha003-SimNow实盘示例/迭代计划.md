## 1. 需求与完成边界

### 1.1 必须实现

1. **同一因子定义、三种使用场景**：Alpha003 同类 native/build 在研究、历史交易回测、实时增量计算中复用；策略与数据适配不得内嵌另一份公式。
2. **真实分钟行情**：SimNow tick 经 BtApiStore/BtApiFeed 形成一分钟已闭合 K 线；同一横截面各品种在指标推进前同步，不靠策略回调事后补救。
3. **自动主力映射**：以品种为单位选择实际月份合约，使用决策当时可获得的最新合格排名数据；支持每日刷新、受控换月，禁止把连续合约代码当可下单合约。
4. **原生交易链**：因子信号由普通 Strategy 发出，通过 BtApiBroker/BtApiStore 及明确的 SimNow SDK 准入送单；实际回报进入 `notify_order/notify_trade`，可核对订单、成交、持仓。
5. **可运行示例**：同一 examples 目录提供研究、回测、实时只读、显式授权模拟交易、记录与离线复算；真实完成至少一次由有效 Alpha003 触发的开平仓闭环和撤单验证。
6. **可持续运行**：处理预热、迟到、缺格、休市、断线、重启、换月、在途/UNKNOWN 订单、容量限制与正常退出。

### 1.2 不作为本轮扩大范围

不重写全部101公式，不引入第二套计算引擎，不在实时线程做 fincore 评价/训练，不实现未闭合分钟反复修订、任意频率混合、所有交易所接入或新的服务拓扑。不以资金实盘盈利、全资产同时成交、跨资产原子下单为验收目标。生产资金账户不在本轮授权范围。

“每个品种”是品种级主力覆盖，不是每个月份都交易；“跑通”不能缩为单资产 Alpha003、手写固定合约或只完成影子行情。开发时可先用小集合跑通，但最终须交付自动覆盖清单和受控的全目标品种运行。

## 3. Alpha003 的统一数学合同

```text
alpha003(i, t) = -corr_10(rank_U(open_t)_i, rank_U(volume_t)_i)
```

- `rank_U` 是同一时点、同一预定资产集合/组内的横截面 rank，不是该资产过去10根的时序 rank。
- 使用现有 `alpha101-v2` 规则：有限成员、精确 float64 ties、平均名次归一化、10格滚动 Pearson 相关。数学最短窗口10根，声明 `lookback_h=9`；实际预热取依赖 minperiod 和完整性要求的较大值。
- 本轮将数据频率明确设为一分钟，输入 open 与**该分钟新增成交量**。这是 Alpha003 的期货分钟应用，不是论文日线统计结果的重现。
- 不能对跨品种 open 先除乘数、价格标准化或各自归一化再声称仍是原 Alpha003。成交量使用一致的手数定义；乘数用于交易经济约束，不偷偷改公式输入。
- 常量窗口、缺失输入、预热不足继续给出原有不可用值/原因，不能填0、前填因子、改变相关系数定义或删去不一致行。
- 期货各品种价格水平差异大，open rank 可能连续10分钟不变，因而相关系数无定义。必须在实际只读观察中报告有效值覆盖率和原因；多品种不保证每个品种每分钟都有有效因子。
- 交易策略要求同截面输入完整、至少两个可交易且因子有限的候选，并且分数有非零差异。若整个窗口没有有效信号，交易项为 `BLOCKED / NO_VALID_SIGNAL`，不能另造“验收因子”下单。

## 4. 架构：共用因子图，分离数据、决策与执行

```text
历史数据/实际保存的分钟带 ──> 研究 FactorStrategy ──> FactorPanel / 可选 fincore
                         └─> 普通交易 Strategy ──> 回测 Broker
SimNow SDK ─> BtApiStore ─> BtApiFeed ─> 同分钟截面交付 ─> Cerebro
                                                        │
                                          同一 Alpha003 / 原生子指标图
                                                        │
                                          不可变当前因子快照/交易决策
                                                        │
                             Strategy.buy/sell/cancel -> BtApiBroker
                                                        │
                             BtApiStore -> 选定的 SimNow SDK 执行路由
                                                        │
                             订单/成交回报 -> Broker -> Strategy/记录
```

- Cerebro 是唯一的 feed/indicator 调度者；不手工调用 `next/once/advance`，不在 pandas 里重算到最新再给策略读。
- 必须复用50交付的共享绑定/cohort，暂用其 `LiveFactorPlan/LiveFactorSet/LiveBarCohort` 名称；缺口回共用模块补齐，不在示例实现第二份。
- 028使用普通 `bt.Strategy` 组合因子集合，仍调用buy/sell/cancel；不强制新的策略基类、`submit_factor_order` 或服务部署。快照只包含计算状态，账户/执行状态由策略与原Broker链处理。
- 研究、回测、实盘共用因子类、参数、字段、group、时间/缺失规则；回测与实盘共用同一策略决策函数。研究不下单，回测使用本地匹配，实盘使用 BtApiBroker。
- offline `runonce=True/False` 与 live `runonce=False, preload=False` 均在各自合同内使用；native/build 的选择是独立配置，不因接实盘自动换实现。
- `FactorStrategy` 的固定 ResearchSpec 和 live 拒绝保持；批量完整数组优化仍可生效，不把 live 循环缓冲索引硬套给批路径。

## 5. 品种集合、主力选择与换月

### 5.1 可复现的“最新主力”定义

本示例当前采用用户选定的临时政策 `ctp_query_snapshot_equal_weight_v1`：在一个完整、同一TradingDay的当前查询快照中，对所有合格月份合约按 `score = 0.5 × OpenInterest + 0.5 × Volume` 排序并选最高分。旧政策 `legacy_previous_complete_day_eod_oi_v1` 保留为显式兼容选项：使用最近已发布的完整交易日EOD数据，按OI降序、Volume降序、到期日升序、实际InstrumentID稳定排序。配置必须明确选择政策；不得在数据缺失时自动切换、混合两条路线，也不得把盘中查询快照标成前一完整日EOD。

1. 目标默认是当前SimNow路由返回的完整CTP期货目录中的全部普通期货合约，不用手工合约表或产品白名单缩小验收池。以 `(ExchangeID, ProductID)` 分组；仅依据目录的真实 `ProductClass`、交易状态、到期日等元数据纳入普通、可交易、未到期月份合约，排除期权、组合、连续指数与无效合约。排名时保留目录和行情返回的原始 `InstrumentID`；许可、保证金和可下单资格是后续独立判定，不改写排名。
2. 使用空过滤器请求完整合约目录并等到终止标记；排名查询必须覆盖按目录与到期规则筛出的每个合格月份普通期货。预期ID集合只包含可参与排名的候选：目录明确标记的期权/组合、非交易、已到期及不足5个已证实交易日到期安全距离的合约逐类记录排除，不要求这些排除项有行情行；若交易日历无法证明候选至少有5个安全交易日，阻断资格判定；候选集合缺失/重复、无法映射或跨TradingDay时阻断该快照及全池结果，不得静默去掉可见性不足的合格候选。无法分类的额外行阻断。CTP当前深度行情查询只代表查询时可见的快照，不是历史EOD排名能力；当前来源无法证明全池覆盖时，保留 `MAIN_CONTRACT_DATA_UNAVAILABLE` 和具体原因。
3. 仅当两个原始计数的单位和语义可直接相加时计算等权分数；保存原始OI、Volume、单位、公式和分数，不做隐式标准化、按乘数加权或改写累计Volume。分数降序；同分依次按OI降序、Volume降序、到期日升序、原始InstrumentID的确定性字典序破同分。若无合格候选，阻断而不产生空映射或回退合约。
4. 查询路线上，TradingDay取本次真实查询结果中的来源日；`available_at` 是该结果实际 `completed_at_utc`，不追记到更早时点；`as_of`只表示完整查询批次的可用边界，不宣称供应商在同一瞬间原子采样全部行。必须绑定真实请求/会话generation、开始和完成时间、完整终止结果及记录摘要；默认 `max_snapshot_age_seconds=300`、`max_collection_span_seconds=300`，两者可配置但在运行前冻结，且只作为选定新epoch时的准入条件。已接受映射在冻结的TradingDay/epoch内持续有效，不因快照年龄超过300秒自动重选或停止新开仓；执行报价仍独立按原新鲜度合同检查。只有下个TradingDay的受控切换或明确的epoch失效才重新查询选主。每行保留原始 `ActionDay`、`UpdateTime`、`UpdateMillisec` 和来源TradingDay；查询完成时间不等同于逐行tick接收时间。OI/Volume快照新鲜度单独按查询年龄、采集跨度和完整回包检查，不套用执行价格/tick的quote-age阈值；执行报价仍按原报价新鲜度合同检查。
5. EOD兼容路线使用其实际发布/可用时间和前一完整交易日标签，交易日与夜盘归属按已验证交易日历确定。过期、非完整、候选覆盖不全或OI未知的数据阻断，不可改走查询快照或另一算法“补齐”。
6. 候选须至少有**5个已验证交易日**到期安全距离；只能在交易日历能证明剩余安全距离时纳入。已知未来日历足以证明不少于5日的远月可参与排名；无法证明5日安全距离的边界候选按未知处理并阻断资格判定，不合成未来交易日。交易权限、tick size、乘数、手数、涨跌停和保证金条件分别检查。
7. 不可变选择清单记录policy/version/权重、来源与query/request/generation身份、TradingDay/as_of/available_at、开始/完成时间、原始摘要、预期/实际ID集合、逐候选原始值/单位/score/排除原因、选中真实InstrumentID及epoch生效边界。分别呈现发现、合格、排除、已映射、可计算和允许交易集合；未覆盖项明确阻断。
8. 启动时使用当前有效TradingDay的已完成快照选定主力，随后在该计算epoch内冻结映射，不随tick或每次查询重新切换。TradingDay切换也先结束旧epoch：停止旧映射的新开仓，撤销/确认旧单终态并对账、平清旧合约持仓；存在UNKNOWN或未完成处置时不得开启新epoch。处置完成后再取得新TradingDay完整快照、生成新清单并重建全组因子状态。
9. 历史研究/回放只能读入当时已保存且 available_at 不晚于决策时点的原始快照/清单，并以同一policy重算；禁止回放时发起未来查询或用事后快照重选、回填历史。缺失原始快照、摘要不符、政策版本不符或时点越界均拒绝。

公开来源能力依据为SimNow官方CTP Mini接口文档：ReqQryInstrument支持空过滤器查询且以终止标记结束；ReqQryDepthMarketData提供当前查询快照，含TradingDay、合约ID、Volume、OpenInterest及来源更新时间字段，不提供历史前一日排名保证。具体实现仍须用实际SDK响应证明查询范围与完整性。参见 [SFIT CTP Mini API v1.2](https://www.simnow.com.cn/DocumentDown/api_3/5_2_4/CTPIIMini_API_Ver1.2.pdf) 和 [SFIT CTP Mini API v1.7](https://www.simnow.com.cn/DocumentDown/api_3/5_2_4/SFIT%2BCTP%2BMini%2BAPI-V1.7.0.pdf)。

### 5.2 更新与受控计算批次

- 启动或TradingDay切换时按已冻结政策取得通过准入检查的完整快照并创建新epoch；快照年龄/采集跨度门槛只在创建时检查。一个epoch内主力映射固定，不按tick、快照变旧或统计刷新改选/停开仓。保存原始快照、旧/新清单和生效边界。
- TradingDay切换先停止旧epoch的新开仓，撤销并确认旧单终态、对账并平清旧合约持仓；UNKNOWN或未完成处置时不启动新epoch。之后才使用新TradingDay快照选择并装配新Feed/新Cerebro。旧持仓始终属于原InstrumentID，不改名；每笔撤单/平仓/开仓仍须原授权与明确终态，不假定换月原子完成。
- 首版用受控 epoch 切换：旧计算实例停止，保留必要旧单回报处理直到对账完成，然后装配新Feed/新Cerebro并预热。暂不实现运行中的动态 `adddata` 或指标目标集合变更。
- 任一品种换月会影响整个截面的 rank，因此重建**全组**相关滚动状态，不能只清空换月那一个品种。
- 新合约从合格预热数据或实时完整分钟开始；禁止无说明拼接旧/新月OHLCV。首版跨映射边界重置窗口，不引入连续复权算法。
- 自动换月逻辑用确定性旧→新主力事件完整测试；自然真实换月若未发生，单列 `NOT_OBSERVED`，不能当作已经真实验证。

## 6. 一分钟行情、横截面与预热

### 6.1 时间与量价

- 桶为交易日历中的 `[start, end)` 一分钟；研究grid使用UTC `close_time=end`，保留Asia/Shanghai会话日期、TradingDay与ActionDay。日/夜盘、午夜和休市分别处理。
- 从源tick确定事件时间，不能用接收时间修补无效ActionDay；本机单调时间用于等待预算，不是交易所时间证明。显著陈旧的7×24事件时钟不能通过重写时间戳混入正常交易profile。
- CTP累计Volume差分生成分钟成交量；启动首tick、换交易日、重连及回退必须验证基线，不能把当日累计量灌入首分钟，不能对负差取绝对值。报价变化但无成交不产生虚构OHLCV。
- 保存原始tick/闭合bar的来源、序号、generation、时间、质量和成交量完整性，以同一条不可变记录驱动line与日志；不能用后来的“最新行情”反造旧bar证据。
- 未闭合、强制flush、起始半分钟或成交量不完整的bar不可交易。无tick不能仅靠本机整分钟计时宣告完整；等待预算到期只能形成明确缺格。

### 6.2 固定截面与共同交易时间

Alpha003横截面组在一个epoch内固定。首版只在全组交易日历的**共同交易分钟**发布截面；不同夜盘终止时间、午休、无夜盘品种不能用旧价格补齐。共同分钟表在运行前冻结：例如全目标池日盘，或明确配置的同夜盘组；这不自动把一组拆成不同公式。

共同日历没有包含的分钟不生成gap；共同日历包含、但任一品种缺数据的分钟是gap。研究、回测、实时使用同一格序列；不能只从实际到达的bar求交集来隐藏行情丢失。首版跨正常休市保留滚动窗口，窗口是最近10个计划内格，不是10个连续自然分钟；变更映射则重建。

在任何指标执行前准备整批同 `close_time` bar，所有成员各推进一次，完成校验后才运行原Cerebro指标图。`notify_bar` 也不能提前对半批截面做业务决策。使用50的prepare/交付分离实现，覆盖 `_load/_check`、重试、全None、EOF；不得建立隐藏旁路。coordinator继续受预算地接收和有界暂存未来事件，但不发布下一批line，旧bar证据不可变，当前执行报价单独更新。

迟到在有界缓冲内按格排序；重复相同数据去重，已封存数据不回写，冲突冻结。50-A须先通过09a冻结重建，再通过09b的Alpha003缺格继续推进profile；不等待50-B全101才解锁该profile。任一必需成员缺格时禁止新开仓，数学membership与数据present分别保存，窗口恢复后才重新就绪。未知profile继续冻结，原订单回报/查询及获准风险处置不断流。

### 6.3 预热与恢复

- **无历史也能启动**：第一条有效tick建立累计量基线，丢弃首个不完整桶，然后等待实时完整截面完成预热；默认预热30格且不少于实际minperiod。不能把“CTP没有历史接口”变成示例永远不能运行。
- **有历史加速启动**：读取明确来源的同合约、同一分钟/日历/成交量口径数据，经同一因子图预热；历史/live重叠去重，直到所有Feed越过同一cutover才允许交易。
- 研究/回测可直接消费保存的同一分钟带和主力清单。缺失或版本不一致拒绝，不悄悄改成其他市场的数据。
- 状态为 INITIALIZING → WARMUP → CATCHING_UP → LIVE_READY；缺格/断线/UNKNOWN进入 DEGRADED/RECONCILING，随后全组预热或补数恢复。历史、追赶和重复格永不补下历史信号。
- 重启先恢复并查询既有订单/持仓/决策，再恢复因子。没有可证明的原单状态时保持不可新增风险；重建因子不允许清空交易去重状态。

## 7. 从因子分数到实际订单

### 7.1 示例的固定策略

研究评价与策略盈利是两件事。本例采用可解释、可冻结的工程策略，回测和实盘完全共享：

1. 每个LIVE_READY完整截面读取原始 Alpha003 与明确 `direction`，默认方向+1。
2. 在预先授权交易子集中排除不可用分数，不改变因子计算池。候选至少2个且最高分严格大于最低分时，最高分的信号目标多1手、最低分的信号目标空1手；同分按品种key稳定排序，最高最低同分则不交易。信号目标不等于可立即执行的订单。
3. 默认最多2个品种持仓、每合约最多1个未决意图；每5个合格分钟检查一次调仓。先减旧风险、确认平仓，再开新风险；不依赖跨品种原子成交。
4. 最大持有格数、停盘前退出与本轮结束平仓是预先冻结的规则，不能为了验收临时加手工交易。当前无有效信号不新开仓；已有风险仍按其原规则处理。
5. 由信号目标结合实际持仓、在途量、资金、保证金、名义价值、最大损失、交易权限及手数上限生成订单；1手不等于低风险。没有可用保证金/元数据就不以固定现金比例猜单量，不能因最高分标的不能下单而临时换成另一排名规则。
6. 实单价格使用决策之后的新鲜bid/ask、tick size与涨跌停限制，采用限价单；不能拿已结束一分钟close假称保证成交。报价失效或被拒绝不盲目追价/换ID重下。

策略参数在实跑前冻结。预研究可据有效值覆盖率选择合理交易子集，但必须记录且对未来窗口验证；不得在看过实际结果后改因子、选择性删行或把手工成交计为因子成交。

回测同样遵守数据可用性：若10:00闭合的截面在10:00:02才全部可用，不能回到10:00:00的下一分钟open成交。具备tick/quote时用决策及提交之后可用的匹配事件；只有分钟数据时，采用首个开端不早于提交可用时点的后续bar作为最早匹配候选，再按正常限价匹配规则处理。不声称分钟OHLC能确定bar内的真实成交顺序，关闭cheat-on-open/close；交易成本与滑点单独配置。

### 7.3 决策身份、UNKNOWN与关闭

使用50的稳定业务key `(account_scope, strategy_scope, logical_run_id, cohort_id, close_time, decision_kind)`；子意图加入实际instrument/side/position_effect/leg，并关联品种、因子模式/版本、主力清单、目标和价格/数量。config/mode/清单变化属于payload，不能改key绕过去重；重启/generation/计算epoch只是诊断，同key不同内容拒绝。新逻辑运行须显式准入并核对旧单/仓和cutover，不在恢复时自动换ID。

复用50在选定路由上交付的最小持久决策/订单关联和查询恢复，不在028再造outbox。提交前后进程中断、发送超时、撤单未知时保留原ID，先查原单，不把“没收到”当“没发出”。无安全依据就停新单；仅永久冻结的实现不能通过完整恢复项，必须在已知终态对账和预热后证明新格可以继续正常交易。

处理部分成交、重复/乱序回报、撤单期间成交、今昨仓与交易所平仓标志。每个品种的方向仓与剩余委托分别核算。默认不接管用户既有仓位；启动发现范围不明的非零仓/活单则阻塞交易并明确报告。

正常退出先停止新决策，查询/撤销本策略已授权活动订单，并按预先同意的规则平本策略仓位，再核对最终状态、停止行情/交易资源。未知订单或未获准平仓不能假报FLAT。进程退出、Job为空与原生正常关闭分开记录；必要的有界监督沿用既有实现，不重建多代来源守卫体系。

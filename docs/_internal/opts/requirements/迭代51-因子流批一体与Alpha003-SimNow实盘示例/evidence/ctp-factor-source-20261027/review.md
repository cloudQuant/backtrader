The 028 path uses `CtpFactorSourceCalendar.from_grid()` to build one shared per-run calendar from the frozen common-minute grid and the exact selected exchange calendars. Its nested lookup maps and product/day sets are immutable on this production path. Calendar hashes, target products, selected product TradingDays, and each product’s non-overlapping session windows are checked before the calendar is passed to per-feed bindings. The conversion contract is the fixed `ctp-asia-shanghai-fixed-utc8-v1`; `clock_domain_id` remains the configured run identity label.

For each source-enabled feed, `project_ctp_factor_tick()` requires raw CTP TradingDay, ActionDay, UpdateTime and UpdateMillisec, the exact captured MD generation, local callback receipt, and the instrument/exchange route. It derives UTC only from raw ActionDay plus UpdateTime/milliseconds. Both the normalized `tick.datetime` and numeric `tick.timestamp` must agree with that derived instant before any no-session return, so an out-of-window quote cannot bypass event-time consistency. The selected Trader TradingDay must match the binding and the calendar’s selected product days.

The projector maps in-window timestamps to their exact product session and planned common minute. A quote with no common planned minute remains quote-only. A timestamp outside a session is also quote-only only when its raw ActionDay is among the local dates covered by that product’s selected TradingDay windows; it receives no session segment or planned close and is not aggregated. An unsupported date or session/member mismatch fails closed. This preserves endpoint, preopen and rest-period observations without treating them as tradable minutes.

The Store stamps source generation and receipt data only in the generation-aware callback bound to the exact active MD client. Enabling this source requires the direct registered SimNow route, a ready Store, and read-only Trader readiness; it does not fabricate an authenticated MD identity. A callback from a replaced client is ignored, and an active callback or reconnect with a generation different from the pinned run generation marks the stream stale and cannot restore health. The feed activates this logic only with an explicit binding and `cohort_source_mode=True`; the ordinary feed path keeps the default `None` binding and lazy-import boundary.

In 028, history selection/validation remains ahead of Store creation when the saved-history path permits it. For `ctp_query`, Store creation is necessary for read-only discovery; the current catalog/depth plan and session selection are frozen before Broker, Cerebro, and feed construction. The runner then uses the ordinary `store.getdata`, `cerebro.adddata`, cohort registration/seal, and Cerebro lifecycle. Source-binding failures before engine start retain the primary error and attempt normal Store cleanup; after engine start the existing Broker shutdown evidence controls whether Store closure is claimed.

The earlier review findings on exact-end/off-session quote handling, checking both event-time fields before the quote-only return, and generation changes across reconnect were fixed in the frozen pins above. I found no remaining production-path blocker in the scoped static review.

# RegisteredSim discovery Store shutdown plan

Public-source analysis only, 2026-10-27. No imports, tests, private configuration reads, provider calls, or shutdown operations were performed.

## Source contract

- `RegisteredSimStore.registered_sim_wait_ready(timeout)` calls `_ensure_api_ready()`, then delegates to `api.trader_client.wait_ready()` and returns only a `bool` (`backtrader/stores/registered_sim.py:2494-2506`). `registered_sim_collect_futures_snapshot()` requires the already-connected Store, `RegisteredSimWrapper`, and its trader client (`backtrader/stores/btapistore.py:4027-4064`). The wrapper is lazily composed by `RegisteredSimStore`; its `sdk_api` property deliberately returns `None` (`registered_sim.py:1603-1632, 1889-1892`). Retain the exact wrapper and child-client references from the owning Store before close; the ordinary framework API does not expose them.
- The CTP wrapper constructs both `md_client` and `trader_client`, starts both, and waits for both to become ready. Its `disconnect()` calls `md_client.stop()` then `trader_client.stop()`, clears wrapper connection/order state, and returns no SDK receipt; `stop()` aliases `disconnect()` (`btapistore.py:2305-2391`).
- `RegisteredSimStore` fixes provider/backend to `ctp`/`direct` (`registered_sim.py:1646-1673`). In `BtApiStore.stop()`, the CTP direct path does not use the SDK-owned close branch: when connected it calls wrapper `disconnect()` and finally returns `get_command_health()`, not a `CtpNativeStopReceipt` (`btapistore.py:6055-6218`; `_sdk_mode` is limited to provider `btapi`, lines 3732-3738). That health result is not proof of native release. The `timeout` bounds Store worker waits, but the direct `api.disconnect()` call is synchronous rather than run through `_bounded_call`.
- A connection exception in `_ensure_api_ready()` is re-raised without closing the direct CTP wrapper (`btapistore.py:17997-18015`). For an unconnected, unstarted direct Store with no command activity, a later `stop()` returns early (`btapistore.py:6106-6120`). A later direct-path balance/readiness failure can already call wrapper `disconnect()` before re-raising (`btapistore.py:18037-18061`), so cleanup must observe the exact clients' saved stop state rather than assume no stop happened.

## Successful discovery session

1. If `store.is_connected is True`, use this path even when `registered_sim_wait_ready()` returned `False` or snapshot collection raised: the direct wrapper may still own a live session. After the ready/snapshot attempt, retain the exact `wrapper = store._api`, `md = wrapper.md_client`, and `trader = wrapper.trader_client` references. Require the wrapper and both clients to be present. Do not use `store.sdk_api` (intentionally `None`) or reacquire/replace clients during close.
2. Call `store.stop(timeout=...)` once to perform Store bookkeeping and its ordinary wrapper disconnect. Do not call wrapper `disconnect()` separately. The Store result is supplemental health only.
3. Require Store shutdown health to show `shutdown_state == "PASS"`, `worker_alive is False`, and `funding_worker_alive is False` (plus `store.is_connected is False`) before final acceptance. `get_command_health()` exposes Store worker/shutdown facts but no CTP typed stop receipt (`btapistore.py:8536-8609`). If `store.stop()` raises, the `finally` path may still mutate connection/shutdown flags; treat the exception as failure even if the later state looks closed. Never call `store.stop()` again. If Store-owned workers are quiescent, the exact client receipt calls below can still distinguish released clients from a partially stopped wrapper; otherwise retain custody and do not stop clients while a Store-owned worker may use them.
4. Once Store-owned work is quiescent, collect `md.stop_and_wait(timeout=...)` and `trader.stop_and_wait(timeout=...)` on those same references. After wrapper disconnect, each SDK helper uses that client's `_last_stopped_native_api` when `_api` is already `None`; it skips `_stop_native_session` for the already-detached API and waits/observes the saved Join/Release state (`bt_api_ctp/ctp/client.py:374-429, 3153-3164, 10634-10701`). If a Store disconnect raised part-way through, the same typed calls stop any still-published client API once and observe clients already detached by the wrapper. This avoids repeating wrapper `disconnect()` while still obtaining per-client receipts.
5. Treat native close as complete only when **both** receipts have `complete is True`, `native_released is True`, `thread_alive is False`, `timed_out is False`, and either `join_required is False` or `join_completed is True`. Preserve each receipt's `connection_generation` with the exact client identity. The SDK's `CtpNativeStopReceipt.complete` property enforces those lifecycle predicates (`client.py:249-267`).

## Startup/connect failure

1. Preserve the exact `store._api` wrapper and whichever `md_client` / `trader_client` objects were actually created. `connect()` validates configuration before creating either child; later failures may occur after one or both clients have started (`btapistore.py:2305-2369`). If failure is one of those pre-construction validations, record that phase. Otherwise, a missing child has no receipt and is not by itself proof of cleanup if construction failed before assignment.
2. After the failed discovery call has unwound, confirm no Store-owned worker is active (`worker_alive` and `funding_worker_alive` false, with no in-flight command); if not, keep custody rather than stopping clients concurrently. For each existing MD client, call `md.stop_and_wait(timeout=...)` once. For an existing trader client, call `trader.stop_startup_and_wait(timeout=...)` once. It fences an in-flight start and returns either `CtpNativeStartupStopReceipt` or, if the session advanced to a positive connection generation, `CtpNativeStopReceipt` (`client.py:10703-10858`). Do not call `store.stop()` as a substitute when the direct Store is still unconnected/unstarted; its early return can leave partial native startup untouched.
3. For `CtpNativeStartupStopReceipt`, accept only `complete is True`: the source defines this for `preflight_no_owner` (no API owner, generation 0) or `api_created_released` (exact attempt ID, confirmed native release, required Join complete, thread absent, no timeout). `factory_uncertain` and `api_created_unconfirmed` are incomplete. For a returned `CtpNativeStopReceipt`, apply the same `complete` predicates as above (`client.py:280-332`). The MD `stop_and_wait` receipt must also be complete.
4. If any receipt is incomplete, a call raises, or startup remains uncertain, retain the Store, wrapper, and exact client objects as live/uncertain custody. Do not repeat `stop`/`disconnect`, manually invoke native `Release`, kill a thread/process, or discard the retained objects. A previously performed wrapper disconnect in the balance-failure branch is observed through the saved client state by the typed methods; it must not be repeated.

Receipt `timeout` bounds the SDK's Join-observation wait; the source performs the client's stop/detach call before that wait, so it is not a wall-clock bound around every synchronous native operation. This is a source-backed sequence for the narrow discovery-only owner. It makes no account or wider Store/Cerebro lifecycle claim.

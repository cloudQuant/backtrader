## 1. 不可变规则

每个纳入迭代 41 inventory 的 strategy runtime 都必须在其已注册的 runtime directory 中存在且只存在一个
`config.yaml`。启动器必须先定位该文件、完成严格校验并生成脱敏的 `EffectiveRuntimeConfig`，之后才可初始化
provider、gateway、execution、risk、monitor 或策略对象。文件缺失、路径未登记、schema 不支持或配置不一致时，
必须以非零状态退出，返回确定的机器码，并保证 **0 网络连接、0 provider 写入**。

`config.yaml` 是本地必需、被 `.gitignore` 精确忽略的运行合同；同目录受版本控制的
`config.example.yaml` 和 preset registry 才是可审阅、可复现的模板/权限规范。普通 profile 的配置包含策略参数、`mode`、`preset` 与
非秘密引用，仍拒绝内联密码；密钥来自被忽略的 `secrets.yaml` 或受支持的操作系统 secret store。**CTP 私有配置例外（sandbox 与未来 live 共用字段）：** 使用者要求在其未跟踪、权限受限的私有 `config.yaml` 中填写一组成对的 `md_front`/`td_front`、或可选的有序 `front_pairs` 候选列表，以及合约范围与认证字段；不使用静态官方前置 allowlist，端点只来自这份显式配置，当前唯一登记的 CTP 私有只读路由仅开放于 `simulation/sandbox`；canonical `ctp:` 字段和 schema parser 保留未来 live mode/preset 的解析结构，但解析配置不会登记、授权或调度 live route。`front_pairs` 每项只有一组成对的 `md_front`/`td_front`，最多 8 项且不得重复，不能和旧的顶层单对字段并用。密封配置中的合约、交易所与 HedgeFlag 直接组成只读查询范围，并按支持的 CTP 字段规则校验；运行时不替换成单独固定的合约或交易所。公开输出与配置模板不得包含密码、可重放 capability 或完整账号。配置不得包含审批或能力开关。`config.yaml` 或 `secrets.yaml` 被追踪属于仓库卫生与 CI 静态检查的拒绝条件；
运行时 loader 不查询 Git index，不能把这项规则表述成它已完成的启动期检测。这样操作者只需从 bootstrap 得到一个明确的本地合同，
而无需复制或手改一组安全开关。
当前本地凭据解析器的 `runtime_secrets` 仅支持可验证 owner/mode 的 POSIX 文件；Windows 使用精确名称的
Credential Manager Generic 凭据，凭据内容只允许代码登记的认证字段。Windows 的 `secrets.yaml` 暂不构成已实现的安全读取路径。
CTP 私有配置在 Windows 上还须核验 runtime 目录与 `config.yaml` 的 owner/DACL：只接受当前用户、SYSTEM、Builtin Administrators 的显式权限，拒绝 Everyone/Users/Authenticated Users、继承或无法解析的 ACE，并把 metadata handle 身份与 loader 读到的配置文件身份比对；无法核验时 fail closed。仓库的精确 Git-ignore/未跟踪测试与真实账号验收仍是独立门；默认 registry 已登记 SimNow 私有只读路由，本机受保护的 `config.yaml` 已存在。当前 `doctor` 离线 exit 0；F 的 `bt_api_base` 与 `bt_api_ctp` 有 scoped pins，只限已登记 sandbox 只读 preflight。最新显式 preflight 已进入 TD，四项 account/position/order/trade 查询均零错误，但 exact-instrument query 的 83 条同交易所结果中仅一条是目标，当次 strict every-row certificate/adapter contract 以 `query_row_instrument_mismatch` 拒绝；随后 Join shutdown incomplete，整体失败。G 新 certificate 预期允许受约束的同交易所 superset，但真实 provider 重测未做。完整 preflight 的 MD 阶段未运行；独立 MD-only 诊断原生登录 15 秒超时（`market_login_timeout`）、无订阅/tick，Join pending、关闭未知、写入为零。managed 第三 parent pin 缺失，managed 写仍 NO_WRITE。

模式和预设只由 `config.yaml` 决定。命令行、环境变量、当前目录搜索、AI 产物或程序默认值都不得把一个配置从
`backtest` 改为 `simulation` 或 `live`，也不得改变其预设、账户访问、order route、能力集合或额度上限。命令行只可
选择一个已经 inventory 注册的 runtime directory；`--confirm-live` 只确认已配置且已获批的 live 合同，绝不选择或升级模式。

## 2. 最小配置

```yaml
config_schema_version: 4

strategy:
  id: example.momentum.v1

runtime:
  mode: backtest                 # backtest | simulation | live
  preset: local_backtest         # 必须与 mode 的允许集合匹配

parameters: {}
secrets_ref: none                # none | runtime_secrets | os_secret_store:<opaque-name>
```

`parameters` 只能传递策略和数据的已登记参数。它不能定义插件 `enabled` 标志、route、账户访问、provider、权限或风险上限；
这些由不可编辑的版本化 preset registry 解析。高级配置仅可在已声明的字段中收紧风控阈值，不能增加写入权限或放宽
preset 的限制。`secrets_ref` 不得携带秘密本体，并须纳入脱敏配置指纹；sandbox/live 的审批 receipt 由受信 registry/
operator profile 单独绑定，不能由用户配置选择。

CTP 私有运行目录的共享配置扩展目标如下。账号、密码与当前合约只保留占位符；公开的 BrokerID/AppID/AuthCode 默认值参考旧示例，接入前仍需由账户 owner 核对。使用者在本地 `config.yaml` 中填写一组成对的 `ctp.md_front`/`ctp.td_front`，也可改用 `ctp.front_pairs` 提供有序的 1–8 组唯一 `{md_front, td_front}` 映射；两种形式互斥。配置是运行时唯一的地址来源，不要求地址属于代码内的官方固定 allowlist，也不允许 CLI、环境变量或模板改变端点。单对直接原样使用；多对只对明示候选做有界、重复的无凭据 TCP connect 探测，按每端点 RTT 样本的中位数取较大值作为 pair score，最低 score 胜出，平分按列表先后。任一端点连接失败或超时则该 pair 不完整并排除；候选全部失败时稳定拒绝，不尝试配置外地址。被选 pair 在本次 provider session 和所有 MD/TD 回调期间固定。该检查只测 transport reachability，不导入 CTP SDK、不提供账号认证或 provider session。`instrument_id`、`exchange_id` 与 `hedge_flag` 也从同一密封块直接成为只读查询范围，经支持值校验后原样使用，不受单独固定的合约或交易所覆盖。路由不读取时间、日历、TradingDay 或 set 名称，也不自动发现 endpoint。旧 `selection`、`set1_profile`、`set2_profile`、`calendar_artifact`、`calendar_sha256` 等选择字段仍拒绝。代码向 provider 提供受信 `provider_environment='simnow'`，不从地址推断 set1/set2。配置 seal、文件权限、凭据验证、受审 SDK artifact provenance、账户/session read-only gates 与零写合同仍单独强制。显式运行配置准备器时可从 owner-only `.env` 读取 current、完整 SET1 编号组和成对 SET2 的 MD/TD 输入并转成无 set 标签的有序 `front_pairs`；重复 pair 去重，半组、冲突与超 8 组拒绝。准备器也支持显式 owner-only YAML `front_pairs`。`.env` 仅作为准备输入；运行时只读取密封配置，不按 set 或时间选择。当前 YAML/multi-source helper 聚焦测试为 `51 passed, 3 skipped`，Ruff 通过；canonical 模板生成的 737 字节输出与受保护配置一致。此前 50/3 与 744-byte 输出仅是早期快照，已由当前结果替代。

用户配置不再包含 `selection`、`set1_profile`、`set2_profile`、`calendar_artifact` 或 `calendar_sha256`；这些旧字段必须作为未知字段拒绝。内部代码使用通用 CTP provider environment，不根据地址分类 set1/set2。已登记的 SimNow path 当前为认证只读：连接成功也不能替代账户身份核对、订阅后 tick 观察、结算、资金对账或模拟账号报撤单验收，也不改变 `external_write=0`。当前开发/QA 优先完成 SimNow。SimNow 与未来 production CTP 使用唯一物理文件 `examples/013_3_sa_midfreq_simnow/runtime-ctp-private/config.yaml` 和完全相同的 canonical `ctp:` 字段结构；未来切换需要在该受保护配置中变更 `runtime.mode`/`runtime.preset` 为经审阅的 live 合同，并替换其账户、front 与 instrument/contract 参数。该配置变更本身不授权网络/写入；共享 CTP runner 的 live dispatch 和准入仍未实现。现在不维护第二份生产 config，不收集/索取生产账号字段。运行前置只来自 sealed `ctp:` block 的明确单对或 `front_pairs`，不按 set 标签、时钟、日历、TradingDay 或服务时段选档，也不探测配置外地址。旧 `ctp_production` 私有 schema、独立 production 目录与准备器归为 legacy/deferred migration，不是当前操作者流程。新的纯 `sealed_config` production scope-binding contract 可从 sealed live `ctp:` block 派生非授权 scope identity，但不验证 approval receipt、key/signature、credential ACL、artifact provenance 或写权限。另，`ctp_production_action_binding.py` 已有逐动作 production scope/credential 的纯离线合同；旧 SimNow binding type 会被拒绝，8 项定向合成测试与 Ruff 通过，默认 verifier fail-closed。该模块未接 SDK 或真实 verifier，也未开放默认 route；维持 `NO_WRITE / LIVE_NO_GO`。该 identity 当前含 registration digest，而 registration 含 approval receipt digest，故未来审批 verifier 必须建立并测试非循环的 verified receipt-to-scope binding；scope identity 单独不能证明审批新鲜或有效。任何将来 production 准入仍需独立 artifact/account/session、账户控制、审批和逐请求写门审查，且不得复用 SimNow receipt 或批准。时钟、日历、TradingDay 与服务时段不参与任何运行前置选择。

可复制的占位符文件见 [CTP SimNow 私有配置模板](templates/config.ctp.example.yaml)。旧 013_3 示例中的历史配置不作为 Iteration 41 runtime schema；其历史 SA 自动选约与 CZCE 日历用途仍属于 Iteration 22 策略，不为本私有 runtime 提供前置选择依据。

The `prepare-ctp-production-config` CLI and internal second-config writers are retired and reject before source or target I/O. Keep the parser and path as migration/audit evidence only; do not create or maintain that second config, route it through the default CLI, or treat its selector/parser tests as production readiness. The intended future contract reuses the registered runtime's one `config.yaml` and the shared CTP field shape: an explicitly reviewed live mode/preset plus that file's account, front-pair and instrument/contract parameters. The shared CTP runner has no live dispatch, approved SDK pin, account session or write route today; changing those config values alone must remain fail-closed. The legacy read-only candidate selector remains injection-only and non-authorizing. Before any future production dispatch, the shared config contract, runner, independent artifact/account/session admission, approval and per-request write gates all require implementation and review. See the [legacy production-runtime audit](../../../../../examples/007_ctp/runtime-production/README.md) for historical code details.

## 3. 模式和预设矩阵

| `runtime.mode` | 允许的 `runtime.preset` | 有效访问和写入合同 | 必须条件 |
| --- | --- | --- | --- |
| `backtest` | `local_backtest` | 仅本地数据/本地 broker；0 网络、0 外部 provider 写入 | 无密钥、无审批；所有外部能力禁用 |
| `simulation` | `replay` | 离线重放；0 网络、0 provider 写入 | 无密钥、无审批 |
| `simulation` | `shadow`、`paper` | 仅 preset 允许的公共读取或本地假设成交；0 provider 写入 | 任何写路径必须由有效配置在 provider 边界拒绝 |
| `simulation` | `sandbox` | demo/SimNow 等隔离环境；registry 的 `write_policy=deny` 默认只允许经认证的私有只读，外部写入为 0；只有已登记 `write_policy=receipt_required` 的 profile 才可能受管写入 | read-only profile 不加载三能力；write profile 缺受信 receipt 必须拒绝，不能静默降级为只读。取得 receipt、账户隔离证明及 execution/risk/monitor 预检后才可写隔离账户；production 写入始终为 0 |
| `live` | `managed_live_direct`、`managed_live_gateway` | 受管 execution → risk hard gate → 监控控制面的生产写入；direct/gateway 仅为 preset 内的账户连接方式 | 有效 live 审批、配置指纹匹配、账户/时段/能力预检、显式 `--confirm-live`；任何失败均不写入 |

`sandbox` 的 registry write policy 也是密封 effective contract，不能由 `parameters`、CLI、secret 或 receipt 自身选择；
receipt 只能满足已经登记的 write profile。不存在 `live_direct` 或“无配置 direct”的用户可选项。为了兼容既有 Backtrader 适配代码，实施可以在某些安全的
`simulation` preset 内解析出受写入封锁的 legacy adapter；这属于 `EffectiveRuntimeConfig` 的内部实现，不能成为用户绕过
配置、风控或审批的入口。每次启动须记录 `mode`、`preset`、脱敏有效配置指纹、允许写入类别和被拒绝的 override。

## 4. 面向操作者的入口

迭代实现已提供一个统一的、配置优先的 `bt-runtime` 入口，替代不同 example 各自的 mode 参数和插件组合。
当前默认 inventory 共 16 条：13 条 source/example `simulation/replay` runner、1 条无 runner 的 CTP SimNow `simulation/sandbox` 私有只读注册、1 条公开 OKX `simulation/shadow` 只读观察，以及 1 条 package-owned `backtest/local_backtest` fixture；该入口不能被用作 live launcher。fixture 只在本地以 Cerebro 跑 4 根 packaged CSV bars，且为 0 network、0 external writes、0 orders/fills/provider submissions、`actual_pnl=NOT_APPLICABLE`，不提供一般 backtest 或部署路线。

1. 首次建立一个 runtime 时执行 `bt-runtime bootstrap --strategy-dir <已登记目录>`。它只在
   `config.yaml` 不存在时生成最安全的已登记 v4 文件；文件已存在则拒绝覆盖并提示使用显式迁移或人工审阅。可选
   `--preset` 只能选择该 runtime 已登记的安全预设，省略时不需要作选择。
   需要准备多个普通 replay 示例时使用 `bt-runtime bootstrap --runtime-set iteration41-replay`；该名称由代码 inventory
   固定，CLI 不接受用户提供的目录清单或 manifest 文件，并会先预检所有目标后才逐目录原子创建。两条仅供工程验收的
   fake-provider L2 另在 `iteration41-managed-replay-l2`，不能据此推导 CTP、SimNow 或 live 权限。
   CTP SimNow 私有 route 因需要本机认证字段和使用者明确填写的行情/交易前置，`bootstrap` 不生成看似可运行的占位符配置；使用者从[专用模板](templates/config.ctp.example.yaml)准备受保护且未跟踪的 `config.yaml`。填完后可先运行离线 `doctor` 排查字段与配置候选，再用同一个目录执行只读 `preflight`；`doctor` 不是 `preflight` 的安全前置。单对直接使用；多对仅在明示的配置候选中按有界 TCP 探测选路，不按时间或日历选档，失败不切至未配置端点。模板本身和旧策略参数配置绝不作为运行时回退。
2. 日常直接执行 `bt-runtime run --strategy-dir <已登记目录>`。`run` 会重新校验配置 schema、preset 和
   已登记策略合同，再调度绑定的 runner；它不执行 provider/account preflight。CTP SimNow 账户与行情只读预检
   由单独的 bt-runtime preflight 执行；I2 当前官方 TD retry 七项 native query terminal/complete、无 query/provider/submit error，但 Join shutdown incomplete，完整只读 preflight 仍拒绝。instruments 为 83 条同交易所行含 1 个目标，margin/commission 各有目标行但 ExchangeID 空、scope unverified。独立 I2 MD-only 在 one-second teardown grace 后仍因 request_id_mismatch / zero ID strict reject，无 ACK/tick、零写入。当前 I2 runtime 为 1156 passed, 26 skipped, 1 warning in 70.83s，SDK CTP offline 为 566 passed, 1 network test deselected；详见[验证汇总](evidence/validation-summary-2026-09-24.md)。
   `doctor` 是可选的只读诊断；不需要操作者手工拼装 plugin flags 或重复选择 mode。
3. 已登记的 CTP SimNow 私有只读 profile 可执行 bt-runtime preflight --strategy-dir <已登记目录>；单对配置按 sealed config 原样使用，多对只探测显式候选后，在所选 pair 上执行只读会话。该路线在受审 SDK artifact provenance 与认证账户 gate 后做七项 TD 私有查询，再以原始 md_front 执行有界 MD 登录、单合约订阅和订阅后有效 tick 检查，拒绝/只读写计数为零。选路不读取时间、日历、TradingDay 或 set 名称，失败不回退。I2 artifact pin 仅限该 registered read-only route；当前完整 I2 preflight 因 TD Join shutdown incomplete 被拒绝，MD-only zero-ID mismatch 保持 strict reject。较早 instrument strict-row mismatch、H2/I1 结果均属历史。当前 runtime/SDK 与 provider 边界见[2026-09-24 验证汇总](evidence/validation-summary-2026-09-24.md)。managed default write admission、账户级 writer fence 和 production live route 仍未验收。
4. 排障执行 `bt-runtime doctor --strategy-dir <已登记目录>`。它只输出脱敏诊断、有效配置摘要、mode/目的地、
   写入与 PnL 边界及下一条安全命令；普通路径缺配置时提示 bootstrap，受审 CTP 私有路径提示从专用模板准备受保护的本地文件。
   它不连接 provider、不下单、不修改配置，也不导入 runner；runner 只在 `run` dispatch 时懒加载。

对于 `live`，`run` 在所有预检通过后还必须要求 `--confirm-live`，并把确认绑定到本次的配置指纹和受信审批 receipt digest。该额外动作
用于避免把已修改的 live 配置误当作旧审批运行；它不能跳过审批，也不能将 backtest/simulation 升级为 live。

## 5. 必测负向合同

实现和验收至少覆盖：缺失 `config.yaml`；schema v3；非法 mode/preset；CLI/环境变量覆盖 mode；普通 profile 的内联秘密；CTP 私有配置不受保护/被 Git 跟踪、缺认证字段、未知 profile、自定义 front、未核验交易日与凭据脱敏；未登记目录；
`bootstrap` 覆盖已有文件；backtest/replay/shadow/paper 的 provider 写入；sandbox 对 production endpoint 的写入；以及 live
缺审批、指纹不匹配、未确认、配置变更后的重启。每一种拒绝都要证明初始化之前没有网络和 provider write；所有允许写入的
路径都要证明其模式、preset、审批、风险许可和监控状态可追溯。

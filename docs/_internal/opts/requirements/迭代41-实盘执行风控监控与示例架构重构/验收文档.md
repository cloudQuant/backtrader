# 迭代 41 验收文档

状态：`PLANNED`。所有验收使用 `PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`；不得用 exit code、文档更新、
replay、shadow、wheel 安装或历史 receipt 单独推导出真实交易/盈利/production 结论。

## 1. 证据与环境合同

每个 `PASS` 至少保存：

- `backtrader`、`bt_api_py` superproject、以及实际启用的 `bt_api_execution`、`bt_api_risk`、`bt_api_monitor`、
  `bt_api_gateway`、selected transport（本轮为 `bt_api_transport_zmq`）的 commit 和 submodule pin；若使用 wheel，则保存版本、SHA-256、安装位置、解释器和所需
  public API 导入位置；
- test profile、完整命令、环境隔离条件、开始/结束时间、退出码和 JUnit/结构化结果；
- 每个写入 runtime 的 route attribution。配置化路径保存 canonical directory、`config_schema_version: 3`、
  `runtime.order_route`、`runtime.account_access`、`plugins.{name}.enabled/required`、resolved descriptor/distribution/pin/schema、attach result、
  实际 gate/control/gateway/transport state、redacted configuration fingerprint 与零 I/O preflight 结果；`legacy_direct`
  可无 `config.yaml`，保存其原生 Broker/Store/provider 身份、认证/会话/协议前提与 route 标识即可。不得保存
  原始 secret、完整账户 ID 或可重放的 credential material；本地 `config.yaml` 可以保存凭据，但其内容绝不作为
  验收证据保存、上传或打印；
- 不含凭据、完整账户标识、approval capability、恢复 token 的 journal/outbox/health/对账脱敏摘要；
- 对外部会话，另外保存新鲜的操作者原件指纹、前后账户快照、订单/成交/撤单事实、清理与最终对账；
- 失败时的第一个失败断言或明确外部阻断原因，不能以大批级联错误替代根因。

除明确的外部 gate 外，所有 contract、fake-provider、fault-injection、replay、shadow 验收必须零真实
provider 写入。测试资产有写入需求时，只能经过受限 `TestExecutionProfile` 和独立外部 acceptance。

## 2. 验收等级

| 等级 | 允许结论 | 不允许结论 |
| --- | --- | --- |
| L0 | contracts、静态 inventory、单元语义正确 | provider 可写、策略已准入 |
| L1 | fake provider/故障注入下的 journal、risk、monitor、恢复正确 | 真实交易所/CTP 行为已验证 |
| L2 | 每个 example 的 replay/shadow 迁移和零写 telemetry 正确 | SimNow、production、盈利、HFT 资格通过 |
| L3 | 一个具备外部条件的受管会话，或一个按 provider 原生规则运行的 direct 会话，在真实时段完成指定观察/对账 | 策略自然信号或长期运行已自动准入；direct 会话不因此成为受管 |
| L4 | 独立研究、账户授权、真实成交、风险与运行证据共同签收 | 不适用；这是后续准入计划，不由本迭代自动给出 |

## 4. 必须覆盖的负向情形

下列情形必须以确定性 fake/provider harness 或受控 profile 测试：

1. 空/错误 risk policy、risk evaluator 异常、policy halt、频率/每日额度耗尽；
2. permit 过期、重放、篡改、跨账户、跨环境、跨 TradingDay/epoch、跨 connection generation；
3. reserve 后、journal 后、发送前、发送后、ack 前后分别进程崩溃；
4. timeout 但远端接受、晚到 ack、重复/乱序 callback、cancel race、远端查询失败；
5. 磁盘满、journal 损坏、writer lease 争抢、时钟回拨、outbox 重复/丢失；
6. 普通额度耗尽后请求紧急减仓，及紧急额度耗尽后的安全裁决；
7. 两策略相反 intent、不同价格/TIF/deadline 的 intent、净额化后 gross 限额绕过；
8. partial fill、舍入 remainder、费用/funding 分配与框架通知不守恒；
9. provider 不支持 native OCO/batch/slice/basket，却有 parent/OCO/transmit 请求；
10. monitor/TradeLogger 停机、伪造控制 command、自动 resume 尝试；
11. CTP 日历缺失、夜盘归属错误、TradingDay/账户/connection generation 漂移；
12. crypto 行情陈旧、stream conservation 失败、重连期间存在 unknown order；
13. examples/test 子进程直接调用旧 writer 但未登记为 `legacy_direct`，或 `managed_execution` 初始化失败后自动调用旧 writer，或 README 用长 duration 绕过短时 candidate 合同；
14. 日志、receipt、metric label、异常栈泄露密码、approval root 或 capability。
15. 显式请求 `managed_execution` 或 `gateway_client` 的 strategy runtime 缺失 `config.yaml`，将 `config.example.yaml` 当作运行时
    fallback，从 CWD/父目录/其他 example 找到意外配置，错误 `runtime.order_route`/`runtime.account_access`/schema/version/identity，重复/未知
    key，YAML include/import/env interpolation、artifact path 的绝对/上跳/符号链接逃逸，或修改配置后仍复用旧 permit；
    与之相对，无 config 的 `legacy_direct` 不应被错误拒绝或触发 module preflight；
16. `plugins.*.required=true` 与 `enabled=false` 的冲突、`managed_execution` 未启用 execution、`gateway_client` 未成对启用
    gateway+transport_zmq、`direct_provider` 启用 gateway/transport，或 managed writer 绕过 execution；`legacy_direct` 被伪装为 managed，
    或 direct+enabled risk/monitor 未在真实 write/control boundary 执行 hard gate/checkpoint/freeze。还应覆盖已启用 capability 未安装/空仓/pin 不匹配、
    gateway client 携带 provider credential/伪造 account 或 strategy scope、server-side write 绕过所需 risk/execution admission、risk 放宽账户上限、monitor 自动 resume/下单，以及
    `config.example.yaml`、git index、日志、证据中出现 credential、完整账户 ID、token、DSN（被忽略的本地
    `config.yaml` 里的合法凭据除外）。

## 5. 最终裁决

迭代可在 AC41-01～36、38～46 通过且所有 scope 内路径已 `managed_execution`、`legacy_direct`、`DISABLED`、
test variant 或 `NOT_APPLICABLE` 明确归责时标记为
`ARCHITECTURE_ACCEPTED` 或 `MIGRATION_ACCEPTED`。AC41-37 可以因外部前提诚实地保持 `BLOCKED`，但必须
有新鲜阻断证据；它不能被补写成 `PASS`。

当 `bt_api_execution` 仍为空仓或尚未形成可安装制品时，AC41-01/07/34 只能证明父安装器安全地
`NOT_PACKAGED`，并不构成 execution 实现或本迭代完成；此时最终状态仍为 `PLANNED / NO-GO`。

即使最终为 `ARCHITECTURE_ACCEPTED`，也不等于任何策略已经 `LIVE_TRADING_ADMITTED`，更不等于盈利、
HFT 资格、期货公司 production CTP、native OCO 或跨 venue 原子篮子已经通过。那些结论仍需要各自的
研究、账户、provider capability、真实时段和外部成交证据。

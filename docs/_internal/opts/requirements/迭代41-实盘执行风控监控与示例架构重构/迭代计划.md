## 0. 实施范围与代码交付承诺

本计划明确包含下列**跨仓源码实现**，不是仅为未来开发保留设计占位：

| 实施域 | 源码归属 | 本迭代必须交付 |
| --- | --- | --- |
| Execution/OMS | `D:/bt_api_py/bt_api/bt_api_execution` Git submodule（初始仓为空） | 建立并实现新的公开 `bt_api_execution` 包；基于现有 `_ExecutionSession` 的兼容迁移完成 durable plan、parent/child、aggregation、allocation、capability、recovery、CTP/crypto lifecycle。 |
| 账户级 hard-gate | `D:/bt_api_py/bt_api/bt_api_risk` Git submodule | 修复当前风控错误，提供版本化 policy、跨进程 durable reservation、permit、settlement、freeze/drain 实现；以兼容 contracts 供 execution 最终 dispatch 使用。 |
| Monitoring control plane | `D:/bt_api_py/bt_api/bt_api_monitor` Git submodule | durable outbox consumer、checkpoint/health state、alerting、认证 control command 与运行 read model 实现。 |
| Shared account gateway | [`cloudQuant/bt_api_gateway`](https://github.com/cloudQuant/bt_api_gateway)（已创建，尚未 package/submodule） | 实现中间件无关的共享账户/session、订阅并集/fan-out、strategy/order correlation、snapshot/replay 与受限 command-routing contracts；不新建 OMS/risk/provider truth。 |
| ZMQ transport adapter | `D:/bt_api_py/bt_api/bt_api_transport_zmq`（近期拟建） | 实现 gateway 的首个 ZMQ socket/framing/security/ACL/backpressure adapter；不拥有 account/session、provider client、execution journal 或 risk ledger。 |
| SDK 组装与 provider 边界 | `D:/bt_api_py` superproject | 维护能力包 pin、optional extras/dependency lock、compatibility matrix、只加载 enabled runtime plugin 的 manager/composition adapter；绑定 provider port，不复制领域状态。 |
| 框架接入 | `D:/source_code/backtrader` | `BtApiStore/BtApiBroker` 双路径适配：execution 接入公共 API；direct 保持 native 行为但将已启用 risk/monitor attach 到真实 submit/cancel/control gate。 |

本计划明确维护两条运行路径，二者都必须在 inventory 中可归责：

- `legacy_direct`：无配置、无 `plugins` 或全 disabled 且均为 `required:false` 时，Backtrader Strategy 保持现有
  `direct_provider` 的 Broker/Store → provider 下单、撤单、查询行为，零 runtime-plugin import，`config.yaml` 不是前置条件。
  有效配置若选择 direct 且 execution disabled，仍保留 direct execution 语义：`direct_provider` 只可加载、验证并
  attach 显式 enabled 的 risk/monitor；`gateway_client` 则必须成对加载 gateway+transport_zmq，并可选 risk/monitor。
  risk/monitor 分别在 native 或 server-side writer 前 hard-gate、经 Broker control gate 执行 freeze/drain；
  `gateway_client` 只改变账户接入拓扑，不能自行授权写入。它始终须满足
  provider 原生或 gateway server 的认证、会话、协议与交易所/CTP 规则，也不因插件而获得 execution aggregation/journal
  或受管准入。
- `managed_execution`：只有有效 `config.yaml` 显式启用 `plugins.execution` 才进入 `examples → Backtrader adapter →
  bt_api_py integration → bt_api_execution → provider port`。这条路径使用 journal、capability、可选 hard
  risk gate 与 monitor control plane，并适用对应的 managed preflight。

`bt_api_risk → bt_api_execution contracts/RiskGate protocol`，`bt_api_monitor ← durable events/checkpoints`。
execution 不得反向导入 risk/monitor 的 concrete 实现；风险和监控包均不得反向导入 Backtrader 或成为
provider writer。`managed_execution` 不得在 config/schema/package/preflight 失败后自动降级为 `legacy_direct`；
`legacy_direct` 必须由无配置或显式 route 选择进入。现有 provider submodule 只实现 provider port，不承担 risk/monitor 领域状态。
每个工作包都必须交付真实源文件、submodule pin、定向测试、隔离安装/consumer 验收和脱敏证据；只提交计划、
mock、fixture、vendor 或 example-local copy 视为 `NOT_DONE`。

### WP41-G：运行时插件、共享账户 gateway 与首个 ZMQ transport 收敛（P0/P1）

## 4. NO-GO 条件

以下 NO-GO 约束 `managed_execution` 的实现、受管声明与自动路线切换；它们**不**把 inventory 已登记的
`legacy_direct` Broker/Store writer 判为错误，也不为 direct 给出 execution journal/交易准入结论。direct 仍须由其
provider 原生认证、会话、协议和账户规则决定能否连接/报单；但它一旦显式启用 risk/monitor，就必须接受真实
hard-gate/control 的相应约束。

- 任一未分类 writer、managed→direct 自动 fallback、第二 SDK client、第二账户 ledger，或在 `managed_execution` 中绕过 execution boundary 的 provider I/O；当 `runtime.order_route=managed_execution` 且 `plugins.risk.enabled=true` 时，任何绕过 `RiskPermit` 的 managed provider I/O；
- 当 `plugins.risk.enabled=true` 时，`bt_api_risk` 任一 policy/limit/evaluator 错误可返回允许，或本应 durable 的 managed 额度在重启/多进程下归零/竞争；
- journal/outbox/lease/capability/账户 scope/TradingDay/connection generation 不完整或不一致；
- 无 capability receipt 却接受 parent/OCO/transmit/basket/native algo；
- unknown order、未完成 cancel、残余仓位或对账不完整时允许新开仓；
- 当 `plugins.monitor.enabled=true` 时，monitor 自身故障、健康/控制状态缺失却仍将该组合声明为正常受监控，或任何 monitor 可自行产生普通开仓；TradeLogger、metrics 或 alert transport 仅为 telemetry，其故障不得改变 risk/execution gate；
- execution/gateway/transport_zmq 任一已选择能力尚未 package、未初始化/未 pin、optional profile 未锁定，或 SDK 通过 ambient editable import/vendor copy/PyPI fallback 取得能力；这不得阻止不导入能力的 `legacy_direct + direct_provider` 启动；
- `managed_execution` 或 `gateway_client` 缺少其目录内 `config.yaml`，schema-v3/version/strategy identity/`runtime.order_route`/`runtime.account_access` 不匹配，任何能力被隐式开启，或 CLI/环境变量/CWD/父目录搜索能够改变安全相关配置；无 config 的 direct_provider 是合法选择，但发现无效 config 时不得静默忽略并下单；
- `plugins.*.required=true` 而对应 capability disabled，或 managed 未启用 execution，或 gateway_client 未成对启用 gateway+transport_zmq，或 direct_provider 启动 gateway/transport；risk/monitor 未启用却声称其保障已生效，risk 配置在启用时能放宽账户 hard limit，或 monitor 配置能自动 resume/下普通单；gateway client 携带 provider credential、伪造 account/strategy scope，或 server-side write 没有再次经过所需 risk/execution admission，同样 NO-GO；`legacy_direct` 启用 risk/monitor 却**未**做到 provider-I/O 前 hard gate / Broker-gated freeze-drain，或把它们伪装成 execution journal、allocation、受管 receipt 或已准入，也同样 NO-GO；
- 本地被忽略的 `config.yaml` 以外的受版本控制文件、git index、日志、receipt、metric、错误或 configuration fingerprint 含有 secret/完整账户身份/可重放 capability；`config.example.yaml` 含有真实凭据，或 `config.yaml` 未被 `.gitignore` 忽略；
- CTP 日界/crypto 连续生命周期借由扩大 timeout 或自动重试未知订单实现；
- 任一 example README 的命令与实际 runner 限制矛盾，或泄露 secret/authorization；
- 以本地单测、replay、shadow、wheel 或文档代替研究、真实会话、成交、盈利或 production 证据。

## 5. 本轮不执行的事项

- 不执行未被独立准入的自然信号下单；
- 不用本计划的代码测试替代 SimNow/期货公司 production 的外部账户、交易时段、日历、审批和结算证明；
- 不把 `legacy_direct` 删除或误称为旁路；但不为受管路径失败保留可自动触发的 direct CTP/交易所写入 fallback；
- 不把策略 alpha、参数优化、成本研究或 HFT 延迟资格混入 execution 基础设施重构；
- 不在 Backtrader 核心创建 exchange-specific 风控数据库、monitor daemon 或订单聚合服务。

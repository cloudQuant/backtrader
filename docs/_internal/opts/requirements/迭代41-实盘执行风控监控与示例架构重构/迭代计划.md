### 0.4 用户操作最小主线（已实现的 config-first CLI）

统一入口名为 `bt-runtime`。当前源码已交付单个登记 runtime 的 `bootstrap`、`validate`、`doctor`、`run`，
以及仅接受代码审核 runtime-set 名称的批量 `bootstrap`；example README 只展示该例实际支持的 preset。

```powershell
# 首次创建：从受信registry生成唯一runtime/config.yaml；选择该 runtime 最安全的已登记预设，不连网、不启动策略
bt-runtime bootstrap --strategy-dir <registered-runtime-dir>
# 日常：重验config/schema/preset policy后运行；不重复输入mode/route/参数文件
bt-runtime run --strategy-dir <registered-runtime-dir>
# 如需真实 CTP 账户/行情只读预检，另行显式调用；当前 doctor 离线 exit 0。早期四候选 selector 的 index 3 / 411.9175 ms 与随后 SDK-origin gate 拒绝均为历史点时观察；当前五对 I2 TCP、TD retry 与 MD-only 结果见本页验收 checkpoint。
bt-runtime preflight --strategy-dir <registered-ctp-runtime-dir>
# 批量：只接受 inventory 中定义的 set 名称，不接受目录清单或 manifest 路径
bt-runtime bootstrap --runtime-set iteration41-replay
```

bootstrap 从 preset registry 写出对应 mode，校验目标不存在后原子创建；文件已存在时 `CONFIG_EXISTS`，
绝不覆盖、合并或隐式修复。批量 bootstrap 使用受信、代码绑定的 runtime-set，先一次预检所有目录/冲突，再按
目录原子创建并输出逐项结果；故障后可重试，已有完全匹配文件验证后跳过，内容不同明确冲突，不删除其他目录。
批量功能不自动写入 secrets、审批 receipt、或执行模拟/实盘。

旧schema/CLI迁移是维护者的一次性离线工具任务，也由A11交付：读取registry允许的旧文件，输出独立
待审v4草案和差异/保留参数报告，不覆盖正式config、不生成授权。无法唯一判定原模式或环境时
`MIGRATION_REVIEW_REQUIRED`，不能猜成live/sandbox。run/bootstrap不在后台执行这种旧格式转换。

日常用户只编辑这一份运行配置中的 mode/preset 与允许参数，再执行同一 `run`；切换会使旧 seal/receipt
失效，重新 preflight/独立审批。`--confirm-live` 仅确认 config 已选择且已审批的 live 合同，不能选择或升级
模式、绕过审批或恢复交易。live 启动缺该显式确认也拒绝；非交互部署使用同一已签运行确认合同，不能自动同意。
`validate --strategy-dir ...` 和 `doctor --strategy-dir ...` 是可选诊断，不是每次运行额外必做步骤；
validate 全程零网络/write，doctor 默认同样只读离线，并显示 mode、目的地、外部写边界、PnL 来源边界和下一条
安全命令。普通登记路径缺配置时 doctor 给 bootstrap 命令；CTP 私有路径给准备本地受保护配置的指引，
不生成含占位认证字段的可运行文件。联网诊断只能由受信只读 profile 明示执行且不发交易命令。
所有错误输出稳定 code、字段路径、脱敏原因与可执行下一步；不得要求用户手工计算 hash 或操作五插件布尔。

## 1. 总体交付顺序

```text
A 基线 / inventory / collector / ADR / 性能 spike
 ├─ B contracts + spine + B8 单 writer 切换
 │    ├─ C durable risk ─┐
 │    └─ D monitor ──────┴─ E 订单图 / lifecycle ─ F 两个 managed consumer ─ H(core)
 ├─ G1/G2 插件加载 / direct gates + G3 既有写门修复 ───────────────────────┘
 ├─ G4 shared gateway ─ G5 ZMQ ─ G6 多 client / CTP 能力 ─ H(gateway)
 └─ I1 shared evidence ─ I2 服务端 admission ─ I3–I7 三产品互操作 ─ H(AI)
```

`WP41-C` 与 `WP41-D` 可在 contracts 冻结后并行。sandbox/live provider 写入必须等待 execution、risk、monitor 和
adapter 通过对应验收；`legacy_direct` 只作为有配置的零外部写入兼容路径在 inventory 中归责。risk 与 monitor
在相应解析出的 profile 中都分别构成 hard gate/control-plane；managed 另有
execution permit/journal/recovery。未启用插件不得被表述为已生效保障。

G1/G2 的合同输入来自 B7，G2 依赖 C/D 的 gate/control 接口；唯一实施任务仍是 G1/G2，**提前进入核心**，
不在 B7/F1 重复实现 manager。G3 是已有 runtime 的安全修复，列入 A 基线差距后的早期提交，不等待 G4。
G4–G6 与 I 不阻塞 `direct_provider` 的核心阶段；一旦选用 gateway 或 AI admission profile，相关阶段的
全部适用 AC 立即成为该部署的前置条件。H 从 A 起持续运行，不留到最后一次性收集证据。

该 parent 映射 primitive 不证明 Backtrader 订单意图跨进程自动恢复。CTP 撤单请求的 `accepted` 只证明请求受理，不证明订单已撤；崩溃后缺撤单回执时保持 `UNKNOWN`，不得凭订单状态推断撤单成功。CTP 6.7.7 的 `ReqQryOrder`/`ReqQryTrade`/`ReqQryInvestorPosition` 只提供单次请求到 `bIsLast` 的回调终包，没有页码、总数或跨查询原子快照接口；`QueryResult.complete` 仅证明该请求流终结。账户级未结单准入仍需验证无截断范围、账户/TradingDay/generation、独占 writer、订单/成交/持仓证据及所选 authority 的对账；在独立完整性论证、ADR 冻结和故障注入前，`query_account_open_orders.complete` 保持 `false`，不得把一次终包或 fake 空结果升级为“账号上没有其他未结单”。

## 4. NO-GO 条件

以下 NO-GO 适用于全部 Iter41 runtime 的配置/模式准入、受管实现及声明。历史writer只作为迁移基线归责，
不能因曾经合法直连而绕过新的config/mode gate。内部native零写回归不获得交易准入。

- 任一未分类 writer、managed→direct 自动 fallback、第二 SDK client、第二账户 ledger，或在 `managed_execution` 中绕过 execution boundary 的 provider I/O；当 `effective_config.runtime.order_route=managed_execution` 且 `effective_config.plugins.risk.enabled=true` 时，任何绕过 `RiskPermit` 的 managed provider I/O；
- 当 `effective_config.plugins.risk.enabled=true` 时，`bt_api_risk` 任一 policy/limit/evaluator 错误可返回允许，或 managed/direct 所共用的账户 durable 额度在重启/多进程/混合 route 下归零、超卖或放大；
- journal/outbox/lease/capability/账户 scope/TradingDay/connection generation 不完整或不一致；同一 risk SQLite
  的 dispatch claim 原子性不得被表述为 execution/risk/monitor 跨库、provider I/O 或恢复流程的原子事务；
- 无 capability receipt 却接受 parent/OCO/transmit/basket/native algo；
- unknown order、未完成 cancel、残余仓位或对账不完整时允许新开仓；
- 当 `effective_config.plugins.monitor.enabled=true` 时，monitor 自身故障、健康/控制状态缺失却仍将该组合声明为正常受监控，或任何 monitor 可自行产生普通开仓；TradeLogger、metrics 或 alert transport 仅为 telemetry，其故障不得改变 risk/execution gate；
- preset选中的execution/risk/monitor/gateway/transport能力未package/未pin/profile未锁定，或通过ambient import/vendor/PyPI fallback取得能力；有有效config且完全离线的已支持preset可独立启动，不得缺配置默认启动；
- 任一runtime缺config或必需字段、schema-v4/version/strategy/mode/preset不匹配，旧schema被运行期接受，用户可覆effective route/access/plugins/capability、secret可切生产域，CLI/环境/CWD可改变安全配置，或配置删改后继续使用旧seal；

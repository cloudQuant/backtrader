# 000 三场所穿透认证：三件套快速通道（v2 修订，2026-10-09）

本页修订 [000三场所模拟穿透开发与验收](000三场所模拟穿透开发与验收.md) 的执行方式，不改其验收语义
（逐案例真实证据、写操作有界且可清理、UNKNOWN 冻结、tracker 只接受真实结果）。修订动因：旧的
"每案例定制管线 + 每轮 Root 托管仪式 + 逐轮独立复核"模式累计产生约 6.5 万行候选代码（仅 binance
`_certification/` 目录即 45k 行、单案例最多 9 个候选版本），却长期停留在 12/99 PASS，且 84 个案例
没有任何真实 runner。对照行业最佳实践（风险分级准入、单一实现、幂等重试、结构化证据、可复现运行），
执行层做如下替换：

## 1. 每案例三件套（唯一交付形态）

```
cases/<ID>/
  config.yaml        # 场景参数 + policy + 凭据 env 变量名（不含密钥）
  <ID>_strategy.py   # 案例逻辑（RISK: READ / WRITE / DANGEROUS）
  run.py             # 入口：干跑自检 / --live / 显式 --allow-write/--allow-dangerous
```

- 单命令运行：`C:/anaconda3/python.exe cases/<ID>/run.py [--live] [--allow-write] [--allow-dangerous]`；
  退出码 0 PASS / 1 FAIL / 2 BLOCKED / 3 UNKNOWN；每次运行写一份 JSON 证据到 `cases/<ID>/evidence/`（git-ignored）。
- 干跑模式校验配置与凭据 env 名称（不联网）；写授权必须显式给出，TRunner 在创建客户端之前拒绝。
- 已放置订单全部登记（`ctx.track_order`），任何失败路径由 runner 补偿撤单；UNKNOWN 冻结该会话写入。

## 2. 每场所一个最小 certlib（约 500–800 行，替代 4 万行候选）

- 凭据：仅按名从 checkout 根 `.env` 读取；证据中不出现任何账号标识字符串（仅伪名指纹）。
- 客户端：Binance/OKX 为 stdlib 同步 REST（服务器时间偏移补偿、签名、有限重试）；SimNow 为
  CPython 3.11 + dev `bt_api_ctp` 原生会话（穿透式 AppID/AuthCode 登录 + 结算确认 + 查询 + 报撤单）。
- 共享件：`monitor.py`（本套件监控记录器 + 阈值告警）、`validation.py`（本地交易前规则，dispatch_absent）、
  `runner.py`（统一入口）、`context.py`（CaseResult/证据写出）。
- 幂等性：读查询单次重试；写操作不重试；OKX 下单对 `50013 Systems busy` 以**同一 clOrdId** 幂等重试
  （`51016` 重复即视为已受理并回读）；SimNow 报单以"场内侧确认"为准（7x24 前置的回报可能滞后）。

## 3. 风险分级与证据链（保留原验收语义）

- READ/WRITE/DANGEROUS 三级；写案例必须 `--allow-write`，危险案例再加 `--allow-dangerous`。
- PASS 条件由案例自身断言并在 facts 中给出可复核事实（订单号/状态/成交/终态/清理结果/拒绝码与消息）。
- **证据化 BLOCKED 原则**：当场所机制确实不可达时，案例必须运行到能给出"为何不可达"的证据，再返回
  BLOCKED（例如 SimNow E01：引擎不校验资金且单笔上限 1000 手，资金不足拒绝不可达；EM03：SimNow 允许
  并发会话，服务端强制登出不可观测；Binance EM01：Demo 密钥具备持仓模式权限，权限拒绝不可复现）。
  不把"不可复现"伪造成 FAIL，也不把不可观测当成 PASS。

## 4. SimNow 写入准入（窄口径，已提交 SDK dev）

官方 SimNow 写入此前被冻结（`ctp_simnow_execution_not_admitted`），根因：单一写者账本/凭证版本绑定/
审批链未完成，冻结防止游离于账本外的真实报单。经用户决策采用**窄口径纳入**：将账号所用官方 SimNow
前置对（含 30002/30012、30003/30013 两组 VPN 补充前置）纳入 SDK 冻结白名单，复用
`arm_execution_for_registered_sim`（精确端点匹配、trading-ready、一次性武装、逐笔身份/交易日/连接代次
复核；生产端点永不匹配）。SDK 提交 `a497bab`（bt_api_ctp dev），离线契约测试 7 项 + 回归 163 项通过。
接入其它模拟账号时的规则：同前置新账号无需再注册；新模拟前置需一次可审计的精确端点注册；生产账号
永远只能走完整受管链（密封配置/审批/账本/围栏），不存在捷径。

## 6. 可选组件 16 拓扑（已完成，16/16 真实通过）

`topology: {transport: direct|gateway_zmq, execution, risk, monitor}` 已是每案例 config 的组成；runner 接受
`--transport/--execution/--risk/--monitor`。`examples/000_live_certification/optional16/` 提供：
拓扑规格（16 组合 id）、网关服务器（独占 provider 会话；localhost ZMQ，经真实 `bt_api_transport_zmq`
ROUTER/REQ，per-run token，JSONL 命令日志）、组件挂载（risk: 真实 `DurableRiskGate` 预留→占用→结算；
execution: 真实 `ManagedExecutionFacade`/`ManagedCancellationFacade` + 每次运行 SQLite 账本；
monitor: 真实 `DurableOutbox` 追加/确认）与矩阵运行器（每组合产出验收记录 `acceptance-matrix.json`）。
**真实运行结果：16/16 组合全 PASS**（binance，指定案例集 C01+T03，共 32 场真实运行；证据含
`imports_observed` 证明未启用组件包从未被导入）。网关能力验收（`gateway-capability.json`）真实 PASS：
双独立客户端共享同一会话（同 pid）、A 下单 B 可观测（订单归属）、坏 token 在命令前被拒、停服后写请求抛
`GatewayCommandUncertain` 且场侧确认未创建订单、命令 journal 全量入档。诚实缺口：本快照无请求去重/防重放
缓存；网关传输仅限 localhost + per-run token，非远程部署控制；`bt_api_gateway` 包的 router/receipt 链未接线
（其 GatewayCommand 需要回执摘要语义，认证场景不伪造成）；组件为 binance 参考接线，okx/simnow 保持直连认证。

版本：`baseline-4 / 2026-09-23`；状态：`PLAN_REVISED / PARTIALLY_IMPLEMENTED / LIVE_NO_GO`。
本记录依据用户本轮“参考四份审阅完善计划”及后续配置合同更新的授权作出计划层技术裁决。原始评审保持原文；

## 1. 责任与冻结

| 角色 | 对什么负责 | 最迟登记/签收点 |
| --- | --- | --- |
| 计划 owner（项目负责人角色） | 范围、资源、阶段取舍、变更基线；指定替补 | M41-0 开始时在 evidence 的责任登记中填写真人及替补；本文件不虚构人名 |
| 技术负责人 / 各库维护者 | 对其仓库 contracts、源码与 release/pin 负责 | A 完成前登记；接口冻结前签收对应 ADR |
| QA 负责人 | 独立审查用例、基准、证据和里程碑结论 | A 完成前登记，不以实现者自报取代验收 |
| operator / 运维负责人 | 凭据、部署、值守、人工 resume/接管、外部会话清理 | 外部会话或需值守运行前登记 |
| 策略研究负责人 | 候选研究、语义审阅、数据与自然信号准入 | 研究/部署 gate 前登记，与工程测试分离 |
| 四方评审角色 | 复核各自领域的处理结果 | contracts freeze 和范围变更时咨询；不替代账户授权 |

这是角色 RACI：owner 对范围最终负责，维护者实施，QA 对验收结论负责，operator 对外部运行负责；
其他角色咨询或知会。不得把无人承担的角色视为默许。资源和实名表是开发启动交付物，
本次文档修订不因尚未安排团队而停止，也不把估算写成团队已经承诺的交付日期。

`baseline-0` 为本轮修订前的 schema-v3 文档集合；四方审阅合并版为 `baseline-1`，以 schema-v4 必需配置
替代其可选配置约定的是 `baseline-2`。CTP SimNow 私有配置先由 `baseline-3` 增补，再由 `baseline-4`
改为显式成对前置地址；`baseline-3` 的自动选档/日历决定已废弃，仅保留为历史记录。
计划冻结事件是 M41-0 的 evidence manifest 发布：包含文档 digest、统一裁决表、FR/WP/AC 追溯、
ADR 索引、资源/角色表、技术 spike 的前提与风险，以及各责任角色签收。A 的盘点、离线 spike 和
安全门修复可先开始；依赖未定 contracts 的功能实现必须等待其签收。P0 技术选择已在本版裁定，
不能在冻结会上重新当作无记录口头约定。

变更规则：提交 `change_id/reason/source/affected_FR_NFR_WP_AC/compatibility/evidence_to_rerun/owner`，
维护者与 QA 复核后递增基线；涉及准入/账户 scope 还需 operator/研究负责人签收。测试失败不能通过
事后调高阈值或将 Must 改为非范围消除。外部 BLOCKED 每个里程碑或最多 30 天复审，过期为 NOT_RUN。

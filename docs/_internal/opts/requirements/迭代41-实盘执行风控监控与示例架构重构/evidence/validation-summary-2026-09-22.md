## 3. 本轮故障注入最小断言

- 配置 leaf 被替换、schema/inline AWS credential/mode override 被注入时，必须在 runner/provider import 前拒绝；runner 不可二次读取 config。
- admitted intent 与真实 Backtrader order 的 instrument、LIMIT、side、quantity/unit、price、offset、reduce-only、metadata digest 任一不一致时，risk 和 provider dispatch counters 必须为零。
- cancel ACK/UNKNOWN 后不得调用本地 terminal cancel 或清映射；重启后必须保留 freeze/reconcile，禁止自动重派。
- permit settle crash、DISPATCHING prepare crash、过期/伪造 writer lease、缺失或过期 sealed metadata snapshot 必须 fail closed。
- SDK confirmed fill 后、Backtrader framework projection 前的注入崩溃已验证：SQLite receipt 在 fresh framework session 恰好一次重建 order、position、commission 与 TradeLogger，且零 provider dispatch；但未验证真实账户 position/cash snapshot 对账、强杀、gateway 或跨存储/observer 原子恢复，receipt 不推导 Broker cash。

## 4. 已关闭的 Windows 目录替换范围、POSIX 局部加固、残余 P1 与 LIVE_NO_GO

- Windows 使用 `CreateFileW` 的 `GENERIC_READ` 目录 handle，允许读/写共享但拒绝 delete-share；handle 转为 CRT fd 后必须与登记 identity 的 `fstat` 一致。lease 覆盖 config load、bootstrap 和整个 runner 调用，所以本轮跨进程 regression 覆盖的 bootstrap/runner 替换不会在 replacement 路径留下本地副作用。
- 上述结论只覆盖普通 Win32 进程与当前本地文件系统；它不是 handle-relative 文件 API，也不覆盖特权、内核或文件系统实现绕过。
- POSIX 的受管 `bt-runtime run` 已局部加固：在取得登记目录 fd 后，dispatch 向 13 条 source/example opt-in runner（不含 package-owned `backtest/local_backtest` fixture）传入 `runtime_dir=None`、无路径 sealed effective/config/registration view、opaque registry token 和 opaque fd-backed capability；013_3 的旧 path-based evidence writer 使用 private workspace，不能重建被隐藏的 runtime pathname。runner suite `32 passed, 2 skipped` 与 runner + static inventory `38 passed, 2 skipped` 是 Windows 本地 portable contract/focus；实际 POSIX rename/symlink filesystem regressions 在本机为 `NOT_RUN`。公开 direct `run_runtime(..., effective=None)` 会在读取 `config.yaml` 或检查 runtime pathname 前以 `runner_dispatch_required` 拒绝，不能重新打开路径；`P1_POSIX_RUNNER_PATHNAME_DIRECTORY_REPLACEMENT_SIDE_EFFECT` 仍因实际 POSIX filesystem regressions 未执行，以及 path-free view/opaque token 不是 hostile in-process Python code 的隔离或沙箱而保持开放，未来 POSIX live 路径不得沿用。

## Dependency-ordered plan

1. **Freeze the decisions before changing acceptance wording.** Resolve the G1 branch below and identify whether an external Actor host/service, distinct OS identity, protected durable store, signing/trust key, authenticated transport and provider-owned account access can be supplied. Keep the current route deny state while these are unresolved.
2. **Build the next offline slice in an isolated copy: AccountActorPort r5 contract hardening.** Start from the frozen r4 payload, not the mutable report copy. Replace shallow cached route classification with a canonical immutable route snapshot and recheck its digest at each submit/cancel. Specify typed command, context, action identity and receipt fields; make actor absence, wrong route, bad receipt and stale epoch fail before local API/SDK/gateway access, with no fallback. Add multi-process/reopen replay tests and callback inbox/deduplication contract tests. A local ledger may test the protocol shape only; it must be labeled fake and must not stand in for remote account authority. Do not wire this candidate to the main Store yet.
3. **In parallel, define the real server trust boundary before extending the SQLite fake.** The server must own credentials and final provider dispatch under an independently authenticated service identity; it must atomically validate account/session/config epoch, reserve the command once, recheck the current full-account snapshot and fence immediately before the provider send, and persist terminal/UNKNOWN state and callbacks. State must be protected from the trading client’s OS principal. Specify crash recovery after CLAIMED, key rotation/revocation, cross-host writer transfer, backup/restore and same-version funds/orders/trades/positions snapshot semantics. r6’s SQLite/HMAC core can remain an adversarial test double; local SQL ACLs or another in-process secret do not close the same-principal counterexample.
4. **Complete main Store compatibility work only after the port contract stabilizes.** In an isolated candidate, migrate the 21 old CTP Store expectations explicitly (8 fail-closed cases and 13 future Actor cases per r2b QA), preserve supported non-CTP adapter behavior, and cover direct/gateway/forwarding/environment override/injected API/public aliases/worker queue/raw `Req*` surfaces. CTP must reject before environment rewrite, object attribute reads, secrets, imports, construction, autostart or connection when no trusted actor exists. Do not use skips/xfails to erase the migration. Require exact-base full Store/runtime regression and independent source-origin/hash verification before proposing any main-tree merge.
5. **Close G0–G4 read-only gates before any trading enablement.** Use one sealed config and exact pair; obtain accepted artifact/RECORD/origin/native module identity; satisfy the selected G1 contract; then prove TD login and all seven scoped terminal queries, native TD Join/Release completion, followed by MD identity, exact subscription acknowledgement, matching first tick and same TradingDay, then MD Join/Release completion. All facts must bind the same config/pair/session generation and show zero trade/settlement writes. The consumed I11/I12 one-shot markers are not reusable evidence.
6. **Close G5 with one durable authority.** Approve the ADR for the single active `OrderRef`/`ActionRef` and command ledger, cut over the Store, execution package and SDK to that authority, import/validate `MaxOrderRef` and cancel targets, and prove restart-safe reservation-before-send, callback identity and UNKNOWN-no-retry. Require one command identity through Store receipt, SDK outbox, native request and provider callbacks. Existing duplicate allocators and the r4 actor ledger cannot qualify.
7. **SimNow branch.** After G0–G5 and G6-S local control tests, require current account/TradingDay settlement readiness, then one tightly bounded, approved limit submit with remaining quantity, native order confirmation, exact cancel, terminal remaining quantity, and same-session queries reconciling orders/trades/positions/funds. Keep an independent close/flatten path and stop on any unknown, outside order or mismatch. This can at most support `SIMNOW_OPERATIONAL_ATTESTATION_TESTED` with the documented cross-host gap; strict F14 requires G6-P and a separate G7-P review. The official 7×24 environment is not evidence of settlement availability.
8. **Production branch.** Only after the same runner is implemented and SimNow evidence is complete, use the same protected `config.yaml` and canonical `ctp:` runner identity after closing the SimNow session. Re-run production-specific artifact, account/permission, credential, risk/limits, approval, monitoring/alerting, external fence, full snapshot and recovery evidence under G8-P. SimNow receipts do not transfer. Current production registration remains unavailable until these gates are independently accepted.

## G1 decision branches

- **Keep strict whole-command G1 (current requirement).** One trusted T0 must precede externally visible launch; the same D must include bootstrap, validation, service readiness, Job/pipe setup, child/native work, response/receipt I/O, pending-I/O completion and exact Job-empty proof. Current evidence does not meet it. A pure Python/C++ process tree cannot establish the required worst-case scheduling and bounded native-call behavior; proceed only if an external/platform mechanism with those guarantees and independent evidence is available. Otherwise keep ordinary `preflight` and all real-provider steps blocked. Offline port/server contracts remain safe work.
- **Adopt the narrower already-READY service contract.** This is a requirement change requiring explicit owner approval and a versioned ADR/matrix update before implementation. Scope a request from ticket publication to a service that is already READY; test startup/prewarm separately. State that UNKNOWN is classified when its owner next runs at/after D, caller observation can be later, nonreturning native calls and OS starvation are outside the promise, and unresolved Jobs/handles stay quarantined. This is an application-level request deadline, not hard whole-command return and not a G1 pass. It may permit a separately accepted service request path; it does not itself satisfy strict F14 or production gates.

## External prerequisites vs offline work

**Offline now:** isolated r5 route/receipt/replay contract; r6 adversarial state-machine test double and crash/reopen scenarios; exact main Store call-surface inventory and old-test migration; versioned interface/ADR drafts; fake end-to-end command identity and no-fallback tests. These can only yield `LOCAL_CONTRACT_PASS`.

**External/provider/owner dependency:** named service owner and host boundary; distinct service principal and protected store; service certificate/key and deployment pin; authenticated transport; dedicated SimNow and production CTP credentials/account permissions; actual provider callback/query completeness including settlement; vendor-confirmed native lifecycle semantics and mapped DLL evidence; normal SimNow environment with real settlement capability for G7-S; production risk limits, approval authority, monitoring/on-call and recovery/flatten authority; independent acceptance of any real order/cancel window. If these resources are unavailable, the path ends at offline contracts and `NO_WRITE / LIVE_NO_GO`.

## Minimum evidence package for any real trading claim

One immutable evidence bundle per account/mode/window: source revision and exact installed artifact hashes/RECORD/import origins; sealed config digest and selected MD/TD pair; G1 contract and timestamped owner/Job/I/O facts; same-generation TD/MD/native close receipts; complete scoped account snapshot and settlement evidence; durable ledger state before/after every command; approved per-action risk/admission and external fence epoch; request/OrderRef/ActionRef/provider IDs linked to raw callback classifications; terminal cancel/fill state and reconciled quantities/funds/positions; restart/crash/duplicate/late-callback results; zero unintended write and redaction checks; operator approval and independent reviewer disposition. Any timeout, UNKNOWN, mismatch, stale epoch, incomplete snapshot, missing close proof or unaccounted order is a failed/unknown gate and stops the run.

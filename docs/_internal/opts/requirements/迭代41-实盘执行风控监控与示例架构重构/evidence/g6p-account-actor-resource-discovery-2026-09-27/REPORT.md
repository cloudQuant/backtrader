Search of the default `backtrader_runtime/inventory.py` and package initializer found no candidate registration. These modules/tests are not a provider actor or external authority.

The F14 admission module is a contract seam with no network client, key, provider access, local-lock fallback, or write-route integration; it requires an independently authenticated authority that atomically claims an action, fences all account writers, and attests a complete snapshot at one version (module lines 1–14). The signed-receipt contract likewise says it has no issuer/service, durable cross-host replay ledger, or native dispatch (lines 1–15). The default managed-action verifier rejects and requires deployment-owned scope, permit, revocation, trusted-clock, and account-wide fence ports (`ctp_managed_action_authority.py`, lines 1–20).

### `D:\source_code\bt_api_py`: a real CTP gateway path, but not an authorized AccountActor

This checkout contains a process wrapper and CTP adapter: `gateway/process.py` can run `GatewayRuntime.start()` in a blocking process (lines 120–141), and `gateway/runtime.py` registers `CtpGatewayAdapter` (lines 32–39). The adapter builds CTP market/trade streams and directly maps submit/cancel into the CTP feed (`gateway/adapters/ctp_adapter.py`, lines 50–60 and 151–229; `feeds/live_ctp_feed.py`, lines 96–162, 418–455, and 500–565). Credentials are ordinary adapter arguments; the feed constructs `TraderClient`/`MdClient` and installs callbacks in that process.

That is a provider-facing gateway implementation, but its command boundary is not a trusted write authority:

- `GatewayClient.connect()` starts a `GatewayRuntime` thread in the same process by default (`gateway/client.py`, lines 68–85). A separate process is optional, not enforced.
- Windows converts default IPC to TCP loopback (`gateway/config.py`, lines 25–40 and 85–103). Custom endpoints are accepted. The ROUTER receives a client-chosen routing identity and dispatches its JSON command without an authenticator or server-derived principal (`gateway/runtime.py`, lines 173–193 and 228–287). Any caller able to reach the endpoint can request `place_order` or `cancel_order`.
- `OrderIdentityMap` is in-memory. `OrderRefAllocator` uses a process-local `threading.RLock` and a JSON state file; persistence errors are logged and swallowed (lines 30–73 and 112–169). This is not an account-wide, crash-safe unique action ledger or cross-process fence.
- CTP order/trade callbacks are converted into queue events (`live_ctp_feed.py`, lines 530–565); this path has no durable callback inbox, stable dedupe ledger, or account/session-generation admission before publication.
- The process stop path sends a signal and calls runtime/adapter stop; the CTP adapter joins its Python worker for one second and calls stream stop (`process.py`, lines 143–190; `ctp_adapter.py`, lines 84–91). No outer Job supervisor receipt proves hard-deadline containment, native Join/Release, callback quiescence, or safe fence release.
- CTP read operations are separate calls; no command binds funds, all open orders, trades, and positions into one authoritative version under an account fence.

The legacy tests exercise fake adapter transport plumbing and health/process helpers; they do not establish remote authentication, CTP authority, a unique account writer, or an atomic snapshot.

## Feasibility judgment

There is no G6-P-acceptable, independently authenticated AccountActor in the audited local code. There are two partial approaches: the older code owns a CTP client but lacks authenticated command admission and account-wide authority; the newer prototype has authenticated transport and durable local routing contracts but lacks a deployed service, actual CTP write adapter composition, trusted issuer/credential custody, cross-host/bypass-excluding writer fence, and same-version account snapshot. They are not safely composable by treating one as proof for the other.

The main blockers are architectural and need independent owner/provider evidence. A local SQLite epoch cannot stop a second host, manual terminal, or another SDK process from using the same CTP account. A Curve/ZAP principal proves who connected to one gateway endpoint, not that the gateway is the sole holder of the CTP credentials. Separate CTP query terminal callbacks do not create a common version of funds, all working orders, trades, and positions. A durable command receipt is not a provider acknowledgement. This matches the current acceptance matrix G6-P row: an external authenticated service must supply cross-host account writer fencing, revoke/transfer, and same-version complete account snapshot; current status is `F14_STRICT_BLOCKED / LIVE_NO_GO` (matrix lines 223–239). The feasibility memo says the reviewed public CTP APIs expose per-query request IDs/terminal callbacks but no common multi-query snapshot version or cross-host lease in that reviewed interface scope; it explicitly does not rule out another broker-side service (memo lines 1–22).

A sole credential-owning gateway could potentially satisfy the *writer fence* portion only if independent evidence proves credential custody and that OS/network controls block every alternate account writer. ADR-41-16 labels this as a design alternative and says it still does not create a common snapshot (lines 46–54). Production cannot inherit a SimNow exception or receipt.

## Staged implementation and G6-P acceptance checklist

1. **Resolve the authority source before implementation.** Obtain a broker/clearing-side account-control contract or approve a sole-credential gateway design. Identify issuer, service identity, exact account scope, fencing generation, snapshot semantics, expiry/revocation, transfer, incident and recovery behavior. If no source can attest all external writers or snapshot consistency, strict F14 remains blocked; do not emulate authority with a caller callback or local database.
2. **Pin and isolate the Actor.** Build a clean reviewed source/artifact set. Run exactly one credential-owning AccountActor per account under a distinct service identity. Strategies and Store processes must not load CTP credentials/native handles. Use OS ACL/egress policy to deny direct writes from every other user, process, host, terminal, and break-glass path; takeover must first revoke/fence the previous epoch. A network transport client ACL alone does not satisfy this step.
3. **Install independent action authorization.** Use a trusted issuer/verification root outside strategy control. A short-lived, single-use permit must bind exact account, environment, runtime/artifact/config digest, actor/session generation, action ID, submit/cancel kind, cancel target, instrument, quantity, price/offset, limits, validity and revocation state. The Actor rechecks permit plus current account epoch immediately before each native side effect. Missing issuer, stale epoch, expired/revoked permit, or ambiguous state means zero native calls.
4. **Unify durable command and callback identity.** Persist one idempotency claim before native dispatch for both submit and cancel. Persist dispatch-in-progress and never resend `UNKNOWN` after process death. Capture native order/trade/query callbacks in an Actor-owned durable inbox keyed by stable request/order identity and session generation; dedupe duplicates, quarantine wrong-account/late-generation callbacks, and publish through a durable sequenced outbox. Treat SDK queue return as local queue evidence only.
5. **Prove same-version account snapshot.** Under the exact active account fence/epoch, attest funds, all open orders, trades, and positions with explicit pagination/coverage and one authoritative version/watermark. If the CTP interface has no atomic snapshot, require a separately reviewed equivalent (for example, a service-controlled all-writer freeze plus callback/query watermark protocol); repeated reads or operator quiescence alone must not be labeled an atomic snapshot.
6. **Supervise startup and shutdown.** Start only from a sealed, pinned deployment. Enforce a parent-owned hard deadline covering credentials, SDK/native startup, readiness, callback drain, stop, Join, Release, socket/pipe close, and Job cleanup. Keep the account epoch fenced and mark it poisoned while any native close, worker exit, callback drain, or dispatch outcome is uncertain. Transfer ownership only after independently verified reconciliation and clean close.
7. **Adversarial verification before G6-P.** Independently test two hosts/processes racing, direct/manual bypass attempts, lease revoke/transfer and stale epochs, expired/replayed action permits, duplicate submit/cancel IDs, crashes before/during/after native call, restart with `UNKNOWN`, late/duplicate/reordered/wrong-session callbacks, partial/missing pages, account mutation during snapshot capture, same-version binding, key rotation/revocation, and bounded supervisor cleanup. Each rejected case must prove zero provider dispatch or remain durably fenced as UNKNOWN. Then obtain separate G6-P source/service/authority receipts and independent QA. Only afterward may the applicable G7-P gate be considered; production still needs its own G8-P evidence.

## Final decision

`NO_TRUSTED_EXTERNAL_ACCOUNT_ACTOR_FOUND` in the reviewed local repositories. The legacy CTP gateway is an actual provider-facing implementation but is not safe or authoritative for G6-P. The newer transport/router/execution components are useful implementation inputs but remain an unpinned, incomplete prototype; the current CTP gateway adapter explicitly rejects direct writes. No local tests were run as part of this audit. `NO_WRITE / LIVE_NO_GO` remains unchanged. This report grants no authority, proves no provider behavior, and does not claim F14 acceptance.

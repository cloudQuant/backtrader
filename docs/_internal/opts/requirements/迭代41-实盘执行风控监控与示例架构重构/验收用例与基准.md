### 2.1 三种模式、预设与不能混淆的事实

所有 runtime 都先校验文件与 schema，再解析受信 registry；`runtime.mode` 只有
`backtest/simulation/live`。模式不由 CLI、CWD、环境、template 或缺文件推断。
普通用户字段仅为schema元数据、strategy.id、runtime.mode/preset及可选parameters/secrets_ref。
registry输出effective route/access/plugins，不提供任意user-plugin覆盖口。
普通local_backtest/replay使用本地引擎时，effective order_route/account_access为null（不适用），
不能为凑旧拓扑表标legacy_direct。下文L1/组件性能的TestExecutionProfile是隔离测试装配：
它可用fake port覆盖direct/managed公共组件，但不改变用户预设映射，也不发布为新用户preset。

| mode / preset | 网络与外部写边界 | 必须向用户显示的事实 |
| --- | --- | --- |
| backtest / local_backtest | 不联网、不读取交易凭据；external/network write=0 | 历史数据的本地回测，成交/PnL只能是回测模型输出，不是真实账户盈利；当前 package-owned `local_backtest` fixture 没有订单，实际报告 `actual_pnl=NOT_APPLICABLE` |
| simulation / replay | 离线fixture，0网络/0外部写 | 工程回放；该fixture可有fake调用，不能标成交易所真实成交或盈利 |
| simulation / paper | 仅allowlist公共行情read；submit/cancel/close等外部写全部0 | 本地假设成交与hypothetical PnL；生产行情来源不代表生产交易 |
| simulation / shadow | 仅allowlist公共行情read；全部外部写0 | 只观察，不产生本轮成交/PnL；未读取私有账户时不能声称账户健康已核实 |
| simulation / sandbox | 独立授权后可向认证demo/SimNow实际报单；production writes=0 | 这是外部模拟环境报单，具有挂单/撤单/持仓与清理责任；sandbox不是离线无副作用 |
| live / managed_live_direct | registry强制managed+execution/risk/monitor，direct_provider；独立production准入后才可写 | 会向真实生产账户报单，影响资金与仓位；配置有效/用户确认均不等于已获准 |
| live / managed_live_gateway | 同上，另gateway+transport_zmq且server唯一owner；已验收provider才可写 | 真实账户写由server执行，client不持provider凭据；未验收CTP gateway仍NOT_SUPPORTED |

mode写边界同样约束provider直接调用、cancel/drain、退出清理及整个子进程树。`simulation/sandbox`
的environment由受信profile/认证身份证明，不能仅检查URL字符串包含demo。写计数按
`external_sandbox_write_count / external_production_write_count / fake_dispatch_count` 分开；
前两者相加为external_provider_write_count。正向L0/L1/L2使用fake port，两种external计数均为0；
实际sandbox/live会话归AC37/L3及后续独立准入，不在本计划修订中尝试。

旧模式只由离线迁移工具映射：replay→simulation/replay、shadow→simulation/shadow、
paper-live→simulation/paper、demo/simnow→simulation/sandbox、production→live的具名managed预设。
未知旧mode拒绝；迁移只创建待校验文件和差异报告，不复制旧receipt/permit或自动运行。
012两候选paper/demo禁令、013_3研究门和所有CTP/HFT边界继续有效；新模式标签不能解除它们。

### 2.3 简洁操作和风险认知测量

预先已具备环境安装、批准策略/研究条件、独立账户/模拟或production授权时，日常首次运行最多：
①普通 profile bootstrap 选择预设并生成文件（CTP 私有 profile 则从受审模板一次性准备受保护的本地 config）；②validate/doctor；③普通 replay `run`。CTP 普通 CLI `preflight` 当前 fail-closed；有总期限 Windows Job supervisor 实现并独立验收前，不得将它写成可执行步骤。程序不得合并隐藏审批步骤来凑数。
用户只选一次mode/preset；live确认读取sealed配置，仅接受同意/取消，不再选择或覆盖模式。
已有配置重复运行可直接run，由run内置验证；doctor是可选诊断，不能变成必须手工复制的安全逻辑。

计算真实顶层命令和用户编辑次数，不能把一长串shell命令包装成“1步”。bootstrap应一次收集
该策略必要parameters/secrets_ref；若仍需用户手工编辑文件，应如实计入准备动作并检验30%改善门。
默认doctor离线；用户需要认证只读preflight时由具名profile明确执行，报告“只读核验”且零写。
输出至少包含mode/preset、目的地environment、是否联网、是否外部报单、成交/PnL类型、审批状态、
阻断项、下一步；禁止用一个绿色“配置成功”暗示实盘已准入。

两名未参与实现的测试人员，各对backtest、paper、sandbox、live四个fake场景，仅看doctor输出

## 1. 共同行为要求

以下 `config.yaml`/`config.example.yaml` 均指 C0 注册 runtime-dir 的运行配置，不指旧策略参数。
**每个 Iter41 runtime 必需配置**；没有文件返回 `CONFIG_REQUIRED`，所有模式均零 I/O 拒绝启动。
用户只选 `runtime.mode` 与 `runtime.preset`，受信 registry 生成只读 route/access/plugins/effective-config，
不暴露十个布尔或允许参数覆盖安全字段。旧 schema-v3 运行期拒绝，仅显式离线迁移工具可读取并生成待审 v4。

| mode / preset | 目标行为与内部路由 | 门槛与真实计数 |
| --- | --- | --- |
| backtest / local_backtest | 本地历史数据、回测 broker；不加载 provider/网络插件 | 网络=0、外部write=0。历史参数仍走原计算逻辑，配置不得改变为live。 |
| simulation / replay | 本地确定性replay/fake provider；managed合同可离线验证 | 网络=0、外部write=0，fake fill/count单列。 |
| simulation / paper | 受信profile读取公开行情，本地假设成交 | 外部submit/cancel/close=0；既有候选paper禁令不解除。 |
| simulation / shadow | 受信profile读取公开行情、无假设成交 | 外部write=0，不能声称真实fill/PnL。 |
| simulation / sandbox | registry绑定demo/SimNow，默认认证私有只读、external_write=0；批准write capability且有效receipt/admission才可写 | 只读不需写审批；写入强制managed execution+risk+monitor、TestExecutionProfile及账户/日历/时段/清理门。两种情况下production write=0。 |
| live / managed_live_direct | 本机受管authority/provider，execution+risk+monitor必选 | 全部研究/账户/production approval/capability/恢复门；live确认只确认已审批合同。 |
| live / managed_live_gateway | 同上，经gateway+transport_zmq配对接入 | 另须gateway服务端授权/归属/能力，CTP未支持写入时仍NOT_SUPPORTED。 |

执行要求：

1. `config_schema_version: 4`、strategy.id、mode、preset 是最小必需字段；parameters/secrets_ref 可选，
   且仅按preset白名单收紧。未知字段、重复key、旧schema、mode/preset冲突和CLI模式覆盖都在plugin/provider初始化前拒绝。
2. 所有writer、operator、测试子进程记录mode/preset/effective route/access、环境、owner与制品/config seal。
   `legacy_direct` 仅为已配置的零外部write兼容/回归分支；没有live direct preset，不能转调旧CLI逃出受管路径。
3. bootstrap 默认选择该 runtime 已登记的最安全预设（当前默认 registry 有 13 条 source/example `simulation/replay` runner：8 个普通策略、007/010 legacy no-action、sample no-action 与两条 managed L2；另登记 1 条无 runner、无 execution capability 的 CTP SimNow `simulation/sandbox` 私有只读 route、1 条公开 OKX `simulation/shadow` 只读观察，以及 1 条 package-owned `backtest/local_backtest` fixture，共 16 条），不放 provider
   凭据；bootstrap 仅首次原子生成、拒绝覆盖，不连接账户。
   批量bootstrap按受信runtime-set清单预检并生成逐项结果，不越界、不覆旧11参数文件、不写receipt。
   日常 `bt-runtime run --strategy-dir ...` 自动重验配置和preset policy；provider/account preflight 需单独显式调用，
   且 CTP SimNow 私有只读 binding 已登记，但没有 runner 或 execution capability；当前唯一受保护的 CTP 私有配置为 `examples/013_3_sa_midfreq_simnow/runtime-ctp-private/config.yaml`，含五组成对候选。新增官方 7x24 pair 两端 TCP 不可达。H2 官方预检完成七项 TD query、零 query error；instruments 83 条同交易所行/1 条配置目标，两个 rate row 的 ExchangeID 为空且 scope unverified；Join pending 导致 `session_close_incomplete`，full preflight FAIL、官方 MD 未到达。独立 H2 MD-only 观察到 front callback，但无被接受登录响应（`market_login_timeout`）；结果 `market_client_stop_failed`、stop returned、Join pending，无 ACK/tick、零写入，原因未明。managed 第三 parent pin 与账户级 writer fence 缺；production 未来复用同一配置和 CTP runner；live-mode admission 与独立生产验收仍未完成。
4. 本地runtime config/secrets精确ignored/untracked，旧参数config继续tracked；配置/参数/secret identity/pin变化均使旧
   seal/receipt失效并重新preflight。secrets_ref只能引用部署已批准的秘密来源，不能改provider/environment或扩大权限。
   gateway/supervisor的策略client无provider凭据，唯一writer的独立受管部署保存；所有输出脱敏。
5. sandbox获准写入/live必须execution+risk+monitor；gateway preset另必须gateway+transport_zmq。展开后的enabled/required
   严格校验，缺包/pin/attach/authority时零写拒绝，无direct或本地provider fallback。未选用插件不导入，不能把它写成保护。
6. 账户风险、journal、lease、unknown/recovery由公共层持有，策略仅保留economics/信号限制；无第二ledger/writer。
   控制经账户owner port，死策略只有存活且授权的supervisor可有限减险，无owner则manual_intervention，不能伪造drain成功。
7. 每个sandbox写入/live测试保留隔离账户/合约、操作预算、TTL、审批、清理及最终对账；fake write与sandbox write、
   production write分开计数。模式名称不是审批，simulation/sandbox也可能真实写外部模拟账户，不能总称零外部写。
8. README有三模式/preset支持表、首次bootstrap/日常run两步主线、可选validate/doctor、live确认、退出/恢复runbook、
   错误下一步、性能/容量和证据限制。支持表只列真实已验收能力，012/013_3/014/015原研究/只读/时间限制保留。

examples 只依赖 Backtrader 与 SDK public facade；`bt_api_execution`、`bt_api_risk`、`bt_api_monitor`、
`bt_api_gateway` 与 `bt_api_transport_zmq` 五个可选能力包的具体安装、版本、pin 和组合由 deployment profile
与 `bt_api_py` integration 管理。example 不得 vendor contracts、直连能力包的私有对象，或以存在本地 checkout
作为可写模式前提。`bt_api_gateway` 仅 README、transport_zmq 尚未创建是 `baseline-2` 历史状态；当前 gateway/
transport local typed implementation 仍没有 package/pin/isolated consumer，也没有已登记 gateway runner，不能被本矩阵表述为已交付能力。
`bt_api_transport_nats` 与 `bt_api_transport_redis` 只保留为未来候选；在各自
独立通过 transport port、认证/ACL、重连/序列缺口和 fan-out 合同前，不能作为本迭代的可选配置或迁移出口。

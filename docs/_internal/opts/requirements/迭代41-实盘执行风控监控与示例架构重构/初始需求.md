# 迭代 41 初始需求

本文件保留立项时的用户诉求，后续需求、设计、实施和验收不得悄然扩大或收窄其安全边界。

1. 当前 examples 中实现的实盘策略有架构问题；每个策略重复配置大量前置条件，不适合实际长期运行。
2. 需要账户级风险控制，至少能限制下单次数、撤单次数，并可扩展到其他账户风险规则。
3. 需要独立的运行监控；需要判断 Backtrader 的 TradeLogger 是否足以替代 monitor。
4. 需要评估 Backtrader 和 `bt_api_py` 已有 execution 能力，以及订单聚合下单应处于哪个框架层。
5. 已有 `bt_api_risk` 和 `bt_api_monitor` 两个模块；需要明确三者与 Backtrader 的职责，补齐缺失功能。
6. 后续需要重构所有 examples 中具备真实 provider 写入能力的策略/运行器，而不是只覆盖最近的
   Iter22–25 示例。
7. CTP 长期运行应以交易日/交易时段边界处理，crypto 应支持 7×24 健康运行；3600 秒不能被当作
   通用交易进程生命周期。
8. 除了设计计划，还需要实际实现 `bt_api_execution`，完善 `bt_api_risk`、`bt_api_monitor`，
   并完成 Backtrader 与 examples 的接入。
9. 当时（引入 gateway/transport 前）的组织决定：前三个包均以独立 Git submodule 挂载到
   `D:/bt_api_py/bt_api/bt_api_execution`、`bt_api_risk`、`bt_api_monitor`；`bt_api_py` 负责明确的
   optional integration/dependency/adapter，不把前三个包的源码并入单体 SDK 包；第 12 条提出的 `bt_api_zmq`
   适用相同独立子仓边界。
10. 当时的配置决定：`config.yaml` 是可选的 `bt_api_execution`、`bt_api_risk`、`bt_api_monitor` 运行时插件启用、参数和
    本地凭据入口；真实 `config.yaml` 必须被该目录 `.gitignore` 忽略，仓库只提交无秘密的
    `config.example.yaml` 模板，操作者复制后自行配置。引入 `bt_api_zmq` 前的三者默认关闭且可根据需要任意组合开启；
    `bt_api_zmq` 作为第四项后也遵循同一显式启用合同。未启用
    execution（或完全没有插件配置）时，Backtrader Strategy 保留经现有 Broker/Store 直接下单的路径，不执行
    新插件验证；启用 execution 才进入受管链路。direct 与 managed 路径必须显式可归责，不能在故障时自动
    互相回退，且都不能借由环境变量、CLI 或目录搜索伪造未启用模块的保障。
11. 当时的架构决定：risk、monitor、execution（以及第 12 条原拟新增的 zmq）都必须是按配置加载的插件；没有配置或
    `enabled: false` 时不得 import/init。risk/monitor 在 `legacy_direct` 被启用时也必须在 Broker/Store 的真实写入和控制边界发挥
    hard-gate/freeze/drain 作用，不能仅作为 advisory/telemetry。
12. 原始 ZMQ 诉求：需要使用 ZMQ 转发行情、账户/订单事件以及下单/撤单命令，但只能是可选传输和网关能力；
    不得再造执行、账户、风险或监控的第二真相源。该名称与职责已由第 13 条取代。
13. **最新决定：** 在 GitHub 创建中间件无关的 `bt_api_gateway`，先实现 `bt_api_transport_zmq` 作为其 transport
    adapter；NATS/Redis 仅在后续有真实需求时增加 `bt_api_transport_nats` / `bt_api_transport_redis`。gateway 管共享
    账户会话、行情订阅复用、账户/订单事件路由和策略归属；transport 只管中间件实现。二者都必须可选、独立打包，
    并且不能拥有第二 OMS、风险账本或 provider 账户真相。

本迭代的响应是：建立以独立 `bt_api_execution` 包为中心、由 SDK 受控组装的 execution 中枢、账户级
risk hard-gate、durable monitoring 控制面和 Backtrader 薄适配；将所有可写 examples 迁移、禁用或明确
标为不适用。它不会自动放宽研究、审批、SimNow、production CTP、HFT 或任何候选的交易准入状态。

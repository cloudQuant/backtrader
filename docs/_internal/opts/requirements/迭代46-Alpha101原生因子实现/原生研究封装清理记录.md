# research 原生实现与封装清理（2026-10-22）

## 范围与结论

在既有 `dev` 上继续清理 `backtrader/research`。实现基线为
`37d3fcabe81df459a3b7eb4d72df5d793ed14016`，验收候选 Git tree 为
`15bb4a75340c423861dc30f2dfc58e5946efef5c`。候选从暂存区导出到仓库外验收，
不包含工作区其他尚未提交的修改。

重复元数据、重复依赖检查和伪造的诊断节点。其余模块均有实际调用职责，
没有继续删除整个模块。

## 已删除的内容与替代入口

| 已删除 | 原因与现有入口 |
| --- | --- |
| `FormulaIdentity`、`ImplementationIdentity` 及生成的 `formula_identity`、`implementation_identity`、`implementation_id`、`implementation_version` | 重复保存因子类已有声明。直接读取 `.formula`、`.lookback_h`、`.formula_fields` 等；运行源码摘要仍由 `FactorSpec` 保存 |
| `_FactorGroupInstances._merge_nodes`、`_MergedFactorNode` | 为诊断重新拼装节点视图。现在测试直接遍历 `group_instances`，读取真实子节点 Lines |
| 聚合对象的 `field_lines`、`classification_lines`、`formula_members`、`research_groups` 转发 | 没有调用者。公式在各组真实 `FactorIndicator` 上调用这些接口；这些原生因子接口保留 |
| `dataset.collect_dataset` | 无调用的单层转发，直接使用 `ResearchDataset.from_collection` |
| 根包 `backtrader.research.save_dataset` 再导出 | 无调用。使用 `dataset.save(path)`；存储层实际 `storage.save_dataset` 保留 |
| `ResearchSpec.to_metadata()` | 无调用，数据集仍保存实际运行配置和来源元数据；`FactorSpec.to_metadata()` 仍被采集器使用 |
| `ResearchSpec.research_grid` | 无生产调用的切片快捷属性；可按 `start/end` 对 `.grid` 显式切片，`.calculation_grid` 保留 |
| `Rank`、`Scale`、`RollingStdDev`、`Corr`、`Cov`、`ElementwiseMin`、`ElementwiseMax` | 无调用的算子别名。对应正式名称为 `CrossSectionalRank`、`CrossSectionalScale`、`RollingStd`、`RollingCorrelation`、`RollingCovariance`、`Minimum`、`Maximum` |
| dataset/storage/field_validation 的重复 pandas 检查及 Strategy 的转发方法 | 统一调用 `specs.require_research_runtime()`，保留延迟依赖检查和标准 `DependencyError` |
| `_OperatorIndicator._set_minperiod`、重复的 target 绑定分支、未使用的运行字段/默认参数、重复 `_factor_specs` 存储 | 没有有效调用或属于不可达分支；实际绑定、窗口和采集检查保留 |

这些是接口删除，不保留兼容转发。全仓生产代码、示例、脚本和测试未发现残留调用。
027 的真实日线 runner 已从 `.formula_identity.expression` 改读 `.formula`。
相关测试检查实际类声明与独立预期，不再检查已删除身份对象的自洽性。

## 保留内容的必要职责

| 内容 | 实际依赖与证据 |
| --- | --- |
| `factor_indicator.py` | 将每个目标输出绑定到真实 Lines；提供字段、PIT 分类、公式成员和输入可用性。绑定、时钟、严格错误测试均运行真实 Cerebro |
| `_OutputLines`、`_PITValueLine` | 前者让 `outputs[data].value` 引用真实输出线；后者把已对齐 PIT 表按目标 Feed 时钟暴露成原生 Indicator 线。不是另一套计算引擎 |
| `_FeedInputLine` | 具名 Feed 输入的原生 Indicator 子节点。直接换成 `LineDelay(0)` 的方案被反例否决，详见下一节 |
| `factor_strategy.py`、最小 `_FactorGroupInstances` | 为每个研究组创建真实因子，采集输出并生成数据集；最小聚合只保留真实组实例、输出引用和生命周期诊断。研究组隔离合同保留 |
| `operators.py` | 本身就是原生 Indicator/FactorIndicator 子类，固定 Alpha101 的并列秩、NaN、常量窗口和数值口径；不能仅按名称替换成口径不同的普通指标 |
| `alpha101/_helpers.py` | 101 式使用逐资产子指标装配，83 式使用截面装配，12 式使用收益链；保留真实节点，不推进时钟 |
| `alpha101/_metadata.py` | 验证窗口、公式字段和分类声明，补齐 profile/PIT 等默认声明；不再制造另一组身份对象 |
| `specs.py` | 冻结参数、字段绑定、H、源码指纹与明确的时间网格/成员范围；Strategy 和保存快照直接使用 |
| `inputs.py`、`field_validation.py` | 025/026/027 和采集器使用完整网格及因果 PIT 输入；检查 ADV/VWAP 的单位、来源、窗口和可用时刻 |
| `strict.py` | 核心 LineBuffer/LineIterator 在因子上下文中调用，保留计算异常原始原因，防止异常被当成正常缺失 |
| `dataset.py`、`storage.py` | 不可变原始面板、可用性与来源快照，以及规范序列化/加载；保存加载合同已验 |
| `fincore_adapter.py`、`factor_report.py` | 已有离线评价和 025/026/027 报告调用路径；分析及报告算法仍由 fincore 提供。报告 3 项测试本轮执行通过 |

研究异常已在上一轮统一至 `backtrader.errors`。根包错误名称再导出和已公开的
`ConfigError = ResearchConfigError` 名称别名没有创建新异常类或调度层。

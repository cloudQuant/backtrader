# 迭代46 — Alpha101 全量原生因子实施计划

版本：**v0.1**；更新：**2026-10-21**。状态：**未开始；L1–L4 全部 NOT_RUN。** 本计划只负责迭代46，依赖迭代45已验收的原生 `panel_mode="next"` 引擎、共享算子、字段/PIT 合同和20个代表式证据。本文不是执行报告，不表示101个 native 因子类已经存在。

## 1. 定位与依赖

迭代46在迭代45稳定的原生引擎上实现**全101个 Alpha 的 native 生产因子**。20个代表式复用迭代45已验证的 native 实现并纳入全库回归；其余81式逐个落为 `PanelFactorIndicator(panel_mode="next")` 类并注册。本迭代只做 native，不实现 `build`/`expression`，不改变迭代45的算子语义、PIT 合同、grid 屏障或评价层。

四迭代入口：

| 迭代 | 计划 | 责任 |
|---|---|---|
| 迭代45 | [迭代45计划](../迭代45-Indicator因子研究与多因子合成/迭代计划.md) | 原生引擎、共享算子/PIT、20式 next、025/026、fincore |
| **迭代46** | **本计划** | **101/101 native 独立参考与全量回归** |
| 迭代47 | [迭代47计划](../迭代47-因子build简洁模式与算子增强/迭代计划.md) | build/expression、算子增强、20式等价、混合装配 |
| 迭代48 | [迭代48计划](../迭代48-Alpha101-build实现/迭代计划.md) | 101/101 build 与101/101 native/build 等价 |

共享规范仍以迭代45目录中的现行文档为准：[需求文档](../迭代45-Indicator因子研究与多因子合成/需求文档.md)、[设计文档](../迭代45-Indicator因子研究与多因子合成/设计文档.md)、[验收方案](../迭代45-Indicator因子研究与多因子合成/验收方案.md)、[Alpha101覆盖清单](../迭代45-Indicator因子研究与多因子合成/Alpha101覆盖清单.md)、[Alpha101代表验收案例](../迭代45-Indicator因子研究与多因子合成/Alpha101代表验收案例.md)。本文只展开迭代46的目标、分轮和退出条件，不另造第二套接口或数值合同。

## 2. 目标与范围

### 2.1 必须交付

1. 全101式冻结目录、ID、完整原式、原始窗口、`operator_profile`、字段/分类绑定和逐式依赖图；20式复用迭代45提交，81式补齐。
2. 81个新增 native 因子类及注册；不得把简写草图、测试辅助函数、027 expression 原型或占位类当作生产实现。
3. 每式独立参考/黄金值、边界/错误区分、lookback/H 和 PIT 检查；独立参考不得调用生产算子、生产 PanelEngine 或生产 DAG。
4. 全101 native 全量回归：runonce/runnext、资产重排、未来扰动、缺 bar/停牌、公式池 PIT、行业层级、ADV 嵌套窗口、长预热和尾段。
5. 已提交安装产物上的全101研究回归及与 fincore 评价的最小集成；025/026回归。

### 2.2 明确不做

- 不实现 `panel_mode="expression"`、`build(ctx, **params)` 或共享 DAG；这些属于迭代47。
- 不重写迭代45的算子、PIT、grid 或评价合同；发现缺口回到迭代45/E2范围修复，不在本迭代私建第二套实现。
- 不承诺原论文收益，不把“全101类已注册”当作所有公式的市场绩效成立。
- 不用20式验收替代81式验收，不把“20+101”重复计为121。
- 不触碰账户、私有配置、实盘进程或 CTP/live 边界。

### 2.3 “全101”口径

“全101”指论文 Appendix A 的全部101式。迭代46的101/101 = 迭代45已完成的20式 + 本迭代新增的81式；20式必须重新纳入全库回归，但不能只靠20式证据关闭迭代46。未选的81式不能被20式替代，也不能从覆盖清单或算子依赖盘点中删除。

## 3. 全101台账与复用边界

L1 先冻结逐式台账，再进入实现。台账每行至少包含：

- 论文 ID、完整原式、原文窗口和 `alpha101-v1` 取整/并列/数值域说明；
- 直接字段、派生输入、行业层级、`formula_universe` 和 PIT 成员语义；
- 依赖算子、嵌套窗口、编译 H、`operator_profile` 和缺失/退化规则；
- 独立参考来源、有限正向值、边界输入和错误实现区分方式；
- 实现状态（`NOT_IMPLEMENTED`/`IMPLEMENTED`）、验收状态和提交定位。

20个代表式以[代表验收案例](../迭代45-Indicator因子研究与多因子合成/Alpha101代表验收案例.md)固定：#1、#2、#3、#4、#7、#9、#13、#29、#48、#56、#58、#62、#63、#67、#81、#84、#92、#96、#100、#101。它们覆盖简单基线、截面/时序交错、历史数据与分组、布尔/幂/复杂分支；其余81式仍须逐式独立参考。

## 5. 验收与退出

同时满足才可关闭迭代46：

1. **101/101 native 公式**均完成注册、独立参考、边界/错误区分和全量回归；20式复用迭代45证据并重新纳入全库回归，81式有本迭代独立证据。
2. 所有公式使用同一 `panel_mode="next"` 生命周期、同一 grid 屏障和同一共享算子；无逐因子 Strategy、无双调度、无私有算子副本。
3. 资产重排、未来扰动、缺 bar、PIT 成员、行业层级、ADV 嵌套窗口、runonce/runnext 均通过；缺失/退化按原因记录，不以全 NaN 或 skip 通过。
4. 安装产物可运行；fincore 只消费 `get_dataset()` 的原始面板，不重算公式内部 rank/行业中性化。
5. 本迭代不产生 build/expression PASS；迭代47必须以迭代45的 next 引擎和迭代46的 native 结果为对照，不能把46的公式实现直接当作 DSL 实现。

若某项因真实能力缺口未完成，保持 `FAIL` 或 `BLOCKED` 并回到对应小批修复；不得用20式通过、静态映射或“类已注册”替代101/101 native 验收。

## 6. 向迭代47交接

迭代46向迭代47交付：

- 稳定的全101 native 类、ID/注册表、逐式独立参考和全量回归 fixture；
- 安装入口、公开研究入口和已知缺口；
- 逐式算子依赖、H、PIT 和退化原因，供 build 前端编译与等价对照。

迭代47的 build 库只在前端层增加声明，不重写这些 native 算法；迭代48的101 build 库必须以迭代46的 native 结果做逐值对照。若迭代46未完成101/101，迭代47仍可只做20式 build，但不得宣称全101 native 已稳定，迭代48不得开工全101 build。

## 7. 证据、提交与边界

- 每轮记录：范围、命令、输入 fixture 版本/哈希、预期与实际、容差、解释器、两仓分支/HEAD、实际导入来源、输出文件及 SHA-256。
- 只在现有 `D:/source_code/backtrader` 和 `D:/source_code/fincore` 的 dev 工作区推进，不建 worktree，不以 master 为起点。
- 每轮执行“实现 → 针对性验收 → 只提交已验收文件 → 下一轮”，保留其他已有改动；fincore 增量先独立验收提交，再由 Backtrader 集成。
- 不触碰账户、私有配置、实盘进程或其他迭代；不推送、不发布、不合并 master。
- 性能只记录测试规模与实测资源；真实供应商 PIT、论文专有股票池和原收益不因数学验收而被证明。

## 3. 发现与建议

### QW65-01（P1）INV65-03 未把 D65-37 平今→平昨派生列为开平例外，与 63.13/§3.9 冲突

- **定位**：[迭代计划](迭代计划.md) §2.3 INV65-03（“合约、方向及经 provider 规则核对的开平符合母单……虚拟平仓转换按 D65-27/28 独立合同……”）；对照同文 §3.9（D65-37 派生平昨子单）、§4.1 共同约束、[63 计划](../迭代63-Gateway统一转发与多策略共享会话/迭代计划.md) 63.13 行（已含 D65-37/Q39 验收）。
- **问题**：INV65-03 是 Gateway 强制的信封不变量（按 D65-01 a），其开平一致性例外只列了虚拟平仓转换（D65-27/28），没有列 D65-37 的平今母单跨日派生平昨子单。派生子单的账户层 offset（CLOSE_YESTERDAY）与母单原意图（CLOSE_TODAY）不同：按 INV65-03 字面实现，63.13 的信封核验会拒绝用户已决定的合法派生；若实施者为此临时放宽整个开平校验，又会削弱信封对普通子单的约束（数量/归属风险）。设计文档未复述该不变量，缺口只在计划一处，但它是规范条文。
- **建议**：在 INV65-03 的例外清单中并列两项：“虚拟平仓转换按 D65-27/28”“平今→平昨跨日派生按 D65-37：仅当原目标身份、方向、理论归属、真实可平容量、授权与原期限核验通过，且持久记录日切映射版本与派生 offset 审计时，子单账户层开平可按 provider 声明的 CLOSE_YESTERDAY 等价映射不同于母单原意图；策略层原意图不变”。65.02/63.13 冻结信封合同与错误码时以修订后的 INV65-03 为准。
- **理由**：不变量章节是 65.01/65.02 冻结合同的直接输入；两条用户已决定的例外必须同层级、同可见度地写入，否则冻结出的信封 schema 会二选一性地违背 D65-37 或 INV65-03。
- **验收**：修订后的 INV65-03 同时给出两个反例断言——(1) 无 D65-37 映射证据的 CLOSE_YESTERDAY 子单在 CLOSE_TODAY 母单下被拒（有限码）；(2) 有完整映射版本与审计的派生子单通过信封核验并计入母单数量守恒。65.03/65.08 的 D65-37 行引用该不变量。

### QW65-02（P2）D65-01 候选 b 与已决定的 D65-32/33 事实冲突，应标注并建议用户确认 a

- **定位**：[迭代计划](迭代计划.md) §7.1 D65-01（“b 更简单（63.13 不需要信封）……若用户认为……应选 b”）；对照 §4.3 D65-32（“内部转移预留与子单预留必须经 Gateway 权威数量桶在同一原子事务……内竞争”）、D65-33（“必须由 Gateway 权威数量桶绑定该窗口/母单”）、共享合同 §2.6/§2.7。
- **问题**：D65-32/33 是 11-08 用户已决定的行为，其执行主体是“Gateway 权威数量桶”。候选 b 下 Gateway 没有母单信封，也就没有可裁决内转/子单竞争的数量桶；D65-06 候选 a 的降级说明（“Gateway 没有信封时无法强制相同边界”）只覆盖了撤单场景。D65-01 的选项表仍把 b 描述为可行备选，未同步这一派生约束——这是同步缺口，不是重开决定。
- **建议**：在 §7.1 D65-01 行补注：“b 与已决定的 D65-32/33（Gateway 权威数量桶裁决内转与子单竞争、窗口队列预留）不兼容：选 b 则 D65-32/33 的裁决只能退到 execution 本地锁，违背复核清单 E2/共享合同 §2.6 的权威占用要求；除非用户撤回 D65-32/33，b 实际不可选”。并在 §5 提请用户确认 a（QW65-Q4）。

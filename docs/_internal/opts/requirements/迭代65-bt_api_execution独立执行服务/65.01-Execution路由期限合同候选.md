# 65.01 Execution 路由与期限合同候选

状态：**审阅候选，未冻结、未实现、未验收**。本稿将无 Risk、关闭内部轧差、显式 PASS 的基础路径具体化，供 63/65 owner 核对；它不删减迭代 65 的内部轧差、其他算法、选 Risk 或跨日等要求，也不证明母单能投影到现有 BT Broker。字段名、版本号、错误码、配置归属和跨服务事务均为候选。内部轧差启用时不增加策略或逐单同意字段。

## 1. 当前起点与迁移边界

当前 `BtApiStore(config={"gateway_strategy": ...})` 连接 SDK Gateway 策略配置。SDK 的 `gateway_strategy_config.py` 只接受严格 v1：`schema_version` 精确为整数 1；`risk` 必填，显式 `none` 为不选 Risk；未知顶层键拒绝。`execution_time_policy` 解释回报时间，并非母单期限；目前不存在本稿 Execution 路由。本基础路径要求策略侧和服务侧各自显式选择 Risk `none`；若任一侧已选择 Risk，不得由另一侧的 `none` 静默覆盖或降级，按选 Risk 合同验证，不满足时拒绝或不可用。本稿候选采用显式 v2 扩展，不向 v1 静默塞入字段：v1 原样解析且不选 Execution；v1 加 `execution` 按未知键拒绝；v2 对所有旧字段继续验证，并新增本稿所述可选 `execution`。旧解析器收到 v2 明确失败。各账户与 Execution 服务使用各自独立、版本化的运营配置；策略配置不是账户授权，具体文件加载和部署契约另行冻结。

账户绑定仍由现有 `binding`、route、peer、主体及服务注册合同核验。示例中的策略 Execution 路由必须属于同一个已配置账户；多个同名字段不构成身份或授权证明。Gateway 不负责根据策略路由强制拦截直通：D65-15 保留由 SDK 本地规则决定路由，配置漂移可能使订单走原路径，不能声称 Gateway 提供该强制保证。

## 2. 三层候选数据形状

下表仅列基础路径的新增子集，不是完整可运行配置。所有对象严格校验必需/可选键、版本和类型，拒绝未知键及重复 YAML 映射键；文本标识必须是非空、无首尾空白、长度有界的字符串。数量采用带合约单位的有限十进制字符串，正数且满足精度与场所网格；不接受 NaN、Infinity、布尔值替代整数或隐式单位。实际合约单位、精度和交易事实仍须独立验证。

| 层次与字段候选 | 类型与含义 | 基础路径约束 |
| --- | --- | --- |
| 账户 `schema_version`、`account_ref`、`execution_principal` | 正整数版本、账户和服务主体引用 | 同一账户绑定单个服务进程；引用不授 grant。 |
| 账户 `allow[]` | 非空列表；每项含策略引用、完整中立合约键集合、方向和开平集合、允许的方案/算法及其版本、数量及期限上限 | 匹配到的策略配置必须是账户允许范围的子集；授权在 Gateway 动态重验。数量上限与单位、合约绑定。 |
| 账户 `not_sent_retry_limit`、`recovery_mode` | 非负整数；`AUTO_CONTINUE` 或 `KEEP_FROZEN` | 重试次数必须显式；0 不重试，仅可信证明未发送且迟到请求被栅栏时适用。恢复默认 `AUTO_CONTINUE` 不越过事实核验及其他冻结原因。 |
| 服务 `schema_version`、`account_ref`、`principal_ref` | 正整数、账户及服务主体 | 与已验证的 Gateway scope 和账户绑定一致；客户端与本地 journal 配置另按 owner 合同核验。 |
| 服务 `risk`、`schemes[]` | 显式 `none`；版本化方案清单 | 本例方案注册 `{name, version}` 和 PASS 类、版本与空参数，显式 `netting.enabled: false`；关闭时不加载轧差类。类名和版本为注册表示，不能自报即获得授权。 |
| 策略 `execution` | 不存在或 `none` 表示未选；否则对象包括客户端、route、peer、操作集合与有序 `rules[]` | 绑定和凭据必须经 SDK/服务核验；未选不加载 Execution。非空规则的 `id` 在配置内唯一。 |
| 规则 `match` | 合约键、side、offset、数量下界与单位；可选订单类型集合 | 所有给定条件同时成立才命中，按列表首条匹配且不合并规则。省略条件表示该维度通配；类型通配规则命中 Market 后按本期 LIMIT 范围拒绝。 |
| 规则 `scheme`、`algorithm` | 已登记的 `{name, version}`；`{class, version, params}` | 本例只选择明确注册的 PASS 和其空参数；PASS 整单、不拆单，仍通过 Execution。`none` 是否作为 PASS 别名及其默认行为尚未冻结。 |
| 规则 `deadline` | 本例 `{kind: absolute, at: <带时区的时间>}` | 首次受理前将可信原截止规范化为 UTC，核对可信当前时间、交易日/日历及账户期限上限；无证明或已到期则明确拒绝或冻结。按原期限跨日，不以本机午夜推断交易日。 |

账户 `allow`、策略规则中的合约必须能与同一完整中立合约键比较，不允许仅凭名称猜测。方案、算法、参数及版本应在匹配的账户允许集和服务注册集中；即使静态配置合法，运行时仍须核验服务身份、当前 grant、账号范围及可用性。版本、规则顺序和参数改变不能改写已接受订单。

## 3. 匹配与受理时序候选

1. 对既有操作，先以账户、策略 scope 与稳定原请求 ID 查询可验证的本地持久绑定，再决定恢复、冲突或 UNKNOWN；已绑定的请求不得因新配置删除 Execution、规则不命中、解析失败或服务离线而重新走直通。只有确属新请求或可靠证明无既有绑定时才按当前配置匹配；身份或绑定状态无法证明时不能假定是新单。加载时纯本地验证整个策略配置的结构、重复 ID 和可静态判定的矛盾；规则明确列出的类型集合只要包含本期不支持的类型即拒绝，`[LIMIT, MARKET]` 亦然。不可因为服务离线而把本地无效配置当作有效。账户或服务配置的受权事实不能由策略文件证明。
2. 对实际请求在本地依次比较规则。`order_types: [LIMIT]` 与 Market 不匹配时该规则不命中；若没有其他规则命中则维持原路径及其原有限制，不宣称原路径支持 Market。类型通配规则如果命中 Market，则以不支持类型拒绝，不能绕过 Execution。动态无法证明是否匹配不能伪装为未命中。第一条命中后不得继续试下一条或直通。
3. 未选或所有规则确定未命中时，不为确定原路径而要求 Execution 在线或查询其远端类表；原路径自身的准入规则仍适用。命中后核验账户/服务范围、类、版本、参数和必要依赖，服务不可用、被撤权或结果不明不得回退。
4. 以稳定原请求身份，在首次可能远程副作用之前持久化原请求摘要、完整规范化规则及其版本、原始方案/算法参数、策略及账户/服务 scope、原期限政策、可信受理基准与一次算定的绝对截止、时间和日历来源及版本。指纹算法及其版本、规范编码、字段覆盖、列表顺序、十进制与时区规范化须联合冻结；有序规则的顺序及所选配置必须覆盖，当前 v1 JSON 和回报时间政策摘要不能直接充当此指纹。普通快照和日志不得保存私钥、密码或私密 profile 值。摘要只能检查一致性，不证明授权。记录必须足以在配置变化、日切和重启后恢复原政策；不能按新配置重新匹配、延长或替换原截止。
5. 无 Risk 的命中路径按 SDK → Execution → Gateway 权威母单登记顺序推进；Gateway 权威登记被确认前不得预约或派发子单。各步远端回复不明时按原操作 ID 查询，不能将本地受理冒充 Gateway 权威受理。重放先按原身份查询既有绑定，不用当前新配置重新计算；同身份同原请求查询既有操作，调用方试图以同身份提交不同请求摘要或不同已绑定方案/账户则拒绝，不能换身份制造新母单。持久化方案后授权撤销、停止和其他独立原因仍动态生效；原快照不构成永久授权。若不能验证原方案/期限/来源则冻结或 UNKNOWN。
6. 仅在能证明远端未受理、没有副作用且原迟到请求已被栅栏时报告确定拒绝；超时或丢回复不能证明未发生，须按原身份查询并保持 UNKNOWN 与适用占用。多服务日志不假设跨库原子，不能在未知时改用新 ID 或旁路发送。

本候选只讨论当前 Gateway Broker 支持的 `Order.valid is None` 且命中的限价请求；非空 BT `valid` 的当前 Gateway 路径在预约前拒绝，拒绝前可能已调用 SDK 本地 getter。不得将其改写为无期限或声称现状支持。普通子单限价不得越过母单约束；平仓与转换等其他权限按对应合同处理。

## 4. 可执行验收向量与错误边界

有限码名称暂以 `INVALID_EXECUTION_CONFIG`、`EXECUTION_SCOPE_DENIED`、`EXECUTION_ORDER_TYPE_UNSUPPORTED`、`EXECUTION_UNAVAILABLE` 和 `EXECUTION_UNKNOWN` 占位，最终与 Base/Gateway owner 对齐。错误必须区分本地确定未受理与远端可能已有副作用；不同底层原因保留可审计来源，不能将授权失败、服务丢回复和未知事实统一成“未发送”。

| 向量 | 必要结果 |
| --- | --- |
| 旧 v1，无新增键 / v1 增加 `execution` / 新版未知键 | 分别保持旧路径 / 旧解析器明确拒绝 / 严格拒绝；均不隐式选择新服务。 |
| 重复键、重复规则 ID、缺字段、`true` 当版本或数量、NaN、负数、单位不符 | 本地确定错误，未创建新的母单、子单或占用。 |
| `[LIMIT, MARKET]` / 通配规则命中 Market / LIMIT 规则未匹配 Market | 加载拒绝 / 命中后受理前拒绝 / 继续匹配余下规则；全部未命中则按原路径。 |
| 重叠规则，首条命中但服务离线 | 不尝试后续规则，不绕过；确定无远端副作用时返回不可用，否则 UNKNOWN。 |
| Execution 离线且本地确定全部未命中 | 按原路径；不要求先连服务，也不推断原路径具备市价能力。 |
| 范围超账户允许、未知方案/版本/参数、撤权 | 命中时拒绝或冻结；禁止降级、切换类或使用历史快照绕过授权。 |
| 同 ID 同内容、同 ID 不同摘要、变更配置后重启 | 分别恢复原操作、拒绝冲突、恢复原截止及方案；缺失或不可验证时冻结。删除 Execution、规则不再命中、新配置损坏或服务离线均不得使既有绑定直通。 |
| 策略和服务 Risk 选择不一致 / 已选 Risk 不可用 | 拒绝或保持不可用，不能以另一侧 none 覆盖已选 Risk 或静默绕过。 |
| PASS 受理及 Gateway 登记前故障 | PASS 不拆单；核验 SDK → Execution → Gateway 的身份与持久顺序，未确认 Gateway 权威登记不得预约或派发子单；丢回复按原 ID 恢复或 UNKNOWN。 |
| 不可信时间或日历、过期截止、超账户期限上限 | 受理前明确拒绝或冻结；不能默认无限期，不能因重启延长。 |
| 已发请求丢回复、迟到请求与重启 | 原 ID 查询及 UNKNOWN/占用持续，直至足够证明；不得另建母单或当作确定无副作用。 |

实际回归须覆盖三层配置解析、同账户 scope、可复现的故障切点、基础安全准入、持久化和打包；验证合成测试、真实组件和账户证据分别列示。真实 Broker 母单/内转事件来源及 Order/Position/Trade、费用与重启投影仍是独立 GAP，不能用本稿替代。

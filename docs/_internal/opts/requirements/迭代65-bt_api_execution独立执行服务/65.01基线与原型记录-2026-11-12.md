## 7. 停止与双租约审阅草案（未冻结）

已决定的正常 stop/restart 停止阶段取消该策略未完成母单余量并尝试撤其场内子单；仅权威终态和成交水位一致才报告结束，迟到成交和 UNKNOWN 按原身份及最坏占用处理，其他策略不受影响，重启不复活已取消母单。策略租约和 Execution 租约相互独立：前者默认不自动 DRAIN、显式选择时按其原因处理；后者失效冻结相关母单，不因此释放活动或 UNKNOWN 子单。恢复只解除经核对的对应原因和版本，不清除其他阻断。

当前 Gateway 有多原因控制、条件解除和单母单 `CANCEL_REQUESTED` 的本地源码路径；这些不证明 Runtime 的持久批量停止意图、Execution 服务租约、跨日恢复或内转屏障已接通。特别是既有 parent register 与停止屏障的同事务竞争未证明，不能将单个 DRAIN 操作视为完整停止合同。

待 63/65/66 联合冻结的候选是：以带主体、范围、稳定操作 ID 和版本的 Gateway 权威停止屏障，和母单登记、子单预留/派发及内转预留在同一权威事务建立明确先后；持久屏障后按原身份逐一取消并记录各母子单状态。丢回复只按原 ID 查询，旧版本不能解除新原因，租约恢复不能自动清除独立停止原因。此段为审阅候选，不是当前 wire 接口或已实现行为。

故障验证至少覆盖屏障与登记/预留/派发/内转的先后竞争；双租约分别及同时失效、不同原因叠加和旧版本解除；母单 10 手已成 4、挂 2、未发 4 的部分撤成/迟到/UNKNOWN；持久前后崩溃、丢回复、撤权、原计划到期及不相关策略并发。真实组件、替身和选用 Risk 的证据分别登记。

## 8. 母单期限兼容方案候选（未冻结）

按照用户对 D65-03 的选择，首期接受 Gateway 当前可提交的 `Order.valid is None` 订单；带非空 BT `valid` 的订单保留现有明确拒绝。策略选中的 Execution 路由须由配置显式提供母单有效期政策，SDK 命中路由后在首次远端副作用之前，将政策版本、来源、时区、受理基准及一次算定的绝对期限与母单原请求身份一起持久化。具体字段名、配置层级、允许的政策组合和受理基准尚需联合冻结；不能仅在内存计算或将子单的原生 `time_in_force` 当作母单期限。

候选政策包含交易日内到期与显式截止时间。交易日边界、截止时刻和日历来源必须可证明，期限缺失、非法、已过期、时钟或交易日不可证明时拒绝受理或暂停，不能默认为无限期。若实现允许由持续时长计算截止，必须绑定一次明确的受理基准，重放及重启只读取原截止，不从当前时间重新起算。账户授权上限与策略选项如何比较由 65.01 完整 schema 冻结；不允许策略通过更宽期限越过账户授权。

跨日的母单在原截止内才可继续，子单仍遵循实际 provider 的交易日、有效期与会话规则。截止后停止新增子单，活动/在途/UNKNOWN 子单及迟到成交继续按 Gateway 权威事实追踪，不能用到期替代撤成或释放证明。配置变更不回写已受理母单；若无法读取原政策或原截止，保持冻结而不是创建新的期限或母单。

## 9. 计划 §8.2 核查（STATIC，仍开放）

1. **CTP TradeID 唯一范围：部分官方证据，整体 OPEN。** [上期技术 CTPIIMini API 参考手册 V1.2，§3.2.37](https://www.simnow.com.cn/DocumentDown/api_3/5_2_4/CTPIIMini_API_Ver1.2.pdf) 以 ExchangeID、TradeID、Direction 组合作为成交标识，并指出部分交易所的成交双方可能共享 TradeID。该手册的 Mini 版本不能直接外推标准 CTP 的全部版本或跨交易日/账户范围。现有 CTP Gateway 回报代码采用 `(TradingDay, ExchangeID, InstrumentID, TradeID)`，Gateway journal 还绑定账户和 route；CTP 其他回调/查询路径的键有所不同。BT direct 按日管理专用键，Gateway stream 另使用请求身份和 trade 摘要。须进一步核对标准 CTP/provider 适用版本与方向冲突，以及跨日和重启；现有代码键不单独证明唯一性。
2. **非行情 `delegate_ref`：部分源码已核，整体 OPEN。** Registry 将完整身份与可信 grant 匹配；Gateway parent/delegate grant 对非空 delegate_ref 拒绝并另核主体、范围和操作。该身份匹配不自动构成代表策略的授权，尚未穷尽所有非行情端口，须逐端口测试伪造身份、越权和撤权。
3. **CTP 原生冰山及改单：整体 OPEN。** [上期技术 SFIT CTP Mini API 参考手册 V1.7.0](https://www.simnow.com.cn/DocumentDown/api_3/5_2_4/SFIT%2BCTP%2BMini%2BAPI-V1.7.0.pdf) 的报单操作说明该 Mini 版本只支持删除而不支持修改；不能直接推广到标准 CTP 的全部版本、场所或账户。当前源码存在 modify 标志的字段说明，但投影只实现取消，且未找到原生冰山实现；缺少实现不能证明实际不支持。须核对适用 provider 和场所的官方版本文档。
6. **Windows 私钥文件权限：OPEN。** 当前检查未发现完整 Windows ACL 校验的实现或测试；不能声称 Windows 已 fail-closed。须选定可信文件身份与 ACL 检查方案，在 Windows 上用临时密钥验证允许、拒绝、继承与无法检查等情形。

## 10. Gateway 母单投影待验证边界

现有 Gateway BT 提交为一笔 BT 订单分配一个 request key，持久化该 key、订单 intent 与框架快照，然后调用 SDK 的 reserve/dispatch。Gateway 返回流与该请求的 reservation、摘要、主体、来源身份、合约、方向及数量绑定；现有 Risk 委托分支有专门的持久化绑定，不是通用 Execution 母子单合同。多个真实子单各自的 reservation、原生订单身份和数量不能直接当作母单的原生事实，也不能把某个子单的终态直接当母单终态。

现行 provider-normalized 回报及 Gateway stream 类型没有已验证的内部转移事件入口。内部转移不是交易所成交，不能为了让现有 BT 消费而编造交易所成交、原生身份、来源证明或 ACK。已登记单命令的多笔合成成交及 checkpoint 原型通过，不能外推为多子单或双边内部转移已支持。

继续研究的候选是 SDK/Execution 显式持有经过授权的母单到各子单映射，逐笔保留 provider 来源，Gateway/SDK 对策略分配和内部转移建立独立的版本化身份、账本、水位和证据，再验证是否能由现有 BT 消费器合法表达与恢复。这是尚未证明可行的合同探索，不允许改写来源以满足旧校验；当前 BT 回报结构及来源校验能否在零产品改动下满足本期完整要求仍是 GAP。若证明不能，应记录具体不可表达项并按用户选择重新讨论，不擅自削减本期目标。

## 11. Execution 服务接口审阅草案（未冻结）

65 提供统一页面所需的版本化服务接口，页面和浏览器联调归 69。Gateway 和 Risk 已有各自的本机 Web 适配与可信宿主，可参考其认证、范围检查和审计模式；它们的 grant、撤单操作或收据不能直接视为 Execution 权限或母单撤销接口。现有 Execution `parent_authority` 有本地母单同 ID 冲突及取消原 ID 查询基础，但不是对外服务 API，尚未证明操作者授权、审计或独立进程能力。

候选接口区分受权读取与状态更改：读取返回账户/策略/对象作用域、事实来源、水位、版本、完整性和 UNKNOWN，列表有界；母单撤销及适用授权管理须按具体操作声明。可信宿主把认证主体映射到 Execution 自身的 principal 和按账户、策略、对象、操作限定的 grant；服务使用时重验有效性和撤权，不以浏览器自报身份授权。

写请求在远端副作用前持久记录原命令 ID、规范摘要、目标与期望版本；同 ID 同内容查询已有结果，异内容冲突；审计关联操作主体、授权版本、目标及实际结果。超时或丢回复按原 ID 查询，无法证明时为 UNKNOWN，不自动换 ID 重试。母单撤销受理、子单终态及迟到成交分别表达；各服务各自的本地事务和审计不假装跨库原子。主体到 grant 的具体映射、操作枚举、撤权与已在途 claim 的线性化点和持久收据恢复仍待冻结。

验收应覆盖无 UI 启动、版本和数据陈旧、跨账户/策略/目标拒绝、撤权与提交竞争、并发重复、崩溃及丢回复、原 ID 异内容冲突、受理不等于终态与 UNKNOWN 保留。真实 Execution/Gateway 联调和选 Risk 路径分别记录；替身及静态源码不代替服务或账户验收。

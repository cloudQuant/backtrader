### 1.1 为什么有本迭代

- 63 分析把 execution 放在唯一派发点之前：execution 把母单拆成子单，交给派发点，自己不碰交易所会话（63 分析:15-19、:27-28、:44）；Gateway 模式下的派发点是每账户一个的 Gateway 交易 owner（:29-33）。
- 63 计划把执行算法、拆单和聚合列为非目标（63 计划 §2.2、§3.15）；64 计划只在 risk 一侧提供母单预留合同，不接入 execution（64 计划 §2.2、64.10）。execution 本身的开发没有归属，用户要求放到迭代 65（原话 1）。
- 用户限定 execution、risk、monitor 只能在开启 Gateway 时启用（原话 2、U65-4）。所以本迭代只设计“Gateway + execution（± risk ± monitor）”，不存在 direct + execution。
- 同日晚上用户又决定（U65-5～U65-9）：risk 是 Gateway 之前的独立服务，开启时 BT 的订单先经 risk 再到 Gateway；Gateway 也接受没有风控批准的订单；急停状态由 Gateway 持有；monitor 只观察、不发控制命令；现有急停词汇改名统一；Gateway 相关的开发都在迭代 63。因此：子单在开 risk 时走 execution → risk 服务 → Gateway；`reserve_parent` 由 execution 经 risk 服务调用（原 D65-12 消解）；本迭代需要的 Gateway 侧能力（母单委托信封、代理 principal、租约、子单幂等键、行情 principal）由 63.13 实现，本迭代不修改 `bt_api_gateway`。

### 1.6 冲突与不足

1. **派发归属的文档冲突。** `BT: docs/TRADING_SYSTEM_ARCHITECTURE.md:84` 把“本地订单意图、派发、恢复与 UNKNOWN”归给 execution；迭代 10 的 AFI 规格把“最终派发”和“策略/人工 book 归属”也归给 execution（`bt_api_py/docs/迭代计划/迭代10-可选组件与可配置通信/ai-for-investor接入与组合风控职责迁移.md:16`、`:23`、`:124`）。按 63 方案 A 与原话 3，派发与每策略归属在 Gateway；execution 只负责母单、子单计划、算法进度和成交向唯一母单的归集（63 分析:126；当前范围按 D65-31）。
2. **现有 execution 是派发 owner 形态。** `account_owner` 直接持有 provider 端口（§1.2 第 6 项）。新服务需要的是 Gateway 的客户端，而不是又一个派发 owner。
3. **配置键冲突。** 若把执行路由写进 `execution_config` 或 §1.3 的 12 个键，BT 会离开 direct/Gateway 路径（`btapistore.py:410-418`），等于让 BT 感知 execution。
4. **委托只有字段，没有授权语义。** `WireIdentity` 有 `actor_ref`、`delegate_ref`，注释写明是 untrusted sender claims（`base: service_protocol.py:194-206`）；ServiceHost 只在行情身份上拒绝 `delegate_ref`（`SDK: service_host.py:738`），非行情端口是否核验委托没有核实。线上声明不能作为“代表策略 X”的授权（INV-05）。已列入 63.13：代理 principal 的授权以 Gateway 的登记为准。
5. **没有母单信封。** Gateway（63 草案初稿）只有逐单预留，没有记录母单总量、方向、开平、价格上限和期限的耐久信封。execution 有缺陷时可以发出超过母单的子单，而 Gateway 无从发现。按已决定的 D65-01 由 63.13 实现；开 risk 时 risk 的母单预留另行约束数量（64 计划 §3.3）。
6. **子单幂等需要调用方键。** 已纳入 63 计划 §3.4、§3.5 的 `request_key`；子单以 `child_id` 作为该键，经 risk 转发时沿用。
7. **行情。** 算法需要盘口和成交量；execution 目前没有任何行情入口，而 MarketHub 的 principal 和键集合是静态给定的（63 计划 §3.3、D63-13）。execution 的行情 principal 已列入 63.13。
8. **原话 2 的文档影响。** 62 计划目标 3、63 分析 §5.2/§5.3 的 direct + risk、direct + execution 条目需随 U65-4 修改；63、64 计划已在 2026-11-06 晚修订，其余见 §9。

## 2. 目标、非目标与新增规则

### 2.1 目标

1. **独立进程。** execution 作为独立的服务进程运行（ServiceHost + CURVE，同主机 loopback），有自己的日志、配置和生命周期；它崩溃不影响 Gateway 和策略进程（U65-1）。
2. **以 Gateway 为前提。** 只有开启 Gateway 时才可以启用；Gateway 未开启而配置了 execution 时以有限错误码拒绝启动；未选择时任何进程都不导入 `bt_api_execution`（U65-4、INV-01）。
3. **BT 投影。** 用户要求 BT 不处理，SDK 负责接入；BT 产品代码零改动能否成立按 D65-03 候选提前验证；`bt_api_py` 按配置把命中规则的 BT 订单作为母单交给 execution，其余订单按 63 方案直通 Gateway；母单对 BT 投影为一笔普通订单（§1.4）。
4. **子单只经 Gateway 派发。** 子单走 Gateway 唯一派发点，受同样的授权、归属、流控与急停约束；开 risk 时子单先经 risk 服务（execution → risk → Gateway，与普通订单同一路径，64 计划 §4.2）；Gateway 用母单委托信封限制子单（D65-01）。
5. **母子两级风控。** execution 受理母单后经 risk 服务整笔预留（`risk.parent.reserve`），子单在 risk 服务逐单 claim（64 合同）；未开 risk 时没有这两级风控。
6. **崩溃安全与幂等。** 每个崩溃点都能按身份恢复；子单结果不明保持 UNKNOWN，不重发；execution 崩溃只冻结母单（U65-1）。
7. **可配置执行方案。** 用 `config.yaml` 选择可扩展的执行方案类、反向轧差方案和算法，支持不选择算法；同向订单和轧差后剩余按原母单各自下场，本迭代完成独立下场与反向轧差纵切；轧差首期必须支持虚拟多空及后续平仓转换（D65-27/28），具体经济和账本规则经用户决定并满足上游合同后交付（§4）。
8. **独立可选前端与后续集成。** 按 D63-47 为 Execution 提供可独立启用的前端入口，页面与服务解耦，前端和以后 ai-for-investor 通过版本化服务 API 接入；关闭页面不停止服务、不改变执行及 UNKNOWN 合同。页面提供查看及各服务授权管理；本迭代不实施 ai-for-investor 集成（§3.11a、§3.12）。
9. **验收。** 回环集成（INTEGRATION_SIM），以及 SimNow 上 1 个 Gateway + 1 个 execution + 2 个策略。

### 2.2 非目标

- 基础转发（归 Gateway，迭代 63）；风控政策（归 risk，迭代 64）；急停（状态与执行在 Gateway，U65-7，迭代 63）。
- 修改 `bt_api_gateway`：本迭代需要的 Gateway 侧能力都在迭代 63 的 63.13（U65-9）；发现缺口时提回 63。
- 同向订单合并下单及多母单共同场所子单：D65-31 已明确不在本迭代范围。反向轧差仍是本迭代目标，相关合同或政策未就绪时保持 GAP。
- VWAP、POV、冰山、盯价的实现（§4.2，后续阶段）。
- 母单改单（amend）：64 计划把“CTP 无改单”记为 provider 事实（64 计划 §3.2 R-04），本仓库未另行核实；母单只能撤销后重下。
- 跨主机部署；execution 高可用或主备；多个 execution 实例服务同一账户。跨交易日母单按 D65-04 属于首期范围。
- direct + execution（U65-4）；修改 direct 路径；退役迭代 60 托管 execution 路径（D65-11）。
- 集成 ai-for-investor；OKX/Binance（D63-10/Q33 已确定后续接入）；生产账户验证。

## 3. 架构

### 3.1 总览

**D65-01 用户 2026-11-08 已决定：先 Execution，再选用的 Risk，再登记 Gateway。** 策略进程通过 SDK 将命中的 BT 母单交给独立 Execution；选用 Risk 时由 Execution 先请求母单风控并确认结果，然后向 Gateway 登记母单范围；未选择 Risk 时 Execution 直接向 Gateway 登记。Gateway 持有并独立验证策略委托、母单数量和价格等权威边界，在子单派发前完成登记；登记不向交易所下单，Gateway 不调用 Risk、不检查 Risk 批准。后续每个子单按配置走 Execution → Risk → Gateway，或未选 Risk 时 Execution → Gateway；撤单依 Gateway 合同。

```text
策略 BT → SDK：形成并持久记录稳定请求身份
     SDK → Execution：parent.submit（Execution 持久母单意图与身份）
     Execution → [选 Risk] risk.parent.reserve：母单风控/占用
     Execution → Gateway：登记/确认母单授权范围与数量桶（不下场）
     Execution → [选 Risk] risk.order.reserve / dispatch → Gateway → CTP
                [未选 Risk] direct.reserve / dispatch → Gateway → CTP
     Gateway → 策略 SDK、Execution、[选 Risk]观察流：各自受权的结果与回报
```

实际操作名、握手与状态由 63/64/65 在 65.01 联合冻结；不能假定各服务已支持。SDK 在首个远程副作用之前持久保存可恢复的请求身份；Execution 在请求 Risk 前持久关联稳定母单身份、原请求摘要与账户/策略/委托、计划和生命周期版本。该身份仅是关联键，不授予账户或场所权限；生成位置、编码、全局唯一约束、认证授权及映射为 65.01 待冻结合同。Gateway 必须按可信主体和委托校验策略身份、scope、当前授权及母单参数，独立创建/确认自身权威记录，不以客户端自报或 Risk 本地记录代替。读取既有 Gateway 行情/账户事实用于 Risk 判断不等于提前登记该母单。

跨进程日志不能原子提交。首次提交的请求/回复丢失时沿原身份分别查询 Execution、所选 Risk 与 Gateway，确认持久状态与迟到请求 fence；无法证明时保持 UNKNOWN 和最坏占用，不新建母单、不换键重发。Gateway 母单权威登记成功前不得预留或派发子单；Risk 被选中而不可用不得绕过。只有按冻结合同证明 Execution 与 Gateway 均已可靠受理，SDK 才向 BT 投影确定受理；具体投影可行性仍须 65.01 真实 BT 原型验证。

### 3.2 BT 订单怎样被路由（SDK）

- 路由在策略进程的 `bt_api_py` Gateway route 内进行，位于 63.05 远端 `DirectWriteProvider` 之前：`make_order(OrderRequest, pre_dispatch_commit, host_scope)` 先按规则匹配，未命中走 63 的直通路径（开 risk 时经 risk 服务），命中走 §3.1 的 Execution → 可选 Risk → Gateway 登记顺序。
- 配置分账户授权、Execution 服务方案、策略路由三层（候选 schema 见 §5）：账户声明可委托范围与上限，服务登记支持的类和组合，策略在两者之内选择或收窄。最终匹配规则与不兼容策略如何分组待 65.01 冻结；策略不能越过账户授权或服务能力。
- 匹配维度：合约、方向、开平、订单类型（首期仅限价母单，D65-07 已决定）、数量阈值（如 ≥ N 手）。自上而下取第一条命中；没有命中就直通。不按信号或指标匹配，因为 BT 不传执行指令（原话 1）。
- 规则在启动时校验并冻结。Gateway 对未授权的 `parent.authorize`（策略无权委托给该 execution、合约不在白名单）拒 `execution_not_authorized`，这是 Gateway 的授权。Gateway 是否还要拒绝“命中规则却走直通”的订单（`execution_route_required`），见尚待决定的 D65-15：候选 a 不强制则执行路由由 bt_api_py 配置决定，配置漂移可能造成绕过；不得把该候选视为已接受。
- 配置键必须位于 SDK 解析的 Gateway route 选项内，不得使用 `execution_config` 或 `DIRECT_EXECUTION_CONFIG_KEYS`（§1.6 第 3 项）；BT 只透传，不解析。
- 命中规则但 execution 不可用（未启动、租约失效、母单被拒）：只有权威证据确认母单未开始时以有限码拒绝；结果不明保持 UNKNOWN 并阻断，不降级为直通（INV65-06）；未命中的订单照常直通（D65-10）。若已选择 risk，SDK/服务配置必须保持 risk 在 Gateway 前且 risk 故障时 fail-closed；Gateway 自身不检查风控批准（U65-6），不能把 SDK 的规则描述成 Gateway 强制保证。

**首期母单类型与拒绝边界（D65-07 / Q36，用户已决定）。** Execution 首期只接受限价母单。明确配置路由到 Execution 的规则若静态可知必然包含不支持的市价或其他类型，在配置加载/校验时以有限错误拒绝该矛盾配置；若规则按运行请求动态匹配，实际命中且类型不支持时在母单受理前明确拒绝该请求。不得静默绕过 Execution、回退直通或自动改成限价；不存在把所有市价请求都默认当作已命中执行路由的规则。Execution 未选择或请求未命中执行路由时保持原有路径及其既有规则；本决定不证明 direct、Gateway 或 provider 的市价能力可用或已验收。

已命中的限价请求须具有合法、有限的限价并满足价格网格、数量和其他既有基础合同；普通子单限价不越母单约束。D65-27/28 的虚拟平仓转换仍适用，并分别保留策略层和账户层真实开平及转换授权，不能以限价范围混淆开平或豁免转换准入。Risk 仍是可选组件；本限价范围是用户的产品选择，不以强制 Risk 或保护价功能归属作为理由。首期算法按 D65-08 已确定为 PASS、SLICE、TWAP；具体参数和调度细节待冻结。

拒绝语义须在入口形成可追溯的有限错误状态和稳定幂等关联，配置错误与动态请求错误分别报告；拒绝应在创建活动母单、子单及新增数量/资金占用前原子发生，不向 Gateway/provider 派发。可保留不携带写入副作用的审计记录，不能留下活动信封或未释放的新预留。65.01 冻结错误码、SDK/BT 错误投影及并发/崩溃边界；若尚不能证明拒绝发生在副作用之前，则按实际已到达的阶段查询和恢复，不能把不明结果伪装成确定拒绝。

测试矩阵：显式 Execution 路由的市价及各声明不支持类型、静态矛盾规则、动态宽泛匹配命中、市价不能自动转限价；合法限价、非有限/缺价/越网格/非法数量；同 ID 重放、并发与失败注入下无活动母子单/新增占用/发送。另测 Execution 未选与规则未命中只按原有路径处理，分别记录其环境和结果，不将替身或这组测试宣称为 Gateway/direct 市价验收。

### 3.3 母单接口（D65-01 已决定；名称与状态在 65.01 冻结）

Gateway 侧由迭代 63 的 63.13 实现，Execution 侧由迭代 65 实现；以下名称是合同候选，不代表现有端口已交付。

| 操作 | 所在 | 调用方 | 语义 |
| --- | --- | --- | --- |
| `parent.submit` | Execution | 策略 SDK | 在第一次远程调用之前以稳定请求身份耐久记录母单、认证策略和委托；相同 ID/摘要幂等、异摘要冲突。选 Risk 先完成所需母单风控；然后由 Execution 请求 Gateway 登记。中间阶段不能当成 Gateway 已受理或场所已发单。 |
| `risk.parent.reserve` | Risk | Execution（仅显式选用） | 在 Gateway 登记前检查并预留适用风险，以稳定母单身份、策略授权及可信账户事实绑定；Risk 不要求 Gateway 已有该母单记录。Risk 客户端与来源授权在 64.01/65.01 冻结。失败或不明不绕过。 |
| `parent.authorize` / `parent.accept` | Gateway | 经授权 Execution | 在所选 Risk 成功后登记并校验原母单、策略、委托、账户/合约、期限和数量及价格边界，创建受 Gateway 权威约束的母单记录；是否合并为一个原子操作由 63/65 冻结。Gateway 不调用 Risk、不检查 Risk 审批；登记不调用 provider。 |

| `parent.cancel` | Gateway；登记前由 Execution 按冻结的初始请求合同处理 | 获授权策略 SDK、运营 | 母单已登记且策略主动取消时 Gateway 冻结该母单并尝试撤其活动子单、逐笔报告结果（D65-06）；不得撤其他母单或将受理当撤成。登记尚不明确时按原身份查 Execution/Risk/Gateway，不能假定不存在、不盲目释放；具体受权取消和迟到请求 fence 由 63/64/65 冻结。 |

Gateway 授权/活动/结束与 Execution 接收/风控/登记中/冻结是不同状态层；版本化映射、取消与故障原因、迟到请求 fence 及最终有限码由 65.01 联合冻结。不得凭进程就绪、Gateway 无记录或超时断言母单确定未开始。

### 3.4 母子身份

- 身份链：BT（策略 UUID、局部序号、`Order.ref`）→ SDK 在远程调用前持久的稳定原始请求键 → Execution 在 Risk 之前持久关联的请求/逻辑母单身份 → Gateway 登记的权威 `parent_ref` → 子单号 `child_id` → Gateway `reservation_id` → 原生身份（该子单交易日、FrontID、SessionID、OrderRef，派发时分配）→ 场所身份（交易日、ExchangeID、OrderSysID）。Gateway 的 `parent_ref` 可以在登记时才生成，也可采用经验证的既有身份；具体分配者、编码及贯穿 Risk/Execution/Gateway 的唯一耐久映射由 63/64/65.01 冻结，不能假定用户已选分配方。`child_id` 在子单请求前持久生成且不复用，具体编码待冻结；身份和映射不授予账户权限，母单关联不随交易日变化。
- `origin` 取值为 `self`、`execution:<execution principal>`，经 risk 转发时为 `risk:<risk principal>`（63 计划 §3.5），同时带 `on_behalf_of`（母单所属策略）与 `parent_ref`；记入归属账本的策略是母单的策略，不是 execution 或 risk（INV65-05）。
- 母单对 BT 的身份候选：`NativeOrderIdentity(exchange_name, client_order_id=<由 parent_ref 派生的稳定母单号>, fields={parent_ref, origin_trading_day})`；初始日只作不可变元数据，不参与滚动身份，不含子单原生字段。该字段表达及跨日投影可行性须经 65.01 真实 BT 原型验证（§1.4），不得假定现有接口已支持。
- 每个实际子单唯一归属一个发起母单与策略；一母单可按算法拆多子单。反向匹配与内部转移仍须各方授权及原子账本，不能把多方内部映射误当作共同场所子单；虚拟转换保留 conversion_id、唯一发起母单/策略、原因和受影响映射。

### 3.5 子单怎样到达唯一派发点

1. execution 写 CHILD_PLANNED（child_id、数量、价格规则），再发出子单预留：开 risk 时调 `risk.order.reserve`（带 `parent_ref`、`child_id`），由 risk 预留并从母单预留中扣减后转发 Gateway `direct.reserve`；未开 risk 时直接调 Gateway `direct.reserve(origin=execution:<E>, on_behalf_of, parent_ref, child_id)`。
2. Gateway 在预留时核对信封（INV65-03）、母单处于 ACTIVE、代理关系（INV65-04）、母单所属策略和代理两级流控份额、急停，以及 63 的其余逐单检查（63 计划 §3.5）。
3. execution 写 CHILD_RESERVED（reservation_id），再发出派发：开 risk 时调 `risk.order.dispatch`，risk 在自己的事务内 claim（自成交、计数等）并提交后转发 Gateway `direct.dispatch`；未开 risk 时直接调 Gateway `direct.dispatch`。Gateway 在派发锁内复查急停 → 写 DISPATCHING → grant → 原生调用。execution 不直接操作 risk 账本。
4. 对可能的确定未发送结果，先按原身份核对权威终态、完整覆盖及旧请求不可再生效的 fence；错误码、超时或缺行本身不能证明 NOT_SENT。用户已确认 D65-14：仅在证明确定未发送、母单有效且具备其他准入条件时，按账户配置的次数使用新的 `child_id` 重试；次数用尽冻结母单并报告。重试上限必填、无数值缺省，显式 0 表示不重试并按用尽处理；须重新验证期限、权限、急停、风控和原计划，不能将所有拒绝笼统视为可重试。结果不明（包括调用 `risk.order.dispatch` 超时）保持 UNKNOWN，母单停止相关切片、不换身份补发。
5. 子单撤单（时间片结束、未成余量）：execution 直接调 Gateway `direct.cancel`，不经 risk（64 计划 INV64-11）；Gateway 核对目标是该 execution 母单的子单；risk 从观察流把撤单计入 R-04。

**真实订单 UNKNOWN 的最小阻断范围（D63-04 / Q28，用户已决定）。** 本系统真实订单结果 UNKNOWN 时，Gateway 持有系统未知栅栏：阻断该订单所属策略在同一合约上的所有新订单（OPEN、CLOSE、新子单以及通过新内部转移提交执行的订单份额）；不得通过更换母单、请求号、路由或执行方案绕过该策略/合约范围。已提交内部转移按原身份查询，不能因阻断而抹除。对其他策略仅当该 UNKNOWN 使同一账户、同一合约、同一持仓方向的实际可平容量无法证明时，暂拒其相应平仓；容量可证明且满足各自既有门槛的平仓，以及其他不受独立阻断影响的交易继续按各自合同处理。不能从策略理论仓或 external 净额推断真实可平容量，也不能将该规则改成所有策略、所有方向的新单均阻断。

撤单和查询入口保留，断线时不承诺可以送达；不因该 UNKNOWN 自动撤销现有挂单或停止策略进程。已选择 Risk 时，其相关最坏占用继续保持，系统栅栏缩小不构成释放依据；未选择 Risk 不引入其服务依赖。按权威证据逐项解除对应 UNKNOWN 原因，不能连带解除其他独立的会话、日切、风控或急停阻断。D65-05 已决定按账户配置选择恢复模式，缺省为核对后按原计划自动继续；该范围规则不解除其他独立阻断。

应区分母单授权/受理结果不明与真实子单是否已派发：前者按原母单/请求身份查 Gateway/Execution 权威阶段并保留相应未决，不能直接假定场所已接收或未经证据套用真实订单 UNKNOWN；真实订单结果不明则按上述范围和原生身份恢复。D63-38 已决定：完整、同交易日、强身份的委托查询查不到原身份时，按既定合同标 `not_found_at_venue`、向策略投影 Rejected 并解除对应阻断，但不自动重发，也不改写成确定未发；查询不完整、旧交易日或身份不可靠不得据此解除。D63-48/49 的 external 禁入及无真实可平量拒单、理论仓不变仍有效，普通 A/B 策略虚拟转换不因此撤销。

验收：A 策略合约 X 的真实子单 UNKNOWN，A 在 X 的 OPEN/CLOSE/新子单均拒，换母单/键/方案仍拒；B 同账户 X 同持仓方向的 CLOSE 分别注入可平容量可信可证与不可证，前者满足独立门槛时继续，后者暂拒；B 其他方向/合约及其他策略不因 A 的 UNKNOWN 一概阻断。验证保留撤单/查询接口但断线不声称送达、不自动撤既有单或停进程；模拟多重独立阻断，证据解决一个原因只解除该原因；Risk 选用时最坏占用不提前释放。母单受理不明但尚无真实派发证据，与真实子单 UNKNOWN 分别恢复；覆盖 D63-38 完整/不完整/跨日强身份查询与不自动重发，D65-05 的账户配置与原计划恢复条件同时验证。

### 3.6 成交归属与对 BT 的投影

- Gateway 按唯一母单/策略归属实际子单和真实成交并写入授权回报流；轧差形成的内部转移另按 §4.3 的多方授权及原子账本合同处理，不产生共同场所成交。转换订单绑定唯一发起母单和策略，同时记录其因果及受影响映射，账本投影按已确认的转换合同核验。
- 策略 SDK 把带 `parent_ref` 的真实子单事件和独立内部转移/转换事件投影为母单事件，保持来源可区分。真实成交保留真实场所成交号、价格、数量和开平；内部转移不补造 TradeID 或手续费。母单数量按下述口径，不能再用 Σ 场所子单成交作为唯一完成量。母单 ACTIVE 时投影 `accepted`；收到通过数量/未决校验的 `parent.complete` 后投影策略订单终态。子单自己的 accepted、cancelled、rejected 不直接投影给 BT。BT executed/通知如何承载不同来源由 65.01 真实框架原型验证并冻结；做不到按 D65-03 提请决定，不伪造成交。
- 账户事实（63 的 `direct.account_facts`）：本策略带 `parent_ref` 的子单委托和成交折叠为母单（§1.4）；其他策略的子单按 63 的“其他策略”标签计数（D63-01）。
- execution 只用 execution 回报流推进算法，不读策略流；子单成交向唯一母单的归集写在 execution 日志里，只用于算法和报告。

**母单完成量技术合同（2026-11-08 交接复核补齐）。** 以 Gateway 权威、去重且来源分明的策略进度事件计算 `strategy_completed_qty`。普通真实成交、已提交内部转移、已完成的虚拟转换进度是互斥的进度来源；转换的真实成交事实与它引起的策略完成事件不能重复累计同一份数量。`venue_filled_qty` 只记录真实场所成交量，`internal_transferred_qty` 只记录内部转移量，`conversion_completed_qty` 表示已由权威映射确认的策略转换完成量；准确字段名和 BT 映射在 65.01 固定。

`strategy_remaining_qty = order_qty - strategy_completed_qty`，其未完成部分另区分可继续执行、在途/UNKNOWN、已取消和已到期，不能把未完成量全部当可再次派发量。FILLED 表示策略意图数量全部完成且不存在未核清子单/转移/转换，不表示全部在交易所成交；取消/到期只结束经证明未执行的余量，不能删除已完成内部转移。全部内部抵消的母单可以完成，原始场所成交量仍为零。

手算验收：A 买 7/B 卖 5 已内部转移 5，随后 A 实际成交 2，则 A 的策略完成量为 7、B 为 5，真实场所成交分别为 2 和 0，两者都可在未决清空后进入 FILLED。只有内转 5 时 A 尚余 2，B 可以完成。转换只确认 2/5 时只推进已证实的 2，剩余 3 不提前完成或释放；重复或跨来源重放不再次推进。

### 3.7 风控（迭代 64 的 API）

调用路径与 64 计划 §3.3、§4.2 一致（原 D65-12 已由 U65-5 消解：Gateway 不调用 risk，所以 `reserve_parent` 不可能由 Gateway 调用）：

| 层级 | 调用 | 调用方 | 依据 |
| --- | --- | --- | --- |
| 母单 | `risk.parent.reserve`（即 `reserve_parent`）：整笔检查 R-03 持仓、R-07 亏损、策略额度，记录母单范围；R-01 单笔上限、R-02 价格带不按母单查 | execution，在 `parent.submit` 受理之后、`parent.accept` 之前 | 64 计划 §3.3 |
| 子单 | `risk.order.reserve`（带 `parent_ref`，从母单扣减，超出母单即拒 `risk_parent_envelope_exceeded`）→ `risk.order.dispatch`（risk 内 claim，提交后转发 Gateway） | execution | 64 计划 §3.3、§4.2 |
| 子单结算 | risk 按 Gateway 结果与观察流结算 | risk 服务自身 | 64 计划 §4.2 第 6、8 行 |
| 母单结束 | `risk.parent.release` 释放未用部分；有 UNKNOWN 子单的母单保持占用 | execution（risk 另从观察流核对） | 64 计划 §3.3 |

- 未选 risk 时，母单只受 Gateway 的信封、授权、归属、流控与急停约束（S-02 选 B 后，单笔上限等不在 Gateway）；execution 不因此获得额外控制，也不另做风控。
- 选中 Risk 且其整体不可用时按已决定的 D64-02：拒绝新的 OPEN/CLOSE 的母单风险受理和子单预留，不改为直达 Gateway；此前已在途而结果不明的请求仍按原身份保持 UNKNOWN。撤单入口经 Gateway 发起，是否送达及终态以实际结果为准，不能因 Risk 不可用声称撤单已成功；母单主动撤单时按 D65-06 冻结并尝试撤其活动子单。
- Gateway 不检查风控批准（U65-6）：若 execution 在开 risk 的配置下被误配为直达 Gateway，子单照常受理，risk 只能事后从观察流看到（64 计划 INV64-10）。这是已接受的性质；Gateway 的母单信封仍然约束子单。

**2026-11-08 Risk 联动决定。** 选 Risk 且 R-08 为 deny 时，整笔母单按保守最坏资金及保证金预留，子单从已占额度划拨、不得重复占用；off/warn 不因此新增 deny 级资金预留，也不能因切换为 off 清零既有 deny 未决占用。费用、取消、部分成交、内部转移、日切及 UNKNOWN 按 63/64/65 共同冻结的来源绑定、水位、守恒和恢复合同处理，不能把 Risk 本地序号当作 provider 余额覆盖证明。未选 Risk 不引入此依赖。

选择 Risk 且启用 R-02 时，实际子单按其规则使用最新成交价并检查质量/新鲜度，过期或缺失时拒绝受该规则约束的开仓；限价平仓依 `apply_to_close`。D65-07 的 Execution 母单及子单首期仅限价；Risk 的价格带启用时市价开平都拒绝适用于其相关路径，不据此宣称未选或未命中 Execution 的市价支持。D65-29 的内部转移定价可选中间价或最新价，与 R-02 参考价是独立合同，不互相替代。

选择 Risk 且适用 R-11 时，消费 64 集中规则文件及其账户、合约、交易日、来源和版本；首期只支持单账户，检查限仓、日内开仓量、交割月等。规则及来源由 64 持有；母单、实际子单与内部转移的检查时机、统计口径和幂等归集由 63/64/65 冻结，不能臆造阈值或将账本转移当作场所成交。启用且适用的规则缺必要证据时不能判通过；未选择 Risk 的路径不依赖该规则服务。

### 3.8 持久化、崩溃恢复与幂等

BT `live_state`、Gateway 日志、execution 日志、risk 账本四个存储彼此不原子。次序规则沿用 63 分析:142：原生调用只发生在所有相关耐久记录之后；恢复按身份查询，不按时间推测。

| 序 | 步骤 | 耐久位置 | 崩溃/丢回复后的恢复 |
| --- | --- | --- | --- |
| 1 | SDK 为 BT 请求持久化稳定提交身份及原始关联，再调用 Execution | `live_state` | 本地记录失败不得发起远端提交；调用结果不明按原身份查询，不创建新母单。 |
| 2 | Execution 校验并耐久接收母单意图、身份、策略委托、摘要与计划版本 | Execution | 回复丢失按原提交键查询；同键同摘要返回原状态，异摘要冲突；不能凭本地缺少回复推断 Execution 未接收。 |
| 3 | 选 Risk：Execution 以稳定母单身份申请母单风控与预留 | Risk | 请求/回复不明按原身份查 Risk 和 Execution；Gateway 尚无母单不证明 Risk 无占用。须经有效 fence 证明无迟到副作用，才能按合同释放；否则 UNKNOWN。 |
| 4 | Execution 在适用 Risk 成功后，请求 Gateway 登记并确认母单授权及权威数量桶 | Gateway | 登记与取消/超时竞争时查询三方原身份、状态和条件提交；Gateway 缺行、TTL 到期或 Risk 单次回复均不证明不会迟到或没有占用；缺证保持 UNKNOWN。Gateway 校验策略与代理 grant，但不检查 Risk 批准。 |
| 5 | SDK 得到符合合同的持久受理结果并投影 BT；Execution 按原计划调度 | SDK、Execution、Gateway | 投影回复丢失按同一身份查询、去重恢复；不得换号重复母单；无法证明受理不伪装成确定拒绝或场所已发单。 |
| 6 | Execution 持久子单计划，经选用 Risk reserve/claim，再经 Gateway 的权威信封 reserve/dispatch | Execution、Risk（选用）、Gateway | 任一阶段结果不明按原身份查询且保持 UNKNOWN；未发送重试按 D65-14 的证明、显式次数和授权条件，不能以错误码或缺行单独推断。 |
| 7 | Gateway 回报并投影；母单终止后按权威证据处理剩余占用 | Gateway、Execution、SDK、Risk（选用） | 按游标与事实身份幂等恢复；迟到成交、转移/撤单不明或占用未核清不得提前释放，不得生成第二个场所结果。 |

- **execution 崩溃（U65-1）。** 租约失效 → Gateway 冻结它的全部母单（不再受理子单预留；在途预留仅按权威终态/fence 核对后处理，不能仅凭到期释放）；活动子单留在场所，照常回报；BT 订单保持活动；risk 对这些母单的预留保持。重启后 execution 读日志，按 child_id 和 reservation_id 向 Gateway（开 risk 时也向 risk）查询；是否恢复切片按 D65-05。

**Execution 崩溃后的母单恢复（D65-05 / Q29，用户已决定；接口字段待冻结）。** 账户 `config.yaml` 可选择按原计划自动继续或保持冻结；候选字段 `components.execution.recovery_mode`，缺省 `AUTO_CONTINUE`，可显式选择 `KEEP_FROZEN`。省略按用户决定取自动继续；非法值拒绝配置，不能默默转为默认。该配置与匹配/定价/算法类分开，随母单受理时的方案及账户配置版本持久绑定；重启配置漂移不静默改变在途母单，必须保留原绑定或按已验证的迁移合同处理。示例配置的名称、序列化和迁移方式在 65.01 与 63 冻结。

自动继续须先证明原计划时间窗仍有效，原母单/子单身份、日志完整与 writer fence、当前授权及 grant、冻结的策略/算法与配置版本、Gateway 账本及子单状态、选用 Risk 的占用和相关源水位均核对一致；没有 UNKNOWN、流缺口、身份冲突或会话/日切/风控/急停等其他阻断，才能继续。服务健康或进程重启本身不构成以上证明。Gateway 以版本化、权威的原子状态转换，只解除有证据解决且当前 grant 有效的本 Execution 故障冻结；Execution 不得私改 Gateway 状态，亦不得自动 RESUME 运营、Risk、Runtime 或其他独立原因。权限变化、账本/配置不匹配、时间或来源不能证明时保持冻结并可见；已到期的原计划不能重新启动。

原计划的截止/价格/数量/预算和算法约束继续有效，恢复只处理原计划当前时刻可证明允许的未下场余量；不能仅因重启默认把错过的所有 TWAP 切片集中补发；按原已冻结算法的错过时刻策略及数量/速率边界继续，不能临时改算法规则。冻结算法合同无法证明存在合法继续动作时保持冻结并说明；不自动重发 UNKNOWN 或改变 D65-14 的确定未发重试政策。已有场所挂单按原 child_id/原生身份继续跟踪，既不因服务故障自动撤单也不重发；后续成交只按原始权威事实推进。KEEP_FROZEN 下母单保持冻结，直到策略撤单或按合同到期，不新增其他人工继续入口。

验收向量：母单 10 手，已成交 4、原挂单 2、未下场 4；重启并逐项核对通过后 AUTO_CONTINUE 仅按原计划处理那 4 手，不撤不重发原挂单 2；原挂单后续成交按真实回报与幂等规则推进。分别验证缺省自动、显式保持冻结、非法值拒绝、旧母单配置版本不因新配置漂移、未决/缺口/授权撤销/原计划到期/其他独立冻结不继续、选 Risk 时占用不明不继续、网关原子恢复防旧 owner 竞态、TWAP 错过时刻遵守原算法规则、不默认集中补发，以及 KEEP_FROZEN 的撤单/到期。D63-04 的 UNKNOWN 范围、D63-38 的查询及拒绝投影、D63-48/49 的 external 边界不因本模式改变。

- **risk 崩溃（开 risk 时）。** 子单预留与派发按 64 计划 §4.3 处理；risk 不可用期间 execution 不切片（子单预留被拒，不改为直达 Gateway，INV65-06）；撤子单仍经 Gateway 发起，不能保证网络可达或撤成。
- **Gateway 崩溃。** 按 63 计划 §3.12 恢复，先解决 DISPATCHING。期间 execution 看到 `gateway_unavailable`，不切片。
- **策略崩溃。** 已被 Gateway 和 Execution 受理的母单原则上按原计划继续，但须满足当前授权、适用租约、Gateway 急停和其他独立准入；不能把策略进程退出当成自动撤母单或交易许可。策略租约过期按 D63-28 配置处理，默认不自动 DRAIN；开启后依 Gateway 权威状态执行。Execution 自身租约失效按上文冻结其母单，二者独立。BT 重启后凭原身份恢复，缺证或 UNKNOWN 不补发（§1.4 第 6 行）。
- **确认边界。** `parent.authorize` 的请求号须在发起远端调用前可从持久本地身份重建；回复丢失后按该号查询/重试，不能生成新号造成孤儿授权。风险预留、释放、母单 accept/complete/cancel 与子单 dispatch 均按远端权威状态和幂等键恢复；本地无记录、超时、失联、期限到达均不单独证明远端未执行。
- **幂等键。** SDK 发给 Execution 的稳定请求号在首次调用前持久，Risk 按已绑定原始/逻辑母单身份预留；Gateway 登记时的权威 `parent_ref` 可以稍后确定。各键须有唯一、耐久且可核验的映射，作用域、分配者和绑定由 63/64/65.01 冻结。另有 `child_id`、`reservation_id`、撤单命令号；同号同内容返回已记录结果，同号不同内容拒绝（沿用 63 计划 §3.5）。
- **分工。** 母单信封和母子映射在 Gateway 日志；母单进度和算法状态在 execution 日志；母单与子单的风控占用在 risk 账本。execution 日志损坏 → execution 拒绝启动，Gateway 侧母单保持冻结；策略主动撤母单时 Gateway 按 D65-06 尝试撤该母单活动子单，逐笔查询与报告实际结果，不撤其他母单或策略的单。

### 3.8a 策略生命周期与 66 审阅的接口边界（2026-11-08，待联合冻结）

输入为 [66 GLM 审阅](../迭代66-bt_api_runtime策略启停与本地操作/glm-迭代66-审阅报告-2026-11-08.md) GL66-03/07/08/10–12、[66 Qwen 审阅](../迭代66-bt_api_runtime策略启停与本地操作/qwen-迭代66-审阅报告-2026-11-08.md) QW66-01/02/05/07，以及 63/66 当前计划；旧报告建议由 Runtime 统一启停共享服务的部分已被 D66-02 取代。以下是 65 所需的边界与工程验收，非服务已交付的证明。

1. **两个重启不是同一事件。** D66-09 是策略进程异常退出后的自动重启，默认关闭、可逐策略显式启用有界退避；D65-05 是 Execution 服务恢复原母单，默认在逐项核对通过后自动继续。Runtime 首期仅监督策略，不能启停共享 Execution、Gateway、Risk、Monitor；进程启动、监控心跳和页面连接均不证明订单、资金或写者权威。用户已决定：其他 D66-09 启动硬门禁满足时，即使存在适用 DRAIN、FREEZE 或 STOP_NEW 也可自动拉起并显示原因，交易仍受限；不因此解除任何阻断，也不更改 D65-05。
2. **正常 stop/restart 的母单处理已决定。** 用户正常停止时取消该策略未完成母单余量，尝试撤销其场内子单，权威终态与成交水位可证明后才确认母单结束（共同合同 §2.33）。这是受权停止意图，不意味着单个子单撤销或 DRAIN 自动等于母单终态；在途请求、迟到成交、UNKNOWN 按原身份继续对账，不因进程退出释放占用。用户后续取消了本期重启后提示或操作原余量重新下单的功能；已取消母单不因重启复活，策略以后独立发单仍依既有准入。65.01 与 63/66 冻结命令、权限、版本、时序与账本映射。
3. **停止与解除的竞争。** Gateway 负责范围、cause/version 与最终交易门槛；Runtime 在受权范围请求策略控制，Execution 不清除原因。已有租约 DRAIN 按 D63-33 在策略重连并完成恢复核对后默认只解除该 cause/version，可配置人工；DRAIN 已发撤单继续跟踪，未发任务按 63 合同处理。63/66 须冻结停止意图仍有效时与该自动解除、多个独立原因、旧版本和原子子单/内转预留竞争的屏障；该屏障未证明前停止相关新动作，不擅自把租约原因改为永久人工或解除其他原因。66 计划中旧的“租约解除待定”表述与共同合同更新存在文档差异，应由 66 同步 D63-33；本节遵循已确认的共同合同，不将其当作新业务选择。不得以 Runtime 本地进程状态替代 Gateway 屏障和成交事实。
4. **组合证据及范围。** 65.08 对接 63/66 已交付的相应接口，覆盖策略租约与 Execution 租约独立/同时失效、启用/关闭租约 DRAIN、取消与迟到成交、多原因及 DRAIN 解除竞争；按母单和子单原身份核查在场、未发余量与选用 Risk 的最坏占用。启动早期 stop、SIGTERM/SIGKILL、进程身份及预算由 66 管理；涉及交易动作时查询各 owner 的耐久记录，不能凭信号送达、超时、观察事件或进程退出认定撤成/未发。无 66 真实组件时替身行单列，不能代替跨组件验收；66 整期不成为 65 基础执行硬前置。

### 3.9 日切、结算、交易时段与流控

- **D65-04（Q38）已决定首期允许原母单跨交易日继续**：同一 `parent_ref` 和初始账户/策略/主体归属、受理时算法/类/构建及配置版本、原有效期和限价均不随日切改变；初始交易日是不可变元数据，不是滚动身份。每个子单保留自己派发时的交易日、会话及场所身份和原序号。日切本身不终结母单，也不延长原期限；显式 DAY 或已达原期限按原合同到期，已发子单仍须按其身份管理。
- **候选生命周期与持久化合同**：受理时保存 `parent_ref`、初始归属及 `origin_trading_day`、`accepted_at`、原 TIF、可证明的绝对到期时刻/时区及规则版本、算法与构建/配置摘要、数量水位和占用；子单单独保存 `child_id`、其 `trading_day`、会话代际和原生/场所身份。候选状态为 ACTIVE → SESSION_PAUSED / DAY_SWITCH_PENDING → RECOVERY_PENDING → ACTIVE 或按原期限进入到期处理；状态名称和 DTO 由 63/65 在 65.01 冻结。原计划需跨日时应以带时区的绝对截止或等价无歧义的 provider 时段合同表达；不接受无日期、无时区的本地 `end_time`。持久化截止及日历版本，不因重启或新日重新计算完整期限。
- **候选日切事务和恢复**：Gateway 权威地建立带 `transition_id`、目标日、预期版本及 writer fence 的日切屏障并持久化，暂停新子单及内转预留；Execution 按原 ID 补回报/账本/会话与未决状态，外部查询不放在跨库事务内。经 Gateway 对一致切点、当前交易日/会话、结算、行情、授权、SDK 准入和各独立阻断作版本化核验，选 Risk 时另核对其当前政策和原占用，再由 Gateway 原子推进日切状态及水位；回复丢失按同一 transition ID 查询，不另建动作。精确接口、事务和 fence 由 63/65（选 Risk 时与 64）冻结，不能宣称现已实现。
- 旧日活动、撤单中和 UNKNOWN 子单保留原 ID 及最坏占用，日切不得释放或重发；可证终态后仅按既有合同释放。D63-38 仅适用于完整同日强身份查询，不将次日旧单空查询当成未发、终态或解除证据。日切后按 D65-05 缺省自动继续也须原有效期、日志、身份、授权、账本、冻结版本及其他条件均可证明；其他独立冻结不自动解除。母单总预算与未决占用跨日延续，按日计数另记，不能重复预留或释放；未下场轧差量须补齐日切事实且重新证明合格后才入池，不恢复同向合并。
- PASS、SLICE、TWAP 均在休市暂停并按原计划合法时刻恢复：PASS 不重复派发已挂子单；SLICE 保持子单顺序和终态条件；TWAP 保持原开始/截止、版本与切片水位，错过时刻按原冻结算法合同处理，不默认集中追补或重置期限。跨日 CLOSE 须按 provider 当前平今/平昨规则和理论仓映射重新核对，不改写旧成交及持仓成本，不自动改 OPEN；平今母单余量按 D65-37 核对原目标仓后可派生平昨子单继续：验证目标身份、方向、理论归属、真实可平容量、授权与原期限，按 provider 声明的 CLOSE_YESTERDAY 或等价映射执行，保存日切映射版本和派生 offset 审计；不得以次日新今仓替代、修改原母单意图或重复占用旧日在途/UNKNOWN 份额；证据不足按既定拒绝/UNKNOWN 合同处理；D65-27/28 的专门转换合同不变。
- 时段：只在合约的交易时段内下子单，午休、夜盘与日盘之间暂停。时段表的来源、版本固定、交易日重读与 UNKNOWN 语义须对接迭代 67 的 provider 日历与 SDK 中立接口，以及迭代 63 的 Gateway 日历/状态转发；本服务消费哪一中立端口在 65.01 与 63/67 冻结，不擅自复制日历或导入原生客户端。需要该时段合同的算法在所需覆盖、版本不可证明或状态冲突时暂停新子单，保持已有子单管理和撤单。67 未交付时相关算法可用明确标记的替身推进，不得据此完成真实日历验收；关闭算法的基础路由不以 67 文件化交付作为硬前置，仍遵守已有基础准入和日切合同。
- 结算确认只由 Gateway 做（D63-14）；execution 在 `day_ready` 之前不切片。
- 流控：子单占用母单所属策略的份额，另设 execution 总份额上限（运营填写）；撤单使用保留容量（63 计划 §3.10）。遇 `gateway_rate_limited` 时退避，不自旋。
- 查询：execution 不触发原生账户查询；子单状态来自 execution 回报流和 `direct.command_status`（63 计划 §3.6），不额外占用单查询槽（63 计划 §3.8）。

### 3.10 安全

- execution 进程不持有 CTP 凭据（INV65-02）。它与 Gateway 之间用 CURVE；私钥文件权限 0600，由运营工具生成，不经 argv 或日志（沿用 63 计划 §3.13 与 D63-13 a 的静态登记）。
- 委托：策略 principal 的 grant 增加“允许委托给 execution principal E”；Gateway 在 `parent.authorize` 时把母单绑定到 E，`parent.accept` 只接受 E；子单请求（E 直达，或经 risk 服务转发）都按 Gateway 自己的母单记录核对（INV65-04），线上 `delegate_ref` 只作审计。
- E 的 grant 仅包含所需的受权策略范围母单登记、读取/完成、其母单子单预留/派发/撤单及状态、execution 回报流和所需合约行情；Gateway 须独立验证策略 principal 的委托、账户/合约/方向 scope、授权代际和原始请求绑定，不信自报的 `on_behalf_of`。不得扩大到账户全量事实、其他策略的回报流、结算或急停命令。开 risk 时 E 另有 Risk 服务的客户端身份（64 计划 §6.1）；具体 grant/入口在 63/65 冻结。
- 运营可以只冻结 E（冻结 E 的全部母单）；FREEZE、STOP_NEW、DRAIN 对子单的作用与对普通订单相同，按子单所属策略匹配范围；急停状态由 Gateway 持有并执行（U65-7，63 计划 §3.17）。

### 3.11 可观测性

- execution 日志 → monitor：复用 `service_execution_monitor` 的中继模式（只读游标、owner 线程 poll、不在下单路径上，`SDK: service_execution_monitor.py:1-12`）。事件：母单受理、冻结、结束；子单拒绝码分布；UNKNOWN 子单；调度滞后；撤单预算消耗；滑点（`ExecutionQualityRecord`，须有到达价与成交证据）。
- Gateway 状态（63 计划 §3.14）增加：每个 execution principal 的租约、活动母单数、冻结母单数（由 63.13 实现）。
- monitor 缺省可选，只观察，不发控制命令（U65-8）。`monitor_required`（U65-2）是 Gateway 根据自己观察到的 monitor 存活作出的判定，与 execution 租约无关：execution 租约失效只冻结它的母单，不触发账户级 STOP_NEW。Q34 已定 Monitor 有效心跳恢复后 Gateway 默认只解除该失联原因，可配置运营恢复；Execution 继续检查其余原因/UNKNOWN 及母单自身恢复前提，不能据该单项解除重发或直接恢复所有母单。组合验收覆盖默认自动、配置人工及多原因保留。
- BT 订单看不到“母单冻结”和“子单 UNKNOWN”（§1.4 结论）；SDK 在 Gateway route 的状态报告里提供这两项，monitor 告警。按 D65-03 a，不为此改 BT。

D63-03/Q35 已决定 Gateway 断连时策略进程继续运行，SDK/Execution 显示链路不可用并停止无法可靠提交的请求，不回退 direct；在场子单仍按原身份跟踪，缺回报/撤单无回复不能当成终态。重连后须回补、对账及适用准入，母单沿原计划/原窗口和 D65-05 等既有条件处理；不得因连上 Gateway 即重发或将所有母单恢复。组合验收覆盖策略进程保持、原子单去重、对账未完成及其他原因保留。

### 4.3 可配置方案与反向轧差（D65-31）

同向原始母单不得合并去场所：A 买 3、B 买 7，分别经 Gateway 下 3 和 7；每个实际子单唯一属于其发起母单和策略，一母单可选算法拆为多个自身子单。只对反向订单配置可继承的轧差类和内部转移：例如 A 买 7、B 卖 5，在授权及合同满足且有合法价格时内部转移 5，A 余 2 按 A 原母单单独下场；不能把余量与其他同向母单重新合并。此例为数量演示，虚拟仓/今昨、成本及转换按 §4.4 和冻结合同处理。

轧差与算法可分别启用、关闭、选类或继承扩展；无算法是经 Execution 信封的整单 PASS。下表是目标而非实现或验收声明：

| 反向轧差 | 算法 | 行为与前置 |
| --- | --- | --- |
| 关 | none / SLICE / TWAP | 各母单独立下场；一母单可按所选算法拆子单，网关授权、持久化和 UNKNOWN 仍有效。 |
| 开 | none / SLICE / TWAP | 只匹配反向、经双方或多方逐一授权且依 D65-32 尚未下场、未被其他计划占用的母单可用量，形成独立内部事件；未抵消量仍逐原母单下场，真实子单不得共享。上游 63 账本/映射合同及选用 Risk 的 64 合同未就绪时该组合 GAP。 |

**反向匹配池与数量竞争（D65-32，用户已决定）。** 仅母单尚未下场且未被子单预留、其他执行计划、内部转移或其他在途/未决事项占用的可用余量可参与反向匹配；已预留派发、派发中、在场所挂单、撤单未确认、UNKNOWN 或任何未证明释放的数量均排除。匹配池只读快照不是预留凭证：内部转移预留与子单预留必须经 Gateway 权威数量桶在同一原子事务或等价可证明的串行栅栏内竞争，逐母单绑定身份、版本及范围，一份数量不能同时承诺内转与下场；竞争失败重新读取合法余量，不能假设对方释放或补发。匹配提案可能过期，提交时重新校验授权、版本和数量；内部转移 UNKNOWN 继续占用并按原身份恢复。

不为轧差主动撤销已下场订单；已有挂单按其原策略/算法计划运行。原本授权的策略撤单、算法撤单及 Gateway 的既有撤单合同仍可用；普通子单撤单并经权威终态和成交完整对齐后，若原母单仍有效，释放的未成交余量可按用户决定重新参与反向匹配；每次必须重新核验双方授权、有效价格、可用数量、原计划及 Gateway 权威数量桶，具体入池时机和事务由 63/65、选 Risk 时与 64 冻结。撤单未确认、UNKNOWN、迟到成交未核齐或母单已取消/到期的数量不得入池，不为轧差主动撤单。立即和有界窗口按 D65-33 明确选择；多方反向匹配的两类方法按 D65-34 明确选择，兼容配对和比例取整等具体合同待冻结，不以不主动撤单替代这些选择。

### 4.4 虚拟多空与转换（D65-27/28 已决定，合同待冻结）

每笔实际成交以可信来源身份、conversion_id、母单与策略建立唯一关联，只以已证实的增量推进 A 的虚拟平仓及真实/虚拟映射；部分成交、撤单结果未明或 UNKNOWN 的未完成数量保留相应占用，不预平 A 的剩余仓位、不重估 B 的成本。实际费用按来源身份、币种、版本和幂等键关联该成交；费用晚到、更正或重放采用追加修订且不重复扣款，费用未知明确为 UNKNOWN，不以零代替。63 的 Gateway 权威账本/映射、SDK 的 BT 非场所投影与选用 64 风控的结算须分别冻结并验证，不伪造 TradeID 或跨库原子性。

D65-29 选择的是内部转移记账价格，不决定该转换真实订单价格；真实订单仍须满足母单限价、D65-28 的专门转换准入及 Gateway 其他适用约束。策略按自身虚拟仓位计提占用并减少各自可用资金，见 D65-36；A 承担真实手续费不决定账户实际保证金如何摊作其他策略成本。非零内部转移费用、其他场景费用和盈亏政策、成本取值及占用公式和数据来源仍需分别冻结。

**策略虚拟保证金占用（D65-36，用户已决定；公式、来源及状态转换由工程合同冻结）。** 各策略按自身虚拟仓位分别计提策略保证金占用，减少各自策略可用资金；跨策略虚拟仓抵消不抵减各方策略占用。该占用是策略内部账本投影，不改变 provider 账户保证金或账户事实。63 的 Gateway 权威策略账本持有该投影及其身份/版本；65 提供方案和转换事实；64 仅在选用 Risk 时据合同做相关预留和 deny，未选 Risk 的路径不以 64 为前置。

在没有其他真实仓位、并经 provider 事实证明账户真实保证金为 0 的示例中，即使 A 虚拟多5、B 虚拟空5 完全抵消，A 和 B 仍分别计提各自 5 手虚拟仓的策略保证金占用。若 A 的虚拟平仓转换只确认 2/5，A 剩虚拟多3，须为剩余3手保留对应策略虚拟保证金；B 虚拟空5未变、仍按其5手计提；账户真实空2的实际保证金以 provider 事实为准，不能从策略账本伪造。A 未决3手须保留适用的未决/最坏占用，直到可信证据允许转换或释放；不得把同一仓位的未决占用和已计提持仓保证金作为两个互不相关费用重复扣减。

策略虚拟保证金、账户真实保证金和账户在途最坏资金是不同作用域、并行约束；不得直接相加并重复扣同一策略预算。母单、子单、内部转移及转换产生的同一风险单位应按冻结合同在预留、在途、已成交及释放之间互斥转换，不因状态复制重复占用；不同 scope 的视图各自保留来源与用途。策略权益与可用资金的核心公式已由 D63-44 确认；实际账户保证金如何分摊成其他策略成本、具体产品占用/估值和同策略双边或组合保证金算法仍待工程合同冻结，不因跨策略互不抵消而擅自推导。这里不授权新增收费或自动强平。

冻结可复核的计算规则及可信输入的来源、作用域、时点与版本，包括合约乘数、费率、价格基准、币种；不得用无依据的缺省值。输入缺失、过期、币种不可比或来源不可证明时，该策略占用及依赖它的可用资金结果标 UNKNOWN/不可用，不写成 0，也不拿账户余额顶替。测试同时覆盖空账户双侧各5、A 平2后3/5、已确认与 UNKNOWN、预留与转换竞争和重放、缺参数/过期/币种不一致，以及 Risk 选用/未选两条路径；该决定不取代 D65-35 的真实手续费由 A 承担。

**D63-46 已确认：允许显式预算超配，账户资金约束另查。** 账户初始权益100万、A/B预算各60万可接受，不拒绝该预算配置、不自动缩成50万，不改变provider/模拟账户真实资金。各策略getter仍按自己的预算计算，不能要求策略权益合计等于账户；同币种可比切点下单列初始预算调节项100−120=−20万，仅解释配置差额，不进入资金池或记作实际借款、亏损、外部残差成交。显式预算调整与真实入出金各有事件/版本，调节项不能掩盖未知交易事实。

实际资金约束按职责保留：BackBroker检查模拟账户购买力，实盘provider/柜台决定实际可承接能力；选择Risk且R-08 deny时另作账户原子预留及适用策略预算检查，不强制安装Risk、不把资金政策迁入Gateway；D64-10 已确认 R-08 缺省 off，仍可显式配置 warn/deny，策略虚拟保证金记账和 BackBroker 账户购买力检查不因 off 停止。账户100万、两笔各需新增资金60万，即使各策略预算满足，也不能在有账户资金预检的路径同时认定足额；验收第一笔预留后40万、第二笔不足、重复/恢复不虚增资金。配置字段、比例基准及预算调整流程仍按共享合同冻结。

**策略资金核心合同及回测对照（D63-44，用户已决定；产品细节待冻结）。** 策略权益 `value = 初始预算 + 预算调整 + 已实现盈亏 + 浮动盈亏 − 费用`；策略可用资金 `cash = 权益 − 虚拟保证金 − 尚未被前项覆盖的在途占用`。浮盈和浮亏均进入权益与可用资金，虚拟保证金减少可用资金但不减少权益；结果为负时原样返回。预算须依 D63-41 明确提供，缺失或必要事实/估值不可证明时不可用，不以账户值或零替代。

公式中的已实现盈亏须是未扣费用的 gross 值，或具备可审计的净费分解，确保费用只减一次；估计费用、已确认费用、迟到修订及预留转实际要以身份/版本幂等转换，已被虚拟保证金覆盖的风险单位不在在途占用再扣。账户真实保证金是并行的 provider 事实，Risk 仅显式选用时实施相应政策；资金不足是否阻断依所选政策，负值显示不自动授权强平、开仓或启用 Risk。现货与期货的价值、保证金和资金占用不同，须由 63/70 冻结适用产品的资金占用、头寸成本与估值合同；不能只因股票保证金为零就把全部权益当成可用现金。币种、时点、价格、乘数、可靠来源、调整和费用估计/修订仍需明确；这些不是重问核心公式。

用户要求 BackBroker 回测也支持 `get_strategy_cash()`、`get_strategy_value()`、`get_strategy_position()`，与实盘共享上述语义；具体接口接线和实现由 63/70 按共享合同分工。65.01 提前规划并用替身/真实框架原型验证接口和来源，65.07 在相同预算、事件、标记价格、费率、映射及切点下与 63/70 的 BackBroker 受控事件对照：getter、内部转移、部分转换、迟到费用修订和占用释放逐步一致。BackBroker 本地模拟不依赖 Gateway、Risk 或 Execution 服务；接口和公式统一不证明完整回测轧差或实盘能力已实现，不在此扩大迭代 70 内部撮合范围。单策略回测按 D63-45 可复用显式账户初资，多策略仍逐个分配；不把库默认现金当作已分配预算。

数值验收：初始预算 100000、预算调整 0、gross 已实现盈亏 2000、浮动盈亏 3000、已知费用 100、虚拟保证金 20000、尚未覆盖的在途占用 10000，则 `value = 104900`、`cash = 74900`。另测浮亏导致现金负值原样显示、相同费用事件重复与更正、预留释放及转真实费用、保证金与在途重叠不重复扣、未知估值/费用不可用、现货已持有资产的占用，以及同一受控序列在两种 Broker 的逐状态一致性。

**手算验收向量**（仅测试假设）：原账户无真实仓，A 虚拟多 5、B 虚拟空 5，双方初始记账价均为 100，合约乘数 1、没有其他盈亏；A 平 5 后真实卖开 5，实际逐手成交价均 99，每手真实手续费为 f，且已确认实际费用为 5f。A 的已实现净盈亏为 `5 × (99 − 100) − 5f = −5 − 5f`；B 保留虚拟空 5、开仓成本仍为 100，以 99 标记的浮盈为 `5 × (100 − 99) = 5`；两策略合计 `−5f`，等于真实新增空 5 按成交价 99 标记时的净收益（0 减已知费用 5f）。真实滑点不再另扣，亦不增加虚拟 CLOSE 费用。

**部分成交与未决**：同一假设下仅确认真实 SELL OPEN 2/5 于 99、实际费用已确认每手 f 时，A 只平 2、剩虚拟多 3；B 保持虚拟空 5、成本 100；账户真实新增空 2；A 对已平 2 的已实现净盈亏为 `−2 − 2f`，只计已确认费用 `2f`，未完成的 3 不预平、不确认为已发生费用；可按适用规则保留预估费用占用，并与已确认费用分开。按 99 标记时，A 剩余多 3 浮亏 `−3`，B 空 5 浮盈 `5`；加上 A 已实现净亏 `−2 − 2f`，策略合计 `−2f`，对应账户新增真实空 2 在 99 的浮动收益为 0、扣已确认费用 `2f`。若剩余 3 为 UNKNOWN，保留其最坏占用并按原身份查询；已确认部分与未决部分隔离，迟到成交和费用修订不得重复计量。费用仍未知时净盈亏中的费用部分未知，不显示 `2f` 或零为已确认值。

跨平台规则：

- 相对路径一律相对于该 `config.yaml` 所在目录，用 `pathlib` 解析；不展开 `~` 或环境变量，不依赖当前工作目录。
- 传输用 loopback TCP 上的 CURVE ZMQ，不用 `ipc://`（Windows 上没有同样语义）。
- SQLite 只放本地磁盘，网络盘上的文件锁不可靠。
- 私钥文件权限：POSIX 检查 0600；Windows 的 ACL 检查方式未定（UNKNOWN，65.01 与 63 一并决定）；不能检查时拒绝启动，而不是忽略。
- 时间：调度用交易所时区（CTP 为 Asia/Shanghai）和 provider 时段表，不用本机时区；时钟质量沿用 D62-21/27/28。
- 未知键、类型错误、策略规则超出账户允许、执行路由写在 `execution_config` 等 BT 选择键下，都在启动时以有限码拒绝。已选类的包缺失、未注册、不兼容、非法参数及不支持的组合均拒绝，不能悄然切换方案或直通；变更在途绑定必须走明确迁移。

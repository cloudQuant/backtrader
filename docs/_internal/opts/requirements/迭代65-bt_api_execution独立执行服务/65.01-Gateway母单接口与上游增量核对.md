## 2. 当前 Gateway 母单服务操作

当前 SDK `gateway_parent_service.py` 的 exact-key wire 参数如下；`GatewayParentAuthority` 是本地 owner，非独立 Execution 服务。登记 `spec` 目前要求包含账户、策略、parent、注册操作、execution domain、完整合约、数量和单位、方向、开平、限价、创建及允许交易日、到期时间、grant revision、目标持仓、方案摘要/版本和 time-in-force。当前支持 DAY/GTD；平仓要求目标仓，OPEN 不得带目标仓；交易日有序唯一，DAY 只允许一天。后续新增或放宽必须通过新合同，不按该字段集合声称已具备跨日/内转。

| 操作及当前请求字段 | 当前本地行为与权限边界 | 65 所需的未交付项 |
| --- | --- | --- |
| `direct.parent.register`：`{spec}` | 经 Registry admission、grant、范围和主体核验后调用 owner；事务中持久记录母单及注册操作。相同身份与内容的重放返回当前母单观察，异内容冲突；不发送场所订单。 | SDK 原请求到母单的耐久映射与未知 parent 时查回、母单受理前条件及迟到请求 fence；现有登记并未证明与 Runtime 停止屏障原子竞争。 |
| `direct.parent.query`：账户、策略、`parent_ref`、`registration_operation_id` | 返回本地当前观察、原 spec/digest、主体与版本；EXPIRED 当前是按读取时钟得到的投影，不是不可逆到期锁存。 | 跨日原期限、可信时钟、不可逆到期及跨 owner 状态/水位；当前观察不能代替原操作历史。 |
| `direct.parent.operation`：query 字段加 `operation_id` | 返回原操作历史结果；SDK 服务路径先查母单并校验 grant，authority 自身的 operation 查询直接查操作表。 | 母单未知或请求未到的可恢复查询及可信迟到 fence；服务端缺行或 UNKNOWN 不证明原注册不会随后到达。 |
| `direct.parent.cancel`：query 字段加 `cancel_operation_id`、`expected_version` | 同 ID 与同摘要先返回保存的原操作结果；新操作须符合当前 ACTIVE/version，事务固定目标集并写 `CANCEL_REQUESTED`。目标包含子单及原请求/预约/摘要、必要原生身份和派生取消身份。 | 受理不等于子单撤成；Execution 离线时策略直接取消的 grant/客户端/独立驱动、目标级重复撤单与 UNKNOWN 栅栏、迟到成交及水位恢复仍须交付。 |

当前 parent grant 绑定完整 WireIdentity、账户、策略、domain、角色、revision、品种集合及操作集合；登记只允许 execution 身份，不能由策略冒充。Registry admission、run、主体、当前 grant 和范围仍须逐次核验。源码允许特定 strategy grant 的 query/cancel/operation 类型，但本次所核 CTP 配置只看到为 execution delegate 装配 parent grant；现有 SDK parent client 还把响应中的 execution principal/actor 与自身 route identity 严格匹配。因此不能把类型定义解释为策略离线直撤已接通。受权新主体的接任、审计和旧身份恢复须明确合同，不能仅放宽校验。

当前服务在进入 owner 前可返回入参/admission 的 `REQUEST_REJECTED`；进入 owner 后异常收敛为 `UNKNOWN`，SDK 客户端只接受来源和内容满足合同的 `OBSERVED`，其他结果或异常通常映射为 `None`。本地 authority 的 `NOT_FOUND`、`REQUEST_CONFLICT`、`VERSION_CONFLICT` 等不能直接当成已由 SDK 可靠保存的确定拒绝。本次 handler 入参/admission 拒绝可以作为本次请求被拒的局部事实；只有进一步证明原操作在该 owner 未发生且不会因迟到请求发生副作用，才能按最终合同声称原操作已确定拒绝或安全释放，其他 owner 的占用独立核清。

## 3. 委托子单与转入事项

Base 的 `GatewayDelegatedCommand` 包含账户、策略、domain、actor、run、请求键、payload digest、合约、grant revision 与成对 parent/child 身份；字段自身不授予权限。Gateway 委托层核验可信 admission、当前 grant、品种、载荷键及摘要，并在 reserve/dispatch 时按 owner 合同重验母单。当前 parent 检查覆盖 ACTIVE、期限/交易日、domain、合约、主体/revision、方向、单位、限价/开平及已完成与未决数量，但不能据此宣称 INV65-03 的所有计划占用、故障竞态与 UNKNOWN 场景已完整验收。

具体委托服务线操作是 `direct.delegated_reserve`（`command`、`payload`、`ttl_seconds`）和 `direct.delegated_dispatch`（`command`、`payload`、`reservation_id`、`expected_version`，适用配置下可带 `market_ref`）；grant 检查使用的逻辑权限分别是 `direct.reserve`/`direct.dispatch`。reserve 或已有非 RESERVED 记录的 `OBSERVED` 可包含原账户/策略、actor、请求键、预约、摘要、状态、版本及 owner/预约 generation；正常派发入队返回 `QUEUED`/`ALREADY_QUEUED` 和请求键/预约 ID，入队不证明实际下场。具体响应仍需客户端按来源及活跃注册验证。计划 §1.6 第 6 项写明以 `child_id` 作为 `request_key` 并在经 Risk 转发时沿用；当前所核 Base DTO 只要求 parent/child 成对，委托服务核对 payload 的 idempotency key 等于 request key，Execution 本地分别验证 child ID 与 request key，尚未看到在这些边界强制二者相等。该计划约束因此仍是 GAP，后续须验证同 child 不同 key、同 key 不同 child、重放及并发，不把字段同时存在当成已证明相等。

[子单身份离线原型](../../../../../tests/unit/test_iter65_delegated_child_identity_prototype.py)使用真实本地 Gateway journal、母单 authority 和合成身份/grant：相等身份首次预约成功；`child_id != request_key` 的首次预约在所测路径同样成功；同 child 换键被拒且无新记录，同键换 child 报冲突且保留原记录；两笔不同 child 占满两单位母单后第三笔被拒。重新打开同一临时 journal 后原记录可重放。主代理在禁网络、仅临时目录可写的沙箱独立复跑 **3 passed、1 warning**（禁插件后的 pytest 配置警告）。这是串行本地预约和重开证据，不证明并发、dispatch、崩溃恢复、真实授权、Risk 或账户；重开使用 `minimum_revision=0`，不证明防回滚。当前不相等的实际接受与计划相等约束仍是需后续实现/验收的差距，不能由这三项通过认定计划满足。

本次隔离快照的 CTP 装配选择 `same_day_only`，完成内转回调固定返回零，未装配跨日 rollover、目标仓或 Risk 子单检查。因此跨日母单、平仓目标及选 Risk 的相关代发不能据此宣称已接通。65.03a 仍须交付：按故障原因和版本恢复母单；跨日和原平今转平昨的可信映射；内部转移、虚拟转换及 STOP_NEW 例外的权限、数量竞争和双边账本；目标仓及选 Risk 的子单检查；以及转入的对账与急停补验。内部轧差不增加策略或逐单的参与同意。

65.01 现有历史原型已暴露需保留的反例：取消先到、Gateway 未见登记后原登记仍可能迟到；策略与 Execution 以不同操作 ID 向同一原子单撤销可出现两次合成发送；特定策略注册组合未获得可用 parent.cancel；STOP_NEW/FREEZE/DRAIN 下母单登记与子单预约的行为不同。这些是指定本地组件和合成身份、传输或回调的旧证据，详见基线记录 §6、§7、§25；不能外推所有并发场景或称真实账户行为通过。目标实现需针对原 ID、同目标唯一未决撤单、屏障与登记/派发竞争、丢回复和恢复分别验证。

## 4. dev 的 Risk v2 增量与 65 边界

本地 SDK dev 指向的 Base v2 定义 Risk 服务能力与 Gateway 首创预约回执数据合同；回执携带的发送方采样剩余时长不是接收方截止时间或新鲜度证明。Gateway dev 的 `reserve_first_delegated` 在受信本机 guard/fence 和 SQLite 事务下识别首次插入；该对象不是可转移的、已封印的一次性 Risk 授权，也不单独绑定 Risk registration/nonce。Risk dev 的 v2 本地账本包含能力摘要及消费/claim 相关原子校验；实际 Registry、Gateway 首创回执与 Risk v2 handler 尚未接线；v1 写入口仍可用，全局防降级未完成。SDK 的相应本地 Registry admission 是默认关闭的受限路径，目前只面向指定策略客户端身份和 scope，不能推断适用于 Execution 代理。

因此，未选 Risk 的 65 基础路径不新增 Risk 依赖；选 Risk 的母/子单需与 64 联合冻结可信注册、scope、原请求及授权版本、能力消费、Gateway 首创证明、来源/epoch 和撤权边界，并完成真实组件联调。64 当前仍 IN_PROGRESS/NO-GO，选 Risk 的母子服务写入口尚未就绪；账户和交易日来源、自成交事实切点、跨代未发送证明及相关撤权/派发边界仍有 GAP；合成 DTO 或测试通过不能证明真实账户可用。此处只读了提交及公开源码，未运行行为验证。

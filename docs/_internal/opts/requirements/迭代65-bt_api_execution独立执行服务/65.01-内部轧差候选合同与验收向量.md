# 65.01 内部轧差候选合同与验收向量

状态：**审阅候选，未冻结、未实现、未验收**。本稿将已确认的反向轧差要求转为可审阅的边界、候选操作及验收向量；字段、状态机、兼容分组、价格网格和数量取整均须由 63/65 及适用 owner 定稿，不将技术候选当作用户已决定的经济规则。选 Risk 时还须对齐 64；未选 Risk 不以其为前置。

## 1. 已决定的边界

- 同向母单不合并，只有反向意图可内部匹配。余量按各自原母单和算法独立下场；每个真实场所子单只归属于唯一母单和策略，不把内转写成共同场所成交。
- Gateway 核验账户允许范围、Execution 服务主体权限和双方母单归属；**不要求参与策略或每张订单再对轧差同意或授权**。账户策略、主体授权和母单归属是既有范围核验，不是新增同意开关。
- 仅尚未下场且未被子单预留、其他计划、转移或 UNKNOWN 等事项占用的可用量参与。不为轧差主动撤场内订单；普通撤单在权威终态、成交水位对齐且占用可证明释放后，若母单仍有效，可在重新核验账户/服务权限、原母单归属、价格、数量、原期限和所选 Risk 后申请匹配。
- 显式选择立即或有限窗口；立即只考虑当时已有合格量，不等待未来订单。窗口时长显式、有限，绑定原窗口及母单期限，重启不能延长。
- 显式选择受理顺序或按可用量比例匹配，并严格遵循所选方法；兼容限制使方法优先级和更大轧差量冲突时，不以最大化总量覆盖优先级。具体双边扫描、兼容分组与比例取整仍待冻结。
- 独立选择中间价或最新成交价类；报价、来源和时效需有效，价格及舍入后结果均不得越过双方限价；缺失、过期、无合法价格或未注册类不自动切换价格类或方案。内部转移默认额外费用为零，真实成交及转换费用独立核算。
- 策略虚拟多空、转换、成本及可平必须按可信权威事实建立；external 不可成为对手、母单或可借用容量。同账户同合约的可比切点满足 `Σ策略有符号理论净仓 + external = provider有符号净仓`，但净额相等不证明 gross、今昨、可平或保证金。

## 2. 数量、身份与候选操作

对同一权威版本的每个母单，候选采用 `Q = F + C + T + P + A`：原量 Q，已权威完成 F，已预留/派发或 UNKNOWN 子单最坏余量 C，内转在途 T，权威窗口计划占用 P（如最终采用）及账面未占用 A。桶互斥、非负且单位相同；A 不单独授权新动作。F 中真实成交、已提交内转与权威确认的转换进度按互斥来源计量，关联真实成交和转换进度不得重复累计同一策略处理量；转换归集时点尚待冻结。仅在有效的同一窗口持有 P 时，可按冻结合同将该窗口份额原子转换为内转 T；不能把 P 同时用于另一个窗口或子单。

方案类只生成提案，不能直接改持仓、持凭据或代表 Gateway 权威。操作合同候选如下，名称和拆分不是既有 API：

| 阶段 | 持久身份/输入候选 | 权威边界及失败语义 |
| --- | --- | --- |
| 固定提案 | account、交易日/会话切点、窗口或立即触发 ID、类/版本/参数、输入水位、两侧各自 parent/strategy、数量、规则版本和 `transfer_id` | 为每笔配对绑定稳定内容摘要；可比切点、权威受理顺序及候选组的来源须证明。提案快照不是数量或授权凭证。 |
| 预留或单步提交 | 原 ID 和摘要、两侧母单版本及各自可用量、权限及撤销版本、独立阻断、双方限价、价格与来源、交易日及适用今昨/持仓/占用证据 | Gateway 在同一权威事务或等价可证明栅栏内重验，并与子单 reserve、取消和窗口占用竞争。跨外部行情/账户源须证明来源与水位可比，且用受信租约、覆盖核验至最终提交的有效栅栏、条件写入或可证明串行化防止并发；仅持有版本号不构成该证明，缺证不得提交，也不能假装与 SQLite 事务原子。 |
| 双边记账 | 同一 `transfer_id`、双方独立分录/进度、相同数量及各自来源、政策与账本修订 | 每笔双边原子提交，分别推进两母单，不能只落一侧或生成场所 TradeID；原身份重复同摘要返回既有结果，异摘要冲突。 |
| 消费与恢复 | 事件来源、每侧策略/母单、转移 ID、版本、游标和持久投影状态 | 投影持久后依合同 ACK；断连、丢回复或未知提交状态按原 ID 查询，不能另造转移、释放 T 或重复下场；未能证明原账本和构建时冻结。 |

Execution 和 Gateway（及选用时的 Risk）各自持久化，不能假定跨服务事务原子。若使用准备/提交两阶段，准备时须确实在 Gateway 权威桶占住双方 T，提交把 T 转为 F；若使用单事务，双方数量及事件一起确定。授权撤销、取消、期限到达、日切及子单占用与提交必须按可证明的序列或版本裁决；提交前条件不再满足时不得提交双边记账；已有准备操作须按同一 ID、可信结果取消并释放，不能假设没有副作用；结果 UNKNOWN 不当作拒绝或释放。

当前 Gateway 策略账本可重放已证明归属的真实成交，现有单策略 financial snapshot、同库事务及 CTP 今昨结构检查可作为局部参考，但均不证明上述双边内转、实际账户可平、来源一致切点或多服务恢复。现有 `transfer_completed` 回调也不等于内转实现。

## 3. 匹配、报价和转换的定稿事项

受理顺序需要持久、可信、可跨双方比较的账户范围顺序，不能拿不同母单的局部 version 相互比较；账户事务序号是候选，当前是否可用须验证。比例法以各自符合条件的可用量为权重，整手候选为向下取整，再按最大余数、同余数按权威受理顺序；**最大余数仅为技术候选**，不是用户已选的取整政策。兼容图并非全连接时，如何分组、配对和处理不足一手需显式、确定、可重放，并保持所选方法优先；不能用一个最大流求解器先改换对手，再称结果符合顺序或比例。

中间价/最新成交价按所选类、来源、可信时钟、新鲜度和策略双方限价验证；网格/舍入规则定稿后，对舍入前后分别验价。提交边界若报价版本或权限已无法证明，应重新验证；能确定尚未提交且条件不成立时不执行内转，已可能提交则保持 UNKNOWN 并保留占用，不以旧报价或另一类补足。确定无有效价格且未提交时，按各自仍有效的原计划处理余量，不额外拒绝整个订单或偷换直通路径。

持仓归属转移涉及真实持仓、合约、持仓方向、今昨、冻结与占用时，须在同一可信切点核验来源、完整性和可用量；净仓恒等式、策略理论持仓或一条 CTP 结构化行不能单独证明实际可平。外部手工成交导致 A 理论多 5、external −5、账户净仓 0，且经同一可信切点核验该方向真实可平量为 0 时，A 平多 5 按已决定规则拒绝，A 理论仓不变，不自动变成 SELL OPEN。

普通 A/B 虚拟平仓若满足专门转换授权和预配条件且需要真实 OPEN，则 STOP_NEW 例外仅适用于预先配置的账户、策略、合约和数量范围，并在提交前重验；普通 OPEN 不因此放行，FREEZE/DRAIN 和其他原因仍适用。选 Risk 时该真实 OPEN 按适用 Risk 合同检查。除已决定的默认零内部额外费用外，真实 OPEN 费用、盈亏、对手方原成本和策略保证金按 D65-35/36 及共同合同核验，不把真实费用冒充内部零费用。

## 4. 对照向量（应在相关实现后自动化）

| 场景 | 必要观察 |
| --- | --- |
| A 买 7、B 卖 5，双方尚未下场且可用；假设适用的开平、真实仓位、映射、今昨/占用、价格与授权来源均可证明，且冻结的经济合同允许 | 内转 5；A 余 2 按 A 原母单独立处理；B 完成 5，双方记录各自虚拟归属，内转时点场所成交为零。A 后续真实成交 2 才有场所成交 2；不伪造共同子单。 |
| A 先全部下场，B 反向到达 | 已预约未派发、派发中及在场量均不入池，不为轧差撤单。撤单受理未终态、UNKNOWN、成交未对齐或占用未证明释放时不得入池；普通撤余终态、水位与释放均可证明且母单仍有效时，可重新核验入池。 |
| A 买 3 先受理、B 买 7 后受理、C 卖 5，均兼容 | 顺序法分给 A3/B2，A 余 0、B 余 5；按候选最大余数比例法分给 A2/B3，A 余 1、B 余 4；余量分别按原母单处理，比例取整尚未定稿。 |
| A、B 买 1；C、D 卖 1；兼容边仅 A-C、A-D、B-C | 若所冻结双方扫描先选 A-C，结果只匹配 1；不得为凑 2 而重排成 A-D 与 B-C。该例条件依赖未来冻结的扫描规则，不预定比例分组。 |
| 可用价位不满足双方限价或 tick 网格 | 不创建内转；不换定价类、不把转移冒充真实成交，仍按有效原计划处理。 |
| 双边转移与子单 reserve、取消、授权撤销、行情/账户源更新并发 | 对每个母单的同一数量，转移、子单及其他动作至多一个有效占用；合法内转须同时占住双方各自等量，取消与撤权按权威顺序裁决。旧版本失败后重新读取，不能靠快照推断释放。 |
| 转移提交前崩溃 / 提交后丢回复 / 多笔中部分 UNKNOWN | 按原 ID 查询、双边原子一致；真实成交与关联转换进度重复、乱序时同一策略处理量只计一次，未知量继续占用，不能补单或随机换对手。 |
| 空账户真实 gross 多空均为零、无在途占用，A 虚拟多 5、B 虚拟空 5 且映射可信；A 平 5 须 SELL OPEN 5 | STOP_NEW 只有符合预配范围且提交前重验的转换可例外；缺配置、超账户/策略/合约/数量或配置撤销均拒，普通 OPEN、FREEZE/DRAIN 及其他独立阻断不放行、不被连带解除。只成交 2/5 时仅推进 2、余量按状态占用；B 原成本不变，真实 OPEN 费用按 D65-35 归 A，选 Risk 检查实际 OPEN。 |
| 未启用 Risk / 已选 Risk 失效 | 前者不加载 Risk；后者按已决定的故障关闭合同处理，不能绕行。 |
| 内部事件投影到原 `BtApiBroker` | 验证双方标准 Order/Position/Trade、费用、通知、去重和持久重启，保留独立内部来源；当前尚无合规入口证据，保持 GAP。 |

价格、权限、来源和版本不足时不得伪称真实成交、真实可平或授权。原 Broker 源码零修改与复用要求继续有效；本稿不是另建 Broker 的授权，也不证明本迭代开发或验收完成。

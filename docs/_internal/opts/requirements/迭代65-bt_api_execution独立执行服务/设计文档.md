## 2. 组件与候选接口

```text
BT Order -> SDK 持久请求身份 -> Execution 持久母单意图
     -> [Risk 母单风控，仅选择时] -> Gateway 登记母单并持有权威数量边界
     Execution: 方案 -> [反向轧差] -> 各母单剩余 -> [算法或 PASS] -> 各自子单
     -> [Risk 子单风控，仅选择时] -> Gateway 唯一订单 owner -> provider
     Gateway 事实/归属 -> Execution 和 SDK 投影 -> BT；Monitor 只读
```

Execution 不持 provider 会话、凭据、原生库或 risk 包；认证及身份由可信服务组合和 Gateway grant 提供，线上声称的策略 ID 不等于授权。Gateway 对账户、交易日、合约、母单范围、grant、租约、原生身份、急停及流控负责；未选择 Risk 时仍有这些基础检查，但没有 Risk 的单笔业务限制、价格带、自成交等政策。已选择 Risk 的路由故障 fail-closed，Gateway 可接受未附风控批准的订单这一已决定事实不变，因此需要独立控制服务配置和可达路径，不能声称 Gateway 强制所有调用者经 Risk。

下列均为 65.01 应冻结的**候选**，中立线协议/版本放 Base，SDK 持服务客户端及 BT 投影，Execution 包持方案和本地日志，Gateway/Risk 实现分别归 63/64：

```python
class ExecutionSchemeV1(Protocol):
    def plan(self, parents: tuple[ParentView, ...], ctx: PlanContext) -> PlanProposal: ...
    def on_event(self, state: SchemeState, event: Evidence) -> SchemeDecision: ...

class MatchingScheduleV1(Protocol):
    def decide(self, window: MatchingWindowView, ctx: ScheduleContext) -> MatchNow | Wait | Stop: ...

class NettingPolicyV1(Protocol):
    def propose(self, parents: tuple[ParentView, ...], ctx: PlanContext) -> NettingProposal: ...

class TransferPricingPolicyV1(Protocol):
    def price(self, quote: MarketView, limits: ParentLimits, ctx: PricingContext) -> PriceProposal | PriceUnavailable: ...

class AlgorithmV1(Protocol):
    def next(self, residual: ResidualView, ctx: ScheduleContext) -> ChildProposal | Wait | Done: ...
```

可继承的基类只提供参数校验、版本声明和不可变结果；业务方法不默认执行网络、写账本或自行派发。`PlanContext` 提供认证后的只读输入、单调时间、可用交易日历/行情证据、输入游标与确定性随机种子（如需）；结果包含原母单引用、数量、价格约束、反向匹配关系与所需证据，宿主重新校验，不信插件的权限声明。宿主提供 `GatewayPort`（`parent.authorize`/`parent.accept`/`parent.status`、`direct.reserve`/`direct.dispatch`、取消/只读事实流，均为待冻结语义）、可选 `RiskPort`（parent/order reserve、dispatch、release、status）、`JournalPort`（事务、outbox、fence）、`ClockPort`、`MarketViewPort`、`CalendarPort`。反向跨策略转移时单独扩充各参与母单授权及转移提交端口，不以单策略字段冒充已有能力。

记录可验证构建/发行物摘要、依赖版本、状态 schema、事件水位和定时器重建规则；同版本不同构建、依赖不符或未验证迁移均冻结。按账户/交易日/原始事实及归属/转移修订身份对每策略独立去重，投影持久提交后推进各自 checkpoint；冻结修订因果、保留期和缺口恢复，测试单侧崩溃、晚到费用、跨日重放。

算法无状态或显式可序列化状态；宿主负责唯一写者和外部交互。异常、耗时超限、返回无效计划均暂停相关母单并以有限码报告，不能绕过所选策略。外部插件通过运维维护的**受控注册表**按标识、包版本、协议版本、schema 和能力选择，只加载所选类，不 `eval` 配置或任意导入路径。持久化类 ID、版本、规范参数和摘要、算法状态、输入水位、时钟/报价版本以及每次计划；恢复时原版本缺失、状态迁移未经验证、输入缺口或 grant 不符则冻结。升级、回滚和并存版本不得改变在途母单绑定。

**首期母单类型与拒绝边界（D65-07 / Q36，用户已决定）。** Execution 首期只接受限价母单。明确配置路由到 Execution 的规则若静态可知必然包含不支持的市价或其他类型，在配置加载/校验时以有限错误拒绝该矛盾配置；若规则按运行请求动态匹配，实际命中且类型不支持时在母单受理前明确拒绝该请求。不得静默绕过 Execution、回退直通或自动改成限价；不存在把所有市价请求都默认当作已命中执行路由的规则。Execution 未选择或请求未命中执行路由时保持原有路径及其既有规则；本决定不证明 direct、Gateway 或 provider 的市价能力可用或已验收。

已命中的限价请求须具有合法、有限的限价并满足价格网格、数量和其他既有基础合同；普通子单限价不越母单约束。D65-27/28 的虚拟平仓转换仍适用，并分别保留策略层和账户层真实开平及转换授权，不能以限价范围混淆开平或豁免转换准入。Risk 仍是可选组件；本限价范围是用户的产品选择，不以强制 Risk 或保护价功能归属作为理由。首期算法按 D65-08 已确定为 PASS、SLICE、TWAP；具体参数和调度细节待冻结。

拒绝语义须在入口形成可追溯的有限错误状态和稳定幂等关联，配置错误与动态请求错误分别报告；拒绝应在创建活动母单、子单及新增数量/资金占用前原子发生，不向 Gateway/provider 派发。可保留不携带写入副作用的审计记录，不能留下活动信封或未释放的新预留。65.01 冻结错误码、SDK/BT 错误投影及并发/崩溃边界；若尚不能证明拒绝发生在副作用之前，则按实际已到达的阶段查询和恢复，不能把不明结果伪装成确定拒绝。

测试矩阵：显式 Execution 路由的市价及各声明不支持类型、静态矛盾规则、动态宽泛匹配命中、市价不能自动转限价；合法限价、非有限/缺价/越网格/非法数量；同 ID 重放、并发与失败注入下无活动母子单/新增占用/发送。另测 Execution 未选与规则未命中只按原有路径处理，分别记录其环境和结果，不将替身或这组测试宣称为 Gateway/direct 市价验收。

**首期执行算法（D65-08 / Q37，用户已决定）。** 首期内置 PASS、SLICE、TWAP，并由配置选类、允许继承扩展。PASS 将母单按约定整笔处理、不拆单，但仍经过 Execution 的母单、信封、授权、持久化和 UNKNOWN 合同；SLICE 按最大子单量顺序拆单；TWAP 按时间分批。反向轧差是独立开关，既不强制启用也不强制使用拆单或 TWAP。三种算法均只接收 D65-07 允许的限价母单并保留相应价格与风险约束；不以首期算法名单推断任一渠道已验收。冰山、盯价和 POV 不属于首期内置交付。

各方案参数、时间片划分、撤单与未成余量、错过时间片与恢复的具体行为属于计划 §4.1 的技术候选，需合同冻结和故障验证，不是用户逐项确认。验收分别覆盖 PASS 不拆且不绕过、SLICE 按最大量顺序、TWAP 按时间分批、三者限价/数量/授权、反向轧差独立开关及继承配置、超时/撤单与 UNKNOWN 下不重复派发。

## 4. 母单、数量和身份

候选身份：`account_scope + strategy_id + parent_ref` 唯一标识原策略母单并绑定初始认证主体；初始交易日仅为不可变元数据，不随日切更换母单身份；`plan_id` 标识一次不可变的单母单计划或反向匹配批次及版本；`child_id` 为母单内持久序号派生且跨日不可复用的子单请求键；每个子单另保留其实际交易日、会话和场所身份；`transfer_id` 标识独立内部转移；每个真实子单只属于一个发起母单/策略，反向匹配批次不是共同场所子单。所有 ID 绑定认证主体、作用域和规范请求摘要，同键同内容返回已知结果，同键异内容冲突拒绝。持久记录关联这些 ID、版本和因果事件，不能用 execution 或 risk principal 替代所属策略；凭线上 `on_behalf_of` 不能授权。

反向匹配计划须对每个母单在 Gateway 独立验证账户、策略授权、交易日、合约、方向、开平、限价与额度，双方或多方受权及内部转移双边原子提交由 63 冻结；不同账户不可轧差。按 D65-34 显式选择匹配方法；兼容配对、具体取整及参与方撤销仍待冻结，不能引入共享场所子单。实际子单由唯一发起母单和策略授权；虚拟转换即使影响多个映射，也须绑定 conversion_id、原始原因、受影响映射与唯一发起母单/策略，Gateway 依据自身权威账本核验。撤销只针对自己母单/子单；并发匹配、转移、迟到成交及 UNKNOWN 的数量占用分别维护。

对每个母单，在同一权威事务/锁内验证：

```text

+ 活动、在途、UNKNOWN 子单对该母单的最坏剩余占用
```

账户侧转换可能是 OPEN，关联的策略 CLOSE 不得重复占用同一母单；按策略层处理量守恒，账户真实成交另核对。每一策略母单数量在同一时点恰属于一个桶：归集成交时从该母单自己的子单剩余占用转移，不增加总占用；内部转移提交从待转移占用转为已确认转移；计划占用转为子单占用需原子转换，禁止两头重复释放或重复申请。实际子单仅占用其唯一母单；撤单确认只有在可信终态与成交完整对齐后释放未成部分，撤单、迟到成交和重放竞争必须串行。UNKNOWN 按最坏剩余占用，不能靠超时释放。若 Gateway 与 Execution 各记副本，前者的信封/账本是权威，后者不能凭本地锁代替跨进程原子栅栏；并发与恢复以 63 提供的原子命令和证据为准。

**完成量与终态。** 按计划 §3.6 的技术合同分别记录原始 `venue_filled_qty`、`internal_transferred_qty`、`conversion_completed_qty` 和来源互斥的 `strategy_completed_qty`；转换的场所成交事实与对应策略转换进度不能重复累计。`strategy_remaining_qty = order_qty - strategy_completed_qty`，未完成部分仍区分在途/UNKNOWN、可继续执行及已取消/到期；剩余不等于可派发。`parent.complete` 须核清实际子单、转移、转换及所有未决占用，再根据策略完成量和停止原因定终态；无子单不能推出完成。FILLED 可由全部内部转移或内部加真实进度形成，不能因此伪造场所成交。取消冻结新子单及转移预留，已提交转移保留，未决按原身份核清；普通撤单不删除原账。

验收 A 买7/B 卖5：内转5后 B 的策略完成量5、真实成交0；A 实际成交2后策略完成7、真实成交2；各自未决清空后可完成。转换仅确认2/5时保留余3，重放不重复推进。SDK/BT 的 executed bits、通知与来源展示在65.01用真实框架原型验证，缺少表达能力时按D65-03处理；技术数量口径不是提前确认BT零修改可实现。

**策略理论持仓与 external 边界（D63-48，用户已决定）。** 内部轧差、内部转移和虚拟持仓转换只处理运行策略形成并经可信来源确认的理论持仓及其授权意图；未决请求或仅预留数量不算已形成的理论持仓。external 账本只记录外部策略/手工来源的有符号归属，不能作为 Execution 母单、反向匹配对手、内部转移/转换参与方或借用容量；即使净额相反、看似可以抵消也不可把 external 自动纳入内部匹配。配置不能覆盖这一边界，Gateway 必须按来源和权威账本独立验证，Execution 不得制造 external 差额或修改其他策略理论仓。 普通策略汇总包含已停止、离线但理论持仓尚未清零的策略，不按当前运行进程列表过滤。

用户要求的恒等式为：同一账户、同一合约，在来源可信且可比的同一切点上，`Σ 策略理论持仓（带符号净数量） + external（带符号净数量） = provider 账户持仓（带符号净数量）`。Gateway 负责事实投影及对账；实际不匹配经受权事件/状态向 Monitor 报告并告警；数据缺失或切点不可比应标 UNKNOWN/NOT_COMPARABLE，不能声称一致。净数量恒等式不证明多空 gross、今昨桶、真实可平、风险或保证金一致，这些仍分别按其合同核验。external 的负数是有符号归属账本结果，不自动等于场所新增真实空仓。已确定的 Q24 首次 external 基线及 Q25 外部订单归 external、系统正常运行不变；外部来源本身不是自动停机条件，也不由 Monitor 发送控制命令。

验收：A 策略理论多 +5，外部手工 `SELL CLOSE 5` 后 provider 账户净仓为 0，按已确认外部事实 external 净记账 −5；`+5 + (−5) = 0`，A 理论仓不因外部成交改变，external 不能参与轧差、转移、转换或成为策略可平容量。制造同切点可比的实际失配时，Gateway 记录差异并由 Monitor 告警；重放/迟到回报不重复登记，缺页或旧水位不得伪称相等。无外部差异的 A/B 策略理论多空内部转换、D65-35 费用与 D65-36 虚拟保证金仍遵守原有决定。

**D63-49（Q27 用户已决定）：外部成交造成无真实可平量时拒单。** A 理论 +5、external −5、账户 0，A 请求平多 5 时拒绝该平仓，理论仓暂不变，拒单后仍为 A +5 / external −5 / 账户 0；不自动改发 `SELL OPEN 5`，也不改 external 或其他策略的理论仓凑平。external 不能提供 D65-28 的转换参与方、映射或 STOP_NEW 例外证明。普通策略 A/B 已确认的内部虚拟转换仍按 D65-27/28 单独处理，不受此拒单规则撤销。

### 4.1 虚拟多空和平仓转换（D65-27/28）

首期必须支持虚拟多空和平仓转换，不限真实仓归属转移。Gateway 持权威策略虚拟账本、真实账户事实和抵消/真实仓映射，Execution 提议转换；账户及策略的方向、开平、今昨分开，净额相等不能证明逐方向可平、保证金或盈亏。空账户 A 虚拟多5、B 虚拟空5 无场所成交；A 平5、B 保留空时可能需实际卖开5。

候选 conversion_id 绑定策略及母单授权、原虚拟仓/映射版本、可平余量、策略 CLOSE、真实 OPEN 的方向/数量/桶、交易日、方案和规则版本、定价证据与最坏占用。Gateway 按自己的权威账本检查身份、授权、映射和数量，不能只信客户端 CLOSE 标签。STOP_NEW 下实际 OPEN 只按单独配置的转换准入规则处理，普通 OPEN 不豁免；FREEZE/DRAIN 及独立阻断不变。仅选 Risk 时还须按实际 OPEN 检查新增敞口、保证金和策略风险，不套 CLOSE 豁免；Gateway 不检查风险批准。未选 Risk 不以 64 为前置，亦不宣称已有这些可选风控。

候选状态 PREPARED → RESERVED → DISPATCHING → PARTIAL → COMPLETED，另有拒绝、撤单与 UNKNOWN，细节待三方冻结。按已证实真实成交及冻结映射推进可证明部分；未完成/未知占用保留，不提前宣告整体平仓完成；原身份查询恢复，不盲目重发。临时映射/差额账如需使用，其 owner、上限和对账须定义，不得暗转给另一策略。转换原生订单价格、其他场景的成本/费用、公平、账户实际保证金成本摊配、虚拟占用公式及来源、今昨结转、补偿和可比性待合同冻结；内部转移记账价格方法按 D65-29，此处转换费用及盈亏归属按 D65-35，策略虚拟保证金占用按 D65-36。

**虚拟平仓转换的费用和盈亏（D65-35，用户已决定；实现时序及字段为技术候选）。** 原账户 flat，A 虚拟多 5、B 虚拟空 5，A 平虚拟多引发实际 SELL OPEN 5：该真实 OPEN 的 provider 手续费归发起平仓的 A，A 按实际成交价确认相应虚拟平仓盈亏，B 保留的虚拟空仓原开仓成本不变。真实成交只属于唯一发起母单/策略，不能复制成 B 的场所成交；费用按真实 OPEN 事实归集，不能再合成或另收一笔虚拟 CLOSE 手续费。滑点已经反映在实际成交价和由此计算的盈亏中，不能再扣一次。真实成交与对应转换进度关联但不重复计入母单完成量。

每笔实际成交以可信来源身份、conversion_id、母单与策略建立唯一关联，只以已证实的增量推进 A 的虚拟平仓及真实/虚拟映射；部分成交、撤单结果未明或 UNKNOWN 的未完成数量保留相应占用，不预平 A 的剩余仓位、不重估 B 的成本。实际费用按来源身份、币种、版本和幂等键关联该成交；费用晚到、更正或重放采用追加修订且不重复扣款，费用未知明确为 UNKNOWN，不以零代替。63 的 Gateway 权威账本/映射、SDK 的 BT 非场所投影与选用 64 风控的结算须分别冻结并验证，不伪造 TradeID 或跨库原子性。

D65-29 选择的是内部转移记账价格，不决定该转换真实订单价格；真实订单仍须满足母单限价、D65-28 的专门转换准入及 Gateway 其他适用约束。策略按自身虚拟仓位计提占用并减少各自可用资金，见 D65-36；A 承担真实手续费不决定账户实际保证金如何摊作其他策略成本。内部转移费用、其他场景费用和盈亏政策、成本取值及占用公式和数据来源仍需分别冻结。

**策略虚拟保证金占用（D65-36，用户已决定；公式、来源及状态转换由工程合同冻结）。** 各策略按自身虚拟仓位分别计提策略保证金占用，减少各自策略可用资金；跨策略虚拟仓抵消不抵减各方策略占用。该占用是策略内部账本投影，不改变 provider 账户保证金或账户事实。63 的 Gateway 权威策略账本持有该投影及其身份/版本；65 提供方案和转换事实；64 仅在选用 Risk 时据合同做相关预留和 deny，未选 Risk 的路径不以 64 为前置。

在没有其他真实仓位、并经 provider 事实证明账户真实保证金为 0 的示例中，即使 A 虚拟多5、B 虚拟空5 完全抵消，A 和 B 仍分别计提各自 5 手虚拟仓的策略保证金占用。若 A 的虚拟平仓转换只确认 2/5，A 剩虚拟多3，须为剩余3手保留对应策略虚拟保证金；B 虚拟空5未变、仍按其5手计提；账户真实空2的实际保证金以 provider 事实为准，不能从策略账本伪造。A 未决3手须保留适用的未决/最坏占用，直到可信证据允许转换或释放；不得把同一仓位的未决占用和已计提持仓保证金作为两个互不相关费用重复扣减。

策略虚拟保证金、账户真实保证金和账户在途最坏资金是不同作用域、并行约束；不得直接相加并重复扣同一策略预算。母单、子单、内部转移及转换产生的同一风险单位应按冻结合同在预留、在途、已成交及释放之间互斥转换，不因状态复制重复占用；不同 scope 的视图各自保留来源与用途。策略权益与可用资金的核心公式已由 D63-44 确认；实际账户保证金如何分摊成其他策略成本、具体产品占用/估值和同策略双边或组合保证金算法仍待工程合同冻结，不因跨策略互不抵消而擅自推导。这里不授权新增收费或自动强平。

冻结可复核的计算规则及可信输入的来源、作用域、时点与版本，包括合约乘数、费率、价格基准、币种；不得用无依据的缺省值。输入缺失、过期、币种不可比或来源不可证明时，该策略占用及依赖它的可用资金结果标 UNKNOWN/不可用，不写成 0，也不拿账户余额顶替。测试同时覆盖空账户双侧各5、A 平2后3/5、已确认与 UNKNOWN、预留与转换竞争和重放、缺参数/过期/币种不一致，以及 Risk 选用/未选两条路径；该决定不取代 D65-35 的真实手续费由 A 承担。

**D63-46 已确认：允许显式预算超配，账户资金约束另查。** 账户初始权益100万、A/B预算各60万可接受，不拒绝该预算配置、不自动缩成50万，不改变provider/模拟账户真实资金。各策略getter仍按自己的预算计算，不能要求策略权益合计等于账户；同币种可比切点下单列初始预算调节项100−120=−20万，仅解释配置差额，不进入资金池或记作实际借款、亏损、外部残差成交。显式预算调整与真实入出金各有事件/版本，调节项不能掩盖未知交易事实。

实际资金约束按职责保留：BackBroker检查模拟账户购买力，实盘provider/柜台决定实际可承接能力；选择Risk且R-08 deny时另作账户原子预留及适用策略预算检查，不强制安装Risk、不把资金政策迁入Gateway；D64-10 已确认 R-08 缺省 off，仍可显式配置 warn/deny，策略虚拟保证金记账和 BackBroker 账户购买力检查不因 off 停止。账户100万、两笔各需新增资金60万，即使各策略预算满足，也不能在有账户资金预检的路径同时认定足额；验收第一笔预留后40万、第二笔不足、重复/恢复不虚增资金。配置字段、比例基准及预算调整流程仍按共享合同冻结。

**策略资金核心合同及回测对照（D63-44，用户已决定；产品细节待冻结）。** 策略权益 `value = 初始预算 + 预算调整 + 已实现盈亏 + 浮动盈亏 − 费用`；策略可用资金 `cash = 权益 − 虚拟保证金 − 尚未被前项覆盖的在途占用`。浮盈和浮亏均进入权益与可用资金，虚拟保证金减少可用资金但不减少权益；结果为负时原样返回。预算须依 D63-41 明确提供，缺失或必要事实/估值不可证明时不可用，不以账户值或零替代。

公式中的已实现盈亏须是未扣费用的 gross 值，或具备可审计的净费分解，确保费用只减一次；估计费用、已确认费用、迟到修订及预留转实际要以身份/版本幂等转换，已被虚拟保证金覆盖的风险单位不在在途占用再扣。账户真实保证金是并行的 provider 事实，Risk 仅显式选用时实施相应政策；资金不足是否阻断依所选政策，负值显示不自动授权强平、开仓或启用 Risk。现货与期货的价值、保证金和资金占用不同，须由 63/70 冻结适用产品的资金占用、头寸成本与估值合同；不能只因股票保证金为零就把全部权益当成可用现金。币种、时点、价格、乘数、可靠来源、调整和费用估计/修订仍需明确；这些不是重问核心公式。

用户要求 BackBroker 回测也支持 `get_strategy_cash()`、`get_strategy_value()`、`get_strategy_position()`，与实盘共享上述语义；具体接口接线和实现由 63/70 按共享合同分工。65.01 提前规划并用替身/真实框架原型验证接口和来源，65.07 在相同预算、事件、标记价格、费率、映射及切点下与 63/70 的 BackBroker 受控事件对照：getter、内部转移、部分转换、迟到费用修订和占用释放逐步一致。BackBroker 本地模拟不依赖 Gateway、Risk 或 Execution 服务；接口和公式统一不证明完整回测轧差或实盘能力已实现，不在此扩大迭代 70 内部撮合范围。单策略回测按 D63-45 可复用显式账户初资，多策略仍逐个分配；不把库默认现金当作已分配预算。

### 5.1 选择 Risk 时的内部转移提交前流程（候选）

`risk.transfer.reserve/dispatch/status/release` 及 Gateway 对应转移接口均是新增**候选**，不是现有能力，须由 63/64/65 共同冻结字段、授权、错误码、快照切点、写者 fence 和恢复语义。Execution 不导入 Risk 或写其账本。该流程既不让 Gateway 调用 Risk，也不要求 Gateway 检查风控批准；Gateway 仅依自己登记的主体权限、双方委托、账本版本和转移合同实施原子记账。

1. Execution 耐久保存 `transfer_id`、规范请求摘要和方案/策略版本，冻结双方母单与策略、认证委托范围、账户/交易日、合约/方向/开平及今昨桶、数量、定价来源/时点/价格、费用、Gateway 账本一致切点版本、双方可用量和最坏占用。向 Risk `risk.transfer.reserve` 发送这些引用和证据；Risk 自己验证可代表双方的授权及可信快照新鲜度、政策、双方可平与风险暴露、账户事实及最坏占用，并在本地事务内预留、持久绑定同一 ID、摘要、版本和 fence。任何身份、价格、授权或事实不足即拒绝或 UNKNOWN，不提交转移。
2. Execution 仅在确认预留后调用 `risk.transfer.dispatch`；Risk 在事务中重新验证许可、摘要、双方授权、过期时间、账本切点和 writer fence，耐久 claim 后，以经 Gateway 登记的代理身份转发/协调 Gateway 的原子双边转移。Gateway 再独立验证调用主体、双方委托、原始母单信封、账本版本、占用和并发栅栏，单事务提交或拒绝；账本版本不匹配、授权被撤销或任一前提变化时不得按旧快照落账。Risk 的本地 claim 与 Gateway 的事务不是一个跨库事务。
3. `risk.transfer.status` 使用原 ID、摘要和认证作用域查询 Risk 及 Gateway 的权威结果；超时、掉线、claim 后崩溃、结果不明时双方和计划保持冻结，最坏占用保留，不能重发或改用无 Risk 路径。确定未发生且持有足够证据时，按冻结的 `risk.transfer.release` 协议幂等释放；结果为 UNKNOWN 时不得凭超时释放。Gateway 确认提交后，Risk 结合完整且去重的观察流结算预留及更新双方风险视图；观察流缺口或账本对账不完整继续阻断相关风险判断。相同 ID/摘要重放返回原状态，异摘要冲突拒绝。

由于 Gateway 不检查 Risk 批准，若其他有权主体绕过 Risk 直接调用 Gateway 的转移接口，Risk 的提交前检查不能保证覆盖该调用。应在 63/64/65 冻结由谁持有转移权限、代理 grant 如何配置与撤销、如何检测/对账绕过及未选 Risk 的授权路径；权限/租约和部署约束未经证实前不得宣称无法绕过。所选 Risk 失败时 Execution 自身必须 fail-closed；无 Risk 模式依据 63 权威授权、账本和转移规则单独验收，不依赖以上候选接口。BT 若不能以非场所来源准确表达内部转移，仍按 D65-03 阻塞并提请决定，禁止伪造成交。

## 6. 时序、崩溃与恢复

**Gateway 断连（D63-03 / Q35，用户已决定）。** 策略进程保持运行、显示断连并等待恢复；SDK/Execution 暂停不可可靠提交的 Gateway 请求，不回退 direct。场内子单可能继续成交，撤单无回复不等于已撤；重连须按原身份补齐、对账与准入，母单遵原计划/原窗口和 D65-05 等恢复条件，不重复派发、不据连接成功解除其他原因。集成验收覆盖断线、策略仍活、场内成交补齐、UNKNOWN及其他阻断保持。

**真实订单 UNKNOWN 的最小阻断范围（D63-04 / Q28，用户已决定）。** 本系统真实订单结果 UNKNOWN 时，Gateway 持有系统未知栅栏：阻断该订单所属策略在同一合约上的所有新订单（OPEN、CLOSE、新子单及通过新内部转移提交执行的订单份额）；不得通过更换母单、请求号、路由或执行方案绕过该策略/合约范围。已提交转移继续按原身份核对，不能因阻断抹除。对其他策略仅当该 UNKNOWN 使同一账户、同一合约、同一持仓方向的实际可平容量无法证明时，暂拒其相应平仓；容量可证明且满足各自既有门槛的平仓，以及其他不受独立阻断影响的交易继续按各自合同处理。不能从策略理论仓或 external 净额推断真实可平容量，也不能将该规则改成所有策略、所有方向的新单均阻断。

撤单和查询入口保留，断线时不承诺可以送达；不因该 UNKNOWN 自动撤销现有挂单或停止策略进程。已选择 Risk 时，其相关最坏占用继续保持，系统栅栏缩小不构成释放依据；未选择 Risk 不引入其服务依赖。按权威证据逐项解除对应 UNKNOWN 原因，不能连带解除其他独立的会话、日切、风控或急停阻断。D65-05 已决定按账户配置选择恢复模式，缺省为核对后按原计划自动继续；该范围规则不解除其他独立阻断。

应区分母单授权/受理结果不明与真实子单是否已派发：前者按原母单/请求身份查 Gateway/Execution 权威阶段并保留相应未决，不能直接假定场所已接收或未经证据套用真实订单 UNKNOWN；真实订单结果不明则按上述范围和原生身份恢复。D63-38 已决定：完整、同交易日、强身份的委托查询查不到原身份时，按既定合同标 `not_found_at_venue`、向策略投影 Rejected 并解除对应阻断，但不自动重发，也不改写成确定未发；查询不完整、旧交易日或身份不可靠不得据此解除。D63-48/49 的 external 禁入及无真实可平量拒单、理论仓不变仍有效，普通 A/B 策略虚拟转换不因此撤销。

验收：A 策略合约 X 的真实子单 UNKNOWN，A 在 X 的 OPEN/CLOSE/新子单均拒，换母单/键/方案仍拒；B 同账户 X 同持仓方向的 CLOSE 分别注入可平容量可信可证与不可证，前者满足独立门槛时继续，后者暂拒；B 其他方向/合约及其他策略不因 A 的 UNKNOWN 一概阻断。验证保留撤单/查询接口但断线不声称送达、不自动撤既有单或停进程；模拟多重独立阻断，证据解决一个原因只解除该原因；Risk 选用时最坏占用不提前释放。母单受理不明但尚无真实派发证据，与真实子单 UNKNOWN 分别恢复；覆盖 D63-38 完整/不完整/跨日强身份查询与不自动重发，D65-05 的账户配置与原计划恢复条件同时验证。

`live_state`、Execution、Gateway 和可选 Risk 是不同持久化域，**没有跨库原子事务**。用户已决定先交 Execution，再经选中的 Risk 母单风控，之后登记 Gateway 并由 Gateway 持有权威数量边界；名称、事务、认证与 fence 在 63/64/65.01 冻结：

1. SDK 在发送前持久化稳定请求身份及策略/BT 关联，再调用 Execution。Execution 先耐久记录母单意图、身份、请求摘要、委托和计划版本；相同请求键同摘要幂等，异摘要拒绝。Gateway 与 Risk 的身份映射可候选由 Execution 持久分配，但分配者、编码和认证授权尚未冻结，关联键本身不授予权限。
2. 选 Risk 时 Execution 使用该稳定身份申请母单风控和占用；可消费既有受信 Gateway 账户/行情观察，不要求目标母单事先在 Gateway 登记。Risk 失败或结果未知时不绕过；未选 Risk 跳过该组件。
3. Execution 在适用 Risk 成功后向 Gateway 登记母单范围，Gateway 独立验证可信策略与代理授权、账户/合约、数量、限价、期限及当前状态，形成自己的权威记录；Gateway 不调用或检查 Risk 批准。成功前不派发子单，母单登记不是交易所下单。
4. SDK 仅在符合冻结合同并能证明 Execution 与 Gateway 持久受理时向 BT 投影确定受理；丢回复或进程崩溃按原请求身份跨 Execution、选用的 Risk 与 Gateway 查询。Gateway 查无母单不证明 Risk 无预留或旧登记不会迟到；唯有完整权威证据、有效 fence 和占用状态对齐才能确定未开始及释放，否则 UNKNOWN。
5. Execution 持久子单计划后经选用 Risk reserve/claim 并转发 Gateway，未选 Risk 则直接经 Gateway；Gateway 按自己的信封、授权与数量桶原子核验、持久记录后才可原生调用。NOT_SENT 按 D65-14 的证据和账户显式次数处理；UNKNOWN 不换身份补发。撤母单时若 Gateway 已登记，按 D65-06 冻结并尝试逐子单撤销；登记前或状态不明的取消由 63/64/65 冻结可查询、授权及 fence 合同，不假称撤成或丢弃 Risk 占用。

Execution 崩溃或租约失效时 Gateway 冻结其母单，已派发子单继续由 Gateway 管理、回报；Risk 已选时保留未决占用。重启先校验写者 fence、日志完整性、冻结的类/配置及 grant，按父/子/转移/转换 ID 查询 Gateway 和可选 Risk，补齐游标和权威事实；有 UNKNOWN、缺口、身份冲突、旧日订单结果无法证明或来源无法证明则保持冻结、不补发、不释放。D65-05 已决定按账户配置选择，缺省在证据齐全并满足原计划条件后自动继续；具体恢复合同见下。完整同日强身份查询未找到按 63 已决定 D63-38 标记 `not_found_at_venue`、解除适用阻断但不自动重发；不完整或旧交易日保持 UNKNOWN。D65-06 已决定策略主动取消时 Gateway 冻结该母单并尝试撤其活动子单，逐笔报告结果；撤单受理不等于柜台撤成，不得撤销其他母单或策略的子单。跨库提交后结果不明时查询同 ID；转移一侧未知时冻结双方及受影响计划，不能凭另一个库成功猜测结果或反向补偿。

**Execution 崩溃后的母单恢复（D65-05 / Q29，用户已决定；接口字段待冻结）。** 账户 `config.yaml` 可选择按原计划自动继续或保持冻结；候选字段 `components.execution.recovery_mode`，缺省 `AUTO_CONTINUE`，可显式选择 `KEEP_FROZEN`。省略按用户决定取自动继续；非法值拒绝配置，不能默默转为默认。该配置与匹配/定价/算法类分开，随母单受理时的方案及账户配置版本持久绑定；重启配置漂移不静默改变在途母单，必须保留原绑定或按已验证的迁移合同处理。示例配置的名称、序列化和迁移方式在 65.01 与 63 冻结。

自动继续须先证明原计划时间窗仍有效，原母单/子单身份、日志完整与 writer fence、当前授权及 grant、冻结的策略/算法与配置版本、Gateway 账本及子单状态、选用 Risk 的占用和相关源水位均核对一致；没有 UNKNOWN、流缺口、身份冲突或会话/日切/风控/急停等其他阻断，才能继续。服务健康或进程重启本身不构成以上证明。Gateway 以版本化、权威的原子状态转换，只解除有证据解决且当前 grant 有效的本 Execution 故障冻结；Execution 不得私改 Gateway 状态，亦不得自动 RESUME 运营、Risk、Runtime 或其他独立原因。权限变化、账本/配置不匹配、时间或来源不能证明时保持冻结并可见；已到期的原计划不能重新启动。

原计划的截止/价格/数量/预算和算法约束继续有效，恢复只处理原计划当前时刻可证明允许的未下场余量；不能仅因重启默认把错过的所有 TWAP 切片集中补发；按原已冻结算法的错过时刻策略及数量/速率边界继续，不能临时改算法规则。冻结算法合同无法证明存在合法继续动作时保持冻结并说明；不自动重发 UNKNOWN 或改变 D65-14 的确定未发重试政策。已有场所挂单按原 child_id/原生身份继续跟踪，既不因服务故障自动撤单也不重发；后续成交只按原始权威事实推进。KEEP_FROZEN 下母单保持冻结，直到策略撤单或按合同到期，不新增其他人工继续入口。

验收向量：母单 10 手，已成交 4、原挂单 2、未下场 4；重启并逐项核对通过后 AUTO_CONTINUE 仅按原计划处理那 4 手，不撤不重发原挂单 2；原挂单后续成交按真实回报与幂等规则推进。分别验证缺省自动、显式保持冻结、非法值拒绝、旧母单配置版本不因新配置漂移、未决/缺口/授权撤销/原计划到期/其他独立冻结不继续、选 Risk 时占用不明不继续、网关原子恢复防旧 owner 竞态、TWAP 错过时刻遵守原算法规则、不默认集中补发，以及 KEEP_FROZEN 的撤单/到期。D63-04 的 UNKNOWN 范围、D63-38 的查询及拒绝投影、D63-48/49 的 external 边界不因本模式改变。

### 6.1 跨交易日母单合同（D65-04 / Q38）

首期允许同一母单跨交易日按原计划继续；父身份及初始账户/策略/主体归属稳定，原始期限、限价、算法、参数、配置和构建版本不随日切重置。日切不终止或无限续期；原 TIF 为 DAY 或原截止已到时按原合同到期，仍跟踪旧子单并依据事实处理。PASS、SLICE、TWAP 均休市暂停并在原计划允许的时间恢复：PASS 不重发旧单，SLICE 保留已发子单及原顺序/终态约束，TWAP 不重置原开始/截止或默认集中追补错过的片；其余量/错过时刻规则依受理时冻结算法，不擅自修改。

可执行字段候选：`ParentLifecycleV1(parent_ref, account_scope, strategy_id, origin_principal, origin_trading_day, accepted_at, original_tif, expiry_at_utc, session_timezone, calendar_version, algorithm_class, build_digest, config_version, schedule_cursor, completed_qty, reserved_qty, version)`；绝对截止与原 TIF 的具体组合按 provider 时段合同明确，无日期/时区的本地 `end_time` 不足以定义跨日截止。`ChildV1(parent_ref, child_id, child_trading_day, session_generation, native_identity, venue_identity, status, remaining_qty, source_cursor)` 将原生/场所身份及交易日固定在每个子单，`child_id` 序号跨日不复用。字段及类型、DAY 具体到期时点、兼容旧载荷与保存位置是待 63/65 冻结的工程候选，并非现有接口；65.01 提前验证 BT 能否消费稳定母单及逐日事实，不以字段名假定 D65-03 已解决。

候选 Gateway 主导日切：`begin_day_transition(parent_ref, transition_id, old_day, new_day, expected_version, fence)` 在权威事务内持久记录屏障与游标并阻断新预留；Execution 在事务外按原父/子身份补齐事实及会话/账本水位。`complete_day_transition(transition_id, evidence_cut, expected_version, fence)` 由 Gateway 原子核验一致证据并切换就绪状态；跨库或远程调用不假装同一事务，超时按同一 ID 查询，重复请求幂等，版本或 fence 冲突冻结。该协议名、状态机与证据 schema 属候选，63 拥有 Gateway 合同、65 持进度/调度，选 Risk 时 64 持风控占用；各本体可用替身先验证，实际联调另记证据。

新日派发须证明当前交易日及会话、结算、行情、授权、SDK 准入与所有独立阻断满足；选 Risk 时还须当前适用政策及原预留状态满足，不选 Risk 不依赖 64。原母单总预算与未决占用持续保留，日计数单独按新日记录，日切不额外整笔预留、不释放未决数量；旧活动、撤单中及 UNKNOWN 按原身份跟踪，不因日切重发或释放。D63-38 的完整同日强身份查询不可外推为次日对旧日委托的空查询，无法证明则继续 UNKNOWN。未下场轧差余量需日切回补并重新证明 D65-32 可用才入池，仍不得同向合并。跨日 CLOSE 须按 provider 当前今昨规则及理论仓映射核对；不改历史成交/成本，不自动 CLOSE 变 OPEN；D65-37（Q39）已决定平今母单在原期限仍有效时，核对原目标持仓后以 provider 原生 CLOSE_YESTERDAY 或其声明的等价映射继续：必须验证原目标身份、方向、理论归属、真实可平量与当前授权，持久记录日切映射版本及子单派生 offset；不得用次日新今仓代替目标、修改母单原始意图，旧日在途或 UNKNOWN 份额不能同时新日派发；证据不足按既定拒绝/UNKNOWN 处理，真实可平量为零按 D63-49；部分不足按原数量/拆单合同及实际事实处理，不由本条自动缩量、额外拆单或补开；既定 D65-27/28 专门转换仍按独立合同。

Q29 缺省 AUTO_CONTINUE 只在原期限有效且身份、授权、配置版本、账本、子单、选 Risk 占用和水位核对清楚、所有独立阻断解除后，由 Gateway 版本化恢复；日切或服务恢复本身不是继续证明。休市、缺口、旧日 UNKNOWN、撤单未确认、行情或日历不可证明、选 Risk 拒绝等保留适用占用并暂停对应动作，不静默切换规则。

### 6.2 策略停止、租约与 Runtime 接口（66 审阅影响）

完整背景和待定项以计划 §3.8a 为准。Runtime 首期只监督策略；Execution 重启恢复 D65-05 和策略异常重启 D66-09 分别适用，不能根据策略、UI 或 Monitor 的存活推断订单终态或解除 Gateway 阻断。策略异常退出后已受理母单原则上按原计划继续，但须满足策略租约、授权、Gateway 原因及其他适用准入；策略租约的可选 DRAIN 与 Execution 自己租约冻结相互独立。

用户已决定正常 stop/restart 取消未完成母单余量并尝试撤场内子单；取消意图不以子单撤单或 DRAIN 代替母单终态。用户后续取消了本期 Runtime 重启后提示或操作原余量重新下单的功能，后续另议；已取消母单不因重启复活。Gateway 提供权威订单事实和策略账本，真实成交及内部转移按原身份入账，见计划 §3.8a 与共同合同 §2.33。在途子单、迟到成交和 UNKNOWN 保留原身份与适用最坏占用。63/66 联合冻结停止屏障与租约原因自动解除、并发派发/内转、多原因的竞态；65 通过 Gateway 权威状态核验，不自行改变原因。D63-33 的租约原因在重连及恢复核对后默认按 cause/version 解除，可配置人工；已发撤单继续跟踪，其他原因不受影响。合同与实际组件未就绪时对应联调记 GAP/NOT_RUN，不阻塞无该组合依赖的基础路径。

## 7. 市场时钟、BT 投影与监控

D63-41 已决定默认 `getcash()`、`getvalue()`、`getposition()` 为账户范围，新增 `get_strategy_cash()`、`get_strategy_value()`、`get_strategy_position()` 查询策略；策略资金未配置即不可用，close、order_target_* 和默认 Sizer 使用策略范围。核心计算按 D63-44；API 所属类、签名及估值/产品占用细节由 63 冻结，不能以账户数据代替策略事实。

计划限制、日切和行情新鲜度由可验证的中立端口提供，拒绝伪造来源时钟。D65-04 已决定首期允许原母单跨交易日继续，D65-07 已决定首期仅限价母单；跨时段、到期、子单预算与下单价格遵照已冻结合同。67 是未来版本化日历数据及实时状态合成：交付前保持 62 的现有适用日历合同，不以 67 为基础核心必需项；若具体选中的策略声明需要 67 的版本、覆盖或状态而不可用，则该策略暂停/拒绝，不能假装可用。67 重读失败时遵守其已冻结的旧版本与覆盖规则；UNKNOWN、未覆盖或冲突不得当作可交易，时段外不新发子单，撤单依 Gateway 合同。

### 7.1 Execution 独立前端与服务 API（D63-47）

65.01 冻结 Web 主体到服务 principal/grant 的映射、失效/撤权拒绝、服务端审计、持久命令 ID 与丢回复后的原 ID 查询；本期 Execution 自有 Web 适配和未来 AFI 宿主适配分别归各自 owner。

共同技术方案见[跨迭代合同与决策](../迭代63-Gateway统一转发与多策略共享会话/跨迭代合同与决策.md) §2.13.1：Vue 3＋TypeScript＋Vite、Vue Router、Pinia、Element Plus、Axios，图表按需 ECharts；可选 FastAPI Web 适配复用既有服务操作，不替换服务间传输。页面组件、API 客户端、宿主适配与独立壳分离，预构建静态资源可选交付；未来 AFI 显式集成，本期不改 AFI。认证/授权和命令重试遵循共同合同，不能照搬 AFI 通用 Axios 重试。Runtime 也提供独立前端，但首期仍只监督策略。

本迭代为 Execution 提供可独立启用的可选前端入口，页面与服务解耦；未启动、关闭或断连页面不停止执行服务，不改变订单、轧差、恢复及 UNKNOWN 合同。页面消费与后续 ai-for-investor 共同使用的版本化 Execution 服务 API，页面和服务不依赖 ai-for-investor，本迭代不实现 AFI 集成。Gateway、Risk 分别由 63、64 提供自身可选页面；Monitor 仍是独立观察服务，不作控制代理；Runtime 首期只监督策略。

现有授权范围内的母单、子单、策略、执行进度、冻结和 UNKNOWN 等状态可作为版本化接口设计输入；显示与访问应带来源、范围和不可用/未知状态，不能将展示、心跳或 Monitor 观察冒充 provider 事实。字段、认证授权、分页/状态版本、断连及兼容合同由 65.01 与相应服务一起冻结，页面不直接读写内部账本或绕过 Gateway/选中 Risk。

用户已决定页面支持查看及各服务授权管理：Execution 页面可查看授权范围内母单、自己的子单、内部转移与转换，并经既有服务操作发起授权的母单撤销等。具体操作枚举、角色、grant、schema 与 D65-06 撤单细节由 65.01 和 63 共同冻结，未冻结操作不推断。UI 不直接调用 provider、不扩大 grant；鉴权、执行、审计和结果持久化由服务端完成。撤销受理不等于场所终态，也不能清除 UNKNOWN。技术栈按共同合同 §2.13.1 采用，具体部署和身份合同在 65.01 冻结。服务基础验收与 UI 独立；D63-47 的前端交付单列，未完成或合同未冻结不冒称完整交付。

### 7.2 审阅整改：状态、投影和 Risk 联动

详细交付责任与验证向量见[计划 §6.1](迭代计划.md)。65.01 须为 Gateway 权威母单生命周期、Execution 自身调度状态、冻结原因和交易日/账户屏障建立版本化映射、作用域及冲突处理，不把账户临时屏障误作母单终态。实际子单必须且只能关联一个母单及策略，多方内部转移使用独立身份；Gateway 仍做认证授权和原子数量核验。算法经宿主提供的版本化状态视图或有序事件通路获得已验证的子单状态、成交及 UNKNOWN；接口形式待冻结，不能靠本地计时猜测终态。保留可显式选择并继承的 PASS、SLICE、TWAP；`none` 与 PASS 的 schema 关系待 65.01 冻结，不能把未选算法当成绕过 Execution。

65.01 以真实 BT 和替身 SDK 核查母单及内部转移双方 Position/Order/Trade、成本、费用、盈亏、通知、幂等、恢复和跨日，评估已有恢复投影/receipt 去重机制；逐项留可表达或不可表达证据。不可表达时记录具体 BT 改动候选并按 D65-03 向用户提出，相关零改动路径暂停；不以替身结果证明真实服务或账户。63/65/67 联合冻结适用的时段和日历版本及 UNKNOWN，67 文件化不是未选其能力的基础执行路由硬前置；68 观察联调单列。

选用 Risk 且 R-08 为 deny 时，母单按整笔最坏资金和保证金预留，子单划拨复用、不重复预留；off/warn 不隐式开启 deny，旧 deny 未决占用不因关闭新预检而清零。账户/策略 scope、费用、水位和跨日/UNKNOWN 的转换与释放由 63/64/65 联合冻结，跨库不假设原子。Risk 整体不可用时拒绝新开仓/平仓，在途不明按原身份 UNKNOWN；撤单经 Gateway 发起，不能保证已送达。

选 Risk 且 R-02 启用时，实际限价子单使用最新成交价并重查来源/新鲜度；缺失或过期拒绝受约束开仓，限价平仓是否检查依 `apply_to_close`；开启该规则时市价开平都拒绝。D65-07 自身已将 Execution 首期范围限定为限价；未选/未命中执行路由按各自适用合同。D65-29 可选中间价或最新价用于内部转移记账，不改变 R-02 的参考价。选 Risk 且 R-11 适用时消费集中维护的单账户规则版本；限仓、日内开仓量、交割月的事实、适用时间及转移/真实子单统计由 63/64/65 冻结，未知阈值不补造，不以单账户结果证明跨账户控制。

用户确认 D65-14：仅权威证明子单确定未发送并且旧请求已被有效 fence 排除时，按账户配置的次数用新 `child_id` 重试，次数用尽冻结母单；次数必填、显式 0 表示不重试。每次仍须检查有效期限、授权、急停、所选 Risk 和原计划；UNKNOWN 或仅依据 D63-38 的场所未找到结论不得自动重发。内部转移默认不收额外内部费用，按已证实政策零及来源记账；与实际成交费用分开，未知费用不冒充零，非零收费是否支持仍待冻结。

### 8.1 数量、费用和恢复的验收例

以下只定义可验证的测试数据。内部转移定价类按 D65-29 显式选择；测试装置注入公平、费率、阈值、舍入和价格来源合同，其余政策上线前仍须确认。

- **独立真实成交与费用**：A 买3、B 买7，分别下各自真实子单；两边各自部分成交时分别按原始来源归属各自母单和策略，真实费用各自依据可信事实入账。A 撤单不得撤 B；重复回报、重启及费用更正不得重复计数，费用未知保持未知。
- **内部转移与净额**：同账户 A 买入意图 7 手、B 卖出意图 5 手；测试合同确定可转移 5 手、统一价格 P，Gateway 同一事务提交 A 的 +5 和 B 的 -5 策略分录，净变化为 0，分别计算双方策略成本与盈亏；此时 provider 成交数及账户场所持仓不变，不能产生 TradeID。余下 A 的 2 手才可通过 Gateway 成场所单，若实际成交 1 手，则原始场所成交总量为 1、账户持仓因该真实成交变化 +1；策略合计变化 +1，剩余 1 手保持在途占用。测试应按真实账户已有的期货多空与今昨桶建立一致初始状态；未定桶规则时此例仅为隔离测试模型，不能推断期货可平量。
- **UNKNOWN 与原子性**：在上述转移事务提交前杀进程，两边均无分录，原申请数量仍被安全占用；提交后回复前杀进程，以同一 transfer_id 查询并恢复，恰有一对分录，重复请求不再入账。若查询超时或权威账本不可用，双方与净额计划冻结、占用不释放；如发现单边分录则停止并报账本不一致，不自动补造。对各自子单在 dispatch 后回复前崩溃和撤单与迟到成交并发做同样注入，直到完整来源事实对齐前不释放 UNKNOWN 占用、不补发。

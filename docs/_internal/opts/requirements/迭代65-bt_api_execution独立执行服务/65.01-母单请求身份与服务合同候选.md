# 65.01 母单请求身份与服务合同候选

状态：**审阅候选，未冻结、未实现、未验收**。本稿细化首次请求、原操作查询和 Gateway 权威母单之间的映射，先以未选 Risk、未选轧差的路径说明；并不移除选 Risk、内部转移、离线撤单或其他完整迭代要求。操作名、字段和错误码均为候选，最终须由 SDK、Execution、Gateway 及适用 Risk owner 联合冻结。

## 1. 当前源码与关键缺口

当前 Execution `ParentAuthority.accept` 以本地 scope 和 `parent_ref` 做同内容幂等，保存 Gateway/Risk 操作号；其 `register`、`reconcile`、`cancel` 是进程内方法，不是独立服务端口。Gateway 提供 parent register、query、cancel 和 operation；SDK `GatewayParentService.handle` 在调用 authority 的 operation 查询前先查询母单并校验 grant，而 authority 的 `query_operation` 自身查询操作表。服务路径中登记缺行不证明迟到登记不会到达；当前 SDK parent client 对不能验证的结果返回 `None`。以上是局部源码事实，不证明正式服务、完整的可验证有限错误、真实授权或账户行为。

仍须交付：SDK 首次请求键到母单及各 owner 操作身份的持久映射、无需已知 `parent_ref` 的原请求查询、登记前取消与迟到请求 fence、独立服务授权审计、Gateway 离线 Execution 时对已登记母单的撤单驱动，以及现有 Broker 对母单/内部转移的真实来源投影。不能将本地持久记录视为这些能力已交付。

## 2. 身份与持久绑定候选

首次命中 Execution 时，在第一个可能的远端副作用之前，SDK 在自身可信本地存储中为**账户、策略及不可变发起运行身份下的原请求键**持久关联规范请求摘要、原政策与截止、方案版本、执行服务身份和可恢复的原提交/登记操作身份；`parent_ref` 若尚未分配则标为待绑定，不能凭空假定已有。随后各 owner 在自己的事务中分别持久接收与 operation ID，未知 `parent_ref` 时仍须能按原请求或操作身份查回并持久绑定。具体由哪个 owner 分配 `parent_ref`、编码及权威注册方式仍待冻结；现有 Gateway 注册要求提供该字段是当前接口约束，不代表分配方案已定。客户端自报不构成身份或 grant。

| 身份或事实 | 候选作用域与约束 |
| --- | --- |
| SDK 原请求键 | 账户、策略、可信发起 run 和 client request ID；可信来源与持久唯一性须证明。同一作用域同键不同规范请求冲突。发起 run 是不可变来源，不可因进程重启自动换 run 前缀生成新单；同一 run 可在会话重建后按原键恢复，运行身份发生更替时须有受信旧→新交接或接管凭据。失证时冻结相关写动作，保留已授权查询及 Gateway 独立撤单。 |
| 母单与注册操作 | `parent_ref` 与 `registration_operation_id` 分别绑定原请求、账户/策略、原方案与期限及摘要；由各 owner 独立保持唯一约束与历史回执。未选 Risk 不调用或加载 Risk，是否保留非授权占位字段按迁移合同决定。 |
| 后续操作 | 每个取消或其他状态更改有独立稳定 operation ID，绑定原主体、目标、原预期版本和规范摘要；不得与注册身份冲突。授权及身份核验后先查历史：同 ID、同原预期版本及摘要返回原回执，异内容为 ID 冲突；仅首次新操作再与当前版本比较。原操作受理回执与当前母单状态分别查询。 |
| 子单与转移 | 子单绑定账户、策略、母单、child ID、原 request/reservation、摘要及真实来源；每个子单只属于一个母单。内部转移使用独立 `transfer_id` 及双方归属，不伪装场所身份。 |

每个 owner 的事务序列、epoch、水位和观测时间都保留本 owner 来源，不能将不同库的版本号相加或比较后假装单一权威版本。摘要的规范化版本、字段覆盖、列表顺序和算法须冻结；摘要只验证内容一致，不证明会话、行情、授权或来源。普通日志不得记录凭据。

## 3. 版本化操作候选

所有操作都须以可信宿主认证的主体、账户/策略/对象/操作 scope 和当前 grant 逐次核验；请求自带的主体或引用不是授权。保留原操作主体及续任关系供审计，但可按当前权限允许新主体查询历史或发起取消，不能仅因主体不同一概拒绝。此表说明目标行为，不是现有 wire API；面向 69 的读取及受权撤单接口由 65 交付，页面由 69 交付。

| 操作候选 | 请求与可验证结果 | 失败和恢复边界 |
| --- | --- | --- |
| `parent.submit` | 原请求键、规范请求/摘要及选定不可变方案；返回本地持久记录或附 owner、身份、版本和来源的可验证受理事实。 | 本地收录不等于 Gateway 或 BT 已受理。无 Risk 时按 SDK → Execution → Gateway 推进；Gateway 权威登记确认前不预留/派发子单。重复同键查原结果，异内容冲突。 |
| `parent.by_request` | 以原请求键及可信作用域查询，无须事先知道 `parent_ref`；返回绑定与原操作身份或带来源的未观察结果。 | 缺行、超时、旧 generation 或未验证回复不证明原请求不会迟到；无法证明时保持 UNKNOWN，不换身份再提交。 |
| `parent.operation.get` | 目标 scope、原 operation ID；返回该 owner 的历史回执、摘要和来源版本。 | 历史登记 ACTIVE 不代表母单当前仍 ACTIVE；每个 owner 单独查询，缺失不自动推出其他 owner 无占用。 |
| `parent.get` / `parent.list` | 已授权 scope 下有界读取当前状态、阻断原因、完成量/未决量、各 owner 来源与完整性；列表有界并按稳定分页合同处理。 | 不可比、陈旧或缺页明确为 UNKNOWN/不完整，不拼成确定状态；列表游标不得跨越授权范围或把缺页当空集合。 |
| `parent.cancel` | 原母单及登记身份、稳定取消 ID、预期版本和授权主体；返回带来源的取消受理或 UNKNOWN。 | `CANCEL_REQUESTED` 不等于所有子单撤成；冻结和目标集、场内撤单、迟到成交及占用释放分别核对。已登记母单的获授权策略在 Execution 离线时仍可走 Gateway 独立持久取消并尝试撤子单，不能依赖此 Execution 操作在线。 |

`parent.submit` 到 Gateway 的授信信封、原操作证明、`parent.by_request` 的确切 owner/transport、读列表快照和客户端投影须实际设计与实现。64 的 parent 风险受理及撤权合同仅在选择 Risk 时接入；各策略/服务设置不一致不能静默降级。当前 Gateway 对未知母单的取消缺少登记前持久屏障：登记未知时先取消获得 NOT_FOUND，迟到注册仍可能成功，必须按原身份保持 UNKNOWN，直到具备可证明未发生或释放相应占用所需的可靠迟到 fence 和适用 owner 证据；在途时已授权查询和撤单仍可用，不等待不相关 owner。不能据空查询释放或新建母单。

## 4. 结果与证据分类候选

- `LOCAL_DURABLE`：只证明本 owner 持久保存的原请求和身份，不能代替远端权威受理。
- `OBSERVED`：仅在响应来源、范围、操作身份、摘要、epoch 和完整性通过该 owner 合同验证时使用；同时返回历史操作和当前状态时各标来源与版本。
- `DEFINITE_REJECTED`：某一 owner 仅在可证明该操作未产生、且旧请求不能迟到产生该 owner 副作用时报告；附证明来源及该 owner。其他适用 owner 的占用另标 UNKNOWN/HELD/RELEASED；只有宣称整笔请求无后续副作用、结束或释放相关占用时才分别满足其证据。未选 Risk 不查询 Risk。
- `CONFLICT`：原作用域同身份不同内容属于 ID 冲突；首次新操作的预期版本不符是条件冲突，附可验证当前版本。同 ID、同原预期版本及摘要的历史重放先返回原回执，不因当前版本变化而拒绝；不修改原未决操作，不将先前 UNKNOWN 变为已拒绝或释放占用。
- `UNKNOWN`：超时、丢回复、来源不可验证、提交结果未知、旧 owner 迟到未被 fence 等均保留原身份及适用的最坏占用，按权威查询恢复；网络异常或空查询不得翻译为确定未发送。

上述为结果分类，不假定已经存在同名错误码。`NOT_FOUND` 可以表示某次查询没有观察到记录，不单独证明请求未发、Risk 无预留、窗口已结束或将来不会生效；完整同日强身份的场所查询按 D63-38 单独处理，不能改成确定未发送或自动重发。取消、到期、服务租约失效和 UNKNOWN 各自独立于母单终态；迟到权威成交仍按原身份处理。

## 5. 离线可执行验收向量

1. 原键尚未持久、刚持久、Execution 持久提交前后分别中断；使用全新临时存储和替身服务验证首次写入先于远端调用、重启按原身份恢复。同键同内容返回原记录，异内容冲突且不影响已有记录。
2. Execution 落库后或 Gateway 登记提交后丢回复；以原请求键、注册操作和母单观察分别查询，不以空查询推断无副作用。Gateway 历史回执 ACTIVE 但当前 CANCEL_REQUESTED 时展示两个有来源的事实，不以旧回执覆盖当前状态。
3. 取消先到而注册缺行，原注册随后迟到；在缺少可靠登记前 fence 的现状中保持 UNKNOWN。未来实现 fence 后分别故障注入屏障前后、旧 owner 迟到及撤权竞争，证明不会错误释放或产生第二母单。
4. 已登记母单在 Execution 离线时，由受授权策略经 Gateway 持久受理取消；子单撤成前不宣称完成。同取消 ID 在受理后版本变化或丢回包时重放原回执和原目标；异内容冲突，首次新 ID 的陈旧版本拒绝。策略经 Gateway 直撤与 Execution 同时使用不同操作 ID 撤同一子单时，目标级至多一个未决撤单派发，两操作各自可查，UNKNOWN 不创建第二次派发；并分别验证不同主体/账户/策略 scope 及撤权。
5. 子单 claim 后未知、撤单回执迟到、重复/乱序成交，分别核对每个 owner 的原 ID、权威事实、数量和占用；只在证明相应释放条件后推进。按适用选 Risk 场景单列测试，不以无 Risk 的替身结果代替。
6. 同一 run 的会话重建使用原键恢复；运行身份更替时，新运行通过受信交接使用旧发起 run 与原键查询。交接或绑定缺失时冻结相关写入，保留已授权查询及 Gateway 独立撤单，不以新 run + 相同本地计数生成另一笔。列表读取检验分页、水位及账户和策略范围隔离。

这些向量需要真实 API、各 owner 的版本化合同、测试替身及后续真实组件联调才能执行；本稿本身不构成行为测试、步骤冻结或账户验收，也不解决禁止修改现有 Broker 条件下的内部来源投影。

对齐 Gateway 资源并为合成 Risk 预建受保护的 v4 账本后，独立进程首次完成 Execution→Risk v2 母单 `ACCEPTED`、子单 `DISPATCHED`，Gateway 关闭并以同一 journal ID 重新就绪。重启后的 Risk 观测停在 `UNVERIFIED/observation_read_failed`，尚未通过恢复后交易和无重复派发的核对。本次夹具未提交，测试拥有的宿主已回收。

同一 Risk 进程的重启诊断，已按正确的 `service.account_read` 注册端口和准确读权限完成阳性对照。重启前注册与消费归属都有效。替代 Gateway 采用同一 journal，策略接收端就绪，服务 epoch 变更，同一账本仍有 4 条测试事件。重启后查不到 Risk 的精确有效读注册，持久消费归属仍指向旧 epoch。40 秒界内持续为 `UNVERIFIED/observation_read_failed`。两个合成 Gateway 均以 `0` 退出，Risk 测试进程已回收。当次未取得 Risk 正常清理证明。

源码表明新 Registry 拒绝旧 epoch 的注销请求。Risk 需要确认原注册注销才能替换连接。当次数据已定位到缺少新读注册，尚未采到 Risk 内部停止于续租还是注销的精确分支。计划性停机重启与保留同一 Risk 进程的恢复分别验收，前者要求在旧 Gateway 仍在线时观察到下游正常清理。

计划性重启采用先闭合下游再关闭 Gateway 的顺序。两个进程同时下线时，Risk 的持久游标保留原历史。重启以有效的新读注册、同账本消费归属、新代际 R-05 切点和合成写入结果为验收依据。Execution 连接每次使用新的注册 key 和客户端会话身份，账本和业务请求身份按原合同保留。旧注册 key 的拒绝在测试中已确认。保持 Risk 进程在线的断开恢复仍独立跟踪。

`34cd07f4` 的单次隔离复跑保留原 Risk PID，同时验证了 Gateway 新 epoch、同一 journal、精确观测注册和持久消费归属匹配，Risk 的观测游标重新 `VERIFIED`。原测试轮询超时后只断言最后读到的切点覆盖标志，曾把仍有效的旧切点误记为当前切点。停机后对照保留的合成账本与替代 Gateway 的代际，唯一 R-05 切点仍属于旧 Gateway owner，账户事实的持久消费归属也仍在旧 Registry epoch。已核对的窗口内没有旧单重放，恢复后的新单派发尚未验证。复跑在后续 Execution 测试客户端调用的 `NOT_REGISTERED` 处停止，该客户端仅注册一次且无续期。Risk 的最终有限记录为 `cleanup_uncertain`，标识 `ACCOUNT_FACTS`，具体失败调用尚未定位。完整自动恢复未通过。

**72.05 Gateway 断连联调。** 合成 TD 断连后已看到登录代际进位、只读就绪恢复和新账户观察。隔离单策略同时订阅两个合约后，最终所测场景在 MD 断开后清空旧来源范围，随后 10 秒界内未创建替代 MD 客户端，也未完成新代际确认。另一次隔离前的尝试观察到两合约完成代际确认和读回。该结果尚不稳定，未提交新夹具，跨服务收敛仍待验收。

后续跨线程回调复现了异步 ACK 被 Hub 当失败的问题。修复后单次完整合成复跑为 1 项失败、1 项通过，失败发生在 ACK 之前。两合约的 2,548 次源重置检查保持 `MARKET_OPERATION_PENDING`，未观察到 CTP 侧相应回调或替代 MD 会话。相邻的阻塞 MD 启动清理通过。完整场景夹具仍未提交，原生 owner 队列推进仍需定位。

新取证中，MD 故障前 owner 活跃，队列有 1 项待处理，维护调用均已返回。故障后维护累计 134 次开始、134 次返回，队列回到 0，IF 的 owner 确认返回成功一次。期间出现有限的 `QUERY_SCOPE_CHANGED`，IH 未取得对应换代结果，10 秒界内仍未完成双合约复原。该次证据排除了 owner 维护回调持续阻塞。

进一步取证确认，故障前后 IF 和 IH 的 Hub 均保有活动注册、handle 和 generation，各自未进入释放或确认失败。该次故障后，两合约的 reset 检查都停在 `MARKET_OPERATION_PENDING`，未进入 CTP reset 回调。截止时 owner 仍运行，维护 131 次开始、130 次完成，恰有 1 次在运行。该瞬时观察无法区分实际在途 market 任务或某次维护的等待。需继续核对两个 handle 上的在途操作类型及其完成状态。

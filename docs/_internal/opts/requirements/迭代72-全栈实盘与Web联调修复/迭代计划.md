## 5. 分层验收矩阵与不可退让红线

### 5.1 证据等级要求（不可互相替代）

| 证据层 | 最低要求 | 说明 |
| --- | --- | --- |
| `UNIT/FAKE` | `bt_api_py`、`bt_api_web`、`backtrader` 涉及修改模块全量单测 0 failed；前端 `vitest` / `vite build` 0 errors | 覆盖边界条件、超时、越权、断连自愈与清理不确定 fail-closed |
| `INTEGRATION_SIM` | 离线多进程 5 服务 + Web + 替身柜台联调，注入 TD 断连、socket 退役、会话过期、越权访问 | 证明故障隔离（杀 Web 不影响 5 服务与策略）与自动恢复 |
| `SIMNOW` | SimNow 开盘时段全栈 9 服务 + 11 策略 + 浏览器连续运行 ≥2 小时 | 必须记录交易日、账户持仓基线、成交笔数、各服务日志与浏览器实测结果 |
| `REAL_ACCOUNT` | **本迭代不执行（`NOT_RUN` / `NO-GO`）** | 未经用户单独验收并书面授权，严禁使用真实资金账户运行 Gateway 写单 |

### 5.2 不可退让的 Fail-Closed 红线

1. **严禁伪造或降级安全校验**：不得为图省事放宽 Win32 DACL/重解析点校验、不得绕过 `authenticated_peer_for_binding()` 的 socket 绑定证明、不得在清理不确定（`unregister_uncertainties > 0`）时强行重建连接。
2. **严禁伪造组件“可用”状态**：不得在 `bt_api_web` 中掩盖 `bt_api_risk` 的 `_v1_source_quarantined` / `counts_coverage=INCOMPLETE` 或将 `UNKNOWN` 翻译为“无委托/未发送/已撤单”。
3. **严禁泄露机密信息**：不得在日志、文档、提交或浏览器输出中打印 `.env` 凭据、SimNow 密码、CURVE 私钥、原始 Bearer/Session token。
4. **严格遵守跨仓提交顺序**：SDK 子包先提交，再更新父仓 `bt_api_py` gitlink；保留所有无关 dirty 文件；仅提交本地 `dev`，未经用户明确要求**禁止 push**。

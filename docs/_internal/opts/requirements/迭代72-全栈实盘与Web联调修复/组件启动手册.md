# 迭代 72｜全栈组件启动手册（5 个 SDK 服务 + bt_api_web + 007_ctp_gateway 11 策略）

本文档面向接手迭代 72 联调与修复的开发者，详细说明如何在 Windows（及 POSIX）环境下按严格依赖顺序独立配置、启动、校验和关闭全部组件，并给出常见故障定位方法。

> **安全禁令**：严禁在日志、终端输出、提交记录或配置文件模板中打印/硬编码任何 `.env` SimNow 凭据、CURVE 私钥或原始会话/访问 token。所有包含密钥、凭据或 token 的文件在 Windows 下必须设置 **owner-only DACL**（等价 POSIX `0600`/`0700`）。

### 1.2 SimNow 凭据与交易时段前置

1. SimNow 凭据读取自 `D:\source_code\backtrader\.env`（受 `.gitignore` 保护，绝不提交）：
   - `CTP_BROKER_ID`（默认 `9999`）
   - `CTP_USER_ID`
   - `CTP_PASSWORD`
   - `CTP_APP_ID`（默认 `simnow_client_test`）
   - `CTP_AUTH_CODE`（默认 `0000000000000000`）
2. **SimNow 第一套（实盘交易时段）前置地址**：
   - TD 前置：`tcp://182.254.243.31:30001`
   - MD 前置：`tcp://182.254.243.31:30011`
   - 时段：日盘 `09:00–11:30`、`13:30–15:00`；夜盘 `21:00–23:00`（夜盘的 CTP `TradingDay` 为**下一个交易日**，例如 `2026-11-24` 夜盘对应的 `trading_day=20261125`）。
   - 7×24 环境（非实盘时段离线联调参考）：仅做连通性参考，不替代第一套实盘时段证据。
3. **SNTP 时钟源**：Gateway 时钟核验需本机能访问至少 1 个配置的 NTP 服务器（如 `ntp.tencent.com`、`ntp.aliyun.com`）。

### 1.3 Windows 私有目录与文件权限（核心踩坑点！）

Windows 默认继承 DACL 包含 `Users` / `Administrators` 写权限，**所有受保护的配置文件、密钥文件和审计/账本目录都会被 SDK 严格拒绝（`PROTECTED_FILE_UNAVAILABLE` / `INVALID_STORAGE`）**。

创建任何运行根目录、密钥文件、配置 JSON/YAML、SQLite 账本后，必须使用 SDK 内置原语收敛为当前用户独占 ACL：

```python
from pathlib import Path
from bt_api_py._win32_security import _set_owner_only_acl

def protect(path: Path) -> None:
    _set_owner_only_acl(path)
```

### 1.4 推荐运行目录布局（单次或持久化工作目录 `<ROOT>`）

```text
<ROOT>/                          # 例如 D:\temp\007_ctp_gateway_simnow_web_20261124（owner-only ACL）
├─ monitor/                      # Monitor 配置、密钥、data/events.sqlite、query-registry.sqlite
├─ gateway/                      # gateway_operator.yaml、resources.json、gateway_web_config.json、journal/、registry/、account_read/、identity/、guard/、flow/、keys/
├─ risk/                         # risk_service.json、risk_policy.yaml、risk_web_config.json、state/risk.sqlite、keys/
├─ execution/                    # manifest.json + 11 个策略各自目录 <strategy>/{journal/,registry/,audit/,keys/,parent.json,read.json}
├─ runtime/                      # runtime.json、operator.json、tokens.json、runtime_home/
├─ web/                          # accounts.sqlite3、night_web_factory.json、web_launch_state.json
├─ strategies/                   # 11 个 007_ctp_gateway 策略运行拷贝 + calendars/ + 公共 runner 模块
└─ logs/                         # 9 个服务的独立日志文件
```

> **持久化建议（重要）**：同一交易日内若已发生 SimNow 真实成交，**不要清空 `<ROOT>/gateway/journal`、`risk/state`、`execution/*/journal` 与策略 `state/`**；否则 SimNow 重放当日成交会触发 `unresolved-return` 与 `STRATEGY_BASELINE_HISTORY_UNRESOLVED`。

## 2. 一次性离线预置（启动前准备）

在拉起任何进程前，按以下步骤生成密钥、初始化账本并执行离线校验：

### 2.1 生成 CURVE 密钥对

使用 `zmq.curve_keypair()` 为以下每个服务端与客户端生成独立 Z85 密钥对（40 字节 ASCII + 换行），全部 `protect()`：

- **Monitor**：`events`（服务端）、`heartbeat`（服务端）、`query_server`（只读查询服务端）、`query_client`（`bt_api_web` 只读查询客户端）、`runtime_telemetry`（Runtime 上报客户端）、`gateway_hb`（Gateway 心跳客户端）
- **Gateway**：`server`（服务端）、`operator_alice`（本地 Web 宿主操作人客户端）、`runtime_control`（Runtime 控制客户端）、`risk_delegate`（Risk 代理下单/查询客户端）、`risk_control`（Risk 控制客户端）、以及 **11 个策略各自独立的 Gateway 客户端密钥**
- **Risk**：`risk_server`（服务端）、`risk_web_operator`（本地 Risk Web 宿主客户端）、**11 个策略各自独立的 Risk 客户端密钥** + **11 个 Execution 各自独立的 Risk 客户端密钥**
- **Execution**：**11 个策略各自独立的 `ParentServiceHost` 服务端密钥 + 策略客户端密钥**；以及被观测策略（如 `sa_dual_ma_gateway`）的 `ReadServiceHost` 服务端密钥 + `bt_api_web` 读取客户端密钥

### 2.2 预建 Gateway 与 Risk 基础 SQLite 账本

1. **计算标准化账户 Scope**：
   ```python
   from bt_api_base.account_protocol import AccountKey
   scope = AccountKey("ctp", "simnow", "simnow", user_id, broker_id).account_key_id
   ```
2. **初始化 Gateway 命令账本与观测身份签发器**：
   ```python
   from bt_api_gateway.direct_command_journal import GatewayDirectCommandJournal
   from bt_api_py.order_correlation_issuer import DurableOrderCorrelationIssuer

   gw_journal = GatewayDirectCommandJournal.create(gw_journal_path, scope, generation="provisioned")
   gw_journal_id = gw_journal.journal_id  # 写入 gateway/resources.json 的 expected_journal_id

   issuer = DurableOrderCorrelationIssuer(gw_identity_path)
   issuer_id = issuer.issuer_id           # 写入 gateway/resources.json 的 expected_observation_issuer_id
   issuer.close()
   ```
3. **引导 Risk Pretrade v4 + R-05 v2 账本**：
   ```python
   from bt_api_risk.core.admission import AccountScope
   from bt_api_risk.pretrade.ledger import PretradeLedger
   from bt_api_risk.risk_order_journal import RiskOrderJournal

   boot_journal = RiskOrderJournal(risk_db_path, writer_id="bootstrap-simnow-web")
   with boot_journal.writer_fence(AccountScope("ctp", scope, "simnow")) as fence:
       boot_ledger = PretradeLedger(boot_journal, fence, schema_version=4)
       boot_ledger.enable_r05_observations_v2()
   ```
4. **初始化 11 个策略本地状态**：
   将 `D:\source_code\backtrader\examples\live\007_ctp_gateway` 下 11 个 `*_gateway` 目录、公共脚本（`gateway_client_runner.py`、`gateway_local_resources.py`、`gateway_runner_lifecycle.py`、`calendar_gate.py`）和日历目录（`examples/live/007_ctp_direct/calendars`）拷贝到 `<ROOT>/strategies/`，生成各策略 `config.yaml`（填入对应 Gateway/Risk/Execution endpoint 与密钥路径、独立 `strategy_uuid`），并对每个策略目录执行一次：
   ```powershell
   python run.py --upgrade-state
   ```
   确认标准输出包含 `LOCAL_STATE_UPGRADED`。

### 2.3 离线配置校验（强烈推荐启动前先跑通）

- Gateway Dry-Run：
  ```powershell
  $env:BT_API_CTP_GATEWAY_RESOURCES_FILE="<ROOT>\gateway\resources.json"
  python -m bt_api_py.gateway_operator_cli --config "<ROOT>\gateway\gateway_operator.yaml" --dry-run
  ```
- Risk / LocalWebHost / Runtime 离线加载检查：
  - `bt_api_py.risk_service_config.load_risk_service_config(risk_cfg_path)`
  - `bt_api_py.gateway_web_local_host.LocalGatewayWebHost(gw_web_cfg_path)`
  - `bt_api_py.risk_web_local_host.LocalRiskWebHost(risk_web_cfg_path)`
  - `bt_api_py.runtime_operator_config.load_config(rt_operator_path)`

## 3. 逐组件启动步骤（严格按 1 → 10 顺序）

> 所有端口均绑定 `127.0.0.1` 随机空闲端口（除 `bt_api_web` 默认固定 `8769`）；以下用 `<PORT_*>` 占位。每个服务都建议设置环境变量 `PYTHONUNBUFFERED=1`、`PYTHONDONTWRITEBYTECODE=1` 并重定向日志至 `<ROOT>\logs\`。

### 步骤 1/10：启动 `bt_api_monitor`（事件写入 + Gateway 心跳）

- **核心配置**（`<ROOT>/monitor/monitor.yaml`）：
  - `schema: bt_api_monitor.service.v1`
  - `storage`: `directory: data`, `outbox_scope: events`, `event_types`: 全部 `sorted("runtime." + e.value + ".v1" for e in bt_api_run_contract.EventKind)`
  - `ingress`: 绑定 `tcp://127.0.0.1:<PORT_MON_EVENTS>`，授权 `runtime-telemetry` 主体
  - `heartbeat`: 绑定 `tcp://127.0.0.1:<PORT_MON_HB>`，授权 `gateway-principal` 主体
- **启动命令**（工作目录 `<ROOT>/monitor`）：
  ```powershell
  python -u -m bt_api_py.monitor_service_host run --config "<ROOT>\monitor\monitor.yaml"
  ```
- **就绪判据**：日志输出 `MONITOR_LISTENERS_READY`（或 `"running": true`），且生成 `<ROOT>\monitor\data\events.sqlite`。

### 步骤 2/10：启动 Monitor 只读查询服务（`ObservationQueryService`）

`monitor_service_host` 写入事件并发布心跳。独立查询宿主通过 CURVE 提供 `observation.query`，并为分页结果签名。它以只读模式打开步骤 1 的 `events.sqlite`。

1. 复制 `D:/bt_api_py/examples/services/monitor-query-service.example.json` 至 `<ROOT>/monitor/monitor_query.json`，用联调部署的固定身份、范围和事件类型替换模板值。
2. 将 `storage.events_db` 指向步骤 1 的已有数据库，为 `storage.registry_path` 指定查询宿主独立的注册库。`service_config.communication` 配置查询宿主的回环 CURVE 端口。
3. `keys` 引用部署的 CURVE 密钥文件及该查询源和 Web 共同使用的 32 字节 HMAC 密钥文件（64 位十六进制）。Windows 私有文件使用 owner-only ACL。Web 通过同一 scope 与独立 CURVE 客户端身份绑定查询端点。

在 `D:/bt_api_py` 的 SDK 环境执行：

```powershell
python -m bt_api_py.monitor_query_service_host run --config '<ROOT>/monitor/monitor_query.json' --dry-run
python -m bt_api_py.monitor_query_service_host run --config '<ROOT>/monitor/monitor_query.json'
```

配置检查输出 `MONITOR_OBSERVATION_QUERY_CONFIG_VALID`，启动后等待 `MONITOR_OBSERVATION_QUERY_READY`。随后从 Web 的受权读源查询一页并校验签名，再将此步骤记为就绪。

本地验证以 `bt_api_py dev 6e30a32e` 和 `bt_api_monitor dev 2fdd5b9` 为基线。配置检查及 3 项合成测试通过，覆盖独立查询进程、认证分页、验签和正常停机。72.07 的 Execution 装配仍需独立验收。

### 步骤 3/10：启动 `bt_api_gateway`（CTP SimNow 共享会话）

- **核心配置**：
  - `<ROOT>/gateway/gateway_operator.yaml`：`gateway_operator_config_schema_version: 2`，`profile_ref: ctp-simnow-trading`，绑定端口 `service.direct_write`、`service.market_source`、`service.account_read`；开启 `dispatch_enabled`、`cancel_enabled`、`control_enabled`、`control_cancel_enabled`、`strategy_ledger_enabled`、`account_extensions_enabled`、`account_facts_financial_enabled`、`actor_stream_enabled`、`strategy_origin_enabled`、`account_fact_recovery_enabled`、`account_event_recovery_enabled`、`delegation_enabled`。
  - `<ROOT>/gateway/resources.json`（由环境变量 `BT_API_CTP_GATEWAY_RESOURCES_FILE` 指向）：
    - `required_monitor`: 指向步骤 1 的 `<PORT_MON_HB>`（`automatic_resume: true`）
    - `controls.operators`: 配置 `operator-alice-principal`（`kind=operator`）、`runtime-control-principal`（`kind=runtime`）、`risk-control-principal`（`kind=risk`）
    - `account_observation.operator_reads`: **必须**显式授予 `operator-alice-principal` 在 `service.account_read` 上的 `["account.snapshot.typed"]`，否则 `LocalGatewayWebHost` `/snapshot` 会返回 403！
    - `order_cut_observation.principals`: 包含 `risk-host`（支撑 Risk R-05 v2）
    - `delegation`: 授权 `risk-host` 代理全部 11 策略写单与账户/行情读取；`risk_only_submit` 覆盖全部 11 策略 UUID
    - `strategy_ledger`:
      - 首次空 journal 且账户已有昨日/外部持仓时，配置精确匹配的 `external_baseline`（可用实盘持仓探针核对 `today_quantity` / `yesterday_quantity`）；
      - 同日重启时保留既有 `orders.sqlite`，启动后核对策略账本状态 `PRESENT` 和活动冻结原因。
- **启动命令**（工作目录 `<ROOT>/gateway`）：
  ```powershell
  $env:BT_API_CTP_GATEWAY_RESOURCES_FILE="<ROOT>\gateway\resources.json"
  python -u -m bt_api_py.gateway_operator_cli --config "<ROOT>\gateway\gateway_operator.yaml" --log-level INFO --startup-timeout 60
  ```
- **就绪判据**：日志输出 `CTP trader login ok`、`Required Monitor phase=MONITORING`、`{"ready": true, "role": "trading_owner", "state": "running"}` 以及 `Gateway strategy ledger baseline ready`（若同日清空重跑遇到历史成交，见 §5 排障）。

### 步骤 4/10：启动 `LocalGatewayWebHost`

- **核心配置**（`<ROOT>/gateway/gateway_web_config.json`，owner-only ACL）：
  - `origin`: `http://127.0.0.1:<PORT_GW_WEB>`
  - `receipt_key_base64`: 32 字节随机 key 的 Base64
  - `operators[0]`: `principal_ref=operator-alice-principal`, `scope_id=desk`, `login_token_sha256`（64 位十六进制随机登录令牌的 SHA-256）, `operations`（只读控制集合 `direct.control.identity/list/status/targets/target_status/resume_status`）, `account_operations: ["account.snapshot.typed"]`
- **启动命令**（工作目录 `<ROOT>/gateway`）：
  ```powershell
  python -u -m bt_api_py.gateway_web_local_host --config "<ROOT>\gateway\gateway_web_config.json"
  ```
- **获取本地操作人会话**：
  - 确认 `GET http://127.0.0.1:<PORT_GW_WEB>/api/v1/session` 返回 `401`（服务已就绪）；
  - 发送 `POST http://127.0.0.1:<PORT_GW_WEB>/login`（Header `Origin: http://127.0.0.1:<PORT_GW_WEB>`，`Content-Type: application/x-www-form-urlencoded`，Body `token=<login_token>`）获取 30 分钟会话 token（`x-gateway-session`）。

### 步骤 5/10：启动 `bt_api_risk`（pretrade v4 + R-05 v2）

- **核心配置**：
  - `<ROOT>/risk/risk_policy.yaml`：`schema: bt_api_risk.policy.v2`、`account: {route: CTP___FUTURE, account_scope: <scope>}`、`per_order.max_quantity`（11 策略各合约上限）、`self_trade: {enabled: true, on_unverifiable: deny}`、`closable_check: {enabled: false}`（按需）。
  - `<ROOT>/risk/risk_service.json`：`schema: bt_api_risk.service.v1`、`pretrade: {schema_version: 4}`、`parent_contract_enabled: true`、`account_facts_observation.order_cut_enabled: true`、`principals` 包含 11 策略 + 11 Execution + 1 个 `role="operator"` 的 `risk-web-operator`（授权 6 项只读：`risk.admin.status`、`risk.policy.read`、`risk.latch.list`、`risk.unknown.list`、`risk.audit.read`、`risk.counts.export`）。
- **启动命令**（工作目录 `<ROOT>/risk`）：
  ```powershell
  python -u -m bt_api_py.risk_service_host run --config "<ROOT>\risk\risk_service.json" --ready-file "<ROOT>\risk\risk.ready.json" --enable-owner-stop-file
  ```
- **就绪判据**：
  1. `<ROOT>\risk\risk.ready.json` 中 `"state": "serving"`；
  2. 启动 Execution 前，核对当前 Gateway owner 代际下的 R-05 v2 切点有效、查询及回报覆盖完整、来源连续，且 Risk 的消费及 ACK 水位均覆盖切点水位。重启时需核对本次代际的证明和时效。

### 步骤 6/10：启动 `LocalRiskWebHost`

- **核心配置**（`<ROOT>/risk/risk_web_config.json`，owner-only ACL）：
  - `origin`: `http://127.0.0.1:<PORT_RISK_WEB>`
  - `operator`: `principal_ref=risk-web-operator`，与 `risk_service.json` 一致的 CURVE 密钥、endpoint 及 6 项只读操作列表
- **启动命令**（工作目录 `<ROOT>/risk`）：
  ```powershell
  python -u -m bt_api_py.risk_web_local_host --config "<ROOT>\risk\risk_web_config.json"
  ```
- **获取本地操作人会话**：同步骤 4，对 `http://127.0.0.1:<PORT_RISK_WEB>/login` 换取 30 分钟 `x-risk-session`。

### 步骤 7/10：启动 `bt_api_execution`（11 个策略的写者与受权读取）

每个策略使用一个 `ParentServiceHost`。父配置采用 `bt_api_execution.parent_service.v1`，`writer_mode` 为 `single_host_cooperative`，`dispatch` 指向步骤 5 的 Risk 和步骤 3 的 Gateway，`routing_rules` 绑定当前交易日。

对 Web 要观测的策略（默认 `sa_dual_ma_gateway`），使用 `bt_api_py.execution_combined_service_host`。配置顶层为 `{"schema": "bt_api_execution.combined_service.v1", "parent": {…}, "management": {…}}`，`parent` 与 `management` 分别填入父宿主和管理读取的配置。管理读取使用 `bt_api_execution.management_read_service.v1` 与 `management_read_only`，母单和计划点读分别授权 `execution.management.parent.read.v1` 与 `execution.management.parent.plan.read.v1`。如需按原请求查，另授权 `execution.management.parent.by_request.read.v1`。启用最近母单发现时，在读服务授权及 Web 客户端注册中同时加入 `execution.management.parent.discover_recent.v1`，并配置明确的 `grant.instruments`。组合宿主会启动父宿主，再启动共用同一 schema 29 账本的只读监听。停机时先关只读监听，再关父宿主。

```powershell
python -m bt_api_py.execution_combined_service_host validate --config '<ROOT>/execution/sa_dual_ma_gateway/combined.json'
python -m bt_api_py.execution_combined_service_host run --config '<ROOT>/execution/sa_dual_ma_gateway/combined.json' --enable-owner-stop-file
```

其他策略使用 `python -m bt_api_py.execution_parent_service_host --config '<该策略的父配置>' --enable-owner-stop-file`。组合宿主已包含被观测策略的父宿主，同一账本只启动一个写者。

组合宿主需输出 `EXECUTION_COMBINED_PARENT_READY` 和 `EXECUTION_COMBINED_MANAGEMENT_READY`，随后给出 `EXECUTION_COMBINED_STOP_FILE` 和本次停机文件名。单独父宿主需输出 `EXECUTION_PARENT_LISTENER_READY` 与 `EXECUTION_PARENT_STOP_FILE`。收齐 11 个父宿主的就绪记录及被观测策略的受权读回结果后，再进入下一步。

### 步骤 8/10：启动 `bt_api_runtime`（策略编排与 HTTP 控制面）

- **核心配置**：

## 6. 优雅停机顺序

1. 经 Runtime HTTP 控制面对 11 个策略依次发送 `operation="runtime.unit.stop"`，等待退出。
2. 终止 `bt_api_web` 进程（仅影响 Web 会话，不影响底层服务）。
3. 在 `runtime.json` 的 `home` 目录下，以当前日志 `runtime_control_stop_file` 给出的文件名创建零字节普通文件，并设置 owner-only DACL（POSIX 为 `0600`）。等到 `runtime_control_closed` 和进程退出码 `0`。
4. 在 `combined.json` 所在目录，以当前日志 `EXECUTION_COMBINED_STOP_FILE` 给出的文件名创建同样受保护的零字节文件。等到 `EXECUTION_COMBINED_STOPPED` 和退出码 `0`。单独运行的父宿主在各自配置旁使用 `EXECUTION_PARENT_STOP_FILE` 给出的文件名，等待 `EXECUTION_PARENT_STOPPED` 和退出码 `0`。
5. 先关闭 `risk_web`。在 `risk_service.json` 所在目录，以 Risk 日志 `RISK_SERVICE_STOP_FILE` 给出的文件名创建受保护零字节普通文件。等待 `RISK_SERVICE_STOPPED` 和退出码 `0`。Risk 的清理未确认时保留原进程、账本和写者锁，继续按有限诊断核对。
6. Risk 正常关闭后依次关闭 `gateway_web` → `gateway` → `monitor_query` → `monitor`，保留原账本。Runtime 与 Execution 在清理未确认时会给出新的停机标记文件名，供明确重试。

## 0. 修订说明

v1.0 里把目标接口写成了 `on_tick()` / `on_orderbook()`，这是错误的。当前项目已经在 `bt.Strategy` 中提供了 `notify_tick()` / `notify_orderbook()`，并且现有 tick/orderbook 示例、bench 和 integration 测试也都使用 `notify_*` 回调。

本轮重构目标应是：**把 `notify_tick()` / `notify_orderbook()` 正式固化为 HFT 策略的标准入口**，而不是新增一套 `on_*` 命名。

---

## 1. 现状结论

当前 HFT / tickbroker 的策略编写风格和原先 Backtrader 的 `bt.Strategy` 风格 **部分一致，部分不一致**。

### 1.1 已经一致的部分

项目已有 channel mode，用户可以通过以下方式运行 tick/orderbook 事件：

```python
cerebro = bt.Cerebro()
cerebro.setbroker(TickBroker(...))
cerebro.addstrategy(MyStrategy)
cerebro.run(channel=queue)
```

`Cerebro._run_channel()` 会按事件顺序推进，先让 broker 处理 tick/orderbook，再通过 `dispatch_channel_event()` 把事件送到策略。`Strategy` 里已有：

- `notify_tick(self, tick)`
- `notify_orderbook(self, orderbook)`
- `notify_funding(self, funding)`
- `notify_bar(self, bar)`
- `get_last_tick(symbol=None)`
- `get_last_orderbook(symbol=None)`

因此，HFT 策略入口本身已经应该沿用 Backtrader 的 `notify_*` 回调风格。

### 1.2 不一致的部分

目前 HFT 用户侧仍存在三种并行写法：

1. 标准 Backtrader 风格：继承 `bt.Strategy`，主要写 `next()`、`notify_order()`。
2. 当前 channel 风格：继承 `bt.Strategy`，把 HFT 逻辑写在 `notify_tick()` / `notify_orderbook()`。
3. HFT 对齐/示例风格：使用 `QuoteBuilder(position, snapshot, context)` 生成报价，再由脚本直接调用 `broker.buy()` / `broker.sell()` / `broker.process_orderbook()` / `broker.process_tick()`。

真正和 Backtrader 策略风格不一致的是第 3 种路径。`backtrader/brokers/hft/examples.py` 定义了 `PlainGridQuoteBuilder`、`QueueMarketMakingQuoteBuilder`、`OBIAlphaQuoteBuilder` 等 builder；`backtrader/brokers/hft/binance_bbo_compare.py` 和 `tests/test_utils/hft_scenarios.py` 再把 builder 输出转成 broker 订单。这条链路绕过了 `Cerebro.addstrategy()` 和 `bt.Strategy` 生命周期。

### 1.3 本轮重构判断

本轮不应重写撮合核心。`TickBroker`、`MatchingCore`、`QueueExchangeModel`、latency、queue position、maker/taker 等能力已经在迭代6后形成基础。真正需要收敛的是 **策略入口、事件分发契约、data reference 和 HFT builder 适配层**：

- HFT 策略正式继承 `bt.Strategy`。
- HFT 逻辑统一写在 `notify_tick()` / `notify_orderbook()`。
- `Cerebro.addstrategy()` 和 `cerebro.run(channel=...)` 成为 HFT 回测主入口。
- 策略下单不再依赖用户手写 dummy data。
- HFT quote-builder 示例和 Binance BBO 对齐脚本逐步迁移到 Strategy 驱动。

## 2. 目标 API

本轮完成后，用户应能用下面这种风格写 HFT 策略：

```python
import backtrader as bt
from backtrader.order import Order


class GridMakerStrategy(bt.Strategy):
    params = (
        ("symbol", "ETH/USDT"),
        ("order_qty", 0.01),
        ("half_spread", 0.5),
    )

    def __init__(self):
        self.working = {}

    def notify_orderbook(self, orderbook):
        if orderbook.symbol != self.p.symbol:
            return
        if not orderbook.bids or not orderbook.asks:
            return

        data = self.get_hft_data(orderbook.symbol)
        mid = orderbook.mid_price
        bid = mid - self.p.half_spread
        ask = mid + self.p.half_spread

        self.cancel_stale_quotes({("buy", bid), ("sell", ask)})
        self.working[("buy", bid)] = self.buy(
            data=data,
            size=self.p.order_qty,
            price=bid,
            exectype=Order.Limit,
        )
        self.working[("sell", ask)] = self.sell(
            data=data,
            size=self.p.order_qty,
            price=ask,
            exectype=Order.Limit,
        )

    def notify_tick(self, tick):
        # 可选：用成交 tick 做成交后风控、撤单、统计或 alpha 更新
        pass
```

运行方式保持 Backtrader 原有风格：

```python
cerebro = bt.Cerebro()
cerebro.setbroker(TickBroker(cash=1_000_000.0, exchange_model=QueueExchangeModel()))
cerebro.addstrategy(GridMakerStrategy, symbol="ETH/USDT")
cerebro.run(channel=queue)
```

### 2.1 最小用户体验目标

用户不需要知道 HFT builder runner、手动 broker loop 或 dummy data 对象，只需要：

1. 继承 `bt.Strategy`。
2. 在 `notify_tick()` / `notify_orderbook()` 中写 HFT 逻辑。
3. 用 `self.buy()` / `self.sell()` / `self.cancel()` 管理订单。
4. 用 `notify_order()` 接收订单状态。
5. 用 `self.get_hft_data(symbol)` 或等价公开方法拿到 channel data reference。

## 3. 非目标范围

本轮不做以下事情：

- 不新增 `on_tick()` / `on_orderbook()` 这套并行命名。
- 不重写 `TickBroker.process_orderbook()` 的撮合细节。
- 不改变 `BackBroker` / bar 回测语义。
- 不移除或重命名现有 `notify_tick()` / `notify_orderbook()`。
- 不承诺一次性追平 `hftbacktest` 的极限性能。
- 本轮目标是提供 Strategy 适配层和迁移路径，完成之后删除 HFT quote builder；

## 4. 关键设计决策

### 4.1 `notify_*` 是 HFT 策略标准入口

本轮应明确：

- `notify_tick(self, tick)`：处理 tick/trade 事件。
- `notify_orderbook(self, orderbook)`：处理 orderbook snapshot/depth 事件。
- `notify_funding(self, funding)`：处理 funding 事件。
- `notify_bar(self, bar)`：处理 channel bar 事件。

这些方法不是临时兼容接口，而是 channel/HFT 模式下的正式策略入口。

### 4.2 默认事件顺序必须避免未来函数

默认事件顺序建议固定为：

1. channel 产生 tick/orderbook 事件。
2. broker 先用当前事件撮合 **此前已经可见的订单**。
3. broker 订单通知先交给 strategy。
4. strategy 再收到 `notify_tick()` / `notify_orderbook()`。
5. strategy 在 notify 中提交的新订单默认从后续事件开始参与撮合。

这和当前 `Cerebro._run_channel()` 的顺序基本一致，也能避免策略看到本事件后立刻下单并在同一事件成交导致的 lookahead bias。

如果后续确实需要同事件下单成交，应作为显式参数处理，例如 `cheat_on_hft_event=True`，不要作为默认行为。

### 4.3 策略下单不应再依赖用户手写 dummy data

当前示例中大量出现：

```python
self._data_obj = type("Data", (), {"_name": symbol, "symbol": symbol})()
self.buy(data=self._data_obj, ...)
```

这不是 Backtrader 用户预期的策略写法。本轮应提供统一的 channel data reference：

- `Cerebro` 在 channel mode 中为每个 symbol 创建稳定 data reference。
- `Strategy` 提供 `get_hft_data(symbol)` 或等价公开方法。
- `notify_tick()` / `notify_orderbook()` 里可以通过事件的 `symbol` 拿到对应 data。
- 单 symbol 策略不再需要自建 `_data_obj`。

### 4.4 HFT builder-first 风格需要废弃，现有 builder 都要迁移成 Strategy

现有 builder 有价值，尤其用于 hftbacktest 对齐、GLFT、OBI、basis、APT 等样例。但它们不应继续作为用户-facing 的策略编写方式。推荐迁移路线分三步：

1. 先新增 `HFTQuoteStrategy` 适配层，用它承接旧 builder 的输出，保证迁移期间结果可对照。
2. 再为每个 builder 落地等价的 `bt.Strategy` 子类，把报价、撤单、挂单、上下文维护都收进 Strategy。
3. 最后删除 builder-first 公共入口、示例和文档，仅保留必要的内部测试夹具或迁移说明。

```python
class HFTQuoteStrategy(bt.Strategy):
    params = (
        ("symbol", None),
        ("quote_builder", None),
        ("decision_interval_ns", None),
        ("order_qty", None),
    )

    def notify_orderbook(self, orderbook):
        ...

    def notify_tick(self, tick):
        ...
```

迁移中期允许 builder 继续负责“根据 position/snapshot/context 生成目标报价”，Strategy 负责“撤旧单、挂新单、维护 working orders、接收订单通知”。迁移完成后，公共 API 应以 Strategy 类为准，不再推荐或导出 builder-first 写法。

## 5. 架构改造范围

| 模块 | 当前职责 | 本轮改造 |
|------|----------|----------|
| `backtrader/strategy.py` | 标准策略生命周期，已有 `notify_tick/orderbook` | 固化 HFT notify 回调语义，补充 `get_hft_data(symbol)` 等策略侧辅助 |
| `backtrader/cerebro.py` | channel mode 事件循环与 broker/strategy 分发 | 抽出 HFT 事件分发 helper，维护 symbol -> data reference |
| `backtrader/channel.py` | Event / StreamingEventQueue | 保持事件模型，必要时补充 data reference 所需元数据 |
| `backtrader/brokers/tickbroker.py` | 高频撮合、状态、订单通知 | 补充公开 last tick/orderbook/state getter；不重写撮合核心 |
| `backtrader/brokers/mixbroker.py` | tick/orderbook/bar 混合状态上下文 | 复用 notify 策略入口，保持 midfreq context |
| `backtrader/brokers/hft/examples.py` | quote builder 和 spec | 先增加 Strategy adapter，再将各 builder 改写/替换为 Strategy，最终删除 builder-first 公共入口 |
| `backtrader/brokers/hft/binance_bbo_compare.py` | backtrader vs hftbacktest 对齐脚本 | 新增 Strategy 驱动 runner，并保留底层 runner 做回归参照 |
| `examples/*` | tick/orderbook/mixed 示例 | 保持 `notify_tick/notify_orderbook`，去掉 dummy data 写法 |
| `tests/*` | HFT 回归和性能基线 | 增加 notify 分发、无未来函数、多 symbol、builder adapter 测试 |

## 7. 验收标准

本轮完成需要同时满足：

1. 用户可以继承 `bt.Strategy`，通过 `notify_tick()` 和 `notify_orderbook()` 编写 HFT 逻辑。
2. `cerebro.addstrategy()` 和 `cerebro.run(channel=...)` 是 HFT 策略主入口。
3. 下单时可通过 `self.get_hft_data(symbol)` 获取 data reference，无需手写 dummy data。
4. 现有 `notify_tick()` / `notify_orderbook()` 策略不破坏。
5. 默认事件顺序不引入未来函数。
6. 所有现有 quote builder 都有等价 Strategy 版本，迁移阶段 adapter 结果与旧 runner 一致。
7. HFT replay、hftbacktest adapted scenarios、quick baseline 都通过。
8. `python -m pytest tests -n 6` 全量通过。

## 8. 风险与控制

| 风险 | 影响 | 控制方式 |
|------|------|----------|
| notify 回调中新增下单能力后产生同事件成交误解 | 高 | 文档和测试明确 broker-first / notify-after |
| 事件顺序变化导致 HFT fill 结果漂移 | 高 | 默认保持当前顺序；新增时序 golden 测试 |
| data ref 设计过重影响性能 | 中 | 使用轻量对象并缓存 symbol -> data ref |
| Strategy adapter 无法完全复刻旧 runner | 中 | 迁移阶段保留旧 runner 作参照，逐项记录差异；删除前必须有 Strategy 等价测试 |
| 用户误以为需要新回调名 | 中 | 文档明确不新增 `on_*`，推荐 `notify_*` |
| 多 symbol 策略事件路由混乱 | 中 | 增加多 symbol integration test |

# 迭代48 — Alpha101 全量 build 因子实施计划

版本：**v0.2**；更新：**2026-10-21**。状态：**未开始；B1–B4 与 AC48-01–06 全部 NOT_RUN。** 本计划只负责迭代48；本文不是执行报告，不表示任何 build 因子或全101等价已经完成。

## 1. 定位与依赖

迭代48在迭代46全101 native 库和迭代47已稳定的 build 前端上补齐**全101个 Alpha build 库与逐式对齐**。20式复用迭代47 build 实现；其余81式按公式和风险拆成小批增加声明。独立公式 oracle、native 和 build 三方都要覆盖同一冻结输入；native/build 两边相符本身不能证明公式正确。声明只表达公式，不复制算法或私建执行路径。

所有 AlphaNative/AlphaBuild 研究都通过统一 `FactorIndicator` 基类和 FactorStrategy 构造、调度与采集；`panel_mode="next"` 与 `panel_mode="expression"` 是同一研究入口的两种编写方式，不增加 FactorSpec.execution 或第三种研究模式。AlphaNative 与 AlphaBuild 可在同一研究组合中混用。编译产生的依赖节点可以使用普通 Backtrader Indicator/Lines，时序公式内部也优先复用这些组件；不得为统一研究入口而给纯时序公式插入 CS rank，也不得另造数学核。普通 Indicator/Lines 仅作子指标或非研究回归对象。

## 2. 目标与范围

### 2.1 必须交付

1. 全101 build 目录、稳定公式 ID、完整原式、窗口、`operator_profile`、字段/分类绑定、H 和逐式依赖图；20式复用，81式新增。
2. 81个新增 build 声明及注册；声明经 FactorIndicator/FactorStrategy 统一入口处理，不作为普通 Indicator 独立研究。编译器可创建由统一入口调度的真实 Indicator/Lines 子节点；声明本身不写 `next`，也不把任意 Python 回调当节点。
3. 三方逐式校验：独立公式 oracle、native 与 build 使用同一固定 fixture/profile/绑定/H/window；oracle 不调用任一被测生产实现。
4. 全101 build 回归：runonce/runnext、资产重排、未来扰动、缺 bar、公式池 PIT、行业层级、ADV 嵌套窗、长预热、尾段和混合装配。有效输入要有有限非全 NaN 结果；缺失输入按完整 mask/reason 验证。
5. **全101 native/build 等价**：完整时间/资产索引、NaN mask、缺失原因必须精确一致；有效数值使用共享合同预先冻结的容差，离散比较、排名和布尔分支精确一致。禁止只比较非空交集或用近似 IC 替代逐值对齐。
6. 双后端 namespace、同公式 ID 的独立 registry、版本迁移规则和配对安装检查；已安装产物上的全101回归、fincore 下游回归、用户指南和最终交接。

### 2.2 明确不做

- 不新增执行模式、不重写 native 算法、不新建第二套 DSL 或私有调度。
- 不把81式算法复制进声明，不把任意 Python 回调当 DAG 节点。
- 不为纯时序公式人为增加 CS rank 或其他截面步骤；声明须表达原公式并复用共享数学核。
- 不承诺原论文收益，不把“101个 build 声明已注册”当作所有公式绩效成立。
- 不把 native/build 互相吻合、近似 IC 或样本相关性当作公式正确性；正确性要由独立 oracle、native、build 三方在同一完整 fixture 上共同支持。
- 不允许 registry 迁移合并/遮蔽 native 与 build 命名空间，或在缺少版本映射、迁移用例时静默改变同 ID 的语义。
- 不用20式等价替代101式验收，不把“20+101”重复计为121。
- 不触碰账户、私有配置、实盘进程或 CTP/live 边界。

### 2.3 “全101”口径

迭代48的101/101 = 迭代47已验收的20式 build + 本迭代新增并验收的81式 build；20式也须重新纳入本轮完整配对复核。公式/输入身份（方程、ID、window、profile、字段/类别绑定、formula-universe、H）与实现身份（native/build 后端、registry/schema 版本、代码提交）分开保存；后端升级不得悄然改变公式身份。全101 build 库完成即四迭代主线完成，但不承诺原论文收益、不证明真实供应商 PIT 或专有股票池。

## 3. 全101 build 台账与复用边界

B1 先冻结逐式 build 台账，再进入实现。台账每行至少包含：

- 论文 ID、完整原式、原文窗口和 `alpha101-v1` 取整/并列/数值域说明；
- `build(ctx, **params)` 声明、字段/算子/H/PIT 绑定和逐式依赖图；
- 独立参考来源、有限正向值、边界输入和错误实现区分方式；
- 迭代46 native 对照入口和迭代47 build 等价证据（20式）；
- 实现状态（`NOT_IMPLEMENTED`/`IMPLEMENTED`）、验收状态和提交定位。

公式 ID 在 native 与 build 两个明确 namespace 中分别注册；同一 ID 在每个后端恰有一个活动实现，不允许 build 注册覆盖 native 注册。台账还要记录 registry/schema 版本及旧版本到新版本的映射、兼容别名/弃用策略和迁移用例。迁移只改变实现/注册身份时，必须保持公式/输入身份；无既有迁移对象时也要记录“无旧格式”依据。

20个代表式固定为：#1、#2、#3、#4、#7、#9、#13、#29、#48、#56、#58、#62、#63、#67、#81、#84、#92、#96、#100、#101。它们复用迭代47的 build 实现；其余81式在本迭代新增，不能用20式替代。

## 5. 等价与回归合同

- **三方 oracle**：每式独立公式 oracle、native、build 在完全相同 fixture/profile/字段与分类绑定/H/window 上分别运行。对齐共享定义见[四迭代路线与对齐合同](../迭代45-Indicator因子研究与多因子合成/四迭代路线与对齐合同.md) ALN-01–08；native/build 两者一致只是其中一项，不能替代 oracle。
- **完整面板**：时间/资产索引、NaN mask、缺失及退化 reason 必须精确一致；不得通过非空交集裁剪、行对齐猜测或缺失值静默补齐。
- **数值与离散值**：连续数值按预先冻结的 `abs(diff) <= 1e-12 + 1e-10 * abs(ref)` 比较；rank、离散比较和布尔分支精确相等。输入异常不能成为事后调宽容差的理由。
- **公式池、PIT 与 H**：三条路径使用相同 `formula_universe`、PIT 成员和行业层级；build 不得绕过成员校验。H 属于 formula identity：先独立声明；build 依赖图推导结果须与该声明交叉核对，不能反向改写身份。
- **缺失与有效性**：每式在有效 fixture 上至少有非全 NaN 的有限正向值；缺字段/缺 bar fixture 检查全量 mask 与 reason，不以全部为空或 skip 通过。
- **统一研究入口与混合**：AlphaNative 与 AlphaBuild 经 FactorIndicator/FactorStrategy 可并列研究，`next` 与 `expression` 仅是入口的编写方式；普通 Indicator/Lines 只作内部子指标或非研究回归，不是第三种研究模式；每 grid 只推进一次，不产生重复回调或写入。
- **IC 的边界**：IC/ICIR 可用于下游研究和安装回归的回归检测，不是公式实现正确性、oracle 对齐或完整覆盖的证据。

## 6. 验收与退出

同时满足才可关闭迭代48：

1. AC48-01–06 全部通过；迭代46与47前置提交固定，81式小批和20式复核均有独立证据/提交，101式目录和双后端 registry 无遗漏。
2. oracle、native、build 在同一冻结 fixture/profile/绑定/H/window 上逐式对齐：完整 index/mask/reason 精确相同；连续数值满足预先固定容差；离散值、排名、比较与布尔分支精确相同。任何非空交集比较、近似 IC 或单纯双后端一致都不能关闭门槛。
3. Build 声明编译到共享 DAG/算子并通过 FactorIndicator/FactorStrategy 调度；生成节点可复用普通 Indicator/Lines，不把它们作为独立研究模式；不复制算法、不新增私有执行路径，native/build 保持独立 namespace，混合研究每 grid 一次。
4. clean 安装产物中两后端各自发现并运行101式，版本迁移用例不改变公式/输入身份；fincore 只消费原始面板，不重算公式内部 rank/行业中性化。
5. IC/ICIR 仅可作为下游研究/安装回归指标；全101 build 完成仍不承诺原论文收益、不证明真实供应商 PIT 或专有股票池，delay-0 的评价边界按共享合同记录。

若某项未完成，保持 `FAIL` 或 `BLOCKED` 并回到对应小批修复；不得用20式等价、静态映射或“声明已注册”替代101/101 build 与101/101等价验收。

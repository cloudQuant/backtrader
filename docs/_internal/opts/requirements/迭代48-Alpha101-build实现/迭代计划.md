# 迭代48 — Alpha101 全量 build 因子实施计划

版本：**v0.1**；更新：**2026-10-21**。状态：**未开始；B1–B3 全部 NOT_RUN。** 本计划只负责迭代48，依赖迭代46的全101 native 库和迭代47已稳定的 build/expression 前端。本文不是执行报告，不表示任何 build 因子或全101等价已经完成。

## 1. 定位与依赖

迭代48用迭代47的 build 简洁模式实现**全101个 Alpha**。20个代表式复用迭代47的 build 实现并纳入全库回归；其余81式逐个写为 `build` 声明。算法仍由底层 PanelEngine/共享算子执行，不在声明中复制算法，不为81式新增私有执行路径。

四迭代入口：

| 迭代 | 计划 | 责任 |
|---|---|---|
| 迭代45 | [迭代45计划](../迭代45-Indicator因子研究与多因子合成/迭代计划.md) | 原生引擎、共享算子/PIT、20式 next、025/026、fincore |
| 迭代46 | [迭代46计划](../迭代46-Alpha101原生因子实现/迭代计划.md) | 101/101 native、逐式独立参考与全量回归 |
| 迭代47 | [迭代47计划](../迭代47-因子build简洁模式与算子增强/迭代计划.md) | build/expression 核心、算子增强、20式等价、混合装配 |
| **迭代48** | **本计划** | **101/101 build、101/101 native/build 等价、安装与最终交接** |

共享规范仍以迭代45目录中的现行文档为准：[需求文档](../迭代45-Indicator因子研究与多因子合成/需求文档.md)、[设计文档](../迭代45-Indicator因子研究与多因子合成/设计文档.md)、[验收方案](../迭代45-Indicator因子研究与多因子合成/验收方案.md)、[Alpha101覆盖清单](../迭代45-Indicator因子研究与多因子合成/Alpha101覆盖清单.md)、[Alpha101代表验收案例](../迭代45-Indicator因子研究与多因子合成/Alpha101代表验收案例.md)。本文只展开迭代48的目标、分轮和退出条件。

## 2. 目标与范围

### 2.1 必须交付

1. 全101 build 目录、ID、完整原式、原始窗口、`operator_profile`、字段/分类绑定、H 和逐式依赖图；20式复用，81式新增。
2. 81个新增 build 声明及注册；每式可编译为共享 DAG，不创建普通实例、不写 `next`、不把 Python 回调当节点。
3. 每式独立参考/黄金值、边界/错误区分、PIT 和 H 检查；独立参考不得调用生产 DAG/算子。
4. 全101 build 全量回归：runonce/runnext、资产重排、未来扰动、缺 bar、公式池 PIT、行业层级、ADV 嵌套窗、长预热、尾段和混合装配。
5. **全101 native/build 等价**：以迭代46的 native 结果为对照，完整面板、NaN mask、原因、时间/资产索引一致；20式复用迭代47等价证据并重新回归。
6. 安装产物上的全101 build 研究回归、fincore 评价、用户指南、迁移说明和最终交接。

### 2.2 明确不做

- 不新增执行模式、不重写 native 算法、不新建第二套 DSL 或私有调度。
- 不把81式算法复制进声明，不把任意 Python 回调当 DAG 节点。
- 不承诺原论文收益，不把“101个 build 声明已注册”当作所有公式绩效成立。
- 不用20式等价替代101式验收，不把“20+101”重复计为121。
- 不触碰账户、私有配置、实盘进程或 CTP/live 边界。

### 2.3 “全101”口径

迭代48的101/101 = 迭代47已完成的20式 build + 本迭代新增的81式 build；20式必须重新纳入全库回归和等价复核。全101 build 库完成即四迭代主线完成，但仍不承诺原论文收益、不证明真实供应商 PIT 或专有股票池。

## 3. 全101 build 台账与复用边界

B1 先冻结逐式 build 台账，再进入实现。台账每行至少包含：

- 论文 ID、完整原式、原文窗口和 `alpha101-v1` 取整/并列/数值域说明；
- `build(ctx, **params)` 声明、字段/算子/H/PIT 绑定和逐式依赖图；
- 独立参考来源、有限正向值、边界输入和错误实现区分方式；
- 迭代46 native 对照入口和迭代47 build 等价证据（20式）；
- 实现状态（`NOT_IMPLEMENTED`/`IMPLEMENTED`）、验收状态和提交定位。

20个代表式固定为：#1、#2、#3、#4、#7、#9、#13、#29、#48、#56、#58、#62、#63、#67、#81、#84、#92、#96、#100、#101。它们复用迭代47的 build 实现；其余81式在本迭代新增，不能用20式替代。

## 5. 等价与回归合同

- **独立参考优先**：每式先写不调用生产 DAG/算子的参考实现，分别验证 build 与 native；两边对照只作为额外门槛。
- **完整面板**：时间索引、资产索引、有效/缺失位置和 NaN mask 必须一致；不能只比较非空交集。
- **原因与退化**：缺失输入、零分母、分类缺失、分位退化等按 DS45-13 记录并一致；不允许一边静默补值。
- **公式池与 PIT**：build 与 native 使用同一 `formula_universe`、同一 PIT 成员和同一行业层级；build 不得绕过成员校验。
- **混合装配**：普通 Indicator、next 因子、build 因子可并列；每 grid 只推进一次，不产生第二次回调或重复写入。
- **容差**：浮点差异按 DS45-13 冻结；差异超出容差必须定位实现问题，不得放宽阈值结案。

## 6. 验收与退出

同时满足才可关闭迭代48：

1. **101/101 build 公式**均完成注册、独立参考、边界/错误区分和全量回归；20式复用迭代47证据并重新纳入全库回归，81式有本迭代独立证据。
2. **101/101 native/build 等价**在完整面板、NaN mask、原因、时间/资产索引上通过；差异仅有冻结容差/原因，不以互相一致替代独立参考。
3. 所有 build 声明编译到同一共享 DAG/算子，不创建普通实例、不复制算法、不新增私有执行路径；普通 Indicator/next/build 混合装配每 grid 一次。
4. 安装产物可发现并运行101式；fincore 只消费原始面板，不重算公式内部 rank/行业中性化。
5. 全101 build 库完成即四迭代主线完成；仍不承诺原论文收益、不证明真实供应商 PIT 或专有股票池，delay-0公式的闭合 bar/next-open 评价边界继续按 DS45-13 记录。

若某项未完成，保持 `FAIL` 或 `BLOCKED` 并回到对应小批修复；不得用20式等价、静态映射或“声明已注册”替代101/101 build 与101/101等价验收。

## 7. 最终交接

迭代48完成后，程序级交付为：

- 迭代45：原生基础设施与20式 next；
- 迭代46：全101 native；
- 迭代47：build 前端、算子增强与20式等价；
- 迭代48：全101 build 与全101 native/build 等价。

四个迭代的提交链、fixture、独立参考、安装产物和已知缺口必须可追溯；不得用迭代48的 build 结果倒写迭代45/46的 native 验收，也不得把20式诊断结果表述为全101生产绩效。

本轮在[迭代47](../迭代47-因子build简洁模式与算子增强/迭代计划.md)交付的build前端和三示例双模式基础上，复用已验收的Alpha003，补齐其余100个公式，最终使全部101个Alpha都能选择native或build，并保持完整结果一致。原“47先20式、48补81式”的拆分取消；025/026的CloseMA、ROC、KDJ.J不计入101。

## 1. 用户入口和实现边界

以下是完成后的目标用法：

```python
native_cls = get_alpha(101)                 # 兼容现有默认
build_cls = get_alpha(101, mode="build")    # 显式选择
```

对应build的公式主体应保持接近Alpha101写法：

```python
@classmethod
def build(cls, ctx, **params):
    return (ctx.close - ctx.open) / ((ctx.high - ctx.low) + 0.001)
```

- 101个native类继续保留并作为默认；每个build类直接表达对应公式，不调用整条native因子取得结果。
- 伴随build类放在现有alpha001.py至alpha101.py对应文件中。扩展现有目录选择即可，不新增平行包、第二套通用注册系统、重复公式身份对象或每式运行脚本。
- 继续用FactorSpec、FactorStrategy、get_panel、现有sink/evaluate_frames和fincore。mode选择发生在装配前，不新增execution分支或第二个时间循环。
- required_fields、字段推导、参数、lookback_h、窗口取整及alpha101-v2语义沿用当前元数据。保留显式H校验；不把自动H推导或全图优化作为迁移门槛。
- 不用“减少重复”为由删除native路径。两种编写方式是用户明确要求的产品能力，须长期可选并接受回归。

## 2. 扩展表达式适配，而不复制计算内核

根据101式实际依赖补齐ctx方法，包括delay/delta、滚动统计、时序rank/argmin/argmax、截面rank/scale、逻辑与where、幂及行业中性化等。先逐项映射现有研究算子；仅对确实无法表达的组合增加薄适配。

1. 数学运算顺序、常量、窗口取整、精确并列、NaN和内部reason必须与native一致。不得把看似等价的代数重写混入迁移。
2. 相关/协方差复用现有稳定float64核；不恢复历史生产Fraction/Decimal实现，也不改变rank相等判断。
3. 行业/分类直接使用当前普通feed字段与显式绑定。资产可用性依赖真实bar及当前研究组，不恢复已删除PIT输入系统。
4. 中间节点保留可追踪引用。复用已有逐节点、逐资产检查，能够定位第一个不同的操作；不能只检查最终排名。
5. 禁止跨实例可变状态共享；CSE、缓存框架、另一套数值执行器均不属于本轮目标。

Alpha003作为全量回归的一员继续执行，不能因47已通过而从101式矩阵中排除。

### 2.1 依据现有源码确定适配范围

本次盘点基于47 E2的`fe06ad46`研究内核。以下仅是待实现的薄构造入口，不新增数值算法：

| ctx入口 | 现有计算节点 | 特别约束 |
|---|---|---|
| `abs/sign/log/signed_power` | Abs/Sign/Log/SignedPower | 保留定义域及reason；SignedPower不能替换为普通Power |
| `minimum/maximum` | Minimum/Maximum | 逐点双表达式，不是滚动highest/lowest |
| `delay/delta/sum/product/stddev/covariance` | Delay/Delta/RollingSum/RollingProduct/RollingStd/RollingCovariance | 直接将窗口交给原生floor/校验；不借用47的普通SMA整数周期规则 |
| `ts_min/ts_max/ts_rank/ts_argmin/ts_argmax/decay_linear` | 对应Ts与DecayLinear节点 | 保留完整窗口、精确并列和arg位置规则 |
| `scale` | CrossSectionalScale | 与rank一样传入实际formula_members及research_groups |
| `indneutralize` | IndNeutralize | 从显式绑定的行业表达式取分类；保留level与每次中性化次序 |
| `logical_or` | LogicalOr | 保留三值布尔，不使用Python的or；只为公式实际依赖增加接口 |
| `less_than/equal_to/subtract` | LessThan/EqualTo/Subtract | 显式保留常量在左的比较顺序，以及#59/#82/#85/#87/#89/#93/#97的纯常量减法节点；避免Python反射比较或提前折叠 |
| `returns` | Delay(close,1) → Subtract(close,prior) → Divide(change,prior) | 复用同一个prior表达式；不改为原生ROC或`close/prior-1` |

接口签名固定为一元`(value)`、逐点二元`(left, right)`、滚动`(value, period)`、相关/协方差`(left, right, period)`、`scale(value, a=1.0)`、`indneutralize(value, groups, *, level)`及`returns()`（读取已声明的close）。分类参数必须属于同一context，数值窗口和scale参数由既有算子校验；不做另一路静默转换。

`ctx.sma/highest/lowest/roc`继续服务47的原生示例，其数值/缺失规则不等同于Alpha101研究算子。101式迁移不得用`ctx.apply`绕过逐节点reason和独立AST检查；全部所需数学内核已存在于`research/operators.py`。额外字段通过已有`ctx.field(name)`或属性读取，不恢复独立输入对象。未提供VWAP、ADV或行业绑定时继续装配失败。

每个伴随类保留显式H、字段、原式和profile，并使用局部表达式变量保留native的构图顺序。尤其不能简化#21/#24的比较加LogicalOr、#67的两个行业层级、#100的三次中性化与两次scale、#101的`+0.001`。同文件元数据可引用现有native类的冻结声明；不得调用其用户初始化、next或整式结果。

纯常量节点也属于逐节点验收范围。没有输入line可证明资产归属时，测试工具从实际结果及消费者依赖追溯到具体目标；无法到达或被多个目标混用的常量节点不能通过。诊断变量名和字典顺序不作为配对依据。

## 4. 全量验收

### 4.1 公式和生命周期

全101式执行native/build × runonce/runnext。每式至少具备有限输出见证，native和build分别对独立参考通过，再做完整逐格配对。

- 同引擎native/build的完整索引、顺序、mask、内部reason、有限值和离散分支精确一致。
- 对独立参考的连续值沿用冻结标准，默认1e-12 + 1e-10*abs(ref)；rank、比较、argmin/argmax和分支精确相同。不能以浮点容差掩盖排序/分支不同。
- 两引擎均满足当前数值合同；按完整面板比较引擎结果，差异必须定位到现有行为或新增实现，不得把一条失败路径排除。
- 复用现有标量/矩阵参考及逐节点验证工具，不调用生产实现生成golden，不做整行排序、NaN交集裁剪或随T放宽误差。
- 全注册表资产重排、未来扰动及有代表性的缺bar、预热、尾段、零方差、行业变化、ADV输入路径通过。混合装配、跨实例/跨运行隔离和参数变体覆盖实际公共路径。
- 显式H、独立公式历史跨度、原生minperiod及实际首个有效时点交叉核对；不只比较最大单窗口。

现有harness的`run_native_batch(..., alpha_classes={id: cls})`可直接注入伴随类；继续使用同一独立参考。当前trace工具比较AST和节点数值，但没有通用reason输出；48须在既有测试工具中按AST节点和资产身份配对标量`node.lines.reason`及截面`node.outputs[data].reason`，不能按native/build诊断变量名或两份字典的插入顺序猜测对应关系。重复出现的相同子表达式也要全部核对。

当前全101资产重排测试只比前280格，未来扰动测试也只验证前缀不变；48将资产重排检查扩展为完整时间范围，未来扰动保留完整前缀并增加真实输入扰动见证。两引擎分别对oracle通过并不等于引擎间已配对：48须另行比较完整面板、原始输出和掩码，定位任何差异；同引擎native/build继续逐格精确相等，不能用oracle容差代替。
